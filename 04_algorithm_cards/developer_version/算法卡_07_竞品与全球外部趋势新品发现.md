# 算法卡_07_竞品与全球外部趋势新品发现

更新时间：2026-08-10

业务原始依据：`archive/source_docs/business_algorithm_docs/算法卡_07_竞品与全球外部趋势新品发现.md`

业务解读依据：`04_algorithm_cards/business_readable/算法07_竞品与全球外部趋势新品发现_业务解读版.md`

开发交付定位：本卡是算法 07 的 V1 开发版算法卡，用于数据开发建表、接入外部数据、生成外部候选、跑数和验收。业务原文要求的完整能力会被承接，但 V1 落地口径必须明确标注，不能把 V1 降级写成业务原文规则。

## 1. 算法目标

算法 07 用外部数据发现或验证具象新品候选，并把外部候选落回内部小分类、门店等级、消费者画像、主体需求，同时保留外部规格和价格证据供算法 05 计算国内价格可行性。

一句话：

```text
外部证明市场上出现了什么商品、属性、价格、供需和趋势线索；
内部证明这个候选能否落到我们的目标门店、目标画像、目标品类和主体需求；
算法 07 输出外部新品候选，交给算法 08 标准化合并，再由算法 09 风险门禁。
```

本算法做：

```text
1. 接入久谦竞品数据和 10 个公开或可授权外部源。
2. 保存外部原始证据、来源血缘、采集时间和来源状态。
3. 把外部商品、文章、价量、供需等证据统一成标准外部证据。
4. 自动生成外部词到标准商品属性的映射结果。
5. 判断外部商品能否映射到内部小分类、SPU、主体商品和属性。
6. 判断同款、高相似、同方向或无法匹配。
7. 计算竞品渠道渗透率、官方价量/供需信号、行业文章证据。
8. V1 不计算正式 Social NPS Proxy，相关字段保留为空并标记 V1 暂不计算。
9. 将外部候选与算法 02-04 的内部需求结果、算法 06 的购物篮增强证据做适配。
10. 识别法规、标签、食品安全或功能声称风险线索，随候选传给算法 08 保存，并由算法 09 做正式门禁。
```

本算法不做：

```text
1. 不把外部趋势单独作为最终新品推荐。
2. 不给外部账号贴内部会员画像。
3. 不把文章热度、商品榜单或竞品价格当成消费者口碑。
4. 不把海外趋势写成国内已流行。
5. 不把海外价格按汇率换算成国内建议价。
6. 不把多个独立热词擅自拼成一个商品。
7. 不用人工固定权重综合分消灭证据冲突。
8. 不越过算法 09 的历史差销、当前货盘、供应、毛利和风险门禁。
9. 不输出促销、陈列、订购、升级、替换或清退动作。
```

## 2. V1 边界

V1 外部数据分两层并存：

| 层级 | 数据 | V1 用途 | 不能替代什么 |
|---|---|---|---|
| 第一层 | 久谦竞品数据 | 提供竞品商品、平台、城市、规格、价格、图片和快照 | 不能替代官方价量、供需、行业文章和真实社媒口碑 |
| 第二层 | 10 个公开或可授权外部源 | 补充官方价量、供需、零售 SKU、POS 新品榜、行业文章和新闻 | 不能替代久谦结构化竞品底座 |

V1 能输出：

```text
外部原始信号
外部候选属性映射
竞品渠道渗透证据
官方价量和供需证据
行业文章和公开新闻证据
内部适配结果
风险线索传递
外部新品候选
```

V1 不能输出：

```text
正式 Social NPS Proxy
真实消费者购后口碑结论
完整全球趋势结论
完整法规自动判断
最终新品推荐结论
```

V1 降级写法：

| 场景 | 字段写法 | 是否阻断 07 V1 输出 |
|---|---|---|
| 没有真实社媒源 | `social_source_status = V1_NOT_CALCULATED`，Social NPS 字段为 `NULL` | 不阻断 |
| 10 个外部源部分采集失败 | 对应来源 `source_status = SOURCE_MISSING` 或 `SOURCE_PARTIAL` | 不直接阻断，但不能进入分子分母 |
| 外部候选无法映射内部小分类 | `mapping_status = CATEGORY_MAPPING_GAP` | 阻断正式候选，只保留证据 |
| 法规或风险源不完整 | `risk_handoff_status = SOURCE_PARTIAL` 或 `SOURCE_MISSING` | 不替代算法 09，候选仍为待门禁 |
| 后验计算不稳定 | `compute_status = COMPUTE_UNSTABLE` | 不进入正式趋势层 |

V1 交付层级：

| 层级 | 开发是否必做 | 产出结果 | 不能输出什么 |
|---|---|---|---|
| 外部原始证据落库 | 必做 | 来源注册、原始快照、标准化证据 | 不能只落最终候选而没有原始证据 |
| 外部属性映射 | 必做 | `external_attribute_mapping`，含原词、标准属性、映射概率、映射状态 | 不能让无法映射的词进入正式候选名称 |
| 竞品渠道渗透 | 必做 | `competitor_channel_evidence`，含分子、分母、后验区间 | 不能把官方价量、供需或文章源放入渠道分母 |
| 官方价量、供需、行业公开证据 | 必做 | `industry_external_evidence` | 不能把文章热度或价格变化当成消费者口碑 |
| Social NPS Proxy | V1 不做 | 相关字段为 `NULL`，状态为 `V1_NOT_CALCULATED` | 不能输出“消费者口碑好” |
| 分层贝叶斯趋势融合和 5% FDR | 正式趋势层必做 | 能稳定实现时输出 `FORMAL_GROWING_TREND` | 没有跑通后验和 FDR 时，不能输出正式趋势层 |
| 探索层和原始信号层 | 必做 | `RAW_EXTERNAL_SIGNAL`、`EMERGING_EXPLORATORY` 等 | 不能删除可追溯的早期信号 |

## 4. 开发执行流程

算法 07 是离线或准离线计算，不在采购前端查询时实时抓网站或实时跑模型。

运行顺序：

```text
1. 每日采集久谦和 10 个外部源，保存原始快照。
2. 每日或每周将原始快照统一成标准外部证据。
3. 自动生成外部词到标准属性、小分类、SPU、主体商品的映射。
4. 计算竞品同款、高相似、同方向和属性渗透。
5. 计算官方价量、供需和行业文章证据。
6. V1 跳过正式社媒口碑计算，Social NPS 字段写空和 V1_NOT_CALCULATED。
7. 形成外部趋势状态。
8. 读取算法 02-04 正式结果和算法 06 增强证据，计算内部适配。
9. 选择并校验图片，保存风险线索。
10. 输出外部新品候选给算法 08，再由算法 09 做风险门禁。
```

采购前端输入的是筛选条件：

```text
城市算法区域、门店等级、消费者画像、小分类、候选状态、外部市场。
```

这些条件只用于读取已计算结果，不是让采购手工输入候选商品、规格、成本或外部趋势词。

## 6. 属性维度和字段命名

算法 07 的属性维度字段不是直接复用商品基础表字段。两类字段要区分：

```text
internal_ 前缀：来自内部商品基础表的字段。
standard_ 或 canonical_ 前缀：算法 07 从外部数据抽取并标准化后的字段。
attribute_dimension：说明一个外部词属于哪个属性维度。
```

内部主数据映射字段：

| 中文字段名 | 英文字段名 | 对齐商品基础表字段 | 中文注释 |
|---|---|---|---|
| 内部小类编码 | `internal_leaf_category_code` | 小类编码 | 外部候选匹配到的钱大妈内部小类编码 |
| 内部小类名称 | `internal_leaf_category_name` | 小类名称 | 外部候选匹配到的钱大妈内部小类名称 |
| 内部 SPU 编码 | `internal_spu_code` | SPU编码 | 外部候选匹配到的内部 SPU 编码 |
| 内部 SPU 名称 | `internal_spu_name` | SPU名称 | 外部候选匹配到的内部 SPU 名称 |
| 内部规格 | `internal_specification` | 规格 | 可参考的内部商品规格 |
| 内部单位 | `internal_unit` | 单位 | 可参考的内部销售单位 |

标准属性维度：

| 属性维度取值 | 中文含义 | 例子 | V1 判断来源 |
|---|---|---|---|
| `MAIN_PRODUCT` | 主体商品 | 鲜鸡蛋、牛柳丝、鸡腿排 | 内部 SPU、小类、外部商品名和描述 |
| `MAIN_MATERIAL` | 主材料或配方材料 | 鸡蛋、牛肉、鸡肉、青椒、菌菇 | 商品名、外部类目、内部 SPU、小类和算法 06 配方证据 |
| `FLAVOR` | 口味 | 黑椒、照烧、麻辣 | 口味词规则、商品名、描述 |
| `PROCESS` | 工艺 | HPP、高压冷杀菌、烟熏 | 工艺词规则、商品描述、行业文章 |
| `FUNCTION_CLAIM` | 功能/营养卖点 | Omega-3、高蛋白、低钠 | 功能词规则、商品详情、行业文章 |
| `PRODUCT_FORM` | 商品形态 | 丝、片、块、丸、排 | 商品名、规格、内部 SPU |
| `SPEC` | 规格 | 12枚、200g、400g/袋 | 规格正则、单位、标准规格重量 |
| `PACKAGING` | 包装 | 袋装、盒装、家庭装 | 商品名、规格、图片 OCR、描述 |
| `SALES_UNIT` | 销售单位 | 份、个、盒、袋、kg | 商品规格、单位和外部商品描述 |
| `ORIGIN` | 产地 | 云南、泰国、进口 | 商品名、产地字段、标题和描述 |
| `GRADE` | 等级 | 特级、一级、精品、大果 | 商品名、等级字段、标题和描述 |
| `CULTIVATION_METHOD` | 种植或养殖方式 | 有机、绿色、散养 | 商品名、认证或养殖种植说明 |
| `CERTIFICATION` | 认证 | GAP、绿色食品、有机认证 | 商品详情、图片 OCR、行业文章 |
| `TEMPERATURE_STATE` | 温层或状态 | 冷藏、冷冻、常温、鲜活 | 商品描述、内部温层、外部标签 |
| `STORAGE_CONDITION` | 存储条件 | 0-4 度冷藏、冷冻保存 | 商品描述、内部存储条件、外部标签 |

辅料或配方结果不单独新增独立属性维度枚举。算法 07/08/09 的候选字段仍可使用 `standard_secondary_ingredient` 保存辅料或配方文本，但属性字典和 `attribute_dimension` 只使用 `dim_candidate_attribute_dictionary` 已冻结枚举。

## 7. 外部属性映射逻辑

V1 属性映射不依赖一次性人工词典。开发必须先由系统生成映射候选结果，再按状态进入计算、观察池或风险传递。

映射流程：

```text
1. 从外部商品名、类目、规格、标签、标题、正文和图片 OCR 中抽取词。
2. 做语言识别、基础翻译、单位规格标准化。
3. 用规则词典识别确定性强的词，例如规格、单位、口味、工艺和风险词。
4. 用内部商品基础表匹配主体商品、小分类和 SPU。
5. 用模型辅助识别规则无法覆盖的新词。
6. 输出映射概率、映射证据、属性维度和映射状态。
7. 高置信结果进入计算；低置信结果进入观察池；风险词形成风险线索，随候选传给算法 08 保存，并由算法 09 做正式门禁。
```

V1 初始阈值：

| 条件 | 处理 |
|---|---|
| 规则命中且小分类边界通过 | `mapping_status = MAPPED`，进入计算 |
| `mapping_probability >= 0.85` 且小分类边界通过 | `mapping_status = MAPPED`，进入计算 |
| `0.60 <= mapping_probability < 0.85` | `mapping_status = REVIEW_REQUIRED`，进入观察池，不进入正式候选名称 |
| `mapping_probability < 0.60` | `mapping_status = UNMAPPED`，只保留原始证据 |
| 命中风险词 | `risk_handoff_status = RISK_REVIEW_REQUIRED`，生成风险线索 ID，随候选传给算法 08 保存，并由算法 09 做正式门禁 |
| 无法可靠匹配内部小分类 | `mapping_status = CATEGORY_MAPPING_GAP`，不进入正式候选 |

上述阈值是 V1 开发初始参数，不是业务原文固定阈值。开发需保存 `attribute_mapping_rule_version`，试跑后用标注样例校准。

## 8. 核心计算逻辑

### 8.1 来源治理

每条外部证据先判断来源状态：

```text
SOURCE_VALID：来源成功采集且关键字段可用。
SOURCE_PARTIAL：来源成功采集但部分字段缺失。
SOURCE_MISSING：本期未采集、采集失败或 V1 未接入。
SOURCE_EXPIRED：来源超过有效期。
SOURCE_REVOKED：授权撤回或不允许继续使用。
V1_NOT_CALCULATED：V1 明确不计算该能力，例如正式 Social NPS Proxy。
```

`SOURCE_MISSING`、`SOURCE_PARTIAL` 和 `V1_NOT_CALCULATED` 不能填 0。

### 8.2 小分类映射

外部候选必须先落到内部小分类：

```text
外部商品名、外部类目、品牌、规格、主材料、商品形态、加工方式、功能属性
-> 匹配 dim_sku 的小类编码、小类名称、SPU编码、SPU名称、商品名称和规格
-> 匹配可靠才进入后续计算
-> 匹配不可靠写 CATEGORY_MAPPING_GAP
```

不允许将无法映射的商品强行归入语义最相似小分类。

### 8.3 竞品关系判断

先做硬边界校验：

```text
internal_leaf_category_code
standard_product_subject
standard_main_ingredient
standard_product_form
standard_process
standard_cooking_method
measurement_type
```

再比较：

```text
standard_function_claim
standard_flavor
standard_spec
standard_package
standard_storage
standard_consumption_scene
normalized_name_embedding
image_embedding
ocr_text
```

输出关系：

| 关系取值 | 中文含义 | 触发条件 |
|---|---|---|
| `EXACT_EQUIVALENT` | 同款或业务等价 | 主体、核心属性、形态、工艺和规格段一致 |
| `BUSINESS_HIGH_SIMILAR` | 高相似 | 解决同一主体需求，但口味、规格或包装存在差异 |
| `SAME_TREND_DIRECTION` | 同方向 | 共享功能、工艺或场景趋势，但不是同款或高相似 |
| `NO_COMPARABLE_MATCH` | 无可比匹配 | 已映射小分类，但没有可比竞品 |
| `CATEGORY_MAPPING_GAP` | 小分类映射缺口 | 无法可靠落入内部小分类 |

### 8.4 竞品渠道渗透率

只使用结构化 SKU / POS / 电商源：

```text
久谦
KSP-POS
7-ELEVEN 台湾
HKTVmall FRESH TO GO
```

有效可比渠道分母：

```text
eligible_channel_count
= 同市场 + 同周期 + 同内部小分类下，成功采集该小分类的独立零售平台或零售品牌数量
```

出现渠道分子：

```text
detected_channel_count
= 在有效可比渠道中，出现指定同款、高相似或趋势属性的渠道数
```

三层渗透率必须分开：

```text
exact_penetration_raw
= EXACT_EQUIVALENT 出现渠道数 / 有效可比渠道数

high_similar_penetration_raw
= BUSINESS_HIGH_SIMILAR 出现渠道数 / 有效可比渠道数

attribute_penetration_raw
= 目标趋势属性出现渠道数 / 有效可比渠道数
```

Jeffreys-Beta 后验：

```text
x = detected_channel_count
n = eligible_channel_count
p ~ Beta(x + 0.5, n - x + 0.5)

penetration_raw = x / n
penetration_posterior_median = median(p)
penetration_ci_low_95 = quantile(p, 0.025)
penetration_ci_high_95 = quantile(p, 0.975)
```

`1/1` 不能解释为高可信 100%。

### 8.5 官方价量和供需证据

官方价量和供需源不进入竞品渠道渗透分母，只进入 `industry_external_evidence`。

可计算字段：

```text
price_value
price_unit
transaction_volume
supply_volume
period_start
period_end
claim_direction
```

基础变化率：

```text
price_change_rate = (current_price - previous_period_price) / previous_period_price
supply_change_rate = (current_supply - previous_period_supply) / previous_period_supply
volume_change_rate = (current_volume - previous_period_volume) / previous_period_volume
```

若来源只提供正文和涨跌描述，保留原文并抽取方向，不强行补数值。

### 8.6 行业文章和公开新闻证据

文章源进入 `industry_external_evidence`，不进入竞品渠道渗透分母。

抽取结果必须包含：

```text
claim_subject：说的是哪个商品、品类或属性
claim_attribute：说的是哪个卖点、工艺、场景或风险
claim_direction：增长、稳定、下降或事实
source_level：官方、行业、媒体或转载
data_period_start / data_period_end：证据对应的数据周期
source_published_at：文章或报告发布时间
```

同一报告多次转载只算一个证据组。

### 8.7 Social NPS V1 处理

V1 不接入真实社媒口碑源，不计算正式 Social NPS Proxy。

处理规则：

```text
social_source_status = V1_NOT_CALCULATED
n_promoter = NULL
n_neutral = NULL
n_detractor = NULL
social_nps_proxy_raw = NULL
social_nps_proxy_posterior_median = NULL
social_nps_proxy_ci_low_95 = NULL
social_nps_proxy_ci_high_95 = NULL
attribute_sentiment_json = NULL
```

Social NPS 不进入 V1 外部证据融合，不进入候选推荐理由。

V1 可以输出：

```text
外部有竞品、价格、规格、供需或行业趋势证据。
```

V1 不能输出：

```text
外部消费者口碑好。
```

### 8.8 外部趋势状态

V1 先用可用证据判断外部状态：

```text
竞品渠道证据
官方价量和供需证据
零售 SKU / POS 新品榜证据
行业文章和公开新闻证据
```

分层贝叶斯模型和 5% 贝叶斯 FDR 不是取消不用，而是控制“正式趋势层”的硬准入。

V1 必须按两层输出：

| 层级 | 进入条件 | 输出状态 |
|---|---|---|
| 探索层 / 原始信号层 | 有可追溯外部证据，但动态趋势模型、历史回测或 FDR 尚未稳定 | `RAW_EXTERNAL_SIGNAL` 或 `EMERGING_EXPLORATORY` |
| 正式趋势层 | 后验概率、增长下界、5% 贝叶斯 FDR、来源血缘全部通过 | `FORMAL_GROWING_TREND` |

如果 V1 暂时没有足够历史样本完成分层贝叶斯趋势融合和 FDR 校验：

```text
p_trend_real = NULL
p_sustained_growth = NULL
trend_growth_posterior_median = NULL
trend_growth_ci_low_95 = NULL
trend_growth_ci_high_95 = NULL
local_false_discovery_rate = NULL
bayesian_fdr_selected_flag = 0
compute_status = COMPUTE_UNSTABLE 或 SOURCE_PARTIAL
external_evidence_status = RAW_EXTERNAL_SIGNAL 或 EMERGING_EXPLORATORY
```

此时仍可把证据传给后续算法作为探索候选，但不得输出 `FORMAL_GROWING_TREND`。

正式趋势条件：

```text
p_trend_real 可计算且较高
p_sustained_growth 可计算且较高
trend_growth_ci_low_95 > 0
local_false_discovery_rate <= 0.05
compute_status = SUCCESS
关键来源血缘完整
```

正式动态趋势模型最小结构：

```text
y_t = 当周包含趋势属性的有效观测数
N_t = 当周同市场、同来源、同小分类有效观测总数

y_t ~ Binomial(N_t, p_t)

logit(p_t)
= level_t
 + season_market_week_t
 + local_calendar_t
 + source_random_effect

level_t = level_(t-1) + slope_(t-1) + eta_t
slope_t = slope_(t-1) + zeta_t
```

如果 V1 只有 SKU/POS/电商、官方价量和行业文章，没有真实社媒：

```text
z_social = 未观察
social_source_status = V1_NOT_CALCULATED
不能把 z_social 填 0
```

外部证据融合最小结构：

```text
logit P(T_grow=1)
= alpha_leaf_category
 + market_random_effect
 + beta_competitor * z_competitor
 + beta_social * z_social
 + beta_industry * z_industry
 + beta_diffusion * z_diffusion
 + source_reliability_random_effect
 + evidence_group_random_effect
```

其中：

```text
z_competitor = 竞品渠道渗透后验、持续在售和新进渠道证据
z_social = 真实社媒自然文档渗透、独立账号覆盖和传播强度；V1 未接入时为未观察
z_industry = 官方价量、供需、行业公开证据、时效和来源可靠性
z_diffusion = 跨市场独立采用证据
```

`beta_*` 是历史滚动训练学习出的来源预测系数，不是人工固定权重。

局部误发现率：

```text
local_false_discovery_rate_i
= P(T_grow_i = 0 | current_external_data)
```

5% 贝叶斯 FDR 选择规则：

```text
1. 在同一正式范围内，按 local_false_discovery_rate 从低到高排序候选。
2. 选择最大的候选集合 S，使 mean(local_false_discovery_rate_i for i in S) <= 0.05。
3. S 内候选 bayesian_fdr_selected_flag = 1。
4. 其他候选 bayesian_fdr_selected_flag = 0。
```

5% FDR 只控制正式趋势层，不删除发现层和探索层。

数值可重复要求：

```text
后验取值使用确定性 Sobol 准蒙特卡洛或等价可复现取值方案。
随机种子由 external_trend_algorithm_version + run_id + source_market + standard_candidate_id 生成。
取值量逐轮加倍，直到主要分位数和后验概率按结果表精度四舍五入后连续两轮不变。
未收敛时 compute_status = COMPUTE_UNSTABLE，不进入正式趋势层。
```

如果无法稳定计算：

```text
compute_status = COMPUTE_UNSTABLE
external_evidence_status = RAW_EXTERNAL_SIGNAL 或 EMERGING_EXPLORATORY
```

来源可靠性和冷启动：

```text
已有历史验证的来源：
按历史滚动回测学习 source_reliability_posterior。

新来源或历史不足来源：
source_reliability_posterior = NULL
compute_status = SOURCE_PARTIAL
external_evidence_status 不能直接进入 FORMAL_GROWING_TREND
```

跨市场扩散：

```text
p_cross_market_diffusion 只在多个独立市场有独立来源证据时计算。
同一品牌全球统一新闻、同一报告转载或统一营销事件只能算一个证据组。
V1 只表达已接入市场范围内的扩散，不表达完整全球趋势。
```

### 8.9 内部适配

外部趋势必须回到内部范围重新判断：

```text
城市算法区域
门店等级
消费者画像
内部小分类
主体商品需求
```

最低内部证据：

```text
算法 02：目标门店等级存在且有效
算法 03：目标消费者画像贡献成立
算法 04：主体商品或同类主体需求成立
算法 06：如存在配方或场景关系，作为增强证据；不是所有外部功能属性都强制要求 06 支持
```

内部适配不通过时，保留外部趋势状态，但不生成该内部范围的正式外部新品候选。

### 8.10 风险线索传递

算法 07 只做风险线索识别和传递，不替代算法 09 做正式风险门禁。

至少识别：

```text
低钠
高蛋白
0 防腐剂
药食同源
儿童可食用
有机
无抗
功能性营养声称
标签、商标、专利、食安或质量风险线索
```

处理：

```text
外部证据本身无法进入候选池，如证据不可追溯、明确禁用或无法归入国内食品分类
-> external_evidence_status = SOURCE_ADMISSION_STOP
-> 不写入 external_new_product_candidate

存在不确定风险但可进一步确认
-> risk_handoff_status = RISK_REVIEW_REQUIRED
-> risk_handoff_ids 随候选传给算法 08 保存，并由算法 09 做正式门禁
```

### 8.11 标准候选生成和属性组合

标准候选不是一个热词，而是一组有来源证据的结构化属性。

候选 ID 生成：

```text
standard_candidate_id
= hash(
  attribute_dict_version,
  internal_leaf_category_code,
  standard_product_subject,
  standard_main_ingredient,
  standard_secondary_ingredient,
  standard_flavor,
  standard_process,
  standard_function_claim,
  standard_product_form,
  standard_spec
)
```

候选名称生成：

```text
candidate_product_name
= 已验证功能/工艺
 + 已验证配方/口味
 + 标准主体商品
 + 外部规格解析得到的标准规格
```

每个进入候选名称的属性都必须有：

```text
canonical_attribute_code
attribute_dimension
mapping_probability
attribute_source_ids
external_evidence_ids
```

不得把多个独立热词直接拼成一个商品。只有以下任一证据成立时，多个属性才可以组合：

```text
同一真实外部商品同时包含这些属性
算法 06 提供配方或场景关系
行业或标准资料证明这些属性不可分
多个独立商品中形成稳定属性组合项集
```

否则分别生成候选，不合并。

### 8.12 外部价格定位

外部价格只用于相对定位和竞品参考，国内建议规格和国内建议价仍由算法 05 生成。

外部价格处理：

```text
保留来源市场币种、包装价、会员价、促销价、规格和标准单位价格。
不把促销价当日常价。
不把海外价格按汇率换算成国内建议价。
不强行换算不同计量类型商品。
```

来源市场相对价格定位：

```text
relative_price_position = BASIC / MAINSTREAM / PREMIUM
```

算法 07 不输出以下国内价格字段：

```text
recommended_spec
recommended_retail_price
target_price_band
price_feasibility_status
```

这些字段由算法 05 写入 `mart_candidate_product_price_feasibility`，再由算法 08 合并到标准候选和范围候选，算法 09 做正式门禁。

### 8.13 图片选择和校验

图片选择按回退顺序执行：

```text
1. EXACT_EQUIVALENT 同款竞品真实图
2. BUSINESS_HIGH_SIMILAR 高相似竞品参考图
3. 可追溯公开实拍图
4. AI 开发示意图
```

校验规则：

```text
主体商品一致
功能、口味、工艺和规格不冲突
OCR 不指向其他商品
授权状态可追溯
```

高相似图必须标记为参考图，AI 图必须标记为示意图，不得写成候选商品实物图。

### 8.14 来源准入和排序

算法 07 不做最终新品推荐，但必须在候选传递前标清状态。

来源准入停止顺序：

```text
来源准入停止
-> 小分类映射缺口
-> 外部下降趋势
-> 本地主体需求不匹配
-> 风险线索随候选进入算法 08；价格、毛利、历史差销、当前货盘、供应和完整风险门禁由算法 05/09 判断
```

未通过来源准入的对象不写入 `external_new_product_candidate`，但保留原始证据和停止状态。

排序只在同一候选池内做 Pareto 比较，不做人工固定权重综合分：

```text
内外部共同收敛的正式趋势
> 单路径正式趋势
> 成熟市场差异化空白
> 新兴探索趋势
> 海外领先探索
> 原始外部信号
```

同层候选比较趋势持续性、渠道渗透可信下界、内部主体需求和跨市场扩散证据。无支配关系时并列输出，不强行加总分。

| `authorization_status` | 授权状态 | `PUBLIC_TRACEABLE` | 公开可追溯 | 公开来源可保留链接和来源标记 |
| `authorization_status` | 授权状态 | `UNKNOWN` | 未知 | 授权状态不明确，仅可作为内部参考或待复核 |
| `authorization_status` | 授权状态 | `REVOKED` | 授权撤回 | 来源撤回或不允许继续使用 |
| `image_status` | 图片状态 | `IMAGE_VALID` | 图片可用 | 图片来源、匹配、授权均通过 |
| `image_status` | 图片状态 | `IMAGE_REFERENCE_ONLY` | 仅参考 | 高相似或公开参考图，只能参考 |
| `image_status` | 图片状态 | `IMAGE_SOURCE_MISSING` | 图片来源缺失 | 无可用外部图片 |
| `image_status` | 图片状态 | `IMAGE_INVALID` | 图片不可用 | 匹配失败或授权不可用 |

## 12. 调度周期

| 任务 | 频率 | 说明 |

## 15. 待评审红线

以下问题会影响算法 07 是否能按 V1 正式交付，需进入项目评审：

| 优先级 | 确认对象 | 红线问题 | 不确认会怎样 |
|---|---|---|---|
| P1 | 数据开发 | 久谦三张表能稳定提供哪些字段，尤其是价格、规格、销量、评论、好评率、售罄、覆盖门店、图片、商品详情链接和标准规格重量 | 缺失字段只能写 `SOURCE_PARTIAL`，不能伪造销量、评价或图片证据 |
| P1 | 数据开发 | 10 个外部源是否按统一原始快照表和标准化证据表落库，并保留原始链接、采集时间、来源状态和失败原因 | 没有来源血缘时，外部候选不能进入正式结果 |
| P1 | 算法/数据开发 | 分层贝叶斯趋势融合、历史回测和 5% FDR 是否能稳定实现 | 未稳定实现时不能输出 `FORMAL_GROWING_TREND`，只能输出探索层或原始信号层 |
| P1 | 算法/数据开发 | 属性映射候选表是否能按规则词典、同义词表、内部商品基础表和模型辅助生成，并保留映射证据和版本 | 无法追溯属性来源时，该属性不能进入候选名称 |
| P1 | 法务/质量/业务 | 功能声称、标签、食品安全、法规或知识产权风险词是否补充到合规词规则和复核样例中 | 避免 07 漏传需要 09 判断的风险线索 |
| P2 | 业务/商品 | 高频词、候选命名词和风险词的人工复核范围 | 未复核词只能进入观察池，不能进入正式候选名称 |
