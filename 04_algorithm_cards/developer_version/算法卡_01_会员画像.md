| 前置过滤 | 哪些数据不参与 | 空会员、`customer_id` 以 6 开头的非真实会员、退货、取消、冲销、非正销售数量或金额、同一会员单日超过 5 张小票的异常会员日；测试交易需在字段枚举确认后再正式过滤 |
| 画像结构 | 最终标签由什么组成 | 先判断时间行为；捡漏型为终止标签，其他会员继续拼接家庭规模、消费频次和价格态度 |
| 时间行为 | 有哪些标签 | `捡漏型 / 上班族晚高峰型 / 常规时段型` |
| 家庭规模 | 有哪些标签 | `大家庭 / 小家庭`，只对非捡漏型会员计算，另输出置信度 |
| 消费频次 | 有哪些标签 | `高频 / 中频 / 低频`，只对非捡漏型会员计算 |
| 价格态度 | 有哪些标签 | `价格敏感 / 价格非敏感`，只对非捡漏型会员计算，另输出置信度 |
| 阈值来源 | 是固定还是动态 | 频次和家庭直接规则使用固定业务阈值；行为得分使用区域熵权；得分分组使用 Jenks 自然断点；家庭补充模型的概率阈值使用 5 折交叉验证 |
| 冲突处理 | 同时命中多个标签怎么办 | 时间行为同时命中捡漏和晚高峰时，比较 `得分 / 自然断点阈值`；相差不超过 0.05 时再比较天数、月数，仍相同则捡漏型优先 |
| 输出结果 | 最终输出什么 | 会员 ID、主归属区域、条件式最终画像、各适用维度得分、阈值、证据、置信度、模型版本与变化原因 |
| 验收方式 | 怎么判断结果合理 | 数据完整性、10 个脱敏会员开发对数、100 个分层会员人工抽样、次月行为延续率、跨版本阈值与标签稳定性 |

## 2. 数据范围、输入表与主归属区域

### 2.0 开发执行流程

算法 01 按月离线批量计算。开发先锁定最近 6 个完整自然月的小票、商品基础表、门店基础表和城市算法区域映射版本；汇总会员在华东范围内的全部有效交易，确定每名会员唯一主归属区域；再按主归属区域组织训练样本并生成区域模型参数，最后产出会员画像结果表、解释表、区域参数表和汇总表。

月中新会员只允许使用已发布的区域参数做增量贴标，不重新训练熵权、Jenks 或逻辑回归参数；其结果写入独立补充画像结果区，不并入月度正式四张表。后续算法和查询服务只读取已发布的正式结果，除非明确读取补充画像，不在前端查询时实时重算或临时改标签。

### 2.4 数据周期

每个正式模型版本使用最近 6 个数据已完整的自然月。

V1 当前输入范围为华东全部业务数据，不是从全国数据中临时筛选华东。会员个人指标使用当前华东数据范围内的全部有效交易。

以后新增南京或其他全国城市时，必须先完成城市到算法区域的映射、对应区域参数的训练或验证，并从新的 `profile_model_version` 开始纳入。区域和参数尚未准备完成的新城市数据不得套用上海或其他区域参数，也不得混入已发布的历史版本。

例如，系统在 2026 年 7 月运行，但 Doris 只有 2026 年 6 月 1 日至 7 日的数据，则 6 月不属于完整月，正式计算周期应为：

```text
2025-12-01 <= business_date < 2026-06-01
```

正式计算窗口必须从自然月 1 日开始，到第 6 个自然月月末结束，不允许使用 `2026-03-15 ~ 2026-08-22` 这类非完整月窗口生成正式版本。完整月还必须通过上游数据完整性检查；分区缺失、明显延迟或关键指标异常时，该窗口不得发布。

版本号生成公式：

```text
profile_model_version = 'profile_' + DATE_FORMAT(calculation_end_date, 'yyyyMM')

示例：
calculation_start_date = 2026-03-01
calculation_end_date   = 2026-08-31
profile_model_version = profile_202608
```

`profile_model_version` 跟计算窗口最后一个完整自然月走，不跟作业运行日期走。

### 2.5 主归属区域

跨区域消费会员只保留一个主归属区域。先对已通过第 3 章过滤的交易按 `customer_id + algorithm_region_code` 汇总，再按以下顺序逐层确定；上一层已经分出高低时不再比较下一层：

```text
region_active_days = COUNT(DISTINCT business_date)
region_ticket_cnt = COUNT(DISTINCT order_id)
region_sales_amt = ROUND(SUM(usual_amt), 2)
region_last_txn_time = MAX(inc_time)

1. region_active_days 降序；多 1 天即为更多
2. 天数相同，region_ticket_cnt 降序；多 1 张即为更多
3. 小票数相同，region_sales_amt 降序；多 0.01 元即为更多
4. 销售额相同，region_last_txn_time 降序；使用完整日期时间比较
5. 最近交易时间仍完全相同，algorithm_region_code 升序取第一名
```

同一天在多个算法区域消费时，该自然日在每个区域的 `region_active_days` 中各计 1 天；计算会员个人指标的全部有效消费天数时，仍按 `customer_id + business_date` 去重，该自然日只计 1 天。

跨区域交易与区域参数的职责必须严格分开：

```text
会员个人指标：使用华东范围内全部有效交易
区域模型训练分组：按会员唯一 primary_region 分组
会员正式贴标：使用 primary_region 对应的已发布参数
正式结果粒度：profile_model_version + customer_id，只输出一条
```

不得只使用主归属区域交易计算会员频次、时间行为、家庭规模或价格态度，也不得按多个区域为同一会员生成多条正式画像。

一个模型版本统一使用 `calculation_end_date` 当日有效的城市算法区域映射快照；窗口内历史交易全部按该快照映射。开发需保存本版本使用的映射生效日期或快照标识，保证重跑可复现。

区域参数不可用时统一回退：

```text
主归属算法区域参数
-> 华东整体参数
-> 该维度默认结果，置信度 = 低
```

默认结果：时间行为为 `常规时段型`、家庭规模为 `小家庭`、价格态度为 `价格非敏感`；消费频次不依赖区域模型，继续按会员真实有效消费天数计算。每次回退必须保存原主归属区域、实际参数区域、回退原因和 `fallback_flag = 1`。

页面筛选区域时只汇总已生成的固定标签，不在查询时重新训练或贴标。区域经营汇总按交易实际发生区域计算；同一跨区域会员可出现在多个区域视图，华东整体会员数必须按 `customer_id` 去重。多个区域视图不代表保存多条区域画像，而是同一条会员画像分别关联其在不同区域发生的交易。

### 2.6 前置维表：算法区域映射表

会员画像中的 `primary_region` 不是直接取城市字段，而是取“算法区域映射表”中的算法区域。

华东一期算法区域按城市归并，使用城市级映射即可，不需要门店级映射。业务已确认映射关系：

```text
上海 => 上海
杭州、宁波、绍兴 => 杭州宁波绍兴
苏州、常州、无锡 => 苏州常州无锡
```

正式映射必须由业务确认，开发不得在代码中写死城市分组规则。小票先通过 `store_id` 关联门店基础表取得城市，再通过本表取得算法区域。

建议落表：

```text
dim_city_algorithm_region
```

表粒度：

```text
一行 = 一个城市 + 一个算法区域映射生效周期
```

主键：

```text
city + effective_start_date
```

关联要求：

```text
Doris 小票商品明细表 store_id -> 门店基础表门店编码 -> 门店基础表城市 -> dim_city_algorithm_region.city。
algorithm_region_name 用于会员画像中的 primary_region、区域熵权、Jenks 阈值和逻辑回归参数训练。
```

| 中文字段名 | 英文字段名 | 类型建议 | 是否必须 | 字段来源 | 中文注释 |
|---|---|---|---|---|---|
| 城市 | `city` | varchar(64) | 必须 | `dim_city_algorithm_region` | 门店基础表中的城市，如上海、杭州、宁波、绍兴、苏州、常州、无锡 |
| 算法区域编码 | `algorithm_region_code` | varchar(64) | 必须 | `dim_city_algorithm_region` | 算法区域唯一编码，如 `SH`、`HZ_NB_SX`、`SZ_CZ_WX` |
| 算法区域名称 | `algorithm_region_name` | varchar(128) | 必须 | `dim_city_algorithm_region` | 算法训练与参数计算口径，如 `上海`、`杭州宁波绍兴`、`苏州常州无锡` |
| 生效开始日期 | `effective_start_date` | date | 必须 | `dim_city_algorithm_region` | 该映射开始生效日期 |
| 生效结束日期 | `effective_end_date` | date | 建议 | `dim_city_algorithm_region` | 当前有效映射可为空，历史映射回填结束日期 |
| 是否当前有效 | `is_active` | int | 必须 | `dim_city_algorithm_region` | `1` 当前有效，`0` 历史无效 |
| 映射确认人 | `confirmed_by` | varchar(64) | 建议 | `dim_city_algorithm_region` | 业务确认人 |
| 映射确认日期 | `confirmed_date` | date | 建议 | `dim_city_algorithm_region` | 业务确认日期 |
| 数据更新时间 | `data_update_time` | datetime | 必须 | `dim_city_algorithm_region` | 数据同步或维护时间 |
| 备注 | `remark` | varchar(255) | 建议 | `dim_city_algorithm_region` | 边界城市、临时调整说明 |

数据质量要求：

```text
1. 同一城市在同一日期只能命中一个有效算法区域。
2. 参与会员画像的小票 store_id 必须能先匹配到门店基础表城市。
3. 参与会员画像的门店城市必须全部能匹配到有效算法区域。
4. 算法区域名称必须稳定，不得同义混写，如“苏州常州无锡”和“苏锡常”不能混用。
5. 映射变化必须保留历史生效周期，不能直接覆盖旧映射。
```

业务已确认华东一期不存在同一城市内门店归属不同算法区域的例外，也不存在不参与会员画像计算的特殊门店。因此华东一期只建设城市级算法区域映射表，不建设门店级例外映射表。

## 3. 前置过滤

### 3.1 有效会员

```text
customer_id IS NOT NULL
AND is_customer = 1
AND customer_id NOT LIKE '6%'
```

`customer_id` 以 6 开头的记录属于非真实会员。`is_customer = 1` 用于确保只对会员交易贴画像。

### 3.2 有效交易明细

首先按 `order_item_id` 检查重复。若同一 `order_item_id` 存在多条记录，按 `update_time` 降序保留最新一条；`update_time` 仍相同时，完全相同的重复行可去重，字段不一致的重复行必须阻断正式发布并进入异常清单，不能随机保留。

去重后只保留：

```text
交易日期位于模型周期内
order_id 不为空
inc_time 不为空
order_status = 'os.completed'
is_return = 0
usual_amt > 0
weight > 0
article_id 不为空
```

剔除：

```text
退货
取消
冲销
测试交易（只有在开发确认可识别字段或枚举后才能正式过滤；未确认前进入异常清单，不得假设已过滤）
非正向销售记录
```

退货记录不计为一次消费，也不参与金额、频次和商品偏好计算。

POS、扫码购、自提、配送等正常渠道均参与画像，不使用 `sales_mode_id` 或 `online_flag` 排除正常交易。时间行为使用 `inc_time` 表示的订单发生时间；线上订单时间不解释为会员实际到店时间。开发验收必须按 `online_flag / sales_mode_id` 输出各时间画像的渠道分布，检查夜间线上订单是否异常放大晚高峰型或捡漏型。

历史交易是否参与只按交易发生当时的有效性和本模型窗口判断，不得因为门店当前已经闭店而删除历史有效交易。`dim_store.is_open` 和 `store_status_code` 仅作质量验收，不作为当前状态过滤条件。

`refund_type` 的具体枚举必须先用真实数据验收，不能仅因字段非空就删除已满足 `order_status = 'os.completed' AND is_return = 0` 的交易。所有时段判断统一使用 `inc_time`；`business_date` 应等于 `DATE(inc_time)`，不一致记录进入异常清单。

参与正式发布的有效交易 `article_id` 必须全部能匹配 `dim_sku.sku_id`，`store_id` 必须全部能匹配门店和算法区域。未匹配记录可以进入试算异常清单，但正式版本发布前必须补齐或有明确剔除清单，不能由各维度自行随机忽略。

### 3.3 异常会员日

按 `customer_id + business_date` 统计去重小票数：

```text
单日小票数 <= 5：保留
单日小票数 > 5：剔除该会员当日全部交易
```

5 张为业务固定阈值。会员其他日期的正常交易继续参与计算。输出中需保留异常天数、异常小票数和被剔除销售额。

## 4. 条件式画像与终止规则

时间行为必须先完成最终判定，再决定是否继续计算其他维度。

捡漏型为终止标签：

```text
time_behavior = 捡漏型
=> final_profile = 捡漏型
=> family_level = NOT_APPLICABLE
=> frequency_level = NOT_APPLICABLE
=> price_attitude = NOT_APPLICABLE
=> profile_terminal_flag = 1
```

捡漏型不区分大小家庭、不区分消费频次、不区分价格态度，也不得生成任何 `捡漏型-家庭-频次-价格态度` 组合标签。

上班族晚高峰型和常规时段型继续计算三个维度：

```text
final_profile =
time_behavior-family_level-frequency_level-price_attitude

profile_terminal_flag = 0
```

例如：

```text
上班族晚高峰型-小家庭-中频-价格非敏感
常规时段型-大家庭-高频-价格敏感
```

周末倾向和品类偏好只作辅助特征，不拼接到主画像名称中。

## 5. 通用熵权法

### 5.1 业务解释

熵权法用于决定多个行为指标的数据权重。某指标在会员之间差异越大，越能区分会员，权重越高。权重不由业务人员固定填写。

### 5.2 公式

对某个区域、某一类行为的 `N` 名会员，第 `j` 个指标的归一化值为 `x_ij`：

```text
p_ij = x_ij / SUM_i(x_ij)
e_j = -1 / ln(N) * SUM_i(p_ij * ln(p_ij))
d_j = 1 - e_j
w_j = d_j / SUM_j(d_j)
score_i = SUM_j(w_j * x_ij)
```

当 `p_ij = 0` 时，`p_ij * ln(p_ij)` 按 0 处理。

当某指标 `SUM_i(x_ij) = 0` 时，不执行除法，直接视为该指标无区分力：`d_j = 0`、`w_j = 0`。只有所有指标都无区分力时，才使用等权，并输出 `entropy_fallback_flag = 1`。

当区域有效会员数 `N < 2` 时，不计算区域熵权，直接回退到华东整体参数，并输出 `entropy_sample_fallback_flag = 1`。

时间行为指标本身为 0—1 占比，可直接使用。价格敏感的超额偏好指标经 P99 上限和对数处理后，再转换为 0—1。

当所有指标的 `SUM(d_j) = 0` 时，使用等权重，并输出：

```text
entropy_fallback_flag = 1
```

### 5.3 必须保存的参数

```text
profile_model_version
region
score_name
sample_member_cnt
metric_name
entropy_e
diversity_d
entropy_weight
entropy_fallback_flag
entropy_sample_fallback_flag
```

## 6. Jenks 自然断点

### 6.1 解决的问题

Jenks 自然断点在行为得分计算完成后，寻找普通行为组与高行为组之间的数据分界线。它不固定标签人数比例，也不使用人工固定分数。

### 6.2 开发计算

对已满足最低行为证据的会员得分排序，遍历每个相邻且得分不同的切分位置 `k`：

```text
SSE(k) =
SUM(score_i - mean_low)^2, i 属于普通组
+ SUM(score_i - mean_high)^2, i 属于高行为组
```

选择 `SSE(k)` 最小的切分位置；如果多个切分位置的 SSE 完全相同，选择产生较高 `jenks_threshold` 的切分位置：

```text
jenks_threshold =
(MAX(score_low_group) + MIN(score_high_group)) / 2
```

如果全部会员得分相同，或不存在相邻且得分不同的有效切分位置，则本区域 Jenks 断点无效，直接回退到华东整体参数。

### 6.3 有效性与回退

本区域断点必须同时满足：

```text
普通组会员数 >= 30
高行为组会员数 >= 30
(高组均值 - 低组均值) / 全体得分标准差 >= 0.5
当期阈值相对上一版本变化 <= 20%
```

当全体得分标准差为 0 时，组间差异不做除法，直接判定本区域断点无效。

阈值必须为正数。阈值小于等于 0 时，不执行得分除以阈值的相对强度计算，直接按断点无效处理。

阈值变化超过 20% 时不自动发布新版本，先检查数据完整性、映射和标记口径。

本区域断点无效时使用华东整体阈值。本区域和华东整体都无有效阈值时：

```text
时间行为默认为常规时段型
价格态度默认为价格非敏感
threshold_fallback_flag = 1
```

30 人、0.5 和 20% 为 V1 统计与运行控制参数，不是标签人数比例。

本算法中“上一级区域”统一指华东整体，不使用未冻结的管理区域或大区层级。所有需要区域参数回退的熵权、Jenks、家庭逻辑回归和价格态度参数均遵循：

```text
主归属算法区域参数
-> 华东整体参数
-> 该维度默认结果，置信度 = 低
```

参数表必须保存 `fallback_flag = 1`、`fallback_source_region = 华东整体` 或默认结果原因；解释表必须保存会员原主归属区域和实际使用的参数区域。

## 7. 时间行为算法

### 7.1 时间窗口

| 日期类型 | 时间 | 行为窗口 |
|---|---|---|
| 周一至周五 | 18:00 以前 | 常规时段 |
| 周一至周五 | 18:00 至 19:30:00，含 19:30:00 | 上班族晚高峰窗口 |
| 周一至周五 | 19:30:00 之后 | 捡漏窗口 |
| 周六、周日 | 19:30:00 及以前 | 常规时段 |
| 周六、周日 | 19:30:00 之后 | 捡漏窗口 |

捡漏行为不区分工作日与周末。上班族晚高峰只计算周一至周五。

V1 的“工作日”按自然星期一至星期五判断，不接入法定节假日和调休日历；自然周统一定义为星期一 00:00:00 至星期日 23:59:59。

### 7.2 晚高峰指标

```text
晚高峰消费天数占比 =
工作日 18:00—19:30:00 消费天数 / 全部有效消费天数

晚高峰小票占比 =
工作日 18:00—19:30:00 小票数 / 全部有效小票数

晚高峰销售额占比 =
工作日 18:00—19:30:00 销售额 / 全部有效销售额
```

按主归属区域分别使用熵权法生成 `commute_score`。

最低证据：

```text
晚高峰消费天数 >= 3
晚高峰消费覆盖自然月数 >= 2
```

候选标签：

```text
满足最低证据
AND commute_score >= commute_jenks_threshold
=> 上班族晚高峰候选会员
```

真实数据留出验证中，“至少 3 天且跨 2 月”相比“至少 2 天”，次月晚高峰延续率提升 6.88—9.61 个百分点。

### 7.3 捡漏指标

```text
19:30:00 后消费天数占比 =
19:30:00 后消费天数 / 全部有效消费天数

19:30:00 后小票占比 =
19:30:00 后小票数 / 全部有效小票数

19:30:00 后销售额占比 =
19:30:00 后销售额 / 全部有效销售额
```

时段折扣生鲜业态中，`19:30:00` 之后的消费直接视为捡漏行为，不再额外检查单品折扣字段。

按主归属区域分别使用熵权法生成 `bargain_score`。

最低证据：

```text
19:30:00 后消费天数 >= 3
19:30:00 后消费覆盖自然月数 >= 2
```

候选标签：

```text
满足最低证据
AND bargain_score >= bargain_jenks_threshold
=> 捡漏候选会员
```

真实数据留出验证中，“至少 3 天且跨 2 月”相比“至少 2 天”，次月捡漏行为延续率提升 2.67—2.92 个百分点。

### 7.4 时间行为冲突

```text
只命中晚高峰 => 上班族晚高峰型
只命中捡漏 => 捡漏型
两类都未命中 => 常规时段型
```

两类同时命中时：

```text
commute_relative_strength = commute_score / commute_jenks_threshold
bargain_relative_strength = bargain_score / bargain_jenks_threshold
```

只有对应断点为正数且有效时才计算相对强度；否则该行为视为未命中并进入回退规则。

相对强度高者为最终标签。当两者相差不超过 0.05 时，依次比较目标时段消费天数、覆盖自然月数；仍相同时捡漏型优先。

### 7.5 时间行为置信度

对最终命中的高行为类型，计算得分与断点的相对距离：

```text
G_time = (score - jenks_threshold) / jenks_threshold
```

```text
命中捡漏型或上班族晚高峰型，且 G_time >= 0.20
=> time_confidence = 高

命中捡漏型或上班族晚高峰型，但 G_time < 0.20
=> time_confidence = 中
```

常规时段型的置信度：

```text
晚高峰和捡漏均有足够行为证据，且两个得分均低于阈值 20% 以上
=> time_confidence = 高

至少一个行为满足最低证据，但没有同时满足“两个行为证据均足且两个得分均低于阈值 20% 以上”的高置信条件
=> time_confidence = 中

晚高峰和捡漏的最低行为证据都不足
=> time_confidence = 低
```

当本区域和华东整体都没有有效时间行为断点、触发 `threshold_fallback_flag = 1` 时，会员输出常规时段型，且 `time_confidence = 低`。

时间行为判定完成后立即执行终止规则：最终为捡漏型的会员不再进入第 8—10 章的家庭规模、消费频次和价格态度计算；最终为上班族晚高峰型或常规时段型的会员继续计算后续维度。

## 8. 家庭规模算法

本章只适用于最终时间行为为上班族晚高峰型或常规时段型的会员。捡漏型会员不参与家庭规模训练、预测和标签输出。

本章品类口径统一按第 8.3 节执行：蔬菜及家庭食材先用 `category_level1_code` 识别，小分类去重使用 `category_level3_code`。

### 8.1 业务含义

家庭规模是根据日常备餐型购物行为推断的消费规模，不是真实人口属性。直接规则只使用 19:00 前的蔬菜购买，避免时段折扣和囤货放大购买量。

### 8.2 第一层：直接规则

稳定行为证据：

```text
19:00 前蔬菜消费天数 >= 3
19:00 前蔬菜消费覆盖自然月数 >= 2
```

指标：

```text
商品行实际重量kg = weight * unit_weight_kg

19:00 前蔬菜总重量kg =
SUM(19:00 前蔬菜商品行实际重量kg)

日均蔬菜重量kg =
19:00 前蔬菜总重量kg / 19:00 前蔬菜消费天数

日均蔬菜 SKU 数 =
SUM(每个蔬菜消费日 COUNT(DISTINCT article_id)) / 蔬菜消费天数
```

`unit_weight_kg` 必须是商品基础表已经标准化后的“单个销售单位对应公斤数”，来源为 `dim_sku.unit_weight_kg`。原始 `dim_sku.unit_weight` 的物理单位必须由开发核实并在进入合同表时统一转换为 kg，不能未经确认直接使用。

换算样例：

```text
称重商品 weight = 0.8，unit_weight_kg = 1
=> 商品行实际重量 = 0.8kg

250g/袋商品购买 2 袋：weight = 2，unit_weight_kg = 0.25
=> 商品行实际重量 = 0.5kg

按斤计价商品购买 3 斤：weight = 3，unit_weight_kg = 0.5
=> 商品行实际重量 = 1.5kg
```

不得把件、盒、袋、份等计价数量直接当成 kg，也不得将无法确认单位的 `unit_weight` 数值直接参与公斤合计。

全华东使用统一固定阈值：

```text
日均蔬菜重量 >= 1.5kg
OR 日均蔬菜 SKU 数 >= 4
OR (日均蔬菜重量 >= 1.2kg AND 日均蔬菜 SKU 数 >= 3)
=> 大家庭，高置信度
```

满足稳定证据但未命中大家庭条件：

```text
AND 参与第一层判断的相关蔬菜商品行均能可靠换算为 kg
=> 小家庭，高置信度
```

重量缺失不会降低大家庭判定门槛，也不得被填 0：

```text
稳定证据满足
AND 已成功换算部分的日均蔬菜重量 >= 1.5kg
=> 大家庭，高置信度

稳定证据满足
AND 日均蔬菜去重 SKU 数 >= 4
=> 大家庭，高置信度

稳定证据满足
AND 已成功换算部分的日均蔬菜重量 >= 1.2kg
AND 日均蔬菜去重 SKU 数 >= 3
=> 大家庭，高置信度

稳定证据满足
AND 已知重量未命中重量条件
AND 存在无法换算 kg 的相关蔬菜商品行
AND 日均蔬菜去重 SKU 数 < 4
=> 第一层不能判定为高置信小家庭，进入第二层补充模型
```

第一层重量完整标记：

```text
veg_weight_expected_line_cnt =
COUNT(参与第一层重量计算的蔬菜商品行)

veg_weight_converted_line_cnt =
COUNT(其中 unit_weight_kg 可靠且成功换算的商品行)

veg_weight_unconvertible_line_cnt =
veg_weight_expected_line_cnt - veg_weight_converted_line_cnt

veg_weight_conversion_rate =
veg_weight_converted_line_cnt / veg_weight_expected_line_cnt

veg_weight_conversion_complete_flag =
CASE
  WHEN veg_weight_expected_line_cnt > 0
   AND veg_weight_unconvertible_line_cnt = 0 THEN 1
  ELSE 0
END
```

分母为 0 时 `veg_weight_conversion_rate = NULL`，不得写 100%。

### 8.3 第二层：购物篮补充模型

不满足第一层稳定蔬菜证据时，所有会员仍必须输出大或小家庭标签。使用主归属区域的逻辑回归模型补充判断。

输入指标均限定在 19:00 前：

```text
x1 = 19:00 前每票平均去重 SKU 数
   = SUM(每张有效小票 COUNT(DISTINCT article_id)) / 19:00 前有效小票数

x2 = 19:00 前平均购买重量kg / 票
   = 19:00 前全部商品实际重量kg / 19:00 前有效小票数

x3 = 19:00 前家庭食材平均去重 SKU 数 / 票
   = SUM(每张有效小票家庭食材 COUNT(DISTINCT article_id)) / 19:00 前有效小票数

x4 = 19:00 前家庭食材平均重量kg / 票
   = 19:00 前家庭食材实际重量kg / 19:00 前有效小票数

x5 = 19:00 前家庭食材平均去重品类数 / 票
   = SUM(每张有效小票家庭食材 COUNT(DISTINCT category_level3_code)) / 19:00 前有效小票数
```

家庭食材包括：

```text
蔬菜、肉禽蛋、猪肉、水产
```

品类识别与去重规则：

```text
is_vegetable = category_level1_code IN (蔬菜对应的大类编码)

is_household_food = category_level1_code IN (
  蔬菜、肉禽蛋、猪肉、水产对应的大类编码集合
)

x5 去重维度 = category_level3_code
```

V1 不强制新建完整品类映射表。开发首次上线前必须核对：上述四个业务品类均是独立、稳定的商品大类；没有相关商品落在其他大类；历史期间大类编码未变更、未复用。核对通过后，将当期实际大类编码值写入现有的 `dim_customer_profile_region_param`，不新建映射表：

```text
region_level = 华东整体
region_code = 华东整体固定编码
profile_dimension = family
param_group = category_scope

param_code = vegetable_level1_codes
param_value_text = 蔬菜大类编码的 JSON 字符串数组，例如 ["C01"]

param_code = household_food_level1_codes
param_value_text = 蔬菜、肉禽蛋、猪肉、水产大类编码的 JSON 字符串数组
```

两条配置均随 `profile_model_version` 保存；`sample_member_cnt = 0`、`sample_ticket_cnt = 0`、`fallback_flag = 0`。实际编码以上线前对 `dim_sku` 的核对结果为准，文档中的 `C01` 只是格式示例，不是真实业务编码。这样既不增加新表，又能保证同版本重跑可复现。

程序运行时不使用中文品类名称或商品名称模糊匹配。只有发现跨大类例外商品、大类编码调整或编码被重用时，才增加版本化的例外映射配置；例外配置不改变 `x5` 使用 `category_level3_code` 去重的公式。

消费频次、客单价和销售额不进入补充模型，避免把高活跃或高消费能力直接等同于大家庭。

`x2`、`x4` 必须使用与第一层相同的 kg 换算。参与第二层的商品存在无法换算重量时：

```text
family_weight_expected_line_cnt = COUNT(参与 x2 或 x4 重量计算的商品行)
family_weight_converted_line_cnt = COUNT(其中 unit_weight_kg 可靠且成功换算的商品行)
family_weight_unconvertible_line_cnt = family_weight_expected_line_cnt - family_weight_converted_line_cnt
family_weight_conversion_rate = family_weight_converted_line_cnt / family_weight_expected_line_cnt

family_weight_conversion_complete_flag =
CASE
  WHEN family_weight_unconvertible_line_cnt = 0 THEN 1
  ELSE 0
END

当 family_weight_conversion_complete_flag = 0：
x2 = NULL
x4 = NULL
不得以 0 代替缺失，不进入逻辑回归代入
family_level = 小家庭
family_confidence = 低
family_model_fallback_flag = 1
failure_reason = 单位重量信息不足
```

当 `family_weight_expected_line_cnt = 0` 时，`family_weight_conversion_rate = NULL`，但不存在应换算而未换算的商品行，因此完整标记为 1；没有 19:00 前有效小票时，五个原始指标仍按第 8.4 节记为 0。

这是证据不足时的保守兜底，不是大家庭规则放宽；任何重量缺失都不能直接产生大家庭结果。

### 8.4 指标预处理

对每个区域、每个模型版本分别处理：

```text
1. 只限制异常大值：X_cap = MIN(X, P99_region)
2. 对数转换：X_log = ln(1 + X_cap)
3. 标准化：X_std = (X_log - mean_region) / std_region
```

不对小值做 P1 提升。没有 19:00 前小票的会员，五个原始指标记为 0，不应被提升到 P1。

某指标在区域训练样本中的 `std_region = 0` 时，该指标无法区分会员，所有会员的该标准化值记为 0，并输出 `standardization_fallback_flag = 1`。

### 8.5 逻辑回归

训练样本只使用第一层高置信度会员，且五个模型输入均可完整计算、参与重量换算的商品行没有缺失：

```text
Y = 1：大家庭
Y = 0：小家庭
```

区域分别训练，使用 L2 约束和类别平衡权重。V1 固定使用标准化输入、L2 正则强度 `lambda = 1.0`；如果开发框架使用 `C` 参数，则使用 `C = 1.0`。最大迭代次数为 1000，收敛容差为 `1e-6`，参数和训练框架版本必须写入参数或运行审计：

```text
weight_large = N / (2 * N_large)
weight_small = N / (2 * N_small)
```

如果本区域的高置信度大家庭或小家庭训练样本少于 30 人，不训练本区域补充模型，使用华东整体已通过验收的模型参数。如果华东整体也无可用模型，证据不足会员输出小家庭、低置信度，并设置 `family_model_fallback_flag = 1`。

模型：

```text
Z = beta_0 + beta_1*x1_std + beta_2*x2_std + beta_3*x3_std + beta_4*x4_std + beta_5*x5_std
P_large = 1 / (1 + exp(-Z))
```

每个区域使用固定 `random_seed` 的分层 5 折交叉验证生成样本外概率。每一折的 P99、均值和标准差只使用该折训练集计算，再应用到该折验证集，不能使用全量样本预处理后再交叉验证。样本少于可完成 5 折分层的最低要求或任一类别无法分层时，不执行 5 折，直接按模型不可用回退。遍历 0.05—0.95、步长 0.01 的候选阈值：

```text
大家庭召回率 = TP / (TP + FN)
小家庭识别率 = TN / (TN + FP)
平衡准确率 = (大家庭召回率 + 小家庭识别率) / 2
```

选择平衡准确率最高的概率为区域阈值；并列时选择较高阈值。最后使用全部高置信度样本重新训练正式模型。

分层划分必须使用固定 `random_seed`，并将种子与模型版本一起保存，保证产研重复运行时可以复现相同阈值。

标签：

```text
P_large >= family_probability_threshold => 大家庭
P_large < family_probability_threshold => 小家庭
```

### 8.6 家庭规模置信度

第一层直接规则：

```text
family_confidence = 高
```

第二层计算概率相对阈值的归一化距离：

```text
当 P_large >= T：D = (P_large - T) / (1 - T)
当 P_large < T：D = (T - P_large) / T
```

```text
19:00 前有效消费天数 >= 3
AND 覆盖自然月数 >= 2
AND D >= 0.20
=> family_confidence = 中

其他第二层结果
=> family_confidence = 低
```

## 9. 消费频次算法

本章只适用于最终时间行为为上班族晚高峰型或常规时段型的会员。捡漏型会员不计算高频、中频或低频标签。

### 9.1 可观察月份

```text
observed_months =
从会员在当期的首次有效消费月
到模型周期结束月的自然月数，含首尾月
```

行为频次：

```text
monthly_shop_days_observed = 有效消费天数 / observed_months
```

同一会员同一日多张小票只计一个消费日。

### 9.2 最终频次标签

```text
monthly_shop_days_observed >= 8 => 高频
4 <= monthly_shop_days_observed < 8 => 中频
monthly_shop_days_observed < 4 => 低频
```

业务含义：

```text
8 天 / 月：约每周 2 次
4 天 / 月：约每周 1 次
```

最终标签不再与区域三等分混合。区域百分位和三等分只作辅助字段。

同时输出周期贡献频次：

```text
monthly_shop_days_full_period = 有效消费天数 / 6
```

该字段不覆盖最终频次标签。

## 10. 价格态度算法

本章只适用于最终时间行为为上班族晚高峰型或常规时段型的会员。捡漏型会员不参与价格态度基准、得分和标签计算。

### 10.1 时间与促销标记

只使用 19:00 前的常规促销行为，不使用 19:30 后时段折扣。

```text
discount_amt > 0 => 该商品行视为常规促销商品
```

`discount_amt` 只作促销标记，不直接求和。促销商品销售额使用该商品行的 `usual_amt`：

```text
促销商品销售额 = SUM(CASE WHEN discount_amt > 0 THEN usual_amt ELSE 0 END)
```

废止使用 `SUM(discount_amt) / SUM(usual_amt)`，防止单位差异或重复字段导致占比超过 100%。

### 10.2 同场景促销基准

优先在以下场景中比较：

```text
门店 + 自然周 + 商品小分类
```

场景按交易实际发生的门店、自然周和商品小分类确定；回退到算法区域时使用交易发生区域，不使用会员的 `primary_region` 替换交易区域。会员最终的价格参数仍按唯一 `primary_region_code` 读取。

自然周统一为星期一至星期日。促销标记严格按 `discount_amt > 0`；`discount_amt` 为空时不直接当作已确认的非促销，需纳入促销字段完整性检查。若促销字段口径或完整性未通过验收，价格态度统一输出价格非敏感、低置信度，不发布高、中置信价格标签。

基准样本必须满足：

```text
去重会员数 >= 10
去重小票数 >= 20
```

样本不足时依次回退：

```text
1. 门店 + 自然周 + 小分类
2. 区域 + 自然周 + 小分类
3. 区域 + 自然月 + 小分类
4. 区域 + 最近 6 个完整月 + 小分类
```

基准使用同场景其他非捡漏会员的平均值，目标会员不参与自身基准；排除目标会员后重新检查去重会员数和去重小票数门槛。输出 `baseline_level`、`baseline_member_cnt` 和 `baseline_ticket_cnt`。

如果某一级基准为 0，不进行除法，按门店周、算法区域周、算法区域月、算法区域 6 个月顺序继续回退。如果区域 6 个月小分类基准仍为 0，该场景不参与偏好指数汇总，并设置 `baseline_zero_flag = 1`。

### 10.3 促销偏好指数

在每个有效场景内：

```text
会员促销 SKU 占比 = 场景内会员促销去重 SKU 数 / 场景内会员全部去重 SKU 数
会员促销销售额占比 = 会员促销商品 usual_amt / 会员全部 usual_amt

同场景促销 SKU 基准 = 同场景其他非捡漏会员促销 SKU 占比的平均值
同场景促销销售额基准 = 同场景其他非捡漏会员促销销售额占比的平均值

场景 SKU 偏好指数 = 会员促销 SKU 占比 / 同场景促销 SKU 基准
场景销售额偏好指数 = 会员促销销售额占比 / 同场景促销销售额基准
```

跨场景汇总：

```text
最终 SKU 偏好指数 = SUM(场景 SKU 偏好指数 * 场景 SKU 数) / SUM(场景 SKU 数)
最终销售额偏好指数 = SUM(场景销售额偏好指数 * 场景销售额) / SUM(场景销售额)
```

如果会员没有任何有效促销比较场景，则不执行跨场景除法，两个最终偏好指数和价格敏感得分均记为 0，输出价格非敏感、低置信度，并设置 `price_scene_fallback_flag = 1`。

### 10.4 价格敏感得分

只保留高于同场景普通会员的部分：

```text
sku_excess = MAX(final_sku_preference_index - 1, 0)
sales_excess = MAX(final_sales_preference_index - 1, 0)
```

分区域做 P99 上限、对数处理和 0—1 归一化：

```text
x_cap = MIN(x, P99_region)
x_log = ln(1 + x_cap)
x_norm = x_log / MAX_region(x_log)
```

当 `MAX_region(x_log) = 0` 时，该指标的全部归一化值记为 0，并设置 `price_normalization_fallback_flag = 1`。

使用两个指标的区域熵权合成：

```text
price_sensitive_score = w_sku * sku_excess_norm + w_sales * sales_excess_norm
```

### 10.5 最低证据与标签

最低证据：

```text
19:00 前促销 SKU 数 >= 3
促销购买覆盖自然月数 >= 2
促销商品覆盖小分类数 >= 2
单一促销 SKU 销售额 / 全部促销商品销售额 <= 0.50
```

3 个 SKU 的数据来源：三个区域稳定促销会员的 P10 为 3—4 个 SKU；该阈值位于分布较低位置。

50% 集中度的数据来源：三个区域 P75 为 41.14%—45.56%，向上取统一、可解释的 50% 上限。

最终标签：

```text
四项最低证据全部通过
AND price_sensitive_score >= price_jenks_threshold
=> 价格敏感

其他
=> 价格非敏感
```

不要求 SKU 偏好指数和销售额偏好指数分别达到两个阈值，只使用一个熵权综合得分断点，避免过度收紧。

### 10.6 价格态度置信度

```text
G = ABS(price_sensitive_score - price_jenks_threshold) / price_jenks_threshold
```

只有 `price_jenks_threshold > 0` 时才计算 `G`；阈值小于等于 0 或无有效阈值时，价格态度直接按无有效断点回退，输出价格非敏感、低置信度。

```text
促销 SKU、月份、小分类和集中度证据齐全
AND G >= 0.20
=> 高置信度

四项证据均满足，但 G < 0.20
=> 中置信度

SKU、月份和小分类证据满足，但单一促销 SKU 集中度 > 0.50
=> 价格非敏感，中置信度

促销 SKU < 3、覆盖月份 < 2、覆盖小分类 < 2、无有效比较场景或无有效断点
=> 低置信度
```

价格敏感只允许中、高置信度。低置信度会员统一输出价格非敏感。

当本区域和华东整体都没有有效价格断点、触发 `threshold_fallback_flag = 1` 时，会员输出价格非敏感，且 `price_confidence = 低`。

## 11. 模型更新与标签稳定

### 11.1 月度正式版本

```text
1. 检查上月数据完整性
2. 使用最近 6 个完整月重新计算参数
3. 完成阈值稳定性、留出数据和人工抽样验收
4. 发布新模型版本
5. 全量更新会员画像
```

已有会员在同一模型版本内不因每日新增小票频繁换标。

版本和生效日期按以下公式生成：

```text
profile_model_version = 'profile_' + DATE_FORMAT(calculation_end_date, 'yyyyMM')
effective_start_date = calculation_end_date 所在月份的次月 1 日
```

示例：

```text
calculation_start_date = 2026-03-01
calculation_end_date   = 2026-08-31
profile_model_version = profile_202608
effective_start_date  = 2026-09-01
```

`effective_start_date` 表示该业务月份版本归属的生效起点，不表示新版本在当天已经可读。正式发布仍受 `published_flag` 控制：

```text
published_flag = 0：试算或待验收，下游不得读取
published_flag = 1：已验收发布，可供下游读取
```

`published_flag` 和 `published_at` 保存在 `dim_customer_profile_region_param`，作为同一 `profile_model_version` 四张正式输出表的统一发布控制。正式发布必须是原子操作：

```text
1. 四张表的 profile_model_version 完全一致。
2. 四张表均已完成写入并通过主键、行数和关联完整性检查。
3. 最后统一将该版本参数记录的 published_flag 置为 1，并写入同一 published_at。
4. 任一表未完成或验收失败时，published_flag 保持 0，四张表均不对下游可读。
```

同一版本参数表虽然有多行参数，但只能有一个版本级发布状态：该版本所有参数行的 `published_flag` 和 `published_at` 必须一致。开发可以复用调度平台已有批次控制记录，也可以按参数表聚合实现；不能出现同一版本部分参数已发布、部分参数未发布。

如果 `profile_202608` 到 2026-09-05 才通过验收并发布，则 2026-09-01 至 2026-09-04 仍读取上一已发布版本。参数表的 `published_at` 记录实际发布时间，用于还原当时下游真正可读的版本。

新完整月版本正式发布后：

```text
新版本 effective_end_date = NULL
上一版本 effective_end_date = 新版本 effective_start_date - 1 天
```

当前正式版本不按作业最后运行时间判断。开发必须先在参数表中筛选整个版本所有参数记录均满足 `published_flag = 1`、`published_at` 非空且完全一致的版本，再选择 `calculation_end_date` 最大的完整月版本。如果同版本参数记录的发布状态或发布时间不一致，该版本视为发布异常，不得供下游读取。重跑历史版本不得使其重新成为当前版本。

`effective_start_date / effective_end_date` 表示版本所属业务月的生效区间；`published_at` 表示实际开始允许下游读取的时间。查询某一历史时点实际使用的版本时，必须以 `published_at` 和当时的发布记录为准，不能只使用 `effective_start_date / effective_end_date` 倒推。

### 11.2 同窗口重跑和整批替换

同一计算窗口重跑时，`profile_model_version`、`calculation_start_date`、`calculation_end_date`、`effective_start_date` 和已有的 `effective_end_date` 保持不变。

同版本重跑采用“先完整计算成功，再整批替换”的统一规则：

```text
1. 在正式批次之外完整计算四张表的新结果。
2. 对新结果执行主键唯一、四表版本一致、行数和关联完整性检查。
3. 任一计算或检查失败时，保留原正式批次不动，本次重跑失败退出。
4. 全部成功后，在同一发布事务或具备同等原子性的发布步骤中，删除并替换四张正式表中该 profile_model_version 的原批次数据。
5. 不允许先删除原批次，再开始计算新结果。
6. 四张表必须同批替换，不允许只替换其中一张或部分会员。
7. effective_start_date、effective_end_date 和当前版本地位保持不变；updated_at 更新为本次写入时间。
8. 已经使用该 profile_model_version 的下游批次，按现有调度机制自动重跑。
```

重跑审计至少保存：

```text
profile_model_version
rerun_started_at
rerun_finished_at
rerun_reason
rerun_status
会员总数
新增会员数
删除会员数
final_profile 变化会员数
主归属区域变化会员数
区域参数和阈值变化数
画像汇总指标差异
是否触发下游重跑
```

如果已经有更新的完整月版本正式发布，历史版本重跑只能修正历史批次，不得回滚当前正式版本。

### 11.3 月中新会员

月中新会员定义为：当前已发布 `profile_model_version` 中不存在该 `customer_id`，且已产生至少 1 张有效小票的会员。月中新会员不并入该月度版本的正式四张表和正式汇总，而是写入独立的补充画像结果区；下月全量版本再写入正式四张表。

增量贴标规则：

```text
1. 使用该会员截至补充处理日已有的华东全部有效交易。
2. 按第 2.5 节确定唯一主归属区域。
3. 只读取当前已发布版本的区域参数，不重新训练熵权、Jenks、逻辑回归或价格基准。
4. is_incremental_new_member = 1；补充画像不计入月度正式汇总和正式版本验收。
5. 所有适用维度置信度统一输出低；捡漏型的不适用维度仍写 NOT_APPLICABLE。
6. 同一正式版本内第一次补充贴标后，不因每日新增小票频繁换标；补充画像独立于月度正式四张表维护。
7. 下一个月度全量版本统一重算，并写 is_incremental_new_member = 0。
8. 增量贴标不自动改变已完成的正式下游批次；下游明确需要时才读取补充画像。
```

必须保存：

```text
profile_model_version
calculation_start_date
calculation_end_date
effective_start_date
effective_end_date
previous_final_profile
final_profile
profile_change_reason
is_incremental_new_member
incremental_observation_start_date
incremental_observation_end_date
```

月中新会员的时间、家庭和频次指标使用补充处理日已有的有效交易；价格态度只读取当前已发布版本已经冻结的同场景促销基准和区域参数，不使用月中新增会员重新计算基准样本。

调度或发布审计中还必须保存：

```text
published_flag
published_at
重跑时间
重跑原因
重跑前后差异数量
是否触发下游重跑
```

## 12. 标签应用与汇总

会员标签生成后，其全部有效消费记录都使用这套固定标签，不只统计用于判断标签的目标时段或促销商品。

```text
会员数占比 = 该画像去重会员数 / 分析范围去重会员总数
销售额占比 = 该画像会员全部有效销售额 / 分析范围会员全部有效销售额
小票数 = 该画像会员全部有效小票数
客单价 = 该画像会员销售额 / 该画像会员小票数
```

区域查询时，使用在所选区域发生的交易汇总固定标签。同一跨区域会员可能分别出现在多个区域视图中，但华东汇总必须按 `customer_id` 去重，不能直接将各区域会员数相加。

### 13.6 缺失和降级写法

输出表统一按以下规则处理缺失、不适用和降级：

```text
1. 主键字段、模型版本、会员 ID、区域编码和生效日期不能为空；无法形成主键的记录不得写入正式结果表。
2. 捡漏型会员的家庭规模、消费频次和价格态度统一写 NOT_APPLICABLE，不得写空值或 0。
3. 参数、阈值或训练样本不足时，先使用华东整体已发布参数；仍不可用时使用本算法规定的默认低置信度结果，并在解释表或参数表中写 `fallback_flag = 1`。
4. 使用回退参数的会员必须保存主归属区域、实际参数区域、原始指标和回退原因，置信度按对应维度规则降为中或低。
5. 指标无观测、分母为 0 或不适用时，除正文公式明确要求写 0 的场景外，不得用 0 代替缺失；应写 null，并在 failure_reason、param_group 或解释指标中说明。
6. 家庭规模重量字段无法完整换算时，按第 8 章执行保守降级：不得将缺失重量填 0，不得因此产生大家庭；第一层不得输出小家庭高置信度，第二层无法完整计算时输出小家庭低置信度并记录原因。
7. 月中新会员只使用已发布参数增量贴标，不重新训练阈值；结果只写独立补充画像结果区，所有适用维度置信度为低，下一次月度全量版本统一重算。
8. 汇总表按已发布画像结果聚合；区域维度缺失导致无法归属时，不并入华东整体汇总，开发交付时需输出未归属记录数用于验收。
```

## 14. 计算样例

以下数字为计算路径示例，用于说明算法判定过程，帮助开发实现和业务验收，不代表生产模型真实参数。

### 14.1 案例 A：捡漏型

输入概要：

```text
主归属区域：上海
可观察月份：6
有效消费天数：60
19:30 后消费：12 天，覆盖 4 个月
晚高峰消费：2 天
```

计算：

```text
捡漏证据通过，bargain_score = 0.58，区域断点 = 0.44 => 捡漏候选
晚高峰天数不足 => 不是晚高峰候选
最终时间行为 = 捡漏型 => 命中终止规则
家庭规模、消费频次和价格态度不再计算，统一为 NOT_APPLICABLE
```

结果：

```text
捡漏型
```

### 14.2 案例 B：上班族晚高峰型-小家庭-中频-价格非敏感

输入概要：

```text
主归属区域：杭州宁波绍兴
可观察月份：6
有效消费天数：30
工作日晚高峰：8 天，覆盖 4 个月
19:30 后消费：1 天
19:00 前蔬菜：6 天，日均 0.85kg，日均 1.7 个 SKU
促销行为证据齐全，但促销偏好接近同场普通会员
```

计算：

```text
晚高峰证据通过，commute_score = 0.68，区域断点 = 0.43 => 晚高峰候选
捡漏证据不足 => 不是捡漏候选
稳定蔬菜证据齐全但未命中大家庭阈值 => 小家庭，高置信度
行为频次 = 30 / 6 = 5 天 / 月 => 中频
price_score = 0.17，区域断点 = 0.27 => 价格非敏感
```

结果：

```text
上班族晚高峰型-小家庭-中频-价格非敏感
```

### 14.3 案例 C：月中新会员的补充判断

输入概要：

```text
首次有效消费：模型周期的最后 1 个月
可观察月份：1
有效消费天数：2
无稳定晚高峰或捡漏证据
无稳定蔬菜证据
促销 SKU：1 个
```

家庭补充模型计算示例：

```text
标准化购物篮指标 = [0.20, 0.40, 0.30, 0.50, 0.10]
示例系数 beta = [-0.60, 0.40, 0.50, 0.30, 0.40, 0.20]

Z = -0.60 + 0.40*0.20 + 0.50*0.40 + 0.30*0.30 + 0.40*0.50 + 0.20*0.10
  = -0.01
P_large = 1 / (1 + exp(0.01)) = 0.4975
区域概率阈值 = 0.58
=> 小家庭，低置信度
```

其他维度：

```text
时间行为 => 常规时段型
行为频次 = 2 / 1 = 2 天 / 月 => 低频
促销证据不足 => 价格非敏感，低置信度
```

结果：

```text
常规时段型-小家庭-低频-价格非敏感
```

示例系数只用于说明代入过程，生产计算必须读取区域模型参数表。

### 14.4 案例 D：跨区域会员只输出一条画像

输入概要：

```text
上海：有效消费 12 天、18 张小票、销售额 900.00 元
杭州宁波绍兴：有效消费 11 天、25 张小票、销售额 1,600.00 元
其中 1 个自然日在两个区域都消费
```

计算：

```text
主归属区域按第一层“区域有效消费天数”比较：上海 12 天 > 杭州宁波绍兴 11 天
=> primary_region = 上海

个人有效消费天数：使用两个区域全部有效交易，跨区域同一自然日只记 1 天
时间、家庭、频次、价格指标：使用两个区域全部有效交易计算
熵权、断点、家庭模型和价格参数：读取上海参数
正式结果：profile_model_version + customer_id 只写 1 条
```

即使杭州宁波绍兴的小票数和销售额更多，也不能越过第一层消费天数改成该区域。

### 14.5 案例 E：蔬菜重量缺失时的保守降级

输入概要：

```text
19:00 前蔬菜消费 4 天，覆盖 2 个月
日均去重蔬菜 SKU 数 = 3.2
已成功换算部分的日均蔬菜重量 = 1.0kg
另有 2 行蔬菜商品缺少可靠 unit_weight_kg
```

计算：

```text
稳定证据满足
已知重量未达到 1.2kg 或 1.5kg
日均 SKU 数未达到 4
veg_weight_conversion_complete_flag = 0
=> 第一层不能判小家庭、高置信度，进入第二层

如果第二层需要的家庭食材重量仍不完整：
x2、x4 = NULL
family_level = 小家庭
family_confidence = 低
family_model_fallback_flag = 1
failure_reason = 单位重量信息不足
```

该结果表示证据不足的保守兜底，不表示已经证明会员属于小家庭。

### 15.4 次月行为延续率验收

次月行为延续率是画像稳定性的验收与监控指标，不写入 `dim_customer_profile` 会员级正式字段。开发可将计算结果保存到验收过程表或验收报告，但不作为后续选品算法的正式输入。

#### 15.4.1 验证月份与固定标签

```text
validation_month_start = calculation_end_date 所在月份的次月 1 日
validation_month_end = validation_month_start 所在月份的月末
```

示例：

```text
profile_model_version = profile_202608
calculation_end_date = 2026-08-31
validation_month = 2026-09-01 ~ 2026-09-30
```

验证时必须固定使用被验证版本已经生成的 `time_behavior`，不使用验证月数据重新训练熵权、Jenks 断点或重新生成完整画像。

验证月交易必须复用第 3 章的有效会员、有效交易和异常会员日过滤规则。月中增量贴标会员 `is_incremental_new_member = 1` 不并入月度全量版本的主验收指标，需单独统计。

延续率必须先按被验证版本中的 `primary_region` 分区域计算。会员的验证月行为使用其验证月全部有效交易，不因交易发生在其他区域而删除；分组区域仍固定使用原画像版本的 `primary_region`，不在验证月重新计算主归属区域。

华东整体结果必须使用各区域的分子、分母汇总后重新计算，不得对各区域比率做算术平均。

#### 15.4.2 晚高峰型延续率

```text
commute_source_member_cnt =
COUNT(DISTINCT customer_id)
WHERE 原版本 time_behavior = '上班族晚高峰型'

commute_active_member_cnt =
原晚高峰型会员中，验证月至少有 1 笔有效交易的去重会员数

commute_continued_member_cnt =
上述活跃会员中，验证月至少有 1 个工作日在
18:00:00 <= sale_time <= 19:30:00 发生有效消费的去重会员数

commute_next_month_active_rate =
commute_active_member_cnt / commute_source_member_cnt

commute_next_month_continuation_rate =
commute_continued_member_cnt / commute_active_member_cnt

commute_next_month_overall_continuation_rate =
commute_continued_member_cnt / commute_source_member_cnt
```

`commute_next_month_continuation_rate` 是默认所说的“次月晚高峰延续率”。

#### 15.4.3 捡漏型延续率

```text
bargain_source_member_cnt =
COUNT(DISTINCT customer_id)
WHERE 原版本 time_behavior = '捡漏型'

bargain_active_member_cnt =
原捡漏型会员中，验证月至少有 1 笔有效交易的去重会员数

bargain_continued_member_cnt =
上述活跃会员中，验证月至少有 1 天在
sale_time > 19:30:00 发生有效消费的去重会员数

bargain_next_month_active_rate =
bargain_active_member_cnt / bargain_source_member_cnt

bargain_next_month_continuation_rate =
bargain_continued_member_cnt / bargain_active_member_cnt

bargain_next_month_overall_continuation_rate =
bargain_continued_member_cnt / bargain_source_member_cnt
```

`bargain_next_month_continuation_rate` 是默认所说的“次月捡漏延续率”。

#### 15.4.4 常规会员对照组

在每个 `primary_region` 内，对 `time_behavior = '常规时段型'` 的会员分别使用同样的活跃分母计算：

```text
regular_source_member_cnt =
原版本同一 primary_region 内 time_behavior = '常规时段型'
的去重会员数

regular_active_member_cnt =
上述常规会员中，验证月至少有 1 笔有效交易的去重会员数

regular_commute_behavior_member_cnt =
上述常规活跃会员中，验证月至少有 1 个工作日
在 18:00:00~19:30:00 消费的去重会员数

regular_bargain_behavior_member_cnt =
上述常规活跃会员中，验证月至少有 1 天
在 19:30:00 之后消费的去重会员数

regular_commute_behavior_rate =
regular_commute_behavior_member_cnt / regular_active_member_cnt

regular_bargain_behavior_rate =
regular_bargain_behavior_member_cnt / regular_active_member_cnt
```

验收方向：

```text
commute_next_month_continuation_rate > regular_commute_behavior_rate
bargain_next_month_continuation_rate > regular_bargain_behavior_rate
```

提升百分点公式：

```text
commute_continuation_lift_percentage_point =
(commute_next_month_continuation_rate - regular_commute_behavior_rate) * 100

bargain_continuation_lift_percentage_point =
(bargain_next_month_continuation_rate - regular_bargain_behavior_rate) * 100
```

历史验证中的 `6.88~9.61` 和 `2.67~2.92` 个百分点只作历史参考，不作为每月固定验收门槛。如果目标画像的延续率不高于常规对照率，输出规则复核结论，不直接修改当前版本会员标签。

#### 15.4.5 验收记录和异常处理

验收过程表或验收报告至少保存：

```text
profile_model_version
primary_region
validation_month_start
validation_month_end
behavior_type
source_member_cnt
active_member_cnt
continued_member_cnt
next_month_active_rate
next_month_continuation_rate
next_month_overall_continuation_rate
regular_behavior_rate
regular_source_member_cnt
regular_active_member_cnt
regular_behavior_member_cnt
continuation_lift_percentage_point
sample_status
validation_conclusion
diagnostic_reason
```

字段取值：

| 字段 | 允许取值 | 含义 |
|---|---|---|
| `behavior_type` | `COMMUTE` / `BARGAIN` | 晚高峰延续率 / 捡漏延续率 |
| `sample_status` | `SUFFICIENT` / `SMALL_SAMPLE` / `NO_SAMPLE` | 目标画像和常规对照组的活跃样本均充足 / 任一组活跃样本小于 30 / 任一组无可计算样本 |
| `validation_conclusion` | `WAITING_FULL_MONTH` | 验证月尚未完整结束 |
| `validation_conclusion` | `DATA_INCOMPLETE` | 验证月数据不完整 |
| `validation_conclusion` | `NOT_CALCULABLE` | 分母为 0，无法计算比率 |
| `validation_conclusion` | `DIRECTION_PASSED` | 目标画像延续率高于同区域常规会员对照率 |
| `validation_conclusion` | `REVIEW_REQUIRED` | 目标画像延续率低于或等于同区域常规会员对照率 |

异常处理：

| 场景 | 验收结论 | 处理 |
|---|---|---|
| 验证月尚未结束 | 等待完整月 | 不提前输出正式延续率 |
| 验证月数据不完整 | 数据不完整 | 不发布该月验收结论 |
| `source_member_cnt = 0` 或 `active_member_cnt = 0` 或 `regular_active_member_cnt = 0` | `validation_conclusion = NOT_CALCULABLE` | 无法计算的比率写 `NULL`，保留目标组、对照组的分子、分母和原因 |
| `active_member_cnt < 30` 或 `regular_active_member_cnt < 30` | `sample_status = SMALL_SAMPLE` | 正常输出分子、分母和比率，但不单独据此判定规则失败 |
| 延续率高于常规对照率 | 方向通过 | 保留差值和样本量 |
| 延续率低于或等于常规对照率 | 需要复核 | 检查数据完整性、时段规则、样本量和阈值变化，不自动改标签 |

发布前使用已经完整的历史月做留出回测；发布后等真实次月完整结束后做持续监控。真实次月延续率不阻塞当月画像正常产出。
