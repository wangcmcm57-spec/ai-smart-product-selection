## 1. 算法目标

本算法用于识别同一城市算法区域、同一品类下，不同门店的品类经营承载能力。

输出结果供后续算法读取：

```text
门店群消费者画像贡献算法
目标画像 SKU 表现算法
新品候选标准化与合并算法
新品机会证据合成与风险门禁算法
新品推荐优先级与开发需求编排
```

本算法只回答：

```text
同一城市算法区域、同一品类下，哪些门店更适合承接新品、扩 SKU 和做试点？
```

本算法不做：

```text
全店综合等级
跨品类门店比较
商品订购量预测
独立促销因果分析
独立损耗诊断报告
大模型实时评分
```

## 3. 计算周期、版本与开发执行流程

算法 02 按月离线批量计算。系统先从全链路调度取得 `algorithm_batch_version（统一算法批次版本）`，锁定该批次共用的城市算法区域映射快照和运行规则；再使用最近 3 个完整自然月生成正式等级，并使用截至同一结束月份的最近 6 个完整自然月进行参数训练、回退和稳定性参考。

业务和采购不需要页面点击或人工放行。业务通过数据库查看候选参数、系统自动发布的参数、运行审计和 `mart_store_category_level`；前端和后续算法只读取已发布结果，不在查询时实时重算等级。采购侧筛选城市、品类或门店等级时，只过滤已计算结果，不作为算法输入事实。

开发执行顺序必须固定为：

```text
1. 锁定 algorithm_batch_version、calculation_start_date、calculation_end_date、parameter_reference_start_date、parameter_reference_end_date、source_data_version 和 run_id。
2. 首次运行按 algorithm_batch_version 生成 dim_algorithm_batch_city_region_snapshot；同批次重跑只读取原快照，禁止重新读取最新区域映射。
3. 校验算法 01、02 共用的会员过滤公共实现、固定验收样例、批次配置和输入表合同；首次运行形成待发布的批次配置快照，同批次重跑读取已发布的原快照。
4. 先产出明细去重、有效交易、会员有效交易、日门店 SKU、到店金额汇总和门店品类指标过程表。
5. 先枚举全部季节窗口、售罄区间和损耗阈值候选，再执行样本、稳定性、分母和字段口径质量门；系统自动排序，形成运行级待发布参数，不等待业务确认。
6. 暂存计算只读取本次运行中各选参组唯一的待发布入选参数；同批次重跑则读取原 `AUTO_PUBLISHED（系统自动发布）`正式参数。完成七个维度、CRITIC、Jenks/BIC、底线修正和质量状态，并先写运行级暂存结果。
7. 正式发布前逐字段校验暂存结果、待发布记录、批次配置快照、城市区域映射、自动入选参数和 `algorithm_batch_version（统一算法批次版本）`一致；首次运行以同一事务或等价原子步骤提交本批次正式参数、`mart_store_category_level（门店品类等级正式结果表）`和运行发布记录。同批次重跑保持原正式参数不变，只原子替换结果并更新发布记录。失败时已发布正式参数、结果和 `AUTO_PUBLISHED（系统自动发布）`记录均不改变。
8. 业务和采购查询数据库中的候选、入选参数、运行审计和正式结果；查询动作不触发重算。
```

### 3.1 共享范围快照与 CITY / CITY_CLUSTER 判定

`dim_city_algorithm_region` 是区域映射的历史源表；`dim_algorithm_batch_city_region_snapshot` 是算法 01～算法 10 在同一 `algorithm_batch_version（统一算法批次版本）` 下共同读取的不可变城市映射快照，不是每个算法各自生成的临时表。

首次运行的固定顺序：

```text
dim_store.city_name
-> dim_city_algorithm_region.city
-> 按计算周期和生效日期筛选唯一映射
-> 按 algorithm_region_code 聚合城市集合
-> 判定 scope_type
-> 按调度传入的 algorithm_batch_version 写入 dim_algorithm_batch_city_region_snapshot
```

快照写入必须使用事务或等价的原子发布方式，不能出现只有部分城市的 `PUBLISHED` 快照。同一批次重跑只读取该批次快照；区域调整默认从下一批次生效。

同一 `algorithm_batch_version + algorithm_region_code` 下：

```text
COUNT(DISTINCT city) = 1 -> scope_type = CITY
COUNT(DISTINCT city) > 1 -> scope_type = CITY_CLUSTER
scope_id = algorithm_region_code
scope_name = algorithm_region_name
```

示例：

```text
SH       -> 上海                    -> CITY         -> scope_id = SH
HZ_NB_SX -> 杭州、宁波、绍兴        -> CITY_CLUSTER -> scope_id = HZ_NB_SX
SZ_CZ_WX -> 苏州、常州、无锡        -> CITY_CLUSTER -> scope_id = SZ_CZ_WX
```

同一城市在同一快照中命中 0 条或超过 1 条有效映射时，阻断受影响范围；不能跨区域回退。区域映射退出时不得物理删除历史记录，应回填 `effective_end_date`、置为历史失效并新增后续生效记录。`is_active` 只用于源表数据质量筛选，历史重跑不再读取它，而是读取已发布快照。

### 3.2 共享会员过滤规则

算法 02 不读取 `dim_customer_profile（会员画像结果表）`。算法 01、02 必须调用同一份会员过滤公共实现，并以本节固定验收样例验证实现结果。会员过滤条件不是运行时可选参数，不建立独立注册表，也不生成独立规则版本号或规则实现摘要；算法 02 的唯一业务版本是 `algorithm_batch_version（统一算法批次版本）`。

V1 规则固定为：

```text
customer_id 不为空
is_customer = 1
customer_id 不以 6 开头
有效交易按 order_status = 'os.completed'、is_return = 0、usual_amt > 0、weight > 0 过滤
同一会员单日有效小票数 > 5 时，剔除该会员当天全部有效交易
```

算法 01 与算法 02 共用的确定性实现为：

```sql
-- 先按 order_item_id 去重并保留可参与计算的有效交易
valid_txn AS (
  SELECT *
  FROM dedup_order_item
  WHERE order_status = 'os.completed'
    AND is_return = 0
    AND usual_amt > 0
    AND weight > 0
),
member_day_ticket AS (
  SELECT customer_id, business_date, COUNT(DISTINCT order_id) AS ticket_cnt
  FROM valid_txn
  WHERE customer_id IS NOT NULL
    AND is_customer = 1
    AND customer_id NOT LIKE '6%'
  GROUP BY customer_id, business_date
),
member_valid_txn AS (
  SELECT v.*
  FROM valid_txn v
  LEFT JOIN member_day_ticket d
    ON v.customer_id = d.customer_id
   AND v.business_date = d.business_date
  WHERE v.customer_id IS NOT NULL
    AND v.is_customer = 1
    AND v.customer_id NOT LIKE '6%'
    AND COALESCE(d.ticket_cnt, 0) <= 5
)
```

算法 02 对会员指标只使用上述公共实现产生的 `member_valid_txn（有效会员交易集）`；销售、货盘、毛利和损耗等非会员指标仍使用有效交易全集。画像月份或 `dim_customer_profile（会员画像结果表）`的任何字段变化都不会改变本批次。

会员过滤条件的变更规则：

```text
会员过滤条件只以算法卡正式规则、公共实现和固定验收样例为准，不允许开发自行修改。
条件变化时必须同步修改算法 01、算法 02 的算法卡、公共实现和验收样例，并从下一个 `algorithm_batch_version（统一算法批次版本）` 生效。
同一 `algorithm_batch_version（统一算法批次版本）` 内，算法 01、02 必须使用同一份公共实现。
历史批次重跑继续使用原批次配置快照和原代码发布记录对应的公共实现，不得用新规则覆盖旧结果。
```

### 5.1.1 促销折扣口径

`promotion_discount_scope（促销折扣口径）`用于说明 `discount_amt（总优惠金额）`是否已经包含时段折扣。当前 V1 已按数据合同和开发确认结果固定为：

```text
promotion_discount_scope = TOTAL_DISCOUNT_INCL_TIME
```

系统必须把该固定值自动写入批次配置快照、促销代理参数表和正式结果血缘，不需要业务或开发在运行前选择、登记、确认或审批。当前公式含义为：

```text
discount_amt（总优惠金额）包含 time_period_discount_amt（时段折扣金额）
regular_discount_amt（常规优惠金额）
= MAX(discount_amt - time_period_discount_amt, 0)
```

`REGULAR_DISCOUNT_ONLY（总优惠仅含常规优惠）`和 `UNKNOWN（口径未知）`只作为历史兼容枚举保留，当前 V1 批次不得写入。未来若数据合同正式改变，必须从新的 `algorithm_batch_version（统一算法批次版本）`同步修改公式和批次配置快照；不得在同一批次只改字符串。字段缺失或实际数据不满足包含关系时，促销健康按第 10.6 节写空并标记 `promotion_confidence=DATA_INSUFFICIENT（促销健康数据不足）`，不能临时切换枚举或根据数值组合反推字段含义。

### 5.1.1.1 促销字段物理口径与聚合边界

以下字段必须按各自的物理粒度使用，不能把 Doris 累计字段和毛利损耗表日粒度字段混为同一个金额：

| 逻辑字段 | 正式来源 | 物理粒度 | 算法用途 | 聚合限制 |
|---|---|---|---|---|
| `discount_amt`（总优惠金额） | `data_agent.dws_member_order_item_detail_df_all_new.discount_amt` | 商品行；候选唯一键为 `order_item_id` | 19 点前标准销售额代理和促销对账 | 先按 `order_item_id` 去重，再按有效交易过滤；当前 V1 按登记口径解释为包含时段折扣 |
| `hour_discount_amt`（会员同小时累计优惠金额） | `data_agent.dws_member_order_item_detail_df_all_new.hour_discount_amt` | 会员 + 业务日期 + 同小时累计，不是商品行金额 | 仅作时段优惠辅助校验和解释 | 禁止按商品行直接 `SUM`，不能与日粒度时段折扣金额直接相加 |
| `is_hour_promotion`（是否命中时段促销） | `data_agent.dws_member_order_item_detail_df_all_new.is_hour_promotion` | 商品行标记 | 识别时段促销销售行 | 1 必须来自已登记的配置/ETL 规则；不得用 `inc_time >= 19:00:00` 代替 |


```text
门店商品日价格表包含仓属性和验收商品编码。进入算法前必须按数据合同主键
`business_date + store_id + sku_id + receipt_sku_id` 做唯一性校验；同一主键重复时，无论金额是否一致都阻断发布并回到基础表修复，禁止随机取一条、取 `MAX` 或按仓重复求和。

唯一性通过后，再汇总到：

business_date + store_id + sku_id

汇总公式：

outbound_arrival_amt_tax_included =
SUM(各验收商品唯一记录的 outbound_arrival_amt_tax_included)

仓编码、验收商品编码及对应金额明细保留在过程解释表中，再将日门店销售 SKU 汇总结果与毛利损耗表关联。
```

原因：

```text
同一个销售商品编码可能对应多个验收商品编码，仓编码是追溯属性。如果不先按合同唯一键验重并聚合，直接按销售商品编码关联，可能重复放大到店金额。
```

## 6. 有效数据过滤

### 6.1 有效交易

```text
商品可以关联到商品基础表正式品类
```

`order_status = 'os.completed'`、`is_return = 0`、`usual_amt > 0` 和 `weight > 0` 是 V1 与算法 01 对齐的正常交易组合。`refund_type` 在 V1 仅作质量审计字段，不单独增加一套与算法 01 不一致的过滤；如果后续确认完成交易中仍含应剔除的退款枚举，必须同步修改算法卡、公共实现和固定验收样例，并从下一个 `algorithm_batch_version（统一算法批次版本）`生效，不能由开发原地改写历史批次。测试、取消、冲销只有在源表已注册对应状态字段和枚举后才允许加入新规则；当前未注册的异常状态必须进入数据质量阻断，不能由开发自行猜测。

销售额和小票数统计全量有效消费，不因为 `customer_id` 为空而删除。

### 6.2 有效会员

会员指标复用算法 01 与算法 02 共用的会员过滤公共实现；算法 02 不读取 `dim_customer_profile（会员画像结果表）`，因此不引用画像数据版本，也不记录独立会员过滤版本：

```text
customer_id 不为空
customer_id 不以 6 开头
is_customer = 1
按已冻结的有效交易条件过滤：`order_status = 'os.completed'`、`is_return = 0`、`usual_amt > 0`、`weight > 0`
同一会员单日有效小票数 > 5 时，剔除该会员当天全部记录
```

算法 01 画像标签变化但会员过滤条件未变时，不影响算法 02。会员过滤条件调整时，算法 01、02 的算法卡、公共实现和固定验收样例必须同步更新，并从下一个 `algorithm_batch_version（统一算法批次版本）`生效；同一批次不得混用两套会员口径，历史批次继续使用原 `code_release_id（代码发布记录ID）`对应的实现。

### 6.3 有效营业日

有效营业日不是确认“门店知不知道营业”，而是确认算法分母来源。

严格口径：

```text
门店当天正常营业
AND 该门店品类有正式可售条件
AND 当天交易、货盘、进货数据已完整入库
```

“数据完整入库”必须由运行前的源数据质量检查给出确定结果：交易、可订可售、毛利损耗、到货价格四张输入表在该营业日均存在对应分区/快照，且通过各自主键唯一性检查。缺少任一表、分区或唯一性检查失败时，该日不计入有效营业日，并写入运行质量问题表；不得把缺失日当作 0 销售日。

V1 默认实现：

```text
dim_store.is_open = 1
AND 门店商品每日可订可售表中，该门店该品类当天至少 1 个 SKU is_saleable = 1
AND 当天交易、货盘、到货数据完整入库
```

`store_status_code` 到 `is_open` 的映射属于 `dim_store` 数据合同交付。算法不得自行维护第二套状态码白名单；无法映射的状态码进入补数清单，对应门店当天不进入正式计算。

这样可以保留“营业但该品类 0 销售”的日期，避免日均销售、日均小票和动销率被抬高。

仅当门店商品每日可订可售表暂未交付时，才允许降级：

```text
用该门店当天有任一有效销售交易作为有效营业日
business_day_rule_degraded_flag = 1
```

降级风险：

```text
0 销售日会被漏掉，日均指标可能偏高。
```

### 6.4 有效在售 SKU 日

V1 默认实现：

```text
门店商品每日可订可售表 is_saleable = 1
AND 实际进货数量 > 0 或 实际进货重量 > 0
```

当净进货量 `<= 0`：

```text
不计算该 SKU 日售罄率
不计入有效在售 SKU 日
不填 0
不视为未动销
```

售罄异常：

```text
计件商品：pre19_sales_qty / receipt_qty > 1.10
称重商品：pre19_sales_weight_kg / receipt_weight_kg > 1.10
=> sell_through_abnormal_flag = 1
```

售罄异常 SKU 日：

```text
不参与订购健康区间训练
不参与订购健康得分
有效交易仍可进入经营规模和商品效率
原始售罄率保留，禁止静默截断为 100%
```

## 8. 通用指标标准化

所有指标都在同一个比较组内标准化。

正向指标：

```text
x_log = ln(1 + x)
M = median(x_log)
MAD = median(|x_log - M|)
robust_z = (x_log - M) / (1.4826 * MAD)
x_score = 100 * Phi(robust_z)
```

其中 `Phi` 为标准正态分布累计分布函数（standard normal CDF），不是可配置函数。

可为负指标：

```text
x_log = SIGN(x) * ln(1 + ABS(x))
```

然后继续使用中位数/MAD 标准化。

反向指标：

```text
reverse_score = 100 * [1 - Phi(robust_z)]
```

反向指标包括：

```text
损耗成本率
常规优惠金额率
常规优惠销售占比
时段折扣金额率
时段折扣销售占比
```

异常与兜底：

```text
ABS(robust_z) > 3.5 => extreme_store_flag = 1
```

当 `MAD = 0`：

```text
1. 优先使用同一正式范围、同一品类最近 6 个模型窗口的 MAD。
2. 仍为 0：该指标所有门店记 50 分，CRITIC 信息量记 0。
```

缺失值不能填 0。

## 9. CRITIC 动态赋权

CRITIC 用于计算权重。

公式：

```text
sigma_j = 指标 j 的标准差
r_jk = 指标 j 与指标 k 的相关系数
C_j = sigma_j * SUM_k(1 - r_jk)
w_j = C_j / SUM_j(C_j)
```

计算时只让当前比较组内有效且可计算的指标进入 `sigma_j`、相关矩阵和 `C_j`；缺失指标不以 0 代入，也不进入分母。相关系数使用成对有效样本，未达到本节样本门槛的 `r_jk` 记为不可用并触发回退。

当所有可用指标的 `C_j = 0` 或 `SUM_j(C_j) = 0` 时，不能执行除零，也不能任意选一个指标：全部可用指标使用等权，`weight_fallback_flag = 1`，`confidence_level = LOW`，最终等级最高为 `B`。如果没有任何可用指标，则该比较组进入 `NOT_CALCULABLE`。

业务含义：

```text
门店之间差异越大的指标，权重越高。
和其他指标重复度越低的指标，权重越高。
```

小样本回退顺序：

```text
1. 优先使用当前正式范围、当前品类的有效门店计算。
2. 当前相关矩阵不稳定时，使用同一范围最近 6 个模型窗口估计。
3. 仍不稳定时，使用上一版已发布权重。
4. 无历史权重时使用等权，weight_fallback_flag = 1。
```

V1 默认稳定性参数：

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `min_store_cnt_for_critic` | 10 | 当前比较组有效门店少于 10 家时，不直接用当前组算 CRITIC |
| `min_pairwise_valid_cnt` | 10 | 两个指标共同有效样本少于 10 时，该相关系数不稳定 |
| `min_pairwise_valid_ratio` | 0.60 | 两个指标共同有效样本占组内门店数低于 60% 时，该相关系数不稳定 |
| `critic_random_seed` | 20260723 | 用于抽样复现 |

以上为 V1 开发默认参数，可在上海试跑后由业务和数据开发复盘调整。

使用等权回退时：

```text
confidence_level = LOW
weight_fallback_flag = 1
final_level 最高 B
```

禁止扩大到华东大区计算权重。

## 10. 七个一级维度计算

### 10.1 经营规模

全部使用 19:00 前数据。

原始指标：

```text
daily_pre19_sales_amt = SUM(pre19_sales_amt) / effective_business_days
daily_pre19_ticket_cnt = COUNT(DISTINCT order_id where inc_time < 19:00:00) / effective_business_days
valid_member_cnt = COUNT(DISTINCT valid customer_id where inc_time < 19:00:00)
```

经营规模附加解释指标同样只使用 19:00 前有效交易，并先执行第 6.1 节有效交易过滤和第 6.2 节有效会员过滤。分子、分母必须使用同一 `algorithm_batch_version（统一算法批次版本）`、同一门店、同一品类颗粒度/品类编码、同一计算周期和同一有效营业日期范围；会员分子不得混入范围外日期或其他品类交易：

```text
valid_member_ticket_cnt（19点前有效会员小票数）
= COUNT(DISTINCT order_id)
  where inc_time < 19:00:00 and 交易属于有效会员

daily_valid_member_ticket_cnt（日均19点前有效会员小票数）
= valid_member_ticket_cnt / effective_business_days

valid_member_sales_amt（19点前有效会员销售额）
= SUM(usual_amt)
  where inc_time < 19:00:00 and 交易属于有效会员

valid_member_sales_ratio（19点前会员销售额占比）
= valid_member_sales_amt / pre19_sales_amt

valid_member_ticket_ratio（19点前会员小票占比）
= valid_member_ticket_cnt / pre19_ticket_cnt
```

分母和空值规则：

```text
输入完整且没有有效会员交易：valid_member_ticket_cnt = 0，valid_member_sales_amt = 0。
effective_business_days = 0：daily_valid_member_ticket_cnt = NULL。
pre19_sales_amt <= 0：valid_member_sales_ratio = NULL。
pre19_ticket_cnt = 0：valid_member_ticket_ratio = NULL。
会员字段、会员规则或必要输入缺失：受影响字段写 NULL，并记录降级原因，不得把数据缺失写成 0。
valid_member_ticket_cnt > pre19_ticket_cnt，或 valid_member_sales_amt > pre19_sales_amt：不得把占比截断为 1；受影响占比写 NULL，degraded_reason 增加 MEMBER_METRIC_SCOPE_MISMATCH，并写入运行质量问题表。
```

来源：

| 指标 | 优先来源 | 备用来源 |
|---|---|---|
| 19点前销售额 | 毛利损耗表 `19点前销售额` | Doris `SUM(usual_amt)`，条件 `inc_time < 19:00:00` |
| 19点前小票数 | Doris `COUNT(DISTINCT order_id)` | 无 |
| 19点前有效会员数 | Doris `COUNT(DISTINCT customer_id)`，按有效会员过滤 | 无 |

得分：

```text
三个指标分别做正向稳健标准化。
使用 CRITIC 生成经营规模内部权重。

scale_score = SUM(指标得分 * 内部权重)
```

同时保留但不重复进入得分：

```text
daily_valid_member_ticket_cnt（日均19点前有效会员小票数）
valid_member_sales_amt（19点前有效会员销售额）
valid_member_sales_ratio（19点前会员销售额占比）
valid_member_ticket_ratio（19点前会员小票占比）
```

`valid_member_ticket_cnt（19点前有效会员小票数）`作为上述日均值和小票占比的共同复算分子同时保留。这 5 个字段只用于解释、数据质量验收和业务复核，不参与经营规模内部 CRITIC 权重，也不重复进入 `scale_score（经营规模得分）`。

### 10.2 货盘宽度

原始指标：

```text
effective_listed_sku_days = COUNT(DISTINCT (business_date, store_id, sku_id) where 有效在售 SKU 日 = 1)
pre19_active_sku_days = COUNT(DISTINCT (business_date, store_id, sku_id) where 19点前有有效销售)

daily_listed_sku_cnt = effective_listed_sku_days / effective_business_days
daily_pre19_active_sku_cnt = pre19_active_sku_days / effective_business_days
pre19_sku_active_rate = pre19_active_sku_days / effective_listed_sku_days
```

`COUNT(DISTINCT (business_date, store_id, sku_id))` 表示按三列联合键去重，SQL 方言不支持元组时必须使用等价的联合哈希键，不能分别去重后相乘。

19 点前有有效销售判断：

```text
pre19_sales_amt > 0
OR pre19_sales_qty > 0
OR pre19_sales_weight_kg > 0
```

得分：

```text
daily_listed_sku_cnt
daily_pre19_active_sku_cnt
pre19_sku_active_rate
```

三个指标分别做正向稳健标准化，再用 CRITIC 生成：

```text
assortment_width_score
```

### 10.3 商品效率

原始指标：

```text
sales_per_sku_day = SUM(pre19_sales_amt) / effective_listed_sku_days
profit_per_sku_day = SUM(full_link_margin_amt) / effective_listed_sku_days
```

得分：

```text
sales_productivity_score：正向稳健标准化
profit_productivity_score：带符号对数 + 正向稳健标准化

sku_efficiency_score =
SQRT(sales_productivity_score * profit_productivity_score)
```

异常处理：

```text
effective_listed_sku_days = 0 时不执行除法
assortment_data_error_flag = 1
sku_efficiency_score = NULL
```

### 10.4 盈利能力

原始指标：

```text
full_day_full_chain_margin_amt = SUM(full_link_margin_amt)
full_day_store_margin_amt = SUM(store_margin_amt)
valid_scope_sales_amt = SUM(sales_amt)

daily_full_chain_margin_amt =
full_day_full_chain_margin_amt / effective_business_days

full_day_store_margin_rate =
full_day_store_margin_amt / valid_scope_sales_amt
```

`valid_scope_sales_amt` 只保留本算法有效营业日、有效门店品类和有效 SKU 日范围内的 `sales_amt`；不能把范围外或重复关联的销售额带入分母。

`sales_amt` 就是本算法的全日有效销售额，不再使用未定义逻辑字段 `full_day_sales_amt`。分母为空或 `<= 0` 时不执行除法，`full_day_store_margin_rate = NULL`，盈利能力按缺失分项处理。

得分：

```text
full_chain_profit_score：带符号对数 + 正向稳健标准化
store_margin_score：带符号对数 + 正向稳健标准化

profitability_score =
SQRT(full_chain_profit_score * store_margin_score)
```

负毛利保留，不填 0。

### 10.5 订购健康

订购健康使用 SKU 日样本计算。

计件商品：

```text
quantity_pre19_sales_qty = SUM(pre19_sales_qty)
quantity_receipt_qty = SUM(receipt_qty)

quantity_sell_through_rate =
quantity_pre19_sales_qty / quantity_receipt_qty
```

称重商品：

```text
weight_pre19_sales_kg = SUM(pre19_sales_weight_kg)
weight_receipt_kg = SUM(receipt_weight_kg)

weight_sell_through_rate =
weight_pre19_sales_kg / weight_receipt_kg
```

禁止：

```text
公斤和件数直接相加
用到货金额加权原始售罄率
将售罄率静默截断为 100%
```

净经营贡献由本批次锁定配置控制，开发不得在运行时临时判断：

```text
gross_profit_includes_store_loss_flag = 0：
net_operating_contribution_amt = full_link_margin_amt - loss_amt

gross_profit_includes_store_loss_flag = 1：
net_operating_contribution_amt = full_link_margin_amt
```

V1 当前按指标平台已提供公式配置为 `0`；配置值及其口径说明写入第 15.0 节的批次配置快照，由发布记录关联 `algorithm_batch_version（统一算法批次版本）`。正式字段口径改变时从下一完整自然月批次切换，不允许同一批次混用两套公式。

健康区间训练范围：

```text
algorithm_batch_version
scope_type
scope_id
category_granularity
category_code
measurement_type
```

健康区间训练使用最近 6 个完整自然月的有效 SKU 日样本。

训练样本补充指标：

```text
arrival_standard_qty =
WEIGHT 使用 receipt_weight_kg
QUANTITY 使用 receipt_qty

unit_arrival_net_contribution =
SUM(net_operating_contribution_amt) / SUM(arrival_standard_qty)

loss_cost_rate =
SUM(loss_amt) / SUM(outbound_arrival_amt_tax_included)
```

`arrival_standard_qty <= 0` 或到店金额 `<= 0` 的样本不进入相应比率计算。`WEIGHT` 与 `QUANTITY` 分开训练，公斤与件数不合并。

`loss_amt < 0` 的样本标记为损耗金额异常，不进入损耗成本率、售罄健康候选质量门或损耗风险线训练；销售和经营规模指标仍可保留该样本的有效交易。

分箱规则：

```text
h = 2 * IQR(sell_through_rate) / n^(1/3)
```

样本不足的相邻区间自动合并：从售罄率低端到高端依次扫描，样本数小于 `min_bin_sample_cnt` 时与相邻样本数较少的一箱合并；两侧样本数相同时优先与售罄率较低的一箱合并。重复直到所有可合并箱满足最小样本数；仅剩一箱仍不足时训练失败。

V1 默认参数：

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `min_sell_through_sample_cnt` | 200 | 健康区间训练最小 SKU 日样本数 |
| `min_bin_sample_cnt` | 30 | 单个售罄率区间最小 SKU 日样本数 |
| `candidate_tolerance_percentiles` | P90/P95/P99 | 用于试算最大容忍距离 |
| `min_pair_sample_cnt` | 30 | 一个相似经营日窗口候选至少需要的有效配对数 |
| `marginal_net_contribution_cv_max` | 1.00 | 边际净贡献不稳定上限；按有效配对的样本标准差 / `ABS(样本均值)` 计算，均值为 0 且标准差大于 0 时记为无穷大，均值和标准差都为 0 时记为 0 |
| `min_cross_period_stability` | 0.75 | 相似经营日窗口跨期稳定性最低通过值 |

上述 V1 默认参数必须写入第 15.0 节定义的批次配置快照；它们不是业务页面可修改的隐式常量。后续调整默认从新的 `algorithm_batch_version（统一算法批次版本）`生效。

健康区间选择原则来自业务文档：

```text
单位到货净贡献接近历史较优水平
损耗处于相对健康水平
增加到货后净经营贡献不再显著增加
```

业务原文没有给出“接近历史较优”和“显著增加”的数值阈值，因此 V1 不把选择动作交给业务页面或开发临时判断。开发必须把每一段连续分箱组合都生成为候选区间，并输出以下指标；系统按本节自动选参规则选择并发布，业务只通过数据库复核候选和入选依据：

相似经营日按以下 V1 确定性规则生成配对样本：

```text
同一 store_id + sku_id + measurement_type
AND 相同星期类型（工作日 / 周末）
AND 相同促销状态（无优惠 / 常规优惠 / 时段折扣）
AND 两个日期相差不超过当前候选 `season_match_window_days（候选季节匹配窗口天数）`
AND 两日均不是日历表标记的异常节假日
AND 两日 arrival_standard_qty 均 > 0 且不相等
```

促销状态必须来自已确认的 `promotion_discount_scope`、`is_hour_promotion` 和日级时段折扣字段；状态无法确定时不把两日强行配对，窗口候选按配对样本不足处理。

`season_match_window_days（候选季节匹配窗口天数）`不依赖人工审批。系统必须在每个 `algorithm_batch_version（统一算法批次版本） + scope_type（范围类型） + scope_id（算法区域编码） + category_granularity（品类颗粒度） + category_code（品类编码） + measurement_type（计量类型）`选参组内，对 `30 / 60 / 90` 天三个窗口分别生成配对样本，并与连续售罄区间、P90/P95/P99 容忍距离组合成完整候选。窗口不单独提前决胜；所有候选统一执行下文的样本、边际净贡献、跨期稳定性、验证结果和确定性排序规则。最终入选候选行上的窗口值就是该选参组的入选窗口，避免“先按一套规则选窗口、再按另一套规则选区间”产生两套互相冲突的排序。

最终入选窗口就是该选参组唯一 `AUTO_PUBLISHED（系统自动发布）`售罄参数行上的 `season_match_window_days（候选季节匹配窗口天数）`。批次配置快照只保存 `season_match_window_candidates_json（季节匹配窗口候选天数列表）`，不得另存全批次唯一的最终窗口参数，否则不同区域、品类或计量类型会互相覆盖。正式结果按计件和称重分别保存入选参数记录 ID；需要展示入选窗口时，通过对应参数记录读取。不得先发布窗口，再只测试该一个候选。没有任何合格窗口时，不生成边际到货吸收率和边际净贡献，订购健康候选仍可按训练指标降级选择并记录 `season_window_selection_status = UNSTABLE（相似经营日窗口不稳定）`。

日期日历表缺失或存在缺失日期时，不生成相似经营日配对、不猜节假日状态，直接记录不稳定状态和质量问题；不得退回到没有日历依据的自然日匹配。为避免同一天被重复放大，每个门店 SKU 日只保留到货标准量差绝对值最小的另一日；并列时依次选择日期差更小、日期更早的一对。到货量较大者为高到货日，另一日为低到货日。

```text
incremental_arrival_absorption_rate =
(高到货日 pre19_sales_standard_qty - 低到货日 pre19_sales_standard_qty)
/ (高到货日 arrival_standard_qty - 低到货日 arrival_standard_qty)

marginal_net_contribution =
(高到货日 net_operating_contribution_amt - 低到货日 net_operating_contribution_amt)
/ (高到货日 arrival_standard_qty - 低到货日 arrival_standard_qty)
```

分母 `<= 0` 时不计算。各售罄分箱使用配对样本的中位数作为边际指标，避免极端日放大均值。

```text
每个售罄率区间的样本数
每个售罄率区间的单位到货净贡献
每个售罄率区间的损耗成本率
每个售罄率区间的边际净贡献
候选区间下限 L、上限 U
区间内单位到货净贡献、损耗成本率、边际净贡献
下一完整自然月净经营贡献额、损耗成本率
使用该候选后的门店等级一致率和阈值稳定性
P90/P95/P99 三种容忍距离下的结果
```

自动参数发布规则：

```text
1. 系统从所有连续分箱组合和 P90/P95/P99 候选中生成候选行，不要求业务点击。
2. 硬性过滤：`training_sample_cnt >= min_sell_through_sample_cnt`、区间下限 <= 区间上限、`selected_tolerance_distance > 0`、`unit_arrival_net_contribution` 和 `loss_cost_rate` 非空、`pair_sample_cnt >= min_pair_sample_cnt`、`marginal_net_contribution_cv <= marginal_net_contribution_cv_max`、`cross_period_stability >= min_cross_period_stability`、稳定性字段不为空且状态不为 `UNSTABLE`。
3. 有下一完整自然月验证数据时，按 validation_net_contribution_amt DESC、validation_loss_cost_rate ASC、level_stability_score DESC、threshold_stability_score DESC、training_sample_cnt DESC 排序。
4. 没有下一完整自然月验证数据时，按 unit_arrival_net_contribution DESC、loss_cost_rate ASC、level_stability_score DESC、threshold_stability_score DESC、training_sample_cnt DESC 排序，并将 selection_basis 标记为 TRAINING_ONLY。
5. 完全相同时按 sell_through_interval_lower ASC、sell_through_interval_upper ASC、tolerance_percentile 的 P90 < P95 < P99 顺序打破平局。
6. 每个 algorithm_batch_version + scope_type + scope_id + category_granularity + category_code + measurement_type 只能有一条 AUTO_PUBLISHED 参数；选中行写入 candidate_manifest_digest、selection_method = SYSTEM_AUTO、selection_rank = 1、published_by = SYSTEM_AUTO、published_at。
7. 其他合格候选保留 CANDIDATE 供数据库复核；不合格候选标记 REJECTED 或 UNSTABLE，不得被正式主任务读取。
8. 主任务必须同时按 `algorithm_batch_version（统一算法批次版本） + scope_type（范围类型） + scope_id（算法区域编码） + category_granularity（品类颗粒度） + category_code（品类编码） + measurement_type（计量类型） + status='AUTO_PUBLISHED（系统自动发布）'`读取每个适用计量类型的参数；任一选参组查到 0 条或超过 1 条，都阻断该门店品类的订购健康参数依赖。
```

健康度得分：

```text
r 在 [L,U]：distance = 0
r < L：distance = L - r
r > U：distance = r - U

sell_through_health_score =
100 * MAX(0, 1 - distance / selected_tolerance_distance)
```

混合计量品类：

```text
combined_sell_through_health_score =
SUM(计量类型健康度 * 该类型有效到货 SKU 天数)
/ SUM(全部计量类型有效到货 SKU 天数)
```

这里的“有效到货 SKU 天”与第 6.4 节“有效在售 SKU 日”使用同一批基础样本：必须 `is_saleable=1（可售）`且该计量类型实际进货量大于 0；另外剔除售罄异常 SKU 日后，才进入订购健康的分类型计数和加权。

计量类型适用和参数完整性规则：

```text
quantity_valid_arrival_sku_day_cnt > 0：计件类型适用，必须命中唯一一条 QUANTITY 的 AUTO_PUBLISHED 参数。
weight_valid_arrival_sku_day_cnt > 0：称重类型适用，必须命中唯一一条 WEIGHT 的 AUTO_PUBLISHED 参数。
混合品类两种类型均适用时，两套参数必须同时唯一命中；任一适用类型缺参、参数不唯一或不稳定，order_health_score = NULL。
不适用的计量类型，其参数记录 ID、售罄率和健康度写 NULL，不视为缺参。
```

健康区间命中率：

```text
healthy_sku_day_cnt = 处于健康区间的有效到货 SKU 天数
valid_arrival_sku_day_cnt = 全部有效到货 SKU 天数

healthy_sku_day_share =
healthy_sku_day_cnt / valid_arrival_sku_day_cnt

healthy_sku_day_share_score = healthy_sku_day_share * 100
```

最终订购健康：

```text
order_health_score =
SQRT(combined_sell_through_health_score * healthy_sku_day_share_score)
```

如果任一适用计量类型训练样本不足、没有唯一 `AUTO_PUBLISHED（系统自动发布）`参数或参数不稳定：

```text
order_health_score = NULL
missing_dimension_cnt 增加 1
confidence_level 降低
若至少一个适用计量类型没有候选记录，且不存在参数不唯一/不稳定问题：sell_through_param_status = MISSING_AUTO_PARAM；
若至少一个适用计量类型存在候选但全部未通过质量门、出现多条自动发布参数或唯一性异常：sell_through_param_status = UNSTABLE
```

### 10.6 促销健康

一期促销健康不是促销因果评估。

它只判断：

```text
门店该品类是否过度依赖常规优惠或时段折扣。
优惠后的经营质量是否仍然健康。
```

方法版本：

```text
promotion_method = TICKET_DISCOUNT_PROXY_V1
```

字段来源：

| 计算内容 | 优先来源 | 字段或公式 |
|---|---|---|
| 实际销售额 | 毛利损耗表 | `销售额` |
| 全日标准销售额 | 毛利损耗表 | `原价销售额` |
| 总优惠金额 | 毛利损耗表 | `mart_sku_margin_loss.discount_amt`，当前 V1 的 `promotion_discount_scope=TOTAL_DISCOUNT_INCL_TIME` |
| 时段折扣金额 | 毛利损耗表 | `mart_sku_margin_loss.time_period_discount_amt`；不得用 Doris `hour_discount_amt` 替代 |
| 常规优惠金额 | 毛利损耗表 | 当前 V1 固定为 `MAX(discount_amt - time_period_discount_amt, 0)`；未来口径变化必须从新的 `algorithm_batch_version（统一算法批次版本）`生效 |
| 19点前标准销售额 | 毛利损耗表或 Doris 小票明细 | 当前 V1 按 `SUM(usual_amt + discount_amt)` 代理，条件 `inc_time < 19:00:00`；只在 `promotion_discount_scope=TOTAL_DISCOUNT_INCL_TIME` 时成立 |
| 19点前常规优惠金额 | Doris 小票明细 | 当前 V1 代理为 `SUM(discount_amt)`，条件 `inc_time < 19:00:00 AND is_hour_promotion = 0`；不得把日粒度 `time_period_discount_amt` 下推到商品行相减 |
| 19点前常规优惠商品标准销售额 | Doris 小票明细 | 当前 V1 代理为 `SUM(usual_amt + discount_amt)`，条件 `inc_time < 19:00:00 AND discount_amt > 0 AND is_hour_promotion = 0` |
| 时段折扣销售额 | Doris 小票明细 | `SUM(standard_sales_amt)`，条件 `is_hour_promotion = 1`；标准销售额口径未确认时不计算 |

重要口径：

Doris `hour_discount_amt` 是“会员当天同小时累计优惠金额”，不是商品行本次时段折扣金额，不能直接按商品行求和。第一期时段折扣金额优先使用毛利损耗表的 `time_period_discount_amt`；若该字段缺失，则促销健康降级，不得把 `hour_discount_amt` 当作替代金额。

当前 V1 的金额关系固定为：

```text
在 business_date + store_id + sku_id 日门店商品粒度：
discount_amt = 总折扣金额（包含时段折扣）
time_period_discount_amt = discount_amt 中满足时段促销的部分
regular_discount_amt = MAX(discount_amt - time_period_discount_amt, 0)

汇总到正式结果粒度时：
total_discount_amt = SUM(日门店商品 discount_amt)
time_period_discount_amt = SUM(日门店商品 time_period_discount_amt)
regular_discount_amt = SUM(日门店商品 regular_discount_amt)
```

上述包含关系只用于毛利损耗表日粒度的全日金额拆分和质量校验。`time_period_discount_amt（时段折扣金额）`没有商品行级拆分字段，不能与 Doris 商品行 `discount_amt（总优惠金额）`逐行相减。19 点前常规优惠指标固定使用 `is_hour_promotion=0（未命中时段促销）`商品行作为代理；命中时段促销的商品行整体排除出常规优惠代理，避免把同一时段折扣重复计入常规优惠。这是 `TICKET_DISCOUNT_PROXY_V1（小票折扣代理口径V1）`的边界，不解释为精确的促销活动归因。

`is_hour_promotion = 1` 只表示该商品行命中时段促销配置/ETL 规则，不表示所有 19:00 后订单，也不能替代 `time_period_discount_amt` 金额。

`discount_amt（总优惠金额）`的正负方向、包含关系和 `usual_amt（实付金额）`含义已经由数据合同及 V1 固定口径锁定，不再要求运行前人工登记。每次运行只做自动数据质量校验；若字段缺失、出现负折扣、`time_period_discount_amt（时段折扣金额） > discount_amt（总优惠金额）`，或标准销售额无法从合同字段确定：

```text
regular_discount_amt_rate = NULL
regular_discount_sales_ratio = NULL
hour_discount_amt_rate = NULL
hour_discount_sales_ratio = NULL
discounted_margin_rate = NULL
promotion_health_score = NULL
promotion_confidence = DATA_INSUFFICIENT
```

不得直接把 `usual_amt + discount_amt` 当成标准销售额，也不得用开发自行猜测的折扣拆分继续评分。

`total_discount_amt（总折扣金额）`的 V1 唯一映射：

```text
promotion_discount_scope = TOTAL_DISCOUNT_INCL_TIME：total_discount_amt = discount_amt；
```

`REGULAR_DISCOUNT_ONLY（总优惠仅含常规优惠）`和 `UNKNOWN（口径未知）`只是历史兼容枚举，当前 V1 不执行对应公式、不得写入批次配置快照或正式结果。未来数据合同改变时，必须从新的 `algorithm_batch_version（统一算法批次版本）`同步修改数据合同、公式和验收规则。

以下对账组合必须在统一比较粒度上输出行数和金额，但只能用于数据质量检查；不能直接把 Doris 商品行字段和毛利损耗表日字段逐条比较：

```text
discount_amt = 0
discount_amt = hour_discount_amt
discount_amt > 0 且 hour_discount_amt = 0
discount_amt > 0 且 hour_discount_amt > 0
```

如果 `time_period_discount_amt` 缺失、`is_hour_promotion` 缺失、毛利损耗表日粒度主键不唯一、任一正式折扣金额为负，或总折扣与时段折扣出现无法解释的负向/超额关系：

```text
promotion_health_score = NULL
promotion_confidence = DATA_INSUFFICIENT
```

其他六个维度仍按各自规则计算；不得把缺失折扣填 0，也不得把 Doris `hour_discount_amt` 直接按商品行求和补齐。

促销健康指标：

```text
pre19_regular_discount_amt =
SUM(discount_amt where inc_time < 19:00:00 and is_hour_promotion = 0)
pre19_standard_sales_amt = SUM(19点前标准销售额)
pre19_regular_discount_sales_amt =
SUM(usual_amt + discount_amt
    where inc_time < 19:00:00
      and discount_amt > 0
      and is_hour_promotion = 0)
time_period_discount_amt = SUM(全日时段折扣金额)
full_day_standard_sales_amt = SUM(全日标准销售额)
hour_promotion_standard_sales_amt = SUM(时段促销商品全日标准销售额)
discounted_margin_amt = SUM(有优惠或时段折扣商品的全链路毛利额)
discounted_sales_amt = SUM(有优惠或时段折扣商品的实际销售额)

regular_discount_amt_rate =
pre19_regular_discount_amt / pre19_standard_sales_amt

regular_discount_sales_ratio =
pre19_regular_discount_sales_amt / pre19_standard_sales_amt

hour_discount_amt_rate =
time_period_discount_amt / full_day_standard_sales_amt

hour_discount_sales_ratio =
hour_promotion_standard_sales_amt / full_day_standard_sales_amt

discounted_margin_rate =
discounted_margin_amt / discounted_sales_amt
```

优惠商品毛利率口径：

```text
优先按 营业日期 + 门店 + 销售商品编码 计算。
如果无法到商品行级，则允许用日门店商品口径近似。
近似时必须输出 discounted_margin_rule_degraded_flag = 1。
```

优惠商品毛利率状态和数值写法：

```text
没有任何优惠或时段折扣商品：promotion_margin_status = NOT_APPLICABLE，discounted_margin_rate = NULL；
存在优惠商品且分母 > 0：promotion_margin_status = CALCULATED，写入数值；
存在优惠商品但实际销售额分母 <= 0 或毛利字段缺失：promotion_margin_status = NOT_CALCULABLE，discounted_margin_rate = NULL。
```

得分：

```text
regular_discount_amt_rate_score：反向稳健标准化
regular_discount_sales_ratio_score：反向稳健标准化
hour_discount_amt_rate_score：反向稳健标准化
hour_discount_sales_ratio_score：反向稳健标准化
discounted_margin_quality_score：带符号对数 + 正向稳健标准化
```

```text
regular_discount_non_dependency_score =
SQRT(regular_discount_amt_rate_score * regular_discount_sales_ratio_score)

hour_discount_non_dependency_score =
SQRT(hour_discount_amt_rate_score * hour_discount_sales_ratio_score)

promotion_health_score =
GEOMEAN_AVAILABLE(
  regular_discount_non_dependency_score,
  hour_discount_non_dependency_score,
  discounted_margin_quality_score
)
```

`GEOMEAN_AVAILABLE` 的确定性规则：只保留非空、非 `NOT_APPLICABLE` 且位于 `[0,100]` 的分项；仅 1 项可用时返回该项；至少 2 项可用时返回可用项乘积的 `1/n` 次方；任何可用项为 0 时结果为 0；没有可用项时返回 `NULL`。

无优惠发生：

```text
discounted_margin_rate = NULL
promotion_margin_status = NOT_APPLICABLE
优惠依赖类指标按 0 依赖参与评分
promotion_confidence = NORMAL
```

小票优惠字段缺失或标准销售额无法确认：

```text
promotion_health_score = NULL
promotion_confidence = DATA_INSUFFICIENT
综合分按可用维度重算权重
```

### 10.7 损耗健康

正式评分使用损耗成本率：

```text
loss_cost_rate =
SUM(loss_amt) / SUM(outbound_arrival_amt_tax_included)
```

来源：

| 逻辑字段 | 来源字段 |
|---|---|
| `loss_amt` | 毛利损耗表：门店损耗金额，已确认成本口径 |
| `outbound_arrival_amt_tax_included` | 门店商品日价格表：出库到店金额含税；先按日+门店+销售 SKU 汇总 |

到店金额缺失时不允许用未定义的估算销售成本自动代替。只有数据合同正式提供到日+门店+销售 SKU 的 `sale_cost_amt` 后，才允许以下降级：

```text
loss_cost_rate =
SUM(loss_amt) / (SUM(sale_cost_amt) + SUM(loss_amt))

loss_cost_rule_degraded_flag = 1
```

当前 `mart_sku_margin_loss` 数据合同尚未把 `sale_cost_amt` 列为正式字段，因此 V1 到店金额缺失时：

```text
loss_cost_rate = NULL
loss_health_score = NULL
loss_cost_rule_degraded_flag = 0
degraded_reason 记录 MISSING_ARRIVAL_AMOUNT
```

得分：

```text
loss_health_score = 100 * [1 - Phi(robust_z)]
```

异常：

```text
loss_amt < 0：标记 loss_cost_abnormal_flag = 1，不参与损耗健康评分
outbound_arrival_amt_tax_included <= 0：loss_health_score = NULL
```

### 10.8 空分母、空值和负值统一处理

下面的规则优先于任何单项 SQL 实现；开发必须按字段写入 NULL、状态或异常标记，禁止把不可计算强行转成 0：

| 场景 | 受影响字段 | 写法 | 同步状态/动作 |
|---|---|---|---|
| `effective_business_days = 0` | `daily_pre19_sales_amt`、`daily_pre19_ticket_cnt`、`daily_listed_sku_cnt`、`daily_pre19_active_sku_cnt`、`daily_full_chain_margin_amt` | `NULL` | 对应维度记缺失；`missing_dimension_cnt` 增加 |
| 会员必要字段或会员规则实现不可用 | `valid_member_cnt` 及 5 个会员附加解释字段 | `NULL` | `degraded_reason` 增加 `MISSING_MEMBER_INPUT`；不得把输入缺失解释为没有会员交易 |
| 会员解释分子大于同范围总量 | `valid_member_sales_ratio` 或 `valid_member_ticket_ratio` | `NULL` | `degraded_reason` 增加 `MEMBER_METRIC_SCOPE_MISMATCH`；记录来源范围不一致，不截断为 1 |
| `effective_listed_sku_days = 0` | `pre19_sku_active_rate`、`sales_per_sku_day`、`profit_per_sku_day` | `NULL` | `assortment_data_error_flag=1`；货盘/效率维度缺失 |
| 19 点前标准销售额 `<= 0` 或为空 | `regular_discount_amt_rate`、`regular_discount_sales_ratio` | `NULL` | `promotion_confidence=DATA_INSUFFICIENT` |
| 全日标准销售额 `<= 0` 或为空 | `hour_discount_amt_rate`、`hour_discount_sales_ratio` | `NULL` | `promotion_confidence=DATA_INSUFFICIENT` |
| 全部有效到货 SKU 日数 `= 0` | `healthy_sku_day_share`、`order_health_score` | `NULL` | `sell_through_param_status` 保留参数状态；订购健康维度缺失 |
| 有效到货标准量分母 `<= 0` | 售罄率、边际吸收率、边际净贡献 | `NULL` | 该 SKU 日/配对不进入训练，并记录原因 |
| 到店金额 `<= 0` | `loss_cost_rate`、`net_operating_contribution_rate`、`loss_health_score` | `NULL` | `loss_cost_rule_degraded_flag=0`；损耗维度缺失 |

## 11. 一级维度综合评分

七个一级维度：

```text
scale_score
assortment_width_score
sku_efficiency_score
profitability_score
order_health_score
promotion_health_score
loss_health_score
```

使用 CRITIC 生成一级权重：

```text
W1-W7
SUM(W1...W7) = 1
```

综合分：

```text
category_score =
scale_score * W1
+ assortment_width_score * W2
+ sku_efficiency_score * W3
+ profitability_score * W4
+ order_health_score * W5
+ promotion_health_score * W6
+ loss_health_score * W7
```

某维度为 `NOT_APPLICABLE` 或 `NULL`：

```text
adjusted_w_j = original_w_j / SUM(可用维度原权重)
category_score = SUM(可用维度得分 * adjusted_w_j)
```

禁止将缺失值、不适用值填 0。

## 12. 动态等级生成

对同一比较组的 `category_score` 从低到高排序，尝试：

```text
K = 1, 2, 3, 4
K_max = MIN(4, 综合分去重值数量)
```

Jenks 自然断点：

```text
选择使组内平方误差 SSE_K 最小的连续切分
```

BIC：

```text
BIC(K) = N * ln(SSE_K / N) + K * ln(N)
```

BIC 越小越好，但候选分层必须通过稳定性验证。

当 `SSE_K = 0`：

```text
不执行 ln(0)
在达到 0 的候选中选择 K 更小且通过稳定性验证的分层
```

稳定性验证：

```text
重复抽样次数 = 500
每次抽取有效门店比例 = 80%
同一等级数量出现比例 >= 80%
单门店等级一致率 >= 75%
最近 4 个滚动窗口中，等级数量至少 3 次一致
```

V1 固定随机种子：

```text
random_seed = 20260723
```

未通过稳定性验证时：

```text
4 级 -> 3 级 -> 2 级 -> 1 级
```

等级命名：

| K | 等级 |
|---:|---|
| 4 | A / B / C / D |
| 3 | A / B / C |
| 2 | A / B |
| 1 | 统一 B，`single_level_flag = 1` |

当综合分去重值数量为 1 时，必须按 K=1 输出：`selected_level_count=1`、`provisional_level=B`、`final_level` 再经过底线修正、`jenks_thresholds_json=[]`、`bic_by_k_json` 只写键 `"1"`、`single_level_flag=1`。不能为了制造层级而按行号或随机数拆分。

K=1 没有可比较断点，`threshold_stability_score` 固定写 `1.000000`（无阈值可波动）；`level_stability_score` 仍按 500 次抽样和滚动窗口复算。

同分规则：

```text
综合分完全相同的门店必须属于同一等级。
禁止用 row_number 强行拆分同分门店。
```

## 13. 经营底线与等级上限

最终等级：

```text
final_level =
APPLY_LEVEL_CAP(
  provisional_level,
  profitability_cap,
  loss_level_cap,
  data_quality_cap,
  weight_fallback_cap
)
```

`APPLY_LEVEL_CAP` 规则必须唯一：等级严格度为 `A < B < C < D`，字母越靠后限制越严；最终等级取暂定等级和所有非空上限中最严格的一个。实现时可映射 `A=1、B=2、C=3、D=4` 后取最大值。例如暂定 `A`、盈利上限 `B`、数据质量上限 `C`，最终等级为 `C`。所有触发原因都写入 `level_adjust_reason`，不能只保留最后一个原因。

### 13.1 连续亏损上限

按最近 3 个完整自然月分别计算：

```text
monthly_net_operating_contribution =
gross_profit_includes_store_loss_flag = 0 时：
monthly_full_link_margin_amt - monthly_loss_amt

gross_profit_includes_store_loss_flag = 1 时：
monthly_full_link_margin_amt
```

触发规则：

```text
M1 < 0 AND M2 < 0 AND M3 < 0
=> continuous_loss_3m_flag = 1
=> profitability_cap = B
```

三个月累计亏损但不是每个月都亏损：

```text
cumulative_loss_3m_flag = 1
不触发连续亏损上限
```

### 13.2 严重损耗上限

训练样本粒度：

```text
algorithm_batch_version
scope_type
scope_id
store_id
category_granularity
category_code
natural_month
```

定义：

```text
x = loss_cost_rate
y = net_operating_contribution_rate
w = outbound_arrival_amt_tax_included

net_operating_contribution_rate =
net_operating_contribution_amt / outbound_arrival_amt_tax_included
```

分母为空或 `<= 0` 的门店品类月样本不进入 Isotonic 训练；权重使用同一含税到店金额，禁止使用单位成本直接求和。

使用单调递减 Isotonic Regression：

```text
最小化 SUM_i[w_i * (y_i - g(x_i))^2]
约束 x_a < x_b 时，g(x_a) >= g(x_b)
```

严重损耗风险线：

```text
按损耗成本率 x 从小到大排列 Isotonic 训练点。
若存在第一个训练点 x_i 使 g(x_i) <= 0，且前一点 g(x_{i-1}) > 0：
  若两点相邻且跨越 0，阈值取线性插值
  x* = x_{i-1} + (0 - g(x_{i-1})) * (x_i - x_{i-1}) /
       (g(x_i) - g(x_{i-1}))
若没有可插值的前一点，阈值取第一个 g(x_i) <= 0 的训练点。
```

以下情况不发布损耗风险线，参数状态写 `UNSTABLE`：

```text
训练样本不足；
所有 g(x) > 0（没有穿过 0）；
所有 g(x) <= 0（无法识别从正到非正的边界）；
阈值在滚动窗口间不稳定；
评价指标分母为 0 或没有可用的下一月验证样本。
```

候选触发规则：

```text
最近 3 个月至少 1 个月超过风险线
最近 3 个月至少 2 个月超过风险线
最近 3 个月 3 个月全部超过风险线
```

下一完整自然月标签定义：

```text
positive_label = 1：下一完整自然月 net_operating_contribution_amt < 0
positive_label = 0：下一完整自然月 net_operating_contribution_amt >= 0
```

对 1、2、3 个月三个候选分别输出：

```text
precision = TP / (TP + FP)
recall = TP / (TP + FN)
false_positive_rate = FP / (FP + TN)
cross_period_stability = 最近 4 个滚动验证窗口中该候选达到验收标准的窗口数 / 4
```

分母为 0 的评价指标记 `NULL`，该候选不能进入自动发布。V1 不依赖人工评审，自动选择规则为：先过滤 `training_sample_cnt < min_loss_training_sample_cnt`、任一评价指标为 `NULL`、`cross_period_stability < min_cross_period_stability` 或状态为 `UNSTABLE` 的候选；再按 `cross_period_stability DESC`、`precision DESC`、`recall DESC`、`false_positive_rate ASC`、`training_sample_cnt DESC` 排序；完全相同时按 `loss_trigger_month_count ASC` 打破平局。`min_cross_period_stability（跨期稳定性最低通过值）`使用第 10.5 节 V1 默认值 0.75，并写入第 15.0 节的批次配置快照。

```text
loss_trigger_month_count_candidate = 1 / 2 / 3
```

自动发布规则：

```text
1. 每个 algorithm_batch_version + scope_type + scope_id + category_granularity + category_code 只能有一条 AUTO_PUBLISHED 参数。
2. 选中行写入 candidate_manifest_digest、selection_method = SYSTEM_AUTO、selection_rank = 1、published_by = SYSTEM_AUTO、published_at。
3. 其他合格候选保留 CANDIDATE；不合格候选标记 REJECTED 或 UNSTABLE。
4. 正式主任务必须同时按 `algorithm_batch_version（统一算法批次版本） + scope_type（范围类型） + scope_id（算法区域编码） + category_granularity（品类颗粒度） + category_code（品类编码） + status='AUTO_PUBLISHED（系统自动发布）'`读取损耗参数；查到 0 条或超过 1 条都不应用该范围品类的严重损耗上限。
```

无 AUTO_PUBLISHED 参数时：

```text
severe_loss_flag = NULL
loss_level_cap = NULL
loss_threshold_unstable_flag = 1
若参数表没有任何候选记录：loss_param_status = MISSING_AUTO_PARAM；
若存在候选但全部为 REJECTED/UNSTABLE：loss_param_status = UNSTABLE。
```

这表示“不应用严重损耗上限”，不表示门店已确认没有严重损耗。

触发后：

```text
severe_loss_flag = 1
loss_level_cap = B
```

V1 默认参数：

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `min_loss_training_month_cnt` | 6 | 损耗风险线最少历史月份 |
| `min_loss_training_sample_cnt` | 100 | 损耗风险线最少门店品类月样本数 |

如果历史曲线没有穿越 0、始终低于 0、样本不足、阈值不稳定或没有合格候选：

```text
不发布损耗等级上限
只保留 loss_health_score 和 loss_threshold_unstable_flag
```

### 13.3 数据与权重回退上限

六个核心维度：

```text
经营规模
货盘宽度
商品效率
盈利能力
订购健康
损耗健康
```

规则：

```text
CRITIC 无历史参数、使用等权回退：最高 B
六个核心维度缺失 1 个：继续计算，低置信度，最高 B
六个核心维度缺失 >= 2 个：不生成正式等级，进入数据修复清单
门店、品类、交易基础映射缺失：NOT_CALCULABLE
```

`NOT_CALCULABLE` 的落表规则：

```text
如果已经能确定 algorithm_batch_version、scope_type、scope_id、store_id、category_granularity、category_code 这组正式主键：
  仍写入 mart_store_category_level 一行；result_status=NOT_CALCULABLE；category_score、provisional_level、final_level 和无法计算的指标写 NULL；degraded_reason 写明确编码。
如果连正式主键都无法形成：
  不写正式结果表；写入运行质量问题表，保存原始键、缺失表/字段、错误类型和 run_id。
```

`NOT_CALCULABLE（不可计算）`行仍必须带齐统一算法批次、范围、周期、运行ID和结果状态，供下游知道该门店品类被排除的原因；下游不得把它当作最低等级或 0 分。

第一期促销健康特殊规则：

```text
无优惠发生：按低依赖参与评分，不视为缺失
促销健康字段缺失或标准销售额无法确认：促销健康为空，重算权重
```

季节窗口按快照中的 `season_match_window_candidates_json（季节匹配窗口候选天数列表）`逐个训练和回测。每个区域、品类和计量类型入选的 `season_match_window_days（季节匹配窗口天数）`只存在对应的 `AUTO_PUBLISHED（系统自动发布）`售罄参数行，不作为全批次唯一配置。当前 V1 的 `promotion_discount_scope（促销折扣口径）`只允许 `TOTAL_DISCOUNT_INCL_TIME（总折扣已包含时段折扣）`，由系统自动写入，不设人工登记或审批。

## 16. 调度与写入

调度周期：

```text
每月一次正式计算
建议在上月完整数据全部入库后运行
```

写入方式：

```text
1. 按 algorithm_batch_version 分区或建立等价分区裁剪能力；calculation_end_date 作为可核验周期字段保留。
2. 同一 `algorithm_batch_version（统一算法批次版本）` 因源数据修正重跑时不升号；必须复用原 `dim_algorithm_batch_city_region_snapshot（统一算法批次城市区域映射快照表）`、正式参数、`run_config_snapshot_json（批次运行配置快照）`、`algorithm_logic_version（算法逻辑版本）`和 `code_release_id（代码发布记录ID）`对应的会员过滤公共实现。
3. 重跑成功后原子替换该 algorithm_batch_version 的算法 02 正式结果，并更新 latest_run_id、calculated_at、updated_at、rerun_reason 和 rerun_status；失败时不覆盖上一成功结果。
4. 不同 algorithm_batch_version 的结果、城市映射快照、正式参数和运行审计必须长期保留。
5. 规则、参数、区域映射或算法逻辑调整默认从下一个完整自然月批次生效；不得为同一数据结束月份生成第二个业务版本。
6. 正式提交前必须校验：待提交发布记录的 `release_status（发布状态）='AUTO_PUBLISHED（系统自动发布）'`；暂存结果、发布记录、城市映射快照和入选参数使用同一 `algorithm_batch_version（统一算法批次版本）`；暂存结果中的促销口径、毛利损耗口径与 `run_config_snapshot_json（批次运行配置快照）`逐字段一致，代码发布记录与批次锁定值一致。校验通过后才在同一原子步骤提交结果和发布记录，不一致则整批回滚。首次运行不得要求数据库中预先存在已发布记录。
7. 下游只读取调度明确传入的 algorithm_batch_version，不得按最新更新时间猜批次。
```

| 多仓、多验收商品 | 同一合同唯一键出现 2 个仓属性，且销售 SKU 对应 3 个验收 SKU | 同一唯一键重复直接阻断基础表交付；修复后只汇总 3 个验收 SKU 的唯一金额，与毛利损耗表关联后保留 1 条日门店销售 SKU |
| 到店金额为 0 | `outbound_arrival_amt_tax_included=0` | 不除法，损耗率、净贡献率和损耗健康为空 |
| 无自动发布售罄参数 | 只有候选参数，没有 `AUTO_PUBLISHED` | `order_health_score=NULL`，维度权重重算，系统记录 `MISSING_AUTO_PARAM`，不阻断其他维度 |

| 区域映射变更后历史批次重跑 | `dim_city_algorithm_region` 最新数据已删除旧区域，但原 `algorithm_batch_version` 仍存在 | 只读取原 `dim_algorithm_batch_city_region_snapshot`，旧区域仍保留在重跑结果中 |
| 会员过滤条件调整 | `BATCH_202608` 使用原固定条件，9 月完成算法卡、公共实现和验收样例同步调整 | `BATCH_202608` 重跑仍使用原 `code_release_id（代码发布记录ID）`对应的实现；`BATCH_202609` 才使用调整后条件，不为 8 月数据另建版本 |
| 季节窗口自动选参时序 | 同一批次、区域、品类、计量类型生成 30/60/90 天候选 | 先完整写入三类候选并完成质量门和排序，最后将入选候选更新为该组唯一 `AUTO_PUBLISHED（系统自动发布）`参数；禁止先定窗口再训练，禁止写成全批次唯一窗口 |
| 混合计量品类 | 同一门店品类同时存在计件和称重有效到货 SKU 日 | 分别命中 QUANTITY、WEIGHT 两条自动发布参数并保存两个参数记录 ID；缺少任一适用类型参数时 `order_health_score=NULL`，不能拿另一类型参数代替 |
| V1 促销折扣口径 | 运行 `BATCH_202608` | 系统自动写入 `promotion_discount_scope=TOTAL_DISCOUNT_INCL_TIME`；运行过程没有人工登记、确认或审批步骤 |
| 同批次数据修正重跑 | `BATCH_202608` 源数据修正后再次运行 | 版本仍为 `BATCH_202608`，复用原城市映射、规则和正式参数；只更新运行审计和成功后的正式结果 |
| 新批次首次发布失败 | `BATCH_202609` 候选已排序，但正式结果质量门失败 | 可以保留候选和失败审计；不得出现该批次 `AUTO_PUBLISHED（系统自动发布）`参数、正式等级或运行发布记录 |

| 多个上限同时触发 | 暂定 A、连续亏损上限 B、数据质量上限 C | 最终等级 C，调整原因同时保留连续亏损和数据质量 |
| 促销分项只剩 1 项 | 仅优惠后毛利质量得分为 70 | `promotion_health_score=70` |

| 同分门店 | 两店综合分完全相同但断点落在二者之间 | 两店进入同一等级，不使用行号拆开 |

## 18. 评审与开发交付验收项

| 验收项 | 确认对象 | 默认处理 |
|---|---|---|
| 全链路毛利额字段口径验收 | 数据开发 / 财务口径负责人 | 当前参数 `gross_profit_includes_store_loss_flag = 0`，即 `净经营贡献 = 全链路毛利额 - 门店损耗金额`；字段口径变化从下一 `algorithm_batch_version（统一算法批次版本）`生效 |
| 优惠商品毛利率 V1 是否按日门店商品近似口径验收 | 数据开发 | 毛利损耗表已定义到营业日期 + 门店 + 销售商品编码；不能到商品行时，用日门店商品近似，并打降级标记 |
| 门店商品每日可订可售表是否按数据合同覆盖 0 销售日 | 数据开发 | 数据合同已定义到日期 + 门店 + 销售商品编码；交付验收时检查是否包含有可售条件但 0 销售的日期 |
| 日期日历表是否可提供节假日、异常日期 | 数据开发 / 业务 | V1 由调度生成或装载；缺失或日期不全时不生成相似经营日配对，窗口状态为 `UNSTABLE` |
| 19点前销售标准量补算口径 | 数据开发 | 若毛利损耗表缺少 19 点前数量/重量字段，V1 由 Doris 小票按有效交易、`inc_time < 19:00:00` 汇总 `weight`；`weight` 是商品行计价数量，称重商品解释为计价重量，计件商品解释为件数/份数/袋数/只数，单位由商品基础表补充 |
| 门店进货数量与重量验收 | 数据开发 | 毛利损耗表已按数据合同同时提供门店进货数量和门店进货重量；开发交付时验收计件商品使用门店进货数量、称重商品使用门店进货重量，不能把件数和重量混在同一分母 |
| 算法实现一致性 | 数据开发 | Jenks、CRITIC、Isotonic Regression 可使用 Python 或等价实现，但必须通过固定样例和数值误差验收；不得改变公式 |
| 订购健康自动参数 | 数据开发 | 验收系统是否按固定排序规则自动发布唯一 `[L,U]` 和 P90/P95/P99 参数；无合格候选时该维度为空，不等待业务点击 |
| 严重损耗自动参数 | 数据开发 | 验收系统是否按固定排序规则自动发布唯一触发月数；无合格候选时损耗等级上限不生效，不等待业务点击 |
| 城市区域映射快照重跑 | 数据开发 | 验收同一 `algorithm_batch_version` 重跑是否复用原快照，且不读取最新 `is_active` 结果替代历史范围 |
| 会员过滤公共实现 | 数据开发 | 验收同一 `algorithm_batch_version（统一算法批次版本）`内算法 01、02 的公共实现和固定样例结果是否一致；过滤条件调整是否只对下一批次生效；算法 02 不读取 `dim_customer_profile（会员画像结果表）` |
| 季节窗口先候选后入选 | 数据开发 | 验收每个区域 + 品类 + 计量类型选参组是否先覆盖全部配置窗口，再自动发布唯一候选；计件、称重分别关联参数，不得预填或共用全批次唯一窗口 |
| 促销折扣固定口径 | 数据开发 | 验收 V1 是否自动写入 `TOTAL_DISCOUNT_INCL_TIME`，且运行链路不存在人工登记或审批依赖 |
