# 算法01_会员画像_业务解读版

版本：开发评审版  
状态：业务规则已确认，确认日期 2026-07-20  
对应算法卡：算法卡 01：会员画像（开发版），路径 `04_algorithm_cards/developer_version/算法卡_01_会员画像.md`

## 一、这张表在 AI 选品里做什么

会员画像算法的作用，是把会员过去一段时间的小票消费行为，转换成一个稳定的消费者画像标签。

后续 AI 选品不会直接看“所有人买了什么”，而是会先看：

```text
哪些消费者画像是主力人群
这些人在哪些品类、门店群里贡献高
这些人偏好什么商品方向
```

所以会员画像是后面“门店群消费者画像贡献”“目标画像 SKU 表现”“新品机会推荐”的基础。

## 二、当前业务规则摘要

会员画像算法当前使用以下规则：

| 项目 | 当前口径 |
|---|---|
| 画像粒度 | `模型版本 + customer_id`，每个模型版本下每个会员只有一条正式画像 |
| 区域归属 | 跨区域会员先确定一个主归属区域，用该区域模型参数贴标 |
| 捡漏型 | 捡漏型是终止标签，最终画像只输出 `捡漏型` |
| 时间行为冲突 | 同时命中捡漏和晚高峰时，先比较相对强度，再按天数、月数、捡漏优先兜底 |
| 家庭与频次 | 家庭规模、消费频次、价格态度只对非捡漏型会员继续计算 |

## 三、最终会输出什么画像

当前规则下，画像分成两条路径。

### 路径一：命中捡漏型

只要会员最终时间行为被判定为捡漏型，就停止继续拆分后续维度。

```text
time_behavior = 捡漏型
final_profile = 捡漏型
family_level = NOT_APPLICABLE
frequency_level = NOT_APPLICABLE
price_attitude = NOT_APPLICABLE
profile_terminal_flag = 1
```

人话解释：

```text
这个会员最强的消费身份就是捡漏型。
不再判断他是大家庭还是小家庭。
不再判断他是高频、中频还是低频。
不再判断他是否价格敏感。
```

最终画像示例：

```text
捡漏型
```

### 路径二：非捡漏型

如果会员不是捡漏型，才继续计算家庭规模、消费频次和价格态度。

```text
final_profile =
time_behavior-family_level-frequency_level-price_attitude
```

最终画像示例：

```text
上班族晚高峰型-小家庭-中频-价格非敏感
常规时段型-大家庭-高频-价格敏感
```

## 四、算法整体运行流程

算法 01 是月度离线批量计算。开发先读取最近 6 个完整自然月的小票、商品、门店和城市算法区域映射，产出正式画像结果、解释记录、区域参数和画像汇总；月中新会员只使用已发布参数做增量贴标，不重新训练整套模型。

后续算法和前端查询只读取已发布的画像结果。采购或产品筛选区域、品类或消费者画像时，不触发算法 01 重新计算，也不能在查询时临时改会员标签。

```text
最近6个完整自然月小票数据
-> 过滤无效会员和异常交易
-> 判断会员主归属区域
-> 按区域计算熵权和自然断点
-> 先判断时间行为
-> 如果是捡漏型，直接输出捡漏型
-> 如果不是捡漏型，继续计算家庭规模、消费频次、价格态度
-> 输出会员画像结果表、解释表、参数表和汇总表
```

## 五、数据范围

正式模型使用最近 6 个数据完整的自然月。

例如系统在 2026 年 7 月运行，但 2026 年 6 月 Doris 只有 6 月 1 日至 6 月 7 日的数据，那么 6 月不是完整月，不进入正式计算。

示例周期：

```text
2025-12-01 <= business_date < 2026-06-01
```

## 六、主归属区域

每个会员只保留一个主归属区域。

这里的主归属区域不是直接取城市，而是取城市算法区域映射后的算法区域。

华东一期默认链路：

```text
小票 store_id
-> 门店基础表
-> 城市
-> 城市算法区域映射表
-> 算法区域
```

例如：

```text
上海 -> 上海
杭州、宁波、绍兴 -> 杭州宁波绍兴
苏州、常州、无锡 -> 苏州常州无锡
```

跨区域消费会员按以下顺序判断主归属区域：

```text
1. 最近6个完整月有效消费天数最多的区域
2. 消费天数相同时，选择有效小票数最多的区域
3. 小票数仍相同时，选择有效销售额最高的区域
4. 仍然相同时，选择最近一次消费所在区域
```

会员使用主归属区域的模型参数贴标。

页面按区域筛选时，只汇总已经生成好的固定标签，不在查询时重新训练或重新贴标。

## 七、前置过滤

### 有效会员

```text
customer_id IS NOT NULL
AND is_customer = 1
AND customer_id NOT LIKE '6%'
```

`customer_id` 以 6 开头的记录属于非真实会员。`is_customer = 1` 用来确保只给会员交易贴画像。

### 有效交易

只保留：

```text
交易日期位于模型周期内
order_id 不为空
order_status = 'os.completed'
is_return = 0
usual_amt > 0
weight > 0
article_id 不为空
```

剔除：

```text
退货
取消
冲销
测试交易
非正向销售记录
```

### 异常会员日

按 `customer_id + business_date` 统计去重小票数：

```text
单日小票数 <= 5：保留
单日小票数 > 5：剔除该会员当日全部交易
```

会员其他日期的正常交易继续参与计算。

## 八、时间行为怎么判断

时间行为有三类：

```text
捡漏型
上班族晚高峰型
常规时段型
```

### 时间窗口

| 日期类型 | 时间 | 行为窗口 |
|---|---|---|
| 周一至周五 | 18:00 以前 | 常规时段 |
| 周一至周五 | 18:00 至 19:30:00，含 19:30:00 | 上班族晚高峰窗口 |
| 周一至周五 | 19:30:00 之后 | 捡漏窗口 |
| 周六、周日 | 19:30:00 及以前 | 常规时段 |
| 周六、周日 | 19:30:00 之后 | 捡漏窗口 |

上班族晚高峰只计算周一至周五。

捡漏行为不区分工作日和周末。

### 晚高峰指标

```text
晚高峰消费天数占比 =
工作日 18:00-19:30:00 消费天数 / 全部有效消费天数

晚高峰小票占比 =
工作日 18:00-19:30:00 小票数 / 全部有效小票数

晚高峰销售额占比 =
工作日 18:00-19:30:00 销售额 / 全部有效销售额
```

### 捡漏指标

```text
19:30:00 后消费天数占比 =
19:30:00 后消费天数 / 全部有效消费天数

19:30:00 后小票占比 =
19:30:00 后小票数 / 全部有效小票数

19:30:00 后销售额占比 =
19:30:00 后销售额 / 全部有效销售额
```

在时段折扣生鲜业态中，19:30 后消费直接视为捡漏行为，不再额外检查单品折扣字段。

## 九、时间行为冲突怎么处理

先分别计算：

```text
commute_score：上班族晚高峰得分
bargain_score：捡漏得分
```

再和各自自然断点阈值比较。

```text
只命中晚高峰 => 上班族晚高峰型
只命中捡漏 => 捡漏型
两类都未命中 => 常规时段型
```

如果两类同时命中：

```text
commute_relative_strength = commute_score / commute_jenks_threshold
bargain_relative_strength = bargain_score / bargain_jenks_threshold
```

处理规则：

```text
1. 相对强度高者为最终标签
2. 两者相差不超过 0.05 时，比较目标时段消费天数
3. 天数仍相同时，比较覆盖自然月数
4. 仍相同时，捡漏型优先
```

## 十、家庭规模怎么判断

家庭规模只适用于非捡漏型会员。

```text
最终时间行为 = 上班族晚高峰型 / 常规时段型
才继续计算家庭规模
```

捡漏型会员不参与家庭规模训练、预测和标签输出。

### 第一层：直接规则

稳定行为证据：

```text
19:00 前蔬菜消费天数 >= 3
19:00 前蔬菜消费覆盖自然月数 >= 2
```

指标：

```text
日均蔬菜重量 = 19:00 前蔬菜总重量 / 19:00 前蔬菜消费天数
日均蔬菜 SKU 数 = 每个蔬菜消费日去重 SKU 数之和 / 蔬菜消费天数
```

大家庭规则：

```text
日均蔬菜重量 >= 1.5kg
OR 日均蔬菜 SKU 数 >= 4
OR (日均蔬菜重量 >= 1.2kg AND 日均蔬菜 SKU 数 >= 3)
=> 大家庭，高置信度
```

满足稳定证据但未命中大家庭条件：

```text
=> 小家庭，高置信度
```

### 第二层：购物篮补充模型

不满足第一层稳定蔬菜证据时，仍然需要输出大或小家庭标签。

此时使用主归属区域的逻辑回归模型补充判断。

输入指标限定在 19:00 前：

```text
x1 = 平均 SKU 数 / 票
x2 = 平均购买重量 / 票
x3 = 家庭食材 SKU 数 / 票
x4 = 家庭食材重量 / 票
x5 = 家庭食材品类数 / 票
```

家庭食材包括：

```text
蔬菜、肉禽蛋、猪肉、水产
```

消费频次、客单价和销售额不进入补充模型。

## 十一、消费频次怎么判断

消费频次只适用于非捡漏型会员。

可观察月份：

```text
observed_months =
从会员在当期的首次有效消费月
到模型周期结束月的自然月数，含首尾月
```

行为频次：

```text
monthly_shop_days_observed = 有效消费天数 / observed_months
```

最终频次标签：

```text
monthly_shop_days_observed >= 8 => 高频
4 <= monthly_shop_days_observed < 8 => 中频
monthly_shop_days_observed < 4 => 低频
```

区域百分位和三等分只作为辅助字段，不覆盖最终频次标签。

## 十二、价格态度怎么判断

价格态度只适用于非捡漏型会员。

```text
最终时间行为 = 上班族晚高峰型 / 常规时段型
才继续计算价格态度
```

只使用 19:00 前的常规促销行为，不使用 19:30 后时段折扣。

促销标记：

```text
discount_amt > 0 => 该商品行视为常规促销商品
```

`discount_amt` 只作促销标记，不直接求和。

促销商品销售额：

```text
促销商品销售额 =
SUM(CASE WHEN discount_amt > 0 THEN usual_amt ELSE 0 END)
```

价格敏感得分使用同场景促销基准、促销 SKU 偏好指数、促销销售额偏好指数，再通过区域熵权合成。

最低证据：

```text
19:00 前促销 SKU 数 >= 3
促销购买覆盖自然月数 >= 2
促销商品覆盖小分类数 >= 2
单一促销 SKU 销售额 / 全部促销商品销售额 <= 0.50
```

最终标签：

```text
四项最低证据全部通过
AND price_sensitive_score >= price_jenks_threshold
=> 价格敏感

其他
=> 价格非敏感
```

低置信度会员统一输出价格非敏感。

## 十三、输出表

会员画像算法正式交付时，不是只给一张表。它会有四张正式输出表，但每张表的用途不同。

```text
结果表 = 后续 AI 选品真正读取的会员画像
解释表 = 业务和开发验收时看“为什么这么判”
参数表 = 保存本次模型用到的权重、阈值和模型参数，保证可以复现
汇总表 = 给业务看区域和画像分布是否合理
```

| 表 | 给谁用 | 解决什么问题 |
|---|---|---|
| 会员画像结果表 | 后续算法和 AI 选品服务 | 这个会员最终是什么画像 |
| 会员画像解释表 | 你、业务、数据开发 | 为什么这个会员是这个画像，证据是什么 |
| 区域模型参数表 | 数据开发、后续复盘 | 当时用的熵权、自然断点、逻辑回归参数是多少 |
| 画像汇总表 | 业务评审 | 上海/区域里各类画像有多少人、贡献多少销售 |

### 结果表怎么用

结果表是一张“会员最终标签表”。

一行代表：

```text
一个模型版本 + 一个会员
```

后续“门店群消费者画像贡献”“目标画像 SKU 表现”“新品机会推荐”主要读取这张表。

核心字段：

```text
profile_model_version
customer_id
primary_region
time_behavior
family_level
frequency_level
price_attitude
final_profile
profile_terminal_flag
time_confidence
family_confidence
price_confidence
is_incremental_new_member
```

捡漏型字段口径：

```text
family_level = NOT_APPLICABLE
frequency_level = NOT_APPLICABLE
price_attitude = NOT_APPLICABLE
family_confidence = NOT_APPLICABLE
price_confidence = NOT_APPLICABLE
final_profile = 捡漏型
```

非捡漏型字段口径：

```text
家庭规模、消费频次、价格态度正常输出
final_profile = time_behavior-family_level-frequency_level-price_attitude
```

### 解释表怎么用

解释表是“验收和排查表”。

比如业务问：

```text
为什么这个会员是捡漏型？
为什么这个会员是大家庭？
为什么这个会员是价格敏感？
```

解释表里要能看到：

```text
晚高峰消费天数
捡漏消费天数
蔬菜购买天数
日均蔬菜重量
促销 SKU 数
价格敏感得分
算法阈值
是否通过
失败原因
```

没有解释表，就只能看到最终标签，看不到算法证据，后续很难验收。

### 参数表怎么用

参数表保存“这次模型到底用了什么规则参数”。

例如：

```text
上海区域的晚高峰指标权重是多少
上海区域的捡漏自然断点是多少
家庭规模逻辑回归 beta 系数是多少
价格敏感阈值是多少
哪些区域使用了上级区域参数回退
```

这张表的核心作用是复现。如果下个月会员标签变了，可以回头看是会员行为变了，还是模型参数变了。

### 汇总表怎么用

汇总表是业务评审用的分布表。

它回答的是：

```text
上海有多少捡漏型会员
常规时段型-小家庭-高频-价格非敏感有多少人
这些画像贡献了多少销售额
各画像的客单价和消费频次是否符合业务直觉
高、中、低置信度分布是否合理
```

所以开发最终交付的不是“很多乱七八糟的过程表”，而是：

```text
1. 会员画像结果表
2. 会员画像解释表
3. 区域模型参数表
4. 画像汇总表
```

开发过程中可以有临时表，但正式对外验收就看这四张表。

## 十四、计算样例

以下样例用于说明算法判定过程，帮助开发实现和业务验收，不代表生产模型真实参数。

### 样例 A：捡漏型

输入概要：

```text
主归属区域：上海
可观察月份：6
有效消费天数：60
19:30 后消费：12 天，覆盖 4 个月
晚高峰消费：2 天
```

计算：

```text
捡漏证据通过
晚高峰天数不足
最终时间行为 = 捡漏型
命中终止规则
家庭规模、消费频次和价格态度不再计算
```

结果：

```text
捡漏型
```

### 样例 B：非捡漏型

输入概要：

```text
主归属区域：杭州宁波绍兴
可观察月份：6
有效消费天数：30
工作日晚高峰：8 天，覆盖 4 个月
19:30 后消费：1 天
19:00 前蔬菜：6 天，日均 0.85kg，日均 1.7 个 SKU
促销行为证据齐全，但促销偏好接近同场普通会员
```

计算：

```text
晚高峰证据通过 => 上班族晚高峰型
捡漏证据不足
稳定蔬菜证据齐全但未命中大家庭阈值 => 小家庭
monthly_shop_days_observed = 30 / 6 = 5 => 中频
价格敏感得分未命中阈值 => 价格非敏感
```

结果：

```text
上班族晚高峰型-小家庭-中频-价格非敏感
```

## 十五、验收重点

开发和业务验收时，重点检查：

```text
全部有效会员必须输出一条画像
最终画像不得为空
捡漏型的家庭、频次和价格态度必须为 NOT_APPLICABLE
非捡漏型的家庭、频次和价格态度不得为空或为 NOT_APPLICABLE
同一模型版本、同一会员只能有一条最终画像
被过滤的非真实会员、退货和异常会员日不得进入计算
```

业务合理性检查：

```text
捡漏型的次月 19:30 后消费延续率应高于常规会员
晚高峰型的次月工作日晚高峰延续率应高于常规会员
大家庭的整篮 SKU 数与购买重量应高于小家庭
高频会员月均消费天数应高于中频和低频
非捡漏型价格敏感会员的促销偏好指数应高于价格非敏感会员
```
