## 1. 先用一句话理解

这个算法要判断：

```text
外部市场有没有已经出现的商品、属性或趋势；
这些外部信号能不能和我们的内部需求、门店等级、消费者画像接上；
如果能接上，再把它变成可追溯的外部新品候选，交给算法 08 标准化与合并。
```

它不是“外面火什么就推荐什么”。

更简单地说，算法 07 做三件事：

```text
1. 看外部：
   竞品、社媒、行业、法规、新闻里有没有真实商品或真实趋势。

2. 对内部：
   这个外部商品或趋势能不能落回我们的内部小分类、目标画像和门店等级。

3. 出候选：
   如果外部证据和内部适配都成立，输出外部新品候选；
   如果只看到外部信号但内部不成立，只保留证据，不推荐开发。
```

V1 第一版先不要把它想得太大。

当前 V1 应该分成两层外部数据一起用，不是二选一：

```text
第一层：久谦竞品数据
用来提供较结构化的竞品商品、价格、规格、平台、城市、图片和快照信息。

第二层：10 个公开或可授权外部源
用官方价量源看价格和供需变化；
用零售 SKU / POS 源看外部商品形态、规格、价格和图片；
用行业文章源看新品卖点、工艺、消费场景和供应链线索；
```

两层数据合在一起，算法 07 才能判断：

```text
外部有没有同款或高相似竞品；
外部商品规格和价格大概在哪里；
原料/品类价格和供需有没有变化；
外部文章里有没有新品卖点、工艺和场景线索；
这些外部信号能不能和内部品类、主体商品和目标范围接上。
```

完整 07 理想能力还包括真实社媒口碑、Social NPS Proxy、完整全球扩散和法规自动判断。

但这些不是 V1 已经具备的能力。

V1 范围内的久谦和 10 个外部源，通过相应用途准入后可以提供：

```text
外部有没有商品；
外部有没有价格、规格、图片；
外部有没有官方价量、供需变化；
外部有没有行业文章、品牌案例、卖点和供应链线索。
```

但这些来源不能完整证明：

```text
消费者真实买后是否推荐；
自然社媒口碑是正向、中立还是负向；
某个趋势是否已经形成真实用户口碑。
```

所以 V1 不计算正式 Social NPS Proxy。
V1 只保存“社媒未计算”的状态快照，状态为 `V1_NOT_CALCULATED`。不要求建未来社媒口碑数值字段；需要展示口碑数值的读取方返回空值，不能填 0。

一个例子：

```text
外部先发现 Omega-3 鲜鸡蛋 12 枚。

V1 可以用久谦判断：
外部竞品平台里是否有类似商品、规格和外部价格如何、是否有图片、能否落回鲜鸡蛋小分类。

V1 可以用 KSP-POS、7-ELEVEN 台湾、HKTVmall 等来源判断：
外部是否有类似商品、规格和外部价格如何、是否有图片、能否落回鲜鸡蛋小分类。

V1 可以用 Foodaily / FoodTalks、红餐 / 新华网食品判断：
外部文章里是否出现 Omega-3、功能蛋、营养功能等卖点和行业线索。

但如果没有接入真实社媒内容：
算法 07 不能计算真实使用口碑和 Social NPS Proxy。
这不是因为 10 个外部源数量不够，而是因为当前来源类型不是“真实消费者口碑源”。
所以 V1 只能写 V1 暂不计算，不能把文章热度、商品榜单或竞品价格当成口碑推荐。

如果没有接入完整法规/标准源：
算法 07 只能传递已观察到的风险线索，不能替代算法 09 做完整风险门禁。

算法 07 不能直接说“中国已经流行 Omega-3 鸡蛋”。
它只能说“在已接入市场和已接入来源中观察到外部证据”。
只有外部证据可追溯、内部需求成立、风险线索可传递后，
输出“外部新品候选”，再交给算法 08、09、10 继续处理。
```

## 2. 最终会输出什么

算法07保留原有9张结果表，另增加来源覆盖时效审计和交给05的逐商品价格输入，共11张正式表。

业务主要查看候选、证据和内部适配结果。

对业务和产品来说，算法 07 最终真正要给后续算法的是一批“外部新品候选”：

```text
这个外部商品或趋势叫什么；
它来自哪个外部来源；
它应该落到我们哪个内部小分类；
它像不像已有竞品或内部候选；
它在外部市场有没有价格、规格、图片、供需、行业文章等证据；
它能不能接上算法 02 的门店等级、算法 03 的目标画像和算法 04 的主体需求；
它有没有法规、标签、食品安全或宣传声称风险线索，需要随候选进入算法 08，并由算法 09 判断。
```

所以最终业务看到的不是“外部热词列表”，而是类似这样的候选：

```text
候选商品：Omega-3 鲜鸡蛋 12 枚
内部小分类：鲜鸡蛋
外部来源：日本 POS 新品榜、台湾零售 SKU、行业文章、久谦竞品数据
外部证据状态：海外领先探索 / 正式增长趋势 / 原始外部信号等
内部适配状态：目标画像是否支持、门店等级是否支持、主体需求是否成立
风险线索：是否存在功能声称、标签合规、食品安全等需要算法 09 门禁判断的问题
下一步：交给算法 08 做候选标准化和合并，再交给算法 09 做风险门禁
```

| 表 | 一行代表什么 | 用途 |
|---|---|---|
| `external_trend_run` | 同一统一算法批次中的一次算法 07 实际运行 | 保存 `algorithm_batch_version`、运行 ID、周期、来源快照、输入锁定清单和运行状态 |
| `external_attribute_mapping` | 一个外部证据中的原词位置的一项属性映射尝试，含未映射 | 解决 Omega-3、欧米伽3、オメガ3 这类多语种同义问题 |
| `competitor_channel_evidence` | 一个候选在某市场、某小分类下的一类渠道渗透指标 | 保存同款、高相似、趋势属性渠道渗透和价格位置 |
| `social_trend_evidence` | 同批次一个候选在某市场的社媒未计算状态快照 | V1 仅保存 `V1_NOT_CALCULATED` 及运行血缘；无候选本表为空，运行参数声明能力未计算 |
| `industry_external_evidence` | 一个统一算法批次中的一条单指标官方价量、供需或文本事实证据 | 保存原始指标、单位、商品身份、日期、准入用途、来源级别和血缘；不合格数值留缺失状态，不混入正式计算 |
| `external_trend_state` | 一个标准候选在外部市场的趋势状态 | 判断探索、增长、成熟、下降、季节回归或跨市场扩散 |
| `external_candidate_internal_fit` | 一个外部候选落回内部范围后的适配结果 | 判断内部主体需求、目标画像和门店等级是否支持 |
| `external_candidate_image` | 一张可展示或不可展示的候选图片 | 保存图片来源、匹配状态、授权状态和回退等级 |
| `mart_external_source_coverage_audit` | 一次运行一个来源/范围/指标角色/用途的评价窗口 | 显示覆盖、缺报、时效和能力是否启用 |
| `mart_external_candidate_price_input` | 一个范围候选的一种来源商品/规格和价格角色观测 | 供05按完整来源键取价，缺价格明确留状态 |
| `external_new_product_candidate` | 一个外部新品候选最终结果 | 产品默认读取，交给算法 08 做标准化合并 |

行业与公开证据表同时保存选中证据和审计镜像；只有 `selection_status = SELECTED` 且对应允许用途已开放的记录进入业务计算。`EXCLUDED`、`SUPERSEDED` 记录的允许用途列表为空，只保留审计，不进入趋势或候选。

最重要的是区分三类结果：

```text
外部信号：
外面出现了某个商品、属性或趋势，但还不能说明内部可做。

外部正式趋势：
外部证据通过可用来源、趋势、渠道渗透和贝叶斯 FDR 校验。
完整能力会加入社媒口碑，V1 不加入正式 Social NPS Proxy。

外部新品候选：
外部趋势已经落回内部小分类、主体需求、消费者画像和门店等级。
```

所以：

```text
外部正式趋势 != 内部马上推荐新品
外部无观测 != 趋势为 0
海外强趋势 != 国内已经流行
竞品图 != 我们候选商品实物图
```

## 3. 它在 AI 选品链路中的位置

```text
算法 01：会员画像
        ↓
算法 02：门店品类等级
        ↓
算法 03：门店群消费者画像贡献
        ↓
内部证据侧：算法 04 / 05 / 06
外部证据侧：算法 07
        ↓
算法 08：新品候选标准化与合并
        ↓
算法 09：新品机会证据合成与风险门禁
        ↓
算法 10：新品推荐优先级与开发需求编排
```

算法 06 和算法 07 不是强上下游关系。

```text
算法 06 是内部购物篮证据：
从我们自己的小票里找配方、搭配、场景机会。

算法 07 是外部市场证据：
从竞品、官方价量、供需、零售 SKU、POS 新品榜、行业文章和新闻里找外部商品和趋势证据。
后续接入真实社媒后，再补口碑证据。

它们通常在算法 08 汇合：
06 产出的内部候选 + 07 产出的外部候选
-> 算法 08 标准化、去重、合并
-> 算法 09 风险门禁
-> 算法 10 排序和开发编排
```

算法 07 自己有两条发现路径：

```text
路径 A：内部候选外部验证
算法 04/06 已经产生内部候选，比如“青椒黑椒牛柳丝 200g”。
算法 07 去外部看竞品、零售 SKU、POS 新品榜、价量和行业文章里有没有同款、高相似、卖点、痛点或价格证据。

路径 B：外部发现内部匹配
外部先出现新品趋势，比如“Omega-3 鲜鸡蛋 12 枚”。
算法 07 先判断它应该落到内部哪个小分类，再检查算法 02、03、04 的内部需求是否支持；算法 06 有适用证据时增强。国内价格可行性由算法 05 负责，不作为算法 07 反向读取的输入。
```

这里先解释“小分类映射”，是因为算法 07 的外部数据都来自公司外部。
外部平台不会使用我们自己的商品分类，所以外部商品进来以后，必须先回答：

```text
这个外部商品，放到钱大妈自己的哪个小分类里才合理？
```

这里的小分类，指的是商品基础表里最末级、最具体的商品分类。
业务原文里的“叶子小分类”，在本项目里可以理解成这个“小分类”。

这个映射不是让开发凭感觉判断，而是用外部商品信息和内部商品基础表做匹配：

```text
外部商品名、原始品类、品牌、规格、主材料、商品形态、加工方式、功能属性
-> 匹配内部商品基础表中的小分类、主体商品和属性
-> 匹配可靠才进入后续计算
-> 匹配不可靠就保留证据，状态写 CATEGORY_MAPPING_GAP
```

如果没有这一步，算法会出现很危险的误判：

```text
把 Omega-3 鲜鸡蛋错放到保健品；
把黑椒牛肉意大利面错当成黑椒牛柳丝；
把早餐场景商品错拼成鸡蛋新品属性。
```

例如：

```text
Omega-3 鲜鸡蛋 12 枚
-> 主体商品是鲜鸡蛋
-> 功能属性是 Omega-3
-> 小分类应落到鲜鸡蛋，而不是乳制品或保健品
```

如果两条路径都成立，输出：

```text
INTERNAL_EXTERNAL_CONVERGED
```

含义是：

```text
内部有真实需求证据，
外部也有竞品或趋势证据，
但两条证据链都要保留，不能互相覆盖。
```

实际运行时：

```text
每日：采集外部数据，保存原始返回和快照。
每周：可做外部趋势预警，但不覆盖正式月度候选。
每月：按同一个 algorithm_batch_version 冻结外部输入、规则和内部算法 02-04 正式结果、算法 06 增强证据，输出当批候选。
法规或安全事件：可以触发紧急复核。
```

每月冻结的意思是：

```text
每天采集的数据持续落原始快照。正式批次的计算结束日必须是同一完整自然月的月末。
系统把本批可用的外部证据、久谦快照、规则参数、区域映射和上游结果一起锁定。
当批结果统一使用 algorithm_batch_version = BATCH_YYYYMM，用于评审、回溯和开发对账。
同月重跑仍用原批次和原快照；采集 ID、输入包 ID、run_id 只用于血缘与实际运行审计。
```

采购前端只输入查询条件：

```text
城市算法区域、消费者画像、门店等级、叶子品类、候选状态
```

这些只用来筛选已经计算好的结果，不是让采购手工输入趋势词、竞品、图片或候选商品。前端全选门店等级时，展开为 A、B、C、D 各实际等级分别读取并合并展示；正式结果不生成 `ALL_RATED` 等级，也不将不同等级合成一个计算组。

## 4. 一期用哪些底层数据

| 数据 | 用来做什么 | V1 事实 |
|---|---|---|
| 竞品 SKU 基础表 `dim_competitor_sku` | 保存竞品商品名称、类目、品牌、规格、图片、首次/最近采集日期 | 已有数据合同 |
| 竞品每日快照表 `fact_competitor_sku_daily_snapshot` | 保存价格、会员价、销量、评价、售罄、覆盖门店、促销等每日变化 | 已有数据合同，API 暂无字段必须留缺失状态 |
| 商品基础表 `dim_sku` | 将外部候选落回内部小分类、主体、规格、单位和属性 | 已有数据合同 |
| 统一算法批次城市区域映射快照表 `dim_algorithm_batch_city_region_snapshot` | 以 `algorithm_batch_version + city` 读取当批锁定的城市区域 | 已有数据合同；同月重跑复用原快照，不读取当前映射重建 |
| 算法 02 门店品类等级 | 判断外部候选落到哪个门店等级群 | 读取正式结果，不重算 |
| 算法 03 消费者画像贡献 | 判断哪个消费者画像有内部需求承接 | 读取正式结果，不给社媒账号贴会员画像 |
| 算法 04 SKU 表现 | 提供内部主体商品和锚点需求 | 读取正式结果 |
| 算法 06 购物篮关联 | 有配方或场景关系时作为增强证据 | 不适用时写 `NOT_APPLICABLE` |
| 10 个公开或可授权外部源 | 补充官方价量、供需、零售 SKU、POS 新品榜和行业趋势文章 | V1 与久谦并存，不替代久谦 |
| 公开外部源原始快照表 `ods_external_source_raw_snapshot` | 保存来源返回、原始行和采集血缘 | 新增字段合同，保留花卉、缺报和无身份记录的原始内容 |
| 标准化外部证据表 `dwd_external_evidence_normalized` | 区分商品、品类、绝对值、百分比、单位和时间含义 | 新增字段合同；标准化完成不等于正式用途准入 |
| 外部证据字段质量明细表 `mart_external_evidence_quality_issue` | 记录一条证据的一个字段质量问题或信息记录 | 新增字段合同；问题数、证据数和商品数分别统计 |
| 外部批次输入锁定清单 `mart_external_batch_input_manifest` | 锁定当批证据、规则、来源包、截止时间和校验摘要 | 新增字段合同；同月重跑沿用原清单 |
| 外部证据解释规则表 `dim_external_evidence_interpretation_rule` | 登记食品范围、商品身份字典、单位、日期和用途准入规则 | 新增规则合同；仅读取已发布且在本批锁定的规则 |

算法 07 不读取算法 05 的国内建议规格和建议价。算法 07 先解决“外部有没有、像谁、证据是什么”；算法 05 再基于 07 的可比对象和外部规格证据计算国内价格可行性。

真实社媒 V1 不作为输入，只保存未计算状态。完整法规资料未接入时，07 只传递已观察到的风险线索，不宣称完整法规自动判断已完成。

### 4.1 V1 竞品底座：久谦两张表

V1 的结构化竞品数据从久谦商品基础表和每日快照表取得。

两表按提供方、平台、城市和竞品SKU关联，日快照另按采集日期区分。算法保留实际读取行的完整键、来源批次、不可变快照和哈希，不要求供应商额外提供API原始响应表。

| 表名 | 中文名 | 这张表解决什么问题 | 例子 |
|---|---|---|---|
| `dim_competitor_sku` | 竞品 SKU 基础表 | 保存竞品商品相对稳定的属性 | 竞品平台、城市、竞品 SKU 编码、商品名称、品牌、规格、图片 |
| `fact_competitor_sku_daily_snapshot` | 竞品每日快照表 | 保存每天会变化的数据 | 当前售价、会员价、促销标签、销量、评论、好评率、售罄、覆盖门店数 |

这两张表能支持 V1 先做：

```text
1. 外部竞品是否出现。
2. 竞品是同款、高相似，还是只是同方向。
3. 竞品价格、规格、图片和促销信息。
4. 同一个外部候选在不同平台、城市、周期里的出现情况。
5. 外部候选能不能落回内部小分类、主体需求和目标门店画像范围。
```

这两张表不能单独完整支持全部 07 能力，所以需要和 10 个公开或可授权外部源并存：

```text
1. 社媒真实使用口碑。
2. Social NPS Proxy。
3. 官方价量和供需趋势。
4. 行业文章里的新品卖点、工艺和供应链线索。
5. 法规和食品安全正式判断。
6. 搜索指数和全网热度。
```

如果久谦 API 暂时拿不到：

```text
评论数、好评率、总销量、日销量、是否售罄、商品详情链接、标准规格重量
```

这些字段不能写成 0，要保留：

```text
SOURCE_MISSING
SOURCE_PARTIAL
NO_EXTERNAL_OBSERVATION
```

### 4.4 五类来源问题怎样处理

算法 07 面向食品选品，花卉排除规则已确认，原始快照保留。这次规则调整默认从下一完整月 `BATCH_YYYYMM` 生效，历史批次仍读取原锁定规则，不能借同批源数据修正回填新范围规则。排除规则必须有经核验的来源分类或代码依据，不能按名称猜测，也不能把类别缺失一并当成花卉删除。

| 场景 | 系统执行什么 | 仍可保留什么 | 当前不能用于什么 |
|---|---|---|---|
| 台湾已确认属于花卉的记录 | 按当批食品范围规则排除，不生成食品候选 | 原始快照、分类依据和排除统计 | 食品价格、供需、趋势和食品候选计算 |
| 台湾有代码但缺品名或类别 | 数据开发获取官方字典，按来源、市场、商品代码和有效期匹配；未匹配记录隔离 | 原始代码、源价格/数量、字典匹配状态和质量问题 | 商品级比较、食品准入或候选命名；不能凭代码或相近名称补身份/单位 |
| 商务周报表头同时出现公斤、升，但未逐商品明确 | 原始绝对值和百分比指标分别保存；逐商品单位未核实的绝对值不参与价格比较 | 原始品名、表头、绝对值、百分比、比较周期和来源摘录 | 未知单位的标准单价/规格换算；百分比趋势用途尚未发布规则时也不默认启用 |
| 香港只有 Yesterday / Last Week 和修订日 | 保留原始日期文字、采集时间和修订日；未取得锚点、时区、周区间依据时，不自动生成交易日期 | 历史来源资料和日期未核实状态 | 日度趋势、同期同比及跨来源同期比较；不能把采集日前一天或修订日当交易日 |
| 源价格/数量为 `-`，或原始行是休市/表头说明 | `-` 写源未报价，数值为 NULL，跳过该数值；休市、表头等 INFO 单独统计 | 原始值、缺报状态、缺报率、信息记录和处理统计 | 不补 0，不插值；INFO 不计入待业务修复的异常数 |

一条标准证据只承载一种指标：绝对价格、价格变化率、交易量、供应量或文本事实分别保存。同一条证据可以有多个质量问题，所以质量记录数不等于问题证据数，更不等于独立商品数。价格和数量分别形成证据时，还要按来源记录的关联键识别同一原始行，避免重复计算覆盖率。

覆盖率和缺报率按来源、市场、指标及预期观测范围分别对账。INFO 不进分母；不能证明预期观测范围或分母时，覆盖率写空，不能用“通过条数 ÷ 全部质量记录数”替代。

来源单位/商品代码字典解决的是“源记录到底是什么、按什么单位记录”，内部候选属性字典解决的是“主体、口味、工艺等词怎样标准化”；两者不能替代。当前 14 个缺身份代码由数据开发取得官方字典后做逐码匹配与依据验收，不要求业务凭代码猜品名。

技术质量通过只表示当前字段校验通过。商品身份、食品范围、内部小分类、日期/单位和具体用途仍须各自通过，才可用于相应计算。发布给业务读取的是本批自动发布成功的一整套结果，不能把所有 SUCCESS 运行直接合并。

## 5. 数据周期和范围怎么理解

算法 07 有采集时间、数据所属时间和正式批次三个不同概念：

```text
采集时间：系统何时拿到原始快照，可能晚于数据实际发生时间。
数据所属时间：交易日期、统计周或报告数据期；必须有来源依据。
正式批次：算法 01～10 共用的完整月数据批次，格式 BATCH_YYYYMM。
```

例如在 2026 年 7 月运行上一完整月批次：

```text
calculation_end_date = 2026-06-30
algorithm_batch_version = BATCH_202606
内部适配使用同批已冻结的上游结果；本例最近 3 个完整自然月周期为 2026-04-01 至 2026-06-30。
外部当期证据只使用当批截止时间及之前已发布且已采集的记录。
```

来源更新频率可以不同，但同一正式批次的结束月份一致。趋势和季节学习可以读取截止时间之前的可用历史，每次历史回测也必须按当时截止时间截断，不能用未来数据评价过去候选。

同一完整月常规复现重跑沿用原 `algorithm_batch_version`、输入锁定清单、规则参数和区域映射快照；新 `run_id` 仅记录新的实际运行。源数据修正时，以同批输入修正记录说明新旧证据、替换范围和重跑原因，保留旧清单与旧发布审计；规则、参数和区域映射仍读原批次快照。规则、参数和映射调整默认从下一完整月批次生效，不靠新采集包或新运行 ID 生成另一套业务版本。

周度探索只生成预警和原始信号，不覆盖已发布月度结果。缺少可证明的数据所属日期时，可以保留历史资料，不能用采集时间代替交易日期进入当期趋势。

外部市场可以包括：

```text
中国大陆
港澳台
日韩
东南亚
欧洲
北美
其他可配置市场
```

但国内落点必须重新校验：

```text
城市算法区域
门店等级
消费者画像
小分类
内部主体需求
```

不能把海外趋势直接复制成国内结论。

## 6. 核心业务对象怎么定义

### 6.1 什么是外部候选

外部候选不是一段热词，而是一个可以结构化描述的商品概念。

它至少要包含：

```text
目标小分类
主体商品
关键属性，例如功能、口味、工艺、配料
规格或规格段
来源市场
证据来源
```

例如：

```text
Omega-3 鲜鸡蛋 12 枚

小分类：鲜鸡蛋
主体：完整鲜鸡蛋
属性：Omega-3
规格：12 枚
来源：日本竞品 + POS 新品榜 + 行业文章
```

### 6.2 什么是同款、高相似和同方向

算法 07 不能只看名字像不像。

先做硬边界：

```text
小分类
主体材料
商品形态
加工方式
计量类型
```

再用模型比较：

```text
功能
口味
工艺
规格
包装
场景
名称
图片
```

结果分成：

| 关系 | 含义 |
|---|---|
| `EXACT_EQUIVALENT` | 同款或业务上等价 |
| `BUSINESS_HIGH_SIMILAR` | 高相似，可以作为强竞品参照 |
| `SAME_TREND_DIRECTION` | 同方向，但不是同款 |
| `CATEGORY_MAPPING_GAP` | 无法可靠落入内部小分类 |
| `NO_COMPARABLE_MATCH` | 没有可比竞品 |

### 6.3 什么是 Social NPS Proxy，V1 为什么不算

Social NPS Proxy 是“社媒净推荐代理值”，不是标准问卷 NPS。

标准问卷 NPS 是直接问消费者：

```text
你有多大可能把这个商品推荐给朋友？
```

社媒没有这个问卷，所以算法 07 只能从公开内容里识别“推荐倾向”。

只有明确发生过：

```text
购买
食用
使用
复购
退货
```

的账号表达，才进入正式口碑样本。

只是：

```text
想买
种草
收藏
围观
点赞
```

不能算推荐，只能进入趋势兴趣或传播强度。

同一账号、同一标准商品、同一周期只计一票。

例子：

| 社媒表达 | 算法怎么理解 |
|---|---|
| 买了三次，孩子很爱吃，还会回购 | 推荐 |
| 味道一般，但加热方便 | 中立 |
| 太咸了，不会再买 | 贬损 |
| 看起来不错，先收藏 | 只是兴趣，不进入 Social NPS Proxy |

如果 V1 没有接入社媒内容，Social NPS Proxy 不能计算，对应状态写 `V1_NOT_CALCULATED`。

这不会阻断算法 07 的 V1 输出。

V1 仍然可以用以下证据发现或验证外部新品候选：

```text
久谦竞品商品、价格、规格、图片和快照；
10 个外部源里的官方价量、供需、零售 SKU、POS 新品榜、行业文章和新闻；
内部算法 02-04 的门店等级、目标画像、主体需求，以及算法 06 的购物篮证据。
```

只是 V1 不能输出：

```text
消费者口碑很好；
社媒净推荐代理值很高；
真实买后推荐明显成立。
```

换句话说：

```text
V1 可以证明“外部有商品、有趋势线索、有价格规格证据”；
V1 不能证明“消费者真实买后愿意推荐”。
```

## 7. 核心算法流程

算法 07 可以按 12 步理解。

### 第一步：采集并保存外部原始数据

先按 V1 已接入或准备接入的数据来源保存原始证据：

```text
久谦竞品商品
久谦竞品每日价格和销量快照
10 个外部源里的官方价量、供需、零售 SKU、POS 新品榜、行业文章和公开新闻
```

所有外部证据都要保存来源：

```text
来源平台
来源市场
采集时间
原始链接或原始批次
原始文本或原始 JSON
授权状态或可使用状态
```

来源失败不能当成 0。原始快照还要保存源商品代码、原始品名/类别、原始单位、日期文字、修订日和原始数值。标准化后的值必须能追到这一行，不能覆盖原值。

真实社媒、完整法规库、搜索指数和更多全球市场数据属于后续增强来源。V1 如果没有接入，只能写来源状态，不能把缺失当成 0。

### 第二步：做来源治理和去重

算法要先识别：

```text
采集成功
采集失败
来源缺失
重复转载
同一品牌全球统一新闻
营销内容
刷量或异常传播
```

例如：

```text
同一行业报告被 20 个媒体转载，
只能算一个证据组，
不能算 20 个独立趋势证据。
```

先完成食品范围、商品身份、单位和日期校验，再分别决定证据能否用于绝对价格、数量比较、百分比趋势或候选映射。一个数值不可用时，只停用对应数值和用途，不把整条原始记录删除。

来源缺报、未知单位、未知日期和未知商品身份分别记录；INFO 只是处理统计。未发布用途规则的证据继续隔离，不用一个技术 PASS 状态绕过业务准入。

### 第三步：多语种词和属性标准化

外部数据里可能同时出现：

```text
Omega-3
欧米伽3
オメガ3
오메가3
```

这一步不是让开发直接自己翻译，也不是让模型自由判断。

V1 的做法是：

```text
先保留外部原文；
再做语言识别和基础翻译；
再用规则词典、同义词表和模型辅助识别；
最后映射到内部可理解的标准属性。
```

这里的重点不是“翻译成中文”这么简单。

翻译只能把词看懂，映射要解决的是：

```text
这个词在商品开发里到底属于哪个属性维度？
是主体商品？
是主材料？
是口味？
是工艺？
是功能卖点？
是规格？
还是只是营销描述，不能进入正式候选？
```

规则词典和同义词表用来解决确定性强的词：

```text
Omega-3 / 欧米伽3 / オメガ3
-> Omega-3 功能属性

HPP / High Pressure Processing / 高压冷杀菌
-> HPP 冷杀菌工艺
```

V1 规则词典不是要求业务一次性手工提供完整大表。

第一版可以由算法和数据开发先从三类来源沉淀：

```text
1. 内部商品基础表：
   商品名称、SPU 名称、小分类、规格、单位、品牌等。

2. 外部来源原文：
   久谦商品名、外部平台类目、商品规格、商品描述、行业文章标题和正文。

3. 业务补充的高风险 / 高频词：
   比如 Omega-3、HPP、低钠、高蛋白、0 防腐剂、药食同源、无菌蛋等。
```

算法和数据开发负责生成候选映射，业务和商品同事只需要重点复核：

```text
高频出现的词；
会进入新品名称的词；
涉及功能声称、法规、食品安全和标签风险的词；
模型置信度不高但可能影响候选的词。
```

模型辅助识别只用于补充判断，不作为唯一依据。
每次映射都要保存原文、来源、证据和置信度。

算法要保留原文，再映射到统一属性：

```text
ATTR_FUNCTION_OMEGA3
```

每次映射必须保存：

```text
mapping_probability
mapping_evidence_json
algorithm_batch_version
当批锁定的属性字典来源摘要
```

如果映射不可靠：

```text
保留原始证据
进入观察池
不进入新品名称
不进入正式候选
```

### 第四步：判断竞品关系

对每个外部商品，判断它和内部目标商品或候选的关系：

```text
同款
高相似
同方向
无可比匹配
品类映射缺口
```

不能因为都有“黑椒牛肉”就判为高相似。

例如：

```text
黑椒牛肉意大利面
黑椒牛柳丝
```

名称相似，但主体、形态、食用场景可能不同，必须通过硬边界和相似模型。

### 第五步：计算竞品渠道渗透率

渠道渗透率回答：

```text
在这个市场、这个周期、这个小分类成功采集到的有效渠道里，
有多少渠道出现了这个同款、这个高相似品，或这个趋势属性？
```

三层分子必须分开：

```text
同款渠道渗透率
= 出现 EXACT_EQUIVALENT 的有效渠道数 / 有效可比渠道总数

高相似渠道渗透率
= 出现 BUSINESS_HIGH_SIMILAR 的有效渠道数 / 有效可比渠道总数

趋势属性渠道渗透率
= 出现目标趋势属性且保持当前小分类的有效渠道数 / 有效可比渠道总数
```

不能把高相似并入同款。

`1/1` 也不等于高可信 100%，要用 Jeffreys-Beta 后验：

```text
x = 出现该商品或属性的有效渠道数
n = 有效可比渠道总数

p ~ Beta(x+0.5, n-x+0.5)
```

输出：

```text
penetration_raw
penetration_posterior_median
penetration_ci_low_95
penetration_ci_high_95
```

### 第六步：后续能力，计算社媒趋势和口碑

这一节是算法 07 的完整理想能力，不是 V1 已经具备的能力。
V1 不做正式社媒趋势和口碑计算，后续接入真实社媒内容后再打开。

V1 当前没有接入真实社媒内容，所以不计算正式 Social NPS Proxy。
久谦、POS 榜单、零售商品页、官方价量和行业文章可以证明外部有商品、价格、供需或趋势线索，
但不能证明消费者真实买后推荐。

V1 不做这一节，不会阻断后续候选输出。
后续计算按“可用证据”继续进行：

```text
竞品渠道证据：通过用途准入后计算
官方价量和供需证据：通过用途准入后计算
零售 SKU / POS 新品榜证据：通过用途准入后计算
行业文章和公开新闻证据：通过用途准入后计算
社媒趋势和 Social NPS Proxy：仅落未计算状态快照，状态写 V1_NOT_CALCULATED
```

因此 V1 输出候选时，可以说：

```text
外部有竞品、价格、规格、供需或行业趋势证据。
```

但不能说：

```text
外部消费者口碑好。
```

后续如果接入真实社媒，再补去重文档渗透、独立账号覆盖、互动强度、推荐/中立/贬损账号和属性口碑。

未来接入真实社媒时，保留业务原文的能力边界：

```text
文档渗透率 = 含目标属性的有效自然去重内容数 / 同市场、来源、小分类、当周的全部有效自然去重内容数
独立账号覆盖率 = 提及目标属性的独立有效账号数 / 同市场、来源、小分类、当周发布有效自然内容的独立账号总数
```

同篇内容多次出现属性只计一篇，账号按独立身份去重。正式口碑只取有购买、食用、使用、复购或退货证据的表达；想买与广告分别保留为兴趣和营销信息。同一市场、平台、账号、候选和正式周期只保留一条正式表达，先看复购/退货证据，再看明确使用证据，同级取最新。

推荐、中立、贬损三类账号使用 `Dirichlet(0.5, 0.5, 0.5)` 先验，后验参数分别为各类账号数加 0.5，联合取值计算 `100 × (p推荐 − p贬损)`，输出中位数和 95% 可信区间。这是社媒净推荐代理值，不能冒充标准问卷 NPS。点赞、收藏等互动只做同平台可比范围内的传播诊断，不进入口碑公式；属性体验分别保留，不能用整体情绪抹掉具体开发痛点。

这些公式只说明后续真实社媒能力的边界，未来社媒指标不作为 V1 必建字段，也不作为 V1 结果判断条件。

### 第七步：识别趋势是不是持续增长

趋势不是简单看“本周比上周涨了多少”。

业务原文要求按周建立贝叶斯动态渗透率模型，判断：

```text
水平 level
斜率 slope
加速
变点
持续性
季节性
```

小样本会自动扩大不确定性。

例如：

```text
从 1 条涨到 2 条
```

不能直接叫强趋势，因为分母和可信区间都太不稳定。

V1 要进入正式趋势层，同样必须完成贝叶斯动态趋势、可用证据融合和 5% FDR；这些要求不能推迟到社媒接入以后。历史不足、输入日期不可靠或数值未收敛时，只保留原始/探索信号，后验概率和区间写空，不能补一个增长概率。

### 第八步：处理行业、法规和公开证据

这一步不是让业务或开发读法规条文打分。

它的意思是：

```text
外部文章、行业报告、官方公告、法规标准里经常会出现一些可追溯说法。
算法 07 要把这些说法拆出来，作为外部证据或风险线索保存。
```

V1 主要从以下来源得到这类证据：

```text
Foodaily / FoodTalks：新品卖点、工艺、品牌案例
红餐 / 新华网食品：预制菜、餐饮供应链、食材趋势
农业农村部、商务预报：品类价格、供需和市场变化
后续如接入法规标准源：标签、功能声称、食安标准、禁限用信息
```

拆出来时，不直接写一段长文章，而是整理成业务能追溯的结论：

```text
说的是哪个商品或品类
说的是哪个属性、工艺、卖点或风险
结论方向：增长 / 稳定 / 下降 / 只是事实
适用市场：大陆、香港、台湾、日本等
数据周期：这个结论对应哪个时间段
来源级别：官方、行业报告、媒体文章、普通转载
```

例如：

```text
文章说：HPP 冷杀菌肉制品在便利鲜食和即食蛋白场景增加。
算法 07 记录为：
主体 = 冷藏肉制品
属性 = HPP 冷杀菌 / 即食蛋白
结论方向 = GROWING
来源 = Foodaily 或行业文章
```

再比如：

```text
外部商品使用“低钠”“高蛋白”“0 防腐剂”“药食同源”等声称。
算法 07 只把它识别成法规声称风险线索。
正式能不能推进、标签是否合规，由算法 09 风险门禁判断。
```

这里的“法规和食品安全线索随候选进入后续算法”，意思是：

```text
算法 07 负责发现风险线索；
算法 08 负责把风险线索保留到标准候选；
算法 09 负责正式风险门禁。
```

例如算法 07 在外部商品或文章里看到：

```text
低钠
高蛋白
0 防腐剂
药食同源
儿童可食用
有机认证
无抗
功能性营养声称
```

算法 07 不能直接判断“合规通过”。
它应该把这些词、来源链接、原始证据、候选商品和风险类型一起保存，随外部候选交给算法 08。

算法 09 再结合公司规则、法规标准、供应链、质量和风险门禁判断：

```text
是否可以继续进入新品候选；
是否需要法务、质量或商品同事复核；
是否需要禁止进入推荐。
```

如果 07 已经从正式法规来源发现明确禁止或明确不符合准入的情况，
可以先标记硬停止；
除此之外，07 不替代 09 做最终风险结论。

报告发布时间和报告数据期要分开。

不能因为报告今天发布，就把报告里几年前的数据当成当期趋势。价量也必须区分交易日、统计期、发布日期、修订日和采集时间；香港相对日期缺少可靠锚点时不能进入日度或同期比较。

官方绝对价格只在商品或品类身份、币种、计价单位和数据周期都可靠且用途准入通过后使用。变化率需要可比的前后期数值、单位和周期；源提供的百分比是独立指标，不反推成绝对价格。来源只给涨跌描述时，保留原文与方向，不编造数值；商务周报百分比的趋势用途未确认时继续隔离。

### 第九步：融合外部证据

算法 07 不使用固定权重。

完整能力下，它把三类证据分开输入分层贝叶斯模型：

```text
竞品渠道证据
社媒趋势和口碑证据
行业、法规和公开证据
```

V1 因为没有真实社媒口碑源，所以先按可用证据融合：

```text
竞品渠道证据：久谦、KSP-POS、7-ELEVEN 台湾、HKTVmall 等
官方价量和供需证据：农业农村部、商务预报、香港和台湾价量/供应数据
行业和公开文章证据：Foodaily / FoodTalks、红餐 / 新华网食品等
社媒口碑证据：不进入融合，只保存社媒未计算状态快照
```

这意味着 V1 仍然可以判断“外部是否有趋势线索和竞品证据”，
但不能把结果解释成“社媒口碑已验证”。

输出：

| 英文字段 | 中文含义 | 人话解释 |
|---|---|---|
| `p_trend_real` | 趋势真实概率 | 这个外部趋势是真的，不是噪声、广告或偶然事件的概率 |
| `p_sustained_growth` | 持续增长概率 | 这个趋势不是昙花一现，后续还能继续增长的概率 |
| `p_cross_market_diffusion` | 跨市场扩散概率 | 这个趋势从一个市场扩散到其他市场的概率 |
| `trend_growth_ci_low_95` | 趋势增长 95% 可信区间下界 | 保守情况下，趋势增长有多低 |
| `trend_growth_posterior_median` | 趋势增长后验中位数 | 模型认为最可能的趋势增长水平 |
| `trend_growth_ci_high_95` | 趋势增长 95% 可信区间上界 | 乐观情况下，趋势增长有多高 |

如果证据冲突，不平均成一个分数，而是输出冲突状态。

后续接入真实社媒时，例如：

```text
竞品渠道渗透高
社媒口碑负向
```

这可能表示：

```text
市场已经验证过，但商品存在明显痛点。
```

### 第十步：用 5% 贝叶斯 FDR 区分正式趋势

算法保留三层结果：

```text
原始信号层：所有有效信号
探索层：有方向但证据不足
正式层：可信区间、稳定性和贝叶斯 FDR 全部通过
```

正式趋势要求：

```text
趋势真实概率与持续增长概率可计算，并满足当批锁定的正式模型判定
趋势增长 95% 后验区间下界 > 0
进入通过 5% 贝叶斯 FDR 的候选集合
数值计算收敛
关键来源血缘完整，所用证据均通过相应用途准入
```

5% FDR 按集合判断：在同一正式计算范围内，将候选的局部误发现率从低到高排序，选择最大的集合，使集合内局部误发现率平均值不超过 0.05。它不是要求每条候选的局部误发现率都小于等于 0.05。

5% FDR 只控制正式层误报，不删除早期趋势。未通过、无足够历史或未稳定计算的候选留在原始信号/探索层，不宣称正式增长。

### 第十一步：落回内部适配

外部趋势必须回到内部范围重新判断。

最低内部证据包括：

```text
算法 02：目标门店等级存在且有效
算法 03：目标消费者画像贡献成立
算法 04：主体商品或同类主体需求成立
算法 06：如存在配方或场景关系，作为增强证据
```

特别注意：

```text
不能给社媒账号贴内部会员画像。
外部候选必须分别与每个内部消费者画像的真实商品、规格、价格和场景行为匹配。
```

原文中的正向属性保留与负向属性改良约束依赖真实属性口碑。V1尚无该口碑输入，不将它们列为正式必填输出；当前候选名称只使用已验证的商品属性，不推断消费者偏好。

### 第十二步：生成外部新品候选并传给后续算法

输出候选时必须保存：

```text
candidate_product_name
standard_candidate_id
candidate_source_status
external_evidence_status
trend_lifecycle_state
primary_image_id
risk_handoff_ids
candidate_development_status
```

进入算法 08 前只能标记：

```text
PENDING_ALGORITHM_08_GATE
EXPLORATORY_PENDING_ALGORITHM_08_GATE
```

这里的状态名沿用业务原文里的 `GATE` 命名；在当前正式编号中，它表示“等待算法 08 标准化注册”，不表示算法 08 执行风险门禁。正式风险门禁由算法 09 执行。

不能写成已经正式开发。

## 8. 图片怎么选

一期主要使用久谦提供的商品图片。其他外部源继续采集商品、价格、规格和正文；不为图片另外找图或抓图，原响应已有图片链接就按商品归属保留。没有链接是正常缺失，不把整个来源判为不可用。V1不启用AI补图。

主图先找已校验的同款图，同类条件下优先久谦；之后才用已校验的高相似参考图。图片须与候选主体、形态、规格及包装文字相符，并有展示授权。久谦有图不代表每个海外候选都有对应图，高相似图必须标注“竞品参考图”。07离线准备图片数据，最终由10推荐结果及采购前端读取展示。

无图时先用商品名称、类目、规格、主材料、形态、工艺及详情做匹配。文字路径独立训练和验收，不能将图片特征填0后沿用有图模型。文字能证明的同款/高相似正常使用；关键属性仍不明确时保留“匹配未确认”，不能记成没有该竞品。

| 场景 | 一期处理 | 影响 |
|---|---|---|
| 无图、文字/规格完整 | 使用已验收文字匹配；主图为空 | 不因缺图阻断候选，最终展示占位图 |
| 有链接但失效、未校验或授权未知 | 留来源和原因，主图为空 | 可靠文字候选继续；不能宣称图片可展示 |
| 关键主体或规格只在包装图里、无法读取 | 相关属性未知，匹配待核验 | 无可靠主体/小类时只留证据，不生成具名候选 |
| 久谦没有对应商品图 | 不拿同品类图填充 | 海外候选可保留为文字候选，最终占位 |

缺图通常不影响结构化官方价量，但会减少包装文字提取、视觉佐证及图片搬运识别能力。去重仍可使用商品编码、链接和正文；不能证明独立的转载不算第二个市场采用。缺图不直接降低趋势分或使09拒绝候选。

## 9. 一个完整例子：Omega-3 鲜鸡蛋

这个例子使用人造数值说明 07 的 V1 链路，不代表已采集商品或当前批次已获得正式趋势。
其中 `Social NPS Proxy` 不参与 V1 计算；以下正式层概率只用于说明模型、历史验证、集合 FDR 和数值收敛全部通过后的写法。

V1 先看：

```text
久谦竞品证据
SKU / POS / 电商渠道证据
官方价量和供需证据
行业文章和公开新闻证据
内部算法 02-04 适配结果和算法 06 增强证据
```

假设外部数据发现：

```text
来源市场：日本
外部候选：Omega-3 鲜鸡蛋 12 枚
小分类：鲜鸡蛋
主体：完整鲜鸡蛋
属性：Omega-3
```

如果后续接入真实社媒，再输出社媒趋势斜率、变点和可信区间。

竞品渠道渗透：

```text
x = 5
n = 8
raw = 62.50%
后验中位数 = 61.97%
95% 可信区间 = [29.48%,88.10%]
```

Social NPS Proxy：

```text
V1 不计算
social_source_status = V1_NOT_CALCULATED
V1 不建设未来口碑数值字段；读取方需要显示数值时返回 NULL
```

外部融合结果：

```text
p_trend_real = 99.1%
p_sustained_growth = 98.7%
p_cross_market_diffusion = 91.4%
local_false_discovery_rate = 1.8%
该候选所在正式集合的平均局部误发现率 <= 5%
bayesian_fdr_selected_flag = 1

```

若没有足够历史、日期/单位/身份未通过相应用途准入，或模型未收敛，则不写以上正式概率和正式增长状态，只保留可追溯原始/探索信号。

内部适配还要继续看：

```text
算法 02 门店等级是否成立
算法 03 目标消费者画像是否成立
算法 04 鲜鸡蛋主体需求是否成立
法规声称风险线索是否已经按既定口径传给算法 08
```

```text
candidate_product_name = Omega-3 鲜鸡蛋 12 枚

external_evidence_status = FORMAL_GROWING_TREND

```

```text

```

```text
海外前瞻趋势，国内需结合内部需求和风险门禁验证。
```

## 10. 结果状态怎么理解

| 状态 | 业务含义 |
|---|---|
| `RAW_EXTERNAL_SIGNAL` | 外部原始信号存在，但不能当正式趋势 |
| `EMERGING_EXPLORATORY` | 早期增长信号，进入探索试点候选 |
| `FORMAL_GROWING_TREND` | 正式增长趋势，通过统计和 FDR |
| `MATURE_MARKET_GAP` | 外部市场成熟，但内部可能存在差异化空白 |
| `OVERSEAS_LEADING_EXPLORATORY` | 海外领先，国内证据弱，只能前瞻探索 |
| `CONFLICTING_EXTERNAL_EVIDENCE` | 竞品、社媒、行业等证据方向冲突 |
| `DECLINING_EXTERNAL_TREND` | 外部趋势下降，不支持新品开发 |
| `NO_EXTERNAL_OBSERVATION` | 当前没有可用外部观测，不代表趋势为 0 |
| `CATEGORY_MAPPING_GAP` | 无法可靠映射到内部小分类 |
| `SOURCE_ADMISSION_STOP` | 来源准入停止，外部证据不可追溯、明确禁用或已确认属于食品范围外，不生成食品新品候选；原始快照保留 |
| `SOURCE_MISSING` | 来源缺失，不能填 0 |
| `SOURCE_PARTIAL` | 来源部分可用，缺失字段不能补 0 |
| `V1_NOT_CALCULATED` | V1 明确暂不计算，例如 Social NPS Proxy |
| `COMPUTE_UNSTABLE` | 数值未收敛，不能进入正式趋势 |

来源质量要另外分开看，不能直接用上表的趋势状态代替：

| 判断层 | 业务含义 |
|---|---|
| 技术质量 | 字段是否按来源口径正确解析；PASS 不代表已经允许用于食品业务。 |
| 商品身份映射 | 商品代码、品名和类别是否有可靠且唯一的对应关系；未匹配或歧义不能靠猜测通过。 |
| 食品业务准入 | 已核验花卉为范围外，业务用途列表为空；未知类别隔离，保留原始证据和原因。 |
| 允许用途 | 绝对价格、趋势、供应量、历史资料、候选属性分别登记；一个用途通过不自动放开其他用途。 |

候选来源状态和外部证据状态不能混用。

例如：

```text
candidate_source_status = EXTERNAL_DISCOVERED_INTERNAL_MATCHED
external_evidence_status = OVERSEAS_LEADING_EXPLORATORY
candidate_development_status = EXPLORATORY_PENDING_ALGORITHM_08_GATE
```

三者分别回答：

```text
候选从哪里来
外部证据处于什么阶段
候选能不能进入后续开发门禁
```

## 11. 开发实际运行流程

算法 07 是离线或准离线批量计算。开发先完成外部数据采集和入库，再按固定批次生成外部证据、趋势状态、候选和图片结果；采购前端只读取已发布结果，不实时抓取网站或临时跑外部趋势模型。

开发可以有过程表，但正式交付以原有9张结果表加覆盖审计、05价格交接输入为准。

开发按同一条 V1 流程逐层产出：

```text
1. 生成或复用统一批次 BATCH_YYYYMM，读取本批城市区域映射快照和上游正式结果。
2. 读取已发布的来源解释规则，准备本批输入清单及来源范围；登记证据截止时间、规则参数和主数据来源摘要。已确认的花卉排除规则作为规则调整从下一完整月 BATCH 生效，同批源修正只更正原观测，不带入新范围规则。
3. 读取久谦两表并冻结实际输入行，公开源采集并保存原始响应；不因花卉、缺报或身份未明删除源记录。
4. 标准化商品、类别、绝对值/百分比、单位、数据期、采集时间和修订日。
5. 写字段质量明细：花卉排除、类别未明、身份未匹配、单位/日期未核实、源未报价分别处理，INFO 单独统计。
6. 按已发布且当批锁定的规则自动判断每种证据用途；商务趋势、香港日度/同期用途在规则未发布时继续停用。
7. 用内部分类规则、官方商品身份字典和候选属性字典分别完成映射，不互相代替；将本批所选证据、来源包和规则摘要锁入输入清单。
8. 仅用合格 SKU / POS / 电商渠道计算同款、高相似和属性渠道渗透；官方价量和文章不进入分母。
9. 对通过用途准入的价量、供需和行业证据计算或抽取结论；无可比值时不补数值。
10. 写社媒未计算状态快照；按可用证据运行趋势模型、融合、集合 FDR 和冲突识别，无历史或未稳定时仅输出原始/探索层。
11. 将候选分别落回内部小分类、主体需求、画像和门店等级，保存图片校验和风险线索。
12. 写11张正式表，校验主键、批次、来源血缘和输入摘要；按当批已发布规则自动决定能否整批发布。
13. 发布成功后切换本批业务读取指针，前端和下游只读取这一整套已发布结果，再交给算法 08 → 09 → 10。
```

`SUCCESS` 表示一次任务执行成功，不等于该运行已经业务发布，更不等于所有证据都可用于所有用途。新的采集包或成功运行不自动覆盖旧结果；发布检查失败时保留原发布结果，新运行和失败原因留作审计，不能把多个成功运行一起汇总。

久谦按两表完整业务键冻结本次实际读取集和证据索引，内部商品主数据同样保留不可变快照及内容哈希；公开源继续保留自己的原始响应和输入清单。该链路能复算从供给行到结果，不能证明供应商最初的API采集过程。最初API原文缺失不单独阻断07；两表行无法定位或冻结时才限制依赖输出。重跑读取父运行锁定内容，已有历史输入包不删除；无法取得原包时不能用当前表冒充历史。

来源批次和更新时间保存在每项输入资产的审计对象及逐行记录里，业务事实和审计信息各自保留哈希。仅运行时间或供给任务变化，不应改变相同商品事实的数值输入指纹；商品、价格或真实观测日期变化则必须反映在事实指纹中。

规则及参数发布完成后，算法自动运行和发布；业务查看、抽样和提出重跑要求是结果复核，不是每次执行前都要人工点击批准。覆盖率、时效或用途规则尚未发布时，对应用途不启用，不能静默通过发布检查。

无合格候选时，仍保留运行清单、字段质量问题、来源摘要及可追溯证据；社媒未计算在运行参数声明，候选表和社媒候选状态表均为空。覆盖/缺报/时效写入mart_external_source_coverage_audit；未知分母/门槛写NULL和未确认状态，不能用技术PASS率替代覆盖率。07 不依赖采购输入成本或竞品事实，前端筛选条件只读取已发布结果。

同一批次、相同输入和规则重跑要复现同精度结果。数值取值种子从统一批次、锁定模型/证据摘要及候选业务键稳定生成；摘要计算排除运行 ID、计算时间等审计变化，`run_id` 不参与种子。运行 ID、计算时间和重跑原因单独留痕。

后续接入真实社媒或完整法规来源时，再扩展相应输入和字段合同；不能因此取消 V1 正式趋势层的模型和 FDR 条件。

### 11.1 本期执行与降级口径

开发先冻结久谦两表读取行、保存公开源原始快照，再产单指标证据、质量问题和来源覆盖审计，随后做属性映射与竞品关系；分别计算完整周观测、可用趋势、内部适配、候选、图片和05价格交接输入，最后按同一BATCH整包发布。

统计交易期、零售实际观测时间、文章发布时间和静态商品属性分别处理。静态商品资料没有交易日也能提供属性；零售采集可证明当时看到了报价，不能证明交易发生日期。同SKU日常、划线、会员、促销价格分开，POS名次不当销量。

无足够历史/正式模型时，概率为空、阶段为UNKNOWN；具备可靠商品身份、属性组合与内部需求的原始信号可作为探索候选。内部画像允许有真实消费证据的非主力画像，不以“非主力”等同没有需求。必要上游缺失则范围适配暂停；连合法范围键都没有时范围表为空，运行摘要记录原因。

覆盖审计同时显示应报、实报、有效、源缺报和未收到数量。示例：应报10、收到8，其中6有效、1源缺报、1无效，则有效覆盖60%、未收到2；这与“技术PASS/收到记录”不同。门槛未确认时只给统计、关闭依赖门槛的正式用途。

07向05逐商品交付来源键、外部规格和不同角色价格；无价格仍保留规格事实。05旧接口未改造时该消费者链路阻断，不能因为07文档已补齐就宣称最终推荐已可运行。07排序同层按可比较证据做Pareto，缺维度并列，不给缺图/缺社媒填0。


城市或城市群的真实区域编码和07内部稳定标识分别保留：前者用于读取02/03/04及价格交接，后者按固定规则生成并在适配与候选结果间直接传递。地区名称只用于解释，不用名称或两套不同编码混接结果。

增长概率分两步估计：先判断信号是否真实，再估计“信号真实时是否增长”。第二步的历史训练、校准和测试只使用已确认真实的样本，不把不真实信号再次作为增长负例。当前预测不需要预先知道未来是否真实；最后按联合概率合成，避免把真实性概率重复扣减。

### 11.2 外部价格定位怎么理解

外部基础/主流/高端说明商品在来源市场可比价格中的相对位置，国内建议售价由05计算。业务原文采用市场价格分布的峰谷和稳定性划分；技术先准备可比样本、试跑边界与反例，再由业务复核结果含义，不要求业务先凭经验填写每个小类的固定上下界。若要改为固定价带，另作业务变更，当前不默认采用。

当前售价、会员价、促销价、POS统计均价、批发行情及产地/门市参考价分别保留；有价格不等于已具备同口径日常零售价。缺币种、单位、规格、观察期或价格性质，以及分布样本不足/方法未验收时，档位为空并说明具体原因；不默认主流、不先取最低价。

同一候选有多个来源/价格角色时先逐价格定位；无法用一个比较范围和同一档位概括时，候选证据的汇总档位为空，各来源价格和原因仍保留。缺相对价位不阻断其他条件已通过的候选继续，也不替代05价格可行性。

久谦两表读取口径已明确，不再把原始响应表的取消列为待确认事项。来源实际启用、更新安排及两表输入行追溯仍须由技术拿配置和冻结样例验收；文档列出来源或更新频率不等于已接入/自动更新，回放行数和生产能力仍需实际证据。

## 12. 业务验收看什么

业务和开发评审重点看 8 件事：

| 验收点 | 看什么 |
|---|---|
| 来源追溯 | 每个外部候选能不能追到原始批次、链接、市场和来源 |
| 多语种映射 | 同义词是否映射到同一标准属性，未通过是否进入观察池 |
| 竞品关系 | 同款、高相似、同方向是否分开，是否先做硬边界 |
| 渠道渗透 | 分子分母是否正确，1/1 是否没有被当成 100% 高可信 |
| 社媒口碑 | V1 是否只有未计算状态快照、状态为 `V1_NOT_CALCULATED`，没有伪造口碑数值 |
| 趋势证据 | 官方价量、零售 SKU、POS 新品榜和行业文章是否分开，不互相冒充 |
| 内部适配 | 是否按当批区域快照落回内部小分类、主体需求、画像和门店等级；国内定价仍由算法 05 负责 |
| 图片和风险 | 图片是否标记来源，法规和安全线索是否随候选进入算法 08，并保留到算法 09 门禁 |

V1 固定复算样例：

```text
x=5,n=8
Jeffreys-Beta 后验中位数 = 61.97%
95% 可信区间 = [29.48%,88.10%]
```

Social NPS Proxy 不作为 V1 复算验收项。

来源修复还必须逐层验收：

| 验收层 | 必须能看到的证据 |
|---|---|
| 原始记录 | 来源行/原始快照、采集时间、原始代码/品名/单位/日期文字/数值；排除或降级后仍可追溯 |
| 身份与范围 | 已核验花卉规则的排除样例、未知类别隔离样例；14 个缺身份代码逐码匹配结果、官方字典依据和有效范围；未匹配继续隔离 |
| 单位与日期 | 商务逐商品单位映射和源百分比独立保存；香港相对日期不自动转交易日；缺报写 NULL，真实 0 保持为 0 |
| 聚合对账 | 过滤前后来源行数、标准证据数、不同问题证据数、字段问题数和 INFO 数分别核对；价格/数量对应同源行不重复放大覆盖率 |
| 公式与正式层 | 渗透分子分母可复算；FDR 按候选集合均值判定；没有可靠历史或数值未收敛时无正式概率和正式增长状态 |
| 批次与发布 | 所有正式结果含同一个 BATCH_YYYYMM；同输入同批重跑结果同精度一致；输入/规则/区域快照不变；前端读取单一发布结果，失败运行不覆盖旧结果 |

验收记录保留样例范围、SQL/脚本、输入和输出行数、差异、失败样例及处理结论。仅提供“技术 PASS 条数”不能替代这些字段级验收。

## 13. 现在还需要确认什么

当前只保留尚未发布规则、会影响对应用途的事项：

| 确认项 | 需要谁确认 | 影响与未确认处理 |
|---|---|---|

花卉排除规则已确认，按下一完整月批次生效，原始快照保留；未知类别不按花卉删除。官方商品代码字典的获取、14 个代码的逐码匹配，以及现有合同是否按要求稳定落库，属于数据开发验收，见上一节，不再让业务逐码猜测或重复确认已冻结合同事实。

## 14. 不要做什么

```text
不能将外部趋势单独作为最终新品推荐
不能将外部社媒账号推断成内部会员画像
不能将广告、点赞、收藏、转载直接当成自然趋势
不能将同一行业报告的多次转载当成多条独立证据
不能将同一品牌全球发布当成多个市场自然扩散
不能将不同平台原始销量、播放量、点赞量或评论量直接相加
不能将采集失败、源未报价或缺失数据写成 0
不能将类别缺失按花卉整批删除，或删除被排除对象的原始快照
不能凭商品代码、近似品名或内部属性词典猜源商品身份和计价单位
不能把商务百分比反推为绝对价格，或在用途未发布时默认进入趋势
不能用采集日前一天或修订日替代香港交易日期
不能把 INFO 计为待业务修复的异常，或用问题记录数代替问题证据/商品数
不能将技术 PASS、任务 SUCCESS 和正式发布视为同一状态
不能把多个成功运行一起汇总，或用新运行 ID 生成新的业务版本
不能将 1/1 渠道渗透表述为高可信 100%
不能将同款、高相似品和趋势属性渗透混成一个分子
不能将 Social NPS Proxy 写成标准问卷 NPS
不能将海外趋势写成国内已流行
不能将海外价格按汇率换算成国内建议价
不能将多个独立热词擅自拼成一个商品
不能将无法映射的商品强行归入语义最相似的小分类
不能用人工固定权重综合分消灭证据冲突
不能把集合均值 5% FDR 改成每条候选局部误发现率必须不超过 5%
不能因未接入社媒就绕过正式趋势层的贝叶斯模型、FDR 和收敛要求
不能在同月重跑时改读当前规则、参数或城市区域映射
不能因外部趋势强就越过当前货盘或历史差销过滤
不能在算法 09 风险门禁前宣称新品已正式进入开发
```

## 15. 一句话总结

算法 07 的关键是：

```text
先证明外部趋势真实、自然、可追溯；
再证明它能落回内部小分类、目标画像、门店等级和主体需求；
最后只把通过证据和适配校验的候选交给算法 08、算法 09 和算法 10。
```
