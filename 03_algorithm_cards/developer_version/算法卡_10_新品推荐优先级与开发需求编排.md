# 算法卡_10_新品推荐优先级与开发需求编排

更新时间：2026-09-04

业务原始依据：`01_source_docs/business_algorithm_docs/算法卡_10_新品推荐优先级与开发需求编排.md`

业务解读依据：`03_algorithm_cards/business_readable/算法10_新品推荐优先级与开发需求编排_业务解读版.md`

开发交付定位：本卡是算法 10 的 V1 开发版算法卡，用于数据开发建设新品推荐展示、同范围优先级、自动解释、推荐卡片、详情展示摘要、范围汇总和审计结果。算法 10 V1 只输出推荐类候选，不做不推荐追问解释，不做候选标准化，不做风险门禁，不修改上游候选事实，不做供应商匹配，不输出下游发布材料。

## 1. 算法目标

算法 10 读取算法 09 的正式门禁结果，把已完成门禁的新品候选编排成采购、产品、Agent 可读取的推荐展示结果。

本算法做：

```text
1. 锁定算法 09 gate_run_id（门禁运行批次 ID）和算法 08 candidate_registry_run_id（候选注册运行批次 ID）。
2. 读取算法 09 中可进入推荐展示的 new_product_gate_result（最终门禁结果表），只包括 `PASS` 和 `CONDITIONAL_PASS`。
3. 校验候选身份、范围、版本、门禁结果和最终候选状态是否一致。
4. 将 new_product_gate_result（门禁结果）和 final_candidate_status（最终候选状态）映射为 recommendation_display_label（推荐展示标签）。
5. 读取算法 09 已合成的共同证据维度，展开为一行一维度。
6. 在同一 comparison_cell_id（可比较单元 ID）内做 Pareto 前沿对账和优先级编排。
7. 计算或继承第一前沿稳定概率；无法计算时写显式状态，不伪造概率。
8. 生成结构化事实载荷、确定性解释文本和默认 LLM 润色结果；LLM 不可用或事实校验失败时回退模板。
9. 生成推荐列表卡片和详情展示摘要，卡片默认包含图片展示位。
10. 输出 8 张正式结果表。
```

本算法不做：

```text
1. 不重新计算算法 01-07 的画像、等级、贡献、锚点、价格、购物篮和外部趋势。
2. 不重新标准化、合并或拆分候选；候选身份由算法 08 负责。
3. 不重新判断风险门禁；门禁由算法 09 负责。
4. 不修改商品名、规格、配料、口味、工艺、售价、成本或毛利。
5. 不用前端交互或人工权重改变推荐结果。
6. 不生成 0-100 机会分或新品成功概率。
7. 不把不同叶子小分类强行合并成统一总榜。
8. 不做供应商准入、匹配、触达、评分、报价排序。
```

## 3. 开发执行流程

算法 10 是离线或准离线批量计算，不在采购前端或 Agent 查询时实时重算。

运行步骤：

```text
1. 创建 recommendation_run_id（推荐运行批次 ID）。
2. 锁定 recommendation_algorithm_version（算法 10 版本）、recommendation_display_mapping_version（展示标签映射版本）、gate_run_id（算法 09 门禁批次）、candidate_registry_run_id（算法 08 候选注册批次）、formal_period（正式周期）和 data_cutoff_at（数据截止时间）。
3. 读取同一 gate_run_id 下 `new_product_gate_result in (PASS, CONDITIONAL_PASS)` 的推荐候选，不做 Top N 过滤。
4. 关联 new_product_candidate_snapshot、candidate_opportunity_evidence、candidate_risk_evidence、mart_new_product_candidate_scope 和 new_product_standard_candidate_registry。
5. 执行唯一性、版本包、候选身份、门禁结果和最终候选状态校验。
6. 对每条门禁结果生成 recommendation_result_id（推荐结果 ID）和输入快照。
7. 按确定性映射表生成 recommendation_display_label（推荐展示标签）。
8. 展开 common_dimension_metrics_json（共同证据维度 JSON），写入证据维度表。
9. 在同一 comparison_cell_id 内计算或复核 Pareto 非支配分层。
10. 计算 front_1_probability（第一前沿稳定概率）；缺少不确定性来源时写 `UNCERTAINTY_SOURCE_MISSING`。
11. 生成 recommendation_fact_payload_json（推荐事实载荷 JSON）和 deterministic_template_text（确定性模板文本）。
12. 默认调用 LLM 将模板文本润色为采购大白话；改写后必须做数字、实体、门禁和禁用表述校验，失败时回退确定性模板。
13. 按展示摘要模板生成 display_brief_id（展示摘要 ID）、列表卡片字段、详情模块字段和图片展示状态。
14. 写入 8 张正式结果表的临时分区。
15. 通过数量、唯一键、状态、事实校验和摘要完整性检查后，标记 run_status = SUCCESS 并发布。
```

失败处理：

```text
任一关键表写入失败或唯一性校验失败：run_status = FAILED。
正式读取视图继续指向上一 SUCCESS 批次。
PARTIAL_SUCCESS 只允许用于部分推荐候选因输入对账异常未生成推荐主表行，但输入快照、审计、异常和对账均已落库的场景。
```

查询口径：

```text
采购前端第一版输入的是筛选条件，只包括运营区域、城市、大分类、中分类、小分类。
这些条件只过滤算法 10 已发布结果，不是采购手工输入候选商品、规格、成本或排名。
门店等级、消费者画像、推荐展示标签和候选状态可以作为结果字段展示或后续扩展筛选项，但不是算法 10 V1 的采购必填查询条件。
```

发布和查询链路：

```text
算法 09 发布 gate_run_id
-> 算法 10 生成 recommendation_run_id
-> 8 张结果表写入临时分区
-> 数据质量验收通过
-> new_product_recommendation_run.run_status = SUCCESS
-> 正式读取视图指向该 SUCCESS 批次
-> 前端和 Agent 只读正式视图，不实时重算
```

如果算法 09 重新发布门禁结果，或成本、货盘、法规规则、图片授权状态等上游事实变化，算法 10 必须生成新的 `recommendation_run_id`，不得在旧 `recommendation_result_id` 上静默覆盖。

## 5. 粒度、主键和版本

### 5.1 正式计算粒度

一条算法 10 主结果代表：

```text
recommendation_algorithm_version（算法 10 版本）
+ gate_run_id（算法 09 门禁运行批次）
+ formal_period_start / formal_period_end（正式周期）
+ target_city_group_id（城市/城市群）
+ final_level（门店等级）
+ final_profile（消费者画像）
+ leaf_category_id（叶子小分类）
+ candidate_scope_result_id（范围候选结果 ID）
```

同一标准候选在不同城市、门店等级、画像、小分类或价格方案下必须生成不同推荐结果。

采购查询使用 `operation_region_name`、`city_name`、`category_level1_code`、`category_level2_code` 和 `leaf_category_id` 过滤已发布结果。大类、中类和运营区域是展示与筛选冗余字段，不改变算法 09 已冻结的候选范围身份。

### 5.2 关键 ID 生成

`*_hash` 和通过 SHA-256 生成的 ID 是开发对账字段，不是业务分数。

| ID 或校验码 | 中文含义 | 生成载荷 | 用途 |
|---|---|---|---|
| `recommendation_run_id` | 推荐运行批次 ID | 算法版本、正式周期、候选注册批次、门禁批次 | 标识一次算法 10 运行 |
| `recommendation_result_id` | 推荐结果 ID | `gate_run_id` + `candidate_scope_result_id` + 算法 10 版本 | 标识一条推荐结果 |
| `display_brief_id` | 展示摘要 ID | `recommendation_result_id` + 展示模板版本 + 候选载荷校验码 | 标识一份展示摘要 |
| `input_snapshot_hash` | 输入快照校验码 | 09 给 10 的候选、门禁、证据和版本事实 | 发现输入是否被静默改动 |
| `result_payload_hash` | 推荐结果载荷校验码 | 展示标签、前沿、稳定概率、状态和摘要 | 验证推荐结果可复算 |
| `display_brief_payload_hash` | 展示摘要载荷校验码 | 摘要字段、模板版本和证据引用 | 验证展示摘要未被静默改动 |

规范化载荷要求：

```text
UTF-8 编码；
JSON key 按字典序；
空字段使用显式 null；
数组按业务定义排序；
金额和概率按来源存储精度格式化；
同一载荷重复计算必须生成同一 ID 或校验码。
```

## 6. 核心计算逻辑

### 6.1 推荐输入池

算法 10 V1 必须读取同一 `gate_run_id` 下可进入推荐展示的 `new_product_gate_result`。

```text
必须读取 PASS 和 CONDITIONAL_PASS；
不能先做 Top N；
RETURN_FOR_REBUILD 和 REJECT 不进入算法 10 V1 推荐输出；
不能把页面筛选条件当成算法输入。
```

只保留推荐输入池的原因：

```text
算法 10 V1 只做新品推荐和推荐理由；
不做不推荐候选的追问解释；
退回重做和拒绝原因留在算法 09 或后续 Agent 能力中。
```

### 6.2 输入准入和异常

| 校验项 | 通过条件 | 不通过写法 |
|---|---|---|
| 门禁批次唯一 | 同一 `candidate_scope_result_id` 在同一 `gate_run_id` 只有一条门禁结果 | 不生成推荐主表行；审计表写 `exception_code = DUPLICATE_GATE_RESULT` |
| 候选身份唯一 | 同一范围候选只关联一个 `standard_candidate_id` | 不生成推荐主表行；审计表写 `CANDIDATE_IDENTITY_CONFLICT` |
| 版本一致 | 09 快照中的 `candidate_registry_run_id` 与 08 表一致 | 不生成推荐主表行；审计表写 `UPSTREAM_VERSION_BUNDLE_CONFLICT` |
| 候选载荷一致 | 09 快照中的 `candidate_payload_hash` 与 08 范围候选表一致 | 不生成推荐主表行；审计表写 `CANDIDATE_PAYLOAD_CHANGED` |
| 门禁与状态一致 | 门禁结果和最终候选状态符合第 6.3 节映射规则 | 不生成推荐主表行；审计表写 `GATE_STATUS_CONFLICT` |
| 展示标签一致 | 09 门禁结果和最终候选状态可稳定映射到展示标签 | 不生成推荐主表行；审计表写 `DISPLAY_MAPPING_CONFLICT` |
| 不具备新品资格排除 | `final_candidate_status` 不得为 `NOT_ELIGIBLE_FOR_NEW_PRODUCT` | 不生成推荐主表行；审计表写 `NOT_ELIGIBLE_STATUS_IN_RECOMMENDATION_INPUT` |

输入对账异常的候选只进入输入快照、审计和范围汇总统计，不进入采购可见的推荐主表、解释表或展示摘要表。

异常不跨范围回退：

```text
上海 A 级异常，不能用上海 B 级结果替代；
牛肉制品异常，不能用净菜或鲜鸡蛋结果替代；
目标画像异常，不能用其他画像结果替代。
```

### 6.3 推荐展示标签映射

| 算法 09 门禁结果 | 算法 09 最终候选状态 | 算法 10 推荐展示标签 | 中文含义 |
|---|---|---|---|
| `PASS` | `FORMAL_NEW_PRODUCT` | `FORMAL_RECOMMENDATION` | 正式推荐展示 |
| `PASS` | `SEASONAL_NEW_PRODUCT` | `SEASONAL_RECOMMENDATION` | 季节推荐展示 |
| `PASS` | `LOCAL_PILOT_NEW_PRODUCT` | `LOCAL_PILOT_RECOMMENDATION` | 局部试点展示 |
| `PASS` | `EXPLORATORY_NEW_PRODUCT` | `EXPLORATORY_RECOMMENDATION` | 探索推荐展示 |

说明：


### 6.6 Pareto 非支配分层

只在同一 `comparison_cell_id` 内比较。

候选 A 支配候选 B 当且仅当：

```text
1. A 和 B 属于同一个 comparison_cell_id；
2. A 和 B 的共同适用维度集合一致；
3. 对所有共同适用维度，A 都不劣于 B；
4. 至少一个共同适用维度，A 优于 B。
```

分层步骤：

```text
1. 找出没有被其他候选支配的候选，写 pareto_front_id = PF_1。
2. 从剩余集合中移除第一前沿。
3. 在剩余候选里继续找第二前沿，写 pareto_front_id = PF_2。
4. 直到所有可比较候选都有前沿。
```

单候选处理：

```text
同一 comparison_cell_id 只有一个候选：
pareto_front_id = PF_1
singleton_cell_flag = 1
```

全并列处理：

```text
所有候选互不支配：
全部保留在 PF_1
substantive_tie_flag = 1
```

### 6.7 第一前沿稳定概率

`front_1_probability` 只用于说明第一前沿结果对上游不确定性的稳定程度，不是新品成功概率。

计算口径：

```text
对同一 comparison_cell_id 做可重复抽样；
每次用同一指标方向和同一 Pareto 规则重算前沿；
front_1_probability = 候选落在第一前沿的有效次数 / 有效抽样次数。
```

状态处理：

| 场景 | 写法 |
|---|---|
| 不确定性来源齐全且收敛 | `pareto_stability_status = CONVERGED`，写入 `front_1_probability` |
| 不确定性来源缺失 | `pareto_stability_status = UNCERTAINTY_SOURCE_MISSING`，`front_1_probability = NULL` |
| 计算未收敛 | `pareto_stability_status = COMPUTE_NOT_CONVERGED`，`front_1_probability = NULL` |
| 不适用场景 | `pareto_stability_status = NOT_APPLICABLE`，`front_1_probability = NULL` |

### 6.9 自动解释

## 9. 缺失值、异常值和不适用值

统一规则：

```text
1. 缺失数值写 null，并配套状态或原因码。
2. 不适用写 NOT_APPLICABLE，不填 0。
3. 不可评估写 NOT_EVALUABLE；若因此无法生成推荐卡片，写审计异常，不输出推荐主表行。
4. 0 只表示真实计算结果为 0。
5. Social NPS Proxy 在 V1 不计算，字段如出现必须为 null，状态写 V1_NOT_CALCULATED。
6. 图片未授权或身份不匹配时，图片 ID 可以保留审计，但主结果不得展示该图。
7. 展示摘要缺字段时必须写 missing_display_fields_json，不能猜测包装、保质期、标签材料或供应商信息。
```

## 10. 验收样例

### 10.1 正式推荐展示样例

输入：

```text
candidate_display_name = 青椒黑椒牛柳丝 200g
new_product_gate_result = PASS
final_candidate_status = FORMAL_NEW_PRODUCT
```

期望：

```text
recommendation_display_label = FORMAL_RECOMMENDATION
recommendation_status = DISPLAY_READY
display_brief_status = COMPLETE
```

### 10.2 法规留痕不阻断样例

输入：

```text
candidate_display_name = Omega-3 鲜鸡蛋 12 枚
new_product_gate_result = PASS
算法 07 传递 Omega-3 功能声称风险线索
09 V1 不启用法规硬门禁
```

期望：

```text
recommendation_display_label = FORMAL_RECOMMENDATION
recommendation_status = DISPLAY_READY
展示文案可以写“存在功能声称风险线索，后续需补材料确认”，不能写成“法规已通过”，也不能写成发布动作。
```

### 10.3 条件推荐展示样例

输入：

```text
candidate_display_name = 燕麦酸奶杯 180g
new_product_gate_result = CONDITIONAL_PASS
condition_to_clear_json 包含真实报价待补或验证条件
```

期望：

```text
recommendation_display_label = CONDITIONAL_RECOMMENDATION
recommendation_status = DISPLAY_REVIEW_REQUIRED
必填展示字段齐全时 display_brief_status = COMPLETE
缺必填展示字段时 display_brief_status = INCOMPLETE
展示文案必须说明待补条件，不能写成正式推荐。
```

### 10.4 09 排除候选不进入 10 样例

输入：

```text
new_product_gate_result = RETURN_FOR_REBUILD
final_candidate_status = NOT_ELIGIBLE_FOR_NEW_PRODUCT
```

期望：

```text
不生成 mart_new_product_recommendation_priority 行；
不生成 new_product_recommendation_explanation 行；
不生成 new_product_recommendation_display_brief 行。
```

### 10.5 09 拒绝候选不进入 10 样例

输入：

```text
new_product_gate_result = REJECT
算法 09 已判定当前货盘存在同款
```

期望：

```text
不生成算法 10 推荐展示、解释或摘要。
原因保留在算法 09；算法 10 V1 不做不推荐追问。
```

### 10.6 Pareto 并列样例

输入：

```text
候选 A 与候选 B 在同一 comparison_cell_id；
A 在需求稳定性更好；
B 在价格成本可行余量更好；
其他共同维度互有高低。
```

期望：

```text
A 不支配 B；
B 不支配 A；
两者同在第一前沿；
如果稳定概率不同，可以影响默认展示顺序；
如果实质键完全相同，substantive_tie_flag = 1。
```

## 11. 数据质量验收清单

| 验收项 | 检查方式 | 失败处理 |
|---|---|---|
| 输入输出数量对账 | `PASS + CONDITIONAL_PASS` 输入数 = 推荐结果数 + 输入对账异常数 | `run_status = FAILED` 或 `PARTIAL_SUCCESS` |
| 唯一键验收 | 每张表主键或唯一键无重复 | 阻断发布 |
| 版本包一致 | `gate_run_id`、`candidate_registry_run_id` 和版本包一致 | 阻断发布 |
| 候选载荷一致 | 09 快照与 08 候选范围表校验码一致 | 阻断该候选 |
| 展示标签映射一致 | 按第 6.3 节全量检查 | 不一致写 `DISPLAY_MAPPING_CONFLICT` |
| 门禁不可提升 | `REJECT`、`RETURN_FOR_REBUILD` 不进入算法 10 输出；`CONDITIONAL_PASS` 不被写成正式推荐展示 | 阻断发布 |
| Pareto 复算 | 同一 comparison_cell_id 重跑前沿，结果稳定 | 不一致写 `MISMATCHED` |
| 输入顺序不变 | 打乱候选输入顺序多次，前沿和展示顺序不变 | 修正排序或 ID 生成逻辑 |
| 文本事实校验 | 文本中的数字、价格、规格、实体和门禁都能回到事实载荷 | 回退确定性模板 |
| Social NPS V1 校验 | 不出现“社媒口碑好”等正式口碑结论 | 阻断解释发布 |
| 展示摘要完整性 | 必填字段齐全或模板明确允许留空 | 不完整时标记为展示不完整 |
| 图片校验 | 图片候选 ID、授权状态和身份匹配 | 图片置空或标记不可展示 |
| 审计验收 | 查询和异常均不改变算法结果 | `algorithm_result_changed_by_event_flag` 必须为 0 |

## 12. 调度和发布

| 运行类型 | 触发条件 | 输出 |
|---|---|---|
| 月度正式运行 | 算法 09 正式 `gate_run_id` 发布后 | 8 张正式表 |
| 门禁重算后运行 | 算法 09 因新成本、新法规、新货盘或证据修正生成新 `gate_run_id` | 新 `recommendation_run_id`，不覆盖旧结果 |
| 回溯重算 | 历史周期修复或规则版本变更 | 新批次结果和审计 |
| 查询读取 | 采购、产品或 Agent 查询 | 只读最新 SUCCESS 批次，不实时计算 |

原子发布要求：

```text
8 张正式表先写临时分区；
质量验收通过后统一发布；
失败时正式视图继续指向上一 SUCCESS 批次。
```

## 13. 不能做的事

```text
不能沿用已废弃的旧顺序或旧职责表述。
不能绕过算法 09 直接推荐算法 06 或算法 07 的候选。
不能把算法 08 未就绪候选展示成正式推荐。
不能把 CONDITIONAL_PASS 写成正式通过。
不能把 RETURN_FOR_REBUILD 或 REJECT 放进算法 10 V1 推荐展示表。
不能用人工权重、前端交互或拖拽改优先级。
不能生成 0-100 机会分或新品成功概率。
不能跨叶子小分类、门店等级或消费者画像做统一总榜。
不能让 LLM 新增事实、属性、价格、风险、趋势或动作。
Social NPS Proxy 在 V1 必须标记为暂不计算。
不能把供应商匹配、触达、报价排序写进算法 10。
不能在同一 recommendation_result_id 上静默修改门禁、展示标签、解释或展示摘要。
```
