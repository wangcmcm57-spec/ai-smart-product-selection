# 算法卡_09_新品机会证据合成与风险门禁

更新时间：2026-08-21

业务原始依据：`01_source_docs/business_algorithm_docs/算法卡_09_新品机会证据合成与风险门禁.md`

业务解读依据：`03_algorithm_cards/business_readable/算法09_新品机会证据合成与风险门禁_业务解读版.md`

开发交付定位：本卡是算法 09 的 V1 开发版算法卡，用于数据开发建设新品机会证据合成、风险门禁、最终候选状态、动作映射和审计重算结果。算法 09 不重算算法 02-07，不标准化合并候选，不做供应商判断，不修改商品规格、配方、成本或价格。

## 1. 算法目标

算法 09 汇总算法 02-07 已产出的机会证据，对算法 08 标准化后的范围候选执行商品相关风险门禁，输出最终门禁结果、候选状态和允许动作。

本算法做：

```text
1. 锁定算法 02-07 上游正式版本和数据截止时间。
2. 读取标准新品候选、范围候选、候选属性来源、价格成本、内部购物篮和外部趋势证据。
3. 校验候选核心数据、属性来源、小分类保持和候选 payload 是否静默变化。
4. 计算当前货盘同款/高相似风险。
5. 计算历史失败同款/高相似风险。
6. 执行法规、食品安全、标签、功能声称和知识产权门禁。
7. 读取算法 05 价格成本毛利可行性，不重算价格带。
8. 构建真实历史经营情景，执行毛利压力测试。
9. 合成机会证据、单项风险和 Pareto 前沿。
10. 输出 `PASS`、`CONDITIONAL_PASS`、`RETURN_FOR_REBUILD`、`REJECT`。
```

本算法不做：

```text
1. 不重新贴会员画像。
2. 不重新给门店评级。
3. 不重新计算 SKU 锚点、价格带、购物篮规则或外部趋势。
4. 不把候选标准化、去重和合并；标准候选由算法 08 负责。
5. 不直接修改候选商品材料、配方、口味、规格、售价或成本。
6. 不做供应商准入、匹配、邀请、评分、排序或触达。
7. 不输出促销、陈列、订购、升级、替换、清退动作。
8. 不生成固定权重机会分或风险总分。
9. 不让高机会证据抵消硬门禁。
```

## 3. 开发执行流程

算法 09 是离线或准离线计算，不在查询服务请求时实时重算法规、相似模型、生存模型或毛利情景。

运行顺序：

```text
1. 生成 gate_run_id，锁定 formal_period、data_cutoff_at 和上游版本。
2. 只读取算法 08 已标记可进入 09 的范围候选，生成 new_product_candidate_snapshot。
3. 校验标准候选、属性来源、小分类、算法 05 可行性、货盘快照和法规版本。
4. 当前货盘重复门禁：汇总公司级可订可售商品，计算同款/高相似/灰区。
5. 历史失败门禁：构建历史生命周期、可订可售状态变化、可用退出原因和多证据失败标签；退出原因缺失时按不确定结局处理。
6. 法规门禁：规则引擎执行确定性条款，AI 只负责字段提取和解释文本。
7. 价格毛利静态门禁：读取算法 05 的价格、成本、毛利和可行性状态。
8. 折扣依赖和毛利压力：基于历史真实门店日情景执行 K-medoids 压力测试。
9. 外部同质化和差异属性：读取算法 07 竞品覆盖和风险线索，判断差异属性。
10. 机会证据合成：校验 02-05 基础条件和 06/07 属性来源，生成证据层级。
11. 按风险优先级生成 new_product_gate_result。
12. 复核或补证后，生成新的 gate_run_id 重算，不覆盖原始结果。
```

### 3.1 候选准入规则

算法 09 的正式候选入口只有算法 08：

```text
mart_new_product_candidate_scope
```

正式运行只接收：

```text
algorithm_09_readiness IN (
  READY_FOR_ALGORITHM_09,
  READY_WITH_ESTIMATED_COST
)
```

处理规则：

| 算法 08 就绪状态 | 09 是否生成候选快照 | 09 处理方式 |
|---|---|---|
| `READY_FOR_ALGORITHM_09` | 是 | 正常进入机会证据合成和风险门禁 |
| `READY_WITH_ESTIMATED_COST` | 是 | 正常进入 09，但价格毛利风险中必须生成估算成本补证条件 |
| `NOT_READY_MISSING_PRICE_RESULT` | 否 | 不进入 09 十张正式表；记录在 08 表中等待算法 05 补价格成本 |
| `REGISTRATION_EXCEPTION` | 否 | 不进入 09 十张正式表；记录在 08 异常表中等待上游修正 |

过滤不是删除。被过滤的候选仍保留在算法 08 表中，用于补字段、修正规则和重跑。算法 10、Agent 和查询服务只能读取 09 正式结果，不得绕过 09 直接展示这些未就绪候选。

算法 09 不接收人工手工录入的候选商品、规格、成本、风险或法规条款。人工复核只能补充或修正证据，再触发新批次重算。

## 6. 关键算法逻辑

### 6.1 核心数据完整性

以下任一核心数据缺失时，不得生成可发布候选：

```text
正式小分类映射
standard_candidate_id
具象候选商品名和规格
候选属性来源 ID
算法 05 价格成本可行性
当前公司级可订可售货盘快照
有效法规知识库版本
```

输出：

```text
risk_type = CORE_DATA_QUALITY
risk_state = NOT_EVALUABLE
new_product_gate_result = RETURN_FOR_REBUILD
```

历史换码、替代和退出原因缺失时，不作为算法 09 整体运行阻断。V1 先用商品基础表 SPU 做标准实体辅助归并；缺正式换码、替代、历史退出原因或真正经营失败规则时，历史结局写 `UNCERTAIN_OUTCOME`，相似关系无法确认时写 `SIMILARITY_GRAY_REVIEW`，历史失败门禁写 `HISTORICAL_FAILURE_REVIEW_REQUIRED` 或 `INSUFFICIENT_HISTORICAL_EVIDENCE`，不得输出历史失败硬拒绝。

### 6.2 最低机会证据

四项基础条件必须全部满足：

```text
store_level_support_status = SUPPORTED
AND target_profile_support_status = SUPPORTED
AND base_product_support_status = SUPPORTED
AND price_feasibility_status IN (PRICE_FEASIBLE, FLOOR_ONLY_FEASIBLE)
```

新品属性来源至少满足一条：

```text
basket_evidence_status IN (FORMAL_BASKET_ATTRIBUTE, EXPLORATORY_BASKET_ATTRIBUTE)
OR external_evidence_status IN (
  FORMAL_GROWING_TREND,
  MATURE_MARKET_GAP,
  EMERGING_EXPLORATORY,
  OVERSEAS_LEADING_EXPLORATORY
)
```

不适用字段必须写 `NOT_APPLICABLE`，不能填 0。

### 6.3 当前货盘重复门禁

公司级当前货盘定义：

```text
同一商品在最新可订可售快照中任一门店是否可售 = 1 或 是否可订 = 1
=> 公司当前货盘存在
```

门禁：

```text
similarity_relation = EXACT_EQUIVALENT
-> risk_state = HARD_STOP
-> new_product_gate_result = REJECT

similarity_relation = BUSINESS_HIGH_SIMILAR
AND similarity_probability >= tau_similarity
AND similarity_gate_status = HARD_GATE_CONFIRMED
-> risk_state = HARD_STOP
-> new_product_gate_result = REJECT

similarity_relation = SIMILARITY_GRAY_REVIEW
-> risk_state = CONDITION_REQUIRED
-> new_product_gate_result = CONDITIONAL_PASS
```

### 6.4 历史失败门禁

历史结局标签：

```text
CONFIRMED_FAILURE
PROBABLE_FAILURE
UNCERTAIN_OUTCOME
NON_FAILURE_COMPETING_EVENT
RIGHT_CENSORED_ACTIVE
```

V1 处理顺序：

```text
1. 先用 mart_store_sku_daily_sale_order_status 判断商品在门店 SKU 日粒度的可订/可售状态变化。
2. 再用 mart_sku_margin_loss、mart_store_sku_daily_price 描述停止前的销售、折扣、成本和毛利表现。
3. 如果已配置季节窗口、换码关系、替代关系、供应中断、法规退出、策略退出和经营失败规则，则按规则识别退出结局。
4. 如果缺历史退出原因判定规则或真正经营失败判定规则，只能写 UNKNOWN_EXIT / UNCERTAIN_OUTCOME / INSUFFICIENT_HISTORICAL_EVIDENCE，不得由无销量、停订、负毛利或折扣依赖直接推导经营失败。
```

退出原因识别优先级：

| 优先级 | 可判定结局 | 触发条件 | 09 输出 |
|---|---|---|---|
| 1 | 仍在售 | 截止日仍可订或可售，或停订后已恢复可订可售 | `historical_exit_reason = STILL_ACTIVE`，`historical_outcome_status = RIGHT_CENSORED_ACTIVE` |
| 2 | 季节结束 | 商品季节状态和销售季窗口证明停订属于正常季节结束 | `historical_exit_reason = SEASONAL_END`，`historical_outcome_status = NON_FAILURE_COMPETING_EVENT` |
| 3 | 换码或 SPU 迁移 | 正式换码关系、迁移规则或业务确认规则证明旧码迁移到新码 | `historical_exit_reason = CODE_REPLACEMENT`，`historical_outcome_status = NON_FAILURE_COMPETING_EVENT` |
| 4 | 供应中断 | 供应中断规则或业务记录证明停订由供应问题导致 | `historical_exit_reason = SUPPLY_INTERRUPTION`，`historical_outcome_status = NON_FAILURE_COMPETING_EVENT` |
| 5 | 法规或食安退出 | 法规、质量或食品安全规则证明退出由合规事件导致 | `historical_exit_reason = REGULATORY_EXIT`，`historical_outcome_status = NON_FAILURE_COMPETING_EVENT` |
| 6 | 经营策略调整 | 策略调整规则或业务记录证明退出由货盘、区域、品牌等策略导致 | `historical_exit_reason = STRATEGY_EXIT`，`historical_outcome_status = NON_FAILURE_COMPETING_EVENT` |
| 7 | 真正经营失败 | 已配置经营失败规则，且排除季节、换码、供应、法规、策略等竞争原因后，经营失败条件成立 | `historical_exit_reason = PERFORMANCE_FAILURE_EXIT`，`historical_outcome_status = CONFIRMED_FAILURE` |
| 8 | 原因未知 | 无法确认以上任一结局，或证据冲突 | `historical_exit_reason = UNKNOWN_EXIT`，`historical_outcome_status = UNCERTAIN_OUTCOME` |

说明：

```text
PROBABLE_FAILURE 只能表示多项经营信号提示疑似失败。
在 V1 未配置正式经营失败规则前，PROBABLE_FAILURE 不得进入历史失败硬拒绝。
```

竞争风险生存模型：

```text
h_ik(t)
= P(T_i=t, J_i=k | T_i>=t, x_i, scope_i)

log[h_ik(t) / h_i0(t)]
= alpha_k(t)
 + u_k,city_group
 + v_k,final_level
 + w_k,leaf_category
 + beta_k' * x_i

S_i(t)
= PRODUCT_{s=1..t} [1 - SUM_k h_ik(s)]

F_i,failure(H)
= SUM_{t=1..H} S_i(t-1) * h_i,failure(t)
```

候选失败后验：

```text
candidate_failure_probability
= E[F_failure(H) | x_candidate, target_scope, model_version]
```

硬拒绝条件：

```text
exit_reason_rule_status = RULE_CONFIGURED
AND historical_exit_reason = PERFORMANCE_FAILURE_EXIT
AND historical_outcome_status = CONFIRMED_FAILURE
AND similarity_relation IN (EXACT_EQUIVALENT, BUSINESS_HIGH_SIMILAR)
AND failure_probability_ci_low_95 > dynamic_failure_threshold
AND historical_stability_status = STABILITY_PASSED
AND key_data_quality_status = CLEAR
```

输出：

```text
risk_type = HISTORICAL_FAILURE
risk_state = HARD_STOP
historical_failure_gate_status = HISTORICAL_FAILURE_HARD_STOP
new_product_gate_result = REJECT
```

非硬拒绝输出：

| 场景 | 历史失败门禁状态 | 风险状态 | 最终结果影响 |
|---|---|---|---|
| 经营信号疑似失败，但缺业务确认规则 | `HISTORICAL_FAILURE_REVIEW_REQUIRED` | `CONDITION_REQUIRED` | 需要业务复核或补规则；不得直接 `REJECT` |
| 退出原因未知、换码/替代关系缺失或证据不足 | `INSUFFICIENT_HISTORICAL_EVIDENCE` | `OBSERVED_NON_BLOCKING` | 只保留风险线索，不改变最终门禁结果 |
| 明确为季节结束、换码、供应中断、法规退出或策略退出 | `HISTORICAL_FAILURE_CLEAR` | `CLEAR` | 不作为经营失败风险 |

### 6.5 法规、食品安全和知识产权门禁

规则结果映射：

```text
REGULATION_HARD_STOP
-> risk_state = HARD_STOP
-> new_product_gate_result = REJECT

REGULATION_DOCUMENT_REQUIRED 或 REGULATION_MANUAL_REVIEW
-> risk_state = CONDITION_REQUIRED
-> new_product_gate_result = CONDITIONAL_PASS

REGULATION_RULE_MISSING
-> risk_state = NOT_EVALUABLE
-> new_product_gate_result = RETURN_FOR_REBUILD

REGULATION_CLEAR
-> risk_state = CLEAR
```

AI 只做候选名称、属性、配方、标签字段提取和解释文本生成，不自行判断规则失效或放宽法规条件。

### 6.6 算法 05 价格成本毛利接口

算法 09 只读取算法 05 结果。

```text
price_feasibility_status = NO_FEASIBLE_INTERSECTION
OR margin_position_status = NO_FLOOR_INTERSECTION
-> risk_state = HARD_STOP
-> new_product_gate_result = REJECT
```

若算法 05 仍有可行交集，但成本只是 V1 估算：

```text
risk_state = CONDITION_REQUIRED
risk_type = PRICE_MARGIN_FEASIBILITY
condition_to_clear = ACTUAL_COST_EVIDENCE_REQUIRED
```

V1 中 `price_feasibility_status` 由算法 05 字段派生：

| 09 派生状态 | 算法 05 触发条件 |
|---|---|
| `PRICE_FEASIBLE` | `margin_position_status IN (TARGET_MARGIN_IN_CORE, TARGET_MARGIN_IN_EXTENDED)` |
| `FLOOR_ONLY_FEASIBLE` | `margin_position_status IN (FLOOR_MARGIN_IN_CORE, FLOOR_MARGIN_IN_EXTENDED)` |
| `NO_FEASIBLE_INTERSECTION` | `margin_position_status = NO_FLOOR_INTERSECTION` 或 `development_action IN (REDESIGN_REQUIRED, NOT_RECOMMENDED)` |
| `SOURCE_MISSING` | 算法 05 候选可行性结果缺失 |

### 6.7 折扣依赖风险

指标：

```text
pre1930_sell_through
= pre1930_sales_qty / actual_receipt_qty

post1930_qty_share
= post1930_sales_qty / full_day_sales_qty

weighted_time_discount_depth
= SUM_h[q_h * (1 - realized_unit_price_h / regular_unit_price)] / SUM_h(q_h)
```

风险成立：

```text
19:30 前自然售罄相对同范围相似商品偏低
AND 19:30 后数量占比和折扣深度依赖偏高
AND 对应真实情景的全链路毛利明显受损
```

折扣风险本身不直接 `REJECT`。

### 6.8 毛利压力情景

有效历史经营情景：

```text
actual_receipt_qty > 0
AND full_day_sales_qty / actual_receipt_qty <= 1.10
AND 金额、成本、毛利字段可对账
```

称重商品和计件商品分开进入情景库，公斤和件数不得相加。

候选代入公式：

```text
scenario_revenue
= q_pre1930 * P
 + SUM_h(q_h * P * discount_factor_h)

scenario_full_chain_cost
= q_arrival * C

scenario_full_chain_margin
= scenario_revenue - scenario_full_chain_cost

scenario_margin_rate
= scenario_full_chain_margin / scenario_revenue
```

状态映射：

```text
基准达到目标毛利，且不利情景毛利仍为正
-> CLEAR

基准达到目标毛利，但不利情景低于目标或转负
-> CONDITION_REQUIRED

基准情景低于目标毛利
-> REBUILD_REQUIRED

算法 05 无价格成本毛利可行交集
-> HARD_STOP
```

### 6.9 外部同质化与差异属性

外部同款或高相似不是内部货盘重复，不自动硬拒绝。

合格差异属性至少满足一种：

```text
低竞品覆盖 + 算法 06 正式配方证据
低竞品覆盖 + 算法 07 正式/探索趋势证据
竞品稳定负面口碑 + 候选有证据的改良属性
价格或规格存在算法 05 已验证的市场空白
```

差异属性必须保留：

```text
attribute_source_ids
competitor_evidence_ids
category_preserved_flag
```

### 6.10 最终门禁优先级

```text
存在任一 HARD_STOP
-> new_product_gate_result = REJECT

否则存在任一 REBUILD_REQUIRED 或核心 NOT_EVALUABLE
-> new_product_gate_result = RETURN_FOR_REBUILD

否则存在任一 CONDITION_REQUIRED
-> new_product_gate_result = CONDITIONAL_PASS

否则
-> new_product_gate_result = PASS
```

优先级：

```text
REJECT > RETURN_FOR_REBUILD > CONDITIONAL_PASS > PASS
```

### 6.11 Pareto 排序

先按 `evidence_tier` 分组，再在共同适用维度做 Pareto。

候选 A 支配候选 B：

```text
A 在所有共同适用维度都不劣于 B
AND A 至少一个维度严格优于 B
```

比较范围：

```text
formal_period
+ target_city_group_id
+ final_level
+ final_profile
+ leaf_category_id
+ evidence_tier
+ new_product_gate_result
```

不同小分类不做同一个 Pareto 排名。

### 6.12 缺失、不适用和降级处理

算法 09 不用填 0 或默认低风险来掩盖缺口。所有缺失都要写成可追溯状态。

| 场景 | 处理方式 | 最终影响 |
|---|---|---|
| 算法 08 候选未就绪 | 不生成 `new_product_candidate_snapshot` | 不进入 09 正式结果，由 08 保留异常或缺价格状态 |
| 算法 08 成本为估算成本 | 进入 09；生成 `PRICE_MARGIN_FEASIBILITY` 单项风险 | 无更高风险时输出 `CONDITIONAL_PASS`，解除条件为补真实报价或成本凭证 |
| 当前货盘快照缺失 | 生成 `CORE_DATA_QUALITY` 风险 | `NOT_EVALUABLE`，最终 `RETURN_FOR_REBUILD` |
| 法规知识库无有效版本 | 生成 `REGULATION_AND_SAFETY` 风险 | `NOT_EVALUABLE`，最终 `RETURN_FOR_REBUILD` |
| 无独立换码、替代、历史退出原因 | 不得把停订或下架直接当失败 | 历史失败输出 `UNCERTAIN_OUTCOME` 或 `INSUFFICIENT_HISTORICAL_EVIDENCE`，不得硬拒绝 |
| 季节候选缺销售季窗口 | 不输出正式季节新品状态 | 输出条件或不可评估原因，等待季节规则补齐 |
| 毛利历史情景不足 | 不虚构基准或不利情景 | `margin_stress_status = INSUFFICIENT_MARGIN_STRESS_EVIDENCE` |
| 外部无图片、无社媒口碑或无外部观测 | 不直接拒绝 | 对应字段写 `IMAGE_NOT_AVAILABLE`、`NOT_APPLICABLE` 或 `NO_EXTERNAL_OBSERVATION` |

| 触发 | 调度口径 | 输出要求 |

| 月度正式运行 | 每月锁定 02-07 正式版本和算法 08 标准候选版本 | 全量产出 10 张正式表 |

## 10. 数据质量验收

必须校验：

```text
1. 10 张正式表主键唯一。
2. 同一正式粒度只有一条 `new_product_gate_result`。
3. `new_product_candidate_snapshot` 只能包含 `READY_FOR_ALGORITHM_09` 和 `READY_WITH_ESTIMATED_COST`。
4. `NOT_READY_MISSING_PRICE_RESULT` 和 `REGISTRATION_EXCEPTION` 不得进入 09 十张正式结果表。
5. `input_candidate_count = accepted_candidate_count + skipped_candidate_count`。
6. `candidate_payload_hash` 变化时不允许静默沿用旧结果。
7. `snapshot_payload_hash` 同一输入、同一版本重复运行必须一致。
8. `algorithm_original_gate_result` 不被例外审批覆盖。
9. `READY_WITH_ESTIMATED_COST` 必须生成成本补证条件，不得直接展示成无条件通过。
10. `risk_handoff_ids` 非空时，必须进入法规、标签、食品安全或功能声称门禁。
11. `HARD_STOP` 一定输出 `REJECT`。
12. `REBUILD_REQUIRED` 或核心 `NOT_EVALUABLE` 在无硬停时一定输出 `RETURN_FOR_REBUILD`。
13. `CONDITION_REQUIRED` 在无更高风险时一定输出 `CONDITIONAL_PASS`。
14. `NOT_APPLICABLE` 不填 0。
15. 商品可订可售、毛利损耗、价格表粒度按数据合同验收；可订可售状态不得用小票无销量替代。
16. 当前货盘同款不得展示成新品开发。
17. 季节结束、换码、供应中断不得写成经营失败。
18. 缺正式换码、替代或退出原因时，历史失败不得硬拒绝。
19. 缺历史退出原因判定规则或真正经营失败判定规则时，`exit_reason_rule_status` 必须写 `RULE_MISSING`，不得输出 `CONFIRMED_FAILURE`。
20. `PROBABLE_FAILURE` 只能输出待复核或条件风险，V1 默认不得进入 `HISTORICAL_FAILURE_HARD_STOP`。
21. 法规硬停必须能追溯 `rule_id`、`rule_version` 和 `source_clause`。
22. 毛利情景 medoid 必须是真实历史门店日。
23. 称重商品和计件商品不得混入同一情景尺度。
24. 历史最差单日不得冒充正式不利情景。
```

| P1 | 算法 08 / 数据开发 | 算法 08 的 `mart_new_product_candidate_scope`、`new_product_standard_candidate_registry` 和属性血缘表是否按本仓库字段合同落库 | 09 不接收非 08 标准候选，不正式运行 |
| P1 | 商品 / 数据开发 | 商品季节状态和销售季窗口是否有规则资产或基础表字段可读取 | 缺失时不能正式输出 `SEASONAL_NEW_PRODUCT`，只写季节状态缺失 |
| P1 | 业务 / 商品 / 营运 / 数据 | 历史退出原因 8 类结局的触发条件、排除条件、优先级和证据要求是否补齐 | 未补齐时 `exit_reason_rule_status = RULE_MISSING`，历史失败不能硬拒绝，只能输出证据不足或灰区 |
| P1 | 业务 / 商品 / 经营 / 财务 | 真正经营失败判定规则是否补齐，包括生命周期、自然动销、毛利、折扣依赖、停订后恢复和排除项 | 未补齐时不得输出 `PERFORMANCE_FAILURE_EXIT`、`CONFIRMED_FAILURE` 或 `HISTORICAL_FAILURE_HARD_STOP` |
| P1 | 商品主数据 / 业务 | V1 采用商品基础表 SPU 做标准实体辅助归并；正式换码、SPU 迁移和替代关系后续补数据合同 | 可做当前货盘 SPU 检查；历史退出不得因为缺关系数据硬拒绝 |
| P1 | 商品 / 供应链 / 业务 | 供应中断和经营策略调整的判断证据是否有来源 | 未补齐时停订商品不能自动归因为经营失败 |
| P1 | 法务 / 质量 / 业务 | 法规知识库和确定性规则引擎是否一期建设，覆盖哪些品类、原料、添加剂、声称、标签和知识产权 | 无有效版本时核心门禁 `NOT_EVALUABLE` 并退回重建 |
| P1 | 算法 / 数据开发 | 商品相似引擎、历史失败模型、动态阈值和时间外回测是否 V1 实现 | 不能用名称相似或固定阈值替代硬门禁 |
| P1 | 算法 / 数据开发 | 毛利真实情景库和 K-medoids 压力测试是否 V1 实现 | 情景不足时输出 `INSUFFICIENT_MARGIN_STRESS_EVIDENCE`，不得伪造低风险 |
| P1 | 财务 / 商品 / 业务 | 估算成本推进口径是否确认，哪些候选可以先发待验证需求，哪些必须先补真实成本 | 未确认时 `READY_WITH_ESTIMATED_COST` 只能输出 `CONDITIONAL_PASS` 和补真实成本条件 |
| P2 | 产品 / 后端 / Agent | `CONDITIONAL_PASS` 下游动作是否按固定口径限制为待验证需求 | 不得进入正式试点或正式开发需求 |

## 13. 不能做

```text
不能生成固定权重机会分或风险总分。
不能让高机会证据抵消硬门禁。
不能把停止订购直接当历史失败。
不能把疑似失败 `PROBABLE_FAILURE` 直接当历史失败硬停。
不能把 S 状态季节结束当失败。
不能把仍在售商品直接标记为成功。

不能用模型特征重要性冒充失败原因。
不能因相似灰区直接拒绝新品。
不能将公司已有商品跨区域引入写成新品开发。
不能将外部竞品相似直接写成内部重复。
不能单独计算、展示或重复扣减损耗风险。
不能做完整蒙特卡洛并输出虚假精确利润。
不能使用历史最差单日冒充不利情景。
不能由算法 09 修改商品规格、价格或配方。
不能在同一候选 ID 下静默修改商品。
不能做供应商准入、匹配、邀请、评分、排序或触达。
不能输出促销、陈列、订购、升级、替换或清退动作。
不能让人工复核直接覆盖 HARD_STOP。
不能跨小分类生成统一新品机会榜。
不能让 RETURN_FOR_REBUILD 或 REJECT 候选发布开发需求。
```
