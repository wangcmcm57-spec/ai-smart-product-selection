# 算法卡_09_新品机会证据合成与风险门禁

更新时间：2026-09-04

业务原始依据：`01_source_docs/business_algorithm_docs/算法卡_09_新品机会证据合成与风险门禁.md`

业务解读依据：`03_algorithm_cards/business_readable/算法09_新品机会证据合成与风险门禁_业务解读版.md`

开发交付定位：本卡是算法 09 的 V1 开发版算法卡，用于数据开发建设新品机会证据合成、风险门禁、最终候选状态、动作映射和审计重算结果。算法 09 不重算算法 02-07，不标准化合并候选，不做供应商判断，不修改商品规格、配方、成本或价格。

V1 范围说明：商品状态和 `S` 商品计划上架开始/结束日期已由算法 08 从 `dim_product_status` 透传进入 09；历史退出原因、真正经营失败、正式换码/替代/供应/策略归因，以及法规、食品安全、标签、功能声称和知识产权的确定性硬门禁，当前版均不启用。相关历史失败和法规硬门禁内容仅保留为后续版本占位，不进入本版开发验收。

## 1. 算法目标

算法 09 汇总算法 02-07 已产出的机会证据，对算法 08 标准化后的范围候选执行商品相关风险门禁，输出最终门禁结果、候选状态和允许动作。

本算法做：

```text
1. 锁定算法 02-07 上游正式版本和数据截止时间。
2. 读取标准新品候选、范围候选、候选属性来源、价格成本、内部购物篮和外部趋势证据。
3. 校验候选核心数据、属性来源、小分类保持和候选 payload 是否静默变化。
4. 读取算法 08 透传的商品状态、季节标记和计划上架窗口完整性。
5. 计算当前货盘同款/高相似风险。
6. 历史失败、退出原因和法规确定性门禁仅保留后续版本占位，不进入本版硬判定。
7. 法规、食品安全、标签、功能声称和知识产权仅承接算法 07 风险线索，不执行确定性硬门禁。
8. 读取算法 05 价格成本毛利可行性，不重算价格带。
9. 构建真实历史经营情景，执行毛利压力测试。
10. 合成机会证据、单项风险和 Pareto 前沿。
11. 输出 `PASS`、`CONDITIONAL_PASS`、`RETURN_FOR_REBUILD`、`REJECT`。
```

本算法不做：

```text
1. 不重新贴会员画像。
2. 不重新给门店评级。
3. 不重新计算 SKU 锚点、价格带、购物篮规则或外部趋势。
4. 不把候选标准化、去重和合并；标准候选由算法 08 负责。
5. 不直接修改候选商品材料、配方、口味、规格、售价或成本。
6. 不做供应商准入、匹配、邀请、评分、排序或触达。
7. 不输出促销、陈列、订购、升级、替换、清退动作。
8. 不生成固定权重机会分或风险总分。
9. 不让高机会证据抵消硬门禁。
```

## 3. 开发执行流程

算法 09 是离线或准离线计算，不在查询服务请求时实时重算法规、相似模型、生存模型或毛利情景。

运行顺序：

```text
1. 生成 gate_run_id，锁定 formal_period、data_cutoff_at 和上游版本。
2. 只读取算法 08 已标记可进入 09 的范围候选，生成 new_product_candidate_snapshot。
3. 校验标准候选、属性来源、小分类、算法 05 可行性、商品状态、计划上架窗口、货盘快照和法规风险线索状态。
4. 当前货盘重复门禁：汇总公司级可订可售商品，计算同款/高相似/灰区。
5. 历史失败门禁：V1 第一版仅保留后续版本占位，不构建历史生命周期判定，不做经营失败硬拒绝；商品状态只用于避免把季节状态误写成历史失败。
6. 法规门禁：V1 第一版仅承接算法 07 风险线索并留痕，不执行法规确定性条款或硬停结论。
7. 价格毛利静态门禁：读取算法 05 的价格、成本、毛利和可行性状态。
8. 折扣依赖和毛利压力：基于历史真实门店日情景执行 K-medoids 压力测试。
9. 外部同质化和差异属性：读取算法 07 竞品覆盖和风险线索，判断差异属性。
10. 机会证据合成：校验 02-05 基础条件和 06/07 属性来源，生成证据层级。
11. 按风险优先级生成 new_product_gate_result。
12. 复核或补证后，生成新的 gate_run_id 重算，不覆盖原始结果。
```

### 3.1 候选准入规则

算法 09 的正式候选入口只有算法 08：

```text
mart_new_product_candidate_scope
```

正式运行只接收：

```text
algorithm_09_readiness IN (
  READY_FOR_ALGORITHM_09,
  READY_WITH_ESTIMATED_COST
)
```

处理规则：

| 算法 08 就绪状态 | 09 是否生成候选快照 | 09 处理方式 |
|---|---|---|
| `READY_FOR_ALGORITHM_09` | 是 | 正常进入机会证据合成和风险门禁 |
| `READY_WITH_ESTIMATED_COST` | 是 | 正常进入 09，但价格毛利风险中必须生成估算成本补证条件 |
| `NOT_READY_MISSING_PRICE_RESULT` | 否 | 不进入 09 十张正式表；记录在 08 表中等待算法 05 补价格成本 |
| `REGISTRATION_EXCEPTION` | 否 | 不进入 09 十张正式表；记录在 08 异常表中等待上游修正 |

过滤不是删除。被过滤的候选仍保留在算法 08 表中，用于补字段、修正规则和重跑。算法 10、Agent 和查询服务只能读取 09 正式结果，不得绕过 09 直接展示这些未就绪候选。

算法 09 不接收人工手工录入的候选商品、规格、成本、风险或法规条款。人工复核只能补充或修正证据，再触发新批次重算。

### 4.3 V1 成本来源

算法 09 V1 不单独接 SRM 或采购价管理作为主依赖。

成本链路统一从 `mart_store_sku_daily_price` 读取，优先顺序为：

```text
1. `purchase_settlement_price` 作为最终结算成本；
2. `daily_purchase_price` 作为当天采购价 / 出库价计算来源；
3. `outbound_arrival_cost_tax_included` 作为到店含税成本口径。
```

读取时遵守价格表主键 `business_date + store_id + sku_id + receipt_sku_id`；算法 09 做成本引用时按 `warehouse_id + sku_id + business_date` 形成仓商品日成本口径，`receipt_sku_id` 保留用于验收映射和对账。同一仓、同一销售 SKU、同一日期存在多个验收商品编码时，优先使用非空 `purchase_settlement_price`，并按验收量或出库到店金额做加权归并；无法归并时写入成本来源缺失或部分缺失状态，不默认填 0。

| 毛利压力情景库 | 毛利压力门禁必需 | 样本不足时 `INSUFFICIENT_MARGIN_STRESS_EVIDENCE` |

## 6. 关键算法逻辑

### 6.1 核心数据完整性

以下任一核心数据缺失时，不得生成可发布候选：

```text
正式小分类映射
standard_candidate_id
具象候选商品名和规格
候选属性来源 ID
算法 05 价格成本可行性
当前公司级可订可售货盘快照
```

输出：

```text
risk_type = CORE_DATA_QUALITY
risk_state = NOT_EVALUABLE
new_product_gate_result = RETURN_FOR_REBUILD
```

V1 第一版不启用的业务确认规则不作为核心输入阻断，包括历史退出原因、真正经营失败、正式换码/替代关系、供应/策略归因和法规确定性规则。对应模块必须写缺失、未启用或证据不足状态，不能硬拒绝，也不能写成已通过。

历史换码、替代和退出原因缺失时，不作为算法 09 整体运行阻断。V1 先用商品基础表 SPU 做标准实体辅助归并；缺正式换码、替代、历史退出原因或真正经营失败规则时，历史结局写 `UNCERTAIN_OUTCOME`，相似关系无法确认时写 `SIMILARITY_GRAY_REVIEW`，历史失败门禁写 `HISTORICAL_FAILURE_REVIEW_REQUIRED` 或 `INSUFFICIENT_HISTORICAL_EVIDENCE`，不得输出历史失败硬拒绝。

商品状态和计划上架窗口按算法 08 快照读取，09 不再从名称、销量曲线或停订事实反推商品状态。

| 08 传入状态 | 09 处理 |
|---|---|
| `product_status_code = A` 且 `seasonality_status = YEAR_ROUND` | 按全年品处理，不生成季节窗口条件 |
| `product_status_code = S` 且 `seasonality_status = SEASONAL` | 可作为季节候选继续门禁；只有在窗口内且其他风险通过时，才能输出季节推荐信号 |
| `product_status_code = S` 且 `seasonality_status = SEASON_WINDOW_INCOMPLETE` | 生成 `SEASON_WINDOW` 单项风险，`risk_state = CONDITION_REQUIRED`；无更高风险时输出 `CONDITIONAL_PASS`，不得输出季节推荐信号 |
| `product_status_code = O` 或 `B` | 透传试卖或备选状态，生成 `PRODUCT_STATUS` 观察风险，不单独改变门禁结果 |
| `product_status_code = D` | 生成 `PRODUCT_STATUS` 硬停风险；V1 普通新品链路不得把淘汰品输出为可推荐候选 |
| 商品状态缺失 | `seasonality_status = UNKNOWN`，生成 `PRODUCT_STATUS` 观察风险；不得猜状态或默认全年品 |
| `S` 商品季节窗口结束 | 不得写成经营失败；历史失败硬判定仍按 `INSUFFICIENT_HISTORICAL_EVIDENCE` 降级 |

### 6.3 当前货盘重复门禁

公司级当前货盘定义：

```text
同一商品在最新可订可售快照中任一门店是否可售 = 1 或 是否可订 = 1
=> 公司当前货盘存在
```

相似引擎采用加权 Gower 式 kNN 校准，五个字段分别是：

```text
品型：层级相似，越接近正式层级，得分越高；
口味：标签集合的 Jaccard 相似度，sim_set = |A∩B| / |A∪B|；
工艺：标签集合的 Jaccard 相似度，sim_set = |A∩B| / |A∪B|；
规格：sim_num = max(0, 1 - abs(x - y) / (P95 - P5))，V1 规格稳健极差 = 281.4g；
百克标价：sim_num = max(0, 1 - abs(x - y) / (P95 - P5))，V1 百克标价稳健极差 = 4.143307 元。
```

综合相似度：

```text
similarity_score
= 0.30 * 品型
 + 0.25 * 口味
 + 0.20 * 规格
 + 0.15 * 百克标价
 + 0.10 * 工艺
```

同口径样本池按 `target_city_group_id + final_level + final_profile + leaf_category_id + formal_period` 取样；相似度权重使用上述 V1 固定权重，`tau_similarity = 0.85` 作为版本化硬门槛，`tau_similarity_gray = 0.70` 作为灰区下界。

空值和缺失处理：

```text
口味或工艺一空一非空 -> 该字段相似度 = 0；
口味或工艺两集合都为空 -> 该字段写 NOT_APPLICABLE，不计入可用字段数；
规格或百克标价任一侧缺失 -> 该字段写 NOT_APPLICABLE，不计入可用字段数；
NOT_APPLICABLE 字段跳过后，按剩余可用字段权重重新归一化；
available_similarity_feature_count < 3 -> SIMILARITY_GRAY_REVIEW。
```

V1 已确认阈值：

```text
similarity_score >= 0.85
AND available_similarity_feature_count >= 4
AND hard_boundary_results 全部为 PASS
-> BUSINESS_HIGH_SIMILAR

0.70 <= similarity_score < 0.85
OR available_similarity_feature_count = 3
OR 任一关键字段为 NOT_APPLICABLE
-> SIMILARITY_GRAY_REVIEW

similarity_score < 0.70
AND hard_boundary_results 全部为 PASS
-> SAME_DIRECTION 或 STRUCTURALLY_DISTINCT
```

门禁：

```text
similarity_relation = EXACT_EQUIVALENT
-> risk_state = HARD_STOP
-> new_product_gate_result = REJECT

similarity_relation = BUSINESS_HIGH_SIMILAR
AND similarity_score >= tau_similarity
AND similarity_gate_status = HARD_GATE_CONFIRMED
-> risk_state = HARD_STOP
-> new_product_gate_result = REJECT

similarity_relation = SIMILARITY_GRAY_REVIEW
-> risk_state = CONDITION_REQUIRED
-> new_product_gate_result = CONDITIONAL_PASS
```

### 6.7 折扣依赖风险

V1 只看两个核心指标：

```text
pre1930_sell_through
= pre1930_sales_standard_qty / actual_arrival_standard_qty

late_sales_uplift_rate
= (late_discount_sales_qty - late_base_sales_qty) / max(late_base_sales_qty, 1)

discount_depth
= 1 - realized_unit_price / regular_unit_price

late_price_elasticity
= late_sales_uplift_rate / max(discount_depth, epsilon)
```

其中 `late_base_sales_qty` 取同口径样本池中非折扣晚间基准销量中位数；`epsilon` 取 0.000001，避免折扣深度为 0 时除零。

时段字段口径：

```text
业务判定切点固定为 19:30。
`pre1930_sales_standard_qty`、`late_discount_sales_qty`、`late_base_sales_qty` 由经营时段加工产出。
如果当前底层合同只有 19 点前/后字段，开发交付时必须显式说明 19 点字段如何映射或补加工到 19:30，不得把 19 点和 19:30 混用。
```

折扣依赖风险分：

```text
discount_dependency_score
= w1 * norm(1 - pre1930_sell_through)
 + w2 * norm(late_price_elasticity)
```

`norm` 使用同口径样本池内的 P5-P95 稳健归一化并截断到 0-1；`w1`、`w2` 由 CRITIC 在同口径样本池内计算；样本池取 `target_city_group_id + final_level + final_profile + leaf_category_id + formal_period`。

折扣依赖等级按同口径样本池内风险分分位数切档：

```text
<= P20  -> LOW_DEPENDENCE
P20~P50 -> MEDIUM_DEPENDENCE
P50~P80 -> HIGH_DEPENDENCE
>= P80  -> SEVERE_DEPENDENCE
```

判定上，19:30 前自然售罄率低且晚间价格弹性高，才说明更依赖折扣；最终是否影响门禁，还要看 `margin_stress_status`。

折扣依赖与毛利压力动作映射：

| 折扣依赖等级 | 毛利压力状态 | 风险状态 | 最终结果影响 | 下一步处理信号 |
|---|---|---|---|---|
| `LOW_DEPENDENCE` / `MEDIUM_DEPENDENCE` | `CLEAR` | `CLEAR` | 不改变最终门禁结果 | 继续推进 |
| `HIGH_DEPENDENCE` / `SEVERE_DEPENDENCE` | `CLEAR` | `OBSERVED_NON_BLOCKING` | 不改变最终门禁结果 | 保留折扣依赖观察线索 |
| `LOW_DEPENDENCE` / `MEDIUM_DEPENDENCE` / `HIGH_DEPENDENCE` | `CONDITION_REQUIRED` | `CONDITION_REQUIRED` | 无更高风险时 `CONDITIONAL_PASS` | `CONDITIONAL_RECOMMENDATION_SIGNAL`，补成本、价格或小范围验证条件 |
| `SEVERE_DEPENDENCE` | `CONDITION_REQUIRED` | `REBUILD_REQUIRED` | 无硬停时 `RETURN_FOR_REBUILD` | `RETURN_TO_UPSTREAM_REBUILD`，优先降本、改规格或改价格 |
| 任意等级 | `REBUILD_REQUIRED` | `REBUILD_REQUIRED` | 无硬停时 `RETURN_FOR_REBUILD` | `RETURN_TO_UPSTREAM_REBUILD` |
| 任意等级 | `HARD_STOP` | `HARD_STOP` | `REJECT` | `EXIT_NEW_PRODUCT_POOL` |
| 任意等级 | `INSUFFICIENT_MARGIN_STRESS_EVIDENCE` | `NOT_EVALUABLE` | 无硬停时 `RETURN_FOR_REBUILD` | 补足真实历史情景后重算 |

折扣等级只解释动作强度，不覆盖算法 05 的价格毛利硬门禁。

### 6.8 毛利压力情景

有效历史经营情景：

```text
actual_arrival_standard_qty > 0
AND full_day_sales_standard_qty / actual_arrival_standard_qty <= 1.10
AND 金额、成本、毛利字段可对账
```

称重商品和计件商品分开进入情景库，公斤和件数不得相加。

候选代入公式：

```text
scenario_revenue
= q_pre1930 * P
 + SUM_h(q_h * P * discount_factor_h)

scenario_full_chain_cost
= q_arrival * C

scenario_full_chain_margin
= scenario_revenue - scenario_full_chain_cost

scenario_margin_rate
= scenario_full_chain_margin / scenario_revenue
```

状态映射：

```text
基准达到目标毛利，且不利情景毛利仍为正
-> CLEAR

基准达到目标毛利，但不利情景低于目标或转负
-> CONDITION_REQUIRED

基准情景低于目标毛利
-> REBUILD_REQUIRED

算法 05 无价格成本毛利可行交集
-> HARD_STOP
```

### 6.9 外部同质化与差异属性

外部同款或高相似不是内部货盘重复，不自动硬拒绝。

合格差异属性至少满足一种：

```text
低竞品覆盖 + 算法 06 正式配方证据
低竞品覆盖 + 算法 07 正式/探索趋势证据
竞品稳定负面口碑 + 候选有证据的改良属性
价格或规格存在算法 05 已验证的市场空白
```

差异属性必须保留：

```text
attribute_source_ids
competitor_evidence_ids
category_preserved_flag
```

### 6.10 最终门禁优先级

```text
存在任一 HARD_STOP
-> new_product_gate_result = REJECT

否则存在任一 REBUILD_REQUIRED 或核心 NOT_EVALUABLE
-> new_product_gate_result = RETURN_FOR_REBUILD

否则存在任一 CONDITION_REQUIRED
-> new_product_gate_result = CONDITIONAL_PASS

否则
-> new_product_gate_result = PASS
```

优先级：

```text
REJECT > RETURN_FOR_REBUILD > CONDITIONAL_PASS > PASS
```

### 6.11 Pareto 排序

先按 `evidence_tier` 分组，再在共同适用维度做 Pareto。

候选 A 支配候选 B：

```text
A 在所有共同适用维度都不劣于 B
AND A 至少一个维度严格优于 B
```

比较范围：

```text
formal_period
+ target_city_group_id
+ final_level
+ final_profile
+ leaf_category_id
+ evidence_tier
+ new_product_gate_result
```

不同小分类不做同一个 Pareto 排名。

### 6.12 缺失、不适用和降级处理

算法 09 不用填 0 或默认低风险来掩盖缺口。所有缺失都要写成可追溯状态。

| 场景 | 处理方式 | 最终影响 |
|---|---|---|
| 算法 08 候选未就绪 | 不生成 `new_product_candidate_snapshot` | 不进入 09 正式结果，由 08 保留异常或缺价格状态 |
| 算法 08 成本为估算成本 | 进入 09；生成 `PRICE_MARGIN_FEASIBILITY` 单项风险 | 无更高风险时输出 `CONDITIONAL_PASS`，解除条件为补真实报价或成本凭证 |
| 当前货盘快照缺失 | 生成 `CORE_DATA_QUALITY` 风险 | `NOT_EVALUABLE`，最终 `RETURN_FOR_REBUILD` |
| V1 第一版未启用法规确定性规则，且算法 07 有风险线索 | 生成 `REGULATION_AND_SAFETY` 留痕和规则未启用占位记录 | `OBSERVED_NON_BLOCKING`，最终门禁结果不变 |
| V1 第一版未启用法规确定性规则，且算法 07 无风险线索 | 不输出法规通过结论 | 不单独改变最终门禁结果 |
| 无独立换码、替代、历史退出原因 | 不得把停订或下架直接当失败 | 历史失败输出 `UNCERTAIN_OUTCOME` 或 `INSUFFICIENT_HISTORICAL_EVIDENCE`，不得硬拒绝 |
| `S` 商品缺计划上架窗口 | 生成 `SEASON_WINDOW` 风险 | `CONDITION_REQUIRED`；无更高风险时输出 `CONDITIONAL_PASS`，等待 SAP POP 商品状态补齐后重算 |
| 毛利历史情景不足 | 不虚构基准或不利情景 | `margin_stress_status = INSUFFICIENT_MARGIN_STRESS_EVIDENCE` |
| 外部无图片、无社媒口碑或无外部观测 | 不直接拒绝 | 对应字段写 `IMAGE_NOT_AVAILABLE`、`NOT_APPLICABLE` 或 `NO_EXTERNAL_OBSERVATION` |

## 9. 调度和重算

| 触发 | 调度口径 | 输出要求 |
|---|---|---|
| 月度正式运行 | 每月锁定 02-07 正式版本和算法 08 标准候选版本 | 全量产出 10 张正式表 |
| 后续开发推进前复核 | 即时读取最新货盘；法规规则启用后同时读取最新法规版本 | 生成新 `gate_run_id`，不覆盖月度结果 |
| 法规或食品安全事件 | 后续启用法规规则后，受影响候选立即重算 | 保留事件触发来源 |
| 候选核心 payload 变化 | 创建新候选或新运行版本 | 原 candidate_id 静默变化时阻断运行 |
| 人工复核或补证 | 修正底层数据或补充证据后重算 | 保留新旧结果和变化原因 |

## 10. 数据质量验收

必须校验：

```text
1. 10 张正式表主键唯一。
2. 同一正式粒度只有一条 `new_product_gate_result`。
3. `new_product_candidate_snapshot` 只能包含 `READY_FOR_ALGORITHM_09` 和 `READY_WITH_ESTIMATED_COST`。
4. `NOT_READY_MISSING_PRICE_RESULT` 和 `REGISTRATION_EXCEPTION` 不得进入 09 十张正式结果表。
5. `input_candidate_count = accepted_candidate_count + skipped_candidate_count`。
6. `candidate_payload_hash` 变化时不允许静默沿用旧结果。
7. `snapshot_payload_hash` 同一输入、同一版本重复运行必须一致。
8. `algorithm_original_gate_result` 不被例外审批覆盖。
9. `READY_WITH_ESTIMATED_COST` 必须生成成本补证条件，不得直接展示成无条件通过。
10. `risk_handoff_ids` 非空时，必须进入法规、标签、食品安全或功能声称留痕，不得静默丢弃。
11. V1 第一版法规规则未启用时，不得输出 `REGULATION_CLEAR` 或 `REGULATION_HARD_STOP`，也不得因此把结果改成 `CONDITIONAL_PASS`。
12. `new_product_candidate_snapshot` 必须透传算法 08 的 `product_status_code`、`seasonality_status`、`seasonal_status`、`season_start`、`season_end`。
13. `seasonality_status = SEASON_WINDOW_INCOMPLETE` 时必须生成 `SEASON_WINDOW` 风险，`risk_state = CONDITION_REQUIRED`；不得输出 `SEASONAL_RECOMMENDATION_SIGNAL`。
14. 当前货盘高相似必须输出 `similarity_score`、`available_similarity_feature_count` 和 `five_feature_similarity_json`。
15. 折扣依赖风险必须输出 `risk_tier` 和 `risk_metric_json`，并按 P20/P50/P80 分层；19:30 时段字段必须有明确加工来源。
16. 成本来源优先读取 `mart_store_sku_daily_price`，按合同主键和仓商品日派生口径验收，不得要求 09 单独直连 SRM。
17. `HARD_STOP` 一定输出 `REJECT`。
18. `REBUILD_REQUIRED` 或核心 `NOT_EVALUABLE` 在无硬停时一定输出 `RETURN_FOR_REBUILD`。
19. `CONDITION_REQUIRED` 在无更高风险时一定输出 `CONDITIONAL_PASS`。
20. `NOT_APPLICABLE` 不填 0。
21. 商品可订可售、毛利损耗、价格表粒度按数据合同验收；可订可售状态不得用小票无销量替代。
22. 当前货盘同款不得展示成新品开发。
23. 季节结束、换码、供应中断不得写成经营失败。
24. 缺正式换码、替代或退出原因时，历史失败不得硬拒绝。
25. 缺历史退出原因判定规则或真正经营失败判定规则时，`exit_reason_rule_status` 必须写 `RULE_MISSING`，不得输出 `CONFIRMED_FAILURE`。
26. `PROBABLE_FAILURE` 在 V1 第一版只能输出观察风险或后续复核线索，不得进入 `HISTORICAL_FAILURE_HARD_STOP` 或单独触发 `CONDITIONAL_PASS`。
27. 法规规则启用后，法规硬停必须能追溯 `rule_id`、`rule_version` 和 `source_clause`。
28. 毛利情景 medoid 必须是真实历史门店日。
29. 称重商品和计件商品不得混入同一情景尺度。
30. 历史最差单日不得冒充正式不利情景。
```

以下事项是算法 09 第一版开发交付验收项。它们不是业务待确认问题，而是开发必须按已确认口径实现、对数和留痕的内容：
