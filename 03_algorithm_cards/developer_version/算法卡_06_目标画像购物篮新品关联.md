# 算法卡_06_目标画像购物篮新品关联

更新时间：2026-08-05

业务原始依据：`01_业务原始与补充文档/业务补充算法文档/算法卡_06_目标画像购物篮新品关联(1).md`

本文档是开发版算法卡，目标是让数据开发可以按本卡建表、写逻辑、跑数和验收。业务原文逐章承接放在承接矩阵中，本卡不再按业务原文章节堆叠。

## 1. 算法目标

算法 06 用目标画像真实小票计算购物篮关联，并判断关联商品能不能转成新品属性。

一句话：

```text
在同一城市算法区域、同一门店品类等级群、同一叶子小分类、同一消费者画像下，
从算法 04 的正式锚点商品 A 出发，
找同一张小票里经常一起购买的商品 B，
再判断 A+B 是否能成为一个可开发的购物篮新品候选。
```

本算法做：

```text
1. 构造目标画像真实购物篮。
2. 发现锚点商品 A 与关联商品 B 的真实共现。
3. 计算 A=>B 和 B=>A 的正反向关联规则。
4. 用贝叶斯区间和 FDR 判断规则是否可靠。
5. 区分自然成交、促销和时段折扣带来的关联。
6. 判断购物篮关联是否能转成目标叶子小分类新品属性。
7. 输出购物篮规则、稳定性和新品候选结果。
```

本算法不做：

```text
1. 不重新计算会员画像、门店品类等级、画像贡献、SKU 锚点和价格带。
2. 不用商品名称相似自动合并 SKU。
3. 不用泛品类关联代替商品关联。
4. 不把餐食互补直接拼成新品名称。
5. 不用 AI 常识代替小分类新品属性规则。
6. 不把促销或晚间折扣才成立的关系生成正式新品。
```

## 2. 正式输出表

算法 06 正式交付 6 张表。开发可以有临时表或过程表，但下游只读取这 6 张正式表。

| 表名 | 中文表名 | 一行代表什么 | 下游用途 |
|---|---|---|---|
| `basket_run` | 购物篮算法运行批次表 | 一次算法 06 正式运行 | 版本追溯、调度和对账 |
| `basket_scope_summary` | 购物篮范围汇总表 | 一个周期 + 一个范围 + 一个叶子小分类 + 一个篮子类型 | 看本次计算覆盖多少小票、会员、门店和锚点 |
| `basket_itemset_cooccurrence` | 购物篮项集共现表 | 一个真实共现项集 | 保留 FP-Growth 发现的底层共现证据 |
| `basket_association_rule` | 购物篮关联规则表 | 一条 A=>B 或 B=>A 规则 | 保存四格表、support、confidence、lift、贝叶斯区间和规则状态 |
| `basket_rule_stability` | 购物篮规则稳定性表 | 一条规则在某个验证维度下的稳定性结果 | 判断规则是稳定、局部、季节、月份依赖或促销依赖 |
| `basket_new_product_candidate` | 购物篮新品候选表 | 一条购物篮关系转成或未转成的新品候选 | 给算法 09 做新品候选标准化与合并 |

运行流程：

```text
1. 月度离线或准离线运行，默认使用最近 3 个数据完整自然月。
2. 先锁定算法 01-05 正式版本和基础数据快照。
3. 再从 Doris 小票构造目标画像购物篮。
4. 再计算共现、关联规则、稳定性和新品候选。
5. 最后写入 6 张正式表。
6. 前端只按城市、门店等级、消费者画像、品类、候选状态等条件读取结果，不实时重算。
```

## 6. 过滤、关联和分流规则

### 6.1 有效交易过滤

Doris 小票基础过滤：

```text
order_status = 'os.completed'
AND is_return = 0
AND usual_amt > 0
AND weight > 0
```

目标画像小票再叠加：

```text
is_customer = 1
AND customer_id IS NOT NULL
AND customer_id <> ''
AND customer_id 命中算法 01 当前正式画像版本
```

硬排除行：

```text
购物袋、包装费、配送费、服务费、押金
充值、优惠券、虚拟权益行
赠品、零金额行、测试商品、财务占位行
无法映射唯一商品编码的记录
```

### 6.2 目标范围过滤

每次运行必须锁定：

```text
analysis_period_start
analysis_period_end
algorithm_region_code
store_category_level_group
target_leaf_category_code
final_profile
```

切换任一条件，都必须重新计算：

```text
有效会员集
有效门店集
U_global / U_category / U_anchor / U_AB
n11 / n10 / n01 / n00
```

### 6.3 三类篮子集合

```text
U_global：当前范围内全部有效目标画像小票

U_category：包含目标叶子小分类商品的小票，
            但保留该小票上的全部有效商品

U_anchor：包含指定锚点 A 的小票
```

FP-Growth 在 `U_category` 和 `U_anchor` 中发现候选项集。正式指标不能仅使用 `U_anchor` 做全局分母。

### 6.4 同时可购买集合 U_AB

针对每个候选商品对 A、B，从 `U_global` 中建立：

```text
U_AB =
在小票时点，
A 和 B 均处于有效售卖状态，
均在实际可售窗口内，
当日实际到货量 > 0，
且尚未售罄的目标画像小票集合。
```

V1 可售和可订按日粒度判断：

```text
is_sellable = 1
AND is_orderable = 1
```

没有正式售罄时间时，用估计口径：

```text
小票时点前累计销售标准量 < 门店当日实际到货标准量
=> 估计仍可购买
```

超卖异常：

```text
当日销售标准量 > 当日实际到货标准量 * 1.10
=> oversell_anomaly_flag = 1
=> 不进入正式 U_AB 分母
```

### 6.5 自然、促销和时段折扣篮子

全量篮子：

```text
ALL_VALID_BASKET = 当前范围内全部有效目标画像小票
```

自然篮子：

```text
A 和 B 均无实际优惠或限时促销代理
AND is_hour_promotion = 0
AND inc_time <= 19:30:00
=> NATURAL_BASKET
```

促销或时段折扣篮子：

```text
A 或 B 的 discount_amt > 0
OR A 或 B 的 is_hour_promotion = 1
OR inc_time > 19:30:00
=> PROMOTION_OR_MARKDOWN_BASKET
```

V1 促销识别：

```text
promotion_identify_method = DISCOUNT_PROXY_V1
```

`hour_discount_amt` 是会员当天同小时累计优惠金额，不能按商品行直接求和。

## 7. 核心计算逻辑

### 7.1 标准商品映射

开发步骤：

```text
1. 小票 `article_id` 关联商品基础表交易商品编码。
2. 取商品基础表 SPU 编码作为 `standard_product_id`。
3. SPU 为空或无法映射时，使用 `article_id`，状态写 `SKU_ONLY`。
4. 属于同一 `standard_product_id` 的 A 和 B 不生成关联规则。
5. V1 不使用名称相似做合并。
```

### 7.2 FP-Growth 发现阶段

发现阶段下限：

```text
discovery_min_count = 1
discovery_min_support = 1 / valid_ticket_count(U_category)
```

技术链：

```text
FP-Growth
-> 发现真实频繁项集
-> Association Rules
-> 对每个项集生成 A=>B 和 B=>A
-> 回到 U_AB 构建四格表
-> 贝叶斯证据与稳定性验证
```

多项扩展：

```text
全部真实二项共现保留
-> 至少达到 EXPLORATORY_RULE 的二项组才扩展三项
-> 正式三项组才扩展四项及以上
```

`A=>B` 和 `A=>C` 不得自动拼成 `{A,B,C}`，必须存在真实三项小票。

### 7.3 四格表

在 `U_AB` 内构造：

|  | 包含 B | 不包含 B |
|---|---:|---:|
| 包含 A | `n11` | `n10` |
| 不包含 A | `n01` | `n00` |

```text
N = n11 + n10 + n01 + n00 = valid_ticket_count(U_AB)
```

点估计：

```text
support(A,B) = n11 / N

confidence(A=>B) = n11 / (n11+n10)

confidence(B=>A) = n11 / (n11+n01)

support(A) = (n11+n10) / N

support(B) = (n11+n01) / N

lift(A=>B) = support(A,B) / [support(A) * support(B)]
```

数学关系：

```text
support(A,B) = support(B,A)
lift(A=>B) = lift(B=>A)
confidence(A=>B) 通常不等于 confidence(B=>A)
```

### 7.4 Jeffreys-Dirichlet 贝叶斯区间

先验：

```text
(p11,p10,p01,p00) ~ Dirichlet(0.5,0.5,0.5,0.5)
```

后验：

```text
(p11,p10,p01,p00)
~ Dirichlet(n11+0.5, n10+0.5, n01+0.5, n00+0.5)
```

边缘分布：

```text
confidence(A=>B) ~ Beta(n11+0.5, n10+0.5)

confidence(B=>A) ~ Beta(n11+0.5, n01+0.5)

support(A,B) ~ Beta(n11+0.5, n10+n01+n00+1.5)
```

Lift 联合后验：

```text
support_A = p11 + p10
support_B = p11 + p01
lift = p11 / (support_A * support_B)
```

实现要求：

```text
1. 使用确定性 Sobol 准蒙特卡洛序列。
2. 序列种子由 algorithm_version + run_id + pair_id 确定。
3. 逐轮加倍取值量，不使用固定重复 500 次。
4. 2.5%、50%、97.5% 分位数和 P(lift>1) 四舍五入后连续两轮不变才停止。
5. 未收敛时输出 COMPUTE_UNSTABLE，不能进入正式规则。
```

### 7.5 贝叶斯 FDR

对同一锚点、同一范围内每条候选规则计算：

```text
local_false_discovery_rate = P(lift <= 1 | current_data)
```

按误报概率从低到高排序，选择最大规则集合，使：

```text
mean(local_false_discovery_rate of selected rules) <= 5%
```

5% 是统计误报控制上限，不是商品经验权重。

### 7.6 规则状态判定

正式规则同时满足：

```text
存在真实共现
AND lift_interval_95_lower > 1
AND 通过贝叶斯 FDR
AND 数值计算已收敛
AND 门店 x 月份稳定性满足对应应用范围
AND 自然篮子验证满足新品开发要求
```

规则状态：

| 状态 | 中文含义 |
---|---|
| `FORMAL_RULE` | 正式购物篮规则 |
| `EXPLORATORY_RULE` | 探索规则，证据不足但可保留 |
| `RAW_COOCCURRENCE` | 只有真实共现，不足以形成规则 |
| `NO_COOCCURRENCE` | 有锚点小票但零共现 |
| `NO_VALID_ANCHOR_BASKET` | 无有效锚点小票 |
| `COMPUTE_UNSTABLE` | 后验模拟未收敛 |
| `PROMOTION_DEPENDENT` | 仅促销或折扣篮子成立 |

### 7.7 稳定性验证

门店和月份分块：

```text
对每条规则，在每个门店 x 自然月分别建立四格表。
```

输出指标：

```text
pooled_lift_interval
new_store_month_prediction_interval
between_store_month_heterogeneity
member_cluster_effect
```

状态判定：

| 条件 | 状态 |
|---|---|
| 总体 Lift 下界 > 1，且新门店月份预测区间下界 > 1 | `CROSS_STORE_MONTH_STABLE` |
| 总体 Lift 下界 > 1，但预测区间跨 1 | `LOCAL_RULE` |
| 删除某一门店或月份后关联消失 | `SINGLE_BLOCK_DEPENDENT` |
| 只有一个有效门店月份 | `EXPLORATORY_RULE` |

### 7.8 S 商品、销售季和拉动月

S 商品正式口径：

```text
锚点 A 为 S，B 为常规商品
=> 规则窗口 = A 的实际上架日至下架日

A 和 B 均为 S
=> 规则窗口 = A、B 实际可售时间交集
```

V1 缺商品 S 状态或销售季规则时：

```text
season_status = SEASONAL_STATUS_MISSING
rule_status 不得输出 S_SEASONAL_RULE
candidate_status 不得输出 SEASONAL_NEW_PRODUCT
```

锚点月度依赖：

```text
完整周期
拉动月或拉动月集合
完整周期删除拉动月
```

判定：

| 条件 | 状态 |
|---|---|
| 删除拉动月后仍成立 | 不依赖拉动月 |
| 只在拉动月成立 | `ANCHOR_MONTH_DEPENDENT_RULE` |
| 删除拉动月后方向反转 | `HIGH_RISK_RULE`，不生成新品 |

如果算法 04 未提供拉动月集合，算法 06 可以按月重算，但必须写：

```text
month_dependency_source = DERIVED_BY_ALGO06
```

### 7.9 小分类新品属性规则

算法 06 不能靠 AI 常识直接判断 B 是否能变成新品属性。

允许维度公式：

```text
allowed(category, dimension)
= category_core_preserved
  AND (
    official_standard_defined
    OR internal_same_category_observed
    OR competitor_same_category_observed
  )
```

品类保持检验：

```text
目标小分类的后验概率下界
>
所有相邻小分类后验概率上界
且不违反正式分类标准
=> CATEGORY_PRESERVED
```

缺规则时：

```text
category_rule_status = CATEGORY_RULE_NOT_CONFIGURED
```

此时可以输出购物篮规则，但不能发布正式 `BASKET_RECIPE`。

### 7.10 购物篮关系转新品候选

关系类型：

| 关系类型 | 新品处理 |
|---|---|
| 配方型关联 | 通过小分类规则和品类保持检验后，可转新品属性 |
| 季节性配方关联 | 可形成限定销售季新品 |
| 局部门店或月份配方关联 | 可形成局部试点新品 |
| 完整餐食互补 | 只作消费场景证据 |
| 高频补充关系 | 只作消费场景证据 |
| 促销/折扣依赖关系 | 不进入新品开发 |
| 原始共现或无法解释 | 保留证据，不生成新品 |

候选状态：

| 状态 | 中文含义 |
|---|---|
| `FORMAL_NEW_PRODUCT` | 正式新品候选 |
| `SEASONAL_NEW_PRODUCT` | 限定销售季新品候选 |
| `LOCAL_PILOT_NEW_PRODUCT` | 局部范围试点新品 |
| `EXPLORATORY_NEW_PRODUCT` | 有方向但证据不足 |
| `NOT_ELIGIBLE_FOR_NEW_PRODUCT` | 关联存在但不能转新品属性 |
| `CATEGORY_RULE_NOT_CONFIGURED` | 小分类新品属性规则缺失 |

冲突处理顺序：

```text
无效数据、同一 SPU 等硬排除
-> 自然篮子是否成立
-> 小分类允许维度
-> 品类保持检验
-> 季节、城市、等级、画像和月份范围限制
-> 后续历史差销、当前货盘和风险硬过滤
```

## 9. 调度周期

| 项目 | 口径 |
|---|---|
| 正式运行周期 | 月度 |
| 默认分析窗口 | 最近 3 个数据完整自然月 |
| 历史稳定性窗口 | 可用完整历史门店月份或完整销售季 |
| 重算触发 | 上游算法版本变化、商品主数据版本变化、城市算法区域版本变化、小分类规则版本变化 |
| 结果保存 | 按 `run_id` 保存，不覆盖历史正式结果 |

## 10. 缺失值和不适用处理

通用规则：

```text
0：真实计算结果为 0
NULL：无法计算或无分母
NOT_APPLICABLE：当前场景不适用
SOURCE_MISSING：来源缺失
SOURCE_PARTIAL：来源部分可用
DATA_INCOMPLETE：核心字段缺失
COMPUTE_UNSTABLE：计算不稳定或未收敛
```

## 11. 验收样例

### 11.1 固定四格表复算

输入：

```text
N = 1,000
n11 = 15
n10 = 85
n01 = 45
n00 = 855
```

必须得到：

```text
support(A,B) = 1.50%
confidence(A=>B) = 15.00%
confidence(B=>A) = 25.00%
lift(A=>B) = lift(B=>A) = 2.50
```

贝叶斯复算：

| 指标 | 后验中位数 | 95% 可信区间 |
|---|---:|---:|
| Support | 1.51% | 0.88%-2.40% |
| A=>B Confidence | 15.12% | 9.04%-22.95% |
| B=>A Confidence | 25.14% | 15.39%-36.95% |
| Lift | 2.50 | 1.58-3.60 |

```text
P(lift>1) = 99.978%
local_false_discovery_rate = 0.022%
```

### 11.2 配方型新品样例

```text
目标小分类：牛肉制品
锚点 A：黑椒牛柳丝 200g
关联 B：青泡椒
规则状态：FORMAL_RULE
自然篮子：成立
```

输出：

```text

```

## 12. 数据质量验收

开发交付必须提供：

```text
1. 输入表主键唯一性检查。
2. 上游版本一致性检查。
3. `order_id` 小票数、`order_item_id` 明细行数对账。
4. 商品基础表 SPU 映射成功率和 SKU_ONLY 占比。
5. U_global、U_category、U_anchor、U_AB 数量对账。
6. n11/n10/n01/n00 加总等于 U_AB。
7. 正反向规则同时输出，support 和 lift 一致，confidence 可不同。
8. 自然篮子和促销/时段折扣篮子分流对账。
9. 小分类规则缺失时不生成 BASKET_RECIPE。
10. S 状态缺失时不生成 SEASONAL_NEW_PRODUCT。
11. 相同 run_id 下版本字段一致。
12. 相同数据快照、相同版本、相同 Sobol 种子下结果可重复。
```

边界测试必须覆盖：

```text
一次真实共现输出 RAW_COOCCURRENCE
零共现输出 NO_COOCCURRENCE
无锚点小票输出 NO_VALID_ANCHOR_BASKET
同一 SPU 不生成 A=>B
A=>B 和 A=>C 不自动拼成 A+B+C
促销依赖不生成正式新品
未到货和已售罄商品不进入 U_AB
销售量/到货量 > 1.10 不截断为 100%
不同画像和门店等级从底层重算
```

## 13. 不能做的事

```text
不能把 MBA 和 FP-Growth 当作二选一算法。
不能只用包含锚点的小票计算全局 Lift。
不能用固定统一 min_support 丢掉真实共现。
不能把一次共现包装成正式规则。
不能只显示 A=>B 而隐藏 B=>A。
不能伪造正反向不同 Lift。
不能用名称相似自动合并商品编码。
不能将同一 SPU 下的不同销售 SKU 生成自关联。
不能删除单商品篮子来提高规则。
不能将未到货或已售罄解释为消费者不购买。
不能将超卖异常截断为 100%。
不能将销售季外无销售计入 S 商品分母。
不能仅使用促销或时段折扣关系生成新品。
不能将餐食互补商品机械拼成新品。
不能将 A=>B 和 A=>C 擅自拼成三项新品。
不能让新品跨出目标叶子小分类。
不能用 AI 品类常识代替品类属性证据。
不能在小分类规则缺失时回退到通用命名模板。
```

## 14. 待评审红线

| 优先级 | 确认对象 | 红线问题 | 不确认会怎样 |
|---|---|---|---|
| P1 | 数据开发 | 是否能实现 FP-Growth、Association Rules、Jeffreys-Dirichlet 区间、Lift 后验模拟和贝叶斯 FDR | 不能用简单共现次数、固定阈值或普通 lift 代替正式算法 |
| P1 | 业务/商品/数据开发 | 小分类新品属性规则如何生成、存储和验收 | 缺规则时只能输出购物篮规则，不能发布 `BASKET_RECIPE` |
