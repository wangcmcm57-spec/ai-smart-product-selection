## 2. 数据范围与主归属区域

### 2.1 数据周期

每个正式模型版本使用最近 6 个数据已完整的自然月。

例如，系统在 2026 年 7 月运行，但 Doris 只有 2026 年 6 月 1 日至 7 日的数据，则 6 月不属于完整月，正式计算周期应为：

```text
2025-12-01 <= business_date < 2026-06-01
```

### 2.2 主归属区域

跨区域消费会员只保留一个主归属区域，按以下顺序确定：

```text
1. 最近 6 个完整月有效消费天数最多的区域
2. 消费天数相同时，选择有效小票数最多的区域
3. 小票数仍相同时，选择有效销售额最高的区域
4. 仍然相同时，选择最近一次消费所在区域
```

区域模型分别训练，会员使用主归属区域已发布的模型参数贴标。页面筛选区域时只汇总已生成的固定标签，不在查询时重新训练或贴标。

### 2.3 前置维表：算法区域映射表

会员画像中的 `primary_region` 不是直接取城市字段，而是取“算法区域映射表”中的算法区域。

华东一期业务已确认算法区域完全按城市归并，本表使用城市级映射即可，不需要门店级映射：

```text
上海 => 上海
杭州、宁波、绍兴 => 杭州宁波绍兴
苏州、常州、无锡 => 苏州常州无锡
```

正式映射以 `dim_city_algorithm_region` 为准，开发不得在代码中写死城市分组规则。小票先通过 `store_id` 关联门店基础表取得城市，再通过本表取得算法区域。

建议落表：

```text
dim_city_algorithm_region
```

表粒度：

```text
一行 = 一个城市 + 一个算法区域映射生效周期
```

主键：

```text
city + effective_start_date
```

关联要求：

```text
Doris 小票商品明细表 store_id -> 门店基础表门店编码 -> 门店基础表城市 -> dim_city_algorithm_region.city。
algorithm_region_name 用于会员画像中的 primary_region、区域熵权、Jenks 阈值和逻辑回归参数训练。
```

| 中文字段名 | 逻辑字段名 | 建议类型 | 是否必须 | 中文注释 |
|---|---|---|---|---|
| 城市 | city | varchar(64) | 必须 | 门店基础表中的城市，如上海、杭州、宁波、绍兴、苏州、常州、无锡 |
| 算法区域编码 | algorithm_region_code | varchar(64) | 必须 | 算法区域唯一编码，如 `SH`、`HZ_NB_SX`、`SZ_CZ_WX` |
| 算法区域名称 | algorithm_region_name | varchar(128) | 必须 | 算法训练与参数计算口径，如 `上海`、`杭州宁波绍兴`、`苏州常州无锡` |
| 生效开始日期 | effective_start_date | date | 必须 | 该映射开始生效日期 |
| 生效结束日期 | effective_end_date | date | 建议 | 当前有效映射可为空，历史映射回填结束日期 |
| 是否当前有效 | is_active | int | 必须 | `1` 当前有效，`0` 历史无效 |
| 映射确认人 | confirmed_by | varchar(64) | 建议 | 业务确认人 |
| 映射确认日期 | confirmed_date | date | 建议 | 业务确认日期 |
| 数据更新时间 | updated_at | datetime | 必须 | 数据同步或维护时间 |
| 备注 | remark | varchar(255) | 建议 | 边界城市、临时调整说明 |

数据质量要求：

```text
1. 同一城市在同一日期只能命中一个有效算法区域。
2. 参与会员画像的小票 store_id 必须能先匹配到门店基础表城市。
3. 参与会员画像的门店城市必须全部能匹配到有效算法区域。
4. 算法区域名称必须稳定，不得同义混写。
5. 映射变化必须保留历史生效周期，不能直接覆盖旧映射。
```

业务已确认华东一期不存在同一城市内部分门店需要归入不同算法区域，也不存在特殊门店不纳入会员画像计算，因此华东一期不增加门店级例外映射表。

## 3. 前置过滤

### 3.1 有效会员

```text
customer_id IS NOT NULL
AND customer_id NOT LIKE '6%'
```

`customer_id` 以 6 开头的记录属于非真实会员。

### 3.2 有效交易明细

只保留：

```text
交易日期位于模型周期内
order_id 不为空
销售数量或重量 > 0
实际销售额 > 0
已完成的正向销售交易
```

剔除：

```text
退货
取消
冲销
测试交易
非正向销售记录
```

退货记录不计为一次消费，也不参与金额、频次和商品偏好计算。

### 3.3 异常会员日

按 `customer_id + business_date` 统计去重小票数：

```text
单日小票数 <= 5：保留
单日小票数 > 5：剔除该会员当日全部交易
```

5 张为业务固定阈值。会员其他日期的正常交易继续参与计算。输出中需保留异常天数、异常小票数和被剔除销售额。

## 4. 条件式画像与终止规则

时间行为必须先完成最终判定，再决定是否继续计算其他维度。

捡漏型为终止标签：

```text
time_behavior = 捡漏型
=> final_profile = 捡漏型
=> family_level = NOT_APPLICABLE
=> frequency_level = NOT_APPLICABLE
=> price_attitude = NOT_APPLICABLE
=> profile_terminal_flag = 1
```

捡漏型不区分大小家庭、不区分消费频次、不区分价格态度，也不得生成任何 `捡漏型-家庭-频次-价格态度` 组合标签。

上班族晚高峰型和常规时段型继续计算三个维度：

```text
final_profile =
time_behavior-family_level-frequency_level-price_attitude

profile_terminal_flag = 0
```

例如：

```text
上班族晚高峰型-小家庭-中频-价格非敏感
常规时段型-大家庭-高频-价格敏感
```

周末倾向和品类偏好只作辅助特征，不拼接到主画像名称中。

## 5. 通用熵权法

### 5.1 业务解释

熵权法用于决定多个行为指标的数据权重。某指标在会员之间差异越大，越能区分会员，权重越高。权重不由业务人员固定填写。

### 5.2 公式

对某个区域、某一类行为的 `N` 名会员，第 `j` 个指标的归一化值为 `x_ij`：

```text
p_ij = x_ij / SUM_i(x_ij)
e_j = -1 / ln(N) * SUM_i(p_ij * ln(p_ij))
d_j = 1 - e_j
w_j = d_j / SUM_j(d_j)
score_i = SUM_j(w_j * x_ij)
```

当 `p_ij = 0` 时，`p_ij * ln(p_ij)` 按 0 处理。

当区域有效会员数 `N < 2` 时，不计算区域熵权，直接进入上一级区域参数回退，并输出 `entropy_sample_fallback_flag = 1`。

时间行为指标本身为 0—1 占比，可直接使用。价格敏感的超额偏好指标经 P99 上限和对数处理后，再转换为 0—1。

当所有指标的 `SUM(d_j) = 0` 时，使用等权重，并输出：

```text
entropy_fallback_flag = 1
```

### 5.3 必须保存的参数

```text
model_version
region
score_name
sample_member_cnt
metric_name
entropy_e
diversity_d
entropy_weight
entropy_fallback_flag
entropy_sample_fallback_flag
```

## 6. Jenks 自然断点

### 6.1 解决的问题

Jenks 自然断点在行为得分计算完成后，寻找普通行为组与高行为组之间的数据分界线。它不固定标签人数比例，也不使用人工固定分数。

### 6.2 开发计算

对已满足最低行为证据的会员得分排序，遍历每个相邻且得分不同的切分位置 `k`：

```text
SSE(k) =
SUM(score_i - mean_low)^2, i 属于普通组
+ SUM(score_i - mean_high)^2, i 属于高行为组
```

选择 `SSE(k)` 最小的切分位置：

```text
jenks_threshold =
(MAX(score_low_group) + MIN(score_high_group)) / 2
```

如果全部会员得分相同，或不存在相邻且得分不同的有效切分位置，则本区域 Jenks 断点无效，直接执行上一级区域回退。

### 6.3 有效性与回退

本区域断点必须同时满足：

```text
普通组会员数 >= 30
高行为组会员数 >= 30
(高组均值 - 低组均值) / 全体得分标准差 >= 0.5
当期阈值相对上一版本变化 <= 20%
```

当全体得分标准差为 0 时，组间差异不做除法，直接判定本区域断点无效。

阈值变化超过 20% 时不自动发布新版本，先检查数据完整性、映射和标记口径。

本区域断点无效时使用上一级区域阈值。本区域和上一级区域都无有效阈值时：

```text
时间行为默认为常规时段型
价格态度默认为价格非敏感
threshold_fallback_flag = 1
```

30 人、0.5 和 20% 为 V1 统计与运行控制参数，不是标签人数比例。

## 7. 时间行为算法

### 7.1 时间窗口

| 日期类型 | 时间 | 行为窗口 |
|---|---|---|
| 周一至周五 | 18:00 以前 | 常规时段 |
| 周一至周五 | 18:00 至 19:30:00，含 19:30:00 | 上班族晚高峰窗口 |
| 周一至周五 | 19:30:00 之后 | 捡漏窗口 |
| 周六、周日 | 19:30:00 及以前 | 常规时段 |
| 周六、周日 | 19:30:00 之后 | 捡漏窗口 |

捡漏行为不区分工作日与周末。上班族晚高峰只计算周一至周五。

### 7.2 晚高峰指标

```text
晚高峰消费天数占比 =
工作日 18:00—19:30:00 消费天数 / 全部有效消费天数

晚高峰小票占比 =
工作日 18:00—19:30:00 小票数 / 全部有效小票数

晚高峰销售额占比 =
工作日 18:00—19:30:00 销售额 / 全部有效销售额
```

按主归属区域分别使用熵权法生成 `commute_score`。

最低证据：

```text
晚高峰消费天数 >= 3
晚高峰消费覆盖自然月数 >= 2
```

候选标签：

```text
满足最低证据
AND commute_score >= commute_jenks_threshold
=> 上班族晚高峰候选会员
```

真实数据留出验证中，“至少 3 天且跨 2 月”相比“至少 2 天”，次月晚高峰延续率提升 6.88—9.61 个百分点。

### 7.3 捡漏指标

```text
19:30:00 后消费天数占比 =
19:30:00 后消费天数 / 全部有效消费天数

19:30:00 后小票占比 =
19:30:00 后小票数 / 全部有效小票数

19:30:00 后销售额占比 =
19:30:00 后销售额 / 全部有效销售额
```

时段折扣生鲜业态中，`19:30:00` 之后的消费直接视为捡漏行为，不再额外检查单品折扣字段。

按主归属区域分别使用熵权法生成 `bargain_score`。

最低证据：

```text
19:30:00 后消费天数 >= 3
19:30:00 后消费覆盖自然月数 >= 2
```

候选标签：

```text
满足最低证据
AND bargain_score >= bargain_jenks_threshold
=> 捡漏候选会员
```

真实数据留出验证中，“至少 3 天且跨 2 月”相比“至少 2 天”，次月捡漏行为延续率提升 2.67—2.92 个百分点。

### 7.4 时间行为冲突

```text
只命中晚高峰 => 上班族晚高峰型
只命中捡漏 => 捡漏型
两类都未命中 => 常规时段型
```

两类同时命中时：

```text
commute_relative_strength = commute_score / commute_jenks_threshold
bargain_relative_strength = bargain_score / bargain_jenks_threshold
```

相对强度高者为最终标签。当两者相差不超过 0.05 时，依次比较目标时段消费天数、覆盖自然月数；仍相同时捡漏型优先。

### 7.5 时间行为置信度

对最终命中的高行为类型，计算得分与断点的相对距离：

```text
G_time = (score - jenks_threshold) / jenks_threshold
```

```text
命中捡漏型或上班族晚高峰型，且 G_time >= 0.20
=> time_confidence = 高

命中捡漏型或上班族晚高峰型，但 G_time < 0.20
=> time_confidence = 中
```

常规时段型的置信度：

```text
晚高峰和捡漏均有足够行为证据，且两个得分均低于阈值 20% 以上
=> time_confidence = 高

至少一个行为得分接近阈值
=> time_confidence = 中

晚高峰和捡漏的最低行为证据都不足
=> time_confidence = 低
```

当本区域和上一级区域都没有有效时间行为断点、触发 `threshold_fallback_flag = 1` 时，会员输出常规时段型，且 `time_confidence = 低`。

时间行为判定完成后立即执行终止规则：最终为捡漏型的会员不再进入第 8—10 章的家庭规模、消费频次和价格态度计算；最终为上班族晚高峰型或常规时段型的会员继续计算后续维度。

## 8. 家庭规模算法

本章只适用于最终时间行为为上班族晚高峰型或常规时段型的会员。捡漏型会员不参与家庭规模训练、预测和标签输出。

### 8.1 业务含义

家庭规模是根据日常备餐型购物行为推断的消费规模，不是真实人口属性。直接规则只使用 19:00 前的蔬菜购买，避免时段折扣和囤货放大购买量。

### 8.2 第一层：直接规则

稳定行为证据：

```text
19:00 前蔬菜消费天数 >= 3
19:00 前蔬菜消费覆盖自然月数 >= 2
```

指标：

```text
日均蔬菜重量 = 19:00 前蔬菜总重量 / 19:00 前蔬菜消费天数
日均蔬菜 SKU 数 = SUM(每个蔬菜消费日去重 SKU 数) / 蔬菜消费天数
```

全华东使用统一固定阈值：

```text
日均蔬菜重量 >= 1.5kg
OR 日均蔬菜 SKU 数 >= 4
OR (日均蔬菜重量 >= 1.2kg AND 日均蔬菜 SKU 数 >= 3)
=> 大家庭，高置信度
```

满足稳定证据但未命中大家庭条件：

```text
=> 小家庭，高置信度
```

### 8.3 第二层：购物篮补充模型

不满足第一层稳定蔬菜证据时，所有会员仍必须输出大或小家庭标签。使用主归属区域的逻辑回归模型补充判断。

输入指标均限定在 19:00 前：

```text
x1 = 平均 SKU 数 / 票
x2 = 平均购买重量 / 票
x3 = 家庭食材 SKU 数 / 票
x4 = 家庭食材重量 / 票
x5 = 家庭食材品类数 / 票
```

家庭食材包括：

```text
蔬菜、肉禽蛋、猪肉、水产
```

消费频次、客单价和销售额不进入补充模型，避免把高活跃或高消费能力直接等同于大家庭。

### 8.4 指标预处理

对每个区域、每个模型版本分别处理：

```text
1. 只限制异常大值：X_cap = MIN(X, P99_region)
2. 对数转换：X_log = ln(1 + X_cap)
3. 标准化：X_std = (X_log - mean_region) / std_region
```

不对小值做 P1 提升。没有 19:00 前小票的会员，五个原始指标记为 0，不应被提升到 P1。

某指标在区域训练样本中的 `std_region = 0` 时，该指标无法区分会员，所有会员的该标准化值记为 0，并输出 `standardization_fallback_flag = 1`。

### 8.5 逻辑回归

训练样本只使用第一层高置信度会员：

```text
Y = 1：大家庭
Y = 0：小家庭
```

区域分别训练，使用 L2 约束和类别平衡权重：

```text
weight_large = N / (2 * N_large)
weight_small = N / (2 * N_small)
```

如果本区域的高置信度大家庭或小家庭训练样本少于 30 人，不训练本区域补充模型，使用上一级区域已通过验收的模型参数。如果上一级也无可用模型，证据不足会员输出小家庭、低置信度，并设置 `family_model_fallback_flag = 1`。

模型：

```text
Z = beta_0 + beta_1*x1_std + beta_2*x2_std + beta_3*x3_std + beta_4*x4_std + beta_5*x5_std
P_large = 1 / (1 + exp(-Z))
```

每个区域使用分层 5 折交叉验证生成样本外概率，遍历 0.05—0.95、步长 0.01 的候选阈值：

```text
大家庭召回率 = TP / (TP + FN)
小家庭识别率 = TN / (TN + FP)
平衡准确率 = (大家庭召回率 + 小家庭识别率) / 2
```

选择平衡准确率最高的概率为区域阈值；并列时选择较高阈值。最后使用全部高置信度样本重新训练正式模型。

分层划分必须使用固定 `random_seed`，并将种子与模型版本一起保存，保证产研重复运行时可以复现相同阈值。

标签：

```text
P_large >= family_probability_threshold => 大家庭
P_large < family_probability_threshold => 小家庭
```

### 8.6 家庭规模置信度

第一层直接规则：

```text
family_confidence = 高
```

第二层计算概率相对阈值的归一化距离：

```text
当 P_large >= T：D = (P_large - T) / (1 - T)
当 P_large < T：D = (T - P_large) / T
```

```text
19:00 前有效消费天数 >= 3
AND 覆盖自然月数 >= 2
AND D >= 0.20
=> family_confidence = 中

其他第二层结果
=> family_confidence = 低
```

## 9. 消费频次算法

本章只适用于最终时间行为为上班族晚高峰型或常规时段型的会员。捡漏型会员不计算高频、中频或低频标签。

### 9.1 可观察月份

```text
observed_months =
从会员在当期的首次有效消费月
到模型周期结束月的自然月数，含首尾月
```

行为频次：

```text
monthly_shop_days_observed = 有效消费天数 / observed_months
```

同一会员同一日多张小票只计一个消费日。

### 9.2 最终频次标签

```text
monthly_shop_days_observed >= 8 => 高频
4 <= monthly_shop_days_observed < 8 => 中频
monthly_shop_days_observed < 4 => 低频
```

业务含义：

```text
8 天 / 月：约每周 2 次
4 天 / 月：约每周 1 次
```

最终标签不再与区域三等分混合。区域百分位和三等分只作辅助字段。

同时输出周期贡献频次：

```text
monthly_shop_days_full_period = 有效消费天数 / 6
```

该字段不覆盖最终频次标签。

## 10. 价格态度算法

本章只适用于最终时间行为为上班族晚高峰型或常规时段型的会员。捡漏型会员不参与价格态度基准、得分和标签计算。

### 10.1 时间与促销标记

只使用 19:00 前的常规促销行为，不使用 19:30 后时段折扣。

```text
discount_amt > 0 => 该商品行视为常规促销商品
```

`discount_amt` 只作促销标记，不直接求和。促销商品销售额使用该商品行的 `usual_amt`：

```text
促销商品销售额 = SUM(CASE WHEN discount_amt > 0 THEN usual_amt ELSE 0 END)
```

废止使用 `SUM(discount_amt) / SUM(usual_amt)`，防止单位差异或重复字段导致占比超过 100%。

### 10.2 同场景促销基准

优先在以下场景中比较：

```text
门店 + 自然周 + 商品小分类
```

基准样本必须满足：

```text
去重会员数 >= 10
去重小票数 >= 20
```

样本不足时依次回退：

```text
1. 门店 + 自然周 + 小分类
2. 区域 + 自然周 + 小分类
3. 区域 + 自然月 + 小分类
4. 区域 + 最近 6 个完整月 + 小分类
```

基准使用同场景其他会员的平均值，目标会员不参与自身基准。输出 `baseline_level`、`baseline_member_cnt` 和 `baseline_ticket_cnt`。

如果某一级基准为 0，不进行除法，继续向上一级范围回退。如果区域 6 个月小分类基准仍为 0，该场景不参与偏好指数汇总，并设置 `baseline_zero_flag = 1`。

### 10.3 促销偏好指数

在每个有效场景内：

```text
会员促销 SKU 占比 = 会员促销 SKU 数 / 会员全部 SKU 数
会员促销销售额占比 = 会员促销商品 usual_amt / 会员全部 usual_amt

同场景促销 SKU 基准 = 其他会员促销 SKU 占比的平均值
同场景促销销售额基准 = 其他会员促销销售额占比的平均值

场景 SKU 偏好指数 = 会员促销 SKU 占比 / 同场景促销 SKU 基准
场景销售额偏好指数 = 会员促销销售额占比 / 同场景促销销售额基准
```

跨场景汇总：

```text
最终 SKU 偏好指数 = SUM(场景 SKU 偏好指数 * 场景 SKU 数) / SUM(场景 SKU 数)
最终销售额偏好指数 = SUM(场景销售额偏好指数 * 场景销售额) / SUM(场景销售额)
```

如果会员没有任何有效促销比较场景，则不执行跨场景除法，两个最终偏好指数和价格敏感得分均记为 0，输出价格非敏感、低置信度，并设置 `price_scene_fallback_flag = 1`。

### 10.4 价格敏感得分

只保留高于同场景普通会员的部分：

```text
sku_excess = MAX(final_sku_preference_index - 1, 0)
sales_excess = MAX(final_sales_preference_index - 1, 0)
```

分区域做 P99 上限、对数处理和 0—1 归一化：

```text
x_cap = MIN(x, P99_region)
x_log = ln(1 + x_cap)
x_norm = x_log / MAX_region(x_log)
```

当 `MAX_region(x_log) = 0` 时，该指标的全部归一化值记为 0，并设置 `price_normalization_fallback_flag = 1`。

使用两个指标的区域熵权合成：

```text
price_sensitive_score = w_sku * sku_excess_norm + w_sales * sales_excess_norm
```

### 10.5 最低证据与标签

最低证据：

```text
19:00 前促销 SKU 数 >= 3
促销购买覆盖自然月数 >= 2
促销商品覆盖小分类数 >= 2
单一促销 SKU 销售额 / 全部促销商品销售额 <= 0.50
```

3 个 SKU 的数据来源：三个区域稳定促销会员的 P10 为 3—4 个 SKU；该阈值位于分布较低位置。

50% 集中度的数据来源：三个区域 P75 为 41.14%—45.56%，向上取统一、可解释的 50% 上限。

最终标签：

```text
四项最低证据全部通过
AND price_sensitive_score >= price_jenks_threshold
=> 价格敏感

其他
=> 价格非敏感
```

不要求 SKU 偏好指数和销售额偏好指数分别达到两个阈值，只使用一个熵权综合得分断点，避免过度收紧。

### 10.6 价格态度置信度

```text
G = ABS(price_sensitive_score - price_jenks_threshold) / price_jenks_threshold
```

```text
促销 SKU、月份、小分类和集中度证据齐全
AND G >= 0.20
=> 高置信度

促销 SKU 和月份证据齐全，但得分接近阈值或集中度超标
=> 中置信度

促销 SKU < 3 或覆盖月份 < 2
=> 低置信度
```

价格敏感只允许中、高置信度。低置信度会员统一输出价格非敏感。

当本区域和上一级区域都没有有效价格断点、触发 `threshold_fallback_flag = 1` 时，会员输出价格非敏感，且 `price_confidence = 低`。

## 11. 模型更新与标签稳定

### 11.1 月度正式版本

```text
1. 检查上月数据完整性
2. 使用最近 6 个完整月重新计算参数
3. 完成阈值稳定性、留出数据和人工抽样验收
4. 发布新模型版本
5. 全量更新会员画像
```

已有会员在同一模型版本内不因每日新增小票频繁换标。

### 11.2 月中新会员

新会员产生第一张有效小票后，使用当前已发布的区域模型参数增量贴标，确保不出现无画像会员。增量会员通常使用低置信度，下一个月度全量版本再统一重算。

必须保存：

```text
model_version
calculation_start_date
calculation_end_date
effective_start_date
effective_end_date
previous_profile
current_profile
profile_change_reason
is_incremental_new_member
```

## 12. 标签应用与汇总

会员标签生成后，其全部有效消费记录都使用这套固定标签，不只统计用于判断标签的目标时段或促销商品。

```text
会员数占比 = 该画像去重会员数 / 分析范围去重会员总数
销售额占比 = 该画像会员全部有效销售额 / 分析范围会员全部有效销售额
小票数 = 该画像会员全部有效小票数
客单价 = 该画像会员销售额 / 该画像会员小票数
```

区域查询时，使用在所选区域发生的交易汇总固定标签。同一跨区域会员可能分别出现在多个区域视图中，但华东汇总必须按 `customer_id` 去重，不能直接将各区域会员数相加。

## 14. 计算样例

以下数字为计算路径示例，用于说明算法判定过程，帮助开发实现和业务验收，不代表生产模型真实参数。

### 14.1 案例 A：捡漏型

输入概要：

```text
主归属区域：上海
可观察月份：6
有效消费天数：60
19:30 后消费：12 天，覆盖 4 个月
晚高峰消费：2 天
```

计算：

```text
捡漏证据通过，bargain_score = 0.58，区域断点 = 0.44 => 捡漏候选
晚高峰天数不足 => 不是晚高峰候选
最终时间行为 = 捡漏型 => 命中终止规则
家庭规模、消费频次和价格态度不再计算，统一为 NOT_APPLICABLE
```

结果：

```text
捡漏型
```

### 14.2 案例 B：上班族晚高峰型-小家庭-中频-价格非敏感

输入概要：

```text
主归属区域：杭州宁波绍兴
可观察月份：6
有效消费天数：30
工作日晚高峰：8 天，覆盖 4 个月
19:30 后消费：1 天
19:00 前蔬菜：6 天，日均 0.85kg，日均 1.7 个 SKU
促销行为证据齐全，但促销偏好接近同场普通会员
```

计算：

```text
晚高峰证据通过，commute_score = 0.68，区域断点 = 0.43 => 晚高峰候选
捡漏证据不足 => 不是捡漏候选
稳定蔬菜证据齐全但未命中大家庭阈值 => 小家庭，高置信度
行为频次 = 30 / 6 = 5 天 / 月 => 中频
price_score = 0.17，区域断点 = 0.27 => 价格非敏感
```

结果：

```text
上班族晚高峰型-小家庭-中频-价格非敏感
```

### 14.3 案例 C：月中新会员的补充判断

输入概要：

```text
首次有效消费：模型周期的最后 1 个月
可观察月份：1
有效消费天数：2
无稳定晚高峰或捡漏证据
无稳定蔬菜证据
促销 SKU：1 个
```

家庭补充模型计算示例：

```text
标准化购物篮指标 = [0.20, 0.40, 0.30, 0.50, 0.10]
示例系数 beta = [-0.60, 0.40, 0.50, 0.30, 0.40, 0.20]

Z = -0.60 + 0.40*0.20 + 0.50*0.40 + 0.30*0.30 + 0.40*0.50 + 0.20*0.10
  = -0.01
P_large = 1 / (1 + exp(0.01)) = 0.4975
区域概率阈值 = 0.58
=> 小家庭，低置信度
```

其他维度：

```text
时间行为 => 常规时段型
行为频次 = 2 / 1 = 2 天 / 月 => 低频
促销证据不足 => 价格非敏感，低置信度
```

结果：

```text
常规时段型-小家庭-低频-价格非敏感
```

示例系数只用于说明代入过程，生产计算必须读取区域模型参数表。

## 15. 开发验收与业务验收

### 15.1 数据完整性

```text
全部有效会员必须输出一条画像
最终画像不得为空
捡漏型的家庭、频次和价格态度必须为 NOT_APPLICABLE
非捡漏型的家庭、频次和价格态度不得为空或为 NOT_APPLICABLE
同一模型版本、同一会员只能有一条最终画像
被过滤的非真实会员、退货和异常会员日不得进入计算
```

### 15.2 开发对数

从真实数据抽取并脱敏 10 名会员，固定输入小票、中间指标、模型参数、期望得分和期望标签。

```text
比例和模型得分误差 <= 0.000001
最终标签 100% 一致
```

### 15.3 业务合理性

```text
捡漏型的次月 19:30 后消费延续率应高于常规会员
晚高峰型的次月工作日晚高峰延续率应高于常规会员
非捡漏型大家庭的整篮 SKU 数与购买重量应高于小家庭
非捡漏型高频会员月均消费天数应高于中频和低频
非捡漏型价格敏感会员的促销偏好指数应高于价格非敏感会员
```

### 15.4 稳定性与人工抽样

```text
对比当期与上期熵权、断点和标签占比
阈值变化超过 20% 必须预警
标签大规模变化必须有数据或行为原因
不得为了维持固定占比而人工调整会员标签
```

每个模型版本按区域、标签和置信度分层抽取 100 名会员，业务查看小票后记录：

```text
判断合理
判断不合理
证据不足
需要调整规则
```

人工意见进入下一版本评估，不直接修改当前版本会员标签。
