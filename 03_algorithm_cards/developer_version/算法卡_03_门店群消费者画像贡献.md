## 1. 算法目标

本算法用于识别同一城市算法区域、同一品类、同一门店品类等级群中的主力消费者类型。

它只回答：

```text
在某个城市算法区域 + 某个品类 + 某个门店等级群里，
哪些消费者类型既覆盖更多有效购买会员，又贡献更多有效会员销售额？
```

输出结果供后续算法读取：

```text
目标画像 SKU 表现算法
新品候选标准化与合并算法
新品机会证据合成与风险门禁算法
新品推荐优先级与开发需求编排
AI 商品机会推荐表
```

本算法不做：

```text
不重新计算会员画像
不重新计算门店品类等级
不生成单门店正式主力人群
不直接推荐 SKU 或新品
不使用非会员销售进入主力贡献得分
不使用客单价、小票占比或人工权重改变正式主力判定
```

## 3. 计算周期、版本与开发执行流程

算法 03 按月离线批量计算。开发先锁定同一贡献周期内的算法 01 画像版本、算法 02 门店品类等级版本、城市算法区域版本和商品分类版本，再把有效会员小票聚合到城市算法区域、品类、门店等级群和消费者画像粒度。

前端和后续算法只读取已发布的 `mart_store_group_consumer_contribution` 和 `mart_store_group_consumer_summary`。采购侧查询城市、品类、门店等级或消费者画像时，只过滤已计算结果，不触发画像贡献实时重算。

正式贡献周期：

```text
最近 3 个数据完整自然月
```

例如 2026 年 7 月运行：

```text
contribution_start_date = 2026-04-01
contribution_end_date   = 2026-06-30
```

更新规则：

```text
每月正式更新一次。
同一贡献周期只能使用一个正式会员画像版本。
同一贡献周期只能使用一个正式门店品类等级版本。
同一贡献周期只能使用一个城市算法区域版本。
同一贡献周期只能使用一个商品基础表分类口径。
```

版本血缘字段必须保存：

```text
consumer_contribution_model_version
profile_model_version
category_level_model_version
category_mapping_version
scope_version
source_data_version
```

V1 口径：

```text
category_mapping_version 表示本次使用的商品基础表分类口径版本。
商品分类使用当前商品基础表分类，不做历史商品分类版本回溯。
如果 dim_sku 没有独立版本号，可使用 dim_sku 数据批次号或本次参与计算的 dim_sku 最大更新时间生成该字段。
```

如果会员画像版本、门店品类等级版本、城市算法区域版本或商品分类口径变化，算法 03 必须重跑当前贡献周期，不能把不同版本混在同一批结果中。

## 7. 关联路径与质量闸门

### 7.1 关联顺序

```text
1. 锁定贡献周期、会员画像版本、门店品类等级版本、城市算法区域版本。
2. 从 mart_store_category_level 读取正式门店品类等级，得到门店群。
3. 从 Doris 小票表读取贡献周期内 valid_all_txn。
4. valid_all_txn 关联 dim_sku 当前商品分类，筛选目标品类。
5. 关联 mart_store_category_level，把小票归入对应门店等级群。
6. 对全量有效交易聚合，得到覆盖率分母。
7. 在全量有效交易中筛选会员交易并关联 dim_customer_profile。
8. 按门店群 + 品类 + final_profile 聚合，计算贡献指标。
```

### 7.2 上游版本闸门

同一批结果必须满足：

```text
COUNT(DISTINCT profile_model_version) = 1
COUNT(DISTINCT category_level_model_version) = 1
COUNT(DISTINCT scope_version) = 1
COUNT(DISTINCT category_mapping_version) = 1
```

不满足时：

```text
result_status = 'UPSTREAM_VERSION_ERROR'
不发布正式主力人群结论
```

### 7.3 会员画像唯一性

检查：

```text
同一 profile_model_version + customer_id 只能有一个 final_profile
```

不满足时：

```text
result_status = 'DUPLICATE_JOIN_ERROR'
diagnostic_reason 记录重复 customer_id 和重复画像数量
```

### 7.4 门店品类等级唯一性

检查：

```text
同一 category_level_model_version
+ scope_version
+ scope_type
+ scope_id
+ store_id
+ category_granularity
+ category_code
只能有一个 final_level
```

不满足时：

```text
result_status = 'DUPLICATE_JOIN_ERROR'
diagnostic_reason 记录重复门店品类等级
```

### 7.5 商品分类唯一性

检查：

```text
同一 category_mapping_version + sku_id 只能命中一个当前商品分类
```

不满足时：

```text
result_status = 'CATEGORY_MAPPING_ERROR'
diagnostic_reason 记录一对多 sku_id
```

### 7.6 关联后对账

对每个门店群品类检查：

```text
关联前已贴标会员销售额 = 关联后各 final_profile 销售额合计
关联前已贴标会员商品行数 = 关联后各 final_profile 商品行数合计
关联前已贴标会员小票数 = 关联后按 final_profile 去重小票后的合计
```

其中会员销售额和商品行数必须完全一致；金额允许误差不超过 `0.01%`。

不满足时：

```text
result_status = 'DUPLICATE_JOIN_ERROR'
不发布正式主力人群结论
```

## 8. 门店群与品类范围

### 8.1 城市算法区域

正式结果支持：

```text
CITY：单城市
CITY_CLUSTER：业务配置城市群
```

范围来自 `dim_city_algorithm_region` 和算法 02 输出，不允许算法 03 自动扩大到华东大区或其他城市。

### 8.2 品类颗粒度

支持：

```text
LARGE：大类
MIDDLE：中类
SMALL：小类
```

每个颗粒度都必须从底层小票重新筛选、关联和聚合：

```text
大类结果 != 下属中类结果平均
中类结果 != 下属小类结果平均
```

### 8.3 门店群类型

支持：

```text
FINAL_LEVEL：指定等级门店群，例如 A / B / C / D
ALL_RATED：当前范围和品类下全部已有正式等级的门店
```

`ALL_RATED` 必须从底层小票重新聚合，不能把 A、B、C、D 四个等级结果直接相加。

原因：

```text
同一会员可能在多个等级门店消费。
如果直接相加，会员数会被重复计算。
```

### 8.4 门店数口径

```text
store_cnt = 当前门店群内参与 03 计算的门店数
rated_store_cnt = 当前范围和品类下已经由算法 02 成功评出等级的门店数
```

V1 不强制输出未评级门店数和已评级门店覆盖率。

如果后续算法 02 能提供“应该参与评级但未形成等级”的门店清单，可以补充：

```text
unrated_store_cnt = 当前范围和品类下应该参与评级、但没有形成正式等级的门店数
rated_store_coverage_rate = rated_store_cnt / (rated_store_cnt + unrated_store_cnt)
```

这两个字段只用于数据覆盖诊断，不参与画像贡献得分。

## 9. 基础聚合指标

### 9.1 消费者类型指标

在同一个门店群品类下，对每个 `final_profile` 计算：

```text
profile_member_cnt = COUNT(DISTINCT customer_id)
profile_sales_amt = SUM(usual_amt)
profile_ticket_cnt = COUNT(DISTINCT order_id)
profile_avg_ticket_amt = profile_sales_amt / profile_ticket_cnt
```

其中：

```text
profile_sales_amt 只统计 valid_profiled_member_txn。
profile_ticket_cnt 在同一个品类内，同一 order_id 只计 1 次。
```

### 9.2 门店群已贴标会员分母

```text
group_member_cnt = COUNT(DISTINCT customer_id)
group_sales_amt = SUM(usual_amt)
group_ticket_cnt = COUNT(DISTINCT order_id)
group_avg_ticket_amt = group_sales_amt / group_ticket_cnt
```

统计范围：

```text
当前门店群
+ 当前品类
+ 当前贡献周期
+ 全部已贴标会员有效交易
```

### 9.3 全量覆盖率分母

```text
group_total_sales_amt = SUM(valid_all_txn.usual_amt)
group_total_ticket_cnt = COUNT(DISTINCT valid_all_txn.order_id)
profiled_member_sales_amt = group_sales_amt
profiled_member_ticket_cnt = group_ticket_cnt
```

覆盖率：

```text
member_sales_coverage_rate = profiled_member_sales_amt / group_total_sales_amt
member_ticket_coverage_rate = profiled_member_ticket_cnt / group_total_ticket_cnt
```

业务含义：

```text
贡献分：只在已贴标会员内部判断主力消费者类型。
覆盖率：判断已贴标会员销售能代表全量销售的程度。
```

### 9.4 画像关联成功率

应关联会员：

```text
valid_all_txn 中 is_customer = 1、customer_id 非空，且满足算法 01 有效会员口径的会员
```

成功关联会员：

```text
应关联会员中能关联本次锁定 dim_customer_profile 正式画像的会员
```

公式：

```text
profile_link_success_rate =
成功关联正式画像的有效会员数 / 应关联正式画像的有效会员数
```

正式发布要求：

```text
profile_link_success_rate = 100%
```

不满足时：

```text
result_status = 'PROFILE_LINK_INCOMPLETE'
不发布正式主力人群结论
```

## 10. 画像贡献占比

对每个 `final_profile` 计算：

```text
member_share = profile_member_cnt / group_member_cnt
sales_share  = profile_sales_amt / group_sales_amt
ticket_share = profile_ticket_cnt / group_ticket_cnt
```

约束：

```text
SUM(member_share) = 100%
SUM(sales_share) = 100%
```

允许浮点误差：

```text
0.01%
```

正式主力判定只使用：

```text
member_share
sales_share
```

`ticket_share` 只用于解释，不改变主力标签。

## 11. 贡献得分

### 11.1 公式

```text
profile_contribution_score =
2 * sales_share * member_share
/ (sales_share + member_share) * 100
```

零分母处理：

```text
sales_share + member_share = 0 时，不执行除法，不生成该消费者类型结果行。
```

### 11.2 解释

该公式是销售占比和会员占比的调和平均。

它要求：

```text
人多
+ 买得多
```

同时成立。

典型效果：

```text
销售占比高但会员占比低：得分会被会员覆盖限制
会员占比高但销售占比低：得分会被销售贡献限制
两项同时高：得分较高
```

### 11.3 解释指数

解释指数不参与正式得分。

```text
per_member_contribution_index = sales_share / member_share
visit_activity_index = ticket_share / member_share
avg_ticket_index = profile_avg_ticket_amt / group_avg_ticket_amt
```

含义：

```text
per_member_contribution_index > 1：该类型人均销售贡献高于门店群平均
visit_activity_index > 1：该类型人均到店小票贡献高于门店群平均
avg_ticket_index > 1：该类型目标品类客单高于门店群平均
```

## 12. 主力消费者类型判定

### 12.1 候选类型

候选类型为同一门店群品类下所有有效 `final_profile`。

保留规则：

```text
profile_member_cnt > 0
profile_sales_amt > 0
```

不设置人工最小样本门槛：

```text
不要求至少 10 名会员
不要求至少 30 张小票
不因小样本直接删除真实消费者类型
```

小样本不确定性由 Bootstrap、留一月验证、原始会员数和小票数披露。

### 12.2 Jenks 自然断点

把同一门店群内所有 `profile_contribution_score` 从低到高排序。

尝试：

```text
K = 1：不分高低组
K = 2：低贡献组 + 高贡献组
```

K=1：

```text
SSE_1 = SUM((score_i - 全体均值)^2)
```

K=2：

```text
枚举所有连续切分位置。
每个切分位置计算左右两组组内平方误差。
选择 SSE_2 最小的断点。
```

限制：

```text
相同贡献得分不得被拆入不同组。
两组都必须非空。
```

### 12.3 BIC 选择 K

公式：

```text
BIC(K) = N * ln(SSE_K / N + epsilon) + K * ln(N)
epsilon = 1e-12
```

其中：

```text
N = 当前门店群有效消费者类型数量
K = 1 或 2
```

选择规则：

```text
BIC 越小越好。
全部贡献得分相同时，只允许 K = 1。
多个候选 BIC 相同时，选择更小的 K。
```

### 12.4 最终主力判定

如果选择 K=2：

```text
高贡献组全部为正式主力消费者类型
is_main_profile = 1
result_status = 'SUCCESS'
```

如果选择 K=1：

```text
没有明显主力
result_status = 'NO_OBVIOUS_MAIN'
is_main_profile = 0
```

K=1 时，贡献得分最高的类型只作为相对主力候选：

```text
is_relative_main_candidate = 1
```

最高分并列时，所有并列最高分类型均为相对主力候选。

### 12.5 单一消费者类型

如果只有一种有效消费者类型：

```text
不运行 Jenks/BIC
result_status = 'SINGLE_PROFILE'
is_main_profile = 1
profile_contribution_score = 100
selected_cluster_count = 1
```

说明：

```text
贡献分 100 只表示当前有效会员消费结构单一。
不代表该人群经营价值必然更高。
```

### 12.6 排名与主力覆盖

排名：

```text
contribution_rank = DENSE_RANK() OVER (ORDER BY profile_contribution_score DESC)
```

主力覆盖：

```text
main_member_coverage_rate =
SUM(主力类型 profile_member_cnt) / group_member_cnt

main_sales_coverage_rate =
SUM(主力类型 profile_sales_amt) / group_sales_amt
```

`NO_OBVIOUS_MAIN` 时：

```text
main_member_coverage_rate = NULL
main_sales_coverage_rate = NULL
```

## 13. 稳定性验证

稳定性只用于解释结果可靠性，不修改完整周期的正式主力判定。

### 13.1 会员级 Bootstrap

抽样单位：

```text
会员 customer_id
```

禁止抽样小票。

每轮步骤：

```text
1. 在当前门店群全部有效会员中有放回抽样。
2. 每轮样本会员数等于原始有效会员数。
3. 被抽中的会员携带贡献周期内全部目标品类有效交易。
4. 重新计算 member_share、sales_share、profile_contribution_score。
5. 重新执行 Jenks/BIC。
6. 记录每个 final_profile 是否被判为主力。
```

自动停止规则：

```text
至少运行 1,000 轮
最多运行 10,000 轮
每 250 轮检查一次
```

MCSE：

```text
MCSE = sqrt(p * (1 - p) / B)
```

其中：

```text
p = 当前消费者类型 Bootstrap 主力入选率
B = 已运行轮数
```

停止条件：

```text
所有消费者类型 MCSE <= 0.01
```

输出字段：

```text
bootstrap_iterations
bootstrap_main_rate
bootstrap_main_rate_ci_lower_95
bootstrap_main_rate_ci_upper_95
bootstrap_mcse
```

95% 区间可按以下方式计算：

```text
bootstrap_main_rate_ci_lower_95 = MAX(p - 1.96 * MCSE, 0)
bootstrap_main_rate_ci_upper_95 = MIN(p + 1.96 * MCSE, 1)
```

### 13.2 留一月验证

正式贡献周期为连续 3 个完整自然月。

验证方式：

```text
验证 1：删除第 1 月，使用第 2 月 + 第 3 月重算
验证 2：删除第 2 月，使用第 1 月 + 第 3 月重算
验证 3：删除第 3 月，使用第 1 月 + 第 2 月重算
```

要求：

```text
会员画像版本保持不变。
门店群成员保持不变。
只改变参与统计的交易月份。
```

公式：

```text
time_main_rate =
被判为主力的有效验证次数 / 有效验证总次数
```

如果删除某个月后没有有效会员消费，该次验证不进入分母。

如果有效验证次数少于 2 次：

```text
time_stability_status = 'INSUFFICIENT_TIME_SAMPLE'
time_main_rate = NULL
```

## 17. 计算步骤

开发实现按以下顺序执行。

```text
1. 确定贡献周期和版本。
2. 校验算法 01、算法 02、城市算法区域、商品分类口径版本唯一。
3. 读取算法 02 正式门店品类等级，生成门店群清单。
4. 读取 Doris 小票，生成 valid_all_txn。
5. valid_all_txn 关联商品基础表当前分类。
6. 按目标品类颗粒度筛选大类、中类、小类。
7. valid_all_txn 关联门店群，得到门店群全量有效交易。
8. 从全量有效交易中筛选会员交易，并关联算法 01 正式会员画像。
9. 校验画像关联成功率和关联前后金额、行数、小票数。
10. 按门店群 + 品类 + final_profile 聚合基础指标。
11. 计算 member_share、sales_share、ticket_share。
12. 计算 profile_contribution_score。
13. 用 Jenks/BIC 判定主力消费者类型。
14. 做会员级 Bootstrap。
15. 做留一月验证。
16. 生成贡献明细表。
17. 汇总生成门店群主力人群汇总表。
18. 执行验收对账。
```

## 22. 最小计算样例

范围：

```text
2026-04-01 至 2026-06-30
上海
小类：牛肉制品
A 级门店群
```

聚合结果：

| 消费者类型 | 会员数 | 销售额 | 小票数 |
|---|---:|---:|---:|
| 常规时段型-小家庭-中频-价格非敏感 | 3500 | 3400000 | 15000 |
| 上班族晚高峰型-小家庭-中频-价格非敏感 | 3000 | 3200000 | 12000 |
| 捡漏型 | 2000 | 1800000 | 9000 |
| 常规时段型-大家庭-高频-价格敏感 | 1500 | 1600000 | 5000 |

分母：

```text
group_member_cnt = 10000
group_sales_amt = 10000000
group_ticket_cnt = 41000
```

第一类贡献得分：

```text
member_share = 3500 / 10000 = 0.35
sales_share = 3400000 / 10000000 = 0.34
profile_contribution_score =
2 * 0.35 * 0.34 / (0.35 + 0.34) * 100 = 34.49
```

如果 Jenks/BIC 选择 K=2，且高贡献组为：

```text
常规时段型-小家庭-中频-价格非敏感
上班族晚高峰型-小家庭-中频-价格非敏感
```

则：

```text
两个消费者类型 is_main_profile = 1
result_status = SUCCESS
main_member_coverage_rate = (3500 + 3000) / 10000 = 65%
main_sales_coverage_rate = (3400000 + 3200000) / 10000000 = 66%
```
