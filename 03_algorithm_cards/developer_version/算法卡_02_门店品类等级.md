## 1. 算法目标

本算法用于识别同一城市算法区域、同一品类下，不同门店的品类经营承载能力。

输出结果供后续算法读取：

```text
门店群消费者画像贡献算法
目标画像 SKU 表现算法
新品候选方向生成算法
新品机会评分与试点范围选择
```

本算法只回答：

```text
同一城市算法区域、同一品类下，哪些门店更适合承接新品、扩 SKU 和做试点？
```

本算法不做：

```text
全店综合等级
跨品类门店比较
商品订购量预测
独立促销因果分析
独立损耗诊断报告
大模型实时评分
```

正式评估周期：

```text

```

```text

level_end_date = 2026-06-30
```

```text
最近 6 个完整自然月
```

6 个月数据只用于：

```text
CRITIC 小样本回退
```

6 个月不生成第二个正式等级。

更新规则：

```text
每月正式更新一次
同一正式版本在月内保持不变
数据修正可重跑同一版本，但必须保存修正原因
城市算法区域配置变化必须生成新的 scope_version
```

## 6. 有效数据过滤

### 6.1 有效交易

Doris 小票商品明细只保留：

```text
business_date 在计算周期内
store_id 不为空
article_id 不为空
order_status = 'os.completed'
is_return = 0
refund_type 为空
usual_amt > 0
商品可以关联到商品基础表正式品类
```

销售额和小票数统计全量有效消费，不因为 `customer_id` 为空而删除。

### 6.2 有效会员

会员指标复用算法 01 的会员过滤：

```text
customer_id 不为空
customer_id 不以 6 开头
is_customer = 1
剔除退货、取消、冲销、测试和非正交易
同一会员单日有效小票数 > 5 时，剔除该会员当天全部记录
```

### 6.3 有效营业日

有效营业日不是确认“门店知不知道营业”，而是确认算法分母来源。

严格口径：

```text
门店当天正常营业
AND 该门店品类有正式可售条件
AND 当天交易、货盘、进货数据已完整入库
```

V1 默认实现：

```text
门店基础表显示门店营业中
AND 门店商品每日可订可售表中，该门店该品类当天至少 1 个 SKU is_saleable = 1
```

这样可以保留“营业但该品类 0 销售”的日期，避免日均销售、日均小票和动销率被抬高。

仅当门店商品每日可订可售表暂未交付时，才允许降级：

```text
用该门店当天有任一有效销售交易作为有效营业日
business_day_rule_degraded_flag = 1
```

降级风险：

```text
0 销售日会被漏掉，日均指标可能偏高。
```

### 6.4 有效在售 SKU 日

V1 默认实现：

```text
门店商品每日可订可售表 is_saleable = 1
AND 实际进货数量 > 0 或 实际进货重量 > 0
```

当净进货量 `<= 0`：

```text
不计算该 SKU 日售罄率
不计入有效在售 SKU 日
不填 0
不视为未动销
```

售罄异常：

```text
计件商品：pre19_sales_qty / actual_received_qty > 1.10
称重商品：pre19_sales_weight / actual_received_weight > 1.10
=> sell_through_abnormal_flag = 1
```

售罄异常 SKU 日：

```text
不参与订购健康区间训练
不参与订购健康得分
有效交易仍可进入经营规模和商品效率
原始售罄率保留，禁止静默截断为 100%
```

## 8. 通用指标标准化

所有指标都在同一个比较组内标准化。

正向指标：

```text
x_log = ln(1 + x)
M = median(x_log)
MAD = median(|x_log - M|)
robust_z = (x_log - M) / (1.4826 * MAD)
x_score = 100 * Phi(robust_z)
```

可为负指标：

```text
x_log = SIGN(x) * ln(1 + ABS(x))
```

然后继续使用中位数/MAD 标准化。

反向指标：

```text
reverse_score = 100 * [1 - Phi(robust_z)]
```

反向指标包括：

```text
损耗成本率
常规优惠金额率
常规优惠销售占比
时段折扣金额率
时段折扣销售占比
```

异常与兜底：

```text
ABS(robust_z) > 3.5 => extreme_store_flag = 1
```

当 `MAD = 0`：

```text
1. 优先使用同一正式范围、同一品类最近 6 个模型窗口的 MAD。
2. 仍为 0：该指标所有门店记 50 分，CRITIC 信息量记 0。
```

缺失值不能填 0。

## 9. CRITIC 动态赋权

CRITIC 用于计算权重。

公式：

```text
sigma_j = 指标 j 的标准差
r_jk = 指标 j 与指标 k 的相关系数
C_j = sigma_j * SUM_k(1 - r_jk)
w_j = C_j / SUM_j(C_j)
```

业务含义：

```text
门店之间差异越大的指标，权重越高。
和其他指标重复度越低的指标，权重越高。
```

小样本回退顺序：

```text
1. 优先使用当前正式范围、当前品类的有效门店计算。
2. 当前相关矩阵不稳定时，使用同一范围最近 6 个模型窗口估计。
3. 仍不稳定时，使用上一版已发布权重。
4. 无历史权重时使用等权，weight_fallback_flag = 1。
```

V1 默认稳定性参数：

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `min_store_cnt_for_critic` | 10 | 当前比较组有效门店少于 10 家时，不直接用当前组算 CRITIC |
| `min_pairwise_valid_cnt` | 10 | 两个指标共同有效样本少于 10 时，该相关系数不稳定 |
| `min_pairwise_valid_ratio` | 0.60 | 两个指标共同有效样本占组内门店数低于 60% 时，该相关系数不稳定 |
| `critic_random_seed` | 20260723 | 用于抽样复现 |

以上为 V1 开发默认参数，可在上海试跑后由业务和数据开发复盘调整。

使用等权回退时：

```text
confidence_level = LOW
weight_fallback_flag = 1
final_level 最高 B
```

禁止扩大到华东大区计算权重。

## 10. 七个一级维度计算

### 10.1 经营规模

全部使用 19:00 前数据。

原始指标：

```text
daily_pre19_sales_amt = SUM(pre19_sales_amt) / effective_business_days
daily_pre19_ticket_cnt = COUNT(DISTINCT ticket_id where inc_time < 19:00:00) / effective_business_days
valid_member_cnt = COUNT(DISTINCT valid member_id where inc_time < 19:00:00)
```

来源：

| 指标 | 优先来源 | 备用来源 |
|---|---|---|
| 19点前销售额 | 毛利损耗表 `19点前销售额` | Doris `SUM(usual_amt)`，条件 `inc_time < 19:00:00` |
| 19点前小票数 | Doris `COUNT(DISTINCT order_id)` | 无 |
| 19点前有效会员数 | Doris `COUNT(DISTINCT customer_id)`，按有效会员过滤 | 无 |

得分：

```text
三个指标分别做正向稳健标准化。
使用 CRITIC 生成经营规模内部权重。

scale_score = SUM(指标得分 * 内部权重)
```

同时保留但不重复进入得分：

```text
日均有效会员小票数
有效会员销售额
会员销售额占比
会员小票占比
```

### 10.2 货盘宽度

原始指标：

```text
effective_listed_sku_days = COUNT(SKU 日 where 有效在售 SKU 日 = 1)
pre19_active_sku_days = COUNT(有效在售 SKU 日 where 19点前有有效销售)

daily_listed_sku_cnt = effective_listed_sku_days / effective_business_days
daily_pre19_active_sku_cnt = pre19_active_sku_days / effective_business_days
pre19_sku_active_rate = pre19_active_sku_days / effective_listed_sku_days
```

19 点前有有效销售判断：

```text
pre19_sales_amt > 0
OR pre19_sales_qty > 0
OR pre19_sales_weight > 0
```

得分：

```text
daily_listed_sku_cnt
daily_pre19_active_sku_cnt
pre19_sku_active_rate
```

三个指标分别做正向稳健标准化，再用 CRITIC 生成：

```text
assortment_width_score
```

### 10.3 商品效率

原始指标：

```text
sales_per_sku_day = SUM(pre19_sales_amt) / effective_listed_sku_days
profit_per_sku_day = SUM(full_chain_gross_profit_amt) / effective_listed_sku_days
```

得分：

```text
sales_productivity_score：正向稳健标准化
profit_productivity_score：带符号对数 + 正向稳健标准化

sku_efficiency_score =
SQRT(sales_productivity_score * profit_productivity_score)
```

异常处理：

```text
effective_listed_sku_days = 0 时不执行除法
assortment_data_error_flag = 1
sku_efficiency_score = NULL
```

### 10.4 盈利能力

原始指标：

```text
daily_full_chain_profit_amt =
SUM(full_chain_gross_profit_amt) / effective_business_days

store_margin_rate =
SUM(store_gross_profit_amt) / SUM(full_day_sales_amt)
```

得分：

```text
full_chain_profit_score：带符号对数 + 正向稳健标准化
store_margin_score：带符号对数 + 正向稳健标准化

profitability_score =
SQRT(full_chain_profit_score * store_margin_score)
```

负毛利保留，不填 0。

### 10.5 订购健康

订购健康使用 SKU 日样本计算。

计件商品：

```text
quantity_sell_through_rate =
SUM(pre19_sales_qty) / SUM(actual_received_qty)
```

称重商品：

```text
weight_sell_through_rate =
SUM(pre19_sales_weight) / SUM(actual_received_weight)
```

禁止：

```text
公斤和件数直接相加
用到货金额加权原始售罄率
将售罄率静默截断为 100%
```

净经营贡献：

```text
net_operating_contribution =
full_chain_gross_profit_amt - store_loss_cost_amt
```

如果开发确认 `full_chain_gross_profit_amt` 已经包含门店损耗影响，则改为：

```text
net_operating_contribution = full_chain_gross_profit_amt
```

健康区间训练范围：

```text
scope_version
scope_type
scope_id
category_granularity
category_code
measure_type
```

健康区间训练使用最近 6 个完整自然月的有效 SKU 日样本。

分箱规则：

```text
h = 2 * IQR(sell_through_rate) / n^(1/3)
```

样本不足的相邻区间自动合并。

V1 默认参数：

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `min_sell_through_sample_cnt` | 200 | 健康区间训练最小 SKU 日样本数 |
| `min_bin_sample_cnt` | 30 | 单个售罄率区间最小 SKU 日样本数 |
| `candidate_tolerance_percentiles` | P90/P95/P99 | 用于试算最大容忍距离 |

健康区间选择原则来自业务文档：

```text
单位到货净贡献接近历史较优水平
损耗处于相对健康水平
增加到货后净经营贡献不再显著增加
```

开发落地时需要输出以下训练指标，供业务复核：

```text
每个售罄率区间的样本数
每个售罄率区间的单位到货净贡献
每个售罄率区间的损耗成本率
每个售罄率区间的边际净贡献
最终选择的健康区间下限 L
最终选择的健康区间上限 U
最终选择的容忍距离参数
```

健康度得分：

```text
r 在 [L,U]：distance = 0
r < L：distance = L - r
r > U：distance = r - U

sell_through_health_score =
100 * MAX(0, 1 - distance / selected_tolerance_distance)
```

混合计量品类：

```text
combined_sell_through_health_score =
SUM(计量类型健康度 * 该类型有效在售 SKU 天数)
/ SUM(全部计量类型有效在售 SKU 天数)
```

健康区间命中率：

```text
healthy_sku_day_share =
处于健康区间的有效 SKU 天数 / 全部有效到货 SKU 天数

healthy_sku_day_share_score = healthy_sku_day_share * 100
```

最终订购健康：

```text
order_health_score =
SQRT(combined_sell_through_health_score * healthy_sku_day_share_score)
```

如果训练样本不足且没有历史参数：

```text
order_health_score = NULL
missing_dimension = 1
confidence_level 降低
```

### 10.6 促销健康

一期促销健康不是促销因果评估。

它只判断：

```text
门店该品类是否过度依赖常规优惠或时段折扣。
优惠后的经营质量是否仍然健康。
```

方法版本：

```text
promotion_method = TICKET_DISCOUNT_PROXY_V1
```

字段来源：

| 计算内容 | 优先来源 | 字段或公式 |
|---|---|---|
| 实际销售额 | 毛利损耗表 | `销售额` |
| 全日标准销售额 | 毛利损耗表 | `原价销售额` |
| 总优惠金额 | 毛利损耗表 | `总折扣额` / `折扣额`，以全日总优惠金额口径映射 |
| 时段折扣金额 | 毛利损耗表 | `时段折扣额` |
| 常规优惠金额 | 毛利损耗表 | `MAX(total_discount_amt - 时段折扣额, 0)` |
| 19点前标准销售额 | Doris 小票明细 | `SUM(usual_amt + discount_amt)`，条件 `inc_time < 19:00:00` |
| 19点前常规优惠金额 | Doris 小票明细 | `SUM(discount_amt)`，条件 `inc_time < 19:00:00 AND is_hour_promotion <> 1` |
| 时段折扣销售额 | Doris 小票明细 | `SUM(usual_amt + discount_amt)`，条件 `is_hour_promotion = 1` |

重要口径：

```text
Doris hour_discount_amt 是“会员当天同小时累计优惠金额”，不是商品行本次时段折扣金额。
不能直接按商品行 SUM(hour_discount_amt)。
一期时段折扣金额必须优先使用毛利损耗表的“时段折扣额”。
```

促销健康指标：

```text
regular_discount_amt_rate =
SUM(19点前常规优惠金额) / SUM(19点前标准销售额)

regular_discount_sales_ratio =
SUM(19点前有常规优惠的标准销售额) / SUM(19点前标准销售额)

hour_discount_amt_rate =
SUM(时段折扣金额) / SUM(全日标准销售额)

hour_discount_sales_ratio =
SUM(时段折扣销售额) / SUM(全日标准销售额)

discounted_margin_rate =
SUM(有优惠或时段折扣商品的全链路毛利额)
/ SUM(有优惠或时段折扣商品的实际销售额)
```

优惠商品毛利率口径：

```text
优先按 营业日期 + 门店 + 销售商品编码 计算。
如果无法到商品行级，则允许用日门店商品口径近似。
近似时必须输出 discounted_margin_rule_degraded_flag = 1。
```

得分：

```text
regular_discount_amt_rate_score：反向稳健标准化
regular_discount_sales_ratio_score：反向稳健标准化
hour_discount_amt_rate_score：反向稳健标准化
hour_discount_sales_ratio_score：反向稳健标准化
discounted_margin_quality_score：带符号对数 + 正向稳健标准化
```

```text
regular_discount_non_dependency_score =
SQRT(regular_discount_amt_rate_score * regular_discount_sales_ratio_score)

hour_discount_non_dependency_score =
SQRT(hour_discount_amt_rate_score * hour_discount_sales_ratio_score)

promotion_health_score =
GEOMEAN_AVAILABLE(
  regular_discount_non_dependency_score,
  hour_discount_non_dependency_score,
  discounted_margin_quality_score
)
```

无优惠发生：

```text
discounted_margin_rate = NOT_APPLICABLE
优惠依赖类指标按 0 依赖参与评分
promotion_confidence = NORMAL
```

小票优惠字段缺失或标准销售额无法确认：

```text
promotion_health_score = NULL
promotion_confidence = DATA_INSUFFICIENT
综合分按可用维度重算权重
```

### 10.7 损耗健康

正式评分使用损耗成本率：

```text
loss_cost_rate =
SUM(store_loss_cost_amt) / SUM(arrival_cost_amt_tax_included)
```

来源：

| 逻辑字段 | 来源字段 |
|---|---|
| `store_loss_cost_amt` | 毛利损耗表：门店损耗金额，已确认成本口径 |
| `arrival_cost_amt_tax_included` | 门店商品日价格表：出库到店成本含税 |

没有到货成本时降级：

```text
loss_cost_rate =
store_loss_cost_amt / (estimated_sales_cost_amt + store_loss_cost_amt)

loss_cost_rule_degraded_flag = 1
```

得分：

```text
loss_health_score = 100 * [1 - Phi(robust_z)]
```

异常：

```text
store_loss_cost_amt < 0：标记 loss_cost_abnormal_flag = 1，不参与损耗健康评分
arrival_cost_amt_tax_included <= 0：loss_health_score = NULL
```

## 11. 一级维度综合评分

七个一级维度：

```text
scale_score
assortment_width_score
sku_efficiency_score
profitability_score
order_health_score
promotion_health_score
loss_health_score
```

使用 CRITIC 生成一级权重：

```text
W1-W7
SUM(W1...W7) = 1
```

综合分：

```text
category_score =
scale_score * W1
+ assortment_width_score * W2
+ sku_efficiency_score * W3
+ profitability_score * W4
+ order_health_score * W5
+ promotion_health_score * W6
+ loss_health_score * W7
```

某维度为 `NOT_APPLICABLE` 或 `NULL`：

```text
adjusted_w_j = original_w_j / SUM(可用维度原权重)
category_score = SUM(可用维度得分 * adjusted_w_j)
```

禁止将缺失值、不适用值填 0。

## 12. 动态等级生成

对同一比较组的 `category_score` 从低到高排序，尝试：

```text
K = 1, 2, 3, 4
K_max = MIN(4, 综合分去重值数量)
```

Jenks 自然断点：

```text
选择使组内平方误差 SSE_K 最小的连续切分
```

BIC：

```text
BIC(K) = N * ln(SSE_K / N) + K * ln(N)
```

BIC 越小越好，但候选分层必须通过稳定性验证。

当 `SSE_K = 0`：

```text
不执行 ln(0)
在达到 0 的候选中选择 K 更小且通过稳定性验证的分层
```

稳定性验证：

```text
重复抽样次数 = 500
每次抽取有效门店比例 = 80%
同一等级数量出现比例 >= 80%
单门店等级一致率 >= 75%
最近 4 个滚动窗口中，等级数量至少 3 次一致
```

V1 固定随机种子：

```text
random_seed = 20260723
```

未通过稳定性验证时：

```text
4 级 -> 3 级 -> 2 级 -> 1 级
```

等级命名：

| K | 等级 |
|---:|---|
| 4 | A / B / C / D |
| 3 | A / B / C |
| 2 | A / B |
| 1 | 统一 B，`single_level_flag = 1` |

同分规则：

```text
综合分完全相同的门店必须属于同一等级。
禁止用 row_number 强行拆分同分门店。
```

最终等级：

```text
final_level =
APPLY_LEVEL_CAP(
  provisional_level,
  profitability_cap,
  loss_level_cap,
  data_quality_cap,
  weight_fallback_cap
)
```

### 13.1 连续亏损上限

按最近 3 个完整自然月分别计算：

```text
monthly_net_operating_contribution =
monthly_full_chain_gross_profit_amt - monthly_store_loss_cost_amt
```

如果开发确认全链路毛利额已扣门店损耗：

```text
monthly_net_operating_contribution =
monthly_full_chain_gross_profit_amt
```

触发规则：

```text
M1 < 0 AND M2 < 0 AND M3 < 0
=> continuous_loss_3m_flag = 1
=> profitability_cap = B
```

三个月累计亏损但不是每个月都亏损：

```text
cumulative_loss_3m_flag = 1
不触发连续亏损上限
```

### 13.2 严重损耗上限

训练样本粒度：

```text
scope_version
scope_type
scope_id
store_id
category_granularity
category_code
natural_month
```

定义：

```text
x = loss_cost_rate
y = net_operating_contribution_rate
w = arrival_cost_amt_tax_included
```

使用单调递减 Isotonic Regression：

```text
最小化 SUM_i[w_i * (y_i - g(x_i))^2]
约束 x_a < x_b 时，g(x_a) >= g(x_b)
```

严重损耗风险线：

```text
loss_break_even_threshold = INF{x : g(x) <= 0}
```

候选触发规则：

```text
最近 3 个月至少 1 个月超过风险线
最近 3 个月至少 2 个月超过风险线
最近 3 个月 3 个月全部超过风险线
```

通过下一月亏损识别的准确率、召回率、误报率和跨期稳定性选择：

```text
loss_trigger_month_count
```

触发后：

```text
severe_loss_flag = 1
loss_level_cap = B
```

V1 默认参数：

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `min_loss_training_month_cnt` | 6 | 损耗风险线最少历史月份 |
| `min_loss_training_sample_cnt` | 100 | 损耗风险线最少门店品类月样本数 |

如果历史曲线没有穿越 0、始终低于 0、样本不足或阈值不稳定：

```text
不发布损耗等级上限
只保留 loss_health_score 和 loss_threshold_unstable_flag
```

### 13.3 数据与权重回退上限

六个核心维度：

```text
经营规模
货盘宽度
商品效率
盈利能力
订购健康
损耗健康
```

规则：

```text

六个核心维度缺失 >= 2 个：不生成正式等级，进入数据修复清单
门店、品类、交易基础映射缺失：NOT_CALCULABLE
```

第一期促销健康特殊规则：

```text

```

## 16. 调度与写入

调度周期：

```text
每月一次正式计算
建议在上月完整数据全部入库后运行
```

写入方式：

```text
1. 按 level_end_date 分区。
2. 同一 model_version + scope_version + level_end_date 可重跑覆盖。
3. 不同 model_version 或 scope_version 必须保留历史结果。
4. 重跑必须记录 rerun_reason。
```

## 17. 验收规则

### 17.1 数据完整性

```text
正式结果唯一键重复数 = 0
门店基础表匹配率 >= 99%
商品基础表品类匹配率 >= 99%
城市算法区域匹配率 = 100%
大类、中类、小类均从底层重新聚合
缺失值未填 0
```

### 17.2 计算口径

```text
19 点前口径严格使用 inc_time < 19:00:00
净进货量 <= 0 的 SKU 日不进入有效在售 SKU 天
售罄率 > 110% 的 SKU 日被标记且不参与订购健康训练
原始售罄率未被截断为 100%
hour_discount_amt 未被直接按商品行求和
损耗金额使用成本口径
```

### 17.3 开发对数

抽取至少 10 个门店品类样例，对以下内容逐字段对数：

```text
输入明细
有效过滤结果
门店品类聚合指标
标准化参数
CRITIC 权重
七个维度得分
综合分
Jenks/BIC 阈值
暂定等级
最终等级
等级调整原因
```

计算误差要求：

```text
金额类误差 <= 0.01
比例类误差 <= 0.000001
等级结果 100% 一致
```

### 17.4 稳定性

```text
重复抽样 500 次
等级数量一致率 >= 80%
单门店等级一致率 >= 75%
最近 4 个滚动窗口至少 3 次选择相同等级数量
```

### 17.5 业务验收

按城市算法区域、品类、等级和置信度分层抽取不少于 100 个门店品类结果。

业务重点看：

```text
高等级门店是否符合经营认知
高销售但低毛利、高损耗门店是否被过度高估
售罄过高是否被解释为订购不足风险
高优惠依赖门店是否被识别
连续亏损门店是否被限制最高等级
等级变化是否能由经营变化、范围版本或参数版本解释
```

## 18. 开发前确认项

| 确认项 | 确认对象 | 默认处理 |
|---|---|---|
| `full_chain_gross_profit_amt` 是否已经扣过门店损耗 | 数据开发 / 财务口径负责人 | 未确认前默认 `全链路毛利额 - 门店损耗金额` |
| 优惠商品毛利率能否按营业日期 + 门店 + 销售商品编码计算 | 数据开发 | 不能到商品行时，用日门店商品近似，并打降级标记 |
| 有效营业日是否能由可订可售表覆盖 0 销售日 | 数据开发 | 优先用可订可售表；缺表时降级为有销售日期 |
| 日期日历表是否可提供节假日、异常日期 | 数据开发 / 业务 | 缺失时相似经营日只按星期类型和月份近似 |
| 19点前销售重量是否可由毛利损耗表直接提供 | 数据开发 | 缺失时由 Doris 小票 `SUM(weight)` 计算 |
| 进货重量是否可直接提供 | 数据开发 | 缺失时需确认能否由进货数量和单位重量换算 |
| Jenks、CRITIC、Isotonic Regression 实现方式 | 数据开发 | 优先 Python/调度任务；如仅 SQL，需要评审降级实现 |
| V1 默认参数是否接受 | 业务 / 数据开发 | 上海试跑后复盘调整 |

## 19. 不能做的事

```text
不能按全店销售额给门店评级
不能跨未配置的城市算法区域比较
不能跨品类比较门店等级
不能平均下一级品类等级得到上一级等级
不能使用固定 0.35 等旧权重

不能使用普通 Min-Max 替代稳健标准化
不能把缺失值或不适用值填 0

不能直接 SUM Doris 的 hour_discount_amt 当作商品行时段折扣金额
不能把促销健康解释为促销因果效果
不能只输出最终等级而不保存中间指标、参数和调整原因
不能用大模型生成门店品类等级
```
