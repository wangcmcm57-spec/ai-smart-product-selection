更新时间：2026-08-04

业务原始依据：`01_source_docs/business_algorithm_docs/算法卡_05_目标画像商品价格带.md`

开发交付定位：本卡是数据开发落地算法 05 的主交付文档。业务原文不修改，原文逐章承接见 `00_project_management/business_confirmations/source_traceability/算法05_目标画像商品价格带_业务原文承接矩阵.md`。

## 1. 算法目标

算法 05 用于计算目标画像商品价格带，并判断候选商品在成本、毛利和竞对价格约束下是否具备价格可行性。

核心问题：

```text
在同一城市算法区域、同一品类、同一门店等级群、同一消费者画像下：
1. 目标消费者的 19:30 前非促销自然成交价格带在哪里？
2. 19:30 前促销价格和 19:30 后时段折扣价格分别是什么表现？
3. 商品属性是否存在稳定溢价？
4. 候选商品成本和目标毛利能否落入消费者价格带？
5. 竞对同款或高度相似品价格是否支持或提示风险？
```

本算法不直接决定商品是否最终开发。算法 05 输出价格、成本和竞对证据，下游仍需结合历史差销、当前货盘、风险门禁和开发资源编排。

整体计算顺序是：

```text
内部价格带预计算
-> 候选商品价格可行性
-> 竞对价格验证补算
```

| 表名 | 一行粒度 | 说明 |

### 2.1 运行流程和表关系

算法 05 开发时必须拆成三段交付，不能理解成前端查询时实时从小票临时计算。

第一段：离线批量预计算内部价格带。

```text
触发：每月正式调度，或上游算法 01-04 正式版本变化后重跑。
输入：算法 01-04 正式结果 + 小票 + 商品 + 毛利损耗 + 到货/可订可售 + 城市算法区域等。
输出：
mart_target_profile_price_band
mart_product_attribute_price_premium
mart_target_profile_time_discount_curve
mart_price_band_stability_audit
```

这一段不需要候选新品，也不依赖采购前端查询。

第二段：候选商品价格可行性计算。

```text
触发：系统候选商品记录、候选成本估算版本、公司毛利配置版本或价格点规则版本变化。
输入：第一段已经沉淀的内部价格带 + 系统候选商品记录 + 候选成本估算结果 + `dim_company_margin_target_config` + `dim_price_point_rule_config`。
输出：
mart_candidate_product_price_feasibility
```

这一段只负责候选价格、成本和毛利是否可行。
candidate_product_id、candidate_spec_version、candidate_cost_version 不是 05 生成的；它们来自系统候选商品记录和候选成本估算结果。

第三段：竞对价格验证补算。

```text
触发：算法 07 输出竞对证据表，或竞品快照更新后重跑。
输入：第二段的建议零售价 + 算法 07 的竞对证据列表 `competitor_channel_evidence` + `dim_competitor_sku` + `fact_competitor_sku_daily_snapshot`。
输出：
mart_competitor_price_validation_result
```

这一段先用算法 07 解决“比谁”，再用竞品快照解决“价格是多少”，最后由 05 计算 `competitor_price_index` 和 `competitor_validation_status`。

07 传给 05 的不是逐行价格验证结果，而是证据列表和代表竞品 ID 列表：

```text
representative_competitor_ids
representative_competitor_names
evidence_metric_type
competitor_similarity_version
```

05 先把 `representative_competitor_ids` 拆成逐 `competitor_sku_id` 明细，再 join 竞品基础表和每日快照表取价格。
`evidence_metric_type` 作为 05 的 `match_type` 来源，`competitor_similarity_version` 作为 05 的 `match_model_version` 来源。
映射关系固定为：`EXACT_EQUIVALENT -> EXACT`，`BUSINESS_HIGH_SIMILAR -> HIGHLY_SIMILAR`，`ATTRIBUTE_PENETRATION -> CATEGORY_REFERENCE`；没有代表竞品 ID 或无法生成有效快照时写 `NO_MATCH`。
`match_confidence` 和 `match_evidence_json` 由 05 根据 07 的证据覆盖率、价格快照和可追溯性生成，不直接抄 07 的聚合字段。

采购前端只传入城市、消费者画像、品类、门店群等查询条件，读取已计算结果。前端筛选条件不是候选商品、规格和成本事实输入。

### 4.6 促销与调价明细

业务原文要求将自然价、促销价和 19:30 后时段折扣价分开。V1 已确认不接入正式促销活动表或调价明细表，按小票实际折扣做价格流分流，业务接受 `DISCOUNT_PROXY_V1`。

开发范围：

```text
1. 不新增促销活动表作为算法 05 V1 输入。
2. 不要求开发补商品级促销规则 ID、价格规则 ID 或调价生效明细。
3. 业务原文中的理想促销/调价口径只在承接矩阵中保留，不进入 V1 开发表字段。
4. 如果后续接入正式促销/调价明细，生成新的 promotion_rule_version / pricing_rule_version 后重算，不覆盖 V1 历史结果。
```

V1 分流口径：

```text
promotion_identify_method = DISCOUNT_PROXY_V1
pricing_rule_status = DISCOUNT_PROXY_V1_CONFIRMED

19:30 前促销代理：
sale_time < '19:30:00'
AND discount_amt > 0

19:30 后时段折扣代理：
sale_time >= '19:30:00'
AND (is_hour_promotion = 1 OR discount_amt > 0)

19:30 前自然代理：
sale_time < '19:30:00'
AND COALESCE(discount_amt,0) <= 0
AND COALESCE(is_hour_promotion,0) = 0
```

`hour_discount_amt` 不能按商品行直接求和，只能作为时段优惠辅助判断。金额校验优先使用毛利损耗表的促销折扣额、会员折扣额、时段折扣额。

### 7.1 标准单位价

```text

```

```text
standard_pricing_unit：标准计价单位
```

### 7.2 可比商品组

V1 已确认：不新增额外可比商品组配置表。

当前状态：

```text
开发按商品基础表 + 业务原文强匹配规则自动生成可比商品组。
业务已确认小分类维度足够细，可作为首要边界。
```

开发执行步骤：

```text
1. 读取商品基础表，取得交易商品编码、商品名称、三级品类编码、三级品类名称、SPU 名称、规格、销售单位、单位重量等字段。
2. 生成商品属性字段：
   category_level3_code = `dim_sku.category_level3_code`
   main_ingredient = 从商品名称 / SPU 名称 / 三级品类名称中识别主材料
   product_form = 从商品名称 / 规格中识别商品形态，如丝、片、粒、丸、整只、袋装、盒装
   processing_method / cooking_method = 从二级品类名称 / 三级品类名称 / 商品名称中识别即食、即烹、冷冻、腌制等
   measurement_type = 根据 `dim_sku.sale_unit` 识别 WEIGHT / QUANTITY / PIECE_COUNT / VOLUME
   net_content = 从 `dim_sku.specification` 或 `dim_sku.unit_weight_kg` 中识别净含量、枚数、件数等
3. 先生成基础可比商品组：
   comparable_product_group_id = HASH(category_level3_code, main_ingredient, product_form, processing_method/cooking_method, measurement_type)
4. 在同一个可比商品组内，再用 net_content 生成 specification_segment_id。
5. 最终价格带计算粒度同时包含 comparable_product_group_id 和 specification_segment_id。
```

规则来源字段：

```text
comparable_group_rule_source = SKU_BASE_RULE_V1
```

强匹配字段：

```text
category_level3_code
main_ingredient
product_form
processing_method / cooking_method
measurement_type
specification_segment_id
```

溢价属性：

```text
functional_attribute
flavor
brand_name
package_type
freshness_attribute
```

强匹配字段缺失时：

```text

evidence_status = HIERARCHICAL_ESTIMATE 或 DATA_ABNORMAL
```

具体降级取决于是否仍能在上级可比组内形成稳定价格带。

### 7.3 规格段

净含量对数：

```text
z_i = ln(net_content_i)
```

在同一可比商品组内，对 `K = 1..min(4, 有效不同规格数)` 运行加权 Jenks：

```text
SSE_K = SUM_i w_i * (z_i - mean_cluster(i))^2

n_eff = (SUM_i w_i)^2 / SUM_i(w_i^2)

BIC_K = n_eff * ln(SSE_K / n_eff) + K * ln(n_eff)
```

选择 `BIC_K` 最小的 K。

输出：

```text
specification_segment_id
spec_segment_lower
spec_segment_upper
spec_segment_method = JENKS_BIC
```

### 7.4 两套权重

会员平衡权重：

```text
w_member(m,t) = 1 / n_m
SUM_t w_member(m,t) = 1
```

`n_m` 是会员 m 在周期内、同一计算范围和可比商品组内的有效购买机会数。同一小票同一 SKU 多行先合并。

经营成交权重：

```text
w_operation(i) = sales_standard_qty_i
```

两套权重分别计算 KDE、价格带、密度峰和稳定性，不得混用。

### 7.5 异常价格

事实异常直接排除：

```text
standard_unit_price <= 0
line_transaction_amt <= 0
sales_standard_qty <= 0
UNIT_CONVERSION_ERROR
PRODUCT_MASTER_CONFLICT
OVERSELL_ABNORMAL
```

可解释低价：

```text
19:30 后符合时段调价 -> 进入时段折扣流
19:30 前有正式促销或 V1 促销代理 -> 进入促销流
```

统计异常：

在同一可比商品组和规格段内，对 `ln(standard_unit_price)` 使用中位数/MAD 标记：

```text
STATISTICAL_PRICE_OUTLIER
```

再交叉核验：

```text
商品基础表原价
促销/调价规则
小票行金额
商品规格
计量单位
```

仍无法解释才从正式分布排除。不得 winsorize。

### 7.6 加权 KDE 价格带

密度函数：

```text
f_h(p)
= 1 / (h * SUM_i w_i)
  * SUM_i [w_i * K((p-p_i)/h)]
```

`K` 使用高斯核。

带宽选择：

```text
h_star = argmax_h SUM_i w_i * ln(f_{-i,h}(p_i))
```

多峰处理：

```text
密度峰值 -> 价格中心
相邻峰之间密度谷值 -> 自然边界
会员平衡概率质量最大的连续区间 -> 主接受价格带
其他稳定峰 -> 次接受价格带
```

单峰处理：

```text
对每个累计权重 q，求包含峰值的最短连续区间 I(q)
W(q) = width(I(q))
选择覆盖权重增加和区间宽度扩张曲线的最大曲率拐点
```

离散处理：

| 状态 | 条件 | 输出 |
|---|---|---|
| `SINGLE_PRICE_POINT` | 有效成交价格完全相同 | 核心和扩展价格带均为该价格点 |
| `DISCRETE_PRICE_DISTRIBUTION` | 价格点少，不足以连续 KDE | 保留加权离散价格分布 |

### 7.7 19:30 前需求支撑

只使用 19:30 前非促销有效 SKU 日：

```text
price_segment_pre1930_sell_through
= SUM(该价格段 19:30 前标准销售量)
  / SUM(对应门店 SKU 日实际到货标准量)
```

字段来源：

```text
分子 pre1930_natural_sales_standard_qty：
由 Doris 小票明细按 sale_time < '19:30:00' 且进入自然价格流的记录 SUM(weight) 计算。

分母 actual_arrival_standard_qty：
WEIGHT 商品取 `mart_sku_margin_loss.receipt_weight_kg`；
QUANTITY / PIECE_COUNT 商品取 `mart_sku_margin_loss.receipt_qty`。
```

禁止：

```text
AVG(单日 SKU 售罄率)
```

低到货量收缩：

按件或枚数：

```text
posterior_mean
= (sold_before_1930 + alpha_group)
  / (actual_arrival + alpha_group + beta_group)
```

`alpha_group`、`beta_group` 由同城市群、同可比商品组历史数据最大似然估计。

称重/体积商品使用分层 Beta 回归，到货暴露作为精度权重。

输出：

```text
pre1930_sell_through_raw
pre1930_sell_through_shrunk
sell_through_interval_lower
sell_through_interval_upper
valid_store_cnt
valid_store_sku_day_cnt
actual_arrival_exposure
local_evidence_weight
```

### 7.8 属性溢价

建模记录：

```text
customer_id + order_id + sku_id + business_date
```

模型：

```text
ln(standard_unit_price_i)
= alpha
+ beta_spec * ln(net_content_i)
+ SUM_a beta_a * attribute_{i,a}
+ city_effect
+ store_group_effect
+ week_effect
+ error_i
```

加权估计：

```text
beta_hat = (X' W X)^(-1) X' W y
```

溢价：

```text
single_attribute_premium = exp(beta_a)-1
combined_attribute_premium = exp(SUM beta_a + identifiable_interactions)-1
```

分层收缩：

```text
beta_shrunk(g,a)
= lambda(g,a) * beta_raw(g,a)
  + (1-lambda(g,a)) * beta_parent(a)

lambda(g,a)
= tau_a^2 / (tau_a^2 + SE(g,a)^2)
```

95% 区间：

```text
premium_interval_95
= [exp(beta_lower)-1, exp(beta_upper)-1]
```

属性可使用条件：

```text
属性在可比组内存在变化
设计矩阵可识别
置信区间和后验方向明确
删除月份和门店后方向不反转
会员平衡模型与经营成交模型不存在无法解释的方向冲突
```

属性缺失处理：

```text
UNKNOWN 保留为 UNKNOWN
不用众数填补
三模型敏感性验证：已知记录模型 / 不加属性模型 / UNKNOWN 独立类别模型
完全绑定只能输出组合溢价
```

### 7.9 目标毛利率

可比商品历史全链路毛利率：

```text
sku_full_chain_margin_rate
= SUM(full_link_margin_amt) / SUM(sales_amt)
```

字段映射：

```text
full_link_margin_amt = mart_sku_margin_loss.full_link_margin_amt
sales_amt = mart_sku_margin_loss.sales_amt
```

小规模 SKU 收缩：

```text
margin_shrunk_sku
= lambda_sku * margin_raw_sku
  + (1-lambda_sku) * margin_group
```

对收缩后毛利率做销售额加权 KDE：

```text
data_margin_floor = 稳定正毛利健康群与低毛利群之间的自然谷值
data_margin_target = 稳定正毛利健康群的密度峰值
```

```text

= max(data_margin_floor, company_margin_floor)

final_margin_target
= max(data_margin_target, company_margin_target)
```

### 7.10 候选商品成本交集

全链路成本：

```text
full_chain_unit_cost
= main_material_estimated_cost
+ packaging_estimated_cost
+ optional_other_attributable_estimated_cost
```

V1 中：

```text
candidate_cost_method = COST_ESTIMATE_V1
```

如果后续接入真实报价，需要扩展候选成本估算数据合同并生成新的 `candidate_cost_version`，不得覆盖历史估算版本。

毛利可行售价：

```text
minimum_floor_price
= full_chain_unit_cost / (1-final_margin_floor)

minimum_target_price
= full_chain_unit_cost / (1-final_margin_target)
```

消费者价格带求交：

```text
target_core_intersection
= [core_lower, core_upper]
  INTERSECT [minimum_target_price, +infinity)

floor_core_intersection
= [core_lower, core_upper]
  INTERSECT [minimum_floor_price, +infinity)
```

扩展价格带同理。

反向成本上限：

```text
cost_ceiling_at_price(P, G) = P * (1-G)
```

建议价选择：

```text
feasible_price_points
= 消费者核心或允许试点的扩展价格带
  INTERSECT 满足目标毛利或毛利底线的价格区间
  INTERSECT 品类价格尾数规则生成的可执行价格点

P_star
= argmax_{P in feasible_price_points} member_balanced_density(P)
```

`P_star` 必须位于需求支持未失效的价格段。

### 7.12 19:30 后折扣曲线

### 7.13 样本不足和分层借数

## 9. 调度周期

| 任务 | 周期 | 说明 |
|---|---|---|
| 内部价格带计算 | 每月正式更新 | 使用最近 3 个完整自然月 |

## 10. 缺失值和不适用处理

| 场景 | 输出状态 | 处理 |
|---|---|---|
| 无候选商品成本估算结果 | `SOURCE_MISSING` | 只输出内部价格带，不输出完整候选可行性 |
| 促销/调价正式明细缺失 | `DISCOUNT_PROXY_V1` / `DISCOUNT_PROXY_V1_CONFIRMED` | V1 已确认用 Doris 小票实际折扣做代理，保留代理标记 |
| 商品属性缺失 | `ATTRIBUTE_INCOMPLETE` / `UNKNOWN` | 不强填；影响可比组或属性溢价 |
| 属性完全绑定 | `BUNDLED_ATTRIBUTE_NOT_IDENTIFIABLE` | 只输出组合溢价，不输出伪独立系数 |
| 竞对无同款或高相似 | `NO_COMPARABLE_COMPETITOR` | 不用普通品类价格冒充 |
| 竞对数据过期或无效 | `COMPETITOR_DATA_STALE_OR_INVALID` | 不进入竞对正式验证 |
| 内部本地样本不足 | `HIERARCHICAL_ESTIMATE` | 分层借数，并输出本地证据权重 |
| 单位无法转换 | `UNIT_CONVERSION_ERROR` | 不进入正式价格带 |
| 超卖异常 | `OVERSELL_ABNORMAL` | 不进入正式价格带和需求验证 |

不能把缺失、不适用、异常写成 0。

## 11. 验收样例

### 11.1 案例 A：可进入开发

输入条件：

```text
会员平衡核心价格带：16.80-18.40 元/份
会员密度峰值：17.90 元/份
扩展价格带：15.90-19.20 元/份
最终毛利底线：22%
最终目标毛利：25%
全链路成本：13.10 元
```

复算：

```text
毛利底线最低售价 = 13.10 / 78% = 16.79
目标毛利最低售价 = 13.10 / 75% = 17.47
目标毛利与核心价格带交集 = 17.47-18.40
建议零售价 = 17.90
成本谈判上限 = 17.90 * 75% = 13.43
```

期望输出：

```text
evidence_status = LOCAL_OBSERVED
margin_position_status = TARGET_MARGIN_IN_CORE
stability_status = STABLE
development_action = READY_FOR_DEVELOPMENT
```

### 11.2 案例 B：成本与价格带无交集

输入条件：

```text
扩展价格带上限：19.20 元
全链路成本：15.20 元
最终毛利底线：22%
最终目标毛利：25%
```

复算：

```text
毛利底线最低售价 = 15.20 / 78% = 19.49
目标毛利最低售价 = 15.20 / 75% = 20.27
19.49 > 19.20
```

期望输出：

```text
margin_position_status = NO_FLOOR_INTERSECTION
development_action = REDESIGN_REQUIRED
```

### 11.3 案例 C：本地证据少且属性不可拆

输入条件：

```text
本地数据贡献 lambda = 34%
上级参考贡献 = 66%
本地价格中心 = 16.20
上级校正后价格中心 = 16.80
```

复算：

```text
收缩后中心 = 34% * 16.20 + 66% * 16.80 = 16.60
```

期望输出：

```text
evidence_status = HIERARCHICAL_ESTIMATE
identifiability_status = BUNDLED_ATTRIBUTE_NOT_IDENTIFIABLE
development_action = CAUTIOUS_PILOT
```

## 12. 数据质量验收

| 验收项 | 通过标准 |

| 主键唯一 | 6 张正式表主键重复数为 0 |

| KDE 复算 | 抽样可复算带宽、峰值、谷值和核心价格带 |

## 13. 不能做的事

```text
不能将自然、促销和 19:30 后折扣价混成一个价格带
不能遗漏 19:30 整点生效价格和成交
不能用固定 P25-P75 代替真实多峰价格分布
不能将超低清货价当成新品自然定价
不能把一件到货、一件售出的 100% 直接当成强需求
不能使用库存口径替代实际到货
不能将超卖比率截断为 100%
不能把两个商品的简单均价差全部解释为功能属性溢价
不能用众数强行填补未知包装或其他属性
不能在属性完全绑定时伪造独立属性系数
不能在商品名称中加入没有系数或未标记的价值属性
不能用更大区域价格直接替代城市群正式结果
不能在成本与扩展价格带无交集时强行推荐
不能因竞对售价更高就越过内部消费者价格上限
不能在竞对无销量时声称竞对消费者接受某价格
不能用普通品类竞对商品冒充同款或高度相似品
不能将 19:30 后折扣接受曲线直接解释为价格弹性
不能让价格算法跳过历史差销和当前货盘相似品硬过滤
```
