# 算法07_竞品与全球外部趋势新品发现_业务解读版

更新时间：2026-08-10

业务原始依据：`01_source_docs/business_algorithm_docs/算法卡_07_竞品与全球外部趋势新品发现.md`

## 1. 先用一句话理解

这个算法要判断：

```text
外部市场有没有已经出现的商品、属性或趋势；
这些外部信号能不能和我们的内部需求、门店等级、消费者画像、价格带接上；
如果能接上，再把它变成可追溯的外部新品候选，交给算法 09 合并。
```

它不是“外面火什么就推荐什么”。

更简单地说，算法 07 做三件事：

```text
1. 看外部：
   竞品、社媒、行业、法规、新闻里有没有真实商品或真实趋势。

2. 对内部：
   这个外部商品或趋势能不能落回我们的内部小分类、目标画像、门店等级和价格带。

3. 出候选：
   如果外部证据和内部适配都成立，输出外部新品候选；
   如果只看到外部信号但内部不成立，只保留证据，不推荐开发。
```

V1 第一版先不要把它想得太大。

当前 V1 应该分成两层外部数据一起用，不是二选一：

```text
第一层：久谦竞品数据
用来提供较结构化的竞品商品、价格、规格、平台、城市、图片和快照信息。

第二层：10 个公开或可授权外部源
用官方价量源看价格和供需变化；
用零售 SKU / POS 源看外部商品形态、规格、价格和图片；
用行业文章源看新品卖点、工艺、消费场景和供应链线索；
```

两层数据合在一起，算法 07 才能判断：

```text
外部有没有同款或高相似竞品；
外部商品规格和价格大概在哪里；
原料/品类价格和供需有没有变化；
外部文章里有没有新品卖点、工艺和场景线索；
这些外部信号能不能和内部品类、主体商品、价格带接上。
```

完整 07 理想能力还包括真实社媒口碑、Social NPS Proxy、完整全球扩散和法规自动判断。

但这些不是 V1 已经具备的能力。

V1 已接入的久谦和 10 个外部源，可以证明：

```text
外部有没有商品；
外部有没有价格、规格、图片；
外部有没有官方价量、供需变化；
外部有没有行业文章、品牌案例、卖点和供应链线索。
```

但这些来源不能完整证明：

```text
消费者真实买后是否推荐；
自然社媒口碑是正向、中立还是负向；
某个趋势是否已经形成真实用户口碑。
```

所以 V1 不计算正式 Social NPS Proxy。
相关字段保留为空，并写明 `V1_NOT_CALCULATED`，不能填 0。

一个例子：

```text
外部先发现 Omega-3 鲜鸡蛋 12 枚。

V1 可以用久谦判断：
外部竞品平台里是否有类似商品、规格价格如何、是否有图片、能否落回鲜鸡蛋小分类。

V1 可以用 KSP-POS、7-ELEVEN 台湾、HKTVmall 等来源判断：
外部是否有类似商品、规格价格如何、是否有图片、能否落回鲜鸡蛋小分类。

V1 可以用 Foodaily / FoodTalks、红餐 / 新华网食品判断：
外部文章里是否出现 Omega-3、功能蛋、营养功能等卖点和行业线索。

但如果没有接入真实社媒内容：
算法 07 不能计算真实使用口碑和 Social NPS Proxy。
这不是因为 10 个外部源数量不够，而是因为当前来源类型不是“真实消费者口碑源”。
所以 V1 只能写 V1 暂不计算，不能把文章热度、商品榜单或竞品价格当成口碑推荐。

如果没有接入完整法规/标准源：
算法 07 只能传递已观察到的风险线索，不能替代算法 08 做完整风险门禁。

算法 07 不能直接说“中国已经流行 Omega-3 鸡蛋”。
它只能说“在已接入市场和已接入来源中观察到外部证据”。
只有外部证据可追溯、内部需求成立、价格可行、风险线索可传递后，
输出“外部新品候选”，再交给算法 09、08、10 继续处理。
```

## 2. 最终会输出什么

算法 07 正式输出 9 张结果表。

先不用被 9 张表吓到。

对业务和产品来说，算法 07 最终真正要给后续算法的是一批“外部新品候选”：

```text
这个外部商品或趋势叫什么；
它来自哪个外部来源；
它应该落到我们哪个内部小分类；
它像不像已有竞品或内部候选；
它在外部市场有没有价格、规格、图片、供需、行业文章等证据；
它能不能接上算法 02 的门店等级、算法 03 的目标画像、算法 04 的主体需求、算法 05 的价格带；
它有没有法规、标签、食品安全或宣传声称风险线索，需要交给算法 08 判断。
```

所以最终业务看到的不是“外部热词列表”，而是类似这样的候选：

```text
候选商品：Omega-3 鲜鸡蛋 12 枚
内部小分类：鲜鸡蛋
外部来源：日本 POS 新品榜、台湾零售 SKU、行业文章、久谦竞品数据
外部证据状态：海外领先探索 / 正式增长趋势 / 原始外部信号等
内部适配状态：目标画像是否支持、门店等级是否支持、价格带是否可行
风险线索：是否存在功能声称、标签合规、食品安全等需要算法 08 门禁判断的问题
下一步：交给算法 09 做候选标准化和合并，再交给算法 08 做风险门禁
```

| 表 | 一行代表什么 | 用途 |
|---|---|---|
| `external_trend_run` | 一次算法 07 正式运行 | 保存运行周期、版本、来源快照和运行状态 |
| `external_attribute_mapping` | 一个外部词、外文词或趋势词映射到一个标准属性 | 解决 Omega-3、欧米伽3、オメガ3 这类多语种同义问题 |
| `competitor_channel_evidence` | 一个候选在某市场、某渠道里的竞品证据 | 保存同款、高相似、趋势属性渠道渗透和价格位置 |
| `social_trend_evidence` | 一个候选属性在社媒里的趋势和口碑证据 | 完整能力保存去重文档渗透、账号覆盖、Social NPS Proxy 和属性情绪；V1 没有真实社媒源时字段保留为空并标记暂不计算 |
| `industry_external_evidence` | 一条行业、法规、标准、报告或新闻证据 | 保存可追溯结论、来源级别和时效 |
| `external_trend_state` | 一个标准候选在外部市场的趋势状态 | 判断探索、增长、成熟、下降、季节回归或跨市场扩散 |
| `external_candidate_internal_fit` | 一个外部候选落回内部范围后的适配结果 | 判断内部主体需求、目标画像、门店等级和价格是否支持 |
| `external_candidate_image` | 一张可展示或不可展示的候选图片 | 保存图片来源、匹配状态、授权状态和回退等级 |
| `external_new_product_candidate` | 一个外部新品候选最终结果 | 产品默认读取，交给算法 09 做标准化合并 |

最重要的是区分三类结果：

```text
外部信号：
外面出现了某个商品、属性或趋势，但还不能说明内部可做。

外部正式趋势：
外部证据通过可用来源、趋势、渠道渗透和贝叶斯 FDR 校验。
完整能力会加入社媒口碑，V1 不加入正式 Social NPS Proxy。

外部新品候选：
外部趋势已经落回内部小分类、主体需求、消费者画像和价格可行性。
```

所以：

```text
外部正式趋势 != 内部马上推荐新品
外部无观测 != 趋势为 0
海外强趋势 != 国内已经流行
竞品图 != 我们候选商品实物图
```

## 3. 它在 AI 选品链路中的位置

```text
算法 01：会员画像
        ↓
算法 02：门店品类等级
        ↓
算法 03：门店群消费者画像贡献
        ↓
内部证据侧：算法 04 / 05 / 06
外部证据侧：算法 07
        ↓
算法 09：新品候选标准化与合并
        ↓
算法 08：新品机会证据合成与风险门禁
        ↓
算法 10：新品推荐优先级与开发需求编排
```

算法 06 和算法 07 不是强上下游关系。

```text
算法 06 是内部购物篮证据：
从我们自己的小票里找配方、搭配、场景机会。

算法 07 是外部市场证据：
从竞品、官方价量、供需、零售 SKU、POS 新品榜、行业文章和新闻里找外部商品和趋势证据。
后续接入真实社媒后，再补口碑证据。

它们通常在算法 09 汇合：
06 产出的内部候选 + 07 产出的外部候选
-> 算法 09 标准化、去重、合并
-> 算法 08 风险门禁
-> 算法 10 排序和开发编排
```

算法 07 自己有两条发现路径：

```text
路径 A：内部候选外部验证
算法 04/06 已经产生内部候选，比如“青椒黑椒牛柳丝 200g”。
算法 07 去外部看竞品、零售 SKU、POS 新品榜、价量和行业文章里有没有同款、高相似、卖点、痛点或价格证据。

路径 B：外部发现内部匹配
外部先出现新品趋势，比如“Omega-3 鲜鸡蛋 12 枚”。
算法 07 先判断它应该落到内部哪个小分类，再检查算法 02、03、04、05 是否支持。
```

这里先解释“小分类映射”，是因为算法 07 的外部数据都来自公司外部。
外部平台不会使用我们自己的商品分类，所以外部商品进来以后，必须先回答：

```text
这个外部商品，放到钱大妈自己的哪个小分类里才合理？
```

这里的小分类，指的是商品基础表里最末级、最具体的商品分类。
业务原文里的“叶子小分类”，在本项目里可以理解成这个“小分类”。

这个映射不是让开发凭感觉判断，而是用外部商品信息和内部商品基础表做匹配：

```text
外部商品名、原始品类、品牌、规格、主材料、商品形态、加工方式、功能属性
-> 匹配内部商品基础表中的小分类、主体商品和属性
-> 匹配可靠才进入后续计算
-> 匹配不可靠就保留证据，状态写 CATEGORY_MAPPING_GAP
```

如果没有这一步，算法会出现很危险的误判：

```text
把 Omega-3 鲜鸡蛋错放到保健品；
把黑椒牛肉意大利面错当成黑椒牛柳丝；
把早餐场景商品错拼成鸡蛋新品属性。
```

例如：

```text
Omega-3 鲜鸡蛋 12 枚
-> 主体商品是鲜鸡蛋
-> 功能属性是 Omega-3
-> 小分类应落到鲜鸡蛋，而不是乳制品或保健品
```

如果两条路径都成立，输出：

```text
INTERNAL_EXTERNAL_CONVERGED
```

含义是：

```text
内部有真实需求证据，
外部也有竞品或趋势证据，
但两条证据链都要保留，不能互相覆盖。
```

实际运行时：

```text
每日：采集外部数据，保存原始返回和快照。
每周：可做外部趋势预警，但不覆盖正式月度候选。
每月：冻结正式版本，和内部算法 02-06 的正式版本对齐，输出正式候选。
法规或安全事件：可以触发紧急复核。
```

每月冻结的意思是：

```text
每天采集的数据会一直进来，但正式结果不能每天被新数据改来改去。
所以每个月选一个截止日期，把当时可用的外部证据、久谦快照和内部算法版本锁成一个正式版本。
这个版本用于当月评审、回溯和开发对账。
截止日期之后新采集到的数据，进入下一次正式版本。
```

采购前端只输入查询条件：

```text
城市算法区域、消费者画像、门店等级、叶子品类、候选状态
```

这些只用来筛选已经计算好的结果，不是让采购手工输入趋势词、竞品、图片或候选商品。

### 4.1 V1 竞品底座：久谦三张表

V1 的结构化竞品数据先从久谦三张表取得。

这里写的不是 3 个字段，而是 3 张竞品数据表。

| 表名 | 中文名 | 这张表解决什么问题 | 例子 |
|---|---|---|---|
| `ods_jiuqian_api_raw` | 久谦接口原始表 | 保存每次 API 请求和原始返回，方便追溯、排错、重跑 | 2026-07-10 请求上海牛肉类目，接口返回 105 条商品 |
| `dim_competitor_sku` | 竞品 SKU 基础表 | 保存竞品商品相对稳定的属性 | 竞品平台、城市、竞品 SKU 编码、商品名称、品牌、规格、图片 |
| `fact_competitor_sku_daily_snapshot` | 竞品每日快照表 | 保存每天会变化的数据 | 当前售价、会员价、促销标签、销量、评论、好评率、售罄、覆盖门店数 |

这三张表能支持 V1 先做：

```text
1. 外部竞品是否出现。
2. 竞品是同款、高相似，还是只是同方向。
3. 竞品价格、规格、图片和促销信息。
4. 同一个外部候选在不同平台、城市、周期里的出现情况。
5. 外部候选能不能落回内部小分类和算法 05 价格带。
```

这三张表不能单独完整支持全部 07 能力，所以需要和 10 个公开或可授权外部源并存：

```text
1. 社媒真实使用口碑。
2. Social NPS Proxy。
3. 官方价量和供需趋势。
4. 行业文章里的新品卖点、工艺和供应链线索。
5. 法规和食品安全正式判断。
6. 搜索指数和全网热度。
```

如果久谦 API 暂时拿不到：

```text
评论数、好评率、总销量、日销量、是否售罄、商品详情链接、标准规格重量
```

这些字段不能写成 0，要保留：

```text
SOURCE_MISSING
SOURCE_PARTIAL
NO_EXTERNAL_OBSERVATION
```

这 10 个源和久谦的关系是：

```text
久谦：更像结构化竞品商品数据。
10 个外部源：补充价量、供需、POS 新品榜、零售 SKU、行业趋势和公开文章证据。
```

V1 竞品渠道渗透率不能把所有来源混在一个分母里。

```text
可以进入竞品渠道渗透率分母：
久谦
KSP-POS
7-ELEVEN 台湾
HKTVmall

不能进入竞品渠道渗透率分母：
农业农村部、商务预报、DATA.GOV.HK、AFCD、台湾价量、Foodaily / FoodTalks、红餐 / 新华网食品
```

官方价量源和文章源只能作为价格、供需、趋势文本或行业证据，不能冒充“竞品渠道出现”。

### 4.3 外部来源注册清单

久谦和 10 个外部源都要进入外部来源注册清单。后续如果再新增社媒、法规、搜索指数或付费数据库，也要先补这张清单。

这张清单要说明：

| 要说明什么 | 例子 |
|---|---|
| 来源类型 | 竞品、社媒、行业、法规、新闻、搜索指数 |
| 来源名称 | 久谦、KSP-POS、7-ELEVEN 台湾、HKTVmall、Foodaily、红餐等 |
| 覆盖市场 | 中国大陆、香港、台湾、日本等已接入市场 |
| 获取方式 | API、文件、公开页面、合规采集、人工上传 |
| 是否需要账号或授权 | 需要 API key、需要账号、无需账号但要合规采集 |
| 能拿哪些字段 | 商品名、价格、销量、评论、正文、发布时间、链接 |
| 更新频率 | 日更、周更、月更、事件触发 |
| 是否允许展示原图或原文 | 可展示、仅内部计算、不可展示 |

没有正式授权或来源说明的数据，不进入正式结果。

## 6. 核心业务对象怎么定义

### 6.1 什么是外部候选

外部候选不是一段热词，而是一个可以结构化描述的商品概念。

它至少要包含：

```text
目标小分类
主体商品
关键属性，例如功能、口味、工艺、配料
规格或规格段
来源市场
证据来源
```

例如：

```text
Omega-3 鲜鸡蛋 12 枚

小分类：鲜鸡蛋
主体：完整鲜鸡蛋
属性：Omega-3
规格：12 枚
来源：日本竞品 + POS 新品榜 + 行业文章
```

### 6.2 什么是同款、高相似和同方向

算法 07 不能只看名字像不像。

先做硬边界：

```text
小分类
主体材料
商品形态
加工方式
计量类型
```

再用模型比较：

```text
功能
口味
工艺
规格
包装
场景
名称
图片
```

结果分成：

| 关系 | 含义 |
|---|---|
| `EXACT_EQUIVALENT` | 同款或业务上等价 |
| `BUSINESS_HIGH_SIMILAR` | 高相似，可以作为强竞品参照 |
| `SAME_TREND_DIRECTION` | 同方向，但不是同款 |
| `CATEGORY_MAPPING_GAP` | 无法可靠落入内部小分类 |
| `NO_COMPARABLE_MATCH` | 没有可比竞品 |

### 6.3 什么是 Social NPS Proxy，V1 为什么不算

Social NPS Proxy 是“社媒净推荐代理值”，不是标准问卷 NPS。

标准问卷 NPS 是直接问消费者：

```text
你有多大可能把这个商品推荐给朋友？
```

社媒没有这个问卷，所以算法 07 只能从公开内容里识别“推荐倾向”。

只有明确发生过：

```text
购买
食用
使用
复购
退货
```

的账号表达，才进入正式口碑样本。

只是：

```text
想买
种草
收藏
围观
点赞
```

不能算推荐，只能进入趋势兴趣或传播强度。

同一账号、同一标准商品、同一周期只计一票。

例子：

| 社媒表达 | 算法怎么理解 |
|---|---|
| 买了三次，孩子很爱吃，还会回购 | 推荐 |
| 味道一般，但加热方便 | 中立 |
| 太咸了，不会再买 | 贬损 |
| 看起来不错，先收藏 | 只是兴趣，不进入 Social NPS Proxy |

如果 V1 没有接入社媒内容，Social NPS Proxy 不能计算，对应状态写 `V1_NOT_CALCULATED`。

这不会阻断算法 07 的 V1 输出。

V1 仍然可以用以下证据发现或验证外部新品候选：

```text
久谦竞品商品、价格、规格、图片和快照；
10 个外部源里的官方价量、供需、零售 SKU、POS 新品榜、行业文章和新闻；
内部算法 02-06 的门店等级、目标画像、主体需求、价格带和购物篮证据。
```

只是 V1 不能输出：

```text
消费者口碑很好；
社媒净推荐代理值很高；
真实买后推荐明显成立。
```

换句话说：

```text
V1 可以证明“外部有商品、有趋势线索、有价格规格证据”；
V1 不能证明“消费者真实买后愿意推荐”。
```

## 7. 核心算法流程

算法 07 可以按 12 步理解。

### 第一步：采集并保存外部原始数据

先按 V1 已接入或准备接入的数据来源保存原始证据：

```text
久谦竞品商品
久谦竞品每日价格和销量快照
10 个外部源里的官方价量、供需、零售 SKU、POS 新品榜、行业文章和公开新闻
```

所有外部证据都要保存来源：

```text
来源平台
来源市场
采集时间
原始链接或原始批次
原始文本或原始 JSON
授权状态或可使用状态
```

来源失败不能当成 0。

真实社媒、完整法规库、搜索指数和更多全球市场数据属于后续增强来源。V1 如果没有接入，只能写来源状态，不能把缺失当成 0。

### 第二步：做来源治理和去重

算法要先识别：

```text
采集成功
采集失败
来源缺失
重复转载
同一品牌全球统一新闻
营销内容
刷量或异常传播
```

例如：

```text
同一行业报告被 20 个媒体转载，
只能算一个证据组，
不能算 20 个独立趋势证据。
```

### 第三步：多语种词和属性标准化

外部数据里可能同时出现：

```text
Omega-3
欧米伽3
オメガ3
오메가3
```

这一步不是让开发直接自己翻译，也不是让模型自由判断。

V1 的做法是：

```text
先保留外部原文；
再做语言识别和基础翻译；
再用规则词典、同义词表和模型辅助识别；
最后映射到内部可理解的标准属性。
```

这里的重点不是“翻译成中文”这么简单。

翻译只能把词看懂，映射要解决的是：

```text
这个词在商品开发里到底属于哪个属性维度？
是主体商品？
是主材料？
是口味？
是工艺？
是功能卖点？
是规格？
还是只是营销描述，不能进入正式候选？
```

规则词典和同义词表用来解决确定性强的词：

```text
Omega-3 / 欧米伽3 / オメガ3
-> Omega-3 功能属性

HPP / High Pressure Processing / 高压冷杀菌
-> HPP 冷杀菌工艺
```

V1 规则词典不是要求业务一次性手工提供完整大表。

第一版可以由算法和数据开发先从三类来源沉淀：

```text
1. 内部商品基础表：
   商品名称、SPU 名称、小分类、规格、单位、品牌等。

2. 外部来源原文：
   久谦商品名、外部平台类目、商品规格、商品描述、行业文章标题和正文。

3. 业务补充的高风险 / 高频词：
   比如 Omega-3、HPP、低钠、高蛋白、0 防腐剂、药食同源、无菌蛋等。
```

算法和数据开发负责生成候选映射，业务和商品同事只需要重点复核：

```text
高频出现的词；
会进入新品名称的词；
涉及功能声称、法规、食品安全和标签风险的词；
模型置信度不高但可能影响候选的词。
```

模型辅助识别只用于补充判断，不作为唯一依据。
每次映射都要保存原文、来源、证据和置信度。

算法要保留原文，再映射到统一属性：

```text
ATTR_FUNCTION_OMEGA3
```

每次映射必须保存：

```text
mapping_probability
mapping_evidence
ontology_version
```

如果映射不可靠：

```text
保留原始证据
进入观察池
不进入新品名称
不进入正式候选
```

### 第四步：判断竞品关系

对每个外部商品，判断它和内部目标商品或候选的关系：

```text
同款
高相似
同方向
无可比匹配
品类映射缺口
```

不能因为都有“黑椒牛肉”就判为高相似。

例如：

```text
黑椒牛肉意大利面
黑椒牛柳丝
```

名称相似，但主体、形态、食用场景可能不同，必须通过硬边界和相似模型。

### 第五步：计算竞品渠道渗透率

渠道渗透率回答：

```text
在这个市场、这个周期、这个小分类成功采集到的有效渠道里，
有多少渠道出现了这个同款、这个高相似品，或这个趋势属性？
```

三层分子必须分开：

```text
同款渠道渗透率
= 出现 EXACT_EQUIVALENT 的有效渠道数 / 有效可比渠道总数

高相似渠道渗透率
= 出现 BUSINESS_HIGH_SIMILAR 的有效渠道数 / 有效可比渠道总数

趋势属性渠道渗透率
= 出现目标趋势属性且保持当前小分类的有效渠道数 / 有效可比渠道总数
```

不能把高相似并入同款。

`1/1` 也不等于高可信 100%，要用 Jeffreys-Beta 后验：

```text
x = 出现该商品或属性的有效渠道数
n = 有效可比渠道总数

p ~ Beta(x+0.5, n-x+0.5)
```

输出：

```text
penetration_raw
penetration_posterior_median
penetration_ci_low_95
penetration_ci_high_95
```

### 第六步：后续能力，计算社媒趋势和口碑

这一节是算法 07 的完整理想能力，不是 V1 已经具备的能力。
V1 不做正式社媒趋势和口碑计算，后续接入真实社媒内容后再打开。

V1 当前没有接入真实社媒内容，所以不计算正式 Social NPS Proxy。
久谦、POS 榜单、零售商品页、官方价量和行业文章可以证明外部有商品、价格、供需或趋势线索，
但不能证明消费者真实买后推荐。

V1 不做这一节，不会阻断后续候选输出。
后续计算按“可用证据”继续进行：

```text
竞品渠道证据：正常计算
官方价量和供需证据：正常计算
零售 SKU / POS 新品榜证据：正常计算
行业文章和公开新闻证据：正常计算
社媒趋势和 Social NPS Proxy：字段为空，状态写 `V1_NOT_CALCULATED`
```

因此 V1 输出候选时，可以说：

```text
外部有竞品、价格、规格、供需或行业趋势证据。
```

但不能说：

```text
外部消费者口碑好。
```

后续如果接入真实社媒，再补去重文档渗透、独立账号覆盖、互动强度、推荐/中立/贬损账号和属性口碑。

这些后续字段在开发版算法卡里预留，但不作为 V1 结果判断条件。

### 第七步：识别趋势是不是持续增长

趋势不是简单看“本周比上周涨了多少”。

业务原文要求按周建立贝叶斯动态渗透率模型，判断：

```text
水平 level
斜率 slope
加速
变点
持续性
季节性
```

小样本会自动扩大不确定性。

例如：

```text
从 1 条涨到 2 条
```

不能直接叫强趋势，因为分母和可信区间都太不稳定。

### 第八步：处理行业、法规和公开证据

这一步不是让业务或开发读法规条文打分。

它的意思是：

```text
外部文章、行业报告、官方公告、法规标准里经常会出现一些可追溯说法。
算法 07 要把这些说法拆出来，作为外部证据或风险线索保存。
```

V1 主要从以下来源得到这类证据：

```text
Foodaily / FoodTalks：新品卖点、工艺、品牌案例
红餐 / 新华网食品：预制菜、餐饮供应链、食材趋势
农业农村部、商务预报：品类价格、供需和市场变化
后续如接入法规标准源：标签、功能声称、食安标准、禁限用信息
```

拆出来时，不直接写一段长文章，而是整理成业务能追溯的结论：

```text
说的是哪个商品或品类
说的是哪个属性、工艺、卖点或风险
结论方向：增长 / 稳定 / 下降 / 只是事实
适用市场：大陆、香港、台湾、日本等
数据周期：这个结论对应哪个时间段
来源级别：官方、行业报告、媒体文章、普通转载
```

例如：

```text
文章说：HPP 冷杀菌肉制品在便利鲜食和即食蛋白场景增加。
算法 07 记录为：
主体 = 冷藏肉制品
属性 = HPP 冷杀菌 / 即食蛋白
结论方向 = GROWING
来源 = Foodaily 或行业文章
```

再比如：

```text
外部商品使用“低钠”“高蛋白”“0 防腐剂”“药食同源”等声称。
算法 07 只把它识别成法规声称风险线索。
正式能不能推荐、页面怎么展示、标签是否合规，由算法 08 风险门禁判断。
```

这里的“法规和食品安全线索传给算法 08”，意思是：

```text
算法 07 负责发现风险线索；
算法 08 负责正式风险门禁。
```

例如算法 07 在外部商品或文章里看到：

```text
低钠
高蛋白
0 防腐剂
药食同源
儿童可食用
有机认证
无抗
功能性营养声称
```

算法 07 不能直接判断“合规通过”。
它应该把这些词、来源链接、原始证据、候选商品和风险类型一起保存，传给算法 08。

算法 08 再结合公司规则、法规标准、供应链、质量和风险门禁判断：

```text
是否可以继续进入新品候选；
是否需要法务、质量或商品同事复核；
是否需要禁止进入推荐。
```

如果 07 已经从正式法规来源发现明确禁止或明确不符合准入的情况，
可以先标记硬停止；
除此之外，07 不替代 08 做最终风险结论。

报告发布时间和报告数据期要分开。

不能因为报告今天发布，就把报告里几年前的数据当成当期趋势。

### 第九步：融合外部证据

算法 07 不使用固定权重。

完整能力下，它把三类证据分开输入分层贝叶斯模型：

```text
竞品渠道证据
社媒趋势和口碑证据
行业、法规和公开证据
```

V1 因为没有真实社媒口碑源，所以先按可用证据融合：

```text
竞品渠道证据：久谦、KSP-POS、7-ELEVEN 台湾、HKTVmall 等
官方价量和供需证据：农业农村部、商务预报、香港和台湾价量/供应数据
行业和公开文章证据：Foodaily / FoodTalks、红餐 / 新华网食品等
社媒口碑证据：暂不进入，字段为空并标记 V1 暂不计算
```

这意味着 V1 仍然可以判断“外部是否有趋势线索和竞品证据”，
但不能把结果解释成“社媒口碑已验证”。

输出：

| 英文字段 | 中文含义 | 人话解释 |
|---|---|---|
| `p_trend_real` | 趋势真实概率 | 这个外部趋势是真的，不是噪声、广告或偶然事件的概率 |
| `p_sustained_growth` | 持续增长概率 | 这个趋势不是昙花一现，后续还能继续增长的概率 |
| `p_cross_market_diffusion` | 跨市场扩散概率 | 这个趋势从一个市场扩散到其他市场的概率 |
| `trend_growth_ci_low_95` | 趋势增长 95% 可信区间下界 | 保守情况下，趋势增长有多低 |
| `trend_growth_posterior_median` | 趋势增长后验中位数 | 模型认为最可能的趋势增长水平 |
| `trend_growth_ci_high_95` | 趋势增长 95% 可信区间上界 | 乐观情况下，趋势增长有多高 |

如果证据冲突，不平均成一个分数，而是输出冲突状态。

例如：

```text
竞品渠道渗透高
社媒口碑负向
```

这可能表示：

```text
市场已经验证过，但商品存在明显痛点。
```

### 第十步：用 5% 贝叶斯 FDR 区分正式趋势

算法保留三层结果：

```text
原始信号层：所有有效信号
探索层：有方向但证据不足
正式层：可信区间、稳定性和贝叶斯 FDR 全部通过
```

正式趋势要求：

```text
趋势真实概率高
持续增长概率高
通过 5% 贝叶斯 FDR
数值计算收敛
关键来源血缘完整
```

5% FDR 只控制正式层误报，不删除早期趋势。

### 第十一步：落回内部适配

外部趋势必须回到内部范围重新判断。

最低内部证据包括：

```text
算法 02：目标门店等级存在且有效
算法 03：目标消费者画像贡献成立
算法 04：主体商品或同类主体需求成立
算法 05：规格和价格可行
算法 06：如存在配方或场景关系，作为增强证据
```

特别注意：

```text
不能给社媒账号贴内部会员画像。
外部候选必须分别与每个内部消费者画像的真实商品、规格、价格和场景行为匹配。
```

### 第十二步：生成外部新品候选并传给后续算法

输出候选时必须保存：

```text
candidate_product_name
standard_candidate_id
candidate_source_status
external_evidence_status
trend_lifecycle_state
retain_attributes
improve_constraints
primary_image_id
risk_handoff_ids
candidate_development_status
```

进入算法 08 前只能标记：

```text
PENDING_ALGORITHM_08_GATE
EXPLORATORY_PENDING_ALGORITHM_08_GATE
```

不能写成已经正式开发。

## 8. 图片怎么选

图片不是随便找一张看起来像的图。

业务原文要求图片回退顺序：

```text
1. 同款竞品真实图
2. 高相似竞品参考图
3. 可追溯社媒实拍图
4. AI 开发示意图
```

每张图必须保存：

```text
image_source_type
image_url_or_asset_id
image_match_probability
ocr_match_result
authorization_status
display_label
```

展示标签不能混淆：

```text
高相似竞品图必须标记“高相似竞品参考图”
社媒图必须标记“社媒公开实拍图”
AI 图必须标记“AI 开发示意图”
```

AI 图不能生成虚构品牌、认证标志、功效检测数值或未确认配料。

## 9. 一个完整例子：Omega-3 鲜鸡蛋

这个例子用来说明 07 的 V1 链路。
其中 `Social NPS Proxy` 不参与 V1 计算。

V1 先看：

```text
久谦竞品证据
SKU / POS / 电商渠道证据
官方价量和供需证据
行业文章和公开新闻证据
内部算法 02-06 适配结果
```

假设外部数据发现：

```text
来源市场：日本
外部候选：Omega-3 鲜鸡蛋 12 枚
小分类：鲜鸡蛋
主体：完整鲜鸡蛋
属性：Omega-3
```

V1 不输出真实社媒趋势模型结果。
如果后续接入真实社媒，再输出社媒趋势斜率、变点和可信区间。

竞品渠道渗透：

```text
x = 5
n = 8
raw = 62.50%
后验中位数 = 61.97%
95% 可信区间 = [29.48%,88.10%]
```

Social NPS Proxy：

```text
V1 不计算
social_source_status = V1_NOT_CALCULATED
相关口碑数值字段 = NULL
```

外部融合结果：

```text
p_trend_real = 99.1%
p_sustained_growth = 98.7%
p_cross_market_diffusion = 91.4%
local_false_discovery_rate = 1.8%
bayesian_fdr_selected_flag = 1
trend_lifecycle_state = GROWING
external_evidence_status = FORMAL_GROWING_TREND
```

内部适配还要继续看：

```text
算法 02 门店等级是否成立
算法 03 目标消费者画像是否成立
算法 04 鲜鸡蛋主体需求是否成立
算法 05 12枚规格和价格是否可行
法规声称风险线索是否要传给算法 08
```

最终候选不能写“国内已流行”，只能写：

```text
candidate_product_name = Omega-3 鲜鸡蛋 12 枚
candidate_source_status = EXTERNAL_DISCOVERED_INTERNAL_MATCHED
external_evidence_status = FORMAL_GROWING_TREND
candidate_development_status = PENDING_ALGORITHM_08_GATE
```

如果国内弱、海外强，则可能是：

```text
OVERSEAS_LEADING_EXPLORATORY
```

业务话术只能是：

```text
海外前瞻趋势，国内需结合内部需求和风险门禁验证。
```

## 10. 结果状态怎么理解

| 状态 | 业务含义 |
|---|---|
| `RAW_EXTERNAL_SIGNAL` | 外部原始信号存在，但不能当正式趋势 |
| `EMERGING_EXPLORATORY` | 早期增长信号，进入探索试点候选 |
| `FORMAL_GROWING_TREND` | 正式增长趋势，通过统计和 FDR |
| `MATURE_MARKET_GAP` | 外部市场成熟，但内部可能存在差异化空白 |
| `OVERSEAS_LEADING_EXPLORATORY` | 海外领先，国内证据弱，只能前瞻探索 |
| `CONFLICTING_EXTERNAL_EVIDENCE` | 竞品、社媒、行业等证据方向冲突 |
| `DECLINING_EXTERNAL_TREND` | 外部趋势下降，不支持新品开发 |
| `NO_EXTERNAL_OBSERVATION` | 当前没有可用外部观测，不代表趋势为 0 |
| `CATEGORY_MAPPING_GAP` | 无法可靠映射到内部小分类 |
| `REGULATORY_STOP` | 法规硬停止，不生成外部新品候选 |
| `SOURCE_MISSING` | 来源缺失，不能填 0 |
| `SOURCE_PARTIAL` | 来源部分可用，缺失字段不能补 0 |
| `V1_NOT_CALCULATED` | V1 明确暂不计算，例如 Social NPS Proxy |
| `COMPUTE_UNSTABLE` | 数值未收敛，不能进入正式趋势 |

候选来源状态和外部证据状态不能混用。

例如：

```text
candidate_source_status = EXTERNAL_DISCOVERED_INTERNAL_MATCHED
external_evidence_status = OVERSEAS_LEADING_EXPLORATORY
candidate_development_status = EXPLORATORY_PENDING_ALGORITHM_08_GATE
```

三者分别回答：

```text
候选从哪里来
外部证据处于什么阶段
候选能不能进入后续开发门禁
```

## 11. 开发实际要怎么做

开发可以有过程表，但正式交付以 9 张结果表为准。

建议开发顺序分两层。

第一层：V1 已确认外部证据能力，久谦和 10 个外部源一起落地。

```text
1. 创建 external_trend_run，锁定外部采集批次、内部算法版本和本次正式周期。
2. 入库久谦原始表、竞品 SKU 基础表和竞品每日快照表。
3. 接入 10 个公开或可授权外部源，保存原始链接、原始行、原始正文或原始页面快照。
4. 把久谦和 10 个源统一到外部证据字段：商品、品类、价格、规格、图片、正文、来源市场、采集时间。
5. 用商品名称、类目、品牌、规格、图片做外部商品标准化和属性映射。
6. 判断竞品和内部候选的关系：同款、高相似、同方向、无法匹配。
7. 只用久谦、KSP-POS、7-ELEVEN 台湾、HKTVmall 等 SKU / POS / 电商源计算竞品渠道渗透率。
8. 用官方价量和供需源计算价格、交易量、供应量变化。
9. 用 Foodaily / FoodTalks、红餐 / 新华网食品抽取趋势词、新品卖点、工艺和供应链线索。
10. 将外部候选落回内部小分类、主体商品、画像、门店等级和算法 05 价格带。
11. 选择并校验候选图片，保存图片来源和授权状态。
12. 写入外部候选结果，交给算法 09。
```

第二层：完整 07 理想能力，等真实社媒、完整法规和更多市场来源接入后再打开。

```text
1. 接入社媒内容后，计算去重文档渗透、账号覆盖和 Social NPS Proxy。
2. 接入行业报告和公开新闻后，抽取行业趋势、市场规模和来源层级。
3. 接入法规和标准资料后，识别法规线索并传给算法 08。
4. 多来源都稳定后，再做完整贝叶斯趋势融合、FDR 和冲突识别。
```

## 12. 业务验收看什么

业务和开发评审重点看 8 件事：

| 验收点 | 看什么 |
|---|---|
| 来源追溯 | 每个外部候选能不能追到原始批次、链接、市场和来源 |
| 多语种映射 | 同义词是否映射到同一标准属性，未通过是否进入观察池 |
| 竞品关系 | 同款、高相似、同方向是否分开，是否先做硬边界 |
| 渠道渗透 | 分子分母是否正确，1/1 是否没有被当成 100% 高可信 |
| 社媒口碑 | V1 未接入真实社媒时，Social NPS Proxy 是否为空并标记 V1 暂不计算 |
| 趋势证据 | 官方价量、零售 SKU、POS 新品榜和行业文章是否分开，不互相冒充 |
| 内部适配 | 是否落回内部小分类、主体需求、画像、门店等级和价格 |
| 图片和风险 | 图片是否标记来源，法规和安全线索是否传给算法 08 |

V1 固定复算样例：

```text
x=5,n=8
Jeffreys-Beta 后验中位数 = 61.97%
95% 可信区间 = [29.48%,88.10%]
```

Social NPS Proxy 不作为 V1 复算验收项。

| 优先级 | 确认对象 | 需要评审的红线 |

| P1 | 数据开发 | 久谦字段是否能稳定支持价格、规格、销量、评论、好评率、售罄、覆盖门店、图片和商品详情链接 |
| P1 | 数据开发 | 10 个外部源是否能按 V1 字段矩阵稳定采集，并保留原始链接、采集时间和来源状态 |
| P1 | 算法/数据开发 | 多语种属性映射按内部商品基础表、外部原文、规则词典、同义词表和模型辅助识别生成候选映射；无法稳定映射的外部词进入观察池，不进入正式候选 |
| P1 | 业务/商品/质量 | 需要优先复核哪些高频词和风险词，例如 Omega-3、HPP、低钠、高蛋白、0 防腐剂、药食同源、无菌蛋等 |
| P1 | 法务/质量/业务 | 07 识别到法规、标签、食品安全或功能声称风险线索后，是否统一传给算法 08 做正式门禁 |

已明确不再重复确认：

```text
V1 外部数据不是久谦和 10 个源二选一，而是并存。
久谦仍然提供结构化竞品数据底座。
10 个外部源补充官方价量、供需、零售 SKU、POS 新品榜和行业趋势文章。
城市范围使用城市算法区域映射表。
外部来源缺失不能填 0。
外部候选无法映射内部小分类时，按 CATEGORY_MAPPING_GAP 保留证据，不进入正式候选。
V1 只表达“已接入来源、已接入市场中观察到的趋势”，不表达完整全球趋势。
```

## 14. 不要做什么

```text
不能将外部趋势单独作为最终新品推荐
不能将外部社媒账号推断成内部会员画像
不能将广告、点赞、收藏、转载直接当成自然趋势
不能将同一行业报告的多次转载当成多条独立证据
不能将同一品牌全球发布当成多个市场自然扩散
不能将不同平台原始销量、播放量、点赞量或评论量直接相加
不能将采集失败或缺失数据写成 0
不能将 1/1 渠道渗透表述为高可信 100%
不能将同款、高相似品和趋势属性渗透混成一个分子
不能将 Social NPS Proxy 写成标准问卷 NPS
不能将海外趋势写成国内已流行
不能将海外价格按汇率换算成国内建议价
不能将多个独立热词擅自拼成一个商品
不能将无法映射的商品强行归入语义最相似的小分类
不能用人工固定权重综合分消灭证据冲突
不能因外部趋势强就越过当前货盘或历史差销过滤
不能在算法 08 风险门禁前宣称新品已正式进入开发
```

## 15. 一句话总结

算法 07 的关键是：

```text
先证明外部趋势真实、自然、可追溯；
再证明它能落回内部小分类、目标画像、门店等级和价格可行性；
最后只把通过证据和适配校验的候选交给算法 09 和算法 08。
```
