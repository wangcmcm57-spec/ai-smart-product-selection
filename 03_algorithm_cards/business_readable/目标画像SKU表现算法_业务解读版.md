## 一、先用一句话理解

算法 04 要判断：

```text
在某个城市算法区域、某个品类、某个门店等级群、某个消费者类型下，
哪些已经卖过的 SKU 表现最好，
可以作为后续新品方向生成的“锚点商品”。
```

锚点商品不是新品。

锚点商品是现有商品，是后续分析的证据起点。

例如：

```text
算法 04 找到现有锚点：黑椒牛柳丝 200g
后续购物篮算法发现：它经常和圆葱、青椒一起买
后续新品方向才可能生成：圆葱黑椒牛柳丝、青椒黑椒牛柳丝
```

所以算法 04 不直接生成新品，也不直接决定新品价格。

## 二、最终会输出什么

算法 04 正式落地时，建议分成：

```text
一张前置中间表
+ 两张正式结果表
+ 一张可选汇总表
+ 一类参数/解释表
```

### 2.1 前置中间表：SKU 7天19点前复购结果

表名：

```text
mart_sku_repurchase_7d_pre19
```

这张表先由 Doris 小票明细计算出来，再给算法 04 读取。

一行表示：

```text
一个数据周期
+ 一个城市算法区域
+ 一个门店等级群
+ 一个品类
+ 一个消费者类型
+ 一个 SKU
的 7天19点前复购表现
```

它输出：

| 指标 | 业务含义 |
|---|---|
| 7天观察窗口首购会员数 | 有完整 7 天观察窗口的首购会员人数 |
| 7天19点前复购会员数 | 首购后第 1-7 个自然日内，19:00 前再次购买同一 SKU 的会员人数 |
| 7天19点前复购率 | 复购会员数 / 观察窗口首购会员数 |
| 复购率 95% 下界 | 小样本保守值，用于正式评分 |

为什么要单独存：

```text
SKU 级复购计算比较重。
如果每次算法 04 都从小票明细重新算，会慢，也不方便验收。
```

### 2.2 正式结果表：目标画像 SKU 表现明细

表名：

```text
mart_target_profile_sku_performance
```

一行表示：

```text
一个周期
+ 一个城市算法区域
+ 一个品类
+ 一个门店等级群
+ 一个消费者类型
+ 一个销售条码 SKU
```

它回答：

```text
这个 SKU 在这个目标画像下表现好不好？
是不是当前正式锚点？
为什么是，或者为什么不是？
```

示例：

| 字段 | 示例 |
|---|---|
| 数据周期 | 2026-04-01 至 2026-06-30 |
| 城市算法区域 | 上海 |
| 品类 | 牛肉制品 |
| 门店群 | A级门店 |
| 消费者类型 | 上班族晚高峰型-小家庭-中频-价格非敏感 |
| SKU | 黑椒牛柳丝 200g |
| 综合表现分 | 86.2 |
| 是否正式锚点 | 是 |
| 原因 | 目标画像贡献高、偏好强、复购证据充分、19:30 前自然动销好、毛利为正 |

### 2.3 正式结果表：标准商品表现

表名：

```text
mart_target_profile_product_performance
```

业务原文要求 SKU 层和标准商品层都输出。

标准商品层的作用是：

```text
把同一个实物商品的旧码、新码、换包装码合并看表现。
```

但是第一版现在没有稳定的新旧码/替代关系时，不能硬合并。

V1 口径：

```text
先按销售条码 SKU 计算。
标准商品层先保留为 SKU_ONLY。
等后续 SPU、换码关系稳定后，再做标准商品合并。
```

### 2.4 可选汇总表：锚点汇总

表名：

```text
mart_target_profile_anchor_summary
```

一行表示：

```text
一个城市算法区域
+ 一个品类
+ 一个门店等级群
+ 一个消费者类型
```

它把明细结果汇总成：

| 类型 | 业务含义 |
|---|---|
| 当前正式锚点 | 当前可订可售，并通过锚点准入的 SKU |
| 历史锚点 | 贡献周期内表现好，但当前不可订不可售的 SKU |
| 低铺货高表现 | 订购覆盖低，但实际经营表现好的 SKU |
| 时间敏感锚点 | 表现依赖某个月份的 SKU |
| 门店集中锚点 | 表现集中在少数门店的 SKU |

### 2.5 参数和解释表

算法 04 会用到：

```text
Jeffreys 95% 下界
CRITIC 动态权重
Jenks+BIC 动态分组
稳健标准化
```

这些方法都会产生参数。

参数表不是采购主表，但需要保存，方便开发、产品和业务复算：

```text
为什么这个 SKU 是 86 分？
为什么这个 SKU 被分到高表现组？
为什么 1 人买 1 人复购不能直接当成强证据？
```

## 六、核心业务对象怎么定义

### 6.1 SKU

这里的 SKU 指销售条码，也就是 Doris 小票里的：

```text
article_id
```

V1 先按销售条码计算，不做强制 SPU 合并。

### 6.2 目标画像

目标画像来自算法 01 和算法 03。

算法 04 自己不重新贴画像。

### 6.3 锚点商品

锚点商品必须是现有 SKU。

正式锚点需要同时满足：

```text
目标画像真实购买
表现进入高表现组
当前可订可售
目标画像毛利为正
SKU整体毛利为正
自然动销窗口有效
样本证据不是低证据
```

### 6.4 历史锚点

业务文档明确要保留历史锚点。

历史锚点是：

```text
贡献周期内有真实销售且表现较好，
但当前不可订不可售的 SKU。
```

它可以保留消费者和购物篮证据，但不能作为当前正式锚点。

后续如果要复开发，必须再查：

```text
为什么停售
供应商是否可恢复
历史订购表现
是否已有相似商品
```

## 七、先过滤什么数据

只保留正常完成的正向销售。

V1 过滤原则：

```text
会员 ID 有效
商品编码有效
销售金额 > 0
销售数量或销售重量 > 0
剔除退货、取消、冲销、测试交易
剔除赠品和零金额行
剔除算法 01 已标记的异常会员日
```

同一小票里同一个 SKU 出现多行时，先合并。

原因：

```text
否则同一张小票里的同一商品会被重复计算小票数和购买次数。
```

## 八、核心维度分别看什么

算法 04 的综合表现分由四个一级维度组成。

| 维度 | 看什么 |
|---|---|
| 目标画像贡献 | 目标画像的钱、会员、小票是否集中在这个 SKU |
| 目标画像偏好 | 目标画像是否比其他画像更喜欢这个 SKU，且是否有复购 |
| 19:30 前自然动销 | 不靠促销时，19:30 前是否卖得动、卖得深 |
| 商品毛利 | 目标画像和 SKU 整体是否有正毛利 |

不进入综合得分，但要输出解释：

```text
订购覆盖
19:30 后半小时折扣阶梯
价格
损耗
商品属性完整度
当前在售状态
```

## 九、7天19点前 SKU 复购怎么做

业务原文要求读取现有 7 天复购结果。

但我们已经确认：指标平台当前没有可直接用于算法 04 的 SKU 级复购结果。

所以 V1 改为：

```text
先基于 Doris 小票明细计算 mart_sku_repurchase_7d_pre19，
算法 04 再读取这张中间表。
```

复购口径：

```text
首次购买：会员在 T 天购买某个 SKU，时间不限
第二次购买：同一会员在 T+1 到 T+7 自然日内再次购买同一 SKU
并且第二次购买发生在 19:00 前
```

同一天多张小票不算复购。

周期结束前不足 7 天观察窗口的首购会员，不进入分母。

公式：

```text
7天观察窗口首购会员数
= 有完整 7 天观察窗口的首购会员去重数

7天19点前复购会员数
= 满足第 1-7 自然日内 19:00 前再次购买同 SKU 的会员去重数

7天19点前复购率
= 7天19点前复购会员数 / 7天观察窗口首购会员数
```

## 十、自然动销怎么做

自然动销只看非促销 SKU 日的 19:30 前表现。

业务原文口径：

```text
门店 + 日期 + SKU
在 19:30 前没有参加商品活动
且 19:30 前没有商品促销折扣
```

第一期没有促销活动表。

V1 落地口径：

```text
优先用毛利损耗表里的促销折扣额、时段折扣额等汇总字段判断。
如果只能用小票 discount_amt > 0 判断，需要标记 PROMOTION_PROXY_V1。
```

自然动销核心指标：

```text
非促销 19:30 前售罄率
= 非促销有效 SKU 日 19:30 前标准销售量
 / 非促销有效 SKU 日实际收货标准量

19:30 前每有效在售门店日标准销售量
= 19:30 前标准销售量
 / 有效在售门店日数
```

注意：

```text
复购的第二次购买看 19:00 前。
自然动销看 19:30 前。
如果现有汇总表只有 19点前销售字段，不能直接替代 19:30 前自然动销，
需要开发用 Doris 小票明细按交易时间补算。
```

## 十一、目标画像毛利怎么做

业务最新原文写的是：

```text
目标画像 SKU 毛利额
= 目标画像 SKU 销售额 - 目标画像 SKU 成本金额
```

业务理想口径是：

```text
如果有交易行级成本，
直接把目标画像购买明细对应的成本金额加总。
```

但我们当前 V1 没有确认存在交易行级成本。

所以 V1 需要补充可执行口径。

### 11.1 优先口径：用日门店SKU全链路毛利推导成本

如果毛利损耗表能稳定提供：

```text
营业日期 + 门店编码 + 销售商品编码
的销售额、全链路毛利额
```

则可以推导：

```text
日门店SKU全链路成本金额
= 日门店SKU销售额 - 日门店SKU全链路毛利额
```

再按目标画像销售额占比分摊：

```text
目标画像日门店SKU成本金额
= 日门店SKU全链路成本金额
 * 目标画像该日门店SKU销售额
 / 该日门店SKU总销售额
```

最后汇总到算法 04 粒度。

### 11.2 备选口径：用门店商品日价格表成本

如果全链路成本无法稳定推导，可以用门店商品日价格表：

```text
出库到店成本含税
```

作为日门店 SKU 成本底数。

但要先把价格表从：

```text
日期 + 门店编码 + 销售商品编码 + 验收商品编码
```

聚合成：

```text
日期 + 门店编码 + 销售商品编码
```

再和小票及目标画像做分摊。

使用该备选口径时需要输出：

```text
cost_source = ARRIVAL_COST_TAX_INCLUDED
cost_allocation_status = COST_ALLOCATED_V1
```

### 11.3 为什么不能直接用价格表当目标画像成本

因为门店商品日价格表没有会员 ID，也没有消费者画像。

它只能说明：

```text
某天某门店某个 SKU 的成本是多少。
```

它不能直接说明：

```text
其中多少成本属于某个目标画像购买。
```

所以必须用小票明细识别目标画像购买金额，再做分摊。

## 十二、标准销售量和单位怎么处理

业务原文要求不同计量类型分别标准化。

V1 先用商品基础表的“单位”字段识别：

| 单位示例 | 计量类型 |
|---|---|
| 千克 / kg / 公斤 / g / 克 | 重量 |
| 件 / 份 / 盒 / 包 / 袋 / 瓶 / 个 | 数量 |

暂时不需要现在补充所有单位。

等商品基础表真实数据落地后，再抽样检查单位值。

如果无法识别：

```text
measurement_mapping_status = UNKNOWN
```

无法识别的 SKU 不直接删除，但数量、售罄率等需要同类比较的指标不能乱算。

## 十三、小样本和置信度怎么处理

业务原文要求使用 Jeffreys 95% 下界。

原因是：

```text
1 人买 1 人复购 = 100%
100 人买 40 人复购 = 40%
```

不能因为第一个原始复购率是 100%，就认为它比第二个更强。

所以正式评分用更保守的下界。

保存：

```text
原始值
分子
分母
95%下界
95%上界
```

正式评分使用下界。

采购或业务查看时可以同时看到原始值和分子分母。

## 十四、综合分怎么合成

算法 04 不使用固定权重。

业务原文要求：

```text
二级指标和四个一级维度都使用 CRITIC 动态赋权。
```

CRITIC 的业务含义：

```text
哪个指标更能区分 SKU，且和其他指标重复度低，
它的权重就更高。
```

先算每个维度内的指标权重，再算四个一级维度的权重。

这样可以避免：

```text
某个维度因为指标数量多，就天然占更高权重。
```

## 十五、锚点结果怎么生成

第一步：

```text
在同一比较组内计算每个 SKU 的综合表现分。
```

第二步：

```text
用 Jenks+BIC 动态分成 1-3 组。
```

可能结果：

| 分组数 | 结果 |
|---|---|
| 3组 | 高表现组 / 中表现组 / 低表现组 |
| 2组 | 高表现组 / 低表现组 |
| 1组 | 没有明显高表现 SKU |

第三步：

```text
最高表现组进入正式锚点准入判断。
```

正式锚点必须同时满足：

```text
当前可订可售
目标画像毛利额 > 0
SKU整体毛利额 > 0
证据充分
自然动销有效
数据完整
```

## 十六、19:30 后折扣阶梯怎么用

业务原文明确：

```text
19:30 后折扣阶梯只用于解释，不进入算法 04 综合得分。
```

要输出的解释内容：

```text
19:30-20:00 销售量 / 增量售罄率 / 实际折扣率
20:00-20:30 销售量 / 增量售罄率 / 实际折扣率
20:30-21:00 销售量 / 增量售罄率 / 实际折扣率
其他实际营业折扣档同理
```

它帮助解释：

```text
这个 SKU 是 19:30 前自然卖得好，
还是主要靠后续一档一档降价清掉。
```

## 十七、开发实际要怎么做

开发不是只建一张表。

正确顺序是：

```text
1. 准备上游正式版本：算法 01、02、03
2. 准备基础数据：小票、商品、门店、毛利损耗、价格、可订可售
3. 先计算 SKU 级 7天19点前复购中间表
4. 计算目标画像 SKU 基础表现
5. 计算目标画像相对偏好
6. 计算自然动销
7. 计算目标画像成本和毛利
8. 做小样本置信度处理
9. 做 CRITIC 动态权重和综合分
10. 做 Jenks+BIC 高表现分组
11. 判断正式锚点、历史锚点和各种状态
12. 输出 SKU 明细表、标准商品表、锚点汇总表和参数解释表
```

## 十八、业务验收看什么

业务验收不只看“有没有分数”。

要看：

```text
销售额是否能和上游对账
SKU 是否和商品基础表对齐
门店群和消费者类型是否来自正式版本
复购分子、分母是否合理
1/1 复购是否没有被误判成强锚点
19:30 前自然动销是否剔除了促销代理日
目标画像毛利是否为正
当前不可订不可售是否只作为历史锚点
商品属性缺失是否没有被 AI 编造
```

## 十九、现在还需要确认什么

| 确认项 | 负责方 | 说明 |
|---|---|---|
| 目标画像成本优先使用全链路成本推导，还是出库到店成本含税 | 业务/数据开发 | 业务确认毛利优先全链路口径；开发需要确认底表可取字段 |
| 毛利损耗表是否能稳定到营业日期 + 门店 + 销售商品编码的全链路毛利额 | 数据开发 | 影响 V1 是否能按全链路成本分摊 |
| 门店商品日价格表的出库到店成本含税是否稳定可取 | 数据开发 | 全链路成本不可用时的备选成本底数 |
| 非促销 SKU 日是否接受 V1 促销代理口径 | 业务 | 无促销活动表时，可能使用折扣字段近似 |
| 商品基础表单位真实值有哪些 | 数据开发/产品 | 等基础表落地后抽样，不需要现在补全 |
| SPU、换码、替代关系何时可用 | 商品/数据开发 | V1 可先 `SKU_ONLY`，后续再合并标准商品 |

## 二十、不要做什么

```text
不要把算法 04 的锚点当成新品推荐结果。
不要把 19:30 后销售额占比当成折扣阶梯。
不要把价格表成本直接当成目标画像成本。
不要在没有正式 SPU 或换码关系时按名称相似合并 SKU。
不要让商品属性缺失阻断经营表现评分。
不要把商品属性缺失交给 AI 猜。
不要用固定权重替代 CRITIC。
不要把 1/1 的 100% 复购当成强证据。
```

## 二十一、一句话总结

算法 04 的核心是：

```text
用目标消费者真实购买、偏好、复购、自然动销和毛利，
找出现有高表现 SKU 锚点；
它为后续购物篮和新品方向生成提供证据，
但它本身不是新品推荐算法。
```
