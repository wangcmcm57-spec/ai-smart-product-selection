# 算法02_门店品类等级_业务解读版

生成日期：2026-07-23  
文档状态：一期业务解读版  
依据文档：`01_业务原始与补充文档/业务补充算法文档/算法卡_02_门店品类等级_业务提供最新原始版_20260722.md`

## 1. 先用一句话理解

门店品类等级算法要做的事是：

```text
在同一个城市算法区域、同一个品类里，
比较不同门店经营这个品类的能力，
最后给每个门店品类一个等级。
```

它不是门店整体评级，也不是门店订货系统。

它服务 AI 新品推荐，回答的是：

```text
这个品类如果要开发新品，哪些门店更适合先试？
哪些门店有品类经营基础？
哪些门店虽然卖得多，但毛利、订购、促销依赖或损耗有风险？
```

## 2. 最终会输出什么

正式结果表：

```text
mart_store_category_level
```

一行结果表示：

```text
一个数据周期
+ 一个城市算法区域
+ 一个门店
+ 一个品类颗粒度
+ 一个品类
+ 一次模型版本
```

示例：

```text
2026-04-01~2026-06-30
上海
上海康桥宝邸
小分类
牛肉制品
门店品类等级 = A
```

同一家门店可以在不同品类上得到不同等级：

| 门店 | 品类 | 等级 |
|---|---|---|
| 上海康桥宝邸 | 牛肉制品 | A |
| 上海康桥宝邸 | 叶菜类 | B |
| 上海康桥宝邸 | 水产类 | C |

输出结果主要包含这些内容：

| 字段组 | 业务含义 |
|---|---|
| 数据周期与版本 | 说明这次等级用了哪段时间的数据、哪版算法、哪版城市算法区域 |
| 城市算法区域 | 说明这家门店和哪些城市/门店放在同一组里比较 |
| 门店与品类 | 说明是哪个门店、哪个大类/中类/小类 |
| 七个维度得分 | 经营规模、货盘宽度、商品效率、盈利能力、订购健康、促销健康、损耗健康 |
| 权重与综合分 | 说明七个维度分别占多少权重，以及最终综合分 |
| 暂定等级与最终等级 | 先按综合分分层，再经过经营底线修正后的等级 |
| 风险解释 | 连续亏损、严重损耗、数据缺失、促销依赖、订购异常等原因 |
| 置信度 | 说明这个等级的数据是否足够稳定 |

开发可以在计算过程中建临时表或过程表，但后续 AI 新品机会模型要稳定读取的是 `mart_store_category_level`。

## 3. 它在 AI 选品链路中的位置

整体链路是：

```text
基础数据表
-> 门店品类等级算法
-> mart_store_category_level
-> 门店群消费者画像贡献算法
-> 新品候选方向生成
-> 新品机会评分
-> AI 新品推荐结果
```

这一步是离线定时计算，不需要大模型参与。

大模型后面只负责理解采购问题、查询结果、解释原因，不负责现场重新计算门店等级。

## 4. 一期用哪些底层数据

一期使用已经在推进的数据底座。

| 数据表 | 本算法怎么用 |
|---|---|
| Doris 小票商品明细表 | 取交易时间、小票、会员、商品、实付金额、优惠金额、重量，用于 19 点前销售、客流、会员、部分优惠指标补算 |
| 门店基础表 | 通过门店编码拿到门店名称、城市、门店状态 |
| 城市算法区域映射表 | 把城市映射到算法区域，例如上海、宁波杭州、苏锡常及其他 |
| 商品基础表 | 通过交易商品编码拿到商品的大类、中类、小类、单位和计量信息 |
| 门店商品可订可售表 | 判断某天某门店某商品是否具备可售/可订条件，用于货盘宽度和有效 SKU 日 |
| 毛利损耗表 | 取销售额、原价销售额、19 点前销售、进货、毛利、折扣、时段折扣、损耗 |
| 门店商品日价格表 | 取出库到店成本含税，用于到货成本和损耗成本率 |

关键关联关系：

```text

```

```text

```

```text
门店 + 日期 + 交易商品编码

```

```text
日期 + 门店编码 + 销售商品编码
-> 门店商品日价格表
-> 出库到店成本含税
```

## 5. 数据周期怎么理解

正式等级每月更新一次。

每次正式计算只用最近 3 个数据完整自然月生成等级。

例如 2026 年 7 月运行：

```text
正式评估周期 = 2026-04-01 到 2026-06-30
```

最近 6 个完整自然月不是再算一版等级。

6 个月数据只用来辅助：

```text
权重不稳定时回退
标准化参数不稳定时参考
订购健康区间训练
损耗风险线训练
等级稳定性检查
```

最简单的理解：

```text
3 个月 = 本次正式打分用的数据
6 个月 = 帮算法判断参数稳不稳的历史参考
```

## 6. 比较范围怎么来

门店不能随便互相比。

算法只允许门店在同一个正式比较范围里比较：

```text
同一个城市算法区域
+ 同一个品类颗粒度
+ 同一个品类
```

城市算法区域由业务配置表维护，不由算法自动生成。

当前已确定使用：

```text
dim_city_algorithm_region
```

表粒度：

```text
一行 = 一个城市 + 一个算法区域映射生效周期
```

关键字段：

| 字段名 | 示例 | 用途 |
|---|---|---|
| 城市 | 上海 / 杭州 / 宁波 / 苏州 | 和门店基础表的城市对齐 |
| 算法区域编码 | SH / NBHZ / SSCQ | 算法比较范围编码 |
| 算法区域名称 | 上海 / 宁波杭州 / 苏锡常及其他 | 算法比较范围名称 |
| 生效开始日期 | 2026-07-01 | 判断某个数据周期使用哪版映射 |
| 生效结束日期 | 空 / 2026-12-31 | 支持历史追溯 |
| 是否当前有效 | 1 / 0 | 判断当前映射是否有效 |
| 映射确认人 | 张三 | 追溯业务确认人 |
| 映射确认日期 | 2026-07-20 | 追溯业务确认时间 |
| 数据更新时间 | 2026-07-20 10:00:00 | 数据维护时间 |
| 备注 | 嘉兴归入苏锡常及其他 | 记录边界城市说明 |

## 7. 品类颗粒度怎么处理

算法支持三个层级：

```text
大分类
中分类
小分类
```

每个层级都必须从底层数据重新聚合、重新评分、重新分层。

不能这样算：

```text
小分类等级平均 = 中分类等级
中分类等级平均 = 大分类等级
```

原因是不同品类层级的经营逻辑不同，门店排序可能完全不一样。

## 8. 先过滤什么数据

正式计算前，要先过滤异常交易。

有效交易保留：

```text
门店编码不为空
商品编码不为空
业务日期不为空
正常完成交易
非退货、非退款、非取消、非冲销、非测试交易
销售金额、销售数量或销售重量符合正向销售口径
商品能关联到正式品类
```

会员相关指标只统计有效会员：

```text
会员编码不为空
会员编码不以 6 开头
会员小票满足会员画像算法里的异常过滤规则
```

有效营业日一期口径：

```text
门店当天有销售数据，就作为有效营业日。
一期输入数据只包含营业中门店。
```

有效在售 SKU 日一期口径：

```text
当天门店商品可订可售表显示可售
+ 当天门店有实际进货数量或进货重量
```

如果某个 SKU 日进货量小于等于 0：

```text
不计算该 SKU 日售罄率
不计入有效在售 SKU 日
不把它当作 0 销售
```

如果 19 点前销售量明显超过进货量：

```text
19点前销售量 / 实际进货量 > 110%
```

这个 SKU 日标记为异常，不进入订购健康训练，但原始销售仍可进入经营规模。

## 9. 七个维度分别看什么

门店品类等级由七个一级维度组成：

| 维度 | 看什么 | 直觉理解 |
|---|---|---|
| 经营规模 | 19 点前销售额、小票数、会员数 | 这个门店这个品类有没有基础消费盘 |
| 货盘宽度 | 有效在售 SKU、动销 SKU、SKU 动销率 | 这个门店能不能承接更多商品 |
| 商品效率 | 单 SKU 日均销售、单 SKU 日均毛利 | 每个 SKU 的产出高不高 |
| 盈利能力 | 全链路毛利额、门店毛利率 | 这个品类是不是真的赚钱 |
| 订购健康 | 19 点前售罄率是否在健康区间 | 到货量和销售消化是否匹配 |
| 促销健康 | 常规优惠依赖、时段折扣依赖、优惠后毛利 | 是否主要靠优惠或晚间折扣卖动 |
| 损耗健康 | 损耗成本率 | 损耗是否拖累经营 |

## 10. 经营规模怎么算

经营规模全部使用 19 点前数据，因为 19 点前更能代表自然消费能力。

核心指标：

```text
日均 19点前销售额 = 19点前销售额 / 有效营业日数
日均 19点前小票数 = 19点前小票数 / 有效营业日数
周期有效会员数 = 19点前去重有效会员数
```

销售额和小票数包含会员与非会员。

会员数只统计有效会员。

这三个指标先各自转成 0-100 分，再用 CRITIC 算出经营规模内部权重，得到：

```text
scale_score
```

## 11. 货盘宽度怎么算

货盘宽度看门店是否有承接更多 SKU 的能力。

核心指标：

```text
有效在售 SKU 天数
19点前动销 SKU 天数
日均在售 SKU 数
日均19点前动销 SKU 数
19点前 SKU 动销率
```

计算方式：

```text
日均在售 SKU 数 = 有效在售 SKU 天数 / 有效营业日数
日均19点前动销 SKU 数 = 19点前动销 SKU 天数 / 有效营业日数
19点前 SKU 动销率 = 19点前动销 SKU 天数 / 有效在售 SKU 天数
```

这些指标转成 0-100 分后，用 CRITIC 得到：

```text
assortment_width_score
```

## 12. 商品效率怎么算

商品效率看的是每个有效 SKU 日的产出。

核心指标：

```text
单 SKU 日均销售产出 = 19点前有效销售额 / 有效在售 SKU 天数
单 SKU 日均毛利产出 = 全日全链路毛利额 / 有效在售 SKU 天数
```

销售品效越高越好。

毛利品效也越高越好，但它可能为负。负毛利不能填 0，因为负数本身就是经营风险。

最终得分：

```text
sku_efficiency_score =
SQRT(销售品效得分 * 毛利品效得分)
```

## 13. 盈利能力怎么算

盈利能力看这个门店这个品类是否真正赚钱。

核心指标：

```text
日均全链路毛利额 = 全日全链路毛利额 / 有效营业日数
门店毛利率 = 全日门店毛利额 / 全日有效销售额
```

两个指标转成 0-100 分后：

```text
profitability_score =
SQRT(全链路毛利额得分 * 门店毛利率得分)
```

净经营贡献用于订购健康、连续亏损和损耗风险：

```text
净经营贡献 = 全链路毛利额 - 损耗金额
```

根据数据指标平台口径，全链路毛利额本质是：

```text
全链路收入项 - 全链路成本项
```

其中成本项里已经包含：

```text
供应链损耗额（不含税）
```

但当前公式里没有看到“门店损耗金额”被扣除。

所以一期先按以下口径理解：

```text
全链路毛利额已经扣供应链损耗
净经营贡献 = 全链路毛利额 - 门店损耗金额
```

如果数据开发或财务口径负责人确认正式字段里的“全链路毛利额”已经包含门店损耗影响，就不能重复扣门店损耗。

## 14. 订购健康怎么算

订购健康看的是：

```text
门店进了多少货，19 点前能消化多少。
```

第一步，分计量类型计算售罄率。

计件商品：

```text
19点前售罄率 = 19点前销售数量 / 门店进货数量
```

称重商品：

```text
19点前售罄率 = 19点前销售重量 / 进货重量
```

如果需要从 Doris 小票明细补算 19 点前销售数量或销售重量，统一按有效交易、`inc_time < 19:00:00` 汇总 `weight`。`weight` 是商品行计价数量，算法里映射为销售标准量：称重商品表示计价重量，计件商品表示件数/份数/袋数/只数。Doris 本身没有单位字段，具体单位由商品基础表决定。

公斤和件数不能直接相加，也不能用到货金额去加权原始售罄率。

第二步，训练健康区间。

健康区间不是业务手工写死的 80%-100%，而是用历史 SKU 日样本训练出来。

训练范围：

```text
城市算法区域 + 品类颗粒度 + 品类 + 计量类型
```

算法会看历史上不同售罄率区间下的经营结果：

```text
净经营贡献是否较好
损耗是否健康
继续增加到货后，净经营贡献是否还明显增加
```

业务文档给出的核心判断是：

```text
如果售罄率很高，而且增加到货仍能带来正向净贡献，说明可能订购不足。
如果售罄率很低，而且增加到货导致损耗升高、净贡献下降，说明可能订购偏多。
中间那段更稳定、更赚钱的区间，就是健康区间。
```

第三步，计算订购健康分。

```text
售罄率落在健康区间内：健康度高
售罄率低于健康区间：可能进货偏多或动销不足
售罄率高于健康区间：可能进货偏少，有缺货风险
```

最终：

```text
order_health_score =
SQRT(综合售罄健康度 * 健康区间命中率得分)
```

## 15. 促销健康怎么算

促销健康仍然是算法里的一个正式维度。

但一期它的含义是：

```text
门店这个品类是否依赖常规优惠或时段折扣。
```

它不是在判断：

```text
某一次促销活动到底有没有带来真实增量。
```

### 15.1 一期用哪些字段

一期优先使用毛利损耗表里的日门店商品汇总字段。

| 计算内容 | 来源表 | 字段或公式 |
|---|---|---|
| 实际销售额 | 毛利损耗表 | 销售额 |
| 全日标准销售额 | 毛利损耗表 | 原价销售额 |
| 总优惠金额 | 毛利损耗表 | 折扣额 |
| 时段折扣金额 | 毛利损耗表 | 时段折扣额 |
| 常规优惠金额 | 毛利损耗表 | `MAX(折扣额 - 时段折扣额, 0)` |
| 19点前标准销售额 | Doris 小票商品明细表 | `SUM(usual_amt + discount_amt)`，条件 `inc_time < 19:00:00` |
| 19点前常规优惠金额 | Doris 小票商品明细表 | `SUM(discount_amt)`，条件 `inc_time < 19:00:00` 且不属于时段促销 |

Doris 小票字段中文含义：

| Doris 字段 | 中文含义 | 本算法怎么用 |
|---|---|---|
| `usual_amt` | 商品行实付金额 | 补算 19 点前实际销售额、19 点前标准销售额 |
| `discount_amt` | 商品行优惠金额，应付金额 - 实付金额 | 补算 19 点前优惠金额 |
| `is_hour_promotion` | 是否小时促销，1 是、0 否 | 识别时段促销交易 |
| `hour_discount_amt` | 会员当天同小时累计优惠金额 | 不直接按商品行求和 |
| `inc_time` | 交易发生时间 | 判断是否 19 点前 |

为什么不直接用 Doris 的 `hour_discount_amt` 求和：

```text
它是会员当天同小时累计优惠金额，
不是这一个商品行自己的时段折扣金额。
直接按商品行 SUM，可能重复累计。
```

所以一期时段折扣金额以毛利损耗表的“时段折扣额”为准。

### 15.2 一期计算哪些指标

常规优惠依赖：

```text
19点前常规优惠金额率 =
19点前常规优惠金额 / 19点前标准销售额
```

```text
19点前常规优惠销售占比 =
19点前有常规优惠的标准销售额 / 19点前标准销售额
```

时段折扣依赖：

```text
全日时段折扣金额率 =
时段折扣金额 / 全日标准销售额
```

```text
全日时段折扣销售占比 =
发生时段折扣的标准销售额 / 全日标准销售额
```

优惠后毛利质量：

```text
优惠商品毛利率 =
有优惠或时段折扣商品的全链路毛利额
/ 有优惠或时段折扣商品的实际销售额
```

如果没有任何优惠发生：

```text
优惠商品毛利率 = NOT_APPLICABLE
优惠依赖类指标按 0 依赖参与评分
```

### 15.3 促销健康分怎么合成

常规优惠依赖和时段折扣依赖越低越好。

优惠商品毛利率越高越好。

```text
常规优惠非依赖得分 =
SQRT(常规优惠金额率得分 * 常规优惠销售占比得分)
```

```text
时段折扣非依赖得分 =
SQRT(时段折扣金额率得分 * 时段折扣销售占比得分)
```

```text
promotion_health_score =
GEOMEAN_AVAILABLE(
  常规优惠非依赖得分,
  时段折扣非依赖得分,
  优惠后毛利质量得分
)
```

`GEOMEAN_AVAILABLE` 的意思是：

```text
只用能算出来的分项合成。
不能算的分项不填 0。
```

## 16. 损耗健康怎么算

损耗健康看的是：

```text
损耗是否拖累这个门店品类的经营贡献。
```

正式评分使用：

```text
损耗成本率 = 全日损耗成本金额 / 全日到货成本金额
```

其中：

```text
全日到货成本金额 = 门店商品日价格表的出库到店成本含税
```

损耗金额已确认不是零售价口径，而是成本口径，可以用于损耗健康计算。

损耗成本率越低，损耗健康分越高。

```text
loss_health_score = 100 * [1 - Phi(robust_z)]
```

## 17. 标准化是什么意思

七个维度里的指标单位不一样，不能直接相加。

例如：

```text
销售额是元
小票数是笔
会员数是人
损耗率是百分比
```

所以算法要先把每个指标转成 0-100 分。

正向指标：

```text
越高越好
例如销售额、会员数、SKU 数、毛利额
```

负向指标：

```text
越低越好
例如损耗成本率、常规优惠依赖率、时段折扣依赖率
```

业务文档使用的是稳健标准化：

```text
对数或带符号对数
+ 中位数 / MAD
+ 转成 0-100 分
```

它的作用是降低极端门店对整体评分的影响。

## 18. CRITIC 动态权重是什么意思

CRITIC 是一种自动算权重的方法。

它不是大模型，也不是训练一个神经网络。

它会看两个问题：

```text
这个维度在门店之间差异大不大？
这个维度和其他维度是不是重复？
```

差异越大、和其他维度重复越少，权重越高。

差异很小、或者和其他维度高度重复，权重越低。

七个一级维度会得到七个权重：

```text
W1 经营规模权重
W2 货盘宽度权重
W3 商品效率权重
W4 盈利能力权重
W5 订购健康权重
W6 促销健康权重
W7 损耗健康权重
```

综合分：

```text
category_score =
经营规模得分 * W1
+ 货盘宽度得分 * W2
+ 商品效率得分 * W3
+ 盈利能力得分 * W4
+ 订购健康得分 * W5
+ 促销健康得分 * W6
+ 损耗健康得分 * W7
```

如果某个维度不能计算：

```text
不填 0
只用剩余可用维度重新分配权重
```

## 19. 等级怎么生成

先得到每个门店品类的综合分。

然后在同一个比较组内做分层：

```text
同一个城市算法区域
+ 同一个品类颗粒度
+ 同一个品类
```

业务文档使用：

```text
Jenks 自然断点 + BIC
```

它的意思是：

```text
先看这些门店的分数天然分成几段最合理；
再判断分 1 档、2 档、3 档还是 4 档更稳定。
```

所以结果不一定永远是 A/B/C/D 四档。

可能是：

| 分层数量 | 输出等级 |
|---|---|
| 1 档 | 全部 B |
| 2 档 | A / B |
| 3 档 | A / B / C |
| 4 档 | A / B / C / D |

如果分层不稳定，就自动降档。

稳定性检查包括：

```text
重复抽样 500 次
每次抽取 80% 有效门店
同一等级数量出现比例 >= 80%
单门店等级一致率 >= 75%
最近 4 个滚动窗口中至少 3 次等级数量一致
```

## 20. 经营底线怎么处理

综合分高，不代表一定能保留高等级。

算法还有经营底线。

### 20.1 连续亏损

如果最近 3 个完整自然月，每个月净经营贡献都小于 0：

```text
最终等级最高只能到 B
```

### 20.2 严重损耗

算法会根据历史数据学习：

```text
损耗成本率升高到什么程度后，
净经营贡献开始变成非正。
```

这条边界就是严重损耗风险线。

如果某个门店品类的损耗成本率超过风险线，并且触发业务文档里的月度规则：

```text
最终等级最高只能到 B
```

如果历史数据不足或风险线不稳定：

```text
不强行发布损耗等级上限
只保留损耗健康分和诊断标记
```

### 20.3 数据质量

如果核心维度缺失过多：

```text
不生成正式等级
进入数据修复清单
```

如果只是个别维度缺失：

```text
继续计算
降低置信度
限制最高等级
```

## 21. 开发实际要怎么做

数据开发拿到开发版算法卡后，实际工作不是只写一条 SQL。

开发过程可以拆成：

```text
1. 建立输入表字段映射
2. 过滤有效交易和异常数据
3. 聚合到 日期 + 门店 + 商品
4. 再聚合到 数据周期 + 算法区域 + 门店 + 品类
5. 计算七个维度的原始指标
6. 做标准化
7. 计算 CRITIC 权重
8. 计算综合分
9. 做 Jenks/BIC 动态分层
10. 应用连续亏损、严重损耗、数据质量等等级上限
11. 输出 mart_store_category_level
12. 保存参数和解释信息，便于复核
```

业务解读版用于理解流程。

开发版算法卡需要继续把字段、公式、异常处理、输出表结构写到可执行粒度。

## 22. 业务验收看什么

验收时不要只看 A/B/C/D。

要分三层看。

第一层：数据是否对。

```text
门店数是否正确
品类映射是否正确
19 点前口径是否正确
有效在售 SKU 天是否正确
进货、毛利、折扣、时段折扣、损耗是否能对上经营报表
```

第二层：指标是否合理。

```text
A 级门店是否通常销售、动销、毛利、订购和损耗更健康
高销售但低毛利、高损耗门店是否被过度高估
售罄过高是否能被解释为订购不足风险
高优惠依赖门店是否被识别出来
```

第三层：等级是否稳定。

```text
同一品类的等级数量是否合理
门店等级是否频繁跳动
业务熟悉的强门店是否大体在高等级
业务熟悉的问题门店是否被识别出风险
等级变化是否能由经营变化、范围版本或参数版本解释
```

## 23. 现在还需要确认什么

这里只保留真正会影响开发落地的口径。

| 确认项 | 需要谁确认 | 为什么重要 |
|---|---|---|
| 全链路毛利额是否已经扣过门店损耗 | 数据开发 / 财务口径负责人 | 指标平台公式已包含供应链损耗额，但未看到门店损耗金额；如果正式字段已扣门店损耗，净经营贡献不能重复扣 |
| 优惠商品毛利率 V1 是否按日门店商品近似口径验收 | 数据开发 | 毛利损耗表已定义到营业日期 + 门店 + 销售商品编码；如果没有商品行级毛利，V1 按日门店商品近似，并在结果中标记口径 |

## 24. 不要做什么

```text
不要把门店品类等级理解成门店整体等级
不要跨未配置的城市算法区域比较
不要平均下一级品类等级得到上一级等级
不要把缺失值填 0
不要把公斤和件数直接合并成一个原始售罄率
不要把售罄率静默截断为 100%
不要固定强行切成 A/B/C/D
不要让高销售完全抵消连续亏损或严重损耗
不要把促销健康解释成促销效果归因
```

## 25. 一句话总结

门店品类等级算法的本质是：

```text
用同一城市算法区域、同一品类下的经营数据，
判断每个门店对这个品类的真实承载能力，
并把销售、货盘、品效、盈利、订购、优惠依赖和损耗综合成可追溯的等级。
```
