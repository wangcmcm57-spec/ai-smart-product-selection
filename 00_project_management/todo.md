## 4. 算法卡 01：会员画像算法

最新业务确认规则：

```text
业务确认日期：2026-07-20
开发版算法卡：03_算法卡_开发版/算法卡_01_会员画像.md
画像粒度：模型版本 + customer_id
区域归属：每个会员确定一个主归属区域
过滤：剔除 customer_id 为空、customer_id 以 6 开头、退货/取消/冲销/测试交易、非正销售数量或金额、同一会员单日超过 5 张小票的异常会员日
时间行为：捡漏型 / 上班族晚高峰型 / 常规时段型
捡漏型：终止标签，final_profile = 捡漏型，family/frequency/price 均为 NOT_APPLICABLE
非捡漏型：final_profile = 时间行为 + 家庭规模 + 消费频次 + 价格态度
时间行为冲突：比较 得分 / 自然断点阈值；差距 <= 0.05 时再比较天数、月数，仍相同则捡漏优先
家庭规模：仅非捡漏型计算，使用 19:00 前蔬菜直接规则 + 购物篮逻辑回归补充模型
消费频次：仅非捡漏型计算，monthly_shop_days_observed >=8 高频，4-8 中频，<4 低频
价格态度：仅非捡漏型计算，使用 19:00 前常规促销行为，不使用 19:30 后时段折扣
```

开发评审仍需确认：

```text
1. 小票表实际字段映射。
2. 销售金额字段的真实口径。
3. 促销金额、会员折扣、时段折扣字段是否到会员商品行级。
4. 工作日历是否可提供。
5. 蔬菜识别是否可稳定落到商品基础表。
6. 商品分类是否能稳定识别蔬菜、肉禽蛋、猪肉、水产。
7. 数据开发是否支持 Jenks 自然断点、熵权、逻辑回归和 5 折交叉验证。
8. 上海试跑后的阈值、模型参数和标签分布是否需要业务校准。
```

## 5. 算法卡 02：门店品类等级算法

源文档规则：

```text
输入：Doris 小票明细 + 商品映射 + 门店映射 + 毛利率 + 损耗率
粒度：区域组 + 城市 + 门店 + 大类 + 中类 + 小类
核心：门店等级不按全店打分，而是在同一品类内比较门店
评分：
销售规模得分 * 0.35
会员客数得分 * 0.20
全链路毛利额得分 * 0.15
门店毛利率得分 * 0.10
19点前销售占比得分 * 0.10
折扣健康度得分 * 0.05
损耗健康度得分 * 0.05
等级：A 前 30%，B 30%-55%，C 55%-80%，D 80% 以后
```

开发评审仍需确认：

```text
1. 销售规模得分内部权重：销售额 70%、小票数 20%、销售量 10% 是否接受。
2. 有效门店数少于 5 时是否标记“样本不足”。
3. 当前小票表 `weight` 是商品行计价数量，可作为销售标准量：称重商品表示计价重量，计件商品表示件数/份数/袋数/只数；Doris 本身没有单位字段，单位需从商品基础表取得。
4. 当前小票表没有独立促销折扣金额，促销折扣率是否暂不进入评分。
5. hour_discount_amt 是否可作为时段优惠金额使用。
6. 毛利、损耗缺失时是否按剩余权重重算，还是直接不评级。
7. A/B/C/D 分位规则是否继续沿用 30% / 55% / 80%。
```
