# 算法04：目标画像 SKU 表现输出前逐项核对

生成日期：2026-07-31

## 1. 本次核对结论

算法 04 可以输出业务解读版和开发版算法卡。

但开发版必须明确两类内容：

```text
1. 业务原文已经确认的算法规则。
2. 因 V1 数据现状需要补充的落地口径。
```

本次最重要的 V1 落地补充：

```text
1. 指标平台没有可直接用于算法 04 的 SKU 级 7天19点前复购结果。
   因此必须先产出 mart_sku_repurchase_7d_pre19。

2. 业务原文要求目标画像 SKU 毛利额 = 目标画像 SKU 销售额 - 目标画像 SKU 成本金额。
   但业务文档没有写交易行级成本缺失时如何分摊。
   V1 需要按日门店SKU成本或全链路毛利推导成本，再按目标画像销售额占比分摊。

3. V1 先按销售条码 SKU 计算。
   标准商品层先标记 SKU_ONLY，不强行做 SPU / 换码合并。

4. 商品属性缺失不阻断经营表现评分。
   只输出 ATTRIBUTE_INCOMPLETE，后续新品方向生成时再处理。
```

## 3. 十个业务确认项处理结果

| 编号 | 问题 | 当前处理 |
|---|---|---|
| 1 | 第一版是否允许按销售条码 SKU 计算，不做 SPU / 新旧码合并 | 允许。开发版写为 V1 `SKU_ONLY`，后续有可靠 SPU / 换码关系再升级 |
| 2 | 商品属性缺失是否不阻断 04 锚点评分 | 允许。输出 `ATTRIBUTE_INCOMPLETE`，不影响经营表现分，但不能自动组合新品 |
| 3 | 商品毛利额使用哪个口径 | 优先全链路毛利口径。开发版优先用毛利损耗表全链路毛利额推导成本 |
| 4 | 目标画像 SKU 毛利是否按销售额占比分摊 | 业务原文没有写分摊。V1 作为落地补充：日门店SKU成本按目标画像销售额占比分摊 |
| 5 | 没有促销活动表时是否用折扣作为代理 | V1 可做代理，但要打标 `PROMOTION_PROXY_V1` |
| 6 | 7天19点前复购是否进入 04 V1 | 必须进入。先计算 `mart_sku_repurchase_7d_pre19` |
| 7 | 7天复购口径 | 按业务原文：首次购买时间不限，第二次购买在第 1-7 个自然日且 19:00 前 |
| 8 | 19:30 后半小时折扣档是否只解释不进分 | 业务原文明确：只解释，不进入综合得分 |
| 9 | 标准销售量是否按商品单位区分 | V1 先用商品基础表“单位”识别。真实数据落地后抽样补单位映射 |
| 10 | 当前不可订不可售但历史表现好的 SKU 是否保留 | 业务原文明确保留为 `HISTORICAL_ANCHOR`，但不作为当前正式锚点 |
