# 算法02_门店品类等级_审阅清单

生成日期：2026-08-03

## 1. 审阅结论

算法 02 当前没有发现业务主算法缺口。开发版算法卡可以进入数据开发评审。

本清单只保留仍会影响开发落地、字段口径或试跑验收的红线。

## 2. 需要确认的红线

| 编号 | 确认项 | 需要谁确认 | 为什么重要 |
|---|---|---|---|
| R1 | `全链路毛利额` 是否已经扣过门店损耗 | 数据开发 / 财务口径负责人 | 若已扣门店损耗，净经营贡献不能再减一次；若未扣，需要按开发版默认口径扣减 |
| R2 | 门店商品每日可订可售表是否按数据合同覆盖 0 销售日 | 数据开发 | 有可售条件但 0 销售的日期必须进入有效营业日分母，否则日均指标和动销率会偏高 |
| R3 | 门店进货数量的单位口径 | 数据开发 | 称重商品售罄率需要实际进货重量；若数量不是重量，需要用商品基础表单位重量换算并标记 |
| R4 | 日期日历表是否提供节假日和异常日期 | 数据开发 / 业务 | 影响相似经营日、订购健康区间训练和异常日期剔除；缺失时只按星期类型和月份近似 |
| R5 | Jenks、CRITIC、Isotonic Regression 实现方式 | 数据开发 | 等级、权重和损耗风险线都依赖这些算法，需确认 Python/调度或 SQL 降级方案 |
| R6 | 上海试跑后 V1 默认参数是否接受 | 业务 / 数据开发 | CRITIC 回退、订购健康区间、损耗风险线等默认参数需要用真实结果复盘 |

## 3. 当前不作为问题的事项

以下事项已经明确，不再反复确认：

```text
毛利损耗表数据合同已定义到营业日期 + 门店 + 交易商品编码。
门店商品日价格表已定义到日期 + 门店 + 销售商品编码 + 验收商品编码。
门店商品每日可订可售表已定义到日期 + 门店 + 销售商品编码。
第一期没有促销活动表。
第一期促销健康使用优惠/时段折扣依赖诊断，不做促销因果评估。

```
