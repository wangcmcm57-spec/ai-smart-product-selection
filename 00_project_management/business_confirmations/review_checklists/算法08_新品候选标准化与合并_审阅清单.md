# 算法08_新品候选标准化与合并_审阅清单

更新时间：2026-08-18

这份清单只保留算法 08 V1 真正需要人工判断或项目评审的红线。开发主交付看开发版算法卡；本清单用于你、业务、商品、算法和数据开发快速对齐。

## 1. 已明确口径

| 已明确事项 | 当前口径 |
|---|---|
| 08 的角色 | 新品候选标准化、注册、合并、拆分、血缘和 09 快照输出 |
| 09 的角色 | 新品机会证据合成与风险门禁 |
| 08 是否做风险门禁 | 不做；当前货盘重复、历史失败、法规、毛利风险都交给 09 |
| 合并规则 | 只允许标准身份精确相等合并，不按名称相似或人工选择合并 |
| 采购前端作用 | 采购输入筛选条件，不改变候选身份、属性、证据、合并关系或状态 |
| 标准候选与范围候选 | `standard_candidate_id` 表示商品实体；`candidate_scope_result_id` 表示具体范围和价格方案 |
| 价格是否属于商品身份 | 不属于 `standard_candidate_id`；价格和成本属于范围结果 |
| 规则资产 V1 生成方式 | 已确认读取候选属性字典、商品命名规则、特殊必填规则和单位换算配置；业务/商品/质量只复核高频词、入名词、风险词和重点小分类规则 |
| 商品状态来源 | 商品状态由数据开发从 SAP POP 平台落 `dim_product_status`；`S` 商品计划上架开始/结束日期用于季节窗口 |
| 下游读取 | 09 读取 `mart_new_product_candidate_scope` 和相关血缘/快照字段 |

## 3. 现在需要确认什么

| 优先级 | 谁确认 | 需要确认什么 | 为什么重要 | 不确认时处理 |
|---|---|---|---|---|
| P1 | 算法/数据开发 | 算法 05 是否稳定输出候选价格可行性结果 ID、明确规格、建议售价、成本、成本上限、毛利底线/目标和状态 | 08 需要生成 `candidate_scope_result_id`，并判断是否可进入 09 | 无价格结果时输出 `NOT_READY_MISSING_PRICE_RESULT`，不进入 09 正式门禁输入 |
| P1 | 算法/数据开发 | 候选属性字典、商品命名规则、特殊必填规则和单位换算配置是否已落表或固化版本并写入版本字段 | 影响候选名称、候选 ID 和合并结果 | 未落表或缺版本时写注册异常，不进入正式候选名称 |
| P1 | 算法/数据开发 | 算法 06、07 候选输出字段是否冻结 | 影响来源快照、属性血缘、内外部合并和图片追溯 | 字段缺失进入异常表，不删除来源快照 |
| P1 | 数据开发/商品 | `dim_product_status` 是否按 SAP POP 来源落表，`S` 商品计划上架开始/结束日期是否齐全 | 影响季节候选状态、09 季节窗口留痕和后续季节开发动作 | S 日期缺失时写 `SEASON_WINDOW_INCOMPLETE`；无商品状态记录写 `UNKNOWN`；不得猜状态，也不得仅因日期缺失阻断 09 |
| P2 | 产品/后端/Agent | 未准备好进入 09 的候选，是否由 09、10、Agent 和查询服务统一过滤 | 防止采购误以为已进入门禁或已推荐 | `NOT_READY_MISSING_PRICE_RESULT`、`REGISTRATION_EXCEPTION` 不进入正式推荐结果 |

## 4. 给业务最短话术

算法 08 不是判断新品能不能做。

它要业务、商品和质量侧复核的是：

```text
1. 高频词是否被正确识别成属性。
2. 会进入新品名称的词是否可以入名。
3. 风险词、功能声称和食安相关词是否需要拦截或复核。
4. 重点小分类的商品命名规则是否符合商品开发习惯。
5. S 商品有没有计划上架开始和结束日期。
```

业务不需要逐字段看 8 张表，重点看：

```text
同一个候选有没有被正确合并；
不同规格有没有被正确拆开；
候选名称是不是具体且有证据；
没有证据的热词有没有被挡住；
08 有没有越界做了 09 的风险判断。
```

## 5. 不要再反复确认的问题

| 不要再问 | 正确写法 |
|---|---|
| Doris 小票数量字段是什么 | 算法 08 不直接从小票计算；如引用上游事实，按数据合同 `weight` 是商品行计价数量 |
| 毛利损耗表是否到日 + 门店 + SKU | 数据合同已定义为营业日期 + 门店编码 + 交易商品编码 |
| 可订可售表是否到日 + 门店 + SKU | 数据合同已定义为日期 + 门店编码 + 销售商品编码 |
| 08 是否排除当前在售重复 | 不排除；当前货盘重复由 09 门禁 |
| 08 是否判断历史失败 | 不判断；历史失败由 09 门禁 |
| 08 是否排序推荐优先级 | 不排序；优先级由 10 |
| 合并能否按名称相似 | 不能，只能按标准身份字段精确相等合并 |
