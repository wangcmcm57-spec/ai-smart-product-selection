## 3. V1 主要缺口归类

| 缺口 | 影响环节 | V1 处理 |
|---|---|---|
| 算法 08 标准候选和范围候选表需要按字段合同落库 | 09 读取的 `standard_candidate_id`、`candidate_scope_result_id`、候选快照、属性来源和候选 payload | 09 只接收算法 08 标记为 `READY_FOR_ALGORITHM_09` 或 `READY_WITH_ESTIMATED_COST` 的候选 |
| 门店商品每日可订可售表需要按数据合同稳定可读 | 当前货盘重复、历史状态变化、0 销售日判断 | 真实库已完整时直接映射；缺字段或粒度不完整时按合同加工补齐；不能用小票无销量替代可订/可售状态 |
| 商品结构化属性不完整 | 相似引擎、差异属性、法规字段提取、季节状态 | 读取算法 08 标准化后的候选属性；商品基础表不足部分写来源缺失或规则缺失 |
| 换码、替代、历史退出原因未形成正式数据合同 | 历史失败标签、当前货盘重复、候选静默修改判断 | V1 先用商品基础表 SPU 辅助标准实体归并；没有正式关系时不能硬拒绝历史失败，只能输出证据不足或灰区 |
| 法规知识库和确定性规则引擎未落库 | 法规、食品安全、标签、功能声称、知识产权门禁 | 作为 P1 红线；没有有效版本时核心门禁 `NOT_EVALUABLE` 并退回重构 |
| 历史失败模型与 K-medoids 情景库实现成本高 | 历史失败硬门禁、毛利压力 | 开发评审确认 V1 能实现到什么范围；不足时保留状态和证据不足，不伪造低风险 |
| 算法 05 价格可行性结果未就绪 | 价格成本毛利接口和毛利压力 | 09 不单独确认毛利配置，只读取 05 的正式结果；缺 05 结果时返回重构或不可评估 |
