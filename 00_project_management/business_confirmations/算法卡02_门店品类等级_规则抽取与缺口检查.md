# 算法卡 02：门店品类等级规则抽取与缺口检查

业务原文：`01_业务原始与补充文档/业务补充算法文档/算法卡_02_门店品类等级_业务提供原始版.md`  
当前结论日期：2026-07-20  
当前状态：已完成第一轮规则抽取，建议重写开发版算法卡 02。

## 1. 总体判断

业务提供的最新 02 文档已经不是旧版“固定权重 + 简单 ABCD 分层”的算法，而是一套完整的门店品类经营能力分层模型。

核心变化：

```text
1. 权重：七个一级维度使用 CRITIC 动态赋权，不再使用固定权重。
2. 分层：使用 Jenks 自然断点 + BIC 动态选择 1-4 组，不强制 ABCD。
3. 品类：大分类、中分类、小分类都要从底层重新聚合、重新评分，不能平均下一级等级。
4. 周期：最近 3 个完整自然月生成正式等级，最近 6 个月只用于稳定性和回退。
5. 底线：连续亏损、严重损耗、数据缺失、权重回退会限制最高等级。
6. 输出：不能只输出最终等级，必须保存指标、权重、参数、阈值、底线调整原因。
```

因此，项目里当前旧版 `03_算法卡_开发版/算法卡_02_门店品类等级.md` 需要重写，不建议在旧版基础上小修。

## 2. 业务目标

本算法用于判断：

```text
同一城市或业务配置城市群、同一品类颗粒度下，哪些门店具备更强的品类经营能力。
```

后续用途：

```text
1. 判断新品优先试点门店群。
2. 支撑门店群消费者画像贡献算法。
3. 支撑目标画像 SKU 表现算法。
4. 支撑新品机会推荐。
```

它不是：

```text
1. 不是门店整体等级。
2. 不是订货建议。
3. 不是全店综合经营评分。
4. 不是简单毛利分析。
```

## 3. 计算粒度

业务原文确认的正式粒度：

```text
模型版本
+ 范围版本
+ 数据周期
+ 城市或城市群
+ 门店
+ 品类颗粒度
+ 品类编码
```

建议正式结果表：

```text
mart_store_category_level
```

建议唯一键：

```text
model_version
scope_version
level_end_date
scope_type
scope_id
store_id
category_granularity
category_code
```

注意：

```text
category_granularity 支持 LARGE / MIDDLE / SMALL。
大分类、中分类、小分类分别从底层数据重算，不能取下级平均值。
```

## 6. 当前最大数据缺口

### 6.1 门店 SKU 每日在售货盘

业务原文要求：

```text
listing_status
listing_start_date
listing_end_date
临时停售
正式上架
正式下架
```

用途：

```text
计算有效在售 SKU 日
计算日均在售 SKU 数
计算 19 点前动销 SKU 数
计算单 SKU 日均销售产出和毛利产出
```

如果没有这类数据，货盘宽度、商品效率、订购健康都会受影响。

### 6.2 门店 SKU 每日实际收货

业务原文要求：

```text
actual_received_weight
actual_received_qty
arrival_cost_amt
```

用途：

```text
判断有效在售 SKU 日
计算 19 点前售罄率
训练售罄健康区间
计算损耗成本率
```

需要确认门店商品日价格表中的验收商品、门店进货金额、出库到店金额等字段，是否能稳定补足这些口径。

### 6.3 促销活动与优惠成本

业务原文要求：

```text
promotion_id
promotion_flag
discount_amt
促销活动时间
活动商品
处理组 / 对照组
```

促销健康算法使用 DID 或匹配方法。如果没有促销活动数据：

```text
没有促销时 promotion_health_score = NOT_APPLICABLE。
有促销但对照验证不通过时，得分为空，置信度低，禁止填 0。
```

这里需要业务和开发确认 V1 是否必须上线促销健康维度。

### 6.4 毛利是否已经扣损耗

业务原文要求必须提供：

```text
gross_profit_includes_loss_flag
```

否则“净经营贡献 = 全链路毛利额 - 损耗金额”可能重复扣损耗。

## 7. 核心算法步骤

按业务原文，02 算法流程应整理为：

```text
1. 确定模型版本、数据周期、比较范围、品类颗粒度。
2. 过滤有效交易、有效会员、有效营业日、有效在售 SKU 日。
3. 按门店 + 品类颗粒度聚合原始经营指标。
4. 对正向、负向、可为负指标做稳健标准化。
5. 计算七个一级维度：
   经营规模
   货盘宽度
   商品效率
   盈利能力
   订购健康
   促销健康
   损耗健康
6. 七个一级维度使用 CRITIC 动态赋权，生成综合分。
7. 使用 Jenks 自然断点生成候选分层。
8. 使用 BIC 选择 1-4 个等级数量。
9. 通过重复抽样和滚动窗口做稳定性验证。
10. 根据连续亏损、严重损耗、数据缺失、权重回退应用等级上限。
11. 输出最终等级、得分、权重、阈值、解释和底线调整原因。
```
