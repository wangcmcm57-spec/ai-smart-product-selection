# 算法10_新品推荐优先级与开发需求编排_导读

## 1. 一句话理解

算法 10 做的是：

```text
把已经通过门禁的新品候选，整理成前端和 Agent 能直接读取的推荐展示结果。
```

它回答的是“哪些候选优先看，页面和 Agent 怎么讲清楚”。

## 2. 它在链路里的位置

算法 10 是推荐结果进入应用层前的最后一步。

```text
09 判能不能过门禁
10 只处理通过推荐口径的候选
前端和 Agent 读取 10 的结果
```

## 3. 它读什么

它读算法 09 的门禁结果、证据合成结果、候选范围、价格方案和解释素材。
只读取已经通过或有条件通过推荐口径的候选，不重新判断底层门禁。

## 4. 它做什么

算法 10 会生成推荐优先级、推荐标签、展示摘要、推荐理由、范围汇总和审计信息。
它把复杂证据整理成采购能看懂、页面能展示、Agent 能解释的结果。

## 5. 它产什么

主输出是推荐优先级结果表、展示摘要表、推荐解释表、范围汇总表和运行审计表。
页面主要读推荐列表、推荐详情和批次追溯相关结果。

## 6. 它不做什么

```text
不重新找候选
不重新改商品名
不重新算价格和成本
不重新判断风险
不直接生成采购立项或供应商动作
```

算法名称里有“开发需求编排”，但 V1 已收窄为推荐展示版。

## 7. 下游谁用

前端读取它做推荐列表和详情。
后端 API 读取它做统一查询。
Agent Harness 读取它解释“为什么推荐这个”。
