# AI选品V1 项目导读

## 1. 这是个什么项目

AI 选品 V1 是一个给采购做新品开发推荐的项目。
它不是让大模型现场算数，也不是做门店订货，更不是做独立毛利分析工具。
它要做的是把内部经营数据、外部竞品数据和机会判断规则，整理成一套能追溯、能复核、能被前后端直接读取的推荐体系。

## 2. 这个项目的目标

项目目标很直接：

```text
把“什么新品值得做、为什么值得做、价格和风险怎么判断”变成稳定结果表。
```

V1 要解决的是采购找方向、看证据、看风险、看优先级的问题。
它不追求一次把所有下游动作都做完。

## 3. 整体过程怎么跑

```text
基础数据合同和质量校验
-> 离线算法 01～07 产出证据和锚点
-> 算法 08 把候选标准化和合并
-> 算法 09 做证据合成和风险门禁
-> 算法 10 生成可展示的推荐结果
-> 后端 API 读取结果表和证据表
-> Harness 抽参数、调接口、做轻量重排
-> 大模型只解释结构化结果
-> 前端展示并收集反馈
```

这条链路里，真正重计算的部分都在离线表里完成。
采购查询时只是读结果，不是现场重算算法。

## 4. 最终会产出什么

V1 的核心产出不是一句“推荐”。
真正交付给开发和业务的是一组稳定表和可追溯结果：

| 产出 | 作用 |
|---|---|
| 基础数据合同 | 定义表粒度、主键、字段和口径 |
| 算法 01～10 结果表 | 承载画像、锚点、候选、门禁和推荐结果 |
| 证据表 | 说明为什么推荐、为什么拦截 |
| 后端 API | 给页面和 Harness 统一查询入口 |
| 反馈表 | 记录采购反馈，供后续复盘 |

## 5. 谁负责哪一段

| 角色 | 负责什么 |
|---|---|
| 产品 / 项目 | 定义业务范围、流程边界、验收口径 |
| 数据开发 | 建表、跑离线算法、维护结果表 |
| 后端开发 | 写查询、证据、反馈和日志 API |
| Agent / Harness 开发 | 写意图识别、参数抽取、工具路由和护栏 |
| 前端开发 | 负责推荐列表、详情和反馈入口 |

## 6. Harness 是什么

Harness 是 Agent 的控制层，不是算法计算层。
它负责把自然语言问题转成结构化参数，再决定调用哪个后端接口，最后把结果交给大模型解释。

它做这些事：

```text
识别意图
抽取参数
缺参追问
调用固定 API
轻量重排
输出解释
```

它不做这些事：

```text
不直接读 Doris 明细表
不实时重算算法
不编造没有返回的证据
不改写离线推荐结论
```

## 7. V1 不做什么

V1 不做多城市对比，不做采购手工录入候选商品让系统实时判断，不做大模型直接扫明细表，也不做推荐结论的在线人工改写。
V1 的重点是先把离线结果算稳，把在线查询边界定清楚。

## 8. 开发先看什么

如果是第一次进入这个项目，建议按这个顺序看：

```text
项目导读
链路图导读
算法 01～10 导读
03_algorithm_cards/business_readable/
03_algorithm_cards/developer_version/
```

一句话总结：

```text
这个项目的核心，不是“会不会问答”，而是“能不能把新品机会算清楚、讲清楚、查清楚”。
```
