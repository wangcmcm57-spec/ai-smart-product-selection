# 城市算法区域映射表字段

文档用途：给业务确认华东一期会员画像算法使用的城市到算法区域映射口径。  
适用算法：算法卡 01：会员消费行为画像。  
建议落表：`dim_city_algorithm_region`。

## 1. 这张表解决什么问题

会员画像最终是一人一条标签，但算法里的熵权、自然断点、逻辑回归参数需要按算法区域分别计算。

华东一期如果业务确认算法区域按城市归并，则不需要门店级映射，只需要确认：

```text
城市 -> 算法区域
```

计算时链路如下：

```text
小票 store_id
-> 门店基础表
-> 城市
-> 城市算法区域映射表
-> 会员主归属区域 primary_region
```

## 2. 表规则

表粒度：

```text
一行 = 一个城市 + 一个算法区域映射生效周期
```

主键：

```text
城市 + 生效开始日期
```

关联要求：

```text
城市必须能和门店基础表里的城市字段对齐。
算法区域名称用于会员画像的主归属区域、区域熵权、Jenks 阈值和逻辑回归参数训练。
```

## 3. 业务需要提供的字段

| 字段名 | 示例 | 是否必须 | 说明 |
|---|---|---|---|
| 城市 | 上海 / 杭州 / 宁波 / 苏州 | 必须 | 门店基础表中的城市名称 |
| 算法区域编码 | SH / NBHZ / SSCQ | 必须 | 算法区域唯一编码，由业务确认 |
| 算法区域名称 | 上海 / 宁波杭州 / 苏锡常及其他 | 必须 | 算法训练和参数计算使用的区域口径 |
| 生效开始日期 | 2026-07-01 | 必须 | 该映射开始生效日期 |
| 生效结束日期 | 空 / 2026-12-31 | 建议 | 当前有效映射可以为空，历史映射需要回填结束日期 |
| 是否当前有效 | 1 / 0 | 必须 | 1 表示当前有效，0 表示历史无效 |
| 映射确认人 | 张三 | 建议 | 业务确认人 |
| 映射确认日期 | 2026-07-20 | 建议 | 业务确认日期 |
| 数据更新时间 | 2026-07-20 10:00:00 | 必须 | 数据同步或维护时间 |
| 备注 | 嘉兴归入苏锡常及其他 | 建议 | 边界城市或临时调整说明 |

## 4. 华东一期映射口径待业务确认

以下只是待确认模板，不代表最终业务口径。

| 城市 | 建议算法区域名称 | 待业务确认点 |
|---|---|---|
| 上海 | 上海 | 上海是否单独作为算法区域 |
| 杭州 | 宁波杭州 | 杭州是否归入宁波杭州 |
| 宁波 | 宁波杭州 | 宁波是否归入宁波杭州 |
| 苏州 | 苏锡常及其他 | 苏州是否归入苏锡常及其他 |
| 无锡 | 苏锡常及其他 | 无锡是否归入苏锡常及其他 |
| 常州 | 苏锡常及其他 | 常州是否归入苏锡常及其他 |
| 其他华东城市 | 苏锡常及其他 | 需要业务明确“其他”包含哪些城市 |

## 5. 数据质量要求

```text
1. 同一城市在同一日期只能命中一个有效算法区域。
2. 参与会员画像的门店城市必须全部能匹配到有效算法区域。
3. 算法区域名称必须稳定，不允许同义混写。
4. 映射变化必须保留历史生效周期，不能直接覆盖旧映射。
```

## 6. 什么时候才需要门店级例外

默认不需要门店级映射。

只有出现以下情况，才需要额外补一张“门店算法区域例外表”：

```text
1. 同一个城市里，不同门店要归入不同算法区域。
2. 某些门店不参与会员画像计算。
3. 某些特殊渠道门店不能按城市统一归属。
```

如果没有这些例外，城市级映射已经足够。

## 7. 给业务的确认问题

```text
1. 华东一期算法区域是否确定为：上海、宁波杭州、苏锡常及其他？
2. 每个华东城市分别归入哪个算法区域？
3. “苏锡常及其他”里的“其他”具体包含哪些城市？
4. 是否存在同一城市内门店归属不同算法区域的例外？
5. 是否存在不参与会员画像计算的特殊门店？
```
