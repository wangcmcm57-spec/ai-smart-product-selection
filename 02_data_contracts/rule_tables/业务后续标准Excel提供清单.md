# 业务后续标准 Excel 提供清单

本文件说明后续业务应该按哪些标准 Excel sheet 提供 AI 选品规则数据。

首版因为业务给的是不标准 Excel，所以项目侧已经转换为标准 Excel 和标准 CSV。后续业务更新时，不再按 B1、B3、B4 的原始格式提供，而是按本清单的标准 sheet 提供。

## 1. 标准交付链路

```text
首版：业务不标准 Excel -> 项目侧转换为标准 Excel + 标准 CSV -> 开发读取标准 CSV 落 Doris -> 算法读取 Doris 规则表
后续：业务按标准 Excel sheet 提供更新 -> 校验字段、主键、版本、生效日期和状态枚举 -> 导出标准 CSV -> 开发落 Doris -> 算法读取 Doris 规则表
```

开发优先使用标准 CSV 落 Doris。标准 Excel 用于业务填报、业务复核、项目侧校验和生成标准 CSV。

## 2. 标准 Excel 通用要求

```text
1. 一个更新批次建议提供一个标准 Excel 工作簿。
2. sheet 名称使用下方清单中的标准名称。
3. 每个数据 sheet 使用固定双表头：第 1 行中文字段名，第 2 行英文字段名，第 3 行开始填写数据。
4. 不使用合并单元格、多层表头、颜色含义、批注含义或隐藏列作为正式数据。
5. 百分比字段统一填 0 到 1 之间的小数，例如 9% 写 0.09。
6. 日期字段统一填 yyyy-mm-dd。
7. 状态枚举必须使用表合同中的英文枚举。
8. 第 2 行英文字段名必须和对应表合同、CSV 表头一致。
9. 每次更新必须能识别规则版本、生效开始日期、是否当前有效、来源文件和数据更新时间。
```

`导入总览`、`字段说明`、CSV、校验报告和预览图由项目侧或数据侧生成，业务不需要手工维护。

商品状态不在本规则 Excel 清单中维护。当前商品状态已经调整为基础数据表 `dim_product_status`，由数据开发从 SAP POP 平台按区域、商品名称、商品编码和商品状态提供。

## 4. 当前最需要业务补充的内容

| 优先级 | 标准 sheet | 当前问题 | 后续处理 |
|---|---|---|---|

| P1 | `07_候选属性字典` | 986 条属性词为 `REVIEW_REQUIRED` | 业务、商品或质量侧复核高频词、入名词和风险词 |
| P1 | `09_分类命名合规` | 5 条分类命名合规规则为 `REVIEW_REQUIRED` | 质量、法务或商品侧确认内部分类映射和规则状态 |

## 5. 映射说明文件是否保留

`import_specs/` 下的映射说明文件需要保留。

保留原因：

```text
1. 解释首版不标准 Excel 是怎么转换成标准表的。
2. 支持后续追溯某个字段来自原始文件的哪一列。
3. 支持重跑首版标准导入数据包。
4. 处理历史非标准 Excel 或业务再次提供非标准材料时有转换依据。
```

但后续业务常规更新不再以 `import_specs/` 作为填报入口，而是以本文件和各标准表合同为准。

商品状态类数据不再走本规则 Excel 清单，开发从 SAP POP 平台接入并落表，交付以基础表合同 [商品状态表](../base_tables/dim_product_status_商品状态表.md) 为准。
