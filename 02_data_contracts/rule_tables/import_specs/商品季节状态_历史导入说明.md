# 商品季节状态历史导入说明

当前定位：本文件仅保留历史口径说明，不再作为后续业务填报模板，也不再作为规则配置表导入入口；其中的销售季窗口字段不是当前商品状态基础表的开发字段合同。

最新口径：商品状态改为基础数据表 `dim_product_status`，由数据开发从 SAP POP 平台按区域、商品名称、商品编码和商品状态提供。`S` 状态本身代表季节品，当前 P0 不维护销售季名称、开始时间、结束时间或每年重复规则。

对应表合同：[商品状态表](../../base_tables/dim_product_status_商品状态表.md)

历史目标表：`dim_product_season_window`。

历史口径说明：首版曾考虑让业务按商品、SPU 或品类提供季节状态和销售季窗口，导入到规则配置表。当前已调整为 SAP POP 基础表口径，本文件只用于理解旧口径，不作为开发落表依据。

## 1. 历史草稿为什么提出销售季窗口

算法 04、06、08 需要区分：

```text
销售季内没有表现：可能是真的表现弱
销售季外没有销售：不能直接判断消费者不喜欢
```

因此历史草稿曾提出单独维护销售季窗口。当前 P0 商品状态表只承接 SAP POP 的 A/O/S/D/B 状态，不再把销售季窗口作为业务标准 Excel 或基础表必填字段。

## 2. 历史建议业务提供模板

| 业务字段 | 是否必须 | 填写说明 |
|---|---|---|
| 适用对象类型 | 必须 | SKU、SPU、中类、小类、一级品类 |
| 适用对象编码 | 条件必须 | 如果业务能提供编码，必须填写 |
| 适用对象名称 | 必须 | 商品、SPU 或品类名称 |
| 是否季节商品 | 必须 | 是、否 |
| 销售季名称 | 条件必须 | 季节商品必填，例如大闸蟹季、年货季 |
| 销售季开始月日 | 条件必须 | 每年重复季节填写，格式 MM-DD |
| 销售季结束月日 | 条件必须 | 每年重复季节填写，格式 MM-DD |
| 销售季开始日期 | 条件必须 | 只对特定年份生效时填写，格式 yyyy-mm-dd |
| 销售季结束日期 | 条件必须 | 只对特定年份生效时填写，格式 yyyy-mm-dd |
| 是否每年重复 | 必须 | 是、否 |
| 备注 | 建议 | 业务补充说明 |

## 3. 历史字段映射

| 业务模板字段 | 目标字段 | 转换规则 |
|---|---|---|
| 系统生成 | `season_rule_version` | 生成 `SEASON_2026_V1` |
| 适用对象类型 | `product_scope_type` | SKU 转 `SKU`；SPU 转 `SPU`；中类转 `CATEGORY_LEVEL2`；小类转 `CATEGORY_LEVEL3`；一级品类转 `CATEGORY_LEVEL1` |
| 适用对象编码 | `product_scope_code` | 原样写入；缺失时从 `dim_sku` 映射 |
| 适用对象名称 | `product_scope_name` | 原样写入 |
| 是否季节商品 | `is_seasonal` | 是转 1，否转 0 |
| 销售季名称 | `season_name` | 原样写入 |
| 销售季名称 | `season_id` | 系统生成稳定 ID |
| 销售季开始月日 | `season_start_month_day` | 原样写入，格式校验为 `MM-DD` |
| 销售季结束月日 | `season_end_month_day` | 原样写入，格式校验为 `MM-DD` |
| 销售季开始日期 | `season_start_date` | 转成 date |
| 销售季结束日期 | `season_end_date` | 转成 date |
| 是否每年重复 | `repeat_yearly` | 是转 1，否转 0 |
| 是否季节商品 | `season_status` | 否写 `YEAR_ROUND`；是写 `IN_SEASON`，算法运行时再按日期判断是否当期在季 |
| 系统生成 | `effective_start_date` | 使用配置确认日期 |
| 系统生成 | `effective_end_date` | 当前有效版本为空 |
| 系统生成 | `is_active` | 当前版本写 1 |
| 系统生成 | `source_file` | 写来源文件名或来源系统 |
| 系统生成 | `source_sheet` | 写来源 sheet 名；非 Excel 来源可为空 |
| 项目维护 | `confirmed_by` | 有确认人则写确认人；没有可为空 |
| 系统生成 | `updated_at` | 导入时间 |

## 4. 历史异常处理

| 场景 | 处理方式 |
|---|---|
| 是否季节商品为空 | 阻断导入 |
| 季节商品缺销售季名称 | 阻断导入 |
| 季节商品没有任何开始和结束时间 | 阻断导入 |
| 每年重复但月日格式错误 | 阻断导入 |
| 不重复但具体日期为空 | 阻断导入 |
| 对象名称无法映射编码 | 可导入名称，但记录待映射 |

## 5. 当前开发校验以基础表为准

当前开发校验见：

```text
02_data_contracts/base_tables/dim_product_status_商品状态表.md
```

历史校验口径如下，仅用于追溯：

```text
1. 同一 season_rule_version + product_scope_type + product_scope_code + season_id 只能有一条 is_active=1 的记录。
2. repeat_yearly=1 时必须填写 season_start_month_day 和 season_end_month_day。
3. repeat_yearly=0 时必须填写 season_start_date 和 season_end_date。
4. is_seasonal=0 时 season_status 必须是 YEAR_ROUND。
5. 算法不能把销售季外无销量当作商品表现差。
```
