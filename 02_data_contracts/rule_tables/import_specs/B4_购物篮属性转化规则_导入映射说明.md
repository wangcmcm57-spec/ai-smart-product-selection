# B4 购物篮属性转化规则导入映射说明

来源文件：`B4-哪些购物篮关联能够转化为新品属性.xlsx`

核心来源 sheet：`算法6主材料+配料，正向`

目标表：`dim_basket_attribute_transfer_rule`

对应表合同：[购物篮属性转化规则表](../dim_basket_attribute_transfer_rule_购物篮属性转化规则表.md)

## 1. 源文件结构

核心 sheet 是矩阵表，不是普通明细表：

```text
第 1 行：说明列，例如分类、配方型品类、品类保持（搭配）
第 2 行开始：规则数据
第 1 列：锚点品类层级，例如中分类、大分类
第 2 列：配方型品类，也就是锚点 A 所属品类
第 3 列以后：允许转成新品属性的关联品类 B
```

示意：

```text
中分类 + 牛肉类 + 根茎类
中分类 + 牛肉类 + 瓜果类
中分类 + 牛肉类 + 调味类
```

导入时必须把矩阵转成长表。

## 2. 导入目标

把 Excel 的一行多列搭配关系拆成多条规则：

```text
一行 = 一个规则版本 + 一个锚点品类 A + 一个关联品类 B + 一个允许转化判断
```

该表只回答：

```text
购物篮里经常和 A 一起出现的 B，能不能作为 A 所在品类的新品属性。
```

该表不计算 A/B 关联强度。关联强度仍由算法 06 用小票数据计算。

## 3. 字段映射

| Excel 位置或来源 | Excel 原始含义 | 目标字段 | 转换规则 |
|---|---|---|---|
| 系统生成 | 购物篮规则版本 | `basket_rule_version` | 生成 `BASKET_ATTR_2026_V1` |
| 第 1 列 `分类` | 锚点品类层级 | `anchor_category_level` | `中分类` 转 `CATEGORY_LEVEL2`；`大分类` 转 `CATEGORY_LEVEL1`；其他值进入待复核 |
| 第 2 列 `配方型品类` | 锚点品类名称 | `anchor_category_name` | 原样写入 |
| 品类映射 | 锚点品类编码 | `anchor_category_code` | 从 `dim_sku` 或品类字典映射；无法唯一映射时为空并留痕 |
| 第 3 列以后非空单元格 | 关联品类名称 | `related_category_name` | 每个非空品类拆成一行 |
| 品类映射 | 关联品类层级 | `related_category_level` | 优先按 `dim_sku` 品类映射；无法判断时默认按 `CATEGORY_LEVEL2` 入库但规则状态写 `REVIEW_REQUIRED` |
| 品类映射 | 关联品类编码 | `related_category_code` | 从 `dim_sku` 或品类字典映射；无法唯一映射时为空并留痕 |
| 来源 sheet 名称 | 转化类型 | `transfer_type` | `算法6主材料+配料，正向` 默认写 `INGREDIENT`；后续业务区分配料和搭配时发新版本 |
| 来源 sheet 含义 | 是否允许转新品属性 | `is_allowed_transfer` | 该 sheet 中展开出的规则统一写 1 |
| 来源 sheet 含义 | 属性维度 | `attribute_dimension` | 默认写 `配料`；如果后续区分搭配、口味、场景，发新版本 |
| 算法 06 口径 | 未覆盖处理方式 | `not_covered_action` | 固定写 `CATEGORY_RULE_NOT_CONFIGURED` |
| 导入校验 | 规则状态 | `rule_status` | 编码和名称都能唯一映射写 `ACTIVE`；任一侧无法映射写 `REVIEW_REQUIRED` |
| 系统生成 | 生效开始日期 | `effective_start_date` | 使用配置确认日期；如需 2026 年统一规则，可写 `2026-01-01` |
| 系统生成 | 生效结束日期 | `effective_end_date` | 当前有效版本为空 |
| 系统生成 | 是否当前有效 | `is_active` | 当前版本写 1 |
| 系统生成 | 来源文件 | `source_file` | 写来源 Excel 文件名 |
| 系统生成 | 来源 sheet | `source_sheet` | 写 `算法6主材料+配料，正向` |
| 系统生成 | 数据更新时间 | `updated_at` | 导入时间 |

## 4. 不导入生产规则的 sheet

| Sheet | 当前处理方式 | 原因 |
|---|---|---|
| `Sheet1` | 不导入 `dim_basket_attribute_transfer_rule` | 这是上海/华东商品清单参考，不替代正式 `dim_sku` |
| `Sheet2` | 不导入正式规则 | 无稳定表头，当前只作来源审计或人工确认材料 |
| `Sheet3` | 不导入正式规则 | 无稳定表头，当前只作来源审计或人工确认材料 |

如果业务后续说明 `Sheet2`、`Sheet3` 的规则含义，需要新增导入版本或单独规则表，不允许开发自行猜含义。

## 5. 矩阵转长表规则

```text
for each row in sheet:
  anchor_category_level = 第 1 列
  anchor_category_name = 第 2 列
  for each non-empty cell from 第 3 列 to last related category column:
    related_category_name = cell value
    insert one rule row
```

空单元格不生成规则。

## 6. 异常处理

| 场景 | 处理方式 |
|---|---|
| 锚点品类为空 | 阻断该行导入 |
| 关联品类为空 | 跳过该空格，不生成规则 |
| 锚点品类无法映射编码 | 可导入中文名称，但 `rule_status` 写 `REVIEW_REQUIRED` |
| 关联品类无法映射编码 | 可导入中文名称，但 `rule_status` 写 `REVIEW_REQUIRED` |
| 同一版本下 A/B 关系重复 | 去重后保留一条；如果转化类型冲突则阻断导入 |

## 7. 开发校验

```text
1. 同一 basket_rule_version + anchor_category_name + related_category_name 只能有一条 is_active=1 的记录。
2. is_allowed_transfer 必须为 1，因为该来源 sheet 只沉淀正向允许规则。
3. 未在该表出现的 A/B 关系，算法 06 不能默认允许转属性。
4. 缺规则时算法 06 输出 CATEGORY_RULE_NOT_CONFIGURED。
```
