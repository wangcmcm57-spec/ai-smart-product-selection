# 用户确认价格点规则导入映射说明

来源：用户已确认的 V1 价格点规则。

目标表：`dim_price_point_rule_config`

对应表合同：[价格点规则配置表](../dim_price_point_rule_config_价格点规则配置表.md)

## 1. 已确认口径

V1 不要求业务提供完整价格阶梯表，先按以下规则生成价格点：

```text
默认每 1 元一个价格点
价格上下限由算法 05 的消费者价格带决定
不同品类按不同价格尾数生成可执行价格点
V1 推荐计算范围为蔬菜、水果、肉禽蛋、冷藏加工、预制菜、水产；猪肉类不进入推荐价格点计算
水产 kg 计价使用 0.98，盒装使用 0.90
```

## 2. 源配置

当前已确认的价格尾数覆盖全部 6 个推荐计算大类。水产按计价方式区分，kg 计价使用 0.98，盒装使用 0.90。

| 品类 | 单位 | 尾数 |
|---|---|---:|
| 蔬菜 | kg | 0.98 |
| 水果 | kg | 0.98 |
| 肉禽蛋 | kg | 0.90 |
| 冷藏加工 | 份/个 | 0.90 |
| 预制菜 | 份/个 | 0.90 |
| 水产 | kg | 0.98 |
| 水产 | 盒 | 0.90 |

## 3. 字段映射

| 配置来源 | 原始含义 | 目标字段 | 转换规则 |
|---|---|---|---|
| 系统生成 | 价格规则版本 | `price_rule_version` | 生成 `PRICE_POINT_2026_V1` |
| 源配置 `品类` | 品类名称 | `category_name` | 原样写入；后续和 `dim_sku` 品类名称对齐 |
| 品类映射 | 品类层级 | `category_level` | V1 默认按一级品类映射，写 `CATEGORY_LEVEL1`；如果 `dim_sku` 口径显示为中类或小类，按实际映射调整 |
| 品类映射 | 品类编码 | `category_code` | 从 `dim_sku` 或品类字典映射；无法唯一映射时为空并留痕 |
| 源配置 `单位` | 计价单位 | `unit` | 原样写入；`份/个` 表示该品类可同时适用份或个 |
| 源配置 `尾数` | 价格尾数 | `price_tail` | 写为小数，例如 0.98、0.90 |
| 已确认口径 | 价格点步长 | `price_step_amt` | 固定写 1.00 |
| 已确认口径 | 价格上下限来源 | `price_bound_source` | 固定写 `CONSUMER_PRICE_BAND` |
| 算法 05 口径 | 是否允许扩展价格带 | `allow_extended_band_flag` | V1 默认写 1，表示谨慎试点可使用扩展价格带 |
| 系统生成 | 生效开始日期 | `effective_start_date` | 使用配置确认日期；如需 2026 年统一配置，可写 `2026-01-01` |
| 系统生成 | 生效结束日期 | `effective_end_date` | 当前有效版本为空 |
| 系统生成 | 是否当前有效 | `is_active` | 当前版本写 1 |
| 系统生成 | 来源文件 | `source_file` | 写 `USER_CONFIRMED` |
| 系统生成 | 来源 sheet | `source_sheet` | 非 Excel 来源可为空 |
| 项目维护 | 配置确认人 | `confirmed_by` | 有确认人则写确认人；没有可为空 |
| 项目维护 | 配置确认日期 | `confirmed_date` | 写用户确认日期 |
| 系统生成 | 数据更新时间 | `updated_at` | 导入时间 |

## 4. 价格点生成规则

算法 05 读取本表后，在消费者价格带内枚举价格点：

```text
候选价格点 = 整数元 + price_tail
候选价格点 >= price_band_lower
候选价格点 <= price_band_upper
整数元按 price_step_amt = 1.00 递增
```

例子：

```text
消费者价格带：9 元到 15 元
尾数：0.98
可执行价格点：9.98、10.98、11.98、12.98、13.98、14.98
```

## 5. 异常处理

| 场景 | 处理方式 |
|---|---|
| 商品品类没有价格点规则 | 算法 05 输出价格点规则缺失状态，不自行猜尾数 |
| 商品单位和规则单位不匹配 | 优先按商品基础表计价单位匹配；仍不匹配则进入待复核 |
| 同一品类同一单位有多个当前有效尾数 | 阻断导入 |
| price_tail 不在 0 到 1 之间 | 阻断导入 |

## 6. 开发校验

```text
1. 同一 price_rule_version + category_name + unit 只能有一条 is_active=1 的记录。
2. price_step_amt V1 必须等于 1.00。
3. price_bound_source V1 必须等于 CONSUMER_PRICE_BAND。
4. 所有价格尾数必须大于等于 0 且小于 1。
```
