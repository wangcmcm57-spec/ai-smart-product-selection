# AI 选品 V1 运行时序

本文给开发说明 AI 选品 V1 的运行顺序。它不展开每张算法卡的字段和公式，只回答：

```text
哪些任务离线批量算？
哪些结果表先产出？
采购查询时后端和 Agent 读什么？
反馈如何回流到下一轮迭代？
```

## 1. 一句话原则

```text
离线算法先把结果表算好；
在线查询只读取正式结果表和证据表；
Agent 负责理解问题、调用接口、组织解释，不直接扫描小票实时重算算法。
```

## 3. A 段：离线批量产表

离线批量任务由数据开发和调度系统负责。

```text
基础数据准备
-> 数据合同与质量校验
-> 算法 01、02 产出上游正式表
-> 算法 03 连接会员画像和门店品类等级
-> 算法 04～06 产出 SKU 表现、价格带和购物篮证据
-> 算法 07 产出外部趋势、竞品和公开证据
-> 算法 08 做新品候选标准化与合并
-> 算法 09 做新品机会证据合成与风险门禁
-> 算法 10 做推荐优先级和开发需求编排
-> 沉淀 AI 新品机会推荐结果表
```

运行要注意：

```text
01 和 02 可以在基础数据满足后并行产出。
03 必须读取 01 和 02 的正式结果。
04～06 继续读取 01～03 的结果和基础经营数据。
07～10 按顺序进入机会引擎，先外部证据，再候选标准化，再风险门禁，最后编排推荐结果。
前端和 Agent 查询时读取已沉淀结果，不实时重算离线算法。
```

## 4. B 段：在线查询与解释

在线链路由采购工作台、Agent Harness、后端 API 和大模型解释层负责。

```text
采购输入查询条件
-> Harness 识别意图并抽取结构化参数
-> Harness 选择固定工具 / 后端 API
-> 后端读取 AI 新品机会推荐结果表
-> 后端按需读取算法证据表
-> Harness 做在线轻量重排和结果组装
-> 大模型解释推荐理由、价格区间、风险提示和试点建议
-> 前端展示结果
-> 采购反馈进入反馈表，供后续复盘和算法迭代
```

开发要注意：

```text
采购输入的是筛选条件，不是让系统实时重新训练算法。
大模型不直接读 Doris 明细表。
后端接口优先读取正式结果表，再按推荐 ID 查询证据明细。
Harness 负责工具调用和轻量重排，不负责离线算法重算。
反馈数据先沉淀，不要求立刻实时影响当次推荐结果。
第 8 步“下一轮复盘和迭代”回到 A 段离线批量产表链路，不回到 B 段在线查询链路。
```

## 5. 和完整架构图的关系

```text
完整架构图：讲项目分几层，每层负责什么。
运行时序图：讲一次离线调度和一次在线查询分别怎么走。
算法卡：讲每个算法具体怎么建表、算字段、验收。
```

开发评审时建议先看整体架构和 Agent 运行架构，再看本时序，最后进入算法 01～03 的开发版算法卡。
