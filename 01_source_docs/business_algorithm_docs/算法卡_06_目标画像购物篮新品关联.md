# 算法卡 06：目标画像购物篮新品关联算法

文档状态：业务规则已确认  
适用范围：从高表现锚点商品的真实购物篮中提炼新品属性，形成具象新品候选  
正式评估周期：与算法 02—05 使用同一个最近 3 个数据完整自然月  
模型更新：每月正式更新；商品映射、上下架时间或小分类新品规则变化时重算  
确认日期：2026-07-27

## 1. 算法澄清表

| 项目 | 业务问题 | 已确认规则 |
|---|---|---|
| 算法名称 | 这个算法叫什么 | 目标画像购物篮新品关联算法 |
| 业务目标 | 解决什么问题 | 以算法 04 高表现锚点商品为起点，从目标画像真实小票中找到可用于新品开发的具体商品或食材属性 |
| 业务边界 | 是否同时做促销、陈列和订购 | 不做；全部逻辑只服务新品开发，促销、时段折扣和完整餐食关系只用于防止误判 |
| 计算对象 | 从哪些商品开始 | 优先使用算法 04 `is_formal_anchor=1` 的正式锚点；回退只能使用证据充分的相对高表现商品或采购明确选定的商品，并标记 `EXPLORATORY_ANCHOR` |
| 计算粒度 | 一条正式规则代表什么 | 周期 + 城市/城市群 + 叶子小分类 + 门店等级群 + 消费者类型 + 锚点标准商品 + 关联标准商品 + 方向 + 篮子类型 |
| 上游依赖 | 依赖哪些算法 | 算法 01 会员画像、算法 02 门店品类等级、算法 03 门店群消费者贡献、算法 04 锚点 SKU、算法 05 规格和价格可行性 |
| 购物篮定义 | 一个篮子是什么 | 一张真实小票是一个篮子；同一会员同日多票不合并 |
| 商品粒度 | 使用 SKU 还是品类 | SKU 用于追溯，标准商品层用于正式 FP-Growth，小分类只用于结构诊断；不得用泛品类冒充关联商品 |
| 映射合并 | 哪些编码可以合并 | 只有正式 SPU、换码或替代关系才能合并；商品名称相似不能自动并码 |
| 发现算法 | MBA 还是 FP-Growth | MBA 是业务分析框架；正式技术链是 FP-Growth 发现频繁项集，Association Rules 生成正反向规则 |
| 发现阈值 | 会不会丢掉低频真实共现 | `discovery_min_count=1`，`discovery_min_support=1/U_category`；所有真实共现保留，但一次共现不能成为正式新品证据 |
| 正式证据 | 如何区分真规则和偶然共现 | Jeffreys-Dirichlet 后验、Lift 95% 可信区间、`P(lift>1)`、贝叶斯 FDR、跨门店月份稳定性综合判定 |
| 正反向 | 页面是否只看 A=>B | 不可以；A=>B 和 B=>A 同时输出。Support 和 Lift 在标准定义下相同，Confidence 不同 |
| 购买机会 | 商品未到货或已售罄怎么办 | 正式指标使用 A、B 在小票时点同时可购买的 `U_AB`，不把无货误解为不喜欢 |
| 促销与折扣 | 促销小票是否删除 | 全部保留，但分成全量、自然和促销/时段折扣篮子；仅促销或折扣期成立的关系不进入新品开发 |
| 季节商品 | S 状态如何处理 | S 是正式季节商品状态，只在实际上架至下架区间计算，销售季外无销售不进入分母 |
| 画像使用 | 周末和其他时段是否改会员标签 | 不改；算法 01 固定画像归属该会员全部有效小票，日期和时段只做场景分层 |
| 稳定性 | 如何防止个别门店、月份或会员拉动 | 以门店×自然月分块，对会员重复购买做聚类处理，使用贝叶斯分层预测区间 |
| 月度依赖 | 锚点依赖某月是否删除 | 不删除；分别计算完整周期、拉动月、删除拉动月三组结果，根据敏感性缩小新品范围 |
| 新品生成 | 是否把所有关联商品拼进名称 | 不是；只有通过小分类允许维度和品类保持校验的配方型属性可进入名称 |
| 小分类规则 | 采购无法给规则怎么办 | 从正式分类、内部商品、竞品和行业标准自动学习品类边界，通过品类保持检验生成版本化专用规则 |
| 大中分类全选 | 如何避免“全部小分类快手菜” | 大分类、中分类和全选必须展开到每个叶子小分类独立计算；专用规则覆盖率是上线前 100% |
| 空结果 | 有小票但没有正式规则如何显示 | 不得显示“暂无小票规则”；必须区分正式规则、探索规则、原始共现、零共现和无有效锚点篮子 |
| 范围切换 | 切换画像或门店等级时怎么办 | 从原始小票重新聚合、重建四格表，不对各组 Lift 求平均，不复用其他范围结果 |
| 输出结果 | 最终输出什么 | 运行批次、篮子范围、项集共现、正反向规则、稳定性验证和新品候选六张表 |
| 验收方式 | 产研如何判断对错 | 固定小票公式复算、贝叶斯区间复算、特殊场景自动化测试、Doris 原始小票对账和相同输入版本可重复 |

## 2. 算法定位与边界

### 2.1 唯一业务目标

```text
算法 04 找到目标画像高表现的现有锚点商品
        +
算法 06 从真实小票找到与锚点共同购买的具体商品
        +
小分类新品属性规则判断关联属性能否进入新品
        +
算法 05 提供目标规格和价格可行性
        ↓
形成“青椒黑椒牛柳丝 200g”类具象新品候选
```

### 2.2 本算法不做的事

```text
不输出促销组合
不输出关联陈列
不输出订购协同
不使用购物篮 Confidence 直接计算订购量
不把餐食互补品机械拼成新品
不从购物篮凭空推导 Omega-3、低胆固醇等功能属性
不跳过历史差销相似品、当前在售相似品和风险过滤
```

促销、折扣、完整餐食互补和高频补充关系仍保留在底层证据中，唯一用途是判断关联能否转化为新品属性，不产生其他业务动作。

### 2.3 全链路位置

```text
算法 01 会员画像
→ 算法 02 门店品类等级
→ 算法 03 门店群主力消费者
→ 算法 04 目标画像高表现锚点 SKU
→ 算法 05 目标规格和价格可行性
→ 算法 06 购物篮新品属性
→ 竞品与外部趋势属性补充
→ 历史差销相似品和当前货盘相似品硬剔除
→ 风险验证
→ 具象新品开发建议
```

## 3. 正式范围与计算粒度

### 3.1 区域和门店群

沿用算法 02—05 的正式范围：

```text
CITY：单城市
CITY_CLUSTER：业务配置的城市群
```

门店群可选择一个 `final_level` 或 `ALL_RATED`。选择多等级或全部等级时，必须合并对应门店的底层小票重新计算，不允许平均已有等级指标。

### 3.2 消费者类型

```text
单一画像 -> 仅使用该 final_profile 会员的有效小票
多画像/全部 -> 合并会员 ID 集合后从底层重算
```

不同画像可能真实得到同一候选商品，但必须分别保留四格表和证据。不得为了页面看起来不同而强制生成不同商品。

### 3.3 品类粒度

所有正式新品候选必须锁定叶子小分类。

```text
采购选择小分类 -> 直接计算该小分类
采购选择中分类 -> 展开所有叶子小分类后逐个计算
采购选择大分类/全选 -> 展开后逐个计算并合并展示
```

“全部小分类”不是一个商品品类，不得进入候选名称。

### 3.4 锚点范围

优先级：

```text
FORMAL_ANCHOR
→ 证据充分的相对高表现商品
→ 采购明确选定的商品
```

后两类统一标记：

```text
anchor_status = EXPLORATORY_ANCHOR
```

现有在售商品不得因为“当前在售”而在算法 06 中删除，因为它是真实购物篮的锚点。在售同款或相似品的新品剔除由后续机会与风险算法完成。

### 3.5 正式规则唯一粒度

```text
basket_algorithm_version
+ analysis_period_start / analysis_period_end
+ scope_version / scope_type / scope_id
+ category_granularity / leaf_category_code
+ store_group_type / final_level
+ profile_model_version / final_profile
+ anchor_standard_product_id
+ associated_standard_product_id_or_itemset
+ direction
+ basket_scope_type
```

## 4. 数据周期与版本

### 4.1 正式周期

每月使用最近 3 个数据完整自然月，与算法 02—05 一致。

```text
例：2026 年 7 月运行
analysis_period_start = 2026-04-01
analysis_period_end   = 2026-06-30
```

### 4.2 当前周期与历史验证窗口分开

```text
当前正式计算周期：最近 3 个数据完整自然月
历史稳定性窗口：可用的完整历史门店月份或完整销售季
```

## 6. 前置过滤与篮子构建

### 6.1 有效会员和交易

完全复用算法 01 有效会员口径：

```text
customer_id 不为空
customer_id 不以“6”开头
不是已确认异常会员日
交易已完成且非退货、取消或冲销
```

算法 06 不再重新贴会员画像。

### 6.2 篮子主键

优先：

```text
basket_id = ticket_id
```

`ticket_id` 无法跨门店唯一时回退：

```text
basket_id
= store_id
+ business_date
+ pos_id
+ source_ticket_no
```

同一会员同日多张小票不合并。同票同 SKU 多行先汇总数量和金额，在出现判定中只计一次。

### 6.3 保留单商品篮子

单商品篮子必须保留，因为它们是 Confidence、Support 和 Lift 的正式分母。不得为了“让规则更多”而删除单商品小票。

### 6.4 硬排除行

```text
购物袋
包装费、配送费、服务费和押金
充值、优惠券和虚拟权益行
赠品、零金额行、测试商品和财务占位行
退货、取消和冲销行
无法映射唯一商品编码的记录
```

高频常见商品不能在 FP-Growth 前人工删除，它们是否存在超过基线的关联由 Lift 和后验区间判断。

## 7. 商品粒度与标准商品

### 7.1 三层粒度

```text
SKU 层：原始编码、到货和小票追溯
标准商品层：正式 FP-Growth 和 Association Rules
小分类层：结构诊断和选择范围
```

正式页面结果必须落到标准商品名称和规格，不得输出“净菜配菜”、“复合调味”或“主食类”等泛类目。

### 7.2 允许合并的关系

```text
正式 spu_id
正式换码关系
正式替代关系
```

例如旧码 `100101` 和新码 `100102` 有正式换码关系，可以合并为 `P100`。散装青泡椒和盒装青泡椒若无正式关系，不能只因名称相似而合并。

### 7.3 禁止自关联

属于同一标准商品、同一换码组或同一替代组的商品不生成 `A=>B`。

## 8. 三层篮子集与可购买集合

### 8.1 三个基础集合

```text
U_global：当前范围内全部有效目标画像小票

U_category：包含目标叶子小分类商品的小票
            但保留该小票上的全部有效商品

U_anchor：包含指定锚点 A 的小票
```

FP-Growth 在 `U_category` 和 `U_anchor` 中发现候选项集。正式指标不能仅使用锚点小票做全局分母。

### 8.2 商品对可购买集合

针对每个候选商品对 A、B，从 `U_global` 中建立：

```text
U_AB
= 在小票时点
  A 和 B 均处于有效售卖状态
  均在实际上下架日期内
  当日实际到货量 > 0
  且尚未售罄
  的目标画像小票
```

没有正式售罄时间时：

```text
小票时点前累计销售量 < 门店当日实际到货量
=> 估计仍可购买
```

销售量超过实际到货量 10% 以上的门店 SKU 日标记异常，不进入正式购买机会分母，不允许将其截断为 100%。

### 8.3 可购买分母的作用

一条黑椒牛柳丝小票发生时青泡椒已售罄，这张小票不能计为“消费者不购买青泡椒”。正式四格表只在 `U_AB` 内构建。

## 9. FP-Growth 发现阶段

### 9.1 动态发现下限

```text
discovery_min_count = 1
discovery_min_support = 1 / valid_ticket_count(U_category)
```

发现阶段不使用统一固定 `min_support`。所有真实共现进入结果表，不意味着所有共现都可以推荐新品。

### 9.2 技术链

```text
FP-Growth
→ 发现真实频繁项集
→ Association Rules
→ 对每个项集生成 A=>B 和 B=>A
→ 回到 U_AB 构建四格表
→ 贝叶斯证据与稳定性验证
```

MBA 是对购物篮分析业务过程的统称，不是与 FP-Growth 二选一的算法。

### 9.3 多项组合扩展

```text
全部真实二项共现保留
→ 至少达到 EXPLORATORY_RULE 的二项组才扩展三项
→ 正式三项组才扩展四项及以上
```

`A=>B` 和 `A=>C` 不得自动拼成 `{A,B,C}`。必须存在真实三项小票，并独立计算：

```text
support(A,B,C)
confidence(A=>{B,C})
confidence({B,C}=>A)
lift(A=>{B,C})
```

对多项规则，将 `X=小票包含整个前件项集`、`Y=小票包含整个后件项集`，仍然建立二元四格表。

## 10. 关联指标和正反向规则

### 10.1 四格表

|  | 包含 B | 不包含 B |
|---|---:|---:|
| 包含 A | `n11` | `n10` |
| 不包含 A | `n01` | `n00` |

```text
N = n11+n10+n01+n00 = valid_ticket_count(U_AB)
```

### 10.2 原始点估计

```text
support(A,B) = n11 / N

confidence(A=>B)
= n11 / (n11+n10)

confidence(B=>A)
= n11 / (n11+n01)

support(A)
= (n11+n10) / N

support(B)
= (n11+n01) / N

lift(A=>B)
= support(A,B) / [support(A)*support(B)]
```

### 10.3 正反向指标的数学关系

```text
support(A,B) = support(B,A)
lift(A=>B) = lift(B=>A)
confidence(A=>B) 通常不等于 confidence(B=>A)
```

正反向验证的核心不是强行得到两个不同 Lift，而是让采购同时看到两个不同的条件购买概率。

## 11. Jeffreys-Dirichlet 贝叶斯区间

### 11.1 先验与后验

使用四分类 Jeffreys 无信息先验：

```text
(p11,p10,p01,p00)
~ Dirichlet(0.5,0.5,0.5,0.5)
```

观察小票后：

```text
(p11,p10,p01,p00)
~ Dirichlet(
    n11+0.5,
    n10+0.5,
    n01+0.5,
    n00+0.5
)
```

`0.5` 不是业务经验权重，而是多项分布的 Jeffreys 先验，用于避免小样本下的零概率和无限 Lift。

### 11.2 可直接计算的边缘分布

```text
confidence(A=>B)
~ Beta(n11+0.5,n10+0.5)

confidence(B=>A)
~ Beta(n11+0.5,n01+0.5)

support(A,B)
~ Beta(
    n11+0.5,
    n10+n01+n00+1.5
)
```

Beta 分布的 `2.5% / 50% / 97.5%` 分位数分别作为 95% 可信区间下界、后验中位数和上界。

### 11.3 Lift 的联合后验

Lift 涉及相关概率，不能将各概率分别取区间后再相除。每次联合取值计算：

```text
support_A = p11+p10
support_B = p11+p01

confidence_A_to_B = p11/support_A
confidence_B_to_A = p11/support_B

lift
= p11/(support_A*support_B)
```

Dirichlet 取值通过 Gamma 归一化生成：

```text
g11 ~ Gamma(n11+0.5,1)
g10 ~ Gamma(n10+0.5,1)
g01 ~ Gamma(n01+0.5,1)
g00 ~ Gamma(n00+0.5,1)

p11 = g11/(g11+g10+g01+g00)
其余同理
```

### 11.4 数值收敛与可重复

产研使用确定性 Sobol 准蒙特卡洛序列，逐轮加倍取值量。不使用“固定重复 500 次”。

停止条件：

```text
2.5%、50%、97.5% 分位数及 P(lift>1)
按结果表规定精度四舍五入后
连续两轮不再变化
```

序列种子由：

```text
algorithm_version + run_id + pair_id
```

确定。未收敛时输出 `COMPUTE_UNSTABLE`，不得进入正式规则。

### 11.5 贝叶斯 FDR

对同一锚点、同一范围内的每条候选规则计算：

```text
local_false_discovery_rate
= P(lift<=1 | current_data)
```

按局部误报概率从低到高排序，选择最大规则集合，使：

```text
mean(local_false_discovery_rate of selected rules) <= 5%
```

5% 是已确认的统计误报控制上限，不是商品经验权重。

## 12. 证据等级与正式规则

### 12.1 发现结果状态

```text
FORMAL_RULE
EXPLORATORY_RULE
RAW_COOCCURRENCE
NO_COOCCURRENCE
NO_VALID_ANCHOR_BASKET
```

### 12.2 正式规则条件

正式规则同时满足：

```text
存在真实共现
且 Lift 95% 后验可信区间下界 > 1
且通过贝叶斯 FDR
且数值计算已收敛
且门店×月份稳定性满足对应应用范围
```

一次共现可以进入 `RAW_COOCCURRENCE`，但不允许生成正式新品。

### 12.3 无规则不等于无数据

```text
有锚点小票且存在共现，但证据不足
=> EXPLORATORY_RULE 或 RAW_COOCCURRENCE

有锚点小票但确实零共现
=> NO_COOCCURRENCE

无有效锚点小票
=> NO_VALID_ANCHOR_BASKET
```

产品不得将前两类简化成“暂无小票规则”。

## 13. 自然、促销与时段折扣篮子

### 13.1 全量篮子

```text
ALL_VALID_BASKET
= 当前范围内全部有效目标画像小票
```

用于保留目标画像真实的全部消费行为。

### 13.2 自然篮子

对关联商品对 A、B：

```text
A 和 B 均未参加限时促销
且无实际时段折扣事实
且小票时间不晚于 19:30:00
=> NATURAL_BASKET
```

小票中其他无关商品参加促销，不影响 A、B 关系的自然属性。长期稳定会员价可作为正常成交价；限时会员活动价进入促销篮子。

调价与实际折扣事实优先于单纯时钟判断。若 19:30 整点已有明确时段折扣标记，应进入时段折扣篮子；无明确折扣事实时，19:30 整点仍按已确认时间边界进入自然篮子。

### 13.3 促销/时段折扣篮子

```text
A 或 B 参加限时促销
或 A 或 B 存在实际时段折扣
或小票时间 > 19:30:00
=> PROMOTION_OR_MARKDOWN_BASKET
```

### 13.4 对新品开发的影响

```text
全量成立 + 自然篮子也成立
=> 可进入新品属性判断

全量成立 + 只有促销/折扣篮子成立
=> PROMOTION_DEPENDENT，不生成新品
```

## 14. 固定画像与时间场景

### 14.1 固定会员画像

会员被算法 01 判定为某一 `final_profile` 后，其分析周期内全部有效小票归属该画像。

例如：

```text
周二 18:40：黑椒牛柳丝 + 青泡椒
周六 10:20：鸡蛋 + 鲜牛奶
周日 19:45：黑椒牛柳丝 + 圆葱
```

三张小票都属于该会员的固定画像。日期和时段只标记工作日晚高峰、周末常规时段或时段折扣场景。

### 14.2 避免选择偏差

不得仅保留定义该画像时的特定时段小票。否则会将“上班族晚高峰型”的周末家庭消费需求丢失。

## 15. 跨门店、月份和会员稳定性

### 15.1 门店×自然月分块

对每条规则，在每个门店、每个自然月分别建立四格表，计算后验关联强度。

### 15.2 贝叶斯分层汇总

门店和月份作为分层随机效应，同一会员的多张小票作为一个会员簇。输出：

```text
pooled_lift_interval
new_store_month_prediction_interval
between_store_month_heterogeneity
member_cluster_effect
```

### 15.3 稳定性状态

```text
总体 Lift 下界 > 1，新门店月份预测区间下界 > 1
=> CROSS_STORE_MONTH_STABLE

总体 Lift 下界 > 1，预测区间跨 1
=> LOCAL_RULE

删除某一门店或月份后关联消失
=> SINGLE_BLOCK_DEPENDENT

只有一个有效门店月份
=> EXPLORATORY_RULE
```

不人工规定“必须 3 个月、5 家门店”，由分层预测区间表达真实不确定性。

## 16. S 商品、行为季节性和月度依赖

### 16.1 S 状态是正式季节口径

```text
锚点 A 为 S，B 为常规商品
=> 规则窗口 = A 的实际上架日至下架日

A 和 B 均为 S
=> 规则窗口 = A、B 实际可售时间交集
```

销售季外的无销售不是消费者不喜欢，不进入 Support 和反向 Confidence 分母。

### 16.2 跨销售季验证

每个 `season_id` 独立计算，再比较不同年度销售季：

```text
S_SEASONAL_RULE：至少一方为 S 商品，销售季内关联成立
SEASONAL_EXPLORATORY：只有一个销售季，尚无法验证跨年重复
BEHAVIORAL_SEASONAL_RULE：双方非 S，但关联跨年在相似时段重复
```

非 S 商品的行为季节性仅在完整年度数据可用时确认；数据不足一年只能标记 `TIME_WINDOW_RULE`。

### 16.3 锚点月度依赖

算法 04 输出拉动月后，算法 06 必须计算：

```text
完整周期
拉动月或拉动月集合
完整周期删除拉动月
```

判定：

```text
删除拉动月后仍成立
=> 关联不依赖拉动月

只在拉动月成立
=> ANCHOR_MONTH_DEPENDENT_RULE

删除拉动月后方向反转
=> HIGH_RISK_RULE，不生成新品
```

S 商品正常集中在销售季不得误判为单月依赖，应按完整销售季验证。

## 17. 小分类新品属性规则自动生成

### 17.1 不使用 AI 品类常识作为正式规则

“鲜鸡蛋允许功能营养”、“牛肉制品允许配料”不能因为 AI 认为符合常识就直接写入生产规则。必须建立可追溯证据。

### 17.2 品类核心边界学习

使用正确归类的内部历史和当前商品，结合相邻小分类，学习：

```text
core_category_signature
required_core_attributes
category_change_triggers
```

历史低表现商品可以用于证明某属性在分类上成立，但不能成为“值得开发”的正向证据。

### 17.3 允许维度证据

```text
allowed(category,dimension)
= category_core_preserved
  AND (
    official_standard_defined
    OR internal_same_category_observed
    OR competitor_same_category_observed
  )
```

外部趋势可以提出某个新属性值，但不能单独创造一个新的允许维度。

### 17.4 品类保持检验

对每个候选属性组合重新预测小分类：

```text
目标小分类的后验概率下界
>
所有相邻小分类后验概率上界
且不违反正式分类标准
=> CATEGORY_PRESERVED
```

否则输出：

```text
CATEGORY_CHANGED
或 CATEGORY_VALIDATION_FAILED
```

模型不设“必须 80 分”类人工经验门槛，使用品类概率区间与相邻类别直接比较。

### 17.5 规则证据状态

```text
STANDARD_CONFIRMED：正式分类或行业标准确认
MULTISOURCE_CONFIRMED：内部商品与竞品均有证据
MODEL_CONFIRMED：真实商品数据和品类保持模型通过
EXPLORATORY：只有单一弱证据，不自动生成正式新品
```

### 17.6 覆盖率和上线门禁

对商品基础表中全部有效叶子小分类：

```text
有效叶子小分类数
= 已生成可用专用规则的小分类数
```

覆盖率 100% 是系统发布条件，不是推荐得分阈值。新增小分类无规则时输出 `CATEGORY_RULE_NOT_CONFIGURED`，不得回退到通用命名模板。

## 18. 购物篮关系向新品属性的转化

### 18.1 关系类型

| 关系类型 | 对新品开发的作用 |
|---|---|
| 配方型关联 | 通过小分类允许维度和品类保持检验后，可以直接提炼新品材料、配料或口味属性 |
| 季节性配方关联 | 可以形成限定销售季的新品 |
| 局部门店或月份配方关联 | 可形成限定范围的试点新品 |
| 完整餐食互补 | 只作消费场景证据，不拼入新品名称 |
| 高频补充关系 | 只作消费场景证据，不拼入新品名称 |
| 促销/折扣依赖关系 | 不进入新品开发 |
| 同类替代关系 | 不由正向 FP-Growth 生成新品 |
| 原始共现或无法解释 | 保留底层证据，不自动生成新品 |

### 18.2 方向必须与目标小分类一致

```text
目标小分类：牛肉制品
锚点：黑椒牛柳丝
关联：青泡椒
=> 青椒可作为牛肉制品的配料候选

目标小分类：青椒
锚点：青泡椒
关联：黑椒牛柳丝
=> 不得在青椒小分类下生成牛肉菜肴
```

### 18.3 只有配方型可直接生成属性

即使鸡蛋和鲜牛奶的 Lift 显著大于 1，鲜牛奶也不属于鲜鸡蛋的可用新品属性。该规则只可作为早餐消费场景证据。

Omega-3、花青素、低胆固醇等属性必须来自竞品、外部趋势或正式商品属性数据，不得伪装成购物篮结论。

### 19.1 生成步骤

## 28. 不能做的事

```text
不能将 MBA 和 FP-Growth 当作二选一的算法
不能只用包含锚点的小票计算全局 Lift
不能因统一固定 min_support 丢掉真实共现
不能将一次共现包装成正式规则
不能只显示 A=>B 而隐藏 B=>A
不能伪造正反向不同 Lift
不能用名称相似自动合并商品编码
不能将同 SPU、换码组或替代组生成自关联
不能删除单商品篮子来提高规则
不能将未到货或已售罄解释为消费者不购买
不能将超卖异常截断为 100%
不能将销售季外无销售计入 S 商品分母
不能仅使用促销或时段折扣关系生成新品
不能将餐食互补商品机械拼成新品
不能将 A=>B 和 A=>C 擅自拼成三项新品
不能让新品跨出采购选择的叶子小分类
不能用 AI 品类常识代替品类属性证据
不能在小分类规则缺失时回退到通用“快手菜”模板
不能在有共现数据时显示“暂无小票规则”
不能平均不同画像或门店等级的 Lift
不能为了演示强制不同范围生成不同商品
不能用购物篮伪造 Omega-3、三天鲜或低胆固醇等外部属性
不能输出促销、陈列、订购协同等非新品业务动作
不能跳过历史差销、当前货盘和风险硬过滤就发布最终新品
```
