# 算法卡 04：目标画像 SKU 表现算法

文档状态：业务规则已确认  
适用范围：目标消费者现有高表现锚点商品识别与 AI 选品  
正式评估周期：最近 3 个数据完整自然月  
模型更新：每月正式更新  
确认日期：2026-07-21

## 1. 算法澄清表

| 项目 | 业务问题 | 已确认规则 |
|---|---|---|
| 算法名称 | 这个算法叫什么 | 目标画像 SKU 表现算法 |
| 业务目标 | 解决什么问题 | 在指定门店群、品类和消费者类型下，识别消费者实际购买且经营表现健康的现有高表现锚点商品，为购物篮和新品属性组合提供起点 |
| 算法边界 | 是否直接生成新品 | 不直接生成新品；算法 04 只识别现有锚点，关联商品或食材必须由后续购物篮算法产生 |
| 计算对象 | 按谁计算 | 底层对算法 03 中全部有有效消费的消费者类型计算，产品默认展示正式主力人群 |
| 计算粒度 | 一条结果代表什么 | 周期 + 城市或城市群 + 品类颗粒度 + 品类 + 门店群范围 + 消费者类型 + SKU |
| 上游依赖 | 依赖哪些算法 | 算法 01 会员画像、算法 02 门店品类等级、算法 03 门店群消费者贡献 |
| 使用数据 | 需要哪些数据 | 小票商品明细、商品基础表、到货与订购、可订可售、商品毛利、促销、日历、门店与品类映射 |
| 数据周期 | 用多长时间 | 与算法 02、03 使用同一个最近 3 个完整自然月，任一上游正式版本变化均需全量重算 |
| 时间口径 | 全天还是分时 | 消费者销售、会员、复购和毛利使用全天；自然动销使用非促销 SKU 日 19:30 前数据 |
| 复购口径 | 复购周期是什么 | 读取现有“近 7 天 19 点前复购率”：首次购买时间不限，第二次购买发生在之后第 1—7 个自然日且在 19:00 前 |
| 偏好判断 | 如何识别目标画像特有偏好 | 在相同门店群、品类和 SKU 可购买门店日内，将目标画像会员渗透率与其他全部有效画像比较 |
| 小样本 | 1 人中 1 人复购怎么办 | 原始值仍显示 100%，正式评分使用 Jeffreys 95%下界；低证据 SKU 不进入正式锚点池 |
| 有效在售 | 当前在售如何识别 | 商品端“可订可售”字段为 1 即识别为当前在售，不以近期是否实际到货代替在售状态 |
| 订购率 | 是否进入综合得分 | 不进入；作为独立覆盖维度，与综合表现形成成熟锚点、低铺货高表现等经营解释 |
| 计量口径 | 不同规格如何比较 | 重量、件数、体积和蛋类枚数分别标准化；无法转换时只在相同计量类型内比较数量指标 |
| 毛利口径 | 是否再减损耗 | 目标画像 SKU 毛利额 = 目标画像 SKU 销售额 - 目标画像 SKU 成本金额；损耗不进入算法 04，也不再次从毛利中扣减 |
| 评分维度 | 从哪些方面评分 | 目标画像贡献、目标画像偏好、19:30 前自然动销、商品毛利 |
| 权重来源 | 权重怎么产生 | 二级指标和四个一级维度分别使用 CRITIC 动态赋权，不使用固定经验权重 |
| 锚点分组 | 如何选出高表现商品 | 综合得分使用 Jenks+BIC 动态选择 1—3 组，最高表现组进入锚点准入判断 |
| 稳定性 | 如何判断偶发性 | 留一门店验证 + 留一月验证；时间敏感锚点进入分月购物篮验证，不直接删除 |
| 商品属性 | 属性从哪里来 | 商品基础表、BOM/规格书、属性字典、名称规则、AI 抽取按优先级补充，按商品编码核对 |
| 输出结果 | 最终输出什么 | SKU及标准商品表现、原始指标、统计区间、四维得分、动态权重、锚点结果、稳定性、属性和版本血缘 |
| 验收方式 | 怎么判断合理 | 上游对账、唯一性、公式复算、分层追溯、稳定性、边界场景和下一周期后验验证 |

## 2. 算法定位与边界

### 2.1 业务问题

本算法只回答：

```text
在指定城市或城市群、品类、门店品类等级群和消费者类型下，
哪些现有商品可以作为后续购物篮分析的高表现锚点？
```

它不回答：

```text
应该开发什么新品
新品应该增加什么配料
新品应该定什么价格
新品是否与现有货盘重复
```

### 2.2 正确链路

```text
算法 01：会员画像 final_profile
        +
算法 02：门店品类等级 final_level
        +
算法 03：门店群消费者贡献和目标画像
        +
有效会员小票、商品、到货、促销和商品毛利
        ↓
算法 04：识别现有高表现锚点商品
        ↓
购物篮算法：寻找真实关联商品或食材
        ↓
锚点商品属性 + 已验证关联属性
        ↓
历史差销、现有货盘、价格、竞品、趋势和风险过滤
        ↓
具象新品候选
```

### 2.3 锚点与新品必须分开

正确示例：

```text
现有锚点：黑椒牛柳丝 200g
购物篮关联：圆葱、青椒
候选新品：圆葱黑椒牛柳丝 200g、青椒黑椒牛柳丝 200g
```

禁止将候选新品“圆葱黑椒牛柳丝 200g”提前写成算法 04 已验证的现有高表现商品。

如果只有两条独立二项规则：

```text
黑椒牛柳丝 => 圆葱
黑椒牛柳丝 => 青椒
```

只能形成两个独立候选方向。只有三项频繁项集 `{黑椒牛柳丝、圆葱、青椒}` 也通过购物篮验证，才能组合成“圆葱青椒黑椒牛柳丝”。

## 3. 正式范围与计算粒度

### 3.1 计算范围

沿用算法 02、03 的正式范围：

```text
CITY：单城市
CITY_CLUSTER：业务配置城市群
```

门店群支持：

```text
指定 final_level
ALL_RATED
```

禁止在数据不足时自动扩大到其他城市、城市群或华东大区。

### 3.2 消费者类型范围

底层对算法 03 中全部有有效消费的 `final_profile` 计算 SKU 表现：

```text
算法 03 存在正式主力
-> 产品默认展示 is_main_profile = 1 的消费者类型

算法 03 为 NO_OBVIOUS_MAIN
-> 产品默认展示相对主力候选并明确没有明显主力

采购手动选择其他消费者类型
-> 读取已计算结果，但不能称为主力人群
```

捡漏型继续使用算法 01 的终止标签：

```text
final_profile = 捡漏型
family_level = NOT_APPLICABLE
frequency_level = NOT_APPLICABLE
price_attitude = NOT_APPLICABLE
```

### 3.3 正式结果粒度

SKU明细唯一粒度：

```text
sku_performance_model_version
+ performance_start_date / performance_end_date
+ scope_version / scope_type / scope_id
+ category_granularity / category_code
+ store_group_type / final_level
+ final_profile
+ sku_id
```

只输出区域门店群正式结果，不生成单门店正式综合得分。

### 3.4 大、中、小分类

大、中、小分类分别从小票明细重新筛选、聚合、标准化和评分：

```text
大分类结果 != 下属中分类结果平均
中分类结果 != 下属小分类结果平均
```

采购选择“全部小分类”时：

```text
每个小分类独立计算 CRITIC、综合得分和锚点组
-> 最后合并展示
```

禁止将全部小分类 SKU 放入同一评分池。具体新品开发优先读取小分类锚点。

## 4. 数据周期与版本

### 4.1 正式周期

每月使用最近 3 个数据完整自然月，与算法 02、03 周期一致。

例如 2026 年 7 月运行：

```text
performance_start_date = 2026-04-01
performance_end_date   = 2026-06-30
```

### 4.2 上游版本

必须锁定：

```text
profile_model_version
category_level_model_version
consumer_contribution_model_version
category_mapping_version
sku_attribute_version
sku_performance_algorithm_version
```

算法 01、02、03 任一正式版本或范围版本变化时，算法 04 必须全量重算。禁止混用不同周期、不同画像版本或不同门店群结果。

### 4.3 当前在售快照

历史表现使用正式 3 个月周期，当前在售状态读取计算时最新正式商品基础表快照：

```text
listing_snapshot_date
orderable_sellable_flag
```

下一次正式运行时重新读取当前状态，不修改已发布历史版本。

## 6. 前置过滤与对账

### 6.1 有效会员和交易

完全复用算法 01、03：

```text
customer_id 非空且不以“6”开头
只保留正常完成的正向销售
销售数量 > 0、实付金额 > 0
剔除退货、取消、冲销、测试交易和赠品/零金额行
剔除算法 01 已标记的异常会员日
```

### 6.2 商品映射

```text
商品编码必须关联唯一正式商品记录
SKU必须成功映射到目标品类
交易发生时只能命中一条有效品类映射
```

一对多或品类冲突输出 `PRODUCT_MASTER_CONFLICT`，禁止发布正式得分。

### 6.3 小票内相同SKU

同一小票内相同 SKU 的多行明细先按以下主键合并：

```text
ticket_key + sku_id
```

其中：

```text
优先 ticket_key = 全局唯一 ticket_id
回退 ticket_key = store_id + business_date + pos_id + source_ticket_no
```

同一会员同一天拆成多张小票不能被误判为复购。

### 6.4 上游金额对账

在同一门店群、品类和消费者类型下：

```text
算法 04 各 SKU 销售额合计
= 算法 03 对应消费者类型销售额
```

无法对平时输出 `UPSTREAM_RECONCILIATION_ERROR`。

## 7. 全天行为与时间窗口

### 7.1 正式消费者表现

以下指标使用全天有效会员交易：

```text
销售额、销量、小票数、购买会员数
目标画像会员渗透率
目标画像相对偏好
近 7 天 19 点前复购
目标画像商品毛利
```

### 7.2 自然动销

自然动销使用非促销 SKU 日 19:30 前数据：

```text
非促销 19:30 前售罄率
19:30 前每有效在售门店日标准销售量
```

### 7.3 两个时间点不能混用

```text
复购第二次购买：19:00 前
自然动销售罄：19:30 前
```

前者来自现有复购字段，后者来自门店日清经营口径。开发不得统一改成同一个时间点。

## 8. SKU 基础表现指标

在同一比较组、同一 `final_profile` 下计算：

```text
sku_sales_amt
= 目标画像购买该 SKU 的实付金额合计

sku_sales_qty
= 目标画像购买该 SKU 的标准销售量合计

sku_ticket_cnt
= 包含该 SKU 的目标画像去重小票数

sku_buyer_cnt
= 购买该 SKU 的目标画像去重会员数

sku_sales_share
= sku_sales_amt / 目标画像在该品类的销售额

sku_buyer_penetration
= sku_buyer_cnt / 目标画像在该品类的去重会员数

sku_ticket_penetration
= sku_ticket_cnt / 目标画像在该品类的去重小票数

sku_avg_paid_price
= sku_sales_amt / sku_sales_qty
```

业务解释：

```text
销售占比：目标画像的钱主要花在哪些 SKU
会员渗透率：目标画像中有多少会员买过该 SKU
小票渗透率：购买该品类时该 SKU 出现得多不多
```

会员渗透率和小票渗透率不要求合计为 100%。

## 9. 近 7 天 19 点前复购

### 9.1 读取现有字段

算法 04 不重新定义月度复购，读取现有正式结果并验证分子、分母：

```text
首次购买：购买该 SKU 的时间不限
第二次购买：首次购买后的第 1—7 个自然日内，且发生在 19:00 前
```

```text
repeat_buyer_cnt_7d_pre19
= 满足第二次购买条件的去重会员数

eligible_first_buyer_cnt_7d
= 具备完整 7 天观察窗口的首次购买会员数

repurchase_rate_7d_pre19
= repeat_buyer_cnt_7d_pre19 / eligible_first_buyer_cnt_7d
```

### 9.2 观察窗口

```text
同一天多张小票不算复购
周期结束前不足 7 天才首次购买的会员不进入分母
```

只提供一个复购率而没有分子、分母的上游结果不能进入正式评分。

## 10. 有效在售、订购与铺货

### 10.1 当前在售

```text
orderable_sellable_flag = 1
-> listing_status = ACTIVE

orderable_sellable_flag = 0
-> listing_status = INACTIVE
```

当前在售不以近期是否有实际到货判断。

### 10.2 有效在售 SKU 日

用于销售深度和售罄率的有效在售 SKU 日：

```text
门店当天该 SKU 实际收货重量或数量 > 0
```

```text
available_store_day_cnt
= COUNT(DISTINCT store_id + business_date)

sales_per_available_store_day
= sku_sales_amt / available_store_day_cnt

buyers_per_available_store_day
= sku_buyer_cnt / available_store_day_cnt
```

### 10.3 门店订购率

```text
ordered_store_cnt
= 周期内实际订购过该 SKU 的门店数

store_order_rate
= ordered_store_cnt / 允许订购该 SKU 的有效门店数

ordered_store_day_rate
= 存在实际收货的门店日数 / 允许订购该 SKU 的有效门店营业日数
```

若只有全局可订可售字段，没有门店级可订清单：

```text
分母 = 门店群全部有效门店
orderable_scope = GROUP_ALL_STORES
```

订购率不进入综合得分，单独反映门店采用程度。

### 10.4 订购率与综合表现

订购率高低使用自身 Jenks+BIC 动态划分，不使用固定 50%：

| 综合表现 | 订购覆盖 | 解释 |
|---|---|---|
| 高 | 高 | 已验证成熟锚点 |
| 高 | 低 | 低铺货高表现，可能存在扩店机会 |
| 低 | 高 | 广泛订购但经营表现较弱 |
| 低 | 低 | 证据较少或整体较弱 |

## 11. 计量单位与数量指标

### 11.1 标准单位

```text
称重商品：kg
按件商品：件
定量包装：销售件数 * 单件净含量
液体商品：L 或 ml
蛋类：优先转换为枚；无法转换时按包装件
```

保存：

```text
measurement_type
source_unit
standard_unit
conversion_factor
measurement_mapping_status
```

### 11.2 混合计量

同一小分类存在无法互转的计量类型时：

```text
销售额、会员渗透率、偏好、复购和毛利：仍在小分类内比较
销售量深度、到货量和售罄率：只在相同 measurement_type 内标准化
```

禁止将“1 盒鸡蛋”和“1kg 散装鸡蛋”直接按数量比较。

## 12. 目标画像相对偏好

### 12.1 对照组

参考组为：

```text
同一周期
+ 同一城市或城市群
+ 同一品类
+ 同一门店等级群
+ 同一 SKU 有效可购买门店日
+ 除目标画像外的全部有效消费者类型
```

禁止跨城市、跨等级或跨品类比较。

### 12.2 原始渗透率

```text
target_penetration
= 目标画像购买该 SKU 的会员数
  / 目标画像在该 SKU 可购买门店日内购买该品类的会员数

reference_penetration
= 其他画像购买该 SKU 的会员数
  / 其他画像在相同可购买门店日内购买该品类的会员数

raw_preference_index
= target_penetration / reference_penetration
```

### 12.3 Jeffreys 平滑

对任一组：

```text
smoothed_penetration
= (购买该 SKU 会员数 + 0.5)
  / (购买该品类会员数 + 1)
```

```text
smoothed_preference_index
= target_smoothed_penetration
  / reference_smoothed_penetration
```

`0.5` 为 Jeffreys 统计先验，不是业务经验阈值。

### 12.4 无参考画像

算法 03 为 `SINGLE_PROFILE` 时：

```text
preference_index = NOT_APPLICABLE
preference_status = NO_REFERENCE_PROFILE
```

该指标从整个比较组的 CRITIC 中移除，其他指标正常计算。

## 13. 小样本与统计证据

### 13.1 原始值和证据值分开

原始比例回答“观察到什么”，统计下界回答“样本量支持我们保守确认到什么程度”。

比例指标保存：

```text
raw_rate
smoothed_rate
credible_lower_95
credible_upper_95
numerator_cnt
denominator_cnt
```

采购页面展示原始比例、分子和分母；正式综合得分使用 95% 下界。

### 13.2 单个比例的 Jeffreys 区间

对成功人数 `x`、总人数 `n`：

```text
posterior = Beta(x + 0.5, n - x + 0.5)

credible_lower_95 = BetaQuantile(0.025, posterior)
credible_upper_95 = BetaQuantile(0.975, posterior)
```

正式评分使用该规则处理：

```text
目标画像会员渗透率
近 7 天 19 点前复购率
```

示例：

| 复购人数/观察人数 | 原始复购率 | 95%下界 |
|---|---:|---:|
| 1/1 | 100% | 14.67% |
| 8/10 | 80% | 49.72% |
| 80/100 | 80% | 71.37% |
| 100/100 | 100% | 97.53% |

### 13.3 偏好指数区间

使用 Jeffreys 修正后的目标组和参考组人数构造风险比。开发可使用等价的 Beta 后验数值法；正式 V1 使用以下可复算近似：

```text
p_t = (x_t + 0.5) / (n_t + 1)
p_o = (x_o + 0.5) / (n_o + 1)

log_rr = ln(p_t / p_o)

se_log_rr
= sqrt(
    1/(x_t + 0.5) - 1/(n_t + 1)
  + 1/(x_o + 0.5) - 1/(n_o + 1)
  )

preference_lower_95 = exp(log_rr - 1.96 * se_log_rr)
preference_upper_95 = exp(log_rr + 1.96 * se_log_rr)
```

正式偏好指标使用 `preference_lower_95`，避免参考组零购买产生无穷大。

### 13.4 不设置人工人数门槛

```text
存在有效销售的 SKU 全部保留原始结果
不使用“至少 10 人”或“至少 30 张小票”硬删除
```

但低证据 SKU：

```text
evidence_status = LOW_EVIDENCE
is_formal_anchor = 0
不作为默认购物篮锚点
```

是否低证据由置信度校正后的综合得分和动态锚点断点共同判断，不因原始 100% 自动获得高分。

### 13.5 低证据状态的可复算判断

使用同一套稳健标准化参数、CRITIC 权重和 Jenks 断点计算两套分数。页面仍展示原始比例，但为了避免参考组零购买产生无穷大，分组敏感性比较使用 Jeffreys 点估计：

```text
point_evidence_score
= 会员渗透率和复购率使用 Jeffreys 后验均值、
  偏好使用 smoothed_preference_index 时的综合得分

conservative_evidence_score
= 三个比例指标使用各自 95%下界时的正式综合得分
```

正式表现分始终使用 `conservative_evidence_score`。

```text
Jeffreys 点估计得分进入最高表现组
但 95%下界得分未进入最高表现组
-> evidence_status = LOW_EVIDENCE
-> is_formal_anchor = 0

95%下界得分仍进入最高表现组
-> evidence_status = SUFFICIENT
```

点估计本身未进入最高表现组的 SKU 直接属于非锚点，不需要用低证据标签解释其落选。该规则没有固定人数门槛，样本量通过可信区间自动影响正式得分。

## 14. 19:30 前自然动销

### 14.1 非促销 SKU 日

按 `门店 + 日期 + SKU` 判断：

```text
该 SKU 在该门店当天 19:30 前没有参加商品活动
并且 19:30 前没有商品促销折扣
-> non_promotion_sku_day = 1
```

只要当日 19:30 前参加过活动，即使某位会员按原价购买，也不能进入非促销自然动销计算。

### 14.2 实际收货与异常

完全复用算法 02 日清口径：

```text
净到货量 = 门店实际收货重量或数量

净到货量 <= 0
-> 不保留有效在售 SKU 日

19:30 前销售量 / 实际收货量 > 1.10
-> SELL_THROUGH_DATA_ERROR
-> 不进入自然动销得分
-> 禁止截断为 100%
```

### 14.3 门店群售罄率

```text
pre1930_sell_through_rate
= SUM(有效 SKU 日 19:30 前标准销售量)
  / SUM(有效 SKU 日实际收货标准量)

non_promo_pre1930_sell_through_rate
= SUM(非促销有效 SKU 日 19:30 前标准销售量)
  / SUM(非促销有效 SKU 日实际收货标准量)
```

禁止先计算各门店日售罄率再简单平均。

### 14.4 销售深度

```text
pre1930_sales_volume_per_available_store_day
= 19:30 前标准销售量
  / 有效在售门店日数
```

售罄率必须与销售深度同时使用：到货 10kg 售 9kg 与到货 100kg 售 85kg 不能只凭 90% 和 85% 判断商品受欢迎程度。

### 14.5 目标画像吸收贡献

作为解释字段输出：

```text
target_profile_pre1930_absorption_rate
= 目标画像 19:30 前购买该 SKU 的标准量
  / 该 SKU 实际收货标准量
```

整体售罄反映商品经营表现，目标画像偏好指数才反映该消费者类型是否特别偏好该 SKU。

### 14.6 没有自然销售窗口

整个周期没有非促销有效在售日：

```text
natural_sales_status = NO_NATURAL_SALES_WINDOW
non_promo_pre1930_sell_through_rate = NOT_APPLICABLE
is_formal_anchor = 0
```

该 SKU 可作为促销环境候选进入分促销状态购物篮验证，但不能称为自然动销已验证的正式成熟锚点。

## 15. 19:30 后折扣阶梯

19:30 后不是固定折扣，每半小时降低一个折扣，因此不使用笼统的“19:30 后销售额占比”判断折扣偏好。

按实际时间和折扣档输出：

```text
19:30—20:00 销售量 / 增量售罄率 / 实际折扣率
20:00—20:30 销售量 / 增量售罄率 / 实际折扣率
20:30—21:00 销售量 / 增量售罄率 / 实际折扣率
其他实际营业折扣档同理
```

```text
band_incremental_sell_through_rate
= 该折扣档销售标准量 / 当日实际收货标准量

cumulative_sell_through_rate_at_band_end
= 截至该折扣档结束累计销售标准量 / 当日实际收货标准量
```

折扣阶梯只用于解释，不进入算法 04 综合得分。

## 16. 商品毛利

### 16.1 销售额减成本金额

```text
target_profile_sku_sales_amt
= SUM(目标画像购买该 SKU 的实付销售额)

target_profile_sku_cost_amt
= SUM(目标画像购买该 SKU 的成本金额)

target_profile_sku_margin_amt
= target_profile_sku_sales_amt - target_profile_sku_cost_amt

target_profile_sku_margin_rate
= target_profile_sku_margin_amt / target_profile_sku_sales_amt

sku_total_sales_amt
= SUM(全部消费者购买该 SKU 的实付销售额)

sku_total_cost_amt
= SUM(全部消费者购买该 SKU 的成本金额)

sku_total_margin_amt
= sku_total_sales_amt - sku_total_cost_amt

sku_total_margin_rate
= sku_total_margin_amt / sku_total_sales_amt
```

### 16.2 不能重复扣损耗

成本金额应使用财务或商品毛利底表中与交易行匹配的成本口径。若该成本口径已经承接损耗、加工、物流或其他全链路成本影响，算法 04 不再二次扣减；若底表只提供商品毛利额，也必须先拆解或映射为销售额、成本金额后再按本节公式输出。

```text
算法 04 不再减损耗
不输出损耗诊断
不将损耗分摊给消费者画像
```

### 16.3 正式锚点毛利底线

```text
target_profile_sku_margin_amt > 0
并且
sku_total_margin_amt > 0
```

任一不为正时：

```text
profitability_status = NON_POSITIVE_MARGIN
is_formal_anchor = 0
```

毛利率较低但毛利额为正时不直接删除，由毛利维度得分反映。

## 20. 稳健标准化

在以下比较组内独立处理：

```text
周期 + 城市或城市群 + 品类颗粒度 + 品类
+ 门店群范围 + final_profile
```

### 20.1 指标转换

```text
金额、每店日销售额、销售量深度：ln(1 + x)
偏好指数下界：ln(x)
比例和毛利率：保留原值
```

### 20.2 稳健 Z 分数

```text
z_j
= (x'_ij - median_j)
  / (1.4826 * MAD_j)

indicator_score_ij
= 100 * Phi(z_j)
```

其中 `Phi` 为标准正态累计分布函数。

### 20.3 MAD 回退

```text
MAD > 0：使用 MAD
MAD = 0 且 IQR > 0：使用 IQR / 1.349
MAD = 0、IQR = 0、标准差 > 0：使用标准差
全部 SKU 取值完全相同：移除该指标
```

禁止使用普通 Min-Max 让极端 SKU 决定其他商品得分。

## 21. 两级 CRITIC 动态赋权

### 21.1 为什么分两级

先在每个一级维度内计算二级指标权重，再对四个一级维度计算权重，避免“某个维度因为指标数量多而天然权重更高”。

### 21.2 CRITIC 公式

对标准化后的指标：

```text
C_j
= sigma_j * SUM_k(1 - corr_jk)

w_j
= C_j / SUM(C_j)
```

```text
dimension_score_d
= SUM(维度内 indicator_score_j * w_j)

sku_performance_score
= SUM(dimension_score_d * dimension_weight_d)
```

CRITIC 自动降低与其他指标高度重复的指标权重，不使用固定销售 30%、复购 20% 等经验权重。

### 21.3 不适用和缺失

整个比较组不适用的指标从 CRITIC 中移除并对全组重算，例如 `SINGLE_PROFILE` 没有偏好参考组。

单个 SKU 的商品毛利、实际到货、商品编码等必需数据缺失时：

```text
result_status = DATA_INCOMPLETE
不填 0
不以同品类平均值替代
不生成正式综合得分
```

商品属性缺失不影响经营表现得分，但输出 `ATTRIBUTE_INCOMPLETE`，不能自动组合新品。

### 21.4 CRITIC 小样本回退

```text
有效 SKU 数 >= 3
-> 正常运行 CRITIC

有效 SKU 数 = 2
-> 不运行 CRITIC
-> 使用四维 Pareto 比较
-> 只有一个 SKU 在所有可用维度均不低于另一个，且至少一维更高，才是相对锚点候选

有效 SKU 数 = 1
-> result_status = SINGLE_SKU
-> 不生成综合得分和正式高表现组
```

所有可用指标没有差异时输出 `NO_OBVIOUS_HIGH_SKU`，不使用人工等权强制排名。

## 22. Jenks+BIC 动态锚点组

### 22.1 候选组数

对同一比较组的 `sku_performance_score` 从低到高排序：

```text
K_max = MIN(3, 综合得分去重值数量)
候选 K = 1 ... K_max
```

相同得分不得被拆到不同组。

### 22.2 Jenks

```text
SSE_K = SUM((score_i - 当前组均值)^2)
```

选择每个 K 下组内平方误差最小的连续切分。

### 22.3 BIC

```text
BIC(K) = N * ln(SSE_K / N + 1e-12) + K * ln(N)
```

BIC 越小越好；相同时选择更小 K。

### 22.4 分组结果

```text
K=3：高表现组 / 中表现组 / 低表现组
K=2：高表现组 / 低表现组
K=1：NO_OBVIOUS_HIGH_SKU，不强制产生正式高表现组
```

最高表现组进入正式锚点准入判断。综合得分只允许在同一比较组内排序，鸡蛋类 85 分不能与牛肉制品 85 分直接比较。

## 24. 当前锚点与历史锚点

```text
ACTIVE_ANCHOR
= 当前可订可售且通过正式锚点准入

HISTORICAL_ANCHOR
= 贡献周期内有真实销售且表现较好，但当前不可订不可售
```

历史锚点可保留消费者和购物篮证据，但进入新品或复开发前必须检查停售原因、历史订购表现、供应商状态和相似商品表现。

```text

供应商断供、季节结束或正式换码 -> 可作为复开发证据
```

算法 04 不删除当前在售商品。后续候选过滤删除的是与当前货盘重复的“新品候选”，不是现有锚点。

## 25. 门店稳定性

### 25.1 集中度

```text
top1_store_sales_share
= 该 SKU 销售额最高门店销售额 / 门店群该 SKU 销售额

= SUM(各门店该 SKU 销售额占比^2)
```

### 25.2 留一门店

对每家覆盖该 SKU 的门店：

```text
删除该门店
-> 重新计算全部 SKU 指标
-> 重新计算 CRITIC 权重、综合得分和 Jenks 分组
```

```text
leave_one_store_anchor_rate
= 删除不同门店后仍进入锚点组的有效次数 / 有效验证次数
```

全部有效验证均保持锚点时为 `STABLE`；任一次发生变化时标记 `STORE_CONCENTRATED`，但不直接删除正式锚点。

覆盖门店不足以形成有效验证时输出 `INSUFFICIENT_STORE_SAMPLE`。

## 26. 时间稳定性

保持正式消费者画像版本和门店群不变：

```text

验证 2：删除第 2 月，使用第 1 月 + 第 3 月重算
验证 3：删除第 3 月，使用第 1 月 + 第 2 月重算
```

```text
leave_one_month_anchor_rate
= 仍进入锚点组的有效次数 / 有效验证次数
```

```text
全部有效验证均保持锚点 -> STABLE
任一次删除月份后不再是锚点 -> TIME_SENSITIVE
有效验证少于 2 次 -> INSUFFICIENT_TIME_SAMPLE
```

完整 3 个月仍为正式结果。时间敏感不直接删除锚点。

```text

-> 组合关系较稳定，可保留常规商品开发价值

关联只在拉动月成立
-> 季节性、节日性或促销场景机会，不作为全年常规推荐
```

## 30. 产品端应用

产品默认按 `sku_performance_score` 展示同一比较组内排名，同时展示：

```text
为什么表现高
目标画像买了多少
相对其他画像是否更偏好
复购证据是否充分
19:30 前自然动销是否成立
商品毛利是否为正
门店订购是否充分
是否依赖某个月或某家门店
```

算法 04 结果只用于：

```text
1. 识别现有高表现锚点商品
2. 决定购物篮分析默认锚点顺序
3. 为后续组合保留锚点的主材料、口味、形态和规格
```

不得将综合得分直接表述为新品成功概率。

## 31. 完整演示案例

以下为产研复算用模拟数据，不代表生产实时结果。

### 31.1 案例 A：稳定成熟锚点

范围：

```text
2026 年 4—6 月
上海
即烹类 / 牛肉制品
A 级门店群
上班族晚高峰型-小家庭-中频-价格非敏感
```

目标画像品类购买会员 1,200 人，其他画像品类购买会员 3,000 人。五个商品部分原始数据：

| SKU | 销售占比 | 目标购买人数 | 其他购买人数 | 7天复购 | 非促销19:30前售罄 | 目标毛利额 | 整体毛利额 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 黑椒牛柳丝200g | 30% | 360 | 400 | 96/300 | 82% | 12万元 | 30万元 |
| 蚝油牛肉片200g | 25% | 300 | 600 | 63/280 | 84% | 8.5万元 | 24万元 |
| 香辣牛肉丝200g | 20% | 240 | 650 | 36/220 | 55% | 5万元 | 15万元 |
| 黑椒牛排200g | 15% | 180 | 450 | 18/160 | 65% | 3.5万元 | 10万元 |
| 孜然牛肉粒180g | 10% | 1 | 0 | 1/1 | 30% | 1万元 | 1.5万元 |

黑椒牛柳丝会员渗透率：

```text
原始会员渗透率 = 360 / 1,200 = 30%
Jeffreys 95%下界 = 27.46%
```

黑椒牛柳丝偏好：

```text
目标画像渗透率 = 360 / 1,200 = 30%
其他画像渗透率 = 400 / 3,000 = 13.33%
原始偏好指数 = 30% / 13.33% = 2.25
Jeffreys 平滑偏好指数 = 2.25
偏好指数 95%下界 = 1.98
```

黑椒牛柳丝复购：

```text
原始 7 天 19 点前复购率 = 96 / 300 = 32%
Jeffreys 95%下界 = 26.91%
```

对全部二级指标按第 20—21 章处理后，四维得分为：

| SKU | 画像贡献 | 画像偏好 | 自然动销 | 商品毛利 |
|---|---:|---:|---:|---:|
| 黑椒牛柳丝200g | 88 | 90 | 82 | 78 |
| 蚝油牛肉片200g | 76 | 62 | 84 | 72 |
| 香辣牛肉丝200g | 60 | 70 | 55 | 50 |
| 黑椒牛排200g | 45 | 40 | 65 | 58 |
| 孜然牛肉粒180g | 30 | 25 | 30 | 35 |

一级 CRITIC 计算结果：

```text
目标画像贡献权重 = 17.24%
目标画像偏好权重 = 41.05%
自然动销权重     = 25.57%
商品毛利权重     = 16.14%
```

黑椒牛柳丝综合得分：

```text
= 88 * 17.24%
+ 90 * 41.05%
+ 82 * 25.57%
+ 78 * 16.14%
= 85.67
```

全部综合得分：

```text
黑椒牛柳丝200g  85.67
蚝油牛肉片200g  71.65
香辣牛肉丝200g  61.21
黑椒牛排200g    50.16
孜然牛肉粒180g  28.75
```

Jenks/BIC：

```text
K=1：SSE=1,868.15，BIC=31.23
K=2：SSE=530.40，BIC=26.54
K=3：SSE=159.33，BIC=22.14
```

选择 K=3：

```text
高表现组：黑椒牛柳丝200g、蚝油牛肉片200g
中表现组：香辣牛肉丝200g、黑椒牛排200g
低表现组：孜然牛肉粒180g
```

黑椒牛柳丝同时满足可订可售、目标和整体商品毛利为正、自然销售窗口有效、证据充分，并在留一门店和留一月验证中保持高表现：

```text
is_formal_anchor = 1
anchor_evidence_type = ACTIVE_STABLE_ANCHOR
```

算法 04 产品结论：

> 黑椒牛柳丝 200g 是该门店群和目标画像下的现有稳定高表现锚点，下一步进入购物篮关联分析。算法 04 尚未产生圆葱、青椒或任何新品配料结论。

### 31.2 案例 B：低订购率高表现

```text
SKU：青椒牛肉丝180g
可订可售：是
允许订购门店：20家
实际订购门店：4家
门店订购率：20%
```

在 4 家实际订购门店中：

```text
目标画像偏好指数下界 = 1.72
7 天 19 点前复购率下界 = 24%
非促销 19:30 前售罄率 = 88%
19:30 前每有效在售门店日销售量较高
目标画像和 SKU 整体商品毛利均为正
综合得分 = 82
Jenks = 高表现组
```

订购率在同组 Jenks 中属于低覆盖，但留一门店验证仍保持较好：

```text
is_formal_anchor = 1
order_coverage_status = LOW
anchor_evidence_type = LOW_ORDER_HIGH_PERFORMANCE
```

产品解释：

> 该 SKU 只被部分门店订购，但在实际经营门店中消费者偏好、自然动销和商品毛利表现较好。它可以进入购物篮分析，同时应评估扩店订购机会，不能因订购率低直接扣减综合得分。

### 31.3 案例 C：1 人中 1 人复购

```text
SKU：孜然牛肉粒180g
目标画像品类购买会员：1,200人
购买该 SKU：1人
具备完整7天观察窗口：1人
发生复购：1人
其他画像购买该SKU：0人
```

原始结果：

```text
原始复购率 = 1 / 1 = 100%
原始偏好指数 = 无穷大
```

统计校正：

```text
复购率 Jeffreys 平滑值 = 75%
复购率 95%下界 = 14.67%

平滑偏好指数 = 7.50
偏好指数 95%下界约 = 0.31

会员渗透率 = 1 / 1,200 = 0.083%
会员渗透率 95%下界约 = 0.009%
```

产品结果：

```text
evidence_status = LOW_EVIDENCE
is_formal_anchor = 0
不作为默认购物篮锚点
```

采购可以查看原始数据或主动运行探索性分析，但系统必须说明当前只有 1 名购买会员，结论不足以支持正式商品开发。

## 32. 开发与业务验收

### 32.1 上游对账

```text
算法 04 各 SKU 销售额合计
= 算法 03 对应门店群、品类、消费者类型销售额

算法 04 各 SKU 商品毛利额合计
= 对应商品毛利底表汇总
```

浮点误差不超过 `0.01%`。

### 32.2 唯一性

```text
同一结果唯一键只能有一行
商品基础表一对多不能造成销售和商品毛利膨胀
正式换码关系之外的相似名称商品不得自动合并
```

### 32.3 公式复算

逐字段复算：

```text
销售占比、会员渗透率、小票渗透率
7 天 19 点前复购分子、分母和 Jeffreys 区间
目标/参考渗透率、偏好指数和 95%下界
有效在售门店日、订购率和 19:30 前售罄率
目标画像及 SKU 整体商品毛利
稳健标准化、两级 CRITIC、综合得分
Jenks SSE、BIC 和最终分组
留一门店和留一月结果
```

### 32.4 分层追溯

按城市或城市群、品类、门店等级和消费者类型抽取至少 30 个门店群，再抽取高、中、低表现 SKU 追溯：

```text
锚点结果
-> 四维指标和权重
-> SKU 会员、小票、到货、促销和商品毛利
-> 商品基础表和属性来源
-> 算法 01、02、03 正式结果
```

人工复核只发现数据或解释问题，不直接修改当前正式得分。

### 32.5 稳定性与后验

```text
检查留一门店和留一月计算可复现
检查时间敏感锚点是否进入分月购物篮路径
观察下一周期目标画像购买、19:30 前动销和商品毛利是否延续
```

下一周期结果用于评估算法，不直接修改当前正式结果。

### 32.6 边界场景

必须验证：

```text
没有目标画像消费
只有 1 个或 2 个有效 SKU
所有 SKU 指标完全相同
1 人中 1 人复购
其他画像 0 人购买目标 SKU
只有一种消费者类型
商品基础表一对多或换码冲突
可订可售但没有近期订购
没有非促销 SKU 日
售罄率超过 110%
混合计量类型
依赖一个月或一家门店
全部小分类分别计算并合并展示
```

## 33. 不能做的事

```text
不能把候选新品当成算法 04 已验证的现有锚点
不能根据两条独立二项规则擅自拼出三属性新品
不能只看目标画像内部销量而不与其他画像比较偏好
不能将 1/1 的 100%复购与 100/100 等同评分
不能使用固定最小会员数替代统计证据
不能使用固定销售、复购和毛利权重
不能把订购率直接加入综合得分
不能只看售罄率而忽略实际到货和销售深度
不能平均门店日售罄率
不能把超过 110%的售罄率截断为 100%
不能用 19:30 后销售额占比代替半小时折扣阶梯
不能再次从现有商品毛利额中扣减损耗
不能把商品属性缺失值交给 AI 编造
不能仅凭名称相似合并商品编码
不能因为 SKU 当前在售而从算法 04 删除它
不能用大分类或中分类结果替代小分类具体锚点
不能将不同比较组的综合得分直接横向比较
不能将 SKU 综合表现得分解释为新品成功概率
```
