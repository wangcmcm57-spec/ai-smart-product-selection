# 算法卡 07：竞品与全球外部趋势新品发现算法

文档状态：业务规则已确认  
适用范围：使用国内外竞品、社媒和行业公开数据发现或验证具象新品候选  
唯一业务目标：新品开发  
正式运行：外部数据按日采集、按周预警，每月冻结正式候选并关联算法 01—06 版本  
确认日期：2026-07-28

## 1. 算法澄清表

| 项目 | 业务问题 | 已确认规则 |
|---|---|---|
| 算法名称 | 第 7 个算法叫什么 | 竞品与全球外部趋势新品发现算法 |
| 业务目标 | 外部数据解决什么问题 | 同时发现内部尚未出现的新品属性，并验证算法 04—06 产生的内部新品候选 |
| 业务边界 | 外部趋势能否直接推荐 | 不能；必须映射正式叶子小分类，并通过内部主体需求、门店等级、消费者类型和价格可行性校验 |
| 业务动作 | 是否同时做促销、陈列或清退 | 不做；全部输出只服务新品开发，不生成促销、陈列、订购、升级、替换或清退动作 |
| 计算对象 | 外部趋势最终按什么算 | 标准新品候选，由叶子小分类、主体商品、功能/口味/工艺属性和规格组成 |
| 正式粒度 | 一条最终结果代表什么 | 周期 + 城市/城市群 + 门店等级 + 消费者类型 + 叶子小分类 + 标准新品候选 |
| 候选路径 | 新品从哪里来 | 分为内部候选外部验证、外部发现内部匹配、内外部共同收敛三条路径 |
| 外部市场 | 只看国内吗 | 不；覆盖中国大陆、港澳台、欧洲、北美、日韩、东南亚等可配置市场 |
| 外部数据 | 使用哪些数据 | 竞品数据、社媒内容与互动、行业报告、法规标准、公开新闻、搜索与渠道指数 |
| 来源合成 | 三类外部数据是否等权 | 不等权也不设人工固定权重；先分别计算，再用分层贝叶斯模型根据历史可靠性动态合成 |
| 区域口径 | 全球趋势如何落到国内 | 各市场先独立计算，再识别跨市场扩散；最终必须在国内目标城市/城市群重新校验内部适配 |
| 词频口径 | 一篇内容重复出现是否重复计数 | 不重复；主指标为去重文档渗透率，同时保留独立账号覆盖率 |
| 新词发现 | 只使用已有词库吗 | 固定词库与新词发现并行；新词必须来自真实内容、能映射商品属性并保留来源 |
| 多语种 | 外文趋势词如何统一 | 保留原文，提取商品属性，使用多语种语义聚类映射统一属性，不可靠映射只进入观察池 |
| 趋势判断 | 如何区分热门与增长趋势 | 按周建立贝叶斯动态渗透率模型，同时识别水平、斜率、加速、变点、持续性和季节性 |
| 小样本 | 1 条增长到 2 条是否算强趋势 | 不直接算；模型使用分子和分母并输出可信区间，小样本自动扩大不确定性 |
| 季节性 | 不同市场的节日是否共用 | 不共用；每个市场建立当地节日、气候和消费日历基线 |
| 竞品相似 | 同款、高相似和同方向如何判断 | 先校验小分类、主材料、形态、加工方式和计量类型，再用训练后的多模态相似度模型比较功能、口味、工艺、规格、包装、场景、名称和图片 |
| 渗透分子 | 高相似品是否并入同款 | 不并入；分别输出同款渠道渗透率、高相似品渠道渗透率和趋势属性渠道渗透率 |
| 渗透分母 | 渠道总数是什么 | 同市场、同周期、同叶子小分类成功采集的有效可比渠道数 |
| 渗透区间 | 1/1 是否等于高渗透 | 不是；使用 Jeffreys-Beta 后验输出中位数和 95% 可信区间，正式证据使用下界 |
| 无销量竞品 | 平台一般没有销量怎么办 | 渠道渗透率为主验证指标；可验证销量、覆盖、持续在售、用户评价和价格稳定只作分层补充 |
| 社媒口碑 | 是否可以直接称为 NPS | 不可以；正式名称为 Social NPS Proxy，明确是自然社媒中的净推荐代理值 |
| 口碑样本 | 哪些内容进入 Social NPS Proxy | 只有明确购买、食用、使用、复购或退货证据的账号表达；想买和种草只进入趋势兴趣 |
| 口碑粒度 | 一个账号多次表达如何计 | 同一账号、同一标准商品、同一周期只计一票，使用最新且证据最充分的表达 |
| 口碑方法 | Social NPS Proxy 如何计算 | 推荐、中立、贬损三类账号使用 Jeffreys-Dirichlet 后验，对 `100*(推荐占比-贬损占比)` 输出中位数和 95% 可信区间 |
| 属性情绪 | 只看整体正负面吗 | 不；同时输出口味、新鲜度、健康功能、便利性、规格、包装、价格和烹饪体验等属性情绪 |
| 互动指标 | 点赞收藏是否代表推荐 | 不代表；只作同平台内的关注强度和传播速度，不进入 Social NPS Proxy，不跨平台直接相加 |
| 广告与刷量 | 如何避免营销热度冒充自然趋势 | 用内容重复、发布节奏、商业标记、账号历史和互动结构输出自然、营销和异常概率，三类内容分流 |
| 行业证据 | 报告和新闻如何计算 | 追溯原始出处，提取可验证结论，根据来源历史可靠性建立似然更新；同一报告的转载只算一个证据组 |
| 跨市场 | 什么叫全球扩散 | 各市场必须出现独立渠道、自然社媒或行业证据；同一品牌的全球统一新闻只算一次营销事件 |
| 证据融合 | 三类证据如何合成 | 分层贝叶斯证据模型动态学习来源可靠性，输出趋势真实、持续增长和跨市场扩散概率 |
| 正式门槛 | 5% FDR 会不会丢掉早期趋势 | 5% 贝叶斯 FDR 只用于正式趋势；全部有效增长信号仍保留在探索层或原始信号层 |
| 证据冲突 | 竞品高渗透但口碑负向怎么办 | 不平均为一个分数；使用冲突场景矩阵识别市场已验证、属性痛点、供给缺口、前瞻趋势和下降风险 |
| 趋势阶段 | 渗透率越高是否越值得开发 | 不是；同时判断新兴、成长、成熟、下降和季节回归，成熟市场只在存在明确属性空白时形成差异化新品 |
| 海外领先 | 海外强、国内弱怎么办 | 通过内部主体需求和基础可行性后可进入 `OVERSEAS_LEADING_EXPLORATORY`，只表述为海外前瞻试点，不得宣称国内已流行 |
| 内部适配 | 外部候选最低需要什么内部证据 | 算法 02 门店等级、03 目标消费者、04 主体商品需求和 05 价格规格可行性必须成立；算法 06 在存在配方或场景关联时作增强证据 |
| 画像适配 | 能否给社媒账号贴内部会员画像 | 不能；外部商品属性必须分别与各内部消费者类型的真实商品、规格、价格和场景行为匹配 |
| 门店等级 | 是否复用 A 级结论到其他等级 | 不；每个当期实际门店等级群从底层内部数据独立重算适配 |
| 外部价格 | 海外价格是否直接汇率换算 | 不；只比较来源市场同品类中的相对价格定位，国内建议价仍由算法 05 生成 |
| 属性组合 | 多个热词能否直接拼接 | 不能；只有在同一真实商品、同一内容语义或稳定组合中出现，并通过品类保持和价格校验才能合并 |
| 商品图片 | 图片使用什么顺序 | 同款竞品真实图、高相似竞品参考图、可追溯社媒实拍图、AI 开发示意图依次回退，每张图必须校验属性一致性并标记来源 |
| 开发要求 | 外部口碑如何转成商品要求 | 稳定正向属性转为核心卖点候选，稳定负向属性转为改良约束，不得推测或照抄竞品未公开配方 |
| 品类缺口 | 外部商品无法归类怎么办 | 进入 `CATEGORY_MAPPING_GAP`，保留证据但不强行归入最相似小分类；正式主数据建立后再重算 |
| 外部空结果 | 没有外部数据是否阻断内部候选 | 不阻断；输出 `NO_EXTERNAL_OBSERVATION`，不把未观察误解为趋势为零 |
| 采集缺失 | 平台采集失败是否记 0 | 不记 0；标记 `SOURCE_MISSING`，扩大不确定性，关键来源长期缺失时降级为数据不足 |
| 在售与历史失败 | 外部强趋势能否越过底层过滤 | 不能；算法 07 保留外部证据，算法 08 对当前在售同款/相似品和历史差销同款/相似品做硬过滤 |
| 法规与风险 | 算法 07 与 08 如何分工 | 算法 07 识别并传递风险线索，明确违法、禁用或无法归类的候选停止；其他风险由算法 08 正式判断 |
| 证据排序 | 多个候选如何排序 | 硬门禁后按证据层级与 Pareto 关系排序，不生成人工固定权重综合分 |
| 输出结构 | 产品只读一张宽表吗 | 不；底层证据、趋势状态、内部适配和最终候选分表存储，产品默认读最终候选表 |
| 产品展示 | 默认给采购看什么 | 默认展示具体商品、外部阶段、主要依据、口碑痛点、内部适配和图片来源；追问再下钻公式、区间和原始链接 |
| 更新频率 | 外部数据与内部周期不同怎么办 | 按日采集、按周预警、按月冻结正式候选；法规或安全事件可紧急重算 |
| 验收方式 | 怎么证明算法可以上线 | 固定公式复算、多语种映射验收、竞品相似与情绪模型验收、历史滚动回测、原始来源对账和端到端血缘验收 |

## 2. 算法定位与边界

### 2.1 唯一业务目标

算法 07 只服务一个目标：形成可以交给采购和供应商的具象新品候选。

```text
外部数据回答：
市场上正在出现什么具体商品或属性
该趋势是自然增长、市场成熟、供给缺口还是短期营销
现有竞品的正向卖点和负向痛点是什么

内部数据回答：
该商品主体是否适合目标城市、门店等级和消费者类型
该规格和价格是否可行
该配方或场景是否有真实购物篮证据
```

只有当外部趋势与内部主体需求在正式小分类内完成匹配，才能输出到新品候选表。

### 2.2 两条发现路径

```text
路径 A：内部候选外部验证
算法 04—06 生成具象新品
-> 算法 07 查找同款/相似竞品、渠道渗透、口碑和趋势
-> INTERNAL_CANDIDATE_EXTERNAL_VALIDATED

路径 B：外部趋势内部匹配
算法 07 发现 Omega-3 等外部属性
-> 映射鲜鸡蛋小分类和标准商品候选
-> 算法 02—05 验证门店、画像、主体需求、规格和价格
-> EXTERNAL_DISCOVERED_INTERNAL_MATCHED
```

两条路径分别产生证据时，输出 `INTERNAL_EXTERNAL_CONVERGED`，但不得覆盖任何一条原始证据链。

### 2.3 本算法不做的事

```text
不把社媒用户推断成内部会员画像
不把外部热词直接当成商品名
不把广告热度当成自然口碑
不把没有数据当成趋势为零
不对不同平台的原始销量或互动量直接相加
不将海外价格按汇率换算成国内建议价
不使用人工固定权重生成综合趋势分
不产生促销、陈列、订购、升级、替换或清退动作
```

## 3. 正式范围与计算粒度

### 3.1 市场与国内落点

外部证据的基础粒度为：

```text
external_period
+ source_market
+ source_type
+ source_platform
+ leaf_category_id
+ standard_candidate_id
```

国内新品候选的正式粒度为：

```text
formal_period
+ target_city_group_id
+ category_level_version
+ final_level
+ profile_model_version
+ final_profile
+ leaf_category_id
+ standard_candidate_id
```

外部趋势可以在多个国内范围共享，但内部适配必须在每个城市/城市群、门店等级和消费者类型下独立重算。

### 3.2 大中分类和全选

```text
选择大分类
-> 展开到所有叶子小分类
-> 每个小分类独立映射、趋势建模和内部匹配
-> 最后合并展示
```

不得将大分类的趋势分数平均分配到小分类，不得用“健康快手菜”类泛词替代叶子小分类专用商品。

## 4. 数据周期、更新和版本

### 4.1 双频更新

| 任务 | 频率 | 产物 |
|---|---|---|
| 原始数据采集 | 按日 | 带时间戳的原始来源快照 |
| 趋势词、变点和扩散监测 | 按周 | 探索预警，不直接覆盖正式月度结果 |

### 4.2 当期证据与历史学习

```text

只使用 external_data_cutoff 及之前已发布、已采集的数据

```

不允许使用截止日之后的帖子、渠道上架、行业报告或试点结果评价当期候选。

## 6. 数据合规与来源治理

### 6.1 可使用数据

```text
公开页面
正式公开接口
已授权数据源
符合内部法务和安全规则的已采集数据
```

登录凭据只能由独立密钥管理系统保管，不得出现在算法卡、SQL、日志、结果表或产品页面。

### 6.2 来源血缘

每个外部属性和图片至少保留：

```text
source_id
source_type
source_market
platform_or_publisher
source_url
publish_at
capture_at
content_hash
authorization_status
valid_to
```

来源删除、链接失效或授权撤回后，必须能定位受影响的属性、候选和图片并触发重算。

## 7. 前置过滤与质量状态

### 7.1 采集状态

```text
SOURCE_VALID：采集成功且关键字段可用
SOURCE_PARTIAL：采集成功但部分字段缺失
SOURCE_MISSING：本期采集失败或未获得数据
SOURCE_EXPIRED：来源超过有效期
SOURCE_REVOKED：授权撤回或不允许继续使用
```

`SOURCE_MISSING` 不得写入任何趋势或渗透率分子、分母。

### 7.2 重复与传播事件

对文本、图片、视频指纹、原始链接和发布时间建立重复聚类：

```text
完全转载 -> 同一 content_cluster_id
同一原始报告转载 -> 同一 reprint_group_id
同一品牌全球发布 -> 同一 campaign_event_id
独立用户体验 -> 独立 organic_evidence_id
```

趋势文档计数对同一 `content_cluster_id` 只计一次。

### 7.3 自然、营销与异常内容

联合使用：

```text
商业合作和广告标记
购买链接和统一口播
文本、图片和视频重复率
账号发布频率与历史商业内容占比
短时间集中发布
互动账号网络和异常互动结构
```

模型输出：

```text
p_organic
p_marketing
p_suspicious
```

自然内容进入正式社媒趋势，营销内容只进入营销热度，不确定内容进入低证据池。分流概率阈值由独立标注集的校准和预期误判损失产生，不使用单一关键词人工一票否决。

## 8. 多语种商品实体与属性标准化

### 8.1 标准属性结构

每条竞品或内容提取：

```text
leaf_category_id
product_subject
main_ingredient
secondary_ingredient
function_claim
flavor
process
product_form
cooking_method
spec_value / spec_unit
package_type
storage_method
consumption_scene
target_user_expression
```

标准新品候选不是一个文本向量，而是一组可追溯、可对比和可校验的结构化属性。

### 8.2 多语种映射链

```text
语言识别
-> 保留原始词和原始上下文
-> 多语种商品实体识别
-> 语义聚类同义表达
-> 映射中文标准属性编码
-> 叶子小分类与属性允许维度校验
```

示例：

```text
high protein
高たんぱく
고단백
高蛋白
-> ATTRIBUTE_FUNCTION_HIGH_PROTEIN
```

每次映射输出 `mapping_probability`、`mapping_evidence`和 `ontology_version`。无法可靠映射的词保留原始证据，但不进入新品名。

### 8.3 固定词库与新词发现

```text
已知属性：
使用版本化商品属性词库持续监测

新词：
从商品名、标题、正文和标签提取新名词短语
-> 在去重文档中计算渗透和变点
-> 与已有属性语义聚类
-> 能映射商品主体或属性后进入探索层
```

AI 可以帮助识别和翻译，但不得生成原始数据中不存在的趋势词。

### 8.4 品类映射缺口

```text
能映射正式叶子小分类
-> 继续计算

与所有现有小分类的主体和形态边界均不符
-> CATEGORY_MAPPING_GAP
-> 保留外部证据
-> 正式分类建立后再重算
```

不允许将无法归类的商品强行放入语义最相似小分类。

## 9. 竞品同款与相似关系

### 9.1 核心边界校验

在计算语义或图片相似度前，先校验：

```text
leaf_category_id
product_subject
main_ingredient
product_form
process_or_cooking_method
measurement_type
```

主体或商品形态冲突时，不得因名称中都有“黑椒牛肉”就判为高相似。

### 9.2 多模态相似模型

通过核心边界后，比较：

```text
function_claim
flavor
process
spec_segment
package_type
storage_method
consumption_scene
multilingual_name_embedding
image_embedding
OCR_text
```

使用已确认的同款、高相似、同方向和无关商品对训练模型，并对概率做校准。不设置主材料 30%、口味 20% 等人工固定权重。

### 9.3 关系状态

```text
EXACT_EQUIVALENT
主体、核心属性、形态、工艺和规格段一致

BUSINESS_HIGH_SIMILAR
解决同一主体需求，但部分口味、规格或包装不同

SAME_TREND_DIRECTION
共享一个功能、工艺或场景趋势，但不是同款或高相似商品

UNRELATED_PRODUCT
核心主体、形态或消费需求不同
```

相似阈值在独立验证集上通过校准、预期误匹配损失和贝叶斯 FDR 产生，不由采购逐个小分类填固定阈值。

## 10. 竞品渠道渗透率

### 10.1 有效可比渠道

对市场 `m`、周期 `t`、小分类 `c`：

```text
C_eligible(m,t,c)
= 本期成功采集该小分类的独立零售平台/零售品牌集合
```

采集失败、未监控该品类或来源过期的渠道不进入分母。

### 10.2 三层渗透率

```text
exact_penetration_raw
= 出现 EXACT_EQUIVALENT 的有效渠道数 / 有效可比渠道总数

high_similar_penetration_raw
= 出现 BUSINESS_HIGH_SIMILAR 的有效渠道数 / 有效可比渠道总数

attribute_penetration_raw
= 出现目标趋势属性且保持当前小分类的有效渠道数 / 有效可比渠道总数
```

三个分子必须独立保留，不得用属性渗透率冒充同款商品渗透率。

### 10.3 Jeffreys-Beta 后验

对任一层渗透率，设：

```text
x = 出现该商品/属性的有效渠道数
n = 有效可比渠道总数

penetration_probability
~ Beta(x+0.5,n-x+0.5)
```

输出：

```text
penetration_raw = x/n
penetration_posterior_median
penetration_ci_low_95
penetration_ci_high_95
```

`1/1` 的原始渗透率虽然是 100%，但可信区间很宽，只能作为低证据观察。

### 10.4 持续在售与新品扩散

每个标准候选同时输出：

```text
first_seen_at
continuous_observed_periods
active_channel_count_by_period
channel_entry_count
channel_exit_count
price_position_by_market
promotion_dependency_observed
```

高渗透、长期稳定只表示成熟市场，不直接等于新品机会。

## 11. 社媒趋势词频与传播

### 11.1 去重文档渗透率

对市场 `m`、来源 `s`、小分类 `c`、属性 `a`、周 `t`：

```text
y_doc(m,s,c,a,t)
= 包含属性 a 的有效自然去重内容数

N_doc(m,s,c,t)
= 该市场、来源、小分类当周全部有效自然去重内容数

document_penetration_raw
= y_doc/N_doc
```

同一内容中属性词出现多次只计一篇。

### 11.2 独立账号覆盖率

```text
y_author(m,s,c,a,t)
= 当周提及属性 a 的独立有效匿名账号数

N_author(m,s,c,t)
= 当周发布该小分类有效自然内容的独立账号总数

author_coverage_raw
= y_author/N_author
```

文档渗透上升但独立账号覆盖不上升，往往意味着少数账号重复传播，不得直接判为广泛趋势。

### 11.3 互动强度

点赞、收藏、评论和播放量只在：

```text
同平台
同小分类
相近发布时间
可比账号规模
```

内做稳健标准化。输出传播速度和关注强度诊断，不进入 Social NPS Proxy，不将不同平台的原始互动量相加。

## 12. 贝叶斯动态趋势模型

### 12.1 基础观测模型

```text
y_t = 当周包含趋势属性的有效去重文档数
N_t = 当周同市场、来源、小分类有效去重文档总数

y_t ~ Binomial(N_t,p_t)
```

不直接对 `y_t` 做环比，因为每周平台可观测内容总数不同。

### 12.2 状态方程

一个可直接实现的正式结构为：

```text
logit(p_t)
= level_t
+ season_market_week_t
+ local_calendar_t
+ source_random_effect

level_t = level_(t-1) + slope_(t-1) + eta_t
slope_t = slope_(t-1) + zeta_t
```

`eta_t` 和 `zeta_t` 使用稳健重尾扰动，避免单周异常点破坏整条趋势。变点通过 `zeta_t` 的稀疏跳变或状态切换后验识别。

### 12.3 趋势输出

```text
penetration_posterior_median_t
penetration_ci_low_95_t
penetration_ci_high_95_t
p_slope_positive
p_acceleration_positive
p_change_point
expected_persistence_periods
seasonality_state
```

阶段不由“环比增长 20%”类固定阈值决定，而是由状态后验、季节基线和历史滚动回测共同产生。

### 12.4 各市场季节基线

每个市场分别配置：

```text
当地法定节假日
当地气候季节
宗教或文化消费周期
当地零售大促节奏
品类自然生产与上市季
```

只有超出该市场历史同期基线的新增部分才能解释为趋势增长。

## 13. Social NPS Proxy 与属性口碑

### 13.1 正式口碑样本

先将内容按消费证据分层：

| 内容证据 | 处理 |
|---|---|
| 明确购买、食用、使用、复购、退货或拒绝再购 | 进入正式 Social NPS Proxy |
| 想买、种草、询价、看起来不错 | 只进入趋势兴趣，不进入 Social NPS Proxy |
| 广告、品牌投放、带货或统一营销话术 | 只进入营销热度 |
| 无法判断是否真实体验 | 进入低证据观察池 |

评论区的真实使用表达可以进入正式样本，但评论账号与原帖账号独立匿名去重。

### 13.2 账号级唯一表达

在同一：

```text
source_market
+ platform_id
+ anonymous_author_id
+ standard_candidate_id
+ formal_period
```

下只保留一条正式表达。优先级为：

```text
有复购/退货证据
> 有明确购买或使用证据
> 只有一般体验表达

同证据级别取最新表达
```

这一规则防止一个高频账号将口碑放大多次。

### 13.3 推荐、中立与贬损

```text
PROMOTER
明确推荐、愿意复购、已复购或主动分享给他人

NEUTRAL
陈述体验但推荐意愿不明，或正负面抵消且无明确决策

DETRACTOR
明确不推荐、踩雷、退货、拒绝再购或劝阻他人购买
```

模型必须处理否定、转折和多属性上下文，不使用正向词数减负向词数的简单计数。

### 13.4 Jeffreys-Dirichlet 后验

设：

```text
n_promoter = 推荐账号数
n_neutral = 中立账号数
n_detractor = 贬损账号数
```

使用三分类 Jeffreys 先验：

```text
(p_promoter,p_neutral,p_detractor)
~ Dirichlet(
    n_promoter+0.5,
    n_neutral+0.5,
    n_detractor+0.5
)
```

每次联合后验取值计算：

```text
social_nps_proxy
= 100*(p_promoter-p_detractor)
```

输出：

```text
social_nps_proxy_raw
social_nps_proxy_posterior_median
social_nps_proxy_ci_low_95
social_nps_proxy_ci_high_95
n_promoter
n_neutral
n_detractor
```

Social NPS Proxy 不是标准问卷 NPS，产品页不得省略“社媒净推荐代理值”标识。

### 13.5 属性级口碑

对每个有明确上下文的属性分别输出：

```text
attribute_code
attribute_sentiment_positive_probability
attribute_sentiment_neutral_probability
attribute_sentiment_negative_probability
attribute_experienced_author_count
attribute_positive_reason
attribute_negative_reason
```

口味、新鲜度、健康功能、便利性、规格分量、包装、价格感知和烹饪体验必须分开。

```text
“Omega-3 概念很好，但腥味大且太贵”
-> 功能属性：正向
-> 口味属性：负向
-> 价格属性：负向
```

不得将该内容简化为整体中立而丢掉开发信息。

## 14. 行业、公开资料和法规证据

### 14.1 来源层级

| 层级 | 来源 | 可用方式 |
|---|---|---|
| 一级 | 政府、监管机构、统计机构、正式标准、学术研究 | 确认法规、标准、宏观统计或已验证事实 |
| 二级 | 行业协会、审计口径市场报告、零售监测、平台公开指数 | 补充市场规模、增长方向和渠道结构 |
| 三级 | 企业新品发布、专业媒体、渠道新闻 | 识别产品与上市事件，不直接代表自然需求 |
| 四级 | 普通转载、无原始口径自媒体观点 | 只作线索，不独立形成正式证据 |

来源层级不是固定分数。一级法规证据可以确认原料是否合法，但不能因此确认消费需求增长。

### 14.2 可计算结论提取

一条行业证据必须拆成：

```text
claim_subject
claim_attribute
claim_market
claim_period
claim_direction = GROWING / STABLE / DECLINING / FACT_ONLY
claim_value
claim_unit
sample_scope
method_available_flag
```

没有统计周期、样本口径或原始出处时，证据完整度降级。

### 14.3 来源可靠性似然

对来源 `s`、证据类型 `e`：

```text
LR_(s,e)
= P(observed_claim | future_trend_realized,s,e)
  / P(observed_claim | future_trend_not_realized,s,e)
```

分子和分母由历史滚动验证学习。同一 `reprint_group_id` 只使用一次似然贡献，相关来源在分层模型中共享证据组随机效应，避免将转载当成独立证据相乘。

### 14.4 时效衰减

```text
社媒与渠道趋势：
衰减速度按市场和小分类历史预测有效期学习

行业报告：
使用 data_period_end 计算时效，不只看 publish_at

企业新品新闻：
后续没有渠道或自然社媒扩散时快速降级

法规和正式标准：
在修订、废止或替代前持续有效
```

不使用所有数据统一 90 天失效等固定衰减参数。

## 15. 来源可靠性学习与冷启动

### 15.1 历史滚动学习

在每个历史截止日 `T`：

```text
1. 只使用 T 及之前的竞品、社媒和行业证据
2. 预测候选后续是否持续增长和扩散
3. 使用 T 之后的渠道渗透、自然文档渗透和市场扩散作为验证
4. 更新各来源对后续真实扩散的校准可靠性
```

短期广告爆发后快速消失的属性不标记为已实现趋势。后续持续增长并进入更多独立渠道或市场才标记为已实现。

公司最终是否开发该商品不作为全球趋势真假标签，因为其受到采购选择和供应能力影响。

### 15.2 预测周期选择

对每个叶子小分类候选多个后续观察窗口，使用滚动回测的对数损失、Brier Score、校准误差和预测区间覆盖选择正式窗口。不统一设置“所有品类都看后续 90 天”。

### 15.3 新来源冷启动

新国家、平台或数据源没有历史时：

```text
优先借用相同来源类型 + 相近市场 + 同小分类的上层先验
-> 保留 local_data_weight 和 borrowed_prior_level
-> 因本地样本少而自动扩大可信区间
-> 数据积累后逐步由本来源后验替代上层先验
```

单一冷启动来源原则上只形成探索证据。法规、强制标准等一级事实证据不受该限制，但仍不能冒充市场需求。

## 16. 跨市场扩散

### 16.1 独立市场信号

对每个市场分别记录：

```text
first_observed_at
first_organic_signal_at
trend_change_point_at
first_channel_presence_at
growth_state_entered_at
formal_state_entered_at
```

跨市场扩散必须由不同市场的独立自然社媒、渠道上架或原生行业证据支持。

### 16.2 统一营销事件去重

```text
同一品牌
+ 相同产品图片/新闻文本
+ 相近全球发布时间
-> 同一 campaign_event_id
```

该事件可证明品牌在多市场同步投放，但不能独立证明各市场已自然采用。

### 16.3 扩散输出

```text
origin_market_probability
market_adoption_probability
p_cross_market_diffusion
independent_adopting_market_count
diffusion_path
campaign_only_market_count
```

产品上的“由日韩向港台与中国大陆扩散”必须能下钻到每个市场的独立证据和时间顺序。

## 17. 分层贝叶斯外部证据融合

### 17.1 不使用固定权重

算法不设置：

```text
竞品 40%
社媒 35%
行业 25%
```

原因是各品类、市场和时间的来源覆盖与可靠性不同。

### 17.2 待估状态

对候选 `i`、市场 `m`、周期 `t`建立潜在状态：

```text
T_real(i,m,t) = 外部趋势是真实可重复信号
T_grow(i,m,t) = 趋势处于持续增长状态
T_diffuse(i,t) = 趋势正在跨市场独立扩散
```

### 17.3 可复现模型结构

将各来源已标准化且带不确定性的证据输入分层模型：

```text
logit P(T_grow=1)
= alpha_leaf_category
+ market_random_effect
+ beta_competitor * z_competitor
+ beta_social * z_social
+ beta_industry * z_industry
+ beta_diffusion * z_diffusion
+ source_reliability_random_effect
+ evidence_group_random_effect
```

其中：

```text
z_competitor：渠道渗透后验、持续在售和新进渠道的联合证据
z_social：自然文档渗透趋势、独立账号覆盖和传播强度
z_industry：原始行业证据似然和时效
z_diffusion：跨市场独立采用证据
```

`beta_*` 不是人工权重，而是历史滚动训练中学习的来源预测系数，并使用分层收缩防止小样本系数极端。

### 17.4 数据缺失与冲突

```text
某一来源缺失
-> 该 z 为未观察
-> 使用其他证据和分层先验
-> 后验不确定性变大

多来源方向冲突
-> 各来源证据原值保留
-> 输出冲突状态
-> 不通过平均分数消灭冲突
```

### 17.5 正式输出概率

```text
p_trend_real
p_sustained_growth
p_cross_market_diffusion
trend_growth_ci_low_95
trend_growth_posterior_median
trend_growth_ci_high_95
```

## 18. 发现层、正式层与贝叶斯 FDR

### 18.1 三层证据池

```text
趋势发现层：
保留所有有效、可映射的属性信号
不使用 5% FDR 删除发现项

正式证据层：
可信区间、稳定性和贝叶斯 FDR 全部通过

探索/原始信号层：
有正向增长、变点或海外领先证据，但尚未通过正式门槛
```

### 18.2 局部误发现率

对同一正式范围中的每个候选计算：

```text
local_false_discovery_rate_i
= P(T_grow_i=0 | current_external_data)
```

按 `local_false_discovery_rate` 从低到高排序，选择最大规则集合，使：

```text
mean(local_false_discovery_rate of selected candidates) <= 5%
```

5% 只是正式趋势证据的统计误报上限，不决定发现池保留多少趋势。

### 18.3 正式趋势条件

```text
存在真实外部观测
且趋势增长 95% 后验区间下界 > 0
且通过 5% 贝叶斯 FDR
且数值计算收敛
且删除单一平台、单一市场或单一月份后未完全反转
且广告/异常内容分流未失效
```

只在单一市场成立的趋势可以是该市场的正式趋势，但不能表述为全球趋势。

### 18.4 数值可重复

后验联合取值使用确定性 Sobol 准蒙特卡洛序列，种子由：

```text
algorithm_version
+ run_id
+ source_market
+ standard_candidate_id
```

生成。取值量逐轮加倍，直到主要分位数和后验概率按结果表精度四舍五入后连续两轮不变。未收敛输出 `COMPUTE_UNSTABLE`，不进入正式趋势。

## 19. 趋势生命周期与证据冲突

### 19.1 生命周期状态

```text
EMERGING
渗透较低但增长后验明显为正，变点刚发生

GROWING
渠道、自然社媒或跨市场采用持续扩大

MATURE
渗透较高且稳定，只有存在明确属性空白或口碑痛点时才形成差异化新品

SEASONAL_RETURN
符合当地历史周期并在当期回归，不解释为全年增长

DECLINING
趋势斜率为负、渠道退出或自然口碑持续转弱
```

生命周期状态来自动态后验与历史回测，不用固定渗透率分段人工划分。

### 19.2 冲突场景矩阵

| 竞品/渠道 | 自然社媒 | 行业/扩散 | 业务解释 |
|---|---|---|---|
| 高渗透、持续在售 | 正向口碑 | 稳定或增长 | 市场已验证，只开发差异化空白 |
| 高渗透、持续在售 | 负向属性明显 | 仍稳定 | 需求存在，现有商品有可改良痛点 |
| 低渗透但新渠道增加 | 自然词频和账号覆盖上升 | 有多源支持 | 早期供给缺口，进入探索试点 |
| 海外增长 | 国内弱或缺失 | 海外跨市场扩散 | 海外领先前瞻，不表述为国内成熟 |
| 渗透下降 | 负向口碑或兴趣下降 | 无新市场扩散 | 下降趋势，不支持新品开发 |
| 只有营销热度 | 无真实体验 | 无独立渠道扩散 | 营销事件，不生成自然趋势 |

冲突输出 `CONFLICTING_EXTERNAL_EVIDENCE`，并保留冲突类型、各来源方向和可信区间。

## 20. 内部主体需求与本地适配

### 20.1 外部账号不贴内部画像

算法不根据社媒用户内容推断其是“上班族晚高峰型”或“小家庭高频”。外部候选必须与每个内部 `final_profile` 的真实小票和商品行为独立匹配。

### 20.2 外部发现候选的最低内部证据

```text
品类保持：
候选保持正式叶子小分类

门店等级：
读取算法 02 当期实际 final_level

目标消费者：
读取算法 03 的群体结构和 final_profile

主体需求：
算法 04 中目标小分类的主体商品存在稳定需求或正式锚点

规格和价格：
算法 05 存在内部价格带、成本毛利与建议价的可行交集

配方或场景：
有算法 06 规则时作增强证据，但 Omega-3 等外部功能属性不强制要求在内部购物篮中已出现
```

### 20.3 切换范围必须重算

切换以下任一条件：

```text
城市/城市群
门店等级
消费者类型
叶子小分类
```

都必须重读算法 02—06 对应粒度的底层结果。外部趋势可以不变，但不同范围的主体需求、规格价格和最终候选可以不同。

若多个范围最终得到相同新品，必须分别保留各自的内部证据，不得复制一个范围的结论。

### 20.4 本地需求不成立

```text
外部正式趋势成立
但目标范围内部主体需求不成立
-> EXTERNAL_TREND_NOT_LOCALLY_MATCHED
-> 保留全球趋势记录
-> 不生成该目标范围的新品候选
```

不得借用全国或其他城市的内部需求强行补齐当地结果。

## 21. 标准新品候选生成

### 21.1 标准候选结构

```text
standard_candidate_id
leaf_category_id
product_subject
main_ingredient
secondary_ingredient
function_claim
flavor
process
product_form
cooking_method
spec_segment
recommended_spec
package_type
storage_method
consumption_scene
```

`standard_candidate_id` 根据标准属性编码和版本生成，不根据展示名称的字面字符串生成。这样可以在多语种和多品牌下识别同一商品概念。

### 21.2 主体、创新属性和规格来源

```text
主体商品：
算法 04 的内部主体需求或正式锚点

配方属性：
算法 06 的正式配方关联，或算法 07 的真实外部商品配方证据

功能/工艺/包装属性：
算法 07 的竞品、社媒或行业趋势证据

规格和国内建议价：
算法 05
```

每个展示属性必须保留 `attribute_source_type`、`attribute_source_id`、`source_market`、`evidence_status`和 `mapping_probability`。

### 21.3 属性组合证据

不得因为多个属性分别热门就直接组合。属性 `a1...ak` 只在以下任一证据成立时合并：

```text
同一真实竞品中同时存在
同一真实社媒商品体验中明确指向同一商品
多个独立商品中形成稳定的属性组合项集
正式行业标准定义了不可分的组合属性
```

然后还必须通过：

```text
品类保持检验
属性语义一致性检验
算法 05 规格价格可行性
算法 08 风险门禁
```

示例：

```text
Omega-3 热门
三天鲜热门
低胆固醇热门

若无组合证据，分别生成：
Omega-3 鲜鸡蛋 12 枚
三天鲜鸡蛋 10 枚
低胆固醇鲜鸡蛋 12 枚

不得生成：
三天鲜 Omega-3 低胆固醇鸡蛋
```

### 21.4 具象商品名

标准展示名的基本结构为：

```text
[已验证功能/工艺]
+ [已验证配方/口味]
+ [主体商品]
+ [算法 05 规格]
```

商品名只使用有证据的属性。“健康”、“新鲜”、“便利”等不可量化的泛词不得单独进入商品名。

```text
可以：Omega-3 鲜鸡蛋 12 枚
可以：青椒黑椒牛柳丝 200g
不可以：健康新鲜鸡蛋
不可以：场景配料快手菜
```

### 21.5 正向属性与改良约束

对属性口碑输出：

```text
retain_attribute
稳定正向属性，作为卖点或基础需求

improve_constraint
稳定负向属性，转为口味、包装、规格、价格或烹饪改良要求

unsupported_attribute
无法追溯、只有营销表述或证据不足的属性，不进入开发要求
```

竞品未公开配方、原料比例或工艺参数不得由 AI 推测或照抄。

## 24. 法规识别与算法 08 风险接口

### 24.1 算法 07 前置识别

至少检查：

```text
原料是否允许用于国内目标食品类别
食品添加剂和限量是否允许
功能或营养声称是否允许对普通食品使用
商品名和宣称是否存在明显误导
商标、专利和特定工艺名称是否可用
国内生产、冷链和检测是否存在明显限制
```

### 24.2 硬停止与风险传递

```text
明确违法、禁用或无法归入国内食品分类
-> REGULATORY_STOP
-> 停止候选

存在不确定但可进一步确认
-> 传递 risk_evidence_id 给算法 08

供应稳定、成本毛利、历史失败、当前货盘重复
-> 由算法 08 正式门禁判断
```

### 24.3 当前在售和历史差销证据

算法 07 不删除外部趋势记录，因为在售商品也需要进行外部市场监测。但新品候选传入算法 08 后：

```text
当前在售同款或高相似品
-> 退出新品推荐池

历史差销同款或高相似品
-> 退出新品推荐池
```

外部趋势强不能直接推翻硬过滤。只有当主材料、功能、口味、工艺、规格或场景发生实质变化，且相似模型证明不再属于历史失败相似品，才能作为新候选重算。

## 25. 外部证据状态、候选来源与排序

### 25.1 外部证据状态

```text
FORMAL_GROWING_TREND
正式增长趋势，可作为新品外部证据

MATURE_MARKET_GAP
市场成熟，但存在明确属性痛点或供给空白

EMERGING_EXPLORATORY
早期增长信号，进入探索试点候选

OVERSEAS_LEADING_EXPLORATORY
海外领先、国内证据弱，只能表述为前瞻探索

CONFLICTING_EXTERNAL_EVIDENCE
竞品、社媒或行业证据冲突

DECLINING_EXTERNAL_TREND
外部趋势下降，不支持新品开发

RAW_EXTERNAL_SIGNAL
已发现可追溯信号，但证据不足

NO_EXTERNAL_OBSERVATION
没有可用外部数据，不等于反对内部候选

CATEGORY_MAPPING_GAP
无法映射正式叶子小分类

REGULATORY_STOP
明确不符合国内法规或分类准入
```

### 25.2 候选来源与开发状态

```text
INTERNAL_CANDIDATE_EXTERNAL_VALIDATED
EXTERNAL_DISCOVERED_INTERNAL_MATCHED
INTERNAL_EXTERNAL_CONVERGED
EXTERNAL_TREND_NOT_LOCALLY_MATCHED
```

候选来源和外部证据状态是两个不同字段。例如，一个外部发现候选可以是 `EXTERNAL_DISCOVERED_INTERNAL_MATCHED + OVERSEAS_LEADING_EXPLORATORY`。

候选进入算法 08 前，开发状态只允许使用：

```text
PENDING_ALGORITHM_08_GATE
正式增长或成熟市场空白候选，等待算法 08 风险门禁

EXPLORATORY_PENDING_ALGORITHM_08_GATE
新兴或海外领先探索候选，等待算法 08 风险门禁
```

`candidate_source_status` 表示候选从哪里产生，`external_evidence_status` 表示外部证据处于什么状态，`candidate_development_status` 表示候选在新品开发流程中的位置，三个字段不得互相替代。

### 25.3 硬门禁顺序

```text
法规停止
-> 品类映射缺口
-> 外部下降趋势
-> 本地主体需求不匹配
-> 算法 05 规格价格不可行
-> 算法 08 历史差销/当前货盘/供应/毛利/其他风险门禁
```

未通过硬门禁的候选不参与新品排序。

### 25.4 Pareto 排序

先按证据层级排序：

```text
内外部共同收敛的正式趋势
> 单路径正式趋势
> 成熟市场差异化空白
> 新兴探索趋势
> 海外领先探索
> 原始外部信号
```

同一层内比较：

```text
趋势持续性
渠道渗透可信下界
自然 Social NPS Proxy 及属性口碑
内部主体需求证据
算法 05 价格成本可行性
跨市场扩散证据
```

候选 A 在所有上述维度都不劣于 B，且至少一项严格更好，才判定 A 支配 B。无支配关系的候选并列展示优势，不强行加权成一个总分。

## 31. 产研与业务验收

### 31.1 固定公式复算

产研必须用固定数据得到：

| 测试 | 输入 | 期望后验中位数 | 期望 95% 可信区间 |
|---|---|---:|---:|
| 渠道渗透 | `x=5,n=8` | 61.97% | 29.48%—88.10% |
| 渠道渗透 | `x=2,n=5` | 40.68% | 9.44%—79.06% |
| 渠道渗透 | `x=4,n=5` | 77.89% | 37.14%—97.75% |
| 渠道渗透 | `x=0,n=6` | 3.57% | 0.01%—33.04% |
| Social NPS Proxy | `72/30/18` | 44.63 | 30.78—57.05 |
| Social NPS Proxy | `42/18/10` | 45.07 | 26.97—60.76 |
| Social NPS Proxy | `50/20/10` | 49.38 | 32.89—63.58 |

小数精度按结果表统一四舍五入。后验取值种子、取值量和收敛状态必须保留。

### 31.2 多语种映射验收

独立标注集必须分层覆盖：

```text
中国大陆、港台、欧洲、北美、日韩、东南亚
中文、英文、日文、韩文及当期实际支持语言
高频品类、低频品类、新词和分类缺口
主体、功能、口味、工艺、规格、包装和场景属性
```

样本量根据目标误差和置信区间计算，不固定抽 100 条。正式映射集合的误映射贝叶斯 FDR 不超过 5%；其他映射保留为探索或分类缺口。

### 31.3 竞品相似模型验收

独立商品对必须包含：

```text
同款不同语言名称
同款不同品牌
换包装和相近规格
同主材料不同商品形态
同口味跨小分类
只有趋势属性相同的无关商品
```

验收同时报告分类准确率、召回率、PR-AUC、Brier Score 和校准曲线。正式 `EXACT_EQUIVALENT` 和 `BUSINESS_HIGH_SIMILAR` 集合使用贝叶斯 FDR 控制误匹配，不只评估总体准确率。

### 31.4 内容、情绪和广告模型验收

独立标注与双人复核的用途是评估模型，不是由人工为每个品类制定商品阈值。验收必须覆盖：

```text
真实使用 / 想买种草 / 商业投放 / 不可判定
推荐 / 中立 / 贬损
否定、转折、反讽和多属性句子
文本转载、图片搬运、统一营销事件和异常账号网络
```

输出宏平均 F1、各类精确率/召回率、概率校准和贝叶斯 FDR。无法在正式误报限制内标签的内容必须进入中立或低证据池，不得强制分类为正向。

### 31.5 历史滚动回测

必须使用 rolling-origin 或 expanding-window 回测，不得随机打散时间。

对比基线：

```text
季节性同期基线
当期去重词频排名
固定时间窗口简单环比
只看渠道渗透率的基线
```

模型评估：

```text
Log Loss
Brier Score
PR-AUC
校准曲线与校准误差
趋势方向准确率
预测区间覆盖率
早期趋势召回与误报率
```

正式模型必须在关键概率损失和校准上优于季节性与简单词频基线，并通过配对时间分块 Bootstrap 的 95% 区间验证改善不是偶然。

### 31.6 稳定性和缺失测试

固定自动化测试必须包含：

```text
删除单一平台重算
删除单一市场重算
删除单一月份重算
采集失败不记 0
同一行业报告多次转载只计一次
同一品牌全球营销事件不冒充自然扩散
不同平台互动量不直接相加
外部数据缺失输出 NO_EXTERNAL_OBSERVATION
小分类无法映射输出 CATEGORY_MAPPING_GAP
```

### 31.7 图片和商品名验收

边界测试必须验证：

```text
鸡蛋候选不使用净菜或牛肉图
青椒黑椒牛柳丝不使用牛肉丸或牛肉面图
高相似图明确标记为参考图
AI 图明确标记为示意图且不含虚构品牌
商品名每个属性都有来源 ID
无组合证据不拼接多个热词
```

正式图片匹配集合在独立验证商品对上控制贝叶斯 FDR，不得只检查页面是否有图片加载成功。

### 31.8 端到端数据对账

任选一个最终候选，必须能追溯：

```text
最终商品名每个属性
-> 多语种映射或内部属性来源
-> 原始竞品/社媒/行业证据
-> 去重和自然/营销分流结果
-> 趋势和口碑后验
-> 内部算法 02—06 证据
-> 图片来源和匹配校验
-> 算法 08 风险接口
```

对账过程中任何一个无法追溯的商品名属性必须删除或降级候选。

## 32. 不能做的事

```text
不能将外部趋势单独作为最终新品推荐
不能将外部社媒账号推断成内部会员画像
不能将转载数、点赞数或广告数直接当成自然趋势
不能将同一行业报告的多次转载当成独立证据
不能将同一品牌的全球发布当成各市场自然扩散
不能将不同平台原始销量、播放量、点赞量或评论量直接相加
不能将采集失败或缺失数据写成 0
不能将 1/1 渠道渗透表述为高可信 100%
不能将同款、高相似品和趋势属性渗透混成一个分子
不能将社媒净推荐代理值宣称为标准问卷 NPS
不能将“想买”和“种草”写成真实购后推荐
不能将海外趋势写成国内已流行
不能将海外价格按汇率换算成国内建议价
不能将多个独立热词擅自拼成一个商品
不能将无法映射的商品强行归入语义最相似小分类
不能将无外部观测写成没有外部趋势
不能用人工固定权重综合分消灭证据冲突
不能将成熟高渗透市场直接解释为新品空白
不能因外部趋势强就越过历史差销相似品或当前货盘相似品过滤
不能在没有真实匹配图片时使用不相关商品图填充页面
不能将 AI 开发示意图冒充竞品实物图
不能让 AI 推测竞品未公开的配方、原料比例、检测值或生产工艺
不能在算法 08 风险门禁前宣称新品已正式进入开发
不能输出促销、陈列、订购、升级、替换或清退动作
```
