## 1. 能力名称

建议业务名称：

```text
门店品类场景画像能力
```

建议 Agent 名称：

```text
门店品类场景画像 Agent
```

建议系统内部能力名：

```text
store_category_scene_profile_agent
```

该能力可以作为消费者画像 Agent 的增强能力，也可以作为独立 Agent 被营销总控 Agent 调用。

## 2. 能力定位

门店品类场景画像不是给会员新增一个静态标签，也不是把门店等级直接贴到消费者身上。

它的核心定义是：

```text
在特定区域、特定品类、特定门店等级或门店经营类型下，
识别哪些消费者画像是真正贡献销售、贡献会员规模、贡献复购和贡献营销转化的人群。
```

它回答的问题是：

```text
什么区域
什么品类
什么门店群
什么消费者画像
适合什么营销目标
应该使用什么券、内容、投放和门店任务
```

它不回答的问题是：

```text
某个会员是否永远属于 A 级门店人群
全店哪个门店最好
全品类哪个 SKU 卖得最好
所有门店是否必须强制分成 A/B/C/D
只按销售额圈选消费者
```

## 3. 与基础消费者画像的关系

基础消费者画像是会员行为画像，粒度为：

```text
store_id + customer_id
```

基础画像由四个维度组成：

```text
时间行为：捡漏型 / 上班族晚高峰型 / 常规时段型
家庭规模：大家庭 / 小家庭
消费频次：高频 / 中频 / 低频
价格态度：价格敏感 / 价格非敏感
```

最终基础画像格式为：

```text
time_behavior + '-' + family_level + '-' + frequency_level + '-' + price_attitude
```

示例：

```text
常规时段型-小家庭-高频-价格非敏感
捡漏型-小家庭-低频-价格敏感
上班族晚高峰型-小家庭-高频-价格非敏感
```

门店品类场景画像是在基础画像之上增加场景维度：

```text
region_group
city
large_category
mid_category
small_category
store_category_level
grade_status
quadrant_type
consumer_profile
marketing_goal
```

因此它不是替代基础画像，而是把基础画像放回具体营销场景中重新判断价值。

## 4. 与门店品类等级的关系

门店品类等级用于判断：

```text
在同一个区域组、同一个品类下，哪些门店更适合承接该品类的经营、选品、营销和试点动作。
```

门店品类等级比较组固定为：

```text
region_group + large_category + mid_category + small_category
```

门店品类场景画像在此基础上继续回答：

```text
这些 A/B/C/D 或观察型门店群中，哪些消费者画像贡献最大？
这些消费者在该品类下买什么、什么时候买、是否复购、是否依赖促销？
这些人适合新品券、提频券、提客单券、召回券，还是不适合强触达？
```

## 5. 适用场景

该能力适用于：

```text
新品上市人群圈选
季节性商品营销规划
品类会员券发放
门店任务下发范围判断
提频券人群选择
提客单券人群选择
召回券人群选择
高潜商品试点人群选择
清库存或晚间消化人群选择
社媒投放种子人群选择
AI 选品中的目标消费者验证
```

不适用于：

```text
不区分区域和品类的全局会员排名
只按客单价发券
只按销售额发券
把门店等级当成消费者永久属性
没有商品、门店、品类场景的泛画像分析
```

## 6. 业务主链路

标准链路：

```text
商品或品类营销目标
-> 区域和品类确认
-> 门店品类等级识别
-> 同品类同等级门店群形成
-> 接入基础消费者画像
-> 计算门店群消费者画像贡献
-> 分析目标画像的品类消费共性
-> 推荐券策略、内容策略、投放策略和门店任务
-> 追踪效果并更新画像贡献
```

该链路的关键不是直接找 TOP SKU，而是先确定：

```text
哪些门店群适合推
这些门店群里谁是主力消费者
这些消费者在这个品类下有什么真实行为
```

## 9. 核心指标

### 9.1 贡献指标

```text
profile_sales_amt：该画像在场景内贡献销售额
profile_sales_share：该画像销售额占场景销售额比例
profile_buyer_cnt：该画像购买会员数
profile_buyer_share：该画像购买会员数占场景会员数比例
profile_ticket_cnt：该画像小票数
profile_ticket_share：该画像小票数占场景小票数比例
profile_avg_ticket_amt：该画像平均客单价
profile_sales_per_buyer：该画像人均贡献销售额
```

### 9.2 行为指标

```text
category_penetration_rate：该画像在目标品类的渗透率
repeat_buyer_cnt：该画像在目标品类的复购会员数
repurchase_rate：该画像在目标品类的复购率
days_since_last_purchase_median：该画像最近一次消费间隔中位数
days_since_last_category_purchase_median：该画像目标品类最近一次消费间隔中位数
pre19_sales_share：该画像 19 点前销售占比
after1930_sales_share：该画像 19:30 后销售占比
commute_sales_share：该画像 18:00-19:30 销售占比
promo_sales_share：该画像促销销售占比
hour_discount_sales_share：该画像时段折扣销售占比
avg_discount_rate：该画像平均折扣率
```

### 9.3 商品偏好指标

```text
top_sku_list：高贡献 SKU
top_sku_sales_share：头部 SKU 销售集中度
price_band_p25：成交价格 25 分位
price_band_p50：成交价格中位数
price_band_p75：成交价格 75 分位
preferred_spec：偏好规格
preferred_flavor：偏好口味
preferred_cooking_type：偏好加工形态
co_purchase_items：高连带商品
```

### 9.4 营销适配指标

```text
frequency_lift_potential：提频潜力
ticket_lift_potential：提客单潜力
new_product_trial_potential：新品尝鲜潜力
recall_potential：召回潜力
coupon_sensitivity：券敏感度
margin_protection_risk：毛利保护风险
discount_dependency_risk：折扣依赖风险
loss_risk：损耗风险
profile_priority_score：画像优先级分
```

其中 `coupon_sensitivity` 第一版可用价格态度、历史折扣依赖和券核销结果联合判断；若暂未接入券核销数据，则先输出观察型判断。

## 10. 场景画像优先级规则

场景画像优先级不使用全局固定阈值，应在同一场景内动态比较。

同一场景指：

```text
region_group + large_category + mid_category + small_category + category_level 或 grade_status
```

高、中、低判断建议综合使用：

```text
同场景分位数
同场景中位数
IQR 异常区间
时间窗口稳定性
营销效果回测
```

不得使用跨区域、跨品类、跨门店等级的统一固定阈值。

### 10.1 主力经营画像

判断逻辑：

```text
profile_sales_share 高
profile_buyer_share 高
profile_ticket_share 高
复购率稳定
折扣依赖风险可控
```

业务含义：

```text
该画像既贡献销售，也贡献会员规模，是新品、季节品、重点品类营销的优先人群。
```

推荐动作：

```text
新品尝鲜
季节品重点券
会员专属权益
组合购
门店重点陈列
内容投放种子人群
```

### 10.2 高客单小众画像

判断逻辑：

```text
profile_sales_share 高
profile_buyer_share 中低
profile_avg_ticket_amt 高
profile_sales_per_buyer 高
```

业务含义：

```text
人数不一定多，但单人价值高，适合高毛利商品、组合购和权益型营销。
```

推荐动作：

```text
高毛利商品推荐
满减阶梯券
会员专享组合
新品优先尝鲜
低频高价值人群唤醒
```

### 10.3 广覆盖低价值画像

判断逻辑：

```text
profile_buyer_share 高
profile_sales_share 中低
profile_avg_ticket_amt 低
```

业务含义：

```text
覆盖会员多，但客单或贡献偏低，适合提客单和连带购买策略。
```

推荐动作：

```text
满额券
加价购
关联商品组合券
早餐篮 / 晚餐篮 / 家庭餐篮
低门槛试探券
```

### 10.4 价格促动画像

判断逻辑：

```text
价格态度为价格敏感
promo_sales_share 高
avg_discount_rate 高
低折扣场景下动销弱
```

业务含义：

```text
该画像可能被优惠驱动，但需要重点控制毛利和补贴效率。
```

推荐动作：

```text
短有效期券
指定品类券
小额提频券
清库存券
预算上限控制
毛利保护线校验
```

### 10.5 自然需求画像

判断逻辑：

```text
价格态度为价格非敏感
pre19_sales_share 高
promo_sales_share 低
repurchase_rate 稳定
```

业务含义：

```text
该画像对商品本身有稳定需求，不需要过度依赖补贴。
```

推荐动作：

```text
新品内容种草
会员权益提醒
轻券或无券内容触达
高毛利商品推荐
长期复购运营
```

### 10.6 晚间消化画像

判断逻辑：

```text
time_behavior 为捡漏型
after1930_sales_share 高
hour_discount_sales_share 高
```

业务含义：

```text
该画像适合承接晚间临期、清货、损耗控制类动作，但不应混入 19 点前自然经营质量判断。
```

推荐动作：

```text
晚间清货提醒
临期折扣触达
库存消化任务
低预算私域触达
不作为新品自然需求主力判断
```

### 10.7 潜力培育画像

判断逻辑：

```text
profile_buyer_share 中低
repurchase_rate 或 category_penetration_rate 有增长
所在门店群为潜力培育型或 B/C 级可测试门店
```

业务含义：

```text
当前规模不大，但具备培育价值，适合小范围试点。
```

推荐动作：

```text
小范围测试券
新品试吃或尝鲜
低预算内容测试
门店导购任务
观察转化和复购
```

## 11. 营销动作映射

### 11.1 按门店品类等级映射

| 门店品类等级或标签 | 场景画像使用方式 | 推荐营销动作 |
|---|---|---|
| A | 优先识别主力经营画像和自然需求画像 | 重点新品、季节品、重点券、重点内容、较高预算 |
| B | 识别主力画像和潜力画像 | 小范围测试、适度发券、观察转化 |
| C | 只选高确定性画像 | 定向小券、低预算验证、提客单测试 |
| D | 原则上不做强营销 | 仅清库存、结构调整或诊断型动作 |
| 暂不分级 | 不做强动作 | 补数据、观察、人工复核 |
| 观察型 | 控制预算测试 | 低风险小样本测试 |
| 潜力培育型 | 关注增长画像 | 小范围新品、内容或会员券试点 |
| 质量改善型 | 先控经营质量 | 先改善毛利、折扣、损耗，再放大营销 |
| 谨慎经营型 | 暂缓强动作 | 低风险处理和问题诊断 |

### 11.2 按营销目标映射

| 营销目标 | 优先画像 | 核心判断 | 推荐动作 |
|---|---|---|---|
| 新品尝鲜 | 主力经营画像、自然需求画像、高客单小众画像 | 复购稳定、折扣依赖低、门店承接强 | 新品券、内容种草、A/B 门店试点 |
| 季节品营销 | 主力经营画像、广覆盖低价值画像 | 季节品类渗透高、会员覆盖足 | 季节主题券、组合购、门店陈列 |
| 提频 | 低频但品类偏好明确的画像 | 近期有购买但频次不足 | 短周期小额券、复购提醒 |
| 提客单 | 广覆盖低价值画像、高客单潜力画像 | 客单低但连带空间大 | 满额券、阶梯券、组合券 |
| 召回 | 历史主力但近期沉默的画像 | 历史贡献高、近期未购 | 短有效期召回券、强利益点触达 |
| 清库存 | 价格促动画像、晚间消化画像 | 对折扣或晚间价格敏感 | 指定商品券、晚间提醒、低预算触达 |
| 毛利改善 | 自然需求画像、高客单小众画像 | 折扣依赖低、接受价格高 | 少券或无券内容、高毛利组合 |
| 社媒投放 | 主力经营画像、自然需求画像、高价值画像 | 可作为相似人群种子 | 内容种草、相似人群扩展、私信互动 |

## 14. Agent 执行步骤

### 14.1 确认营销场景

输入：

```text
region_group
city
large_category
mid_category
small_category
marketing_goal
```

如果商品已经确定，需要先映射到：

```text
large_category
mid_category
small_category
```

不得跳过小分类直接生成泛化营销建议。

### 14.2 调用门店品类等级结果

按以下粒度取得门店群：

```text
region_group + large_category + mid_category + small_category
```

读取：

```text
category_level
grade_status
quadrant_type
grade_reason
risk_flags
```

如果门店品类等级为暂不分级、观察型或人工复核，场景画像不得输出高置信强营销建议。

### 14.3 接入基础消费者画像

按以下键关联：

```text
store_id + customer_id
```

必须使用四维基础画像：

```text
time_behavior
family_level
frequency_level
price_attitude
consumer_profile
```

不得输出旧标签：

```text
偏高频
偏低频
周末集中型
促销机会型
非促销驱动
```

周末行为、品类偏好、券敏感度可以作为扩展分析，不进入基础画像主标签。

### 14.4 计算场景画像贡献

在每个场景内，按 `consumer_profile` 聚合：

```text
sales_amt
buyer_cnt
ticket_cnt
avg_ticket_amt
sales_per_buyer
repurchase_rate
pre19_sales_share
promo_sales_share
hour_discount_sales_share
```

然后计算：

```text
profile_sales_share
profile_buyer_share
profile_ticket_share
```

优先级必须在同一场景内比较，不允许跨区域、跨品类、跨门店等级直接比较。

### 14.5 识别画像类型

至少输出以下类型之一：

```text
主力经营画像
高客单小众画像
广覆盖低价值画像
价格促动画像
自然需求画像
晚间消化画像
潜力培育画像
观察型画像
暂不建议画像
```

每个类型必须输出：

```text
判断原因
主要优势
主要风险
适合的营销动作
不适合的营销动作
```

### 14.6 分析品类内消费共性

确定目标消费者画像后，只在当前品类内继续分析：

```text
买什么 SKU
什么时间买
买多大规格
买什么价格带
是否买促销
是否买时段折扣
是否复购
和哪些商品一起买
是否集中在少数 SKU
```

最终输出不应停留在 TOP SKU，而应提炼为：

```text
这类消费者在这个门店群里偏好什么类型的商品。
```

### 14.7 输出营销建议

营销建议必须同时结合：

```text
门店品类等级
消费者画像类型
品类消费共性
营销目标
毛利、折扣和损耗风险
预算约束
```

输出动作包括：

```text
是否发券
发什么券
券门槛
券面额
有效期
目标门店
目标会员
内容方向
门店任务
投放预算建议
风险控制规则
```

## 15. 券策略衔接规则

| 场景画像 | 券策略 | 风控要求 |
|---|---|---|
| 主力经营画像 | 新品券、季节券、会员专属券 | 控制补贴，避免对自然需求过度让利 |
| 高客单小众画像 | 满额券、权益券、组合券 | 保证毛利，不做低价泛发 |
| 广覆盖低价值画像 | 提客单阶梯券、搭配购券 | 门槛按历史客单上浮设计 |
| 价格促动画像 | 小额短效券、指定品类券 | 设置预算上限和毛利保护线 |
| 自然需求画像 | 轻券、内容触达、权益提醒 | 优先少补贴或无补贴 |
| 晚间消化画像 | 晚间清货券、临期提醒 | 不作为新品自然需求判断 |
| 潜力培育画像 | 小样本测试券 | 观察复购和客单变化 |
| 暂不建议画像 | 不发强券 | 保留观察或人工复核 |

## 16. 内容和投放衔接规则

场景画像可以作为内容 Agent 和投放 Agent 的输入。

内容生成应包含：

```text
目标画像
消费场景
商品共性
门店等级
核心利益点
风险限制
```

投放扩展人群可以基于：

```text
主力经营画像
自然需求画像
高客单小众画像
高复购画像
低折扣依赖画像
```

不建议直接拿以下人群做高预算投放种子：

```text
仅靠时段折扣驱动的人群
仅靠高额券驱动的人群
样本量不足的人群
门店品类等级暂不分级的人群
```

## 17. 禁止事项

该 Agent 禁止：

```text
1. 禁止把门店等级写成会员永久标签。
2. 禁止脱离区域、品类和门店等级解释消费者画像。
3. 禁止用全店销售额代替门店品类等级。
4. 禁止用固定权重和固定前 30% 规则替代升级后的门店品类等级规则。
5. 禁止在样本不足时输出高置信营销建议。
6. 禁止把 hour_discount_rate 纳入 19 点前自然经营质量判断。
7. 禁止用 is_hour_promotion 判断 19 点前价格敏感。
8. 禁止输出旧版画像标签：偏高频、偏低频、周末集中型、促销机会型、非促销驱动。
9. 禁止只输出 TOP SKU，不提炼商品共性。
10. 禁止只给营销动作，不输出原因、风险和适用边界。
```

## 18. 异常处理

### 18.1 基础画像缺失

触发条件：

```text
目标门店群中的 customer_id 无法匹配基础消费者画像。
```

处理：

```text
保留销售统计
输出 missing_profile_cnt
该部分不参与画像优先级判断
必要时降级为观察型画像
```

### 18.2 门店品类等级不稳定

触发条件：

```text
grade_status 为暂不分级、观察型或人工复核
熵权分数差异不足
象限结果与综合分冲突
```

处理：

```text
不输出强营销建议
仅输出低预算测试或补数据建议
```

### 18.3 样本不足

触发条件：

```text
场景内会员数、小票数、销售额不足以支持稳定判断。
```

处理：

```text
profile_priority_type = 观察型画像
confidence_level = 低
recommended_action = 小样本测试或继续观察
```

### 18.4 毛利、损耗或品类映射缺失

触发条件：

```text
SKU 缺少品类、毛利率或损耗率。
```

处理：

```text
缺失 SKU 可以进入销售观察
不得进入质量评分和强营销建议
输出 mapping_missing_flag
```

## 20. 自检清单

每次运行或产出文档时必须检查：

```text
1. 是否保留基础消费者画像四维口径。
2. 是否按 store_id + customer_id 关联基础画像。
3. 是否按 region_group + large_category + mid_category + small_category 使用门店品类等级。
4. 是否没有把门店等级当成会员永久标签。
5. 是否采用升级后的门店品类等级规则。
6. 是否避免固定权重和固定比例分级。
7. 是否区分 19 点前促销折扣和晚间时段折扣。
8. 是否只在当前场景内比较画像优先级。
9. 是否输出销售贡献和会员覆盖两个维度。
10. 是否输出品类消费共性，而不是只输出 TOP SKU。
11. 是否输出营销动作、风险和置信度。
12. 是否对样本不足和映射缺失做降级处理。
```

任一关键检查不通过时，不得输出高置信营销建议，只能输出：

```text
观察型画像
暂不建议画像
人工复核
补数据后重算
```

## 21. 示例解释

示例场景：

```text
区域：上海
品类：肉禽蛋类 / 蛋类 / 鸡蛋类
门店群：A 级门店
营销目标：新品尝鲜
```

如果场景画像显示：

```text
常规时段型-小家庭-高频-价格非敏感
销售贡献高
会员覆盖高
19 点前销售占比高
促销依赖低
复购稳定
```

则该画像可解释为：

```text
上海鸡蛋类 A 级门店中，该画像是适合新品功能蛋、鲜度蛋和早餐篮连带的主力经营画像。
营销上应优先使用内容种草、轻券尝鲜和门店陈列，而不是大额补贴。
```

如果场景画像显示：

```text
捡漏型-小家庭-低频-价格敏感
19:30 后销售占比高
时段折扣销售占比高
低折扣下动销弱
```

则该画像可解释为：

```text
该画像适合晚间消化、临期提醒和清库存动作，不应作为新品自然需求主力人群。
```

## 22. 第一版落地建议

第一版先沉淀三张表：

```text
store_category_scene_profile_summary
store_category_scene_profile_product_commonality
store_category_scene_profile_marketing_action
```

第一版先支持四类营销目标：

```text
新品尝鲜
季节品营销
提频
提客单
```

第二版再接入：

```text
召回
券核销效果
社媒投放
私信互动
自动预算优化
```

第一版的判断重点不是自动化执行，而是把以下问题稳定回答清楚：

```text
这个品类在哪些门店群推？
这些门店群里谁是主力消费者？
这些消费者在该品类下买什么、怎么购买、是否依赖折扣？
应该用什么营销动作，哪些动作要避免？
```
