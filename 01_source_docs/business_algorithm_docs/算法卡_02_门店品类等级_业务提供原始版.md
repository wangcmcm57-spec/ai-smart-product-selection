# 算法卡 02：门店品类等级算法

文档状态：业务规则已确认  
适用范围：门店品类经营能力分层与 AI 选品  
正式评估周期：最近 3 个数据完整自然月  
参数与稳定性参考周期：最近 6 个完整自然月  
模型更新：每月正式更新  
确认日期：2026-07-19

## 1. 算法澄清表

| 项目 | 业务问题 | 已确认规则 |
|---|---|---|
| 算法名称 | 这个算法叫什么 | 门店品类等级算法 |
| 业务目标 | 解决什么问题 | 识别门店在指定品类上的经营承载能力，为新品试点、SKU 宽度、订购深度和商品调整提供依据 |
| 计算对象 | 按谁计算 | 按门店和指定品类颗粒度计算 |
| 计算粒度 | 一条结果代表什么 | 模型版本 + 范围版本 + 数据周期 + 城市或城市群 + 门店 + 品类颗粒度 + 品类编码 |
| 比较范围 | 门店和谁比较 | 门店只与同一城市或业务配置城市群、同一品类颗粒度的门店比较 |
| 品类颗粒度 | 支持哪些层级 | 大分类、中分类、小分类分别从底层数据重新聚合、重新评分，禁止平均下一级等级 |
| 数据周期 | 用多长时间 | 最近 3 个完整自然月生成唯一正式等级；最近 6 个月只用于稳定性、参数和权重回退 |
| 评价维度 | 从哪些方面评价 | 经营规模、货盘宽度、商品效率、盈利能力、订购健康、促销健康、损耗健康 |
| 时间口径 | 使用全天还是分时 | 销售、客流、会员、动销、销售品效和促销使用 19:00 前；毛利和损耗使用全日 |
| 标准化 | 如何避免极端门店干扰 | 对数或带符号对数 + 中位数/MAD 稳健标准化 |
| 权重来源 | 权重如何产生 | 二级指标按已确认规则合成；七个一级维度使用 CRITIC 动态赋权，不使用固定 0.35 等权重 |
| 分层方法 | 如何产生等级 | Jenks 自然断点 + BIC 动态选择 1—4 组，再通过重复抽样和滚动时间稳定性验证 |
| 等级数量 | 一定是 ABCD 吗 | 不固定；可为单一等级、A/B、A/B/C 或 A/B/C/D |
| 冲突与底线 | 高规模能否抵消亏损 | 不能完全抵消；连续亏损、严重损耗和数据质量会限制最高等级 |
| 唯一性 | 是否会产生多个正式等级 | 同一模型版本、范围、门店、品类颗粒度和品类只能有一个最终正式等级 |
| 验收方式 | 怎么判断合理 | 开发逐字段对数、分层人工复核、重复抽样稳定性、滚动窗口稳定性和下一周期经营验证 |

## 2. 业务目标与使用边界

本算法只回答：

```text
同一城市或城市群、同一品类下，哪些门店具备更强的品类经营承载能力？
```

结果供以下模块读取：

```text
门店群消费者画像贡献算法
目标画像 SKU 表现算法
新品候选方向生成算法
新品机会评分与试点范围选择
```

本算法不做：

```text
全店综合等级
跨品类门店比较
商品订购量预测
单独的促销因果分析报告
单独的损耗诊断报告
```

同一家门店可以在不同品类上获得不同等级，但同一正式版本、同一比较范围、同一品类只有一个最终等级。

## 3. 比较范围与品类颗粒度

### 3.1 正式比较范围

支持两种范围：

```text
CITY：单城市
CITY_CLUSTER：业务配置城市群
```

示例：

```text
CITY：上海
CITY_CLUSTER：清远 + 肇庆 + 云浮
```

城市群由业务配置表维护，算法可以提供相似城市建议，但不能自动修改正式范围。配置必须包含：

```text
scope_version
scope_type
scope_id
scope_name
city_code
effective_start_date
effective_end_date
approved_by
```

同一模型版本内，每家门店只能归属于一个正式评级范围。华东一区、华东二区和华东大区可作为组织汇总维度，但不重新计算第二个正式等级。

### 3.2 品类颗粒度

支持：

```text
LARGE：大分类
MIDDLE：中分类
SMALL：小分类
```

每个颗粒度都从交易、货盘、到货、毛利和损耗底层数据重新聚合：

```text
大分类等级 != 下属中分类等级平均
中分类等级 != 下属小分类等级平均
```

禁止对 A/B/C/D 编码取平均或对下一级综合分简单平均。

## 4. 数据周期与模型版本

### 4.1 正式周期

每月使用最近 3 个数据完整自然月生成正式等级。

例如 2026 年 7 月运行：

```text
level_start_date = 2026-04-01
level_end_date = 2026-06-30
```

最近 6 个完整自然月只用于：

```text
CRITIC 小样本回退
稳健标准化参数回退
分层滚动稳定性
阈值稳定性
长期参考分与趋势标记
```

最近 6 个月不生成第二个门店品类等级。

### 4.2 更新规则

```text
每月正式更新一次
同一正式版本在月内保持不变
周度结果只作诊断，不覆盖正式等级
数据修正可重跑同一版本，但必须保存修正原因
城市群配置变化必须生成新的 scope_version
```

## 6. 有效数据过滤

### 6.1 有效交易

只保留：

```text
门店、商品和业务日期不为空
已完成的正常销售交易
非退货、非退款、非取消、非冲销、非测试交易
销售金额、销售数量或销售重量符合正向销售口径
商品可以关联到正式品类
```

全量销售额和全量小票不因 `customer_id` 为空而删除。

### 6.2 有效会员

会员指标复用会员画像算法的过滤：

```text
customer_id 不为空
customer_id 不以 6 开头
剔除退货、取消、冲销、测试和非正交易
同一会员单日有效小票数 > 5 时，剔除该会员当天全部记录
```

### 6.3 有效营业日

```text
门店当天正常营业
AND 交易、货盘、到货数据均已完整入库
AND 该品类处于门店正式经营范围
```

门店正常营业且品类正式经营时，即使当天销售为 0，仍是有效营业日。闭店、品类尚未引入或已经正式退出的日期不计入。

### 6.4 有效在售 SKU 日与实际收货

在售状态窗口：

```text
从正式上架生效日开始
到正式下架生效日前一天结束
临时停售期间不计候选在售 SKU 日
```

日清模式下，正式评分使用的有效在售 SKU 日还必须满足：

```text
门店 SKU 当日实际收货重量或实际收货数量 > 0
```

最终确认的净到货口径：

```text
称重商品净到货量 = 门店当日实际收货重量
计件商品净到货量 = 门店当日实际收货数量
```

门店不存在 19:00 后到货，不做跨时段到货拆分。

当净到货量 `<= 0` 时：

```text
不计算该 SKU 日售罄率
不保留该 SKU 日的有效在售 SKU 天数
不填 0，不视为未动销
```

当 19:00 前销售量超过实际收货量 10% 以上：

```text
pre19_sales_qty / actual_received_qty > 1.10
或
pre19_sales_weight / actual_received_weight > 1.10
=> sell_through_abnormal_flag = 1
```

异常 SKU 日不参与售罄健康区间训练和订购健康得分，但有效交易仍可进入经营规模和销售品效。原始售罄率必须保留，禁止直接截断为 100%。

## 7. 通用稳健标准化

### 7.1 正向经营指标

销售额、小票数、会员数、SKU 数等正值指标：

```text
x_log = ln(1 + x)
M = median(x_log)
MAD = median(|x_log - M|)
robust_z = (x_log - M) / (1.4826 * MAD)
x_score = 100 * Phi(robust_z)
```

### 7.2 可为负的指标

毛利额、毛利品效和促销 ROI 可为负：

```text
x_log = SIGN(x) * ln(1 + ABS(x))
```

其余步骤与正向指标相同。

### 7.3 反向指标

损耗率和促销依赖率越低越健康：

```text
reverse_score = 100 * [1 - Phi(robust_z)]
```

### 7.4 异常值与兜底

```text
ABS(robust_z) > 3.5 => extreme_store_flag = 1
```

数据异常修正或剔除；真实旗舰店保留原始值和排名，但不能决定其他门店的最小值和最大值。

当 `MAD = 0`：

```text
优先使用同一正式范围、同一品类最近 6 个模型窗口的 MAD
仍为 0：该指标所有门店记 50 分，CRITIC 信息量记 0
```

## 8. CRITIC 动态赋权

### 8.1 公式

对标准化后的指标：

```text
sigma_j = 指标 j 的标准差
r_jk = 指标 j 与指标 k 的相关系数
C_j = sigma_j * SUM_k(1 - r_jk)
w_j = C_j / SUM_j(C_j)
```

指标差异越大、与其他指标重复越少，权重越高。

某指标标准差为 0 时，该指标 `C_j = 0`。存在空值时，相关系数只使用两个指标均有效的门店；配对样本不足时，相关矩阵判定为不稳定并执行小样本回退。全部指标 `SUM(C_j) = 0` 时禁止除法，直接执行权重回退。

### 8.2 小样本回退

```text
1. 优先使用当前正式范围和品类的有效门店计算
2. 当前相关矩阵不稳定时，使用同一范围最近 6 个模型窗口估计
3. 仍不稳定时，使用上一版已发布权重
4. 无历史权重时使用等权，weight_fallback_flag = 1
```

使用等权回退时输出低置信度，最终等级最高为 B。禁止扩大到华东大区计算权重。

## 9. 七个一级维度

### 9.1 经营规模

全部使用 19:00 前数据：

```text
日均总销售额 = 19 点前全部有效销售额 / 有效营业天数
日均总小票数 = 19 点前全部有效小票数 / 有效营业天数
周期有效会员数 = 19 点前去重有效会员 ID 数
```

销售额、小票数包含会员和非会员；会员数只使用有效会员。

三个指标稳健标准化后，使用 CRITIC 生成内部权重：

```text
scale_score = SUM(指标得分 * CRITIC 内部权重)
```

同时保留但不重复进入得分：

```text
日均有效会员小票数
有效会员销售额
会员销售额占比
会员小票占比
```

### 9.2 货盘宽度

```text
有效在售 SKU 天数 = 满足 6.4 规则的 SKU 日数量
19 点前动销 SKU 天数 = 有效在售 SKU 日中，19 点前至少有一笔有效销售的数量

日均在售 SKU 数 = 有效在售 SKU 天数 / 有效营业天数
日均 19 点前动销 SKU 数 = 19 点前动销 SKU 天数 / 有效营业天数
19 点前 SKU 动销率 = 19 点前动销 SKU 天数 / 有效在售 SKU 天数
```

三个正向指标稳健标准化后，使用 CRITIC 生成：

```text
assortment_width_score
```

### 9.3 商品效率

```text
单 SKU 日均销售产出 = 19 点前有效销售额 / 有效在售 SKU 天数
单 SKU 日均毛利产出 = 全日全链路毛利额 / 有效在售 SKU 天数
```

销售品效使用正向对数，毛利品效使用带符号对数。分别稳健标准化后：

```text
sku_efficiency_score =
SQRT(sales_productivity_score * profit_productivity_score)
```

在售 SKU 天数为 0 时不执行除法，标记 `assortment_data_error_flag = 1`。

### 9.4 盈利能力

全部使用全日数据：

```text
日均全链路毛利额 = 全日全链路毛利额 / 有效营业天数
门店毛利率 = 全日门店毛利额 / 全日有效销售额
```

稳健标准化后：

```text
profitability_score =
SQRT(full_chain_profit_score * store_margin_score)
```

负毛利保留，不填 0。

### 9.5 订购健康

#### 9.5.1 原始售罄率

称重和计件商品分别计算：

```text
称重商品 19 点前售罄率 =
SUM(19 点前销售重量) / SUM(实际收货重量)

计件商品 19 点前售罄率 =
SUM(19 点前销售件数) / SUM(实际收货件数)
```

公斤与件数禁止相加，也不使用到货金额加权原始售罄率。

#### 9.5.2 健康区间训练

按以下范围分别训练：

```text
范围版本 + 城市或城市群 + 品类颗粒度 + 品类 + 计量类型
```

历史 SKU 日样本计算：

```text
净经营贡献 = 全链路毛利额 - 损耗金额
```

如果全链路毛利已扣损耗，不再次扣减。

健康区间同时满足：

```text
单位到货净贡献接近历史较优水平
损耗处于相对健康水平
增加到货后净经营贡献不再显著增加
```

在匹配后的相似经营日中计算：

```text
增量到货吸收率 =
(高到货日 19 点前销售量 - 低到货日 19 点前销售量)
/ (高到货日收货量 - 低到货日收货量)

边际净贡献 =
(高到货日净经营贡献 - 低到货日净经营贡献)
/ (高到货日收货量 - 低到货日收货量)
```

高售罄区间中边际净贡献仍显著大于 0，表示增加订购仍能带来利润，应识别为订购不足风险；低售罄区间中边际净贡献小于 0 且损耗上升，表示订购偏多。

相似经营日需要控制：

```text
同门店、同 SKU、相同星期类型、相近季节、相同促销状态、非异常节假日
```

售罄率统计组距使用 Freedman-Diaconis 初始组距：

```text
h = 2 * IQR(sell_through_rate) / n^(1/3)
```

样本不足的相邻区间自动合并。健康边界使用原始售罄率，不强制取整到 10%。

#### 9.5.3 健康度得分

设健康区间为 `[L, U]`：

```text
r 在 [L,U]：distance = 0
r < L：distance = L - r
r > U：distance = r - U
```

最大容忍距离分别试算 P90、P95、P99，并用下一周期经营结果和等级稳定性选择正式参数：

```text
sell_through_health_score =
100 * MAX(0, 1 - distance / selected_tolerance_distance)
```

P90/P95/P99 只用于分数缩放，不改变原始售罄率和健康区间。

#### 9.5.4 混合计量品类

```text
综合售罄健康度 =
SUM(计量类型健康度 * 该类型有效在售 SKU 天数)
/ SUM(全部计量类型有效在售 SKU 天数)
```

只合并无单位健康度，不合并原始公斤和件数。

#### 9.5.5 日间稳定性

```text
健康区间命中率 =
处于健康区间的有效 SKU 天数 / 全部有效到货 SKU 天数

order_health_score =
SQRT(综合售罄健康度 * 健康区间命中率得分)

健康区间命中率得分 = 健康区间命中率 * 100
```

### 9.6 促销健康

只使用 19:00 前促销，毛利结果使用全日。

#### 9.6.1 对照组优先级

```text
1. 同促销期间、同范围、同 SKU 的未参加活动门店：DID
2. 同门店、同 SKU 的相似非促销日：匹配
3. 同范围、同小分类、价格带和规格相近的非促销商品：匹配
```

对照需控制星期类型、季节、节假日和营业状态。没有合格对照时不判断有效或无效。

DID 的促销增量公式：

```text
ATT =
(处理组活动后 - 处理组活动前)
- (对照组活动后 - 对照组活动前)
```

正式发布前必须检查活动前趋势；前趋势不成立时不得使用 DID 结果，继续执行匹配回退。

#### 9.6.2 指标

```text
促销增量净贡献 = 实际净经营贡献 - 无促销反事实净经营贡献
促销 ROI = 促销增量净贡献 / 19 点前促销优惠金额

增量标准销售额 = 增量销售数量 * 商品非促销期正常单价
促销依赖率 = 增量标准销售额 / 19 点前全部标准销售额
```

销售、小票和会员增量只作解释，不重复计分。

#### 9.6.3 得分

```text
ROI：带符号对数 + 正向稳健标准化
促销依赖率：反向稳健标准化

promotion_health_score =
SQRT(promotion_roi_score * promotion_non_dependency_score)
```

没有促销时为 `NOT_APPLICABLE`。有促销但对照验证不通过时得分为空，`promotion_confidence = 低`，禁止填 0。

### 9.7 损耗健康

损耗金额只作展示，正式评分使用全日损耗成本率：

```text
损耗成本率 = 全日损耗成本金额 / 全日到货成本金额
```

没有到货成本时降级为：

```text
损耗成本率 = 损耗金额 / (实际销售成本 + 损耗金额)
loss_cost_rule_degraded_flag = 1
```

使用反向稳健标准化生成：

```text
loss_health_score = 100 * [1 - Phi(robust_z)]
```

损耗率小于 0 或到货成本为 0 时不执行评分，标记数据异常或缺失。

## 10. 一级维度综合评分

七个一级得分使用 CRITIC 生成 `W1—W7`：

```text
category_score =
scale_score * W1
+ assortment_width_score * W2
+ sku_efficiency_score * W3
+ profitability_score * W4
+ order_health_score * W5
+ promotion_health_score * W6
+ loss_health_score * W7

SUM(W1...W7) = 1
```

某维度为 `NOT_APPLICABLE` 时：

```text
adjusted_w_j = original_w_j / SUM(可用维度原权重)
category_score = SUM(可用维度得分 * adjusted_w_j)
```

禁止将缺失值或不适用值填 0。

## 11. 动态等级生成

### 11.1 Jenks 自然断点

对同一比较组的 `category_score` 从低到高排序，分别尝试 `K=1、2、3、4`，选择使组内平方误差最小的连续切分。

```text
K_max = MIN(4, 综合分去重值数量)
```

相同综合分不得被切分到不同组。全部门店综合分相同时只允许 `K=1`。

### 11.2 BIC 选择等级数量

```text
BIC(K) = N * ln(SSE_K / N) + K * ln(N)
```

BIC 越小越好，但候选分层还必须通过稳定性验证。

当某个候选 `SSE_K = 0` 时，不执行 `ln(0)`；在达到 0 的候选中选择 K 更小且通过稳定性验证的分层。

### 11.3 稳定性验证

```text
重复抽样次数：500
每次抽取有效门店比例：80%
同一等级数量出现比例 >= 80%
单门店等级一致率 >= 75%
最近 4 个滚动窗口中，等级数量至少 3 次一致
```

未通过时依次从 4 级降为 3 级、2 级、1 级。

### 11.4 等级命名与同分

```text
K=4：A/B/C/D
K=3：A/B/C
K=2：A/B
K=1：统一输出 B，single_level_flag = 1
```

多组时按组内综合分均值从高到低命名。综合分完全相同的门店必须属于同一等级，禁止使用 `row_number` 强行拆分。

## 12. 经营底线与等级上限

### 12.1 连续亏损

按最近 3 个完整自然月分别计算：

```text
月度净经营贡献 = 月度全链路毛利额 - 月度损耗金额
```

如果全链路毛利已扣损耗，直接使用全链路毛利。

```text
M1 < 0 AND M2 < 0 AND M3 < 0
=> continuous_loss_3m_flag = 1
=> profitability_cap = B
```

三个月累计亏损但并非每月都亏损时，只输出 `cumulative_loss_3m_flag = 1`，不触发连续亏损上限。

### 12.2 严重损耗风险线

历史样本粒度：

```text
正式范围 + 门店 + 品类 + 自然月
```

定义：

```text
x = 损耗成本率
y = 净经营贡献率
w = 到货成本金额
```

使用单调递减 Isotonic Regression：

```text
最小化 SUM_i[w_i * (y_i - g(x_i))^2]
约束 x_a < x_b 时，g(x_a) >= g(x_b)
```

严重损耗风险线为预测净经营贡献率首次由正转为非正的位置：

```text
loss_break_even_threshold = INF{x : g(x) <= 0}
```

使用滚动历史数据验证以下候选触发规则：

```text
最近 3 个月至少 1 个月超过风险线
最近 3 个月至少 2 个月超过风险线
最近 3 个月 3 个月全部超过风险线
```

根据下一月亏损识别的准确率、召回率、误报率和跨期稳定性选择 `loss_trigger_month_count`。触发后：

```text
severe_loss_flag = 1
loss_level_cap = B
```

历史曲线没有穿越 0、始终低于 0 或阈值不稳定时，不发布损耗等级上限，只保留损耗健康度和诊断标记。

### 12.3 数据与权重回退上限

```text
CRITIC 无历史参数、使用等权回退：最高 B
六个核心维度缺失 1 个：最高 B
```

最终等级取暂定等级与所有等级上限中更严格的结果：

```text
final_level = APPLY_LEVEL_CAP(provisional_level, profitability_cap,
                              loss_level_cap, data_quality_cap,
                              weight_fallback_cap)
```

## 16. 开发与业务验收

### 16.1 数据完整性

```text
正式结果唯一键重复数 = 0
大、中、小分类结果均从底层重新聚合
销售时间口径严格为 trade_time < 19:00:00

原始售罄率未被静默截断为 100%
缺失值未填 0
```

### 16.2 开发对数

```text
原始聚合指标完全一致
公式计算误差 <= 0.000001
暂定等级和最终等级 100% 一致
```

### 16.3 稳定性

```text
重复抽样 500 次
等级数量一致率 >= 80%
单门店等级一致率 >= 75%
最近 4 个滚动窗口至少 3 次选择相同等级数量
```

### 16.4 人工与后验验收
