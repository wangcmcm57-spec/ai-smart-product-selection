# 上海试点 AI 新品推荐工作台需求说明 V1

更新时间：2026-09-08

文档状态：第一版草案，待产品、研发和测试评审。

## 1. 项目背景

当前新品选品链路大致分为：

```text
发现新品方向或外部线索；
判断这个方向是否值得继续开发；
开发寻源，联系供应商，拿样和报价；
做毛利测算、基础品质判断和试吃；
进入选品决策；
准备上架、小范围试点或上市验证；
复盘是否继续扩大。
```

在真实工作中，前两步主要依赖采购经验、竞对观察、供应商推荐、毛利空间和试吃判断。这个方式可以支撑日常选品，但缺少统一的数据佐证和稳定选品逻辑，容易出现几个问题：

```text
新品机会主要靠人工发现，覆盖面和稳定性不够；
竞对、供应商、毛利、试吃和经验判断没有统一证据口径；
消费者画像、门店群差异和品类机会没有稳定进入选品判断；
一个方向为什么值得做，往往难以在事后复盘；
推荐方向进入开发寻源前，缺少结构化的判断依据。
```

AI 新品推荐 V1 放在“发现新品方向”和“开发寻源”之间，服务于新品开发前评估。

它不是替采购做最终拍板，也不是直接发起供应商开发需求，而是先把系统识别到的新品方向整理成采购可查询、可看懂、可追问、可反馈的推荐结果，帮助采购更快判断“这个新品方向值不值得继续看、有没有依据、风险在哪里、适合怎么试点”。

后续版本可以在采购确认方向后，继续打通开发寻源和供应商触达，让采购把新品开发需求直接发给供应商。V1 先聚焦把推荐方向、证据、风险和试点建议跑通。

## 2. V1 目标

V1 的目标是让华东采购在智慧中台内完成上海试点新品推荐的查询、查看、追问和反馈。

| 目标 | 业务含义 |
|---|---|
| 能查 | 采购能按运营大区、上海和商品分类查询系统已生成的新品推荐 |
| 能看懂 | 每条推荐都能看到推荐理由、用户画像、竞对价格、行业趋势、风险和试点建议 |
| 能追问 | 采购能用大白话追问当前推荐为什么值得看、风险是什么、怎么试点 |
| 能反馈 | 采购能对单条推荐点击有帮助 / 没帮助 |
| 能沉淀 | 推荐级反馈可被记录，供后续试用复盘使用 |

## 3. V1 项目全貌和运行链路

V1 不是单独做一个页面，而是把“离线算法结果”变成“采购能在线使用的新品推荐工作台”。

整体链路如下：

```text
基础数据和外部数据准备
-> 算法 01～07 产出消费者画像、品类机会、购物篮机会、价格毛利、竞对和趋势证据
-> 算法 08 统一新品候选身份，合并重复或相近候选
-> 算法 09 合成机会证据，完成风险门禁
-> 算法 10 生成推荐队列、推荐类型、展示摘要和解释内容
-> 后端 API 读取已发布推荐结果
-> Agent / Harness 抽取采购问题中的查询条件，调用固定 API
-> 大模型基于接口返回结果做大白话解释
-> 工作台展示推荐列表、单品决策档案和 AI 追问
-> 记录有帮助 / 没帮助反馈，供后续试用复盘
```

这条链路里，推荐结果由上游数据和算法预先产出。采购在页面点击查询或使用 AI 追问时，只读取已发布结果，不触发算法实时重算。

### 3.1 系统分工

| 环节 | V1 产出 | 和本需求的关系 |
|---|---|---|
| 基础数据和外部数据 | 商品、门店、销售、价格、毛利、竞对、趋势等基础事实 | 支撑算法结果，不在页面临时补数 |
| 算法 01～07 | 消费者画像、品类机会、购物篮机会、价格毛利、竞对和趋势证据 | 作为推荐证据来源 |
| 算法 08 | 标准化后的新品候选 | 解决候选是否是同一个商品方向的问题 |
| 算法 09 | 机会证据、风险门禁和通过状态 | 决定候选是否能进入推荐口径 |
| 算法 10 | 推荐队列、推荐类型、排序、展示摘要、解释内容 | 页面、API 和 Agent 的主要读取结果 |
| 后端 API | 查询列表、查询详情、提交反馈、AI 追问调用入口 | 承接页面和 Harness 调用 |
| Agent / Harness | 意图识别、参数抽取、缺参处理、接口调用和回答边界控制 | 保证 AI 只解释当前结果，不编造新推荐 |
| 工作台页面 | 筛选区、推荐列表、单品决策档案、AI 追问和反馈入口 | 采购实际使用入口 |
| 试用复盘 | 反馈结果和后续新品开发、试点上架观察 | 放在 `04_product/02_launch_feedback/` 后续维护 |

### 3.2 V1 对外输出

V1 交付给采购使用的不是算法表，而是以下产品结果：

| 输出 | 内容 |
|---|---|
| 推荐新品队列 | 当前筛选条件下可查看的新品推荐列表 |
| 推荐理由 | 每条推荐为什么值得看的一句话摘要 |
| 单品决策档案 | 用户画像、内部证据、竞对价格、行业趋势、风险和试点建议 |
| AI 大白话解释 | 围绕当前推荐结果解释原因、风险、竞对价格和试点方式 |
| 推荐反馈 | 采购对单条推荐点击有帮助 / 没帮助 |

### 3.3 离线计算和在线调用边界

开发实现时必须明确：

```text
算法 01～10 不是打包给 Agent 在线实时调用的工具链；
底层算法更接近数据开发任务，按固定链路离线或准离线跑完；
算法链路先产出推荐结果表、证据表、风险门禁表和解释表；
线上页面、后端 API 和 Agent 只读取已发布结果；
采购查询条件只用于筛选结果，不作为算法实时计算输入；
采购追问只触发解释，不触发算法 01～10 重算；
推荐结论来自算法结果表，AI 不修改推荐结论、推荐类型、排序和风险门禁。
```

因此，Agent 在线上的职责是交互、解释和辅助判断：

```text
根据采购输入识别查询意图；
抽取运营大区、城市、分类等查询条件；
通过后端 API 读取已发布推荐结果；
基于接口返回的结构化事实，用采购能理解的话解释推荐理由、风险、竞对价格和试点建议；
在缺数据或证据不足时说明缺失，不自行补充商品事实、价格、趋势或风险结论。
```

推荐结果发生变化时，应由上游数据或算法任务生成新批次并发布，线上查询、点击反馈和 AI 追问不得直接改写已发布算法结果。

## 5. 采购主流程

V1 的采购主流程如下：

```text
1. 采购进入智慧中台的 AI 新品推荐模块。
2. 页面展示查询条件，城市固定为上海。
3. 采购选择运营大区、大分类、中分类，可选择小分类。
4. 采购点击查询。
5. 系统返回当前条件下的推荐新品队列。
6. 采购点击一条推荐，查看单品决策档案。
7. 采购查看推荐理由、用户画像、竞对价格、行业趋势、风险和试点建议。
8. 采购必要时使用 AI 追问，围绕当前推荐做大白话解释。
9. 采购对单条推荐点击有帮助或没帮助。
10. 项目侧在试用复盘中分析反馈和后续新品开发推进情况。
```

## 6. 查询条件和业务规则

### 6.1 查询条件

| 查询条件 | 业务含义 | V1 规则 | 是否必选 | 默认值 |
|---|---|---|---|---|
| 运营大区 | 华东下的运营区域，例如华东 1 区、华东 2 区、华东 3 区 | 单选，支持全部 | 非必选 | 全部 |
| 城市 | 试点城市 | 固定上海，不开放非试点城市 | 必选 | 上海 |
| 大分类 | 商品一级分类 | 单选，只展示 6 个试点大分类 | 必选 | 空 |
| 中分类 | 商品二级分类 | 随大分类级联 | 必选 | 空 |
| 小分类 | 商品叶子分类或更细分类 | 随中分类级联 | 非必选 | 空 |

采购不需要选择门店群、门店等级、消费者画像、推荐标签或候选状态。门店群、门店等级等范围信息只在推荐卡片、详情或试点建议中展示。

### 6.2 分类级联

分类选择规则：

```text
先选择大分类；
再选择中分类；
小分类可选；
更换大分类时，自动清空中分类和小分类；
更换中分类时，自动清空小分类。
```

### 6.3 查询按钮

点击查询后，系统应按当前筛选条件读取已发布的推荐结果。

查询规则：

```text
大分类和中分类未选择时，不发起查询；
城市固定为上海；
小分类为空时，返回该中分类下全部可展示推荐；
查询只过滤算法 10 已发布结果，不触发实时重算；
查询不改变推荐标签、排序、解释和门禁结论。
```

### 6.4 重置按钮

点击重置后，页面回到初始状态：

```text
运营大区恢复为全部；
城市恢复为上海；
大分类、中分类、小分类清空；
推荐新品队列清空；
单品决策档案清空；
AI 追问上下文清空；
当前页面反馈选中态清空。
```

重置不删除已经写入后端的历史反馈记录。

### 6.5 导出规则

V1 页面不提供推荐列表导出按钮。

## 7. 推荐结果来源和资格

### 7.1 结果来源

页面和 AI 追问只读取算法 10 已发布的推荐结果。

业务口径：

```text
算法 09 先完成新品机会证据合成与风险门禁；
算法 10 再读取 PASS 和 CONDITIONAL_PASS 的候选；
算法 10 生成推荐主结果、推荐解释和展示摘要；
页面和 Agent 只读取最新成功发布结果；
采购查询只做筛选，不实时重算算法。
```

### 7.2 可展示推荐类型

V1 可展示的推荐类型包括：

| 推荐类型 | 采购理解 |
|---|---|
| 正式推荐 | 证据和门禁条件较完整，可以作为重点新品机会查看 |
| 季节推荐 | 适合在计划上架窗口内重点查看 |
| 局部试点推荐 | 适合先在部分范围做小范围试点 |
| 条件推荐 | 机会有价值，但需要先补齐条件或材料 |
| 探索推荐 | 证据还偏早，适合观察或研究，不作为正式新品结论 |

条件推荐必须明确展示待补条件，不得包装成正式推荐。

## 8. 推荐列表展示内容

查询成功后，页面展示推荐新品队列。

每条推荐至少需要让采购看懂：

| 展示项 | 业务说明 |
|---|---|
| 推荐新品名称 | 候选展示名，含规格时展示规格 |
| 推荐分类 | 大分类 / 中分类 / 小分类 |
| 适用范围 | 上海、运营大区、门店群、门店等级或其他适用范围摘要 |
| 推荐类型 | 正式推荐、季节推荐、局部试点推荐、条件推荐、探索推荐 |
| 推荐理由摘要 | 一句话说明为什么值得看 |
| 用户画像 | 目标消费者画像及其简要依据 |
| 建议价格 | 建议零售价或价格区间；缺失时展示价格待补 |
| 竞对价格 | 竞对商品价格或价格区间；缺失时展示暂无竞对价格 |
| 行业趋势 | 行业趋势摘要；缺失时展示暂无趋势证据 |
| 风险提示 | 无明显风险、需补材料、价格风险、法规风险等摘要 |
| 试点建议 | 是否建议试点、建议范围或待补条件 |

图片可作为卡片展示内容。只有图片匹配候选且授权状态允许展示时，才展示真实图片；无图、授权未知、未授权或图片身份不匹配时，展示占位或不展示真实图。

## 9. 单品决策档案

采购点击一条推荐后，展示该推荐的单品决策档案。

单品决策档案至少包含：

| 模块 | 业务说明 |
|---|---|
| 推荐结论 | 当前推荐类型、推荐状态和同范围优先级 |
| 为什么推荐 | 用采购能理解的话说明推荐成立的关键原因 |
| 适合谁 | 目标消费者画像、消费场景或画像贡献摘要 |
| 内部证据 | 锚点商品表现、购物篮关联、价格带或毛利可行性摘要 |
| 竞对价格 | 竞品名称、平台、规格、价格、时间和来源摘要 |
| 行业趋势 | 趋势方向、来源、时间和趋势强弱摘要 |
| 风险和门禁 | 当前货盘、历史失败、法规、毛利、图片授权等风险结论 |
| 怎么试点 | 建议试点范围、试点注意事项、待补条件 |

详情内容必须基于算法 10 和上游证据，不由前端或大模型临时编造。

## 10. AI 追问业务边界

AI 追问是辅助解释入口，不是主查询入口，也不是新品推荐生成器。

V1 支持采购围绕当前查询结果或当前选中推荐追问：

```text
为什么推荐这个；
适合什么用户；
竞对价格怎么看；
风险是什么；
为什么是条件推荐；
怎么做小范围试点；
缺了哪些条件。
```

V1 AI 追问必须遵守：

```text
只解释当前已展示推荐；
只基于接口返回的结构化事实回答；
缺数据时明确说缺失，不把缺失解释成机会低；
不实时重算算法；
不生成新的推荐结果；
不解释未展示候选为什么没被推荐；
不把条件推荐说成正式推荐；
不生成成功概率、销量预测或无来源口碑结论；
不发起供应商沟通或新品开发需求。
```

AI 回答应使用采购能理解的大白话，不堆算法编号和底层字段。

## 11. 有帮助 / 没帮助反馈

### 11.1 反馈入口

每条推荐提供两个反馈动作：

```text
有帮助
没帮助
```

反馈对象是一条推荐结果，不是整页查询结果。

### 11.2 反馈规则

| 规则 | V1 口径 |
|---|---|
| 是否必须反馈 | 非必须 |
| 反馈粒度 | 用户 + 当前查询条件 + 推荐结果 |
| 是否允许修改 | 同一用户对同一推荐可修改反馈，以最后一次有效反馈为准 |
| 是否影响排序 | 不影响当前推荐排序 |
| 是否影响推荐结论 | 不改变推荐类型、推荐理由、门禁结论和试点建议 |
| 是否进入算法实时计算 | 不进入实时计算，不触发算法重算 |
| 主要用途 | 评估采购是否认为推荐有参考价值，并支持试用复盘 |

### 11.3 反馈状态

点击有帮助后：

```text
有帮助进入选中态；
没帮助取消选中；
页面提示反馈已记录。
```

点击没帮助后：

```text
没帮助进入选中态；
有帮助取消选中；
页面提示反馈已记录。
```

反馈失败时：

```text
提示反馈提交失败；
允许用户重试；
刷新或重新查询后以后端记录为准。
```

## 12. 空态、异常和缺数据展示

### 12.1 初始状态

用户刚进入模块时：

```text
城市默认为上海；
运营大区默认为全部；
大分类、中分类、小分类为空；
不展示推荐新品队列；
不展示单品决策档案；
AI 追问提示先查询或先选择推荐。
```

### 12.2 必填条件缺失

点击查询时，如果大分类或中分类未选择：

```text
不发起查询；
提示补齐大分类和中分类；
保留当前已选条件。
```

### 12.3 无推荐结果

如果当前条件下没有可展示推荐：

```text
展示当前条件下暂无新品推荐结果；
不生成假推荐；
不从其他城市、其他分类或其他门店群借结果。
```

### 12.4 推荐结果未生成

如果当前条件下推荐结果尚未生成：

```text
展示当前条件下推荐结果暂未生成；
不展示历史不一致结果；
不让 AI 编造推荐。
```

### 12.5 证据缺失

如果某条推荐缺少价格、竞对价格、行业趋势或图片：

```text
价格缺失展示价格待补；
竞对价格缺失展示暂无竞对价格；
行业趋势缺失展示暂无趋势证据；
图片不可展示时使用占位或不展示真实图；
AI 解释中说明对应信息缺失，不做推断。
```

### 12.6 接口失败

如果查询、详情、反馈或 AI 追问失败：

```text
提示操作失败；
允许用户重试；
保留已选筛选条件；
不因失败清空上一轮成功查询结果，除非用户点击重置。
```

## 13. 后端 API 需求

后端 API 是工作台和 Agent / Harness 读取推荐结果的统一入口。前端和 Agent 不直接读取 Doris 明细表，也不直接调用算法任务。

V1 至少需要支持以下能力：

| API 能力 | 调用方 | 业务用途 | 关键要求 |
|---|---|---|---|
| 查询筛选项 | 前端 | 获取运营大区、上海、6 个大分类及其下属中分类、小分类 | 城市固定上海；大分类只返回 V1 试点 6 类 |
| 查询推荐列表 | 前端、Harness | 按运营大区、城市、大分类、中分类、小分类读取推荐新品队列 | 只读算法 10 已发布结果；不触发实时重算；返回用户当前反馈状态 |
| 查询推荐详情 | 前端、Harness | 根据单条推荐查看单品决策档案 | 返回推荐理由、用户画像、内部证据、竞对价格、行业趋势、风险和试点建议 |
| 提交推荐反馈 | 前端 | 记录采购对单条推荐的有帮助 / 没帮助反馈 | 同一用户对同一推荐可修改，以最后一次有效反馈为准 |
| AI 追问 | 前端、Harness | 围绕当前查询结果或当前推荐进行解释 | 只使用当前结果上下文；不生成新推荐；不重算算法 |
| 记录交互事件 | 前端、后端 | 记录查询、详情打开、反馈点击和 AI 追问事件 | 用于问题排查和试用复盘，不改变推荐结论 |

API 返回给前端或 Agent 的业务信息应以算法 10 已生成的推荐主结果、展示摘要和解释内容为准。

接口需要携带能唯一定位推荐结果和批次的标识，供反馈记录、问题排查和追溯使用；这些标识不要求在采购主界面直接展示。

### 13.1 推荐列表 API

推荐列表 API 需要满足：

```text
入参支持运营大区、城市、大分类、中分类、小分类；
城市固定为上海；
大分类和中分类为必填；
小分类为空时返回该中分类下全部可展示推荐；
返回结果按算法 10 已发布排序展示；
返回每条推荐的当前用户反馈状态；
接口失败时不要求前端清空上一轮成功结果。
```

### 13.2 推荐详情 API

推荐详情 API 需要满足：

```text
入参通过推荐结果标识定位单条推荐；
详情内容必须来自已发布推荐结果、展示摘要、解释内容和证据字段；
缺少竞对价格、行业趋势、图片或价格时，返回明确缺失状态或缺失文案；
不得由后端临时生成新的推荐结论。
```

### 13.3 反馈 API

反馈 API 需要满足：

```text
反馈值只允许有帮助或没帮助；
反馈必须绑定用户、当前查询条件和推荐结果；
同一用户对同一推荐可修改反馈；
反馈成功后前端回显最后一次有效状态；
反馈不改变推荐排序、推荐类型、推荐理由、门禁结论和试点建议。
```

### 13.4 AI 追问 API

AI 追问 API 需要满足：

```text
支持围绕当前查询结果追问；
支持围绕当前选中推荐追问；
必须接收当前查询条件或推荐结果标识；
回答只基于后端返回的结构化事实和解释内容；
缺少上下文时，返回需要先查询或先选择推荐；
不把大模型回答写回算法结果表。
```

## 14. Agent / Harness 需求

Harness 是 Agent 的控制层，负责把采购的自然语言输入转成可控的系统动作。它不是算法计算层。

V1 Harness 需要支持：

| 能力 | 说明 |
|---|---|
| 意图识别 | 判断采购是在查询推荐、追问推荐理由、追问风险、追问竞对价格、追问试点建议，还是补充筛选条件 |
| 参数抽取 | 从采购输入中抽取运营大区、城市、大分类、中分类、小分类 |
| 缺参处理 | 大分类或中分类缺失时，提示采购补充，不调用推荐列表 API |
| 工具路由 | 按意图调用推荐列表、推荐详情、反馈或 AI 追问 API |
| 上下文管理 | 保存当前查询条件、当前推荐列表和当前选中推荐 |
| 回答生成 | 基于 API 返回内容生成大白话解释 |
| 护栏控制 | 防止生成新推荐、实时重算、编造价格趋势或改写推荐结论 |

V1 支持的典型问题：

```text
上海华东 1 区冷藏加工有什么新品推荐？
这个为什么推荐？
这个适合什么用户？
竞对价格怎么看？
风险是什么？
为什么是条件推荐？
怎么做小范围试点？
还缺哪些条件？
```

当采购问题超出当前能力时，Harness 应给出边界说明，而不是让大模型自由发挥。

边界处理规则：

```text
询问非上海城市：提示当前只支持上海试点；
询问未选择大分类或中分类的推荐：提示补齐分类条件；
询问未展示候选为什么没推荐：提示当前只解释已展示推荐；
要求新增推荐或实时算一个候选：提示当前只读取已发布结果；
要求联系供应商或发起开发需求：提示当前版本只提供推荐解释和试点建议；
接口返回缺数据：说明对应信息暂缺，不推断原因。
```

## 15. 反馈和埋点需求

V1 需要记录采购在工作台中的关键行为，用于反馈回显、问题排查和试用复盘。

前端至少需要记录以下事件：

| 事件 | 触发时机 | 关键记录内容 | 用途 |
|---|---|---|---|
| 查询推荐 | 点击查询并发起列表请求 | 用户、时间、运营大区、城市、大分类、中分类、小分类 | 了解采购实际查询范围，排查无结果问题 |
| 打开推荐详情 | 点击单条推荐并打开单品决策档案 | 用户、时间、查询条件、推荐结果标识 | 判断采购是否进一步查看推荐证据 |
| 点击有帮助 | 对单条推荐点击有帮助 | 用户、时间、查询条件、推荐结果标识、反馈值 | 记录采购正向反馈 |
| 点击没帮助 | 对单条推荐点击没帮助 | 用户、时间、查询条件、推荐结果标识、反馈值 | 记录采购负向反馈 |
| 修改反馈 | 同一用户修改已有反馈 | 用户、时间、查询条件、推荐结果标识、修改前后反馈值 | 回显最后一次有效反馈，支持复盘 |
| 发起 AI 追问 | 提交追问问题 | 用户、时间、查询条件、推荐结果标识、问题类型 | 了解 AI 解释使用情况，排查回答问题 |
| AI 追问失败 | AI 追问接口失败或缺少上下文 | 用户、时间、失败原因、当前上下文状态 | 排查交互失败和上下文缺失 |

埋点和反馈记录不得改变算法推荐结果。

反馈记录和交互事件需要能关联到：

```text
用户；
查询条件；
推荐结果；
推荐批次；
反馈值或事件类型；
发生时间。
```

## 16. 业务验收标准

### 16.1 范围验收

| 验收项 | 通过标准 |
|---|---|
| 页面入口 | 智慧中台中存在 AI 新品推荐模块入口 |
| 城市范围 | V1 只开放上海试点数据 |
| 分类范围 | 大分类只开放蔬菜、水果、肉禽蛋、冷藏加工、预制菜、水产 |
| 猪肉类排除 | 筛选项、推荐列表、详情和 AI 追问中不出现猪肉类新品推荐 |
| 门店群口径 | 采购不按门店群筛选，门店群只作为适用范围或试点建议展示 |
| 导出范围 | V1 不出现推荐列表导出入口 |

### 16.2 查询验收

| 验收项 | 通过标准 |
|---|---|
| 必选条件 | 未选择大分类或中分类时不能发起查询 |
| 分类级联 | 更换大分类清空中分类和小分类；更换中分类清空小分类 |
| 查询结果 | 完整条件下能返回推荐列表、空态或结果未生成状态 |
| 重置 | 重置后筛选、列表、详情、AI 上下文和当前页面反馈选中态回到初始状态 |
| 不实时计算 | 查询只读取已发布推荐结果，不触发算法重算 |

### 16.3 推荐展示验收

| 验收项 | 通过标准 |
|---|---|
| 推荐资格 | 只展示算法 10 可展示推荐结果 |
| 推荐类型 | 条件推荐不能展示成正式推荐 |
| 推荐内容 | 推荐理由、用户画像、竞对价格、行业趋势、风险和试点建议可查看 |
| 缺失表达 | 价格、竞对、趋势、图片缺失时有明确展示，不编造内容 |

### 16.4 AI 追问验收

| 验收项 | 通过标准 |
|---|---|
| 当前上下文 | AI 只围绕当前查询结果或当前选中推荐回答 |
| 大白话解释 | 回答能让采购理解推荐理由、风险、竞对价格和试点建议 |
| 不编造 | 缺数据时说明缺失，不新增商品事实、价格、趋势、风险或动作 |
| 不越界 | 不生成新推荐、不实时重算、不解释未展示候选为什么没被推荐 |

### 16.5 反馈验收

| 验收项 | 通过标准 |
|---|---|
| 反馈文案 | 按有帮助 / 没帮助展示 |
| 反馈对象 | 反馈绑定到单条推荐 |
| 反馈修改 | 同一用户可修改反馈，回显最后一次有效状态 |
| 反馈影响 | 反馈不改变当前推荐排序、标签、理由和门禁结论 |

### 16.6 API 和 Harness 验收

| 验收项 | 通过标准 |
|---|---|
| API 读取边界 | 前端和 Agent 通过后端 API 读取已发布结果，不直接读取明细表 |
| 算法计算边界 | 查询、反馈和 AI 追问都不触发算法 01～10 实时重算 |
| Harness 参数处理 | 大分类或中分类缺失时能提示补齐，不调用推荐列表 API |
| Harness 回答边界 | AI 只解释当前查询结果或当前选中推荐，不生成新推荐 |
| 埋点记录 | 查询、详情打开、有帮助、没帮助、修改反馈和 AI 追问事件可被记录 |
