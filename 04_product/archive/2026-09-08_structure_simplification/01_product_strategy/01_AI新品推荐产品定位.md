# AI 新品推荐产品定位

更新时间：2026-09-08

文档状态：第一版草案，待产品和业务复核。

## 1. 文档定位

本文用于说明 AI 智能选品项目的产品背景、长期目标、V1 产品定位和产品边界。

本文只写产品策略，不写算法公式、数据表结构、接口字段和前端视觉设计。

## 2. 一句话定位

AI 新品推荐不是一个“给答案的聊天机器人”，而是一个帮助采购把新品机会从发现、判断、开发寻源到试点验证逐步打通的新品推荐决策台。

V1 先聚焦“新品机会发现和采购判断”，核心输出是：

```text
推荐方向 + 证据 + 风险 + 试点建议
```

长期目标是形成：

```text
AI 发现新品机会
-> 采购判断和确认推进
-> 生成新品开发需求
-> 直达供应商发起开发
-> 供应商反馈规格、报价、样品和交付能力
-> 内部评估和小范围试点
-> 上市表现复盘
-> 反哺后续选品和新品开发
```

## 3. 项目背景

当前新品选品不是缺少流程，而是缺少统一的数据佐证和稳定的选品判断逻辑。

在真实工作中，采购通常会先看竞对在卖什么、供应商能提供什么，再结合毛利空间、基础品质和经验判断，决定一个新品方向是否值得继续推进。这种方式能支撑日常选品，但更多依赖个人经验、供应商供给和市场观察，缺少统一沉淀的证据链。

这会带来几个问题：

```text
新品机会主要靠人工发现，覆盖面和稳定性不够；
竞对、供应商、毛利、试吃和经验判断没有统一证据口径；
一个方向为什么值得做，往往难以在事后复盘；
消费者画像、门店群差异和品类机会没有稳定进入选品判断；
“竞对在卖、供应商能做、毛利能算、不难吃”不一定等于适合上海门店群；
推荐方向进入开发寻源前，缺少结构化的判断依据和后续沉淀。
```

因此，本项目不应只被理解为“提供一份推荐列表”。它的长期价值，是把新品选品从“竞对和供应商驱动 + 采购经验判断”，逐步升级为“数据证据 + 采购经验 + 开发落地反馈”共同支撑的决策流程。

## 4. 为什么 V1 先做推荐决策台

虽然长期目标包括开发寻源和供应商协同，但 V1 需要先解决最前端的判断问题：

```text
哪些新品方向值得采购先看；
为什么值得看；
适合哪些消费者和门店；
竞对价格和行业趋势支持不支持；
有什么风险；
建议怎么小范围试点。
```

如果没有稳定的推荐方向、证据和风险解释，后续即使接入供应商，也会变成“把不清楚的需求更快发出去”。所以 V1 先把推荐结果解释清楚，让采购可以更快判断是否值得继续推进。

## 5. V1 产品形态

V1 产品形态是“AI 新品推荐决策台 / 新品雷达型工作台”，接入现有智慧中台，作为单独模块给华东采购使用。

V1 页面不以聊天为主入口，而是以结构化工作台为主：

```text
筛选区；
推荐新品队列；
单品决策档案；
AI 大白话追问；
单条反馈。
```

采购可以先按运营大区、城市、大分类、中分类、小分类查询，再查看推荐新品列表和单品详情。AI 追问区只负责解释当前查询结果或当前选中的推荐，不生成新的推荐结果。

## 6. V1 试点范围

| 项目 | V1 口径 |
|---|---|
| 试点城市 | 上海 |
| 目标用户 | 华东采购 |
| 业务场景 | 新品推荐 |
| 门店范围 | 覆盖上海全部门店群 |
| 商品范围 | 蔬菜、水果、肉禽蛋、冷藏加工、预制菜、水产 |
| 不进入 V1 新品范围 | 猪肉类 |
| 计划试用时间 | 2026 年 10 月中旬给采购试用 |

猪肉类不进入 V1 新品推荐范围。基础交易、商品、会员、门店等底层数据不因产品范围被物理裁剪；算法卡和数据合同中对应范围调整在算法侧文档另行处理。

## 7. 产品价值

### 7.1 对采购的价值

```text
减少从零找新品方向的时间；
用统一格式看到推荐理由、画像、竞对、趋势、风险和试点建议；
把经验判断变成可追溯的证据判断；
降低和业务、供应商沟通前的信息整理成本；
为后续生成新品开发需求打基础。
```

### 7.2 对业务管理的价值

```text
沉淀哪些推荐被采购认为有参考价值；
后续复盘哪些推荐推动了新品开发和试点上架；
看清不同品类、门店群、消费者画像下的新品机会；
用上市后的表现反哺下一轮选品和开发策略。
```

### 7.3 对长期供应商协同的价值

V2 以后，系统可以把采购认可并确认推进的推荐方向转成结构化新品开发需求，并支持采购向供应商发起开发需求。

供应商可围绕需求反馈：

```text
可开发商品；
规格和包装；
报价；
样品；
产能；
交付周期；
风险和限制条件。
```

这会把“AI 推荐方向”推进为“真实新品开发动作”，也让供应商响应、内部评估和上市表现可以回流到系统中。

## 8. 产品边界

V1 做：

```text
展示已生成的新品推荐结果；
解释推荐理由、用户画像、竞对价格、行业趋势、风险和试点建议；
支持采购按上海试点范围查询；
支持采购对单条推荐反馈有帮助 / 没帮助；
支持 AI 围绕当前推荐做大白话解释。
```

V1 不做：

```text
不替代采购做最终决策；
不替代评委委员会评审；
不直接向供应商发起新品开发需求；
不做供应商报价和样品协同；
不承诺新品上市成功率；
不在前端实时重算算法；
不展示未进入推荐结果的候选为什么未推荐。
```

## 9. 成功指标口径

V1 的成功要分两层看：第一层是采购在页面内是否觉得推荐有参考价值，第二层是试用后这些推荐是否真的推动新品开发或试点上架。

V1 页面内直接记录的是“有帮助 / 没帮助”，不新增“采纳 / 加入开发池”动作。

| 指标层级 | 指标 | 含义 |
|---|---|---|
| V1 页面指标 | 有帮助率 | 采购认为推荐解释有参考价值的比例 |
| V1 页面指标 | 没帮助率 | 采购认为推荐暂时没有参考价值的比例 |
| V1 页面指标 | 详情查看率 | 推荐列表中被打开详情的比例 |
| V1 页面指标 | AI 追问使用率 | 采购使用 AI 解释能力的比例 |
| 试用复盘指标 | AI 推荐转新品开发数 / 转新品开发率 | 推荐结果后续进入新品开发或开发讨论的数量和比例 |
| 试用复盘指标 | AI 推荐转试点上架数 / 转试点上架率 | 推荐结果后续进入小范围试点或上架验证的数量和比例 |
| 后续观察指标 | 新品上市后表现 | 动销、毛利、损耗、复购、门店反馈和是否扩大范围 |

V1 阶段先用有帮助率判断推荐是否被采购认可；试用复盘时再看这些推荐是否推动了新品开发和试点上架。新品上市后的表现应该进入长期复盘，但不作为 V1 选品阶段唯一成败判断。
