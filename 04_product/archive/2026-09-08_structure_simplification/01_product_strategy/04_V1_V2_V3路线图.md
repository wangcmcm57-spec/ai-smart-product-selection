# V1 V2 V3 路线图

更新时间：2026-09-08

文档状态：第一版草案，待产品、业务和研发复核。

## 1. 文档定位

本文用于说明 AI 新品推荐工作台从上海试点 V1 到新品开发、供应商协同、上市验证闭环的阶段规划。

路线图只说明产品演进方向，不等于当前版本承诺。每一阶段进入开发前，仍需要独立 PRD、API 需求、Harness 需求、埋点方案和验收清单。

## 2. 路线图原则

```text
先让采购看懂推荐，再判断是否值得推进开发；
先把被认可的推荐沉淀为结构化需求，再打通供应商协同；
先验证上海试点，再扩大城市和品类；
先记录业务动作，再评价上市表现；
AI 负责辅助判断和提高流转效率，不替代采购、供应商和评委委员会决策。
```

## 3. 阶段总览

| 阶段 | 产品主题 | 核心目标 | 目标时间 |
|---|---|---|---|
| V1 | AI 新品推荐决策台 | 让华东采购能查、看懂、追问和反馈新品推荐 | 2026 年 10 月中旬采购试用 |
| V2 | 推荐推进与新品开发需求 | 将采购认可的推荐转成结构化新品开发需求 | V1 试用复盘后规划 |
| V3 | 供应商协同 | 支持采购向供应商发起新品开发需求，并收集供应商响应 | V2 跑通后规划 |
| V4 | 上市验证和复盘闭环 | 跟踪试点上架和上市表现，反哺推荐和开发策略 | V3 跑通后规划 |

## 4. V1：AI 新品推荐决策台

### 4.1 V1 目标

V1 目标是让华东采购在智慧中台中完成新品推荐查询和判断。

V1 要做到：

```text
能按上海试点范围查询新品推荐；
能看到推荐方向、证据、风险和试点建议；
能用 AI 大白话追问当前推荐；
能对单条推荐反馈有帮助 / 没帮助；
能为后续是否推进新品开发沉淀线索。
```

### 4.2 V1 核心能力

| 能力 | 说明 |
|---|---|
| 筛选查询 | 支持运营大区、上海、6 个大分类、中分类、小分类 |
| 推荐新品队列 | 展示当前条件下的推荐新品 |
| 单品决策档案 | 展示推荐理由、用户画像、竞对价格、行业趋势、风险和试点建议 |
| AI 追问 | 只解释当前查询结果或当前选中推荐 |
| 单条反馈 | 支持有帮助 / 没帮助 |
| 埋点和反馈 | 记录查询、曝光、详情、AI 追问和反馈行为 |

### 4.3 V1 不做

```text
不直接生成新品开发需求；
不向供应商发起需求；
不收集供应商报价和样品；
不接新品审批流；
不做上市后复盘看板；
不覆盖非上海城市和猪肉类新品推荐。
```

## 5. V2：推荐推进与新品开发需求

### 5.1 V2 目标

V2 目标是把“采购觉得值得看”推进到“可以进入新品开发”的业务动作。

建议新增能力：

```text
确认推进推荐；
加入新品开发池；
生成结构化新品开发需求；
支持采购补充需求；
沉淀推进原因、目标消费者、目标门店群、建议价格、风险和试点建议；
形成新品开发需求列表。
```

### 5.2 V2 关键产出

| 产出 | 说明 |
|---|---|
| 新品开发需求 | 由推荐结果转成结构化需求 |
| 推进记录 | 记录采购是否推进、推进时间、推进人和原因 |
| 开发状态 | 记录待确认、已进入开发、已取消、已提报等状态 |
| 需求补充 | 支持采购补充规格、价格、包装、目标供应商等信息 |

### 5.3 V2 指标

```text
推荐推进率；
AI 推荐转新品开发数；
AI 推荐转新品开发率；
需求补充完成率；
从推荐到进入开发的耗时。
```

## 6. V3：供应商协同

### 6.1 V3 目标

V3 目标是把结构化新品开发需求直达供应商，让供应商围绕需求反馈可开发方案。

建议新增能力：

```text
采购选择一个或多个供应商；
向供应商发起新品开发需求；
供应商反馈可开发商品、规格、包装、报价、样品、产能和交付周期；
采购查看供应商响应对比；
供应商响应进入内部评估材料。
```

### 6.2 V3 关键产出

| 产出 | 说明 |
|---|---|
| 供应商需求单 | 采购向供应商发出的新品开发需求 |
| 供应商响应 | 供应商提交的规格、报价、样品和产能信息 |
| 响应对比 | 不同供应商方案的结构化对比 |
| 评估材料 | 可进入内部盲测、供应商评估和成本核算 |

### 6.3 V3 指标

```text
供应商响应率；
供应商平均响应时长；
有效响应数；
从推荐推进到供应商响应的耗时；
供应商方案进入内部评估的比例。
```

## 7. V4：上市验证和复盘闭环

### 7.1 V4 目标

V4 目标是把试点上架和上市表现回流到系统中，判断 AI 推荐是否真的提升新品开发质量。

建议新增能力：

```text
追踪推荐结果是否进入小范围试点；
追踪新品上市后的动销、毛利、损耗、复购和门店反馈；
记录试点是否扩大范围；
支持复盘推荐证据与真实表现是否一致；
反哺后续推荐规则、风险门禁和新品开发策略。
```

### 7.2 V4 指标

| 指标 | 说明 |
|---|---|
| 试点上架数 / 上架率 | 推荐结果进入试点或上架验证的数量和比例 |
| 动销表现 | 新品上市后的销售和动销情况 |
| 毛利表现 | 是否达到目标毛利或底线毛利 |
| 损耗表现 | 是否出现高损耗风险 |
| 复购表现 | 是否形成稳定复购 |
| 门店反馈 | 门店对陈列、销售和顾客反馈的评价 |
| 扩大范围比例 | 小范围试点后是否扩大销售范围 |

上市后表现要纳入长期评估，但不能直接作为 V1 推荐决策台的唯一成败判断。

## 9. 指标分层

| 指标层级 | 指标 | V1 是否建议纳入 |
|---|---|---|
| 页面直接指标 | 有帮助率 / 没帮助率 | 是，V1 直接埋点 |
| 页面直接指标 | 详情查看率 | 是，V1 直接埋点 |
| 页面直接指标 | AI 追问使用率 | 是，V1 直接埋点 |
| 试用复盘指标 | AI 推荐转新品开发数 / 转新品开发率 | 是，但不要求 V1 页面新增采纳动作 |
| 试用复盘指标 | AI 推荐转试点上架数 / 转试点上架率 | 是，但可先人工复盘 |
| 后续观察指标 | 动销、毛利、损耗、复购、门店反馈 | V4 重点建设 |

V1 只通过“有帮助 / 没帮助”记录采购对推荐的即时反馈。推荐是否进入新品开发、是否试点上架，在试用复盘中追踪，不要求 V1 页面新增“采纳 / 加入开发池”动作。
