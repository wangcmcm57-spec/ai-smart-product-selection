# 算法02_门店品类等级_审阅清单

更新日期：2026-09-21

## 1. 审阅结论

算法 02 已按“系统自动生成候选 → 自动质量检查 → 自动选参 → 自动发布 → 自动计算 → 数据库查询”的方式闭合。业务不需要在页面上手工点击批准，业务确认的作用是查看结果、发现异常或提出重新计算要求，不是正式运行前置。

## 2. 只保留开发交付验收红线

| 编号 | 验收项 | 已冻结口径 | 失败处理 |
|---|---|---|---|
| D1 | 范围快照和版本 | 首次运行生成 `dim_algorithm_scope_snapshot`；同版本重跑复用原 `scope_version`；映射语义变化才生成新版本 | 阻断受影响范围，不跨区域回退 |
| D2 | CITY / CITY_CLUSTER | 一个城市为 `CITY`，两个及以上城市为 `CITY_CLUSTER`；`scope_id` 始终为 `algorithm_region_code` | 快照类型不一致时阻断范围发布 |
| D3 | 会员规则版本 | 算法 01、02 共用 `dim_member_filter_rule_version`；V1/V2 只能新增不能覆盖；算法 02 不读取 `dim_customer_profile` | 规则摘要不一致时阻断会员指标任务 |
| D4 | 自动参数选择 | 候选、质量门、排序、并列决胜、唯一 `AUTO_PUBLISHED` 行、发布审计都落库 | 无合格候选按文档降级，不等待业务点击 |
| D5 | 当前版本读取 | 下游读取 `mart_store_category_level_run_release` 的唯一 `AUTO_PUBLISHED` 指针，再关联模型版本和范围版本 | 禁止按 MAX 版本或最新时间猜测 |
| D6 | 0 销售可售日 | `is_open=1`、品类至少一个 SKU 可售且数据完整的日期进入营业日 | 只能按明确降级标志切换有效销售日 |
| D7 | 进货和计量类型 | 计件使用 `receipt_qty`，称重使用 `receipt_weight_kg`，两者不相加 | 计量类型未知的售罄结果置空并记状态 |
| D8 | 多仓多验收商品 | 先按合同唯一键验重，再汇总验收商品金额到日+门店+销售 SKU；单位成本不得相加 | 重复直接阻断基础表交付 |
| D9 | 毛利和损耗口径 | 当前 `gross_profit_includes_store_loss_flag=0`；净经营贡献 = 全链路毛利额 - 门店损耗金额 | 口径变化必须新模型版本 |
| D10 | 促销代理口径 | `hour_discount_amt` 不按商品行直接求和；时段折扣优先用毛利损耗表汇总字段 | 口径不满足时促销健康降级 |

## 3. 业务查看清单（不阻断运行）

业务连接数据库后可查看：

```text
1. 候选参数表：所有候选区间、风险线、评价指标和状态。
2. 自动发布审计表：系统为什么选中、为什么淘汰、何时发布。
3. 范围快照表：本批次城市、区域编码、CITY/CITY_CLUSTER 和 scope_version。
4. 运行发布指针：当前正式模型版本和重跑记录。
5. mart_store_category_level：门店品类等级、七维得分、风险、置信度和降级原因。
```

业务发现结果不符合认知时，可提出“重新计算”或“规则版本升级”要求；开发按新 `run_id` 或新模型版本重跑并保留旧结果，不能直接覆盖历史版本或在线手工改等级。

## 4. 已明确、不再重复确认

```text
正式结果主键和字段合同以开发版算法卡为准。
城市映射历史记录不得物理删除。
同一 scope_version 的历史重跑不得读取最新 is_active 映射。
同一数据周期的 MEMBER_FILTER_V1 和 MEMBER_FILTER_V2 结果可以并存。
没有 AUTO_PUBLISHED 售罄参数时 order_health_score 为空并重算权重。
没有 AUTO_PUBLISHED 损耗参数时 severe_loss_flag 为空且损耗等级上限不生效。
缺失、不适用和异常不得静默填 0。
```
