# 算法02_门店品类等级_审阅清单

更新日期：2026-09-20

## 1. 审阅结论

算法 02 的业务主链路已经承接，公共字段、营业日、金额聚合、公式分母和等级上限合并规则已经完成开发无歧义修复。

当前可以进入数据开发准备和候选参数试跑，但在“订购健康参数”和“严重损耗触发月数”正式批准前，不能宣称整张算法卡已经具备全部七维正式评分与全部等级上限。开发不得自行选择默认参数。

## 2. 需要用户和业务拍板的红线

| 编号 | 拍板项 | 已有候选输出 | 拍板后影响 |
|---|---|---|---|
| R1 | 订购健康的正式 `[L,U]` 和容忍距离 | 每个连续候选区间的样本、单位到货净贡献、损耗、边际净贡献、下一月经营结果，以及 P90/P95/P99 下的等级稳定性 | 写入已批准售罄参数表后，`order_health_score` 才进入正式七维评分 |
| R2 | 严重损耗最近 3 个月需超线几个月 | 1个月、2个月、3个月三套候选的 precision、recall、false positive rate、跨期稳定性 | 写入已批准损耗参数表后，`severe_loss_flag` 和损耗等级上限才正式生效 |
| R3 | 相似经营日季节窗口 `season_match_window_days` | 试跑时比较候选窗口对配对数量、边际净贡献稳定性和下一月验证结果的影响 | 写入运行参数表并形成新模型版本；未批准前不生成正式订购健康候选 |

## 3. 数据与财务交付验收

以下不是让用户重新定义算法，而是开发交付时必须验证：

| 编号 | 验收项 | 确定口径 |
|---|---|---|
| D1 | 全链路毛利是否已含门店损耗 | 当前模型参数配置为 0，即净经营贡献 = 全链路毛利额 - 门店损耗；如正式字段未来改变，先发布新参数版本 |
| D2 | 0 销售可售日是否覆盖 | `dim_store.is_open = 1` 且品类至少一个 SKU `is_saleable = 1` 的日期进入营业日；不能只保留有销售日 |
| D3 | 进货数量与重量 | 计件使用 `receipt_qty`，称重使用 `receipt_weight_kg`，公斤和件数不得合并 |
| D4 | 多仓、多验收商品到店金额 | 先按数据合同主键验重；仓编码只作追溯，不得造成同一合同唯一键重复；再把各验收商品唯一记录的 `outbound_arrival_amt_tax_included` 汇总到日+门店+销售 SKU |
| D5 | 节假日与异常日期 | 日期日历可用时参与相似经营日匹配；缺失时按星期类型和月份近似，并记录降级 |
| D6 | 优惠商品毛利率 | 优先日+门店+销售 SKU；不能更细时使用该粒度近似并标记降级 |

## 4. 已闭合、不再反复确认

```text
毛利损耗表粒度：营业日期 + 门店 + 销售 SKU。
门店商品日价格表粒度：日期 + 门店 + 销售 SKU + 验收 SKU。
有效营业日保留营业、品类可售但 0 销售的日期。
门店毛利率分母使用 mart_sku_margin_loss.sales_amt。
损耗成本率分母使用出库到店金额含税，不使用单位成本求和。
净经营贡献率 = 净经营贡献额 / 出库到店金额含税。
多个等级上限同时触发时取最严格结果。
Doris hour_discount_amt 不得按商品行直接求和。
无已批准动态参数时相关得分或等级上限不生效，开发不得猜测。
相似经营日窗口没有 APPROVED 运行参数时，不生成边际到货吸收率和边际净贡献。
```
