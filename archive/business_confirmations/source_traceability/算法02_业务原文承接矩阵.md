## 3. 关键 V1 适配和版本闭环

| 业务原文 / 历史问法 | V1 正式落地 | 开发必须验证 |
|---|---|---|
| CITY / CITY_CLUSTER | `dim_store.city_name -> dim_city_algorithm_region.city -> algorithm_region_code`；一个城市为 `CITY`，多个城市为 `CITY_CLUSTER`；`scope_id = algorithm_region_code` | 同一 `scope_version + scope_id` 城市集合与 `scope_type` 一致 |
| 区域配置变化后重跑 | 首次运行锁定 `dim_algorithm_scope_snapshot`；同版本重跑复用旧 `scope_version`；变更才生成新版本 | 09.05/09.06/09.10 反例通过 |
| 会员过滤规则 | `dim_member_filter_rule_version` 注册 `MEMBER_FILTER_V1/V2`，实现摘要不可变；算法 02 不读 `dim_customer_profile` | 同周期 V1/V2 结果共存，模型版本不同 |
| 订购健康候选参数 | 生成所有连续分箱和 P90/P95/P99；质量门后按验证期贡献、损耗、等级稳定性、阈值稳定性、样本数排序，自动发布唯一行 | 只有一条 `AUTO_PUBLISHED`；无合格候选时维度置空并降级 |
| 严重损耗触发月数 | 生成 1/2/3 月候选；按跨期稳定性、precision、recall、误报率、样本数排序，自动发布唯一行 | 无合格候选时不应用等级上限，状态为 `MISSING_AUTO_PARAM/UNSTABLE` |
| 相似经营日窗口 | 从 30/60/90 天候选自动选择，写入运行参数；无合格窗口记 `UNSTABLE`，不生成边际配对指标 | 不出现人工等待或未知窗口 |
| 业务查看结果 | 查询正式表、候选表、自动发布审计和 run_release 指针 | 查询不触发实时重算；下游不按 MAX 版本猜测 |
