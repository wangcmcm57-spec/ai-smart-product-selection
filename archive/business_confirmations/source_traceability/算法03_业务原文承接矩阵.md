## 1. 复核范围与职责冻结

| 项目 | 冻结结论 |
|---|---|
| 算法编号 | 算法 03 |
| 算法名称 | 门店群消费者画像贡献算法 |
| 本算法做什么 | 在同一城市算法区域、品类和门店群内，按算法 01 的 `final_profile` 计算会员覆盖、会员销售贡献和主力消费者类型 |
| 本算法不做什么 | 不重新生成会员画像；不重新计算门店品类等级；不推荐候选商品；不在前端查询时实时重算 |
| 上游读取谁 | `dim_customer_profile`、`mart_store_category_level`、`data_agent.dws_member_order_item_detail_df_all_new`、`dim_sku`、`dim_store`、`dim_city_algorithm_region` |
| 下游交给谁 | 算法 04 及后续新品机会分析读取两张正式结果表 |
| 正式运行顺序 | 算法 01、算法 02 发布正式结果后，算法 03 月度离线计算；算法 03 不改变 01/02 结果 |

## 3. 业务原文必需输入的可支撑性

| 原文必需输入 | 当前支撑情况 | V1 处理 | 缺失时仍可输出什么 | 缺失会阻断什么 |
|---|---|---|---|---|
| 算法 01 `final_profile` | 已有正式表合同 | 只读取锁定版本，检查 `customer_id` 唯一 | 无法形成画像贡献明细 | 受影响范围全部正式结果 |
| 算法 02 `final_level` / `result_status` | 已有正式表合同 | `SUCCESS` 组建门店群，`NOT_CALCULABLE` 统计未评级 | 有完整等级行时可计算对应门店群 | 无正式等级门店或版本混用时阻断 |
| 交易有效条件 | Doris 新表和已确认过滤字段 | order 状态、退货、金额、数量、主键、会员过滤 | 通过闸门的范围可计算 | 交易主键冲突、分母异常时阻断 |
| 商品分类 | `dim_sku` 当前分类 | V1 不做历史回溯；一对多或缺失进入异常 | 分类完整的范围可计算 | 受影响品类正式结果 |
| 未评级门店集合 | 依赖算法 02 是否输出 `NOT_CALCULABLE` 行 | 有行则计算覆盖率；无行则 `store_coverage_status = UNAVAILABLE` 且覆盖率 NULL | 主力贡献仍可计算 | 只影响未评级覆盖率字段，不扩大为全链路阻断 |
| Bootstrap 运行参数 | 需要调度运行时登记 | 固定种子、会员级抽样、1,000～10,000 轮 | 完整周期主力结论仍可发布，稳定性字段按状态写 | 不影响正式主力标签，但阻断可复现性验收 |

## 4. 当前结论

四份文档已对齐。算法 03 的正式开发主交付是开发版算法卡；本矩阵只用于逐章证明承接关系。数据开发需验收上游正式结果是否按合同稳定产出、`NOT_CALCULABLE` 门店行是否可供覆盖率复算，以及 Bootstrap 固定种子和审计参数是否落盘。数据合同已明确的表名、粒度、主键和 `order_id` 唯一性按开发交付合同验收。
