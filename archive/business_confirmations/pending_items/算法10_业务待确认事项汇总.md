# 算法10_业务待确认事项汇总

更新时间：2026-09-04

适用范围：算法 10 新品推荐优先级与开发需求编排

阅读对象：业务、商品、采购、产品、质量、法务、数据开发

## 1. 先看结论

算法 10 V1 已收窄为“新品推荐展示版”。

第一版只做：

```text
把算法 09 已通过或有条件通过的新品候选展示出来；
告诉采购为什么推荐这个新品；
给同一个范围里的推荐候选排展示优先级；
生成推荐卡片摘要和推荐理由。
```

第一版不做：

```text
不展示 REJECT 拒绝候选；
不展示 RETURN_FOR_REBUILD 退回重做候选；
不做“为什么没推荐”的追问；
不做采纳、拒绝处理或发布开发需求；
不做供应商匹配、触达或报价排序；
不输出开发需求草稿。
```

所以，业务当前只需要拍板“推荐卡片怎么写、怎么展示”，不需要确认流程动作。

## 2. 已从算法 10 V1 移除的动作字段

以下字段不再作为算法 10 V1 输出，也不需要业务在本版确认口径。

| 原始字段或动作 | 具体是什么 | V1 处理 |
|---|---|---|
| `recommendation_action_queue` | 原本用于表示候选进入正式开发、条件验证、探索观察、退回重做或不推进等动作队列 | 删除；V1 改用 `recommendation_display_label` 表示推荐展示标签 |
| `publication_type` | 原本用于表示要发布正式开发需求、验证需求或探索需求 | 删除；V1 不发布任何开发需求 |
| `can_publish_requirement` | 原本用于表示是否允许发布某类需求 | 删除；V1 不判断发布权限 |
| `can_publish_formal_development` | 原本用于表示是否允许发布正式新品开发需求 | 删除；V1 不输出正式开发权限 |
| `new_product_development_requirement_draft` | 原本用于承接新品开发需求草稿 | 删除；V1 改为 `new_product_recommendation_display_brief` 推荐展示摘要 |
| 采纳 / 拒绝处理 / 发布开发需求 | 原本属于推荐后的产品工作流动作 | 不进入算法 10；后续版本或产品流程另行设计 |

## 3. 本轮已确认的 V1 展示口径

### 3.1 采购查询条件

采购第一版只需要选择：

```text
运营区域；
城市；
大分类；
中分类；
小分类。
```

门店等级、消费者画像、推荐展示标签和候选状态不作为第一版采购必填查询条件。它们可以作为结果字段展示，也可以后续再做扩展筛选。

### 3.2 列表卡片展示

查询成功后，页面展示推荐新品列表。每张卡片必须有图片区域；可展示图片放到卡片上，图片不可展示时使用占位或隐藏真实图。

每条推荐至少展示：

| 展示项 | V1 口径 |
|---|---|
| 推荐新品名称 | 候选展示名，含规格时展示规格 |
| 推荐分类 | 大分类、中分类、小分类 |
| 适用范围 | 上海、运营大区或门店群 / 门店等级等适用范围 |
| 推荐展示标签 | 正式推荐、条件推荐、探索推荐、局部试点、季节推荐等推荐类标签；不推荐不进入 V1 列表 |
| 推荐理由摘要 | 一句话说明为什么值得看 |
| 用户画像 | 目标消费者画像，例如年轻家庭、品质型等 |
| 建议价格 | 建议零售价或价格区间；缺失时展示“价格待补” |
| 竞对价格 | 竞对商品价格或价格区间；缺失时展示“暂无竞对价格” |
| 行业趋势 | 行业趋势摘要；缺失时展示“暂无趋势证据” |
| 风险提示 | 无明显风险、需补材料、价格风险、法规风险等摘要 |
| 试点建议 | 是否建议试点、建议试点范围或待补条件 |
| 结果更新时间 | 推荐批次或数据截止时间 |

### 3.3 详情展示

用户点击某条推荐后，展示该推荐的详情。

详情至少包含：

| 模块 | 展示内容 |
|---|---|
| 推荐结论 | 推荐展示标签、推荐状态、同范围优先级 |
| 推荐理由 | 系统生成的最终解释文本，必须基于结构化事实 |
| 用户画像 | 目标画像名称、画像贡献、销售额 / 会员占比等摘要 |
| 内部证据 | 锚点商品表现、购物篮关联、价格带或毛利可行性摘要 |
| 竞对价格 | 竞品名称、平台、规格、价格、价格时间和来源 |
| 行业趋势 | 趋势方向、外部来源、时间、趋势强弱或摘要 |
| 风险和门禁 | 当前货盘、历史失败、法规、毛利、图片授权等风险结论 |
| 试点建议 | 建议试点门店群、试点范围、试点注意事项、待补条件 |
| 追溯信息 | 推荐运行批次、推荐结果 ID、证据 ID、数据截止时间 |

### 3.4 图片和推荐理由

图片口径：

| 图片状态 | V1 展示 |
|---|---|
| 图片匹配候选且授权可展示 | 放到推荐卡片上 |
| 无图、授权未知或图片待复核 | 卡片使用占位或隐藏真实图，保留审计 |
| 图片不匹配、授权撤回或明确不可展示 | 不展示真实图 |

推荐理由口径：

```text
V1 启用大模型润色；
大模型只能把结构化事实改写成采购能看懂的大白话；
不能决定要不要推荐，不能新增卖点、成本、法规材料或趋势结论；
事实校验失败时回退固定模板。
```

## 4. 法规在算法 10 的处理

09 V1 已按当前业务确认采用法规留痕口径，不启用法规硬门禁。

算法 10 V1 不做法规判断，只读取算法 09 的最终门禁结果：

```text
如果 09 输出 PASS，10 可以进入对应推荐展示；
如果 09 输出 CONDITIONAL_PASS，10 展示为条件推荐并说明待补材料；
如果 09 输出 RETURN_FOR_REBUILD 或 REJECT，10 V1 不展示。
```

以 Omega-3 鲜鸡蛋为例：

```text
如果 09 V1 因“法规规则未启用”仍输出 PASS，10 可以展示推荐；
但推荐文案只能写“存在功能声称风险线索，后续需补材料确认”；
不能写成“法规已通过”，也不能因为这条法规线索单独改成条件推荐。
```

法规硬门禁可以放到后续版本补，不阻断算法 10 V1 推荐展示开发。

## 5. 当前仍需复核什么

当前没有阻断算法 10 V1 开发的业务待确认项。

后续只需要在业务验收时复核：

| 复核点 | 看什么 |
|---|---|
| 卡片可读性 | 采购是否能一眼看懂推荐什么、为什么值得看、有什么风险 |
| 缺失提示 | 价格待补、暂无竞对价格、暂无趋势证据、图片不可展示等提示是否清楚 |
| 推荐理由 | 大模型润色后是否仍然完全基于结构化事实 |

## 6. 暂不需要业务确认的事项

以下事项不要再问业务：

```text
推荐 ID 怎么生成；
哈希或校验码怎么计算；
Pareto 具体程序怎么写；
每张表的字段类型；
前端如何调接口；
采购是否可以手工改门禁或排名；
算法 10 是否输出采纳、拒绝处理或发布开发需求；
算法 10 是否解释 REJECT 或 RETURN_FOR_REBUILD 候选为什么没推荐。
```

这些是开发实现、产品流程、后续 Agent 能力或已收窄范围，不应让业务逐项复核。
