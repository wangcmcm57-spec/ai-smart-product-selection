# 消费者画像驱动的门店群商品机会模型

生成日期：2026-06-15

## 1. 核心定义

本方案用于支持一种非传统选品方法：不从全店、全品类、全消费者的 TOP 商品出发，而是先确定目标消费者，再回到具体品类和门店群中分析真实消费行为，最终结合外部趋势与竞对数据形成商品机会。

推荐模型名称：

```text
消费者画像驱动的门店群商品机会模型
```

也可以简称：

```text
AI选品模型
```

## 2. 业务逻辑主链路

整体链路如下：

```text
城市消费者画像
-> 高消费占比且高会员占比的重点人群
-> 门店品类等级
-> 同品类同等级门店群
-> 门店群下目标消费者画像
-> 品类内消费者行为二次分析
-> 消费明细商品共性挖掘
-> 外部数据、竞对数据、行业趋势验证
-> 商品机会评分
-> 商品开发与试点建议
```

该方法的关键不是直接看“卖得最好的 SKU”，而是回答：

```text
什么门店群
什么品类
什么主力消费者
在该品类下真实偏好什么商品共性
未来哪些商品方向值得开发
```

## 3. 第一层：城市消费者画像

先使用城市级消费者画像结论，例如上海会员消费行为画像。

重点关注同时满足以下条件的人群：

```text
消费占比高
会员占比高
```

这部分人群是后续商品开发的优先关注对象。

示例画像：

```text
常规时段型-小家庭-高频-价格非敏感
捡漏型-低频
上班族晚高峰型-小家庭-高频-价格非敏感
```

业务更正口径：捡漏型消费者最终画像只保留“捡漏型-高频 / 捡漏型-中频 / 捡漏型-低频”，不再拼接大家庭 / 小家庭，也不再拼接价格敏感 / 价格非敏感。

## 4. 第二层：门店品类等级

基于门店品类等级结果，识别不同门店在同一品类下的等级分布。

核心不是比较所有门店，而是在同一品类下找到同等级门店群：

```text
上海
预制菜
A 级门店群
```

或：

```text
上海
肉禽类
B 级门店群
```

这一步的输出是门店品类等级表。

核心字段建议：

```text
city
store_id
category
category_level
sales_amt
sales_share
buyer_cnt
ticket_cnt
avg_ticket_amt
rank_in_category
```

## 5. 第三层：门店群消费者画像贡献

在同一品类、同一等级门店群中，查看不同消费者画像的贡献。

核心判断：

```text
哪些消费者画像在该门店群、该品类中既贡献销售额，也贡献会员规模
```

建议输出：

```text
city
category
category_level
consumer_profile
sales_amt
sales_share
buyer_cnt
buyer_share
ticket_cnt
avg_ticket_amt
profile_priority
```

重点人群判断逻辑：

```text
sales_share 高
buyer_share 高
```

如果某类画像销售占比高但会员占比低，可能是高客单小众人群。

如果某类画像会员占比高但销售占比低，可能是广覆盖但价值不高的人群。

优先用于商品开发的人群，应当同时具备较高销售贡献和较高会员覆盖。

## 6. 第四层：品类内消费者行为二次分析

确定目标门店群和目标消费者画像后，只在该品类内部继续分析。

不再看全店、全品类、全消费者。

分析内容包括：

```text
买什么 SKU
什么时间买
买多大规格
买什么价格带
是否买促销
是否买时段折扣
是否复购
和哪些商品一起买
是否集中在少数 SKU
是否偏好牛肉、鸡肉、猪肉、水产、素菜
是否偏好即烹、即热、即食
```

建议输出：

```text
city
category
category_level
consumer_profile
sku_id
sku_name
sales_amt
qty
ticket_cnt
buyer_cnt
repeat_buyer_cnt
repurchase_rate
avg_price
discount_rate
hour_discount_rate
pre19_sales_share
co_purchase_items
```

## 7. 第五层：挖掘商品共性

这一步不是简单输出 TOP SKU，而是提炼商品特征共性。

### 7.1 商品属性共性

```text
肉类偏好：牛肉 / 鸡肉 / 猪肉 / 水产 / 素菜
加工形态：即烹 / 即热 / 即食
规格：150g / 200g / 250g / 300g
价格带：按食材、时段、规格输出明确成交价格区间，不使用笼统的低 / 中 / 高
口味：黑椒 / 奥尔良 / 酱香 / 川香 / 蒜香
品牌：自有品牌 / 外部品牌
```

### 7.2 行为共性

```text
高复购 SKU
高连带 SKU
高 19 点前消化 SKU
低折扣仍能卖 SKU
高客单 SKU
高渗透 SKU
```

### 7.3 组合共性

```text
常和哪些商品一起买
同一小票里是否出现主菜 + 配菜
是否有家庭餐组合倾向
是否偏好半成品肉菜搭配
```

适合使用的算法：

```text
关联规则：找商品组合和连带关系
聚类：找 SKU 特征群
序列 / 时段分析：找购买时间偏好
复购分析：找稳定需求商品
价格带分布：找可接受价格区间
```

最终输出不应是“买了哪些 SKU”，而应是：

```text
这类消费者在这个门店群里偏好什么类型的商品
```

示例：

```text
250g 以内
牛肉 / 鸡肉即烹
黑椒 / 奥尔良口味
19 点前动销强
低时段折扣依赖
适合小家庭高频晚餐场景
```

## 8. 第六层：引入外部数据

内部数据回答：

```text
过去什么卖得好
```

外部数据回答：

```text
未来什么可能值得开发
```

外部数据分三类：

```text
竞对数据：在售 SKU、价格、规格、口味、销量、评价、上新频率、促销力度
行业趋势：预制菜、健康轻食、空气炸锅、高蛋白、低脂、儿童餐、一人食、家庭快手菜、地域口味
内容 / 搜索趋势：小红书、抖音、电商搜索热词、菜谱热度、节假日消费趋势
```

外部数据不能直接决定选品，而是与内部行为共性做匹配和验证。

## 9. 第七层：商品机会评分

在进入机会评分前，必须先做候选商品负向过滤。以下两类规则属于硬性不推荐逻辑，不是简单扣分。

### 9.0 不做推荐的底层过滤规则

#### 9.0.1 历史订购差销商品剔除

基于历史数据库、历史订购数据、历史销售数据、历史毛利与损耗数据，识别历史上曾经订购或开发过、但销售表现不好的商品。

命中以下情况时，不进入推荐池：

```text
历史上曾经订购过
且销售额、销量、小票数、复购率、动销天数等表现较差
或长期依赖折扣、时段折扣、清仓折扣才能动销
或毛利、损耗、退货、报损表现不健康
```

不仅原商品不推荐，相似商品也不推荐。相似判断包括：

```text
同主材料
同口味
同加工形态
同规格价格带
同使用场景
同供应商或同系列商品
商品名称高度相似
```

该规则的目的不是否定品类机会，而是避免重复推荐历史已经验证失败的具体商品形态。

示例：

```text
历史订购过 250g 黑椒牛肉粒，A/B 级门店动销差、折扣依赖高
-> 不推荐同款黑椒牛肉粒
-> 不推荐相似的黑椒牛肉丁、黑椒牛肉块、同规格同口味牛肉快炒包
-> 可以继续分析牛肉品类，但必须换材料组合、口味、规格或场景
```

#### 9.0.2 现有在售货盘重复商品剔除

基于当前在售货盘，判断候选商品是否已经存在同款或高度相似商品。

命中以下情况时，不进入推荐池：

```text
现有货盘已有同款商品
现有货盘已有同主材、同口味、同规格、同场景的相似商品
现有货盘已有可满足同一消费者需求的替代商品
```

该规则用于避免 AI 推荐已经在卖的商品，或推荐一个采购无法区分的新旧重复 SKU。

示例：

```text
现有货盘已有 220g 盐焗鸡翅
-> 不推荐再开发 220g 盐焗鸡翅
-> 不推荐高度相似的盐焗鸡中翅、盐焗鸡翅根
-> 如果要推荐，只能转为明确的升级、替换或差异化方向，例如低钠盐焗鸡翅、空气炸锅盐焗鸡翅根、家庭装盐焗鸡翅组合
```

因此，候选商品进入评分前的顺序应为：

```text
候选商品方向生成
-> 历史订购差销商品剔除
-> 历史差销相似品剔除
-> 当前在售货盘同款剔除
-> 当前在售货盘相似品剔除
-> 剩余候选商品进入机会评分
```

最终每个候选商品或商品方向形成机会分。

```text
AI选品机会分 =
内部需求匹配分
+ 门店群适配分
+ 消费者画像适配分
+ 外部趋势分
+ 竞对验证分
+ 毛利 / 供应可行性分
- 折扣风险
- 损耗风险
- 同质化风险
```

评分含义：

```text
内部需求匹配分：目标消费者是否已经买类似商品
门店群适配分：该等级门店是否适合扩这个品类
消费者画像适配分：是否符合小家庭、高频、价格非敏感等特征
外部趋势分：是否有行业热度或内容热度
竞对验证分：竞对是否已有成熟销量
毛利 / 供应可行性分：是否能赚钱、能稳定供货
折扣风险：是否高度依赖促销或时段折扣
损耗风险：是否容易损耗、滞销或过期
同质化风险：是否与现有商品或竞对商品高度重复
```

## 10. 最终推荐结果结构

最终输出不是简单给采购一个 SKU 列表，而是一套可解释的商品机会建议。

建议字段：

```text
city
category
category_level
target_consumer_profile
recommended_product_direction
candidate_sku
recommended_action
expected_reason
risk_reason
confidence_score
```

示例：

```text
城市：上海
品类：预制菜
门店群：A级门店
主力消费者：常规时段型-小家庭-高频-价格非敏感

消费者行为结论：
偏好 200-250g 即烹肉类
牛肉 / 鸡肉表现强
19 点前消化好
对时段折扣依赖低
高频复购集中在黑椒、奥尔良、牛肉丝、牛柳类

外部趋势：
高蛋白、空气炸锅、快手晚餐类商品热度上升
竞对已有黑椒牛肉粒、奥尔良鸡排、低脂鸡胸类商品稳定销售

推荐方向：
1. 200-250g 黑椒牛肉粒
2. 低脂奥尔良鸡排
3. 空气炸锅鸡翅根
4. 家庭快手菜牛肉组合

推荐动作：
A 级门店优先试点
B 级门店小范围测试
C / D 级门店暂不扩品
```

## 11. 四张核心产物表

本模型最终应沉淀四张核心表：

```text
1. 门店品类等级表
2. 门店群消费者画像贡献表
3. 目标消费者品类消费共性表
4. AI商品机会推荐表
```

后续算法讨论重点应放在第三张和第四张表：

```text
如何从消费明细中稳定提炼商品共性
如何把外部趋势转成可评分的商品机会
```

## 12. 与传统选品的区别

传统选品常见路径：

```text
看全区 TOP 商品
看采购经验
看竞对有啥就跟啥
```

本模型路径：

```text
先确定谁是主力消费者
再确定这些消费者在哪些门店群里买什么品类
再看他们在该品类下真实偏好的商品共性
最后结合外部趋势生成商品方向
```

因此，本模型的核心不是“商品排名”，而是“消费者画像驱动的商品机会识别”。

## 13. 已验证模块一：消费者行为画像 V3

消费者画像来自 Doris 小票明细表：

```text
data_agent.dws_member_order_item_detail_df
```

当前消费者画像与门店品类等级统一采用三个区域组：

```text
上海
宁波杭州
苏锡常及其他
```

当前 V3 画像已经验证的核心步骤如下。

### 13.1 数据过滤

```text
剔除 customer_id 为空
剔除 customer_id 以 6 开头的会员
剔除同一会员同一天小票数 > 5 的异常会员日
画像粒度为 store_id + customer_id
同一会员同一天多张小票，消费频次只算 1 天
```

### 13.2 四类画像维度

```text
时间行为：捡漏型 / 上班族晚高峰型 / 常规时段型
家庭规模：大家庭 / 小家庭
消费频次：高频 / 中频 / 低频
价格态度：价格敏感 / 价格非敏感
```

业务更正口径：捡漏型消费者最终画像只保留时间行为和消费频次，即“捡漏型-高频 / 捡漏型-中频 / 捡漏型-低频”。家庭规模和价格态度可以作为中间指标计算，但不拼接进捡漏型最终画像标签。

周末消费行为不进入主画像，后续作为周末专项单独分析。

### 13.3 时间行为

捡漏型：

```text
19:30 后消费天数占比
19:30 后小票占比
19:30 后金额占比
```

上班族晚高峰型：

```text
工作日 18:00-19:30 消费天数占比
18:00-19:30 小票占比
18:00-19:30 金额占比
```

判断方式：

```text
熵权法计算综合得分
动态阈值判断是否命中
优先级：捡漏型 > 上班族晚高峰型 > 常规时段型
```

### 13.4 家庭规模

家庭规模只使用 19 点前蔬菜消费行为判断。

大家庭规则：

```text
pre19_veg_days >= 2
并且满足以下任意条件：
1. 19点前日均蔬菜重量 >= 1.5kg
2. 19点前日均蔬菜 SKU 数 >= 4
3. 19点前日均蔬菜重量 >= 1.2kg 且 19点前日均蔬菜 SKU 数 >= 3
```

不满足大家庭规则的会员归为小家庭。

### 13.5 消费频次

消费频次使用两套口径交叉验证：

```text
绝对频次：按月均消费天数分为高频 / 中频 / 低频
分布频次：按全部会员 monthly_shop_days 做三等分
```

最终规则：

```text
任一口径为高频 -> 高频
任一口径为低频 -> 低频
其他 -> 中频
```

旧版的“偏高频”并入“高频”，“偏低频”并入“低频”。

### 13.6 价格态度

价格态度只分为：

```text
价格敏感
价格非敏感
```

价格敏感使用 19 点前促销行为判断，不使用 `is_hour_promotion`。

核心指标：

```text
19点前促销 SKU 占比
19点前促销金额占比
19点前促销天数
19点前促销小票占比
19点前促销 SKU 分散度
```

最终命中必须同时满足：

```text
pre19_promo_sku_share >= 动态阈值
pre19_promo_amt_share >= 动态阈值
最低促销 SKU 数
最低促销天数
单一促销 SKU 金额占比不能过高
```

### 13.7 画像标签输出

非捡漏型画像标签由四类维度组合生成：

```text
时间行为-家庭规模-消费频次-价格态度
```

示例：

```text
常规时段型-小家庭-高频-价格非敏感
上班族晚高峰型-大家庭-低频-价格敏感
```

捡漏型画像标签只由时间行为和消费频次组合生成：

```text
捡漏型-高频
捡漏型-中频
捡漏型-低频
```

## 14. 已验证模块二：门店品类等级

门店品类等级的销售、客数、时间、折扣等行为指标来自 Doris 小票明细；Excel 只作为 Doris 缺失字段的补充，主要提供商品品类映射、门店城市映射、毛利率和损耗率。

最终分析口径：

```text
门店-品类等级：使用 Doris 全量明细
Doris 明细范围：2025-10-26 至 2026-06-07
Doris 原始明细行数：54,173,893
Excel：不参与销售时间窗口筛选，只作为静态补充结果表
```

本次使用数据：

```text
Doris：data_agent.dws_member_order_item_detail_df
Excel：华东门店商品明细（4月至今）.xlsx
Excel：华东门店猪肉类商品明细（4月至今）.xlsx
```

口径说明：

```text
销售额、销售数量/重量、小票数、会员数、19点前销售额、折扣额、时段折扣额：来自 Doris
大类/中类/小类、商品名称、门店名称、城市、毛利率、损耗率：来自 Excel
毛利额：用 Excel 毛利率 × Doris 销售额重算
损耗额：用 Excel 损耗率 × Doris 销售额重算
```

因此，Excel 文件里的“4 月至今”不作为本次门店品类等级的时间范围；真正的销售行为时间范围以 Doris 全量明细为准。

### 14.1 区域分组

所有结果按三个区域组输出：

```text
上海
宁波杭州
苏锡常及其他
```

其中：

```text
上海 -> 上海
```

### 15.3 19 点后分时段价格感知

19 点后的购买行为要单独分析，因为它反映消费者对“性价比”和“值多少钱”的判断。

后续应拆成：

```text
19:00-19:29
19:30-20:29
20:30-21:29
21:30 以后
```

每个时段计算：

```text
sales_amt
sales_qty
buyer_cnt
ticket_cnt
avg_transaction_price
discount_rate
hour_discount_rate
sales_share
```

价格带不按“低 / 中 / 高”输出，而按食材和规格输出明确数值区间：

```text
猪肉即烹 200-250g：消费者可接受成交价区间
猪肉即食 150-250g：消费者可接受成交价区间
牛肉即烹 200-250g：消费者可接受成交价区间
鸡肉即烹 200-300g：消费者可接受成交价区间
```

建议算法：

```text
按食材 + 烹饪方式 + 规格段 + 时段聚合成交价格
取 p25 / p50 / p75 作为价格接受区间
取销量加权平均价作为当前成交中枢
```

## 18. AI 选品页面逻辑修正：先锚定小分类，再做关联和商品建议

本次页面调整增加一条硬约束：商品开发建议必须先锁定当前选择的 `大分类 / 中分类 / 小分类`，尤其是小分类。AI 不能只根据“方便、健康、快手”等泛趋势直接跳到另一个品类，也不能把包装策略混进商品主名称里。

### 18.1 推荐顺序

```text
1. 读取采购选择的大分类 / 中分类 / 小分类
2. 优先在当前小分类内寻找商品开发方向
3. 用历史订购、历史销售、毛利、损耗数据剔除历史差销商品及相似品
4. 用当前在售货盘剔除已有商品及相似品
5. 再从同一小票里寻找具体连带 SKU
6. 只在连带商品中扩展到相邻场景品类
7. 最后叠加门店等级、消费者画像、竞品和外部趋势
```

示例：

```text
肉禽蛋类 / 蛋类 / 鸡蛋类
-> 商品建议只能先落在鸡蛋小分类
-> 合理方向：Omega-3鸡蛋、花青素鸡蛋、低胆固醇鸡蛋、三天鲜鸡蛋
-> 不合理方向：鸡蛋彩椒玉米腌制快炒包
```

### 18.2 购物篮规则口径

基于 FP-Growth 或关联规则分析时，只要目标筛选条件下存在足够小票，理论上不应该直接显示“暂无购物篮规则”。如果强规则较少，应降低阈值或展示低支持度但高提升度的具体规则，并说明口径，而不是返回空白。

页面采用以下口径：

```text
有 Doris 小票级结果：展示具体 SKU 的正向和反向规则
暂未落地全量结果：按当前小分类生成具体商品锚定规则，并标记正式上线由 Doris 复算
禁止展示：净菜配菜、复合调味、主食类这类泛类目冒充关联商品
```
