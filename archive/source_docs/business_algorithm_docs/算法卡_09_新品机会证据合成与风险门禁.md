# 算法卡 09：新品机会证据合成与风险门禁算法

文档状态：业务规则已确认  
适用范围：汇总算法 02—07 形成的具象新品候选证据，并执行商品相关风险门禁  
唯一业务目标：新品开发  
正式计算粒度：周期 + 城市/城市群 + 门店等级 + 消费者类型 + 叶子小分类 + 标准新品候选  
确认日期：2026-07-31

## 1. 算法澄清表

| 项目 | 业务问题 | 已确认规则 |
|---|---|---|
| 算法名称 | 第 9 个算法叫什么 | 新品机会证据合成与风险门禁算法 |
| 业务目标 | 解决什么问题 | 汇总算法 02—07 的新品机会证据，过滤商品相关风险，输出采购可以执行的最终新品候选状态 |
| 业务边界 | 是否只做风险提醒 | 不是；同时完成机会证据合成、硬门禁、条件门禁、候选分层和开发动作映射 |
| 计算对象 | 按谁计算 | 按标准新品候选在具体城市/城市群、门店等级和消费者类型下计算 |
| 正式粒度 | 一条结果代表什么 | 周期 + 城市/城市群 + 门店等级 + 消费者类型 + 叶子小分类 + 标准新品候选 |
| 范围差异 | 同一商品是否全区域共用结论 | 不共用；同一候选在不同目标范围独立计算，法规禁用等全局证据作为公共底层输入 |
| 候选修改 | 算法 09 能否直接修改商品 | 不能；材料、口味、工艺、规格或价格发生变化时创建新候选 ID，并重跑相关上游算法 |
| 候选入口 | 哪些候选进入 | 正式和探索候选都进入，但风险通过不能把探索证据升级为正式证据 |
| 门禁结果 | 如何输出能否继续 | `PASS`、`CONDITIONAL_PASS`、`RETURN_FOR_REBUILD`、`REJECT` 四类 |
| 最终候选状态 | 如何表达机会等级 | `FORMAL_NEW_PRODUCT`、`SEASONAL_NEW_PRODUCT`、`LOCAL_PILOT_NEW_PRODUCT`、`EXPLORATORY_NEW_PRODUCT`、`NOT_ELIGIBLE_FOR_NEW_PRODUCT` |
| 条件通过 | 可以做什么 | 可以发布待验证开发需求，但不能进入正式试点；补证后重跑算法 09 |
| 硬拒绝 | 哪些风险可以拒绝 | 仅确定性且可追溯的法规禁用、当前货盘重复、历史失败同款/高相似、算法 05 无可行交集等风险 |
| 历史失败范围 | 一地失败是否全国失败 | 否；按目标范围判断并分层借数，只有跨范围稳定失败才升级为全局失败证据 |
| 历史退出 | 停止订购是否等于失败 | 不等于；季节结束、换码、供应中断、法规退出和经营失败必须分开 |
| 历史样本 | 样本少能否硬拒绝 | 不能；必须输出失败后验、可信区间和稳定性，样本不足只能提示不确定 |
| 历史阈值 | 失败概率阈值如何产生 | 使用历史真实损益和滚动时间外回测动态选择，不固定为 80% 等经验值 |
| 历史原因 | 如何识别失败原因 | 使用准实验、匹配和分级因果证据；模型特征重要性不能单独证明原因 |
| 相似商品 | 如何判断 | 复用统一版本化商品相似引擎，结合商品编码、分类、材料、配料、口味、工艺、规格、包装、保质期、价格和场景 |
| 相似阈值 | 灰区如何处理 | 硬拒绝优先判准；相似概率灰区进入 `NEEDS_DUPLICATE_REVIEW`，不能直接拒绝 |
| 当前在售 | 如何识别 | 商品基础表 `可订可售` 字段为当前在售状态 |
| 货盘范围 | 只检查目标城市吗 | 不；先检查公司全量当前货盘，已有商品跨区域引入不属于新品开发 |
| 法规 | 如何判断 | 版本化法规知识库 + 确定性规则引擎；AI 只提取字段和解释，不能自行放宽规则 |
| 供应商 | 是否判断供应商 | 不判断；不做供应商准入、匹配、邀请、评分、排序或触达，只做商品相关风险 |
| 价格毛利 | 是否重算算法 05 | 不重算；读取算法 05 的价格、成本、目标毛利和可行交集结果 |
| 折扣风险 | 什么才算风险 | 19:30 前自然售罄不足、19:30 后阶梯折扣依赖和全链路毛利受损共同出现 |
| 损耗风险 | 是否单独计算 | 不计算、不展示，也不重复扣分；经营影响仅通过现有全链路毛利体现 |
| 毛利风险 | 是否做完整蒙特卡洛 | 不做；使用历史真实基准情景和不利情景压力测试，完整模拟留给试点评估 |
| 压力情景 | 如何生成 | 稳健标准化 + K-medoids 真实样本聚类，聚类数量通过稳定性和时间外验证选择 |
| 情景缺失 | 无高相似历史商品怎么办 | 分层回退，仍不足则输出 `INSUFFICIENT_MARGIN_STRESS_EVIDENCE`，不虚构情景 |
| 数据质量 | 所有缺失都拒绝吗 | 否；核心数据缺失退回重建，增强证据缺失只降低完整度 |
| 外部同质化 | 竞品相似是否拒绝 | 不直接拒绝；内部货盘重复才硬拒绝，明确知识产权侵权按法规硬拒绝 |
| 差异属性 | 如何确认 | 使用标准属性、竞品贝叶斯覆盖率、购物篮/趋势来源和竞品痛点证据，不使用 AI 文案冒充差异 |
| 机会总分 | 是否生成 0—100 分 | 不生成；使用最低证据条件、证据等级和 Pareto 排序 |
| 最低证据 | 候选至少需要什么 | 算法 02—05 基础条件全部满足，算法 06 或 07 至少提供一条可追溯新品属性来源 |
| 风险升级 | 风险低能否升级机会等级 | 不能；风险门禁只能保留、降级或退出，不能补足上游机会证据 |
| 局部试点 | 如何判断 | 机会在稳定门店子群成立但尚不能推广到完整目标群，不用固定门店数量判断 |
| 季节新品 | 如何判断 | 继承商品端 `S` 状态及正式上下架窗口，季外无销售不作为失败 |
| 多风险冲突 | 最终结果如何确定 | `REJECT > RETURN_FOR_REBUILD > CONDITIONAL_PASS > PASS`，同时保留全部已发现原因 |
| 单项风险 | 是否使用高中低 | 不使用；使用可执行状态 `CLEAR`、`OBSERVED_NON_BLOCKING`、`CONDITION_REQUIRED`、`REBUILD_REQUIRED`、`HARD_STOP`、`NOT_EVALUABLE` |
| 人工复核 | 采购能否覆盖硬门禁 | 不能直接覆盖；可以纠正数据或补充证据后重算，特殊业务例外走独立审批并保留算法原结论 |
| 更新频率 | 多久更新 | 月度正式计算，货盘和法规在发布开发需求前即时复核，关键字段变化触发重算 |
| 产品展示 | 普通采购看什么 | 默认展示商品、范围、机会依据、门禁结果、风险原因、解除条件和下一步动作；技术层保留完整证据 |
| 排序 | 不同路径怎么比较 | 先按证据层级分组，再在共同适用维度做 Pareto；不适用指标不填 0 |
| 跨品类 | 全选是否生成统一榜单 | 不；展开叶子小分类分别计算和展示，不跨品类强行排名 |
| 数据周期 | 所有数据是否同周期 | 不；机会证据读同一 3 个月正式版，货盘和法规用最新状态，历史失败使用完整合格生命周期 |
| 输出结构 | 只存一张宽表吗 | 不；输出十张正式表，产品默认读取最终门禁结果表 |
| 验收方式 | 产研如何判断正确 | 固定案例复算、状态优先级、时间外回测、相似模型判准、法规版本、K-medoids 情景和端到端血缘验收 |

## 2. 算法定位与边界

### 2.1 全链路位置

```text
算法 02：目标门店等级群
+ 算法 03：目标消费者类型与贡献
+ 算法 04：主体商品需求和正式锚点
+ 算法 05：规格、售价、成本和目标毛利可行性
+ 算法 06：购物篮配方型新品属性
+ 算法 07：竞品与全球外部趋势新品属性
        ↓
算法 09：最低机会证据校验
        ↓
当前货盘、历史失败、法规、价格毛利、折扣依赖、同质化和数据质量门禁
        ↓
最终新品候选状态 + 门禁结果 + 下一步动作
```

### 2.2 本算法做什么

```text
汇总而不重算算法 02—07 的正式证据
验证每个商品名称属性都有来源
识别公司当前货盘同款和高相似品
识别历史经营失败同款和高相似品
执行法规、食品安全、标签、声称和知识产权规则
读取算法 05 并执行历史真实毛利情景压力测试
识别折扣依赖、外部同质化和数据不可评估风险
确定门禁结果、最终候选状态和开发动作
```

### 2.3 本算法不做什么

```text
不重新贴会员画像
不重新划分门店品类等级
不重新计算 SKU 锚点、价格带、购物篮或外部趋势
不直接修改商品材料、口味、工艺、规格或价格
不输出促销、陈列、订购、替换、升级或清退建议
不计算或展示独立损耗风险
不做完整蒙特卡洛利润预测
不生成跨叶子小分类的机会总榜
不生成固定权重机会分或风险总分
不做供应商准入、匹配、邀请、评分、排序或触达
```

供应商系统后续回传的新成本、配方或规格不是算法 09 的供应商判断结果。字段发生变化时，应先更新候选，并按影响范围重跑算法 05、算法 08，再重跑算法 09。

## 3. 正式计算对象与唯一粒度

### 3.1 正式结果粒度

```text
gate_algorithm_version
+ formal_period
+ target_city_group_id
+ final_level
+ final_profile
+ leaf_category_id
+ standard_candidate_id
```

同一版本和粒度只能有一条最终门禁结果。

### 3.2 范围切换必须重算

切换以下任一字段必须读取对应范围的上游证据和商品数据重新计算：

```text
城市/城市群
门店等级
消费者类型
叶子小分类
标准新品候选
```

不得平均不同城市、等级或画像的失败概率、毛利情景和门禁结果。

### 3.3 大、中分类和全选

```text
选择小分类：直接计算该叶子小分类
选择中分类：展开全部叶子小分类后逐个计算
选择大分类或全选：继续展开叶子小分类，分别门禁并分组展示
```

不允许将“全部小分类”作为候选商品分类，也不允许跨叶子小分类生成统一机会总榜。

## 4. 数据周期、版本和重算触发

### 4.1 四类时间口径

| 数据类型 | 正式口径 |
|---|---|
| 算法 02—07 机会证据 | 同一个最近 3 个数据完整自然月正式版本 |
| 当前货盘 | 门禁执行时最新的公司级 `可订可售` 快照 |
| 法规规则 | 门禁执行时已经生效的最新法规知识库版本 |
| 历史失败模型 | 全部满足质量要求的历史商品生命周期，按上市批次滚动训练 |
| 毛利压力情景 | 优先使用近期同季节历史数据，旧数据统一价格和成本口径后使用 |

禁止使用 `data_cutoff_at` 之后的数据评价当期候选。

### 4.2 正式更新和即时复核

```text
每月：关联算法 02—07 版本，生成正式门禁结果
```

## 6. 前置过滤、数据质量和对账

### 6.1 核心数据

缺失以下任一核心字段时，不得继续形成可发布候选：

```text
正式叶子小分类映射
standard_candidate_id
具象候选商品名和规格
商品名称各属性来源 ID
算法 05 价格成本可行性
当前公司级可订可售货盘快照
历史商品换码和状态关系
有效法规知识库版本
```

处理结果：

```text
risk_state = NOT_EVALUABLE
new_product_gate_result = RETURN_FOR_REBUILD
```

### 6.2 增强数据

```text
外部趋势
竞品图片
社媒口碑
高相似历史经营情景
毛利压力测试情景
```

增强数据缺失不直接拒绝候选。必须输出具体缺失状态，并根据是否影响当前开发动作确定 `OBSERVED_NON_BLOCKING` 或 `CONDITION_REQUIRED`。

### 6.3 到货与销售异常

毛利情景库沿用日清门店已确认口径：

```text
actual_receipt_qty <= 0
-> 不保留有效经营情景

full_day_sales_qty / actual_receipt_qty > 1.10
-> 标记超卖或数据异常
-> 不允许将销售量静默截断为到货量
-> 不进入情景聚类
```

称重商品和计件商品分别计算，公斤与件数不得相加。

### 6.4 金额对账

```text
full_chain_margin_amt
= actual_sales_amt - full_chain_cost_amt
```

算法 09 读取现有全链路成本和毛利口径，不再次扣减损耗、折扣或其他已入账成本。

## 7. 最低机会证据与候选入口

### 7.1 四项基础条件必须全部满足

```text
算法 02：目标门店等级群存在且版本有效
AND 算法 03：目标消费者类型及贡献结构明确
AND 算法 04：目标叶子小分类的主体商品需求成立
AND 算法 05：规格、售价、成本和目标毛利存在可行交集
```

### 7.2 新品属性来源至少满足一条

```text
算法 06：正式或探索购物篮配方型属性
OR
算法 07：正式或探索外部新品属性
```

算法 06 与算法 07 都成立时，候选可以标记为内外部收敛，但不得覆盖原始证据链。

### 7.3 不适用不是零分

```text
Omega-3 鲜鸡蛋没有购物篮配方属性
-> basket_evidence_status = NOT_APPLICABLE
-> 不填 0

青椒黑椒牛柳丝没有正式外部趋势
但内部正式购物篮规则成立
-> external_evidence_status 可以为 NO_EXTERNAL_OBSERVATION
-> 不填 0
```

### 7.4 最低证据失败

```text
主体需求不成立
价格成本无可行交集
候选属性无任何可追溯来源
候选无法保持叶子小分类
```

以上结果不得通过高趋势或低风险抵消。

## 8. 统一商品相似引擎

### 8.1 先做硬边界校验

以下边界不满足时，不得仅凭名称相似认定为同款：

```text
叶子小分类
主材料
商品形态
加工工艺
计量类型
```

### 8.2 商品编码确定关系

```text
product_id 相同
OR 正式 SPU 相同
OR replacement_group_id / change_code_relation 明确为同一商品
=> EXACT_EQUIVALENT
```

### 8.3 多模态相似特征

```text
商品名称语义
主材料和配料
口味
加工形态和工艺
标准化规格
价格位置
包装方式
保质期
烹饪和消费场景
图片和 OCR，仅在有真实图片时使用
```

使用已标注的 `EXACT_EQUIVALENT`、`BUSINESS_HIGH_SIMILAR`、`SAME_DIRECTION`、`STRUCTURALLY_DISTINCT` 商品对训练并校准概率。不设置主材料 30%、口味 20% 等人工固定权重。

### 8.4 关系状态

```text

BUSINESS_HIGH_SIMILAR

SAME_DIRECTION

CATEGORY_BOUNDARY_FAILED
```

### 8.5 硬门禁阈值

对候选阈值 `tau_similarity` 做时间外商品对验证：

```text
误拒成功新品成本
= 该新品后续实际正向全链路毛利机会

漏过重复商品成本
= 重复开发成本 + 重复货盘造成的已验证经营损失

tau_similarity
= 在时间外样本中使净损失最低，
   且硬门禁判准率满足稳定性要求的阈值
```

硬拒绝优先保证判准。低于硬门禁但无法确认结构差异的候选进入 `SIMILARITY_GRAY_REVIEW`，不得直接拒绝。

## 10. 历史经营结局标签

### 10.1 退出原因必须拆分

历史商品退出事件至少区分：

```text
PERFORMANCE_FAILURE_EXIT：经营失败退出
SEASONAL_END：S 状态按计划季节结束
CODE_REPLACEMENT：正常换码或 SPU 迁移
SUPPLY_INTERRUPTION：供应中断事实
REGULATORY_EXIT：法规或安全原因退出
STRATEGY_EXIT：组织或货盘策略退出
STILL_ACTIVE：观察截止日仍在售
UNKNOWN_EXIT：原因不明确
```

只有 `PERFORMANCE_FAILURE_EXIT` 是确定历史失败事件。`STILL_ACTIVE` 是右删失，不得直接标记为成功。

### 10.2 多证据概率标签

明确退出原因缺失时，联合使用：

```text
停止订购时间
持续负全链路毛利
19:30 前自然动销不足
长期阶梯折扣依赖
后续是否恢复订购
商品换码和 S 状态关系
```

概率标签输出：

```text
CONFIRMED_FAILURE
PROBABLE_FAILURE
UNCERTAIN_OUTCOME
NON_FAILURE_COMPETING_EVENT
RIGHT_CENSORED_ACTIVE
```

`UNCERTAIN_OUTCOME` 不作为确定失败训练标签，只用于扩大不确定性。

### 10.3 标签示例

```text
商品 A：S 状态小龙虾，在正式下架日停止订购
=> SEASONAL_END，不是失败

商品 B：编码 1001 停止，次日由正式换码 2001 继续销售
=> CODE_REPLACEMENT，不是失败

商品 C：连续经营期负全链路毛利、长期依赖折扣，退出原因为经营不佳
=> CONFIRMED_FAILURE

商品 D：只经营 8 天后停止，退出原因缺失
=> UNCERTAIN_OUTCOME，不能触发硬拒绝
```

## 11. 历史失败分层竞争风险生存模型

### 11.1 为什么不是普通二分类

历史商品存在以下事实：

```text
经营时间长短不同
观察截止日仍有商品在售
季节结束、换码和供应中断会与经营失败竞争发生
同一商品在不同城市群和门店等级的结果可能不同
```

将“停止订购=失败、仍在售=成功”会产生系统性错误，因此使用分层竞争风险生存模型。

### 11.2 分析单位

```text
历史商品标准实体
+ 城市/城市群
+ 门店等级
+ 叶子小分类
+ 上市后的有效经营周期 t
```

有效经营周期只保留商品正式可订可售、门店正常经营且交易、到货和成本数据完整的周期。

### 11.3 竞争风险公式

设历史商品 `i` 在周期 `t` 的事件类型为 `k`：

```text
k = 1：PERFORMANCE_FAILURE_EXIT
k = 2：SEASONAL_END
k = 3：CODE_REPLACEMENT
k = 4：SUPPLY_INTERRUPTION
k = 5：REGULATORY_EXIT
k = 6：STRATEGY_EXIT
```

离散时间原因别风险：

```text
h_ik(t)
= P(T_i=t, J_i=k | T_i>=t, x_i, scope_i)
```

使用多项逻辑分层模型：

```text
log[h_ik(t) / h_i0(t)]
= alpha_k(t)
 + u_k,city_group
 + v_k,final_level
 + w_k,leaf_category
 + beta_k' * x_i
```

其中 `h_i0(t)` 表示该周期没有退出事件；城市群、门店等级和叶子小分类效应使用分层先验收缩。

存活概率：

```text
S_i(t)
= PRODUCT_{s=1..t} [1 - SUM_k h_ik(s)]
```

指定评估窗口 `H` 内的经营失败累计发生概率：

```text
F_i,failure(H)
= SUM_{t=1..H} S_i(t-1) * h_i,failure(t)
```

### 11.4 评估窗口不是固定三个月

候选窗口来自历史数据：

```text
1. 对每个叶子小分类统计经营结果首次稳定的时间分布
2. 候选多个 H 进行上市批次滚动时间外预测
3. 比较校准误差、Brier 分数、实际损益净收益和结论稳定性
4. 选择时间外表现最好的 H
5. 样本不足时向中分类和相似品类分层收缩
```

窗口版本记录在 `failure_horizon_version`，不得由采购临时修改。

### 11.5 防止未来数据泄漏

模型分成两阶段：

```text
阶段 A：历史结局识别
使用历史自然动销、折扣、全链路毛利和退出原因
形成历史商品结局及失败时间

阶段 B：新品风险映射
只使用新品开发前已知字段：
分类、材料、配料、口味、工艺、规格、价格位置、
包装、保质期、季节和目标范围
```

新品尚未发生的销量、复购、实际折扣不得填 0 后进入预测。

### 11.6 候选失败后验

```text
candidate_failure_probability
= E[F_failure(H) | x_candidate, target_scope, model_version]
```

同时输出：

```text
failure_probability_posterior_median
failure_probability_ci_low_95
failure_probability_ci_high_95
evidence_borrow_level
effective_analog_count
historical_stability_status
```

`effective_analog_count` 是模型有效信息量，不是人工固定的原始商品数量门槛。

## 12. 历史失败动态门禁

### 12.1 动态临界点

对每个候选失败概率阈值 `tau` 做上市批次时间外回测：

```text
false_pass_cost(tau)
= 被放过的失败商品实际负全链路毛利
 + 已确认的重复开发成本

false_reject_cost(tau)
= 被错误拒绝的成功商品后续正向全链路毛利机会

correct_reject_benefit(tau)
= 正确拒绝失败商品避免的实际损失

net_benefit(tau)
= correct_reject_benefit
 - false_pass_cost
 - false_reject_cost
```

正式阈值：

```text
tau_failure
= argmax_tau OOT_net_benefit(tau)
```

阈值还必须通过跨上市批次、月份和主要叶子小分类稳定性验证。阈值、训练截止日和回测结果全部版本化。

### 12.2 历史失败硬门禁条件

以下条件同时满足才能因历史失败触发硬拒绝：

```text
候选与历史失败商品为 EXACT_EQUIVALENT
或达到硬阈值的 BUSINESS_HIGH_SIMILAR

AND 历史结局为 CONFIRMED_FAILURE 或高置信 PROBABLE_FAILURE
AND 候选失败概率可信区间支持超过动态门禁临界点
AND 跨月份、门店或范围稳定性通过
AND 数据没有关键质量缺口
```

结果：

```text
risk_type = HISTORICAL_FAILURE
risk_state = HARD_STOP
new_product_gate_result = REJECT
```

### 12.3 样本不足

```text
historical_evidence_status = INSUFFICIENT_HISTORICAL_EVIDENCE
risk_state = OBSERVED_NON_BLOCKING 或 CONDITION_REQUIRED
```

样本不足不能直接变成“低风险”，也不能由一次短期试销触发硬拒绝。

### 12.4 历史失败商品改良

历史失败方向可以重新开发，但必须：

```text
识别失败原因证据等级
-> 在对应材料、口味、工艺、规格、价格或场景上发生实质变化
-> 创建新的 standard_candidate_id
-> 重新运行算法 05—08
-> 相似模型确认不再属于历史失败高相似品
```

只改名称、包装文案或无关配料不能解除门禁。

### 12.5 失败原因因果证据

证据优先级：

```text
随机或准随机试验
> 合格 DID / 合成控制
> 平衡性通过的匹配比较
> 稳健相关诊断
> 单纯模型特征重要性
```

必须输出：

```text
CONFIRMED_CAUSE
PROBABLE_CAUSE
UNKNOWN_CAUSE
```

因果估计需要明确处理变量、结果变量、对照组、时间窗口和识别假设，并执行前趋势、平衡性、安慰剂和敏感性检查。

### 12.6 原因未知时的处理

```text
UNKNOWN_CAUSE + 仍为同款/高相似
-> HARD_STOP / REJECT

UNKNOWN_CAUSE + 已有实质变化且不再高相似
-> CONDITION_REQUIRED / CONDITIONAL_PASS
-> 明示“相关历史方向失败原因尚未确认”
```

### 12.7 历史失败计算示例

模拟历史数据：

```text
候选：250g 黑椒牛肉粒
目标范围：上海 / B 级门店 / 牛肉制品
历史高相似商品：240g 黑椒牛肉丁
历史结局：CONFIRMED_FAILURE
相似关系：BUSINESS_HIGH_SIMILAR
```

生存模型输出：

```text
failure_probability_posterior_median = 0.84
failure_probability_95%_CI = [0.72,0.92]
动态门禁临界点 tau_failure = 0.69
跨月份稳定性 = PASS
```

因为可信区间下界仍高于当期动态阈值，且高相似关系达到硬门禁判准条件：

```text
risk_state = HARD_STOP
new_product_gate_result = REJECT
```

以上数值仅用于产研固定复算，不代表 Doris 生产结果。

## 16. 折扣依赖风险

### 16.1 时间窗口

```text
自然窗口：营业日至 19:30:00，包含 19:30 整点
时段折扣窗口：19:30:00 之后
```

商品活动促销与 19:30 后时段折扣分开记录。

### 16.2 指标

```text
pre1930_sell_through
= pre1930_sales_qty / actual_receipt_qty

post1930_qty_share
= post1930_sales_qty / full_day_sales_qty

weighted_time_discount_depth
= SUM_h[q_h * (1 - realized_unit_price_h / regular_unit_price)]
 / SUM_h(q_h)
```

### 16.3 风险成立条件

折扣风险不是单项固定阈值。以下三类证据需要联合成立：

```text
19:30 前自然售罄相对同范围相似商品偏低
AND 19:30 后数量占比和折扣深度依赖偏高
AND 对应真实情景的全链路毛利明显受损
```

联合边界通过历史真实经营结局和时间外净收益学习，不使用“19:30 后销售额占比超过 30%”等统一经验线。

### 16.4 应用

```text
折扣风险高且可通过规格/价格/包装重构
-> REBUILD_REQUIRED / RETURN_FOR_REBUILD

折扣风险证据不足
-> CONDITION_REQUIRED / CONDITIONAL_PASS

折扣风险低
-> CLEAR
```

折扣风险本身不直接 `REJECT`；重构后算法 05 仍无可行交集时才硬拒绝。

## 17. 毛利真实情景压力测试

### 17.1 为什么不用完整蒙特卡洛

新品尚未试销，复杂概率模拟主要依赖相似商品，容易产生虚假精度。算法 09 只回答：

```text
算法 05 静态可行后，
在历史真实基准经营情景和真实不利情景中，
候选商品是否仍能守住全链路毛利。
```

完整蒙特卡洛、正式订购量和试点利润预测留给后续试点评估算法。

### 17.2 历史情景向量

每个有效门店日形成真实联合向量：

```text
v_d = (
  actual_receipt_qty,
  pre1930_sales_qty,
  discount_tier_1_qty,
  ...,
  discount_tier_H_qty,
  full_day_sales_qty,
  actual_sales_amt,
  full_chain_cost_amt,
  full_chain_margin_amt
)
```

所有字段来自同一商品、同一门店、同一经营日，禁止从不同日期人工拼接。

### 17.3 相似历史商品回退

```text
同范围高相似商品
-> 同城市群其他等级高相似商品
-> 相似城市群高相似商品
-> 同范围、同叶子小分类、相同保质期和加工形态商品
```

每次回退保留 `evidence_borrow_level`。仍不足时：

```text
margin_scenario_status = INSUFFICIENT_MARGIN_STRESS_EVIDENCE
risk_state = CONDITION_REQUIRED
```

### 17.4 稳健标准化

对正偏数量和金额先使用：

```text
x_log = ln(1+x)
```

再计算：

```text
robust_z
= (x_log - median(x_log)) / (1.4826 * MAD(x_log))
```

`MAD=0` 时逐级回退到 IQR 和合格父级尺度参数。称重与计件商品分开。

### 17.5 K-medoids 聚类

使用 PAM K-medoids，使每个聚类中心都是一个真实历史门店日。

候选聚类数：

```text
k = 1 ... min(10, floor(sqrt(n_valid_scenarios)))
```

`10` 只是计算保护上限，不是业务风险阈值。正式 `k` 通过以下顺序选择：

```text
1. 使用滚动月份留出集计算 medoid 分配误差
2. 使用 bootstrap 计算聚类成员稳定性
3. 使用轮廓系数检查可分性
4. 优先选择时间外误差最低且稳定的 k
5. 结果近似时选择更小 k，避免过拟合
```

单日异常点和数据质量异常不进入情景候选。

### 17.6 基准和不利情景

```text
baseline_scenario
= 跨月份稳定、历史覆盖最广的真实 medoid 情景

adverse_scenario
= 在重复稳定情景中全链路毛利较差的真实 medoid 情景
```

不利情景必须在滚动月份和重复抽样中可复现，不能使用历史最差单日。

### 17.7 候选商品代入公式

设候选算法 05 建议原价为 `P`，全链路单位成本为 `C`：

```text
scenario_revenue
= q_pre1930 * P
 + SUM_h(q_h * P * discount_factor_h)

scenario_full_chain_cost
= q_arrival * C

scenario_full_chain_margin
= scenario_revenue - scenario_full_chain_cost

scenario_margin_rate
= scenario_full_chain_margin / scenario_revenue
```

未售出到货商品不单列损耗，但其成本已经通过 `q_arrival*C` 进入全链路毛利。

同时输出：

```text
per_effective_store_day
per_100_items_or_100kg
```

算法 09 不据此生成订购量或整月毛利承诺。

### 17.8 风险映射

```text
基准达到目标毛利，且不利情景毛利仍为正
-> CLEAR

基准达到目标毛利，但不利情景低于目标或转负
-> CONDITION_REQUIRED
-> CONDITIONAL_PASS

基准情景已低于目标毛利
-> REBUILD_REQUIRED
-> RETURN_FOR_REBUILD

算法 05 无价格成本毛利可行交集
-> HARD_STOP
-> REJECT
```

### 17.9 固定复算示例

模拟候选：青椒黑椒牛柳丝 200g。

```text
P = 29.90 元/份
C = 18.00 元/份
标准化到货量 = 100 份
```

基准真实情景：

```text
19:30 前原价售出 78 份
9 折售出 10 份
8 折售出 7 份

revenue
= 78*29.90 + 10*29.90*0.90 + 7*29.90*0.80
= 2,768.74 元

cost = 100*18.00 = 1,800.00 元
margin = 968.74 元
margin_rate = 34.99%
```

不利真实情景：

```text
19:30 前原价售出 55 份
9 折售出 20 份
8 折售出 15 份
7 折售出 5 份

revenue
= 55*29.90 + 20*29.90*0.90
 + 15*29.90*0.80 + 5*29.90*0.70
= 2,646.15 元

cost = 1,800.00 元
margin = 846.15 元
margin_rate = 31.98%
```

若算法 05 目标毛利率为 30%，两种情景都通过，毛利压力风险为 `CLEAR`。

## 18. 外部同质化与差异属性

### 18.1 内部重复与外部相似不能混用

```text
公司当前货盘同款/高相似
-> 新品重复硬门禁

外部竞品同款/高相似
-> 市场供给和同质化证据
-> 不自动拒绝
```

### 18.2 差异属性维度

```text
主材料
配料
口味
功能
工艺
规格
包装
消费场景
```

### 18.3 竞品属性覆盖率

对候选属性 `a`：

```text
x_a = 出现属性 a 的有效可比竞品渠道数
n = 同市场、同周期、同叶子小分类有效可比渠道数

coverage_a ~ Beta(x_a+0.5, n-x_a+0.5)
```

输出覆盖率后验中位数和 95% 可信区间。差异边界通过历史新品验证动态确定，不固定规定覆盖率低于 20% 即差异。

### 18.4 合格差异属性

至少满足一种：

```text
低竞品覆盖 + 算法 06 正式配方证据
低竞品覆盖 + 算法 07 正式/探索趋势证据
竞品稳定负面口碑 + 候选有证据的改良属性
价格或规格存在算法 05 已验证的市场空白
```

每个差异属性必须保留属性来源 ID、竞品证据 ID 和品类保持结果。

### 18.5 门禁应用

```text
没有差异属性但市场需求成立
-> OBSERVED_NON_BLOCKING 或 REBUILD_REQUIRED
-> 不直接 REJECT

明确商标、专利或受保护工艺侵权
-> HARD_STOP / REJECT
```

## 19. 单项风险状态

```text
CLEAR
证据支持该风险已通过

OBSERVED_NON_BLOCKING
存在可追溯风险信号，但不影响当前门禁

CONDITION_REQUIRED
需要补充证据或解除条件后再正式推进

REBUILD_REQUIRED
当前商品设计需要重构并生成新候选

HARD_STOP
命中确定性硬门禁

NOT_EVALUABLE
核心数据不足，当前无法计算
```

每条风险必须同时输出：

```text

risk_state
risk_reason_code
risk_reason_text
risk_evidence_ids
applicable_scope
condition_to_clear
model_or_rule_version

```

## 20. 最终门禁决策引擎

### 20.1 风险执行顺序

```text
核心数据完整性
-> 法规和食品安全
-> 当前货盘重复
-> 历史失败同款/高相似
-> 算法 05 价格成本毛利可行性
-> 最低机会证据
-> 折扣依赖和毛利压力情景
-> 外部同质化和差异属性
```

发现硬门禁后仍保存已经计算出的其他风险原因，避免采购修复一个问题后才发现另一个问题。

### 20.2 状态优先级

```text
存在任一 HARD_STOP
-> REJECT

否则存在任一 REBUILD_REQUIRED 或核心 NOT_EVALUABLE
-> RETURN_FOR_REBUILD

否则存在任一 CONDITION_REQUIRED
-> CONDITIONAL_PASS

否则
-> PASS
```

优先级：

```text
REJECT
> RETURN_FOR_REBUILD
> CONDITIONAL_PASS
> PASS
```

### 20.3 不允许证据抵消

```text
强消费者需求不能抵消法规禁用
高 Lift 不能抵消当前货盘同款
全球趋势不能抵消历史失败高相似
高价格接受度不能抵消算法 05 无成本毛利交集
低预测风险不能把探索候选升级为正式候选
```

## 21. 最终候选状态

### 21.1 状态定义

```text
FORMAL_NEW_PRODUCT
正式内部或外部证据成立，并通过当前门禁

SEASONAL_NEW_PRODUCT
继承 S 状态和正式上下架窗口，并通过当前门禁

LOCAL_PILOT_NEW_PRODUCT
机会在稳定门店子群成立，但尚不能推广到完整目标群

EXPLORATORY_NEW_PRODUCT
新兴趋势、海外领先或探索规则候选

NOT_ELIGIBLE_FOR_NEW_PRODUCT
当前候选被退回重构或拒绝
```

### 21.2 门禁不能升级证据

```text
探索候选 + PASS
-> 仍为 EXPLORATORY_NEW_PRODUCT

季节候选 + PASS
-> 仍为 SEASONAL_NEW_PRODUCT

任一候选 + RETURN_FOR_REBUILD / REJECT
-> 当前 candidate_id 为 NOT_ELIGIBLE_FOR_NEW_PRODUCT
```

`CONDITIONAL_PASS` 保留原机会等级，但产品必须同时显示“待补证”，不得写成可以正式试点。

### 21.3 局部试点判定

```text
整体机会方向成立
AND 至少存在重复稳定的正向门店子群
AND 删除部分门店或月份后完整目标群结论明显变化
AND 分层模型和重复抽样确认不是单店偶然结果
AND 没有硬门禁
```

算法 09 只输出局部适用证据范围，不选择具体试点门店。

### 21.4 季节新品

```text
seasonal_status = S
AND 当前候选属性来源可追溯到正式季节窗口
```

历史失败、购物篮和毛利压力只在对应销售季计算；季外无销售不进入失败证据。

## 22. 机会证据合成与 Pareto 排序

### 22.1 不生成机会总分

算法 09 不输出 0—100 的“AI 机会分”。原因：

```text
当前没有完整、无偏且口径一致的历史新品成功标签
不同候选可能从购物篮或外部趋势不同路径产生
硬风险不能被高机会分抵消
固定权重无法解释为什么是 30% 或 20%
```

### 22.2 先按证据层级分组

```text
内外部共同收敛的正式证据
> 单路径正式证据
> 成熟市场差异化空白
> 正式季节证据
> 局部门店群证据
> 新兴或海外领先探索证据
> 原始信号
```

该顺序用于产品分层，不允许覆盖门禁状态。

### 22.3 同层共同维度

```text
目标消费者主体需求稳定性
算法 05 价格与成本可行空间
历史毛利不利情景稳健性
竞品差异属性证据
跨门店和月份稳定性
风险证据完整度
```

购物篮或外部趋势等路径专属指标不适用时标记 `NOT_APPLICABLE`，不填 0。

### 22.4 Pareto 支配

候选 A 只在以下条件成立时支配候选 B：

```text
A 在所有共同适用维度都不劣于 B
AND A 至少一个维度严格优于 B
```

无支配关系的候选处在同一个 `pareto_front_id`，并列展示各自优势，不强行打总分。

### 22.5 比较范围

Pareto 只在以下相同范围内计算：

```text
formal_period
+ target_city_group_id
+ final_level
+ final_profile
+ leaf_category_id
+ evidence_tier
+ new_product_gate_result
```

不同叶子小分类不得相互排名。

### 22.6 Pareto 示例

```text
候选 A：消费者需求更稳，毛利不利情景更好，差异属性一般
候选 B：消费者需求略低，毛利不利情景一般，差异属性更强

A 和 B 各有严格优势
=> 不互相支配
=> 同一 Pareto 前沿并列展示
```

## 30. 产研与业务验收

### 30.1 唯一性和版本

必须验证：

```text
同一正式粒度只有一条最终门禁结果
候选 payload 变化但 candidate_id 未变化时阻断运行
算法 02—07 版本与门禁批次完整关联
当前货盘和法规快照时间可追溯
相同输入和版本得到相同结果
```

### 30.2 状态优先级固定测试

| 单项最高状态 | 期望门禁结果 |
|---|---|
| 全部 `CLEAR/OBSERVED_NON_BLOCKING` | `PASS` |
| 任一 `CONDITION_REQUIRED`，无更高状态 | `CONDITIONAL_PASS` |
| 任一 `REBUILD_REQUIRED/核心 NOT_EVALUABLE`，无硬停止 | `RETURN_FOR_REBUILD` |
| 任一 `HARD_STOP` | `REJECT` |

同时命中多个状态时必须输出所有原因，但最终结果严格按上述优先级。

### 30.3 当前货盘边界测试

```text
同商品编码 -> REJECT
正式换码同实体 -> REJECT
高相似达到硬门禁 -> REJECT
相似灰区 -> CONDITIONAL_PASS + NEEDS_DUPLICATE_REVIEW
普通鲜鸡蛋 vs 有正式功能证据的 Omega-3 鲜鸡蛋 -> 不得仅因名称主体相同自动拒绝
```

### 30.4 历史失败模型验收

```text
S 状态按计划下架不得标为失败
换码不得标为失败
仍在售商品必须按右删失处理
退出原因缺失不得强制标为失败
同一实体不得跨训练/测试泄漏
门禁阈值只能从训练期产生
时间外概率校准和损益净收益必须达标
```

### 30.5 法规验收

```text
每个硬停止可追溯到有效 rule_id 和原始条款
规则失效后不得继续命中
配方或检测字段缺失只能条件通过，不能伪造值
知识产权和普通竞品相似必须分开
```

### 30.6 毛利情景固定复算

产研必须复算：

| 案例 | 基准毛利率 | 不利/目标关系 | 期望状态 |
|---|---:|---|---|
| 青椒黑椒牛柳丝 200g | 34.99% | 不利 31.98% > 目标 30% | `CLEAR` |
| 香辣鸡腿肉家庭装 500g | 19.89% | 基准 < 目标 25% | `REBUILD_REQUIRED` |

金额和毛利率必须由第 17.7 节公式重新计算，不能直接抄案例结果。

### 30.7 K-medoids 验收

```text
每个 medoid 必须对应真实历史门店日
称重和计件不得混合
销售超过实际到货 10% 的异常日不得进入情景库
基准和不利情景必须跨月份可复现
历史最差单日不得直接冒充正式不利情景
样本不足必须输出明确状态，不得合成虚假情景
```

### 30.8 机会证据与 Pareto 验收

```text
算法 02—05 基础条件必须全部通过
算法 06 或 07 至少一个属性来源成立
NOT_APPLICABLE 不得填 0
不同叶子小分类不得互相排名
无支配关系候选必须允许并列
探索候选通过风险门禁后仍为探索候选
```

### 30.9 产品动作验收

```text
PASS 才能按候选类型发布对应开发需求
CONDITIONAL_PASS 只能发布待验证需求
RETURN_FOR_REBUILD 和 REJECT 不得显示发布按钮
采购复核只能触发证据修正和新运行
业务例外不得覆盖算法原始结果
```

### 30.10 端到端对账

随机抽取候选，必须可追溯：

```text
最终候选
-> 全部单项风险
-> 当前和历史相似商品
-> 历史结局与模型版本
-> 法规条款
-> 毛利真实情景
-> 算法 02—07 上游证据
-> 商品名称每个属性来源
-> 最终动作权限
```

## 31. 不能做的事

```text
不能生成固定权重机会分或风险总分

不能将外部竞品相似直接写成内部重复

不能输出促销、陈列、订购、升级、替换或清退动作
不能让采购直接覆盖 HARD_STOP

不能让 RETURN_FOR_REBUILD 或 REJECT 候选发布开发需求
```
