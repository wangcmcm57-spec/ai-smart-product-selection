# 区域门店品类等级算法规则

生成日期：2026-06-19

来源文档：`消费者画像驱动的门店群商品机会模型.md`

## 1. 模型定位

区域门店品类等级模型用于判断：

```text
在同一个区域组、同一个品类下，哪些门店更适合承接该品类的经营、选品、营销和试点动作。
```

它不是给门店做全店等级，也不是简单按门店总销售额排名，而是：

```text
同区域组 + 同大类 + 同中类 + 同小类
```

在这个比较组内，对不同门店的该品类表现进行评分和分层。

## 2. 业务用途

该规则最初用于 AI 选品底层能力，支持识别：

```text
什么区域
什么品类
哪些门店群
更适合开发、引入、试点、替换或清退某类商品
```

迁移到营销 Agent 后，也可以用于判断：

```text
哪些门店适合重点营销
哪些门店适合小范围测试
哪些门店只适合清库存或低预算动作
哪些门店暂不适合投券或投流
```

### 4.3 重算指标

毛利额使用 Excel 毛利率套用 Doris 销售额重算：

```text
supply_gross_profit_amt = sales_amt * supply_gross_margin_rate
store_gross_profit_amt = sales_amt * store_margin_rate
full_chain_gross_profit_amt = sales_amt * full_chain_gross_margin_rate
```

损耗额使用 Excel 损耗率套用 Doris 销售额重算：

```text
loss_amt = sales_amt * loss_rate
```

折扣率、时段折扣率、损耗率用于经营诊断；其中营销品类等级评分中的折扣健康度只使用 19 点前促销折扣率：

```text
discount_rate = discount_amt / sales_amt
promo_discount_rate = pre19_promo_discount_amt / pre19_sales_amt
hour_discount_rate = hour_discount_amt / sales_amt
loss_rate = loss_amt / sales_amt
```

说明：

```text
promo_discount_rate 在本规则中专指 19 点前促销折扣率。
hour_discount_rate 反映晚间时段折扣，不进入营销品类等级评分。
如果需要保留全日促销折扣率，建议另命名为 total_promo_discount_rate，避免和 19 点前促销口径混淆。
```

19 点前销售占比：

```text
pre19_sales_share = pre19_sales_amt / sales_amt
```

## 6. 门店品类等级粒度

门店等级不按全店打分，而是在同一品类内比较门店。

当前粒度：

```text
region_group
city
store_name
large_category
mid_category
small_category
```

建议实际落表时同时保留：

```text
store_id
store_name
```

因为 `store_name` 适合业务展示，`store_id` 更适合系统关联、任务发布和后续追踪。

完整比较组可以理解为：

```text
同区域组 + 同大类 + 同中类 + 同小类
```

在这个比较组内，再比较不同门店在该品类下的表现。

## 8. 品类等级划分依据

品类等级划分不使用人工固定权重，也不强制每个区域门店品类组都输出 A/B/C/D。

当前规则应按以下五步执行：

```text
第一步：熵权法计算综合得分
第二步：象限分析判断经营类型
第三步：检查样本量、分数差异、象限一致性
第四步：只对满足条件的门店品类组输出 A/B/C/D
第五步：不满足条件的输出观察型标签，不强制分级
```

这五步共同构成门店品类等级的判断依据。

## 9. 熵权法综合评分

### 9.1 核心原则

所有指标权重必须由熵权法根据当前数据自动计算，不能人为指定固定权重。

综合得分公式：

```text
category_score = Σ 标准化指标得分 × 熵权法自动计算权重
```

其中：

```text
指标权重 = 由该指标在同一比较组内的信息熵和差异度决定
差异度越大，说明该指标越能区分门店，该指标权重越高
差异度越小，说明该指标对门店区分度不足，该指标权重越低
```

比较组：

```text
region_group + large_category + mid_category + small_category
```

### 9.2 参与熵权法的指标

正向指标：

| 指标 | 方向 | 业务含义 |
|---|---|---|
| sales_amt | 越高越好 | 该门店该品类销售规模 |
| member_customer_cnt | 越高越好 | 该门店该品类会员客数 |
| full_chain_gross_profit_amt | 越高越好 | 该门店该品类全链路毛利贡献 |
| store_margin_rate | 越高越好 | 该门店该品类门店毛利率 |
| pre19_sales_share | 越高越好 | 19 点前自然经营承接能力 |

反向指标：

| 指标 | 方向 | 业务含义 |
|---|---|---|
| promo_discount_rate | 越低越好 | 19 点前促销折扣依赖程度 |
| loss_rate | 越低越好 | 区域品类损耗风险 |

折扣健康度只考虑 19 点前促销折扣：

```text
promo_discount_rate = pre19_promo_discount_amt / pre19_sales_amt
```

不考虑：

```text
hour_discount_rate
```

原因：

```text
hour_discount_rate 反映晚间时段折扣和临期消化逻辑，不应混入营销品类等级中的自然经营质量判断。
```

损耗健康度按区域品类建立：

```text
region_group + large_category + mid_category + small_category
```

也就是每个区域品类有自己的损耗容忍线，不使用全局统一损耗阈值。

### 9.3 标准化规则

熵权法标准化采用 50 分位标准化，也就是中位数标准化。

不采用极大极小值标准化作为主口径，因为业务数据里极大值、极小值容易包含异常门店、异常商品或异常小票，直接用极值会放大异常情况对评分的影响。

正向指标标准化：

```text
以同一比较组内该指标的中位数作为基准。
指标值高于中位数，标准化得分高于基准。
指标值低于中位数，标准化得分低于基准。
```

反向指标标准化：

```text
以同一比较组内该指标的中位数作为基准。
promo_discount_rate、loss_rate 低于中位数，健康度得分高于基准。
promo_discount_rate、loss_rate 高于中位数，健康度得分低于基准。
```

建议先在同一比较组内完成：

```text
1. 同向化
2. 中位数标准化
3. 必要的异常值处理
4. 熵值和权重计算
```

异常值处理原则：

```text
不使用极大值、极小值直接决定标准化尺度。
对明显异常值可做缩尾或剔除，但必须保留诊断标记。
```

### 9.4 熵权计算逻辑

对每一个比较组分别计算：

```text
1. 对各指标做同向化和标准化
2. 计算每个门店在每个指标上的占比
3. 计算每个指标的信息熵
4. 计算每个指标的差异系数
5. 根据差异系数计算指标权重
6. 用自动权重加权得到 category_score
```

业务解释：

```text
如果某个品类下门店销售额差异很大，销售额权重会自然提高。
如果某个品类下门店毛利率差异不大，毛利率权重会自然降低。
如果某个品类下损耗差异很大，损耗健康度会成为更重要的判断因素。
```

## 10. 象限分析交叉验证

熵权法负责生成综合分，但综合分不能单独决定 A/B/C/D。

需要增加象限分析，用于判断门店品类的经营类型，并对熵权评分做交叉验证。

### 10.1 象限维度

建议使用两个主轴：

```text
经营规模轴
经营质量轴
```

经营规模轴可以由以下指标综合形成：

```text
sales_amt
member_customer_cnt
ticket_cnt
```

经营质量轴可以由以下指标综合形成：

```text
full_chain_gross_profit_amt
store_margin_rate
pre19_sales_share
promo_discount_rate 的反向健康度
区域品类 loss_rate 的反向健康度
```

两个主轴也应优先使用熵权法或数据驱动方式计算，不使用人工固定权重。

### 10.2 象限类型

| 象限 | 判断 | 业务含义 |
|---|---|---|
| 高规模 + 高质量 | 优势经营型 | 既有销售和客数，也有较好的毛利、折扣和损耗表现 |
| 高规模 + 低质量 | 规模强但质量待改善 | 卖得动，但可能依赖折扣、损耗偏高或毛利质量不足 |
| 低规模 + 高质量 | 潜力培育型 | 当前规模不大，但经营质量健康，适合小范围培育 |
| 低规模 + 低质量 | 谨慎经营型 | 规模和质量都不足，应谨慎投入 |

### 10.3 交叉验证规则

熵权综合分与象限判断需要互相校验：

```text
高分 + 高规模高质量象限：可判为强等级候选
高分 + 高规模低质量象限：不能直接判 A，需要标记质量风险
中高分 + 低规模高质量象限：可判为潜力型，不宜简单压到 C/D
低分 + 低规模低质量象限：可判为谨慎或暂缓
```

## 11. 非强制分级规则

门店品类等级不是所有区域、所有品类、所有门店组都必须输出 A/B/C/D。

只有同时满足以下条件，才进入正式等级划分：

```text
样本量足够
指标缺失率可控
熵权综合分存在有效区分度
象限分析结果与综合分基本一致，或通过多算法交叉验证
业务指标没有明显异常
```

如果不满足条件，输出观察型标签，而不是强行分级。

### 11.1 正式等级标签

| 标签 | 判断依据 | 业务含义 |
|---|---|---|
| A | 熵权高分，且象限验证为优势经营型 | 优先经营、优先试点、优先营销 |
| B | 熵权得分较高，或具备明确潜力，但存在轻微短板 | 适合测试、跟进和中等强度营销 |
| C | 综合表现一般，或规模、质量存在明显短板 | 谨慎推进，适合小范围验证 |
| D | 低分且象限验证偏弱，或质量风险明显 | 暂缓扩品或重点营销 |

### 11.2 观察型标签

| 标签 | 触发条件 | 业务含义 |
|---|---|---|
| 暂不分级 | 样本量不足、数据缺失过高或分数无法稳定区分 | 不输出 A/B/C/D |
| 观察型 | 有一定数据，但暂不足以支持明确等级 | 继续观察，不直接做强动作 |
| 潜力培育型 | 低规模 + 高质量 | 可小范围测试，不应简单判低等级 |
| 质量改善型 | 高规模 + 低质量 | 有销售基础，但需先改善毛利、折扣或损耗 |
| 谨慎经营型 | 低规模 + 低质量 | 谨慎投入，优先诊断原因 |

### 11.3 分级保护规则

以下情况不得强制输出 A/B/C/D：

```text
同一比较组门店数量过少
该品类销售额或小票数过低
关键字段缺失严重
熵权分数差距过小
象限结果与综合分明显冲突
折扣、损耗或毛利指标存在异常值且未处理
毛利率或损耗率缺失导致关键质量指标无法计算
```

### 11.4 样本置信度阈值

正式分级不设置人工固定的最低样本量、小票数、销售额阈值。

阈值由数据结果的置信度决定，建议从以下维度动态判断：

```text
同一比较组内可评分门店数
该品类销售额规模
该品类小票数规模
会员购买人数规模
关键指标缺失率
熵权分数分布稳定性
多算法交叉验证一致性
```

如果数据不足以支持稳定判断，则输出：

```text
暂不分级
观察型
```

而不是为了覆盖率强行给出 A/B/C/D。

### 11.5 熵权分数差异阈值

熵权分数差异阈值不预先写死。

正式阈值需要在大量历史数据上验证后确定，至少应验证：

```text
同一比较组内 category_score 的分布离散度
不同等级之间的销售、毛利、折扣、损耗表现是否真的分离
等级结果在不同时间窗口下是否稳定
等级结果对后续营销效果是否有解释力
```

如果某个比较组的熵权分数差异未达到有效区分阈值，则：

```text
熵权法结果不参与最终多算法交叉验证
保留其他算法结果继续交叉验证
最终输出观察型标签或人工复核标签
```

### 11.6 冲突处理与多算法交叉验证

当象限结果与熵权结果发生冲突时，不直接以某一方为准。

需要引入多种算法做交叉验证，例如：

```text
熵权法综合评分
象限分析
聚类分析
稳健排名分析
时间窗口稳定性验证
业务规则校验
```

交叉验证原则：

```text
如果熵权分数差异达到有效区分阈值，熵权法结果可以参与交叉验证。
如果熵权分数差异未达到有效区分阈值，熵权法结果必须从交叉验证中剔除。
剔除熵权结果后，保留象限分析、聚类分析、稳定性验证和业务规则校验继续判断。
如果多算法仍无法形成一致结论，输出人工复核或观察型标签。
```

### 11.7 缺失数据处理

缺失毛利率或损耗率的商品不参与品类等级评分。

处理规则：

```text
缺失毛利率的 SKU：不参与毛利相关指标评分
缺失损耗率的 SKU：不参与损耗健康度评分
关键质量指标缺失较多的门店品类组：不输出正式 A/B/C/D
缺失数据进入映射缺口表，等待补齐后重算
```

业务口径：

```text
缺失数据商品可以保留在销售统计和映射诊断中。
但不得参与最终等级评分，避免把不可解释的销售额误判为高质量经营能力。
```

## 14. 业务解释规则

### 14.1 A 级门店

判断含义：

```text
该门店在同区域同品类下熵权综合分高，且象限分析验证为优势经营型。
```

适合动作：

```text
新品优先试点
季节品重点营销
重点发券
重点陈列
较高预算投放
作为商品机会验证样板门店
```

### 14.2 B 级门店

判断含义：

```text
该门店在同区域同品类下熵权得分较高，或具备明确潜力，但存在轻微短板。
```

适合动作：

```text
小范围测试
跟随 A 级门店策略
适度发券
适度门店任务
观察转化和复购
```

### 14.3 C 级门店

判断含义：

```text
该门店在同区域同品类下综合表现一般，或经营规模、经营质量存在明显短板。
```

适合动作：

```text
低预算测试
定向券验证
诊断销售弱、客数弱、毛利弱、折扣依赖或损耗高的原因
```

### 14.4 D 级门店

判断含义：

```text
该门店在同区域同品类下熵权低分，且象限验证偏弱，或质量风险明显。
```

适合动作：

```text
暂缓扩品
暂缓重点营销
仅在清库存、结构调整、门店补短板时介入
必要时考虑缩减该品类经营权重
```

### 14.5 观察型标签

判断含义：

```text
该门店品类组暂不适合强制判断 A/B/C/D，需要继续观察或先做诊断。
```

适合动作：

```text
暂不分级：不直接做强营销动作
观察型：继续积累数据，控制预算试探
潜力培育型：小范围测试新品、内容或会员券
质量改善型：先优化毛利、折扣、损耗，再放大营销
谨慎经营型：低预算、低风险动作，优先诊断原因
```

## 16. 已确认算法口径

```text
1. 熵权法标准化采用 50 分位标准化，也就是中位数标准化。
2. 经营规模轴使用 sales_amt + member_customer_cnt + ticket_cnt。
3. 经营质量轴使用 full_chain_gross_profit_amt + store_margin_rate + pre19_sales_share + promo_discount_health_score + loss_health_score。
4. 折扣健康度只使用 19 点前 promo_discount_rate，不使用 hour_discount_rate。
5. 损耗健康度按照区域品类建立，即 region_group + large_category + mid_category + small_category。
6. 正式分级的最低样本量、小票数、销售额不预设固定值，由数据结果的置信度动态给出目标阈值。
7. 熵权分数差异阈值需要在大量历史数据验证后给出；未达到有效区分阈值时，熵权结果不得进入最终交叉验证。
8. 象限结果与熵权结果冲突时，增加多算法交叉验证；若熵权分数差异未达阈值，则剔除熵权结果，保留其他算法结果继续验证。
9. 缺失毛利率、损耗率的 SKU 不参与品类等级评分，只进入缺失映射诊断和必要的销售统计观察。
```
