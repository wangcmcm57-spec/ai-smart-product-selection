# 基础数据表合同

这里存放 V1 AI 新品推荐需要开发准备的内部基础数据表。

这些表都需要并行准备。当前项目不是给门店做订购系统，但 **门店商品每日可订可售表已经由业务确认为 V1 必做表**，原因是算法需要判断某个商品在某门店没有销量，到底是消费者不买，还是本来不可售、不可订。

## 合同统一格式

每张基础表合同必须写清：

```text
1. 目标表建议名。
2. 一行代表什么。
3. 主键或唯一键。
4. 关联要求。
5. 完整字段清单，统一使用：中文字段名 | 英文字段名 | 类型建议 | 是否必须 | 字段来源 | 中文注释。
6. 如有状态字段，写清状态字段取值约束。
7. 缺失和降级写法。
```

## 开发反馈要求

每张表请按以下口径反馈：

1. 字段是否能提供。
2. 字段来源系统或来源表。
3. 是否能按合同粒度产出。
4. 主键是否唯一。
5. 关联字段是否能和小票表对齐。
6. 数据更新频率。
7. 可提供的历史数据周期。
8. 缺失字段、替代字段和口径差异。

## 注意事项

- 小票商品明细表已有，不在这里重复建表，但所有基础表都要能和小票表关联。
- 交易商品编码必须能对齐小票表 `article_id`。
- 门店编码必须能对齐小票表 `store_id`。
- 商品状态表由数据开发从 SAP POP 平台按区域、商品名称、商品编码、商品状态提供，不再作为规则配置表从业务规则 Excel 导入；其中 `product_status_code = S` 的商品还要带计划上架开始日期和结束日期。
- [Doris `data_db` 基础表查漏补缺清单](../Doris_data_db基础表查漏补缺清单_2026-08-10.md) 是当前有效的开发补数清单，用于说明现有 Doris 表能覆盖什么、还缺什么。
- 真实 Excel、CSV、Doris 导出结果不放入 Git。
