# 城市算法区域映射表

目标表建议名：`dim_city_algorithm_region`

表用途：记录华东一期会员画像算法使用的城市到算法区域映射口径。该表用于会员画像的主归属区域、区域熵权、Jenks 阈值和逻辑回归参数训练。

## 1. 这张表解决什么问题

会员画像最终是一人一条标签，但算法里的熵权、自然断点、逻辑回归参数需要按算法区域分别计算。

华东一期算法区域按城市归并，不需要门店级映射：

```text
城市 -> 算法区域
```

计算时链路如下：

```text
小票 store_id
-> 门店基础表
-> 城市
-> 城市算法区域映射表
-> 会员主归属区域 primary_region
```

## 2. 表规则

一行代表：

```text
一行 = 一个城市 + 一个算法区域映射生效周期
```

主键：

```text
city + effective_start_date
```

关联要求：

```text
城市必须能和门店基础表里的城市字段对齐。
算法区域名称用于会员画像的主归属区域、区域熵权、Jenks 阈值和逻辑回归参数训练。
```

## 3. 字段清单

| 中文字段名 | 英文字段名 | 类型建议 | 是否必须 | 字段来源 | 中文注释 |
|---|---|---|---|---|---|
| 城市 | `city` | varchar(64) | 必须 | 业务确认 + `dim_store.city_name` 对齐 | 门店基础表中的城市名称 |
| 算法区域编码 | `algorithm_region_code` | varchar(64) | 必须 | 业务确认 | 算法区域唯一编码，例如 `SH`、`HZ_NB_SX`、`SZ_CZ_WX` |
| 算法区域名称 | `algorithm_region_name` | varchar(128) | 必须 | 业务确认 | 算法训练和参数计算使用的区域口径 |
| 生效开始日期 | `effective_start_date` | date | 必须 | 业务确认或项目维护 | 该映射开始生效日期 |
| 生效结束日期 | `effective_end_date` | date | 建议 | 业务确认或项目维护 | 当前有效映射可为空，历史映射需要回填结束日期 |
| 是否当前有效 | `is_active` | tinyint | 必须 | 项目维护 | `1` 表示当前有效，`0` 表示历史无效 |
| 映射确认人 | `confirmed_by` | varchar(128) | 建议 | 项目维护 | 业务确认人 |
| 映射确认日期 | `confirmed_date` | date | 建议 | 项目维护 | 业务确认日期 |
| 数据更新时间 | `data_update_time` | datetime | 必须 | 入库时间或维护时间 | 数据同步或维护时间 |
| 备注 | `remark` | varchar(1024) | 建议 | 项目维护 | 边界城市或临时调整说明 |

## 3.1 状态字段取值约束

| 状态字段 | 中文字段名 | 允许取值 | 中文含义 | 触发条件 |
|---|---|---|---|---|
| `is_active` | 是否当前有效 | `1` | 当前有效 | 当前算法周期使用该城市到算法区域的映射 |
| `is_active` | 是否当前有效 | `0` | 历史无效 | 映射已被新生效周期替代 |

## 3.2 缺失和降级写法

```text
1. `city`、`algorithm_region_code`、`algorithm_region_name`、`effective_start_date`、`is_active` 不能为空。
2. 门店基础表中的城市如果匹配不到本表当前有效记录，默认不纳入华东一期会员画像算法区域。
3. 同一城市同一日期不能命中多个 `is_active = 1` 的算法区域。
4. 映射变化必须新增生效周期，不得直接覆盖旧记录。
```

## 4. 华东一期映射口径

以下为业务已提供的城市到算法区域映射关系。

| 城市 | 算法区域编码 | 算法区域名称 | 业务口径 |
| --- | --- | --- | --- |
| 上海 | SH | 上海 | 上海单独一个算法区域 |
| 杭州 | HZ_NB_SX | 杭州宁波绍兴 | 杭州、宁波、绍兴合并 |
| 宁波 | HZ_NB_SX | 杭州宁波绍兴 | 杭州、宁波、绍兴合并 |
| 绍兴 | HZ_NB_SX | 杭州宁波绍兴 | 杭州、宁波、绍兴合并 |
| 苏州 | SZ_CZ_WX | 苏州常州无锡 | 苏州、常州、无锡合并 |
| 常州 | SZ_CZ_WX | 苏州常州无锡 | 苏州、常州、无锡合并 |
| 无锡 | SZ_CZ_WX | 苏州常州无锡 | 苏州、常州、无锡合并 |

未出现在本表中的城市，默认不纳入华东一期算法区域；如后续需要纳入，需由业务补充城市归属。

## 5. 数据质量要求

```text
1. 同一城市在同一日期只能命中一个有效算法区域。
2. 华东一期参与会员画像的门店城市必须全部能匹配到上述三个算法区域之一。
3. 算法区域名称必须稳定，不允许同义混写。
4. 映射变化必须保留历史生效周期，不能直接覆盖旧映射。
```

## 6. 业务确认结论

业务已确认：

```text
1. 算法区域名称采用：上海、杭州宁波绍兴、苏州常州无锡。
2. 算法区域编码采用：SH、HZ_NB_SX、SZ_CZ_WX。
3. 不存在同一城市内门店归属不同算法区域的例外。
4. 不存在不参与会员画像计算的特殊门店。
```

因此华东一期只建设城市级算法区域映射表，不额外建设门店级例外映射表。

## 7. 编码规则说明

```text
SH：上海
HZ_NB_SX：杭州、宁波、绍兴
SZ_CZ_WX：苏州、常州、无锡
```

编码使用城市拼音首字母缩写，并用下划线分隔城市，便于开发识别、避免中文编码在接口和 SQL 中出现兼容问题。该规则适合 V1 使用。
