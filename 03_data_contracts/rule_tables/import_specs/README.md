# 规则表导入映射说明

本目录说明首版业务补充 Excel、用户确认配置和后续非标准业务资料如何转换到标准规则表。

这些文档需要保留，用于首版迁移审计、转换规则追溯、重跑标准导入包和处理历史非标准 Excel。它们不是后续业务的日常填报模板。

后续业务常规更新应按标准 Excel sheet 提供数据，清单见：

```text
../业务后续标准Excel提供清单.md
```

这些文档的目的不是让算法读取 Excel，也不是让开发从原始 Excel 猜字段，而是让项目侧和数据侧清楚：

```text
源文件哪一列
经过什么转换
进入哪张标准表的哪个字段
缺失或异常时怎么处理
```

## 2. 通用导入字段

所有规则配置表都要补齐这些系统字段：

| 中文字段名 | 英文字段名 | 生成规则 |
|---|---|---|
| 规则版本 | `*_version` | 按来源和日期生成，例如 `MARGIN_2026_V1`、`NAMING_2026_V1`、`COMPLIANCE_2026_0818` |
| 生效开始日期 | `effective_start_date` | 有业务生效日期则用业务日期；没有则用本次配置确认日期 |
| 生效结束日期 | `effective_end_date` | 当前有效版本为空；历史版本按新版本生效前一天回填 |
| 是否当前有效 | `is_active` | 当前生效规则写 1，历史规则写 0 |
| 来源文件 | `source_file` | 写原始 Excel 文件名、用户确认配置或来源系统 |
| 来源 sheet | `source_sheet` | 写原始 sheet 名；非 Excel 来源可为空 |
| 数据更新时间 | `updated_at` | 数据导入或刷新时间 |

## 3. 通用品类编码映射

业务 Excel 里多数是中文品类名，标准表需要尽量补品类编码。

编码获取顺序：

```text
1. 优先用 dim_sku 中已经存在的品类编码和品类名称映射。
2. 如果 dim_sku 暂时不能提供独立品类字典，可用 B3 分类库参考做一次初始化对照。
3. 如果一个中文品类名匹配到多个编码，规则状态写 REVIEW_REQUIRED。
4. 如果中文品类名找不到编码，编码字段先为空，规则状态写 REVIEW_REQUIRED 或导入异常。
```

开发不能自行按名称相似度强行补编码；无法唯一匹配时必须留痕。

## 4. 通用校验要求

```text
1. Excel 文件本身不进入生产算法。
2. 导入后算法只读取标准规则表。
3. 同一规则版本、同一业务主键不能出现多条当前有效记录。
4. 所有百分比字段必须落为 0 到 1 之间的小数，不能落成 9% 或 9。
5. 原始样例、复核样例和审核工作台只进入 fact_rule_review_item，不直接决定算法结果。
```
