# 业务规则 Excel 落表模块开发说明

## 1. 模块定位

本模块负责把业务维护的规则 Excel 变成 Doris 规则配置表。
它不是算法的一部分，也不是让算法直接读 Excel。

一句话：

```text
业务规则 Excel 落表模块负责把业务填的标准 sheet 校验、转 CSV、落 Doris、发布规则版本，再让算法按规则版本读取。
```

## 2. 为什么要单独做

业务规则会持续变化，例如毛利目标、价格点、购物篮属性转化、竞对分类映射、命名规则和合规词。
如果开发让算法直接读 Excel，会出现三个问题：

```text
字段名不稳定
版本不可追溯
线上结果无法复盘
```

所以 V1 正式链路固定为：

```text
业务标准 Excel
-> 字段和主键校验
-> 标准 CSV
-> Doris 规则配置表
-> 规则版本发布
-> 算法读取 Doris
-> 算法结果记录规则版本
```

## 3. 首版和后续更新的区别

| 场景 | 输入 | 处理方式 | 产出 |
|---|---|---|---|
| 首版导入 | 业务已给的不标准 Excel | 项目侧已转换为标准 Excel 和标准 CSV；评审期临时放在 `import_ready/2026-08-18/`，开发优先使用其中 `csv/` 落 Doris | Doris 规则配置表首版数据 |
| 后续更新 | 业务按标准 sheet 维护的 Excel | 校验 sheet、字段、枚举、主键、版本和生效日期后导出 CSV | 新规则版本 |
| 历史追溯 | 原始 B1/B3/B4 或合规词库材料 | 只看 `import_specs/` 追溯转换逻辑 | 审计说明或重跑标准包 |

生产算法只读取 Doris 表。
Excel、原始业务导出和中间校验文件不作为算法运行时输入。

## 4. 标准处理流程

```text
接收标准 Excel
-> 校验 sheet 名称和表头
-> 校验字段类型、必填、枚举和日期
-> 校验目标表主键或唯一键
-> 校验规则版本、生效日期和是否当前有效
-> 导出标准 CSV
-> 数据开发导入 Doris 规则表
-> 生成或更新规则版本
-> 算法运行时读取当前有效规则
-> 算法结果写入使用的规则版本
```

如果校验失败，不发布新规则版本。
旧版本继续有效，直到新版本通过校验并发布。

## 5. V1 标准 sheet 和目标表

| 标准 sheet | 目标 Doris 表 | 用于算法 | 维护重点 |
|---|---|---|---|
| `01_毛利目标配置` | `dim_company_margin_target_config` | 05、08 | 公司毛利底线、目标毛利、适用范围和生效日期 |
| `02_价格点规则` | `dim_price_point_rule_config` | 05、08 | 价格尾数、价格步长、上下限来源和计价单位 |
| `03_购物篮转属性` | `dim_basket_attribute_transfer_rule` | 06、08 | 锚点属性、关联属性、转化类型和规则状态 |
| `04_商品命名规则` | `dim_product_naming_rule` | 07、08 | 分类、命名结构、必填字段和异常拦截 |
| `05_特殊必填属性` | `dim_special_product_required_attribute_rule` | 07、08 | 特殊商品关键词、必填属性和缺失处理 |
| `06_竞对分类映射` | `dim_competitor_category_mapping_rule` | 07、08 | 外部分类到内部分类的映射状态 |
| `07_候选属性字典` | `dim_candidate_attribute_dictionary` | 07、08 | 标准属性、别名、适用品类、入名和风险标识 |
| `08_命名合规词` | `dim_naming_compliance_term_rule` | 07、08、09 | 禁用词、需审核词、风险等级和法源代码 |
| `09_分类命名合规` | `dim_category_naming_compliance_rule` | 07、08、09 | 分类合规要求、证照提示和规则状态 |
| `10_法规依据` | `dim_regulation_reference` | 07、08、09 | 法规名称、法规状态、关键条款和来源链接 |
| `11_复核样例` | `fact_rule_review_item` | 07、08、09 | 待复核对象、原因、优先级和复核结论 |

标准 sheet 的详细状态和当前缺口以 `业务后续标准Excel提供清单.md` 为准。
每张 Doris 表的字段、主键和状态约束以本目录对应数据合同为准。

## 6. 通用校验规则

| 校验项 | 规则 |
|---|---|
| sheet 名称 | 必须使用标准 sheet 名称 |
| 表头 | 第 1 行中文字段名，第 2 行英文字段名，第 3 行开始数据 |
| 字段名 | 英文字段名必须和目标表合同、CSV 表头一致 |
| 必填字段 | 表合同标为必须的字段不能为空 |
| 日期 | 使用 `yyyy-mm-dd` |
| 百分比 | 使用 0 到 1 的小数 |
| 枚举 | 使用表合同中的英文枚举 |
| 主键 | 同一目标表、同一规则版本内不得重复 |
| 生效期 | 生效开始日期不能为空；当前有效规则不能出现互相冲突的生效区间 |
| 规则版本 | 每次发布必须有明确版本号，算法结果必须记录使用的版本 |

## 7. 发布和回滚

| 动作 | 处理方式 |
|---|---|
| 发布新版本 | 新 CSV 导入临时分区或临时表，校验通过后切换当前有效版本 |
| 校验失败 | 不发布新版本，保留错误报告和原始批次 |
| 发现规则错误 | 修正规则后发布新版本，受影响算法按新规则版本重算 |
| 回滚 | 当前有效版本切回上一通过验收的规则版本，并记录原因 |
| 历史复盘 | 按算法结果中记录的规则版本回查当时规则 |

规则不能在 SQL 或代码里临时硬编码。
业务规则变化必须进入新规则版本。

## 8. 和开发分工的关系

| 角色 | 负责内容 |
|---|---|
| 业务 / 商品 / 质量 / 法务 | 按标准 sheet 维护业务规则和复核结论 |
| 产品 / 项目侧 | 维护标准模板、解释字段口径、组织复核和验收 |
| 数据开发 | CSV 入库、Doris 表建设、版本发布、主键和质量校验 |
| 算法开发 | 只读取已发布 Doris 规则表，并在结果表记录规则版本 |
| 后端 / Agent / 前端 | 读取算法结果和解释，不直接读取业务 Excel |

## 9. 开发验收

开发交付本模块时，至少验收：

```text
标准 Excel 能稳定导出标准 CSV
CSV 表头和 Doris 表合同一致
同一规则版本内主键不重复
必填字段、日期、百分比和枚举校验可执行
新版本发布失败时不影响旧版本
算法结果能记录并回查所使用的规则版本
生产算法没有直接读取 Excel 文件
```
