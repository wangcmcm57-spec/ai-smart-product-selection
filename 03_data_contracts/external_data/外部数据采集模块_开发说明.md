# 外部数据采集模块开发说明

## 1. 模块定位

本模块负责为算法 07 提供可追溯的外部数据输入。
它不是前端查询的一部分，也不是 Harness 的在线工具调用。

一句话：

```text
外部数据采集模块负责把外部商品、价格、规格、图片、文章、供需和风险线索采集成标准数据，再交给算法 07 离线计算。
```

## 2. 实现方式优先级

开发实现时按下面优先级选择，不建议把所有外部源都做成浏览器自动化。

| 优先级 | 实现方式 | 适用场景 | 说明 |
|---|---|---|---|
| 1 | 数据供应商 API | 久谦、授权商业数据源 | 最稳定，优先保存原始响应和接口参数 |
| 2 | 官方 API / RSS / 下载文件 | 官方价量、法规、行业公开数据 | 优先使用结构化或半结构化来源 |
| 3 | HTTP 采集服务 | 静态列表页、文章页、公开接口 | 可用 Python `requests` / `httpx` / `Scrapy` 等实现 |
| 4 | 无头浏览器采集 | 必须渲染后才能取得数据的页面 | 可用 Playwright 或同类方案，成本和稳定性要单独评估 |
| 5 | browser-harness | 页面结构验证、采集路径 PoC、人工辅助排查 | 不作为生产调度依赖 |

生产任务必须由可调度、可重试、可监控的采集服务承担。
browser-harness 可以帮助开发理解网页结构和验证抓取策略，但不能替代正式采集任务。

## 3. 标准采集链路

```text
配置外部数据源
-> 发起 API / HTTP / 浏览器采集
-> 保存原始响应、请求参数、采集时间和来源状态
-> 标准化商品、价格、规格、图片、文章和风险线索
-> 写入外部数据表或算法 07 可读的标准输入
-> 算法 07 按批次读取并生成外部证据和外部候选
```

任何外部证据都要能回答：

```text
来自哪里
什么时候采集
原始内容是什么
采集是否成功
是否允许展示图片或引用
如何映射到内部分类和候选属性
```

## 4. 当前已定义外部表

当前外部数据合同已定义久谦链路的 3 张表：

| 表 | 一行代表什么 | 用途 |
|---|---|---|
| `ods_jiuqian_api_raw` | 一次久谦接口请求或采集批次 | 保存原始响应、接口参数、状态和错误 |
| `dim_competitor_sku` | 一个数据提供方 + 平台 + 城市 + 竞品 SKU | 保存竞品商品稳定属性 |
| `fact_competitor_sku_daily_snapshot` | 一个采集日期 + 平台 + 城市 + 竞品 SKU | 保存价格、销量、促销、售罄、评价和图片变化 |

其他公开外部源如果进入生产采集，也应补同等粒度的原始快照合同。
不能只把抽取后的结论直接写进算法 07 结果表。

## 5. 调度口径

| 任务 | 建议频率 | 产出 |
|---|---|---|
| 久谦数据采集 | 每日 | 原始批次、竞品 SKU、竞品每日快照 |
| 官方 / 行业 / 公开源采集 | 每日或按来源发布频率 | 原始快照、文章证据、价量和供需证据 |
| 图片可用性和授权校验 | 随采集或每日 | 图片状态、授权状态、异常原因 |
| 外部证据标准化 | 每日或每周 | 算法 07 可读取的标准外部证据 |
| 探索预警 | 每周 | 预览信号，不覆盖正式月度候选 |
| 正式候选冻结 | 每月 | 锁定 `external_data_cutoff` 后交给算法 07 正式运行 |

采购查询、前端页面和 Agent 对话不触发实时外部采集。

## 6. 必须记录的采集字段

每次采集至少要记录：

```text
source_name
source_type
request_url
request_params
request_method
collection_batch_id
collection_started_at
collection_finished_at
collection_status
http_status_code
raw_payload
payload_hash
error_code
error_message
license_or_authorization_status
```

图片类数据还要记录：

```text
image_url
image_hash
image_match_status
image_license_status
display_allowed_flag
```

## 7. 异常处理

| 异常 | 处理方式 |
|---|---|
| 来源不可访问 | 记录采集失败，不用旧数据冒充新数据 |
| 字段缺失 | 写缺失状态，不能填 0 代替未知 |
| 页面结构变化 | 进入采集异常，不发布该来源新批次 |
| 授权状态未知 | 图片和引用默认不展示，只保留内部追溯 |
| 反复失败 | 标记来源不稳定，算法 07 只能读取已成功标准化批次 |
| 外部词无法映射内部分类 | 保留证据，不进入正式候选 |

## 8. 开发验收

开发交付本模块时，至少验收：

```text
同一采集批次可追溯原始响应
同一来源重复采集不会生成重复主键
采集失败有明确状态和错误原因
图片展示必须经过匹配和授权状态判断
每日快照能按日期、平台、城市和竞品 SKU 唯一
算法 07 能按外部数据截止时间读取稳定批次
浏览器自动化不是生产唯一依赖
```

## 9. 和 browser-harness 的关系

browser-harness 可以用于：

```text
验证页面是否能打开
检查 DOM 和接口结构
辅助定位按钮、下载入口或分页逻辑
生成采集策略 PoC
排查采集失败原因
```

正式生产采集应沉淀为独立任务、脚本或服务，并接入调度、监控、重试、版本和审计。
不能要求算法 07 或 Harness 在采购查询时临时打开浏览器抓取数据。
